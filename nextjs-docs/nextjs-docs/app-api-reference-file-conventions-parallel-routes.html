Parallel RoutesParallel Route

Parallel Route를 사용하면 같은 layout 안에서 하나 이상의 page를 동시에 또는 조건부로 render할 수 있습니다. dashboard나 소셜 사이트의 feed처럼 앱에서 매우 dynamic한 영역에 유용합니다.

Parallel Routes allows you to simultaneously or conditionally render one or more pages within the same layout. They are useful for highly dynamic sections of an app, such as dashboards and feeds on social sites.

예를 들어 dashboard에서 parallel route를 사용해 team page와 analytics page를 동시에 render할 수 있습니다:

For example, considering a dashboard, you can use parallel routes to simultaneously render the team and analytics pages:

Convention규칙

SlotsSlot

Parallel route는 이름이 붙은 slot으로 만듭니다. slot은 @folder convention으로 정의합니다. 예를 들어 다음 파일 구조는 @analytics와 @team 두 개의 slot을 정의합니다:

Parallel routes are created using named slots. Slots are defined with the @folder convention. For example, the following file structure defines two slots: @analytics and @team:

slot은 공유 상위 layout에 props로 전달됩니다. 위 예시에서 app/layout.js의 component는 이제 @analytics와 @team slot props를 받으며, 이를 children prop과 함께 병렬로 render할 수 있습니다:

Slots are passed as props to the shared parent layout. For the example above, the component in app/layout.js now accepts the @analytics and @team slots props, and can render them in parallel alongside the children prop:

TSJSapp/layout.tsx
export default function Layout({
  children,
  team,
  analytics,
}: {
  children: React.ReactNode
  analytics: React.ReactNode
  team: React.ReactNode
}) {
  return (
    <>
      {children}
      {team}
      {analytics}
    </>
  )
}
export default function Layout({ children, team, analytics }) {
  return (
    <>
      {children}
      {team}
      {analytics}
    </>
  )
}

하지만 slot은 route segment가 아니며 URL 구조에 영향을 주지 않습니다. 예를 들어 /@analytics/views의 경우 @analytics가 slot이므로 URL은 /views가 됩니다. slot은 일반 Page component와 결합되어 해당 route segment에 연결된 최종 page를 구성합니다. 이 때문에 같은 route segment level에서 prerender되는 slot과 dynamic하게 render되는 slot을 따로 둘 수 없습니다. 하나의 slot이 dynamic이면 그 level의 모든 slot이 dynamic이어야 합니다.

However, slots are not route segments and do not affect the URL structure. For example, for /@analytics/views, the URL will be /views since @analytics is a slot. Slots are combined with the regular Page component to form the final page associated with the route segment. Because of this, you cannot have separate prerendered and dynamically rendered slots at the same route segment level. If one slot is dynamic, all slots at that level must be dynamic.

Good to know
  • children prop은 폴더에 mapping할 필요가 없는 암묵적인(implicit) slot입니다. 즉, app/page.js는 app/@children/page.js와 동일합니다.
  • The children prop is an implicit slot that does not need to be mapped to a folder. This means app/page.js is equivalent to app/@children/page.js.

default.js

초기 load나 full-page reload 시 match되지 않는 slot에 대한 fallback으로 render할 default.js 파일을 정의할 수 있습니다.

You can define a default.js file to render as a fallback for unmatched slots during the initial load or full-page reload.

다음 폴더 구조를 생각해 보세요. @team slot에는 /settings page가 있지만 @analytics에는 없습니다.

Consider the following folder structure. The @team slot has a /settings page, but @analytics does not.

/settings로 이동하면 @team slot은 /settings page를 render하고, @analytics slot은 현재 활성 page를 유지합니다.

When navigating to /settings, the @team slot will render the /settings page while maintaining the currently active page for the @analytics slot.

새로고침하면 Next.js는 @analytics에 대해 default.js를 render합니다. default.js가 없으면 대신 404가 render됩니다.

On refresh, Next.js will render a default.js for @analytics. If default.js doesn't exist, a 404 is rendered instead.

또한 children은 암묵적인 slot이므로, Next.js가 상위 page의 활성 상태를 복구할 수 없을 때 children에 대한 fallback을 render하려면 default.js 파일도 만들어야 합니다.

Additionally, since children is an implicit slot, you also need to create a default.js file to render a fallback for children when Next.js cannot recover the active state of the parent page.

Behavior동작

기본적으로 Next.js는 각 slot의 활성 state(또는 subpage)를 추적합니다. 하지만 slot 안에 render되는 content는 navigation의 종류에 따라 달라집니다:

By default, Next.js keeps track of the active state (or subpage) for each slot. However, the content rendered within a slot will depend on the type of navigation:

  • Soft Navigation: client-side navigation 중에 Next.js는 partial render를 수행해, 다른 slot의 활성 subpage가 현재 URL과 match되지 않더라도 이를 유지한 채 해당 slot 안의 subpage만 바꿉니다.
  • Hard Navigation: full-page load(브라우저 새로고침) 후에는 Next.js가 현재 URL과 match되지 않는 slot의 활성 상태를 알 수 없습니다. 대신 match되지 않는 slot에 대해 default.js 파일을 render하고, default.js가 없으면 404를 render합니다.
  • Soft Navigation: During client-side navigation, Next.js will perform a partial render, changing the subpage within the slot, while maintaining the other slot's active subpages, even if they don't match the current URL.
  • Hard Navigation: After a full-page load (browser refresh), Next.js cannot determine the active state for the slots that don't match the current URL. Instead, it will render a default.js file for the unmatched slots, or 404 if default.js doesn't exist.
Good to know
  • match되지 않는 route에 대한 404는 의도하지 않은 page에서 parallel route가 실수로 render되지 않도록 보장하는 데 도움이 됩니다.
  • The 404 for unmatched routes helps ensure that you don't accidentally render a parallel route on a page that it was not intended for.

Examples예시

With useSelectedLayoutSegment(s)useSelectedLayoutSegment(s)와 함께

useSelectedLayoutSegment와 useSelectedLayoutSegments는 모두 parallelRouteKey parameter를 받으며, 이를 통해 slot 안의 활성 route segment를 읽을 수 있습니다.

Both useSelectedLayoutSegment and useSelectedLayoutSegments accept a parallelRouteKey parameter, which allows you to read the active route segment within a slot.

TSJSapp/layout.tsx
'use client'

import { useSelectedLayoutSegment } from 'next/navigation'

export default function Layout({ auth }: { auth: React.ReactNode }) {
  const loginSegment = useSelectedLayoutSegment('auth')
  // ...
}
'use client'

import { useSelectedLayoutSegment } from 'next/navigation'

export default function Layout({ auth }) {
  const loginSegment = useSelectedLayoutSegment('auth')
  // ...
}

사용자가 app/@auth/login(또는 주소창의 /login)으로 이동하면 loginSegment는 문자열 "login"이 됩니다.

When a user navigates to app/@auth/login (or /login in the URL bar), loginSegment will be equal to the string "login".

Conditional Routes조건부 Route

Parallel Route를 사용하면 사용자 role 같은 특정 조건에 따라 route를 조건부로 render할 수 있습니다. 예를 들어 /admin role과 /user role에 서로 다른 dashboard page를 render하려면 다음과 같이 합니다:

You can use Parallel Routes to conditionally render routes based on certain conditions, such as user role. For example, to render a different dashboard page for the /admin or /user roles:

TSJSapp/dashboard/layout.tsx
import { checkUserRole } from '@/lib/auth'

export default function Layout({
  user,
  admin,
}: {
  user: React.ReactNode
  admin: React.ReactNode
}) {
  const role = checkUserRole()
  return role === 'admin' ? admin : user
}
import { checkUserRole } from '@/lib/auth'

export default function Layout({ user, admin }) {
  const role = checkUserRole()
  return role === 'admin' ? admin : user
}

layout이 어느 쪽을 반환하든 두 slot 모두 server에서 render됩니다. 조건문은 사용자가 무엇을 보는지를 결정할 뿐, 무엇이 실행되는지를 결정하지 않습니다. @admin/page.js는 모든 사용자에 대해 data fetch를 실행하며, 그 결과는 브라우저로 전송되는 response에 포함됩니다. 각 slot의 page 안에서, 또는 Data Access Layer에서 권한을 확인하세요:

Both slots render on the server, regardless of which one the layout returns. The conditional decides what the user sees, not what runs: @admin/page.js executes its data fetches for every user, and its output is included in the response sent to the browser. Authorize inside each slot's page, or in your Data Access Layer:

TSJSapp/dashboard/@admin/page.tsx
import { getAdminStats } from '@/lib/dal'

export default async function AdminPage() {
  const stats = await getAdminStats()
  return <Stats stats={stats} />
}
import { getAdminStats } from '@/lib/dal'

export default async function AdminPage() {
  const stats = await getAdminStats()
  return <Stats stats={stats} />
}

Tab GroupsTab Group

slot 안에 layout을 추가하면 사용자가 그 slot을 독립적으로 navigate할 수 있습니다. tab을 만들 때 유용합니다.

You can add a layout inside a slot to allow users to navigate the slot independently. This is useful for creating tabs.

예를 들어 @analytics slot에 /page-views와 /visitors 두 개의 subpage가 있다고 해 봅시다.

For example, the @analytics slot has two subpages: /page-views and /visitors.

@analytics 안에 layout 파일을 만들어 두 page가 tab을 공유하게 하세요:

Within @analytics, create a layout file to share the tabs between the two pages:

TSJSapp/@analytics/layout.tsx
import Link from 'next/link'

export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <nav>
        <Link href="/page-views">Page Views</Link>
        <Link href="/visitors">Visitors</Link>
      </nav>
      <div>{children}</div>
    </>
  )
}
import Link from 'next/link'

export default function Layout({ children }) {
  return (
    <>
      <nav>
        <Link href="/page-views">Page Views</Link>
        <Link href="/visitors">Visitors</Link>
      </nav>
      <div>{children}</div>
    </>
  )
}

ModalsModal

Parallel Route는 Intercepting Routes와 함께 사용해 deep linking을 지원하는 modal을 만들 수 있습니다. 이를 통해 modal을 만들 때 흔히 겪는 다음과 같은 문제를 해결할 수 있습니다:

Parallel Routes can be used together with Intercepting Routes to create modals that support deep linking. This allows you to solve common challenges when building modals, such as:

  • modal content를 URL로 공유 가능하게 만들기.
  • page를 새로고침했을 때 modal을 닫지 않고 context를 유지하기.
  • 뒤로 가기 navigation 시 이전 route로 이동하는 대신 modal 닫기.
  • 앞으로 가기 navigation 시 modal 다시 열기.
  • Making the modal content shareable through a URL.
  • Preserving context when the page is refreshed, instead of closing the modal.
  • Closing the modal on backwards navigation rather than going to the previous route.
  • Reopening the modal on forwards navigation.

사용자가 client-side navigation으로 layout에서 login modal을 열거나, 별도의 /login page에 접근할 수 있는 다음 UI pattern을 생각해 보세요:

Consider the following UI pattern, where a user can open a login modal from a layout using client-side navigation, or access a separate /login page:

이 pattern을 구현하려면 먼저 main login page를 render하는 /login route를 만드세요.

To implement this pattern, start by creating a /login route that renders your main login page.

TSJSapp/login/page.tsx
import { Login } from '@/app/ui/login'

export default function Page() {
  return <Login />
}
import { Login } from '@/app/ui/login'

export default function Page() {
  return <Login />
}

그다음 @auth slot 안에 null을 반환하는 default.js 파일을 추가하세요. 이렇게 하면 modal이 활성 상태가 아닐 때 render되지 않습니다.

Then, inside the @auth slot, add default.js file that returns null. This ensures that the modal is not rendered when it's not active.

TSJSapp/@auth/default.tsx
export default function Default() {
  return null
}
export default function Default() {
  return null
}

@auth slot 안에서 <Modal> component와 그 children을 @auth/(.)login/page.tsx 파일에 import하고, 폴더 이름을 /@auth/(.)login/page.tsx로 바꿔 /login route를 intercept하세요.

Inside your @auth slot, intercept the /login route by importing the <Modal> component and its children into the @auth/(.)login/page.tsx file, and updating the folder name to /@auth/(.)login/page.tsx.

TSJSapp/@auth/(.)login/page.tsx
import { Modal } from '@/app/ui/modal'
import { Login } from '@/app/ui/login'

export default function Page() {
  return (
    <Modal>
      <Login />
    </Modal>
  )
}
import { Modal } from '@/app/ui/modal'
import { Login } from '@/app/ui/login'

export default function Page() {
  return (
    <Modal>
      <Login />
    </Modal>
  )
}
Good to know
  • (.) convention은 intercepting route에 사용됩니다. 자세한 내용은 Intercepting Routes 문서를 참고하세요.
  • <Modal> 기능을 modal content(<Login>)와 분리하면, modal 안의 모든 content(예: form)가 Server Component가 되도록 보장할 수 있습니다. 자세한 내용은 Interleaving Client and Server Components를 참고하세요.
  • The convention (.) is used for intercepting routes. See Intercepting Routes docs for more information.
  • By separating the <Modal> functionality from the modal content (<Login>), you can ensure any content inside the modal, e.g. forms, are Server Components. See Interleaving Client and Server Components for more information.

Opening the modalmodal 열기

이제 Next.js router를 활용해 modal을 열고 닫을 수 있습니다. 이렇게 하면 modal이 열릴 때와 뒤로/앞으로 이동할 때 URL이 올바르게 업데이트됩니다.

Now, you can leverage the Next.js router to open and close the modal. This ensures the URL is correctly updated when the modal is open, and when navigating backwards and forwards.

modal을 열려면 @auth slot을 상위 layout에 prop으로 전달하고 children prop과 함께 render하세요.

To open the modal, pass the @auth slot as a prop to the parent layout and render it alongside the children prop.

TSJSapp/layout.tsx
import Link from 'next/link'

export default function Layout({
  auth,
  children,
}: {
  auth: React.ReactNode
  children: React.ReactNode
}) {
  return (
    <>
      <nav>
        <Link href="/login">Open modal</Link>
      </nav>
      <div>{auth}</div>
      <div>{children}</div>
    </>
  )
}
import Link from 'next/link'

export default function Layout({ auth, children }) {
  return (
    <>
      <nav>
        <Link href="/login">Open modal</Link>
      </nav>
      <div>{auth}</div>
      <div>{children}</div>
    </>
  )
}

사용자가 <Link>를 클릭하면 /login page로 이동하는 대신 modal이 열립니다. 하지만 새로고침하거나 초기 load 시에는 /login으로 이동하면 사용자가 main login page로 가게 됩니다.

When the user clicks the <Link>, the modal will open instead of navigating to the /login page. However, on refresh or initial load, navigating to /login will take the user to the main login page.

Closing the modalmodal 닫기

router.back()을 호출하거나 Link component를 사용해 modal을 닫을 수 있습니다.

You can close the modal by calling router.back() or by using the Link component.

TSJSapp/ui/modal.tsx
'use client'

import { useRouter } from 'next/navigation'

export function Modal({ children }: { children: React.ReactNode }) {
  const router = useRouter()

  return (
    <>
      <button
        onClick={() => {
          router.back()
        }}
      >
        Close modal
      </button>
      <div>{children}</div>
    </>
  )
}
'use client'

import { useRouter } from 'next/navigation'

export function Modal({ children }) {
  const router = useRouter()

  return (
    <>
      <button
        onClick={() => {
          router.back()
        }}
      >
        Close modal
      </button>
      <div>{children}</div>
    </>
  )
}

더 이상 @auth slot을 render하지 않아야 하는 page로 Link component를 사용해 이동할 때는, parallel route가 null을 반환하는 component와 match되도록 해야 합니다. 예를 들어 root page로 돌아갈 때를 위해 @auth/page.tsx component를 만듭니다:

When using the Link component to navigate away from a page that shouldn't render the @auth slot anymore, we need to make sure the parallel route matches to a component that returns null. For example, when navigating back to the root page, we create a @auth/page.tsx component:

TSJSapp/ui/modal.tsx
import Link from 'next/link'

export function Modal({ children }: { children: React.ReactNode }) {
  return (
    <>
      <Link href="/">Close modal</Link>
      <div>{children}</div>
    </>
  )
}
import Link from 'next/link'

export function Modal({ children }) {
  return (
    <>
      <Link href="/">Close modal</Link>
      <div>{children}</div>
    </>
  )
}
TSJSapp/@auth/page.tsx
export default function Page() {
  return null
}

  return null
}

또는 다른 page(/foo, /foo/bar 등)로 이동하는 경우에는 catch-all slot을 사용할 수 있습니다:

Or if navigating to any other page (such as /foo, /foo/bar, etc), you can use a catch-all slot:

TSJSapp/@auth/[...catchAll]/page.tsx
export default function CatchAll() {
  return null
}
export default function CatchAll() {
  return null
}
Good to know
  • parallel route의 동작 방식 때문에 @auth slot에서 catch-all route를 사용해 modal을 닫습니다. slot과 더 이상 match되지 않는 route로 client-side navigation을 해도 slot이 계속 보이므로, modal을 닫으려면 slot을 null을 반환하는 route와 match시켜야 합니다.
  • 다른 예로는 별도의 /photo/[id] page를 두면서 gallery에서 사진 modal을 여는 경우, 또는 side modal로 장바구니를 여는 경우가 있습니다.
  • Intercepted Route와 Parallel Route로 만든 modal 예시를 확인하세요.
  • We use a catch-all route in our @auth slot to close the modal because of how parallel routes behave. Since client-side navigations to a route that no longer match the slot will remain visible, we need to match the slot to a route that returns null to close the modal.
  • Other examples could include opening a photo modal in a gallery while also having a dedicated /photo/[id] page, or opening a shopping cart in a side modal.
