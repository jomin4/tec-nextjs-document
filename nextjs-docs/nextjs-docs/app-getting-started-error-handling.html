Error Handling에러 처리

error는 예상된 error(expected error)와 처리되지 않은 exception(uncaught exception)의 두 가지 범주로 나눌 수 있습니다. 이 페이지에서는 Next.js 애플리케이션에서 이런 error를 처리하는 방법을 안내합니다.

Errors can be divided into two categories: expected errors and uncaught exceptions. This page will walk you through how you can handle these errors in your Next.js application.

Handling expected errors예상된 error 처리하기

예상된 error란 server-side form validation이나 실패한 request처럼 애플리케이션이 정상적으로 동작하는 중에도 발생할 수 있는 error입니다. 이런 error는 명시적으로 처리해서 client에 반환해야 합니다.

Expected errors are those that can occur during the normal operation of the application, such as those from server-side form validation or failed requests. These errors should be handled explicitly and returned to the client.

Server Functions

Server Functions에서 예상된 error를 처리하려면 useActionState hook을 사용할 수 있습니다.

You can use the useActionState hook to handle expected errors in Server Functions.

이런 error에는 try/catch block을 사용해 error를 throw하는 방식을 피하세요. 대신 예상된 error를 반환값으로 모델링하세요.

For these errors, avoid using try/catch blocks and throw errors. Instead, model expected errors as return values.

TSJSapp/actions.ts
'use server'

export async function createPost(prevState: any, formData: FormData) {
  const title = formData.get('title')
  const content = formData.get('content')

  const res = await fetch('https://api.vercel.app/posts', {
    method: 'POST',
    body: { title, content },
  })
  const json = await res.json()

  if (!res.ok) {
    return { message: 'Failed to create post' }
  }
}

action을 useActionState hook에 전달하고, 반환된 state를 사용해 error 메시지를 표시할 수 있습니다.

You can pass your action to the useActionState hook and use the returned state to display an error message.

TSJSapp/ui/form.tsx
'use client'

import { useActionState } from 'react'
import { createPost } from '@/app/actions'

const initialState = {
  message: '',
}

export function Form() {
  const [state, formAction, pending] = useActionState(createPost, initialState)

  return (
    <form action={formAction}>
      <label htmlFor="title">Title</label>
      <input type="text" id="title" name="title" required />
      <label htmlFor="content">Content</label>
      <textarea id="content" name="content" required />
      {state?.message && <p aria-live="polite">{state.message}</p>}
      <button disabled={pending}>Create Post</button>
    </form>
  )
}

Server Components

Server Component 안에서 데이터를 fetch할 때는 response를 사용해 조건부로 error 메시지를 render하거나 redirect할 수 있습니다.

When fetching data inside of a Server Component, you can use the response to conditionally render an error message or redirect.

TSJSapp/page.tsx
export default async function Page() {
  const res = await fetch(`https://...`)
  const data = await res.json()

  if (!res.ok) {
    return 'There was an error.'
  }

  return '...'
}

  const data = await res.json()

  if (!res.ok) {
    return 'There was an error.'
  }

  return '...'
}

Not found

route segment 안에서 notFound 함수를 호출하고 not-found.js 파일을 사용해 404 UI를 보여 줄 수 있습니다.

You can call the notFound function within a route segment and use the not-found.js file to show a 404 UI.

TSJSapp/blog/[slug]/page.tsx
import { notFound } from 'next/navigation'
import { getPostBySlug } from '@/lib/posts'

export default async function Page({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = getPostBySlug(slug)

  if (!post) {
    notFound()
  }

  return <div>{post.title}</div>
}
import { notFound } from 'next/navigation'
import { getPostBySlug } from '@/lib/posts'

export default async function Page({ params }) {
  const { slug } = await params
  const post = getPostBySlug(slug)

  if (!post) {
    notFound()
  }

  return <div>{post.title}</div>
}
TSJSapp/blog/[slug]/not-found.tsx
export default function NotFound() {
  return <div>404 - Page Not Found</div>
}

  return <div>404 - Page Not Found</div>
}

Handling uncaught exceptions처리되지 않은 exception 다루기

처리되지 않은 exception은 애플리케이션의 정상적인 흐름에서는 발생하지 않아야 할 bug나 문제를 나타내는 예상치 못한 error입니다. 이런 error는 throw해서 처리해야 하며, throw된 error는 error boundary가 잡습니다.

Uncaught exceptions are unexpected errors that indicate bugs or issues that should not occur during the normal flow of your application. These should be handled by throwing errors, which will then be caught by error boundaries.

Nested error boundaries중첩된 error boundary

Next.js는 처리되지 않은 exception을 다루기 위해 error boundary를 사용합니다. error boundary는 child component에서 발생한 error를 잡아, 충돌한 component tree 대신 fallback UI를 표시합니다.

Next.js uses error boundaries to handle uncaught exceptions. Error boundaries catch errors in their child components and display a fallback UI instead of the component tree that crashed.

route segment 안에 error.js 파일을 추가하고 React component를 export해서 error boundary를 만드세요:

Create an error boundary by adding an error.js file inside a route segment and exporting a React component:

TSJSapp/dashboard/error.tsx
'use client' // Error boundaries must be Client Components

import { useEffect } from 'react'

export default function ErrorPage({
  error,
  retry,
}: {
  error: unknown
  retry: () => void
}) {
  useEffect(() => {
    // Log the error to an error reporting service
    console.error(error)
  }, [error])

  return (
    <div>
      <h2>Something went wrong!</h2>
      <button
        onClick={
          // Attempt to recover by re-fetching and re-rendering the segment
          () => retry()
        }
      >
        Try again
      </button>
    </div>
  )
}

error는 가장 가까운 상위 error boundary로 전파(bubble up)됩니다. 따라서 route hierarchy의 여러 수준에 error.tsx 파일을 배치해 세밀하게 error를 처리할 수 있습니다.

Errors will bubble up to the nearest parent error boundary. This allows for granular error handling by placing error.tsx files at different levels in the route hierarchy.

component 수준의 error 복구에는 catchError 함수를 사용하면 component tree의 어느 부분이든 감쌀 수 있는 error boundary를 만들 수 있습니다:

For component-level error recovery, the catchError function lets you create error boundaries that can wrap any part of your component tree:

TSJSapp/custom-error-boundary.tsx
'use client'

import { catchError, type ErrorInfo } from 'next/error'

function ErrorFallback(props: { title: string }, { error, retry }: ErrorInfo) {
  const message = error instanceof Error ? error.message : String(error)

  return (
    <div>
      <h2>{props.title}</h2>
      <p>{message}</p>
      <button onClick={() => retry()}>Try again</button>
    </div>
  )
}

export default catchError(ErrorFallback)

그런 다음 반환된 component를 어떤 layout이나 page에서든 wrapper로 사용하세요:

Then use the returned component as a wrapper in any layout or page:

TSJSapp/some-component.tsx
import ErrorBoundary from './custom-error-boundary'

export default function Component({ children }: { children: React.ReactNode }) {
  return <ErrorBoundary title="Dashboard Error">{children}</ErrorBoundary>
}
import ErrorBoundary from './custom-error-boundary'

export default function Component({ children }) {
  return <ErrorBoundary title="Dashboard Error">{children}</ErrorBoundary>
}

error boundary는 event handler 안의 error를 잡지 않습니다. error boundary는 앱 전체가 충돌하는 대신 fallback UI를 보여 주기 위해 rendering 중에 발생한 error를 잡도록 설계되었습니다.

Error boundaries don't catch errors inside event handlers. They're designed to catch errors during rendering to show a fallback UI instead of crashing the whole app.

일반적으로 event handler나 async 코드의 error는 rendering 이후에 실행되기 때문에 error boundary가 처리하지 않습니다.

In general, errors in event handlers or async code aren’t handled by error boundaries because they run after rendering.

이런 경우를 처리하려면 error를 직접 catch해서 useState나 useReducer로 저장한 다음, UI를 업데이트해 사용자에게 알리세요.

To handle these cases, catch the error manually and store it using useState or useReducer, then update the UI to inform the user.

'use client'

import { useState } from 'react'

export function Button() {
  const [error, setError] = useState(null)

  const handleClick = () => {
    try {
      // do some work that might fail
      throw new Error('Exception')
    } catch (reason) {
      setError(reason)
    }
  }

  if (error) {
    /* render fallback UI */
  }

  return (
    <button type="button" onClick={handleClick}>
      Click me
    </button>
  )
}

단, useTransition의 startTransition 안에서 처리되지 않은 error는 가장 가까운 error boundary로 전파된다는 점에 유의하세요.

Note that unhandled errors inside startTransition from useTransition, will bubble up to the nearest error boundary.

'use client'

import { useTransition } from 'react'

export function Button() {
  const [pending, startTransition] = useTransition()

  const handleClick = () =>
    startTransition(() => {
      throw new Error('Exception')
    })

  return (
    <button type="button" onClick={handleClick}>
      Click me
    </button>
  )
}

Global errorsGlobal error

흔하지는 않지만, internationalization을 활용하는 경우에도 root app directory에 있는 global-error.js 파일을 사용해 root layout의 error를 처리할 수 있습니다. global error UI는 활성화되면 root layout이나 template을 대체하므로 자체 <html>과 <body> tag를 정의해야 합니다.

While less common, you can handle errors in the root layout using the global-error.js file, located in the root app directory, even when leveraging internationalization. Global error UI must define its own <html> and <body> tags, since it is replacing the root layout or template when active.

TSJSapp/global-error.tsx
'use client' // Error boundaries must be Client Components

export default function GlobalError({
  error,
  retry,
}: {
  error: unknown
  retry: () => void
}) {
  return (
    // global-error must include html and body tags
    <html>
      <body>
        <h2>Something went wrong!</h2>
        <button onClick={() => retry()}>Try again</button>
      </body>
    </html>
  )
}
'use client' // Error boundaries must be Client Components

  return (
    // global-error must include html and body tags
    <html>
      <body>
        <h2>Something went wrong!</h2>
        <button onClick={() => retry()}>Try again</button>
      </body>
    </html>
  )
}
