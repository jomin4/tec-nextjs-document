getInitialPropsgetInitialProps

Good to know

getInitialProps는 legacy API입니다. 대신 getStaticProps나 getServerSideProps를 사용하는 것을 권장합니다.

getInitialProps is a legacy API. We recommend using getStaticProps or getServerSideProps instead.

getInitialProps는 page의 default export React component에 추가할 수 있는 async 함수입니다. server-side에서 실행되고, page 전환 시 client-side에서도 다시 실행됩니다. 함수의 결과는 props로 React component에 전달됩니다.

getInitialProps is an async function that can be added to the default exported React component for the page. It will run on both the server-side and again on the client-side during page transitions. The result of the function will be forwarded to the React component as props.

TSJSpages/index.tsx
import { NextPageContext } from 'next'

Page.getInitialProps = async (ctx: NextPageContext) => {
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const json = await res.json()
  return { stars: json.stargazers_count }
}

export default function Page({ stars }: { stars: number }) {
  return stars
}

Good to know
  • getInitialProps에서 반환된 data는 server rendering 시 serialize됩니다. getInitialProps가 반환하는 object가 Date, Map, Set을 사용하지 않는 plain Object인지 확인하세요.
  • 최초 page 로드 시에는 getInitialProps가 server에서만 실행됩니다. 이후 next/link component나 next/router를 사용해 다른 route로 이동할 때는 client에서도 getInitialProps가 실행됩니다.
  • custom _app.js에서 getInitialProps를 사용하고 이동하려는 page가 getServerSideProps를 사용한다면, getInitialProps는 server에서만 실행됩니다.
  • Data returned from getInitialProps is serialized when server rendering. Ensure the returned object from getInitialProps is a plain Object, and not using Date, Map or Set.
  • For the initial page load, getInitialProps will run on the server only. getInitialProps will then also run on the client when navigating to a different route with the next/link component or by using next/router.
  • If getInitialProps is used in a custom _app.js, and the page being navigated to is using getServerSideProps, then getInitialProps will only run on the server.

Context ObjectContext 객체

getInitialProps는 context라는 하나의 argument를 받으며, 이는 다음 property를 가진 object입니다:

getInitialProps receives a single argument called context, which is an object with the following properties:

NameDescription
pathname현재 route, 즉 /pages 안에서의 page path
queryobject로 parse된 URL의 query string
asPath브라우저에 표시되는 실제 path(query 포함)의 String
reqHTTP request object (server 전용)
resHTTP response object (server 전용)
errrendering 중 error가 발생한 경우의 Error object
NameDescription
pathnameCurrent route, the path of the page in /pages
queryQuery string of the URL, parsed as an object
asPathString of the actual path (including the query) shown in the browser
reqHTTP request object (server only)
resHTTP response object (server only)
errError object if any error is encountered during the rendering

Caveats주의 사항

  • getInitialProps는 pages/ 최상위 파일에서만 사용할 수 있으며, nested component에서는 사용할 수 없습니다. component 수준에서 nested data fetching을 하려면 App Router를 살펴보세요.
  • route가 static이든 dynamic이든 관계없이, getInitialProps에서 props로 반환된 모든 data는 client-side의 initial HTML에서 확인할 수 있습니다. 이는 page가 올바르게 hydrate될 수 있도록 하기 위함입니다. client에 노출되면 안 되는 민감한 정보를 props로 전달하지 않도록 주의하세요.
  • getInitialProps can only be used in pages/ top level files, and not in nested components. To have nested data fetching at the component level, consider exploring the App Router.
  • Regardless of whether your route is static or dynamic, any data returned from getInitialProps as props will be able to be examined on the client-side in the initial HTML. This is to allow the page to be hydrated correctly. Make sure that you don't pass any sensitive information that shouldn't be available on the client in props.
