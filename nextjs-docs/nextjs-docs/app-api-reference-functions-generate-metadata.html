generateMetadatagenerateMetadata

metadata object나 generateMetadata 함수를 사용해 metadata를 정의할 수 있습니다.

You can use the metadata object or the generateMetadata function to define metadata.

The metadata objectmetadata object

static metadata를 정의하려면 layout.js 또는 page.js 파일에서 Metadata object를 export하세요.

To define static metadata, export a Metadata object from a layout.js or page.js file.

TSJSlayout.tsx | page.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: '...',
  description: '...',
}

export default function Page() {}
export const metadata = {
  title: '...',
  description: '...',
}

export default function Page() {}

지원되는 option의 전체 목록은 Metadata Fields를 참고하세요.

See the Metadata Fields for a complete list of supported options.

generateMetadata functiongenerateMetadata 함수

현재 route parameter, 외부 데이터, parent segment의 metadata 같은 dynamic 정보에 의존하는 dynamic metadata는 Metadata object를 반환하는 generateMetadata 함수를 export해서 설정할 수 있습니다.

Dynamic metadata depends on dynamic information, such as the current route parameters, external data, or metadata in parent segments, can be set by exporting a generateMetadata function that returns a Metadata object.

generateMetadata를 resolve하는 과정은 페이지 rendering의 일부입니다. 페이지가 prerender될 수 있고 generateMetadata가 dynamic 동작을 일으키지 않는다면, 결과 metadata는 페이지의 initial HTML에 포함됩니다.

Resolving generateMetadata is part of rendering the page. If the page can be prerendered and generateMetadata doesn't introduce dynamic behavior, the resulting metadata is included in the page's initial HTML.

그렇지 않으면 generateMetadata에서 resolve된 metadata는 initial UI를 보낸 뒤 stream될 수 있습니다.

Otherwise the metadata resolved from generateMetadata can be streamed after sending the initial UI.

TSJSapp/products/[id]/page.tsx
import type { Metadata, ResolvingMetadata } from 'next'

type Props = {
  params: Promise<{ id: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}

export async function generateMetadata(
  { params, searchParams }: Props,
  parent: ResolvingMetadata
): Promise<Metadata> {
  // read route params
  const { id } = await params

  // fetch data
  const product = await fetch(`https://.../${id}`).then((res) => res.json())

  // optionally access and extend (rather than replace) parent metadata
  const previousImages = (await parent).openGraph?.images || []

  return {
    title: product.title,
    openGraph: {
      images: ['/some-specific-page-image.jpg', ...previousImages],
    },
  }
}

export default function Page({ params, searchParams }: Props) {}
export async function generateMetadata({ params, searchParams }, parent) {
  // read route params
  const { id } = await params

  // fetch data
  const product = await fetch(`https://.../${id}`).then((res) => res.json())

  // optionally access and extend (rather than replace) parent metadata
  const previousImages = (await parent).openGraph?.images || []

  return {
    title: product.title,
    openGraph: {
      images: ['/some-specific-page-image.jpg', ...previousImages],
    },
  }
}

export default function Page({ params, searchParams }) {}

params와 searchParams의 type completion을 위해, page에서는 PageProps<'/route'>로, layout에서는 LayoutProps<'/route'>로 첫 번째 argument의 type을 지정할 수 있습니다.

For type completion of params and searchParams, you can type the first argument with PageProps<'/route'> or LayoutProps<'/route'> for pages and layouts respectively.

Good to know
  • Metadata는 layout.js와 page.js 파일에 추가할 수 있습니다.
  • Next.js는 metadata를 자동으로 resolve하고 페이지에 맞는 <head> tag를 생성합니다.
  • metadata object와 generateMetadata 함수 export는 Server Component에서만 지원됩니다.
  • 같은 route segment에서 metadata object와 generateMetadata 함수를 동시에 export할 수 없습니다.
  • generateMetadata 안의 fetch request는 generateMetadata, generateStaticParams, Layout, Page, Server Component 전반에서 같은 데이터에 대해 자동으로 memoize됩니다.
  • fetch를 사용할 수 없다면 React cache를 사용할 수 있습니다.
  • File-based metadata가 더 높은 우선순위를 가지며 metadata object와 generateMetadata 함수를 override합니다.
  • Metadata can be added to layout.js and page.js files.
  • Next.js will automatically resolve the metadata, and create the relevant <head> tags for the page.
  • The metadata object and generateMetadata function exports are only supported in Server Components.
  • You cannot export both the metadata object and generateMetadata function from the same route segment.
  • fetch requests inside generateMetadata are automatically memoized for the same data across generateMetadata, generateStaticParams, Layouts, Pages, and Server Components.
  • React cache can be used if fetch is unavailable.
  • File-based metadata has the higher priority and will override the metadata object and generateMetadata function.

Why generateMetadata is Server Component onlygenerateMetadata가 Server Component 전용인 이유

generateMetadata와 metadata export는 Server Component에서만 지원됩니다. metadata는 page component가 render되기 전에 server에서 resolve되어야 하기 때문입니다. 이렇게 해야 Next.js가 initial HTML response에 metadata를 포함할 수 있습니다.

generateMetadata and the metadata export are only supported in Server Components because metadata must be resolved on the server before the page component is rendered. This allows Next.js to include the metadata in the initial HTML response.

Client Component 기능을 사용해야 한다면 page.tsx는 Server Component로 유지하고, Client Component 로직은 별도 파일로 옮기세요:

If you need to use Client Component features, keep your page.tsx as a Server Component and move the Client Component logic to a separate file:

TSJSapp/page.tsx
import type { Metadata } from 'next'
import { InteractiveComponent } from './interactive-component'

export const metadata: Metadata = {
  title: 'My Page',
}

export default function Page() {
  return <InteractiveComponent />
}
import { InteractiveComponent } from './interactive-component'

export const metadata = {
  title: 'My Page',
}

export default function Page() {
  return <InteractiveComponent />
}
TSJSapp/interactive-component.tsx
'use client'

export function InteractiveComponent() {
  // Client-side interactivity (hooks, event handlers, etc.)
}
'use client'

export function InteractiveComponent() {
  // Client-side interactivity (hooks, event handlers, etc.)
}

Reference

Parameters

generateMetadata 함수는 다음 parameter를 받습니다:

generateMetadata function accepts the following parameters:

  • props - 현재 route의 parameter를 담은 object:

    • params - root segment부터 generateMetadata가 호출되는 segment까지의 dynamic route parameters object를 담은 object입니다. 예시:

      RouteURLparams
      app/shop/[slug]/page.js/shop/1{ slug: '1' }
      app/shop/[tag]/[item]/page.js/shop/1/2{ tag: '1', item: '2' }
      app/shop/[...slug]/page.js/shop/1/2{ slug: ['1', '2'] }

    • searchParams - 현재 URL의 search params를 담은 object입니다. 예시:

      URLsearchParams
      /shop?a=1{ a: '1' }
      /shop?a=1&b=2{ a: '1', b: '2' }
      /shop?a=1&a=2{ a: ['1', '2'] }
  • parent - parent route segment에서 resolve된 metadata의 promise입니다.
  • props - An object containing the parameters of the current route:

    • params - An object containing the dynamic route parameters object from the root segment down to the segment generateMetadata is called from. Examples:

      RouteURLparams
      app/shop/[slug]/page.js/shop/1{ slug: '1' }
      app/shop/[tag]/[item]/page.js/shop/1/2{ tag: '1', item: '2' }
      app/shop/[...slug]/page.js/shop/1/2{ slug: ['1', '2'] }

    • searchParams - An object containing the current URL's search params. Examples:

      URLsearchParams
      /shop?a=1{ a: '1' }
      /shop?a=1&b=2{ a: '1', b: '2' }
      /shop?a=1&a=2{ a: ['1', '2'] }
  • parent - A promise of the resolved metadata from parent route segments.

Returns

generateMetadata는 하나 이상의 metadata field를 담은 Metadata object를 반환해야 합니다.

generateMetadata should return a Metadata object containing one or more metadata fields.

Good to know
  • metadata가 request 정보에 의존하지 않는다면 generateMetadata 대신 static metadata object로 정의해야 합니다.
  • fetch request는 generateMetadata, generateStaticParams, Layout, Page, Server Component 전반에서 같은 데이터에 대해 자동으로 memoize됩니다. fetch를 사용할 수 없다면 React cache를 사용할 수 있습니다.
  • searchParams는 page.js segment에서만 사용할 수 있습니다.
  • Next.js의 redirect()와 notFound() method도 generateMetadata 안에서 사용할 수 있습니다.
  • If metadata doesn't depend on request information, it should be defined using the static metadata object rather than generateMetadata.
  • fetch requests are automatically memoized for the same data across generateMetadata, generateStaticParams, Layouts, Pages, and Server Components. React cache can be used if fetch is unavailable.
  • searchParams are only available in page.js segments.
  • The redirect() and notFound() Next.js methods can also be used inside generateMetadata.

Metadata Fields

다음 field가 지원됩니다:

The following fields are supported:

title

title attribute는 문서의 제목을 설정하는 데 사용됩니다. 단순한 string이나 선택적인 template object로 정의할 수 있습니다.

The title attribute is used to set the title of the document. It can be defined as a simple string or an optional template object.

String
JSlayout.js | page.js
export const metadata = {
  title: 'Next.js',
}
<head> output
<title>Next.js</title>
default

title.default는 title을 정의하지 않은 child route segment에 fallback title을 제공하는 데 사용할 수 있습니다.

title.default can be used to provide a fallback title to child route segments that don't define a title.

TSapp/layout.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    default: 'Acme',
  },
}
TSapp/about/page.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {}

// Output: <title>Acme</title>
template

title.template은 child route segment에서 정의된 titles에 prefix나 suffix를 추가하는 데 사용할 수 있습니다.

title.template can be used to add a prefix or a suffix to titles defined in child route segments.

TSJSapp/layout.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    template: '%s | Acme',
    default: 'Acme', // a default is required when creating a template
  },
}
export const metadata = {
  title: {
    template: '%s | Acme',
    default: 'Acme', // a default is required when creating a template
  },
}
TSJSapp/about/page.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'About',
}

// Output: <title>About | Acme</title>
export const metadata = {
  title: 'About',
}

// Output: <title>About | Acme</title>
Good to know
  • title.template은 정의된 segment 자체가 아니라 child route segment에 적용됩니다. 즉:
    • title.template을 추가할 때는 title.default가 필수입니다.
    • layout.js에서 정의한 title.template은 같은 route segment의 page.js에서 정의한 title에는 적용되지 않습니다.
    • page는 항상 마지막(terminating) segment이므로(child route segment가 없음) page.js에서 정의한 title.template은 아무 효과가 없습니다.
  • route가 title이나 title.default를 정의하지 않았다면 title.template은 아무 효과가 없습니다.
  • title.template applies to child route segments and not the segment it's defined in. This means:
    • title.default is required when you add a title.template.
    • title.template defined in layout.js will not apply to a title defined in a page.js of the same route segment.
    • title.template defined in page.js has no effect because a page is always the terminating segment (it doesn't have any children route segments).
  • title.template has no effect if a route has not defined a title or title.default.
absolute

title.absolute는 parent segment에서 설정한 title.template을 무시하는 title을 제공하는 데 사용할 수 있습니다.

title.absolute can be used to provide a title that ignores title.template set in parent segments.

TSJSapp/layout.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    template: '%s | Acme',
  },
}
export const metadata = {
  title: {
    template: '%s | Acme',
  },
}
TSJSapp/about/page.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: {
    absolute: 'About',
  },
}

// Output: <title>About</title>
export const metadata = {
  title: {
    absolute: 'About',
  },
}

// Output: <title>About</title>
Good to know
  • layout.js
    • title(string)과 title.default는 (자체 title을 정의하지 않은) child segment의 기본 title을 정의합니다. 가장 가까운 parent segment에 title.template이 있으면 그것으로 보강됩니다.
    • title.absolute는 child segment의 기본 title을 정의합니다. parent segment의 title.template은 무시합니다.
    • title.template은 child segment를 위한 새 title template을 정의합니다.
  • page.js
    • page가 자체 title을 정의하지 않으면 가장 가까운 parent에서 resolve된 title이 사용됩니다.
    • title(string)은 route의 title을 정의합니다. 가장 가까운 parent segment에 title.template이 있으면 그것으로 보강됩니다.
    • title.absolute는 route title을 정의합니다. parent segment의 title.template은 무시합니다.
    • page는 항상 route의 마지막 segment이므로 page.js에서 title.template은 아무 효과가 없습니다.
  • layout.js
    • title (string) and title.default define the default title for child segments (that do not define their own title). It will augment title.template from the closest parent segment if it exists.
    • title.absolute defines the default title for child segments. It ignores title.template from parent segments.
    • title.template defines a new title template for child segments.
  • page.js
    • If a page does not define its own title the closest parents resolved title will be used.
    • title (string) defines the routes title. It will augment title.template from the closest parent segment if it exists.
    • title.absolute defines the route title. It ignores title.template from parent segments.
    • title.template has no effect in page.js because a page is always the terminating segment of a route.

metadataBase

metadataBase는 fully qualified URL이 필요한 metadata field에 base URL prefix를 설정하는 편의 option입니다.

metadataBase is a convenience option to set a base URL prefix for metadata fields that require a fully qualified URL.

  • metadataBase를 사용하면 현재 route segment와 그 하위에서 정의된 URL 기반 metadata field가 원래 필요한 absolute URL 대신 relative path를 사용할 수 있습니다.
  • field의 relative path는 metadataBase와 합쳐져 fully qualified URL이 됩니다.
  • metadataBase allows URL-based metadata fields defined in the current route segment and below to use a relative path instead of an otherwise required absolute URL.
  • The field's relative path will be composed with metadataBase to form a fully qualified URL.
JSlayout.js | page.js
export const metadata = {
  metadataBase: new URL('https://acme.com'),
  alternates: {
    canonical: '/',
    languages: {
      'en-US': '/en-US',
      'de-DE': '/de-DE',
    },
  },
  openGraph: {
    images: '/og-image.png',
  },
}
<head> output
<link rel="canonical" href="https://acme.com" />
<link rel="alternate" hreflang="en-US" href="https://acme.com/en-US" />
<link rel="alternate" hreflang="de-DE" href="https://acme.com/de-DE" />
<meta property="og:image" content="https://acme.com/og-image.png" />
Good to know
  • metadataBase는 보통 root app/layout.js에 설정해 모든 route의 URL 기반 metadata field에 적용합니다.
  • generateMetadata가 'use cache'를 사용할 때는 반환값이 serializable해야 합니다. URL instance는 Cache Function에서 지원되지 않으므로, metadataBase 같은 값은 문자열로 반환해야 합니다(예: url.toString()). use cache serialization 요구 사항을 참고하세요.
  • absolute URL이 필요한 모든 URL 기반 metadata field는 metadataBase option으로 설정할 수 있습니다.
  • metadataBase에는 https://app.acme.com 같은 subdomain이나 https://acme.com/start/from/here 같은 base path를 포함할 수 있습니다.
  • metadata field가 absolute URL을 제공하면 metadataBase는 무시됩니다.
  • metadataBase를 설정하지 않고 URL 기반 metadata field에 relative path를 사용하면 build error가 발생합니다.
  • Next.js는 metadataBase(예: https://acme.com/)와 relative field(예: /path) 사이의 중복 slash를 하나의 slash로 정규화합니다(예: https://acme.com/path).
  • metadataBase is typically set in root app/layout.js to apply to URL-based metadata fields across all routes.
  • When generateMetadata uses 'use cache', its return value must be serializable. URL instances are not supported by Cache Functions, so values such as metadataBase should be returned as strings (for example, url.toString()). See use cache serialization requirements.
  • All URL-based metadata fields that require absolute URLs can be configured with a metadataBase option.
  • metadataBase can contain a subdomain e.g. https://app.acme.com or base path e.g. https://acme.com/start/from/here
  • If a metadata field provides an absolute URL, metadataBase will be ignored.
  • Using a relative path in a URL-based metadata field without configuring a metadataBase will cause a build error.
  • Next.js will normalize duplicate slashes between metadataBase (e.g. https://acme.com/) and a relative field (e.g. /path) to a single slash (e.g. https://acme.com/path)

URL CompositionURL 조합

URL 조합은 기본 directory 탐색 방식보다 개발자의 의도를 우선합니다.

URL composition favors developer intent over default directory traversal semantics.

  • metadataBase와 metadata field 사이의 trailing slash는 정규화됩니다.
  • metadata field의 "absolute" path(일반적으로 URL path 전체를 대체하는 것)는 "relative" path(metadataBase의 끝에서부터 시작)로 취급됩니다.
  • Trailing slashes between metadataBase and metadata fields are normalized.
  • An "absolute" path in a metadata field (that typically would replace the whole URL path) is treated as a "relative" path (starting from the end of metadataBase).

예를 들어 다음과 같은 metadataBase가 있다고 하면:

For example, given the following metadataBase:

TSJSapp/layout.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  metadataBase: new URL('https://acme.com'),
}
export const metadata = {
  metadataBase: new URL('https://acme.com'),
}

<link> element에는 외부 resource가 필요할 가능성이 높다는 것을 브라우저에 hint로 알려 주는 여러 rel keyword가 있습니다. 브라우저는 이 정보를 이용해 keyword에 따라 preloading 최적화를 적용합니다.

The <link> element has a number of rel keywords that can be used to hint to the browser that an external resource is likely to be needed. The browser uses this information to apply preloading optimizations depending on the keyword.

Metadata API는 이 hint들을 직접 지원하지 않지만, 새로운 ReactDOM method를 사용해 문서의 <head>에 안전하게 삽입할 수 있습니다.

While the Metadata API doesn't directly support these hints, you can use new ReactDOM methods to safely insert them into the <head> of the document.

  ReactDOM.preconnect('...', { crossOrigin: '...' })
  ReactDOM.prefetchDNS('...')

  return '...'
}

Streaming metadata

Streaming metadata를 사용하면 Next.js가 generateMetadata가 완료되기를 기다리지 않고 initial UI를 render해 브라우저로 보낼 수 있습니다.

Streaming metadata allows Next.js to render and send the initial UI to the browser, without waiting for generateMetadata to complete.

generateMetadata가 resolve되면 결과 metadata tag가 <body> tag에 추가됩니다. JavaScript를 실행하고 전체 DOM을 검사하는 bot(예: Googlebot)이 metadata를 올바르게 해석한다는 것을 확인했습니다.

When generateMetadata resolves, the resulting metadata tags are appended to the <body> tag. We have verified that metadata is interpreted correctly by bots that execute JavaScript and inspect the full DOM (e.g. Googlebot).

JavaScript를 실행할 수 없는 HTML-limited bot(예: facebookexternalhit)에 대해서는 metadata가 계속 페이지 rendering을 block합니다. 결과 metadata는 <head> tag에서 사용할 수 있습니다.

For HTML-limited bots that can’t execute JavaScript (e.g. facebookexternalhit), metadata continues to block page rendering. The resulting metadata will be available in the <head> tag.

Next.js는 User Agent header를 보고 HTML-limited bot을 자동으로 감지합니다. Next.js config 파일의 htmlLimitedBots option을 사용해 기본 User Agent 목록을 override할 수 있습니다.

Next.js automatically detects HTML-limited bots by looking at the User Agent header. You can use the htmlLimitedBots option in your Next.js config file to override the default User Agent list.

streaming metadata를 완전히 비활성화하려면:

To fully disable streaming metadata:

TSJSnext.config.ts
import type { NextConfig } from 'next'

const config: NextConfig = {
  htmlLimitedBots: /.*/,
}

export default config
module.exports = {
  htmlLimitedBots: /.*/,
}

Streaming metadata는 TTFB를 줄여 체감 성능을 높이고, LCP 시간을 낮추는 데 도움이 될 수 있습니다.

Streaming metadata improves perceived performance by reducing TTFB and can help lowering LCP time.

htmlLimitedBots를 override하면 response 시간이 길어질 수 있습니다. Streaming metadata는 고급 기능이며, 대부분의 경우 기본값으로 충분합니다.

Overriding htmlLimitedBots could lead to longer response times. Streaming metadata is an advanced feature, and the default should be sufficient for most cases.

With Cache ComponentsCache Components와 함께 사용하기

Cache Components가 활성화되어 있으면 generateMetadata는 다른 component와 같은 규칙을 따릅니다. metadata가 runtime 데이터(cookies(), headers(), params, searchParams)에 접근하거나 cache되지 않은 data fetching을 수행하면 request time으로 미뤄집니다.

When Cache Components is enabled, generateMetadata follows the same rules as other components. If metadata accesses runtime data (cookies(), headers(), params, searchParams) or performs uncached data fetching, it defers to request time.

Next.js가 이를 처리하는 방식은 페이지의 나머지 부분에 따라 달라집니다:

How Next.js handles this depends on the rest of your page:

  • 다른 부분도 request time으로 미뤄지는 경우: prerendering이 static shell을 생성하고, metadata는 다른 지연된 콘텐츠와 함께 stream됩니다.
  • page나 layout이 그 외에는 완전히 prerender 가능한 경우: Next.js는 명시적인 선택을 요구합니다. 가능하면 데이터를 cache하거나, 지연된 rendering이 의도된 것임을 알려야 합니다.
  • If other parts also defer to request time: Prerendering generates a static shell, and metadata streams in with other deferred content.
  • If the page or layout is otherwise fully prerenderable: Next.js requires an explicit choice: cache the data if possible, or signal that deferred rendering is intentional.

페이지의 나머지 부분이 완전히 prerender 가능한데 metadata만 runtime에 stream하는 경우는 흔하지 않습니다. 이 동작이 의도된 것인지 확인하기 위해, 어떤 page나 layout을 처리해야 하는지 알려 주는 error가 발생합니다.

Streaming metadata at runtime while the rest of the page is fully prerenderable is not common. To ensure this behavior is intentional, an error is raised indicating which page or layout needs to be handled.

이를 해결하는 방법은 두 가지입니다. metadata가 외부 데이터에는 의존하지만 runtime 데이터에는 의존하지 않는다면 use cache를 사용하세요:

To resolve this, you have two options. If metadata depends on external data but not runtime data, use use cache:

TSapp/page.tsx
export async function generateMetadata() {
  'use cache'
  const { title, description } = await db.query('site-metadata')
  return { title, description }
}

metadata가 정말로 runtime 데이터를 필요로 한다면 페이지에 dynamic marker component를 추가하세요:

If metadata genuinely requires runtime data, add a dynamic marker component to your page:

TSapp/page.tsx
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { connection } from 'next/server'

export async function generateMetadata() {
  const token = (await cookies()).get('token')?.value
  // ... use token to fetch personalized metadata
  return { title: 'Personalized Title' }
}

const Connection = async () => {
  await connection()
  return null
}

async function DynamicMarker() {
  return (
    <Suspense>
      <Connection />
    </Suspense>
  )
}

export default function Page() {
  // DO NOT place await connection() here
  // doing so prevents the article tag content from
  // being included in the static shell
  return (
    <>
      <article>Static content</article>
      <DynamicMarker />
    </>
  )
}

DynamicMarker component는 아무것도 render하지 않지만, 페이지에 의도된 dynamic 콘텐츠가 있다는 것을 Next.js에 알려 줍니다. 이를 Suspense로 감싸면 static 콘텐츠는 여전히 정상적으로 prerender됩니다.

The DynamicMarker component renders nothing but tells Next.js the page has intentional dynamic content. By wrapping it in Suspense, the static content still prerenders normally.

전체 해결 방법과 trade-off는 Next.js encountered runtime data in generateMetadata()와 Next.js encountered uncached data in generateMetadata()를 참고하세요.

See Next.js encountered runtime data in generateMetadata() and Next.js encountered uncached data in generateMetadata() for full fix options and trade-offs.

Ordering순서

Metadata는 root segment부터 최종 page.js segment에 가장 가까운 segment까지 순서대로 평가됩니다. 예를 들면 다음과 같습니다:

Metadata is evaluated in order, starting from the root segment down to the segment closest to the final page.js segment. For example:

  1. app/layout.tsx (Root Layout)
  2. app/blog/layout.tsx (중첩된 Blog Layout)
  3. app/blog/[slug]/page.tsx (Blog Page)
  1. app/layout.tsx (Root Layout)
  2. app/blog/layout.tsx (Nested Blog Layout)
  3. app/blog/[slug]/page.tsx (Blog Page)

Merging병합

평가 순서에 따라, 같은 route의 여러 segment에서 export된 Metadata object는 shallow하게 병합되어 route의 최종 metadata 결과가 됩니다. 중복된 key는 순서에 따라 대체됩니다.

Following the evaluation order, Metadata objects exported from multiple segments in the same route are shallowly merged together to form the final metadata output of a route. Duplicate keys are replaced based on their ordering.

즉, 앞선 segment에서 정의한 openGraph나 robots 같은 중첩 field를 가진 metadata는 마지막으로 이를 정의한 segment에 의해 덮어써집니다.

This means metadata with nested fields such as openGraph and robots that are defined in an earlier segment are overwritten by the last segment to define them.

Overwriting fieldsfield 덮어쓰기

JSapp/layout.js
export const metadata = {
  title: 'Acme',
  openGraph: {
    title: 'Acme',
    description: 'Acme is a...',
  },
}
JSapp/blog/page.js
export const metadata = {
  title: 'Blog',
  openGraph: {
    title: 'Blog',
  },
}

// Output:
// <title>Blog</title>
// <meta property="og:title" content="Blog" />

위 예제에서:

In the example above:

  • app/layout.js의 title은 app/blog/page.js의 title로 대체됩니다.
  • app/blog/page.js가 openGraph metadata를 설정하므로 app/layout.js의 모든 openGraph field가 app/blog/page.js에서 대체됩니다. openGraph.description이 없다는 점에 주목하세요.
  • title from app/layout.js is replaced by title in app/blog/page.js.
  • All openGraph fields from app/layout.js are replaced in app/blog/page.js because app/blog/page.js sets openGraph metadata. Note the absence of openGraph.description.

일부 중첩 field는 segment 간에 공유하고 나머지는 덮어쓰고 싶다면, 공유할 field를 별도 변수로 분리할 수 있습니다:

If you'd like to share some nested fields between segments while overwriting others, you can pull them out into a separate variable:

JSapp/shared-metadata.js
export const openGraphImage = { images: ['http://...'] }
JSapp/page.js
import { openGraphImage } from './shared-metadata'

export const metadata = {
  openGraph: {
    ...openGraphImage,
    title: 'Home',
  },
}
JSapp/about/page.js
import { openGraphImage } from '../shared-metadata'

export const metadata = {
  openGraph: {
    ...openGraphImage,
    title: 'About',
  },
}

위 예제에서 OG 이미지는 app/layout.js와 app/about/page.js 간에 공유되지만 title은 서로 다릅니다.

In the example above, the OG image is shared between app/layout.js and app/about/page.js while the titles are different.

export const metadata = {

Notes

Notes

  • app/layout.js의 title은 app/about/page.js의 title로 대체됩니다.
  • app/about/page.js가 openGraph metadata를 설정하지 않으므로 app/layout.js의 모든 openGraph field가 app/about/page.js에 상속됩니다.
