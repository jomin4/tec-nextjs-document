useSelectedLayoutSegmentuseSelectedLayoutSegment

useSelectedLayoutSegment는 자신이 호출된 Layout보다 한 단계 아래에 있는 활성 route segment를 읽을 수 있게 해 주는 Client Component hook입니다.

useSelectedLayoutSegment is a Client Component hook that lets you read the active route segment one level below the Layout it is called from.

활성 child segment에 따라 style이 바뀌는 parent layout 안의 tab처럼, navigation UI에 유용합니다.

It is useful for navigation UI, such as tabs inside a parent layout that change style depending on the active child segment.

TSJSapp/example-client-component.tsx
'use client'

import { useSelectedLayoutSegment } from 'next/navigation'

export default function ExampleClientComponent() {
  const segment = useSelectedLayoutSegment()

  return <p>Active segment: {segment}</p>
}
'use client'

import { useSelectedLayoutSegment } from 'next/navigation'

export default function ExampleClientComponent() {
  const segment = useSelectedLayoutSegment()

  return <p>Active segment: {segment}</p>
}
Good to know
  • useSelectedLayoutSegment는 Client Component hook이고 Layout은 기본적으로 Server Components이므로, useSelectedLayoutSegment는 보통 Layout에 import된 Client Component를 통해 호출됩니다.
  • useSelectedLayoutSegment는 한 단계 아래의 segment만 반환합니다. 모든 활성 segment를 반환하려면 useSelectedLayoutSegments를 참고하세요
  • catch-all route의 경우, match된 segment들이 하나로 합쳐진 string으로 반환됩니다. 예를 들어 app/blog/[...slug]/page.js가 있을 때 /blog/a/b/c를 방문하면서 app/blog/layout.js에서 호출하면 'a/b/c'가 반환됩니다.
  • Since useSelectedLayoutSegment is a Client Component hook, and Layouts are Server Components by default, useSelectedLayoutSegment is usually called via a Client Component that is imported into a Layout.
  • useSelectedLayoutSegment only returns the segment one level down. To return all active segments, see useSelectedLayoutSegments
  • For catch-all routes, the matched segments are returned as a single joined string. For example, given app/blog/[...slug]/page.js, calling from app/blog/layout.js when visiting /blog/a/b/c returns 'a/b/c'.

Parameters

const segment = useSelectedLayoutSegment(parallelRouteKey?: string)

useSelectedLayoutSegment는 선택적으로 parallelRouteKey를 받으며, 이를 통해 해당 slot 안의 활성 route segment를 읽을 수 있습니다.

useSelectedLayoutSegment optionally accepts a parallelRouteKey, which allows you to read the active route segment within that slot.

Returns

useSelectedLayoutSegment는 활성 segment의 string을 반환하며, 활성 segment가 없으면 null을 반환합니다.

useSelectedLayoutSegment returns a string of the active segment or null if one doesn't exist.

Behavior동작

Cache Components

cacheComponents가 활성화되어 있으면 useSelectedLayoutSegment에 Suspense boundary가 필요할 수 있습니다. 이는 prerendering 중에 활성 segment를 resolve할 수 있는지에 따라 달라집니다.

When cacheComponents is enabled, useSelectedLayoutSegment may require a Suspense boundary. This depends on whether the active segment can be resolved during prerendering.

  • Static route와 generateStaticParams가 있는 route: dynamic param을 포함한 모든 route segment를 build 시점에 알 수 있습니다. prerendering 중에 활성 segment를 resolve할 수 있으므로 useSelectedLayoutSegment는 server에서 resolve되며 Suspense boundary가 필요하지 않습니다.
  • generateStaticParams로 다루지 않는 dynamic param이 있는 route: 이 param은 request 시점까지 알 수 없는 fallback param입니다. prerendering 중에 활성 segment를 resolve할 수 없으므로 useSelectedLayoutSegment는 suspend됩니다. prerendering 중에 fallback이 render될 수 있도록 component(또는 상위 component)를 Suspense boundary로 감싸세요. 그렇지 않으면 build가 실패합니다.
  • Static routes and routes with generateStaticParams: every route segment, including dynamic params, is known at build time. The active segment can be resolved during prerendering, so useSelectedLayoutSegment resolves on the server and no Suspense boundary is required.
  • Routes with dynamic params not covered by generateStaticParams: the param is a fallback param that is not known until request time. The active segment cannot be resolved during prerendering, so useSelectedLayoutSegment suspends. Wrap the component (or a parent) in a Suspense boundary so its fallback can be rendered during prerendering; otherwise, the build fails.

이는 useSelectedLayoutSegment를 호출하는 component 자체가 static인 경우에도 적용됩니다. 예를 들어 parent layout에서 render되는 tab bar는, 그 아래에 있는 page 중 알 수 없는 dynamic param을 가진 page에서 suspend됩니다. layout의 나머지 부분을 prerender된 상태로 유지하려면 useSelectedLayoutSegment를 호출하는 component(또는 상위 component)를 fallback이 있는 Suspense boundary로 감싸세요.

This applies even when the component that calls useSelectedLayoutSegment is itself static. For example, a tab bar rendered in a parent layout suspends on any page below it that has an unknown dynamic param. To keep the rest of the layout prerendered, wrap the component that calls useSelectedLayoutSegment (or a parent) in a Suspense boundary with a fallback.

전체 해결 방법과 trade-off는 Next.js encountered URL data in a Client Component outside of Suspense를 참고하세요.

See Next.js encountered URL data in a Client Component outside of Suspense for full fix options and trade-offs.

Examples예시

Creating an active link componentactive link component 만들기

useSelectedLayoutSegment를 사용해 활성 segment에 따라 style이 바뀌는 active link component를 만들 수 있습니다. 예를 들어 블로그 sidebar의 추천 글 목록이 있습니다:

You can use useSelectedLayoutSegment to create an active link component that changes style depending on the active segment. For example, a featured posts list in the sidebar of a blog:

TSJSapp/blog/blog-nav-link.tsx
'use client'

import Link from 'next/link'
import { useSelectedLayoutSegment } from 'next/navigation'

// This *client* component will be imported into a blog layout
export default function BlogNavLink({
  slug,
  children,
}: {
  slug: string
  children: React.ReactNode
}) {
  // Navigating to `/blog/hello-world` will return 'hello-world'
  // for the selected layout segment
  const segment = useSelectedLayoutSegment()
  const isActive = slug === segment

  return (
    <Link
      href={`/blog/${slug}`}
      // Change style depending on whether the link is active
      style={{ fontWeight: isActive ? 'bold' : 'normal' }}
    >
      {children}
    </Link>
  )
}

TSJSapp/blog/layout.tsx
// Import the Client Component into a parent Layout (Server Component)
import { BlogNavLink } from './blog-nav-link'
import getFeaturedPosts from './get-featured-posts'

export default async function Layout({
  children,
}: {
  children: React.ReactNode
}) {
  const featuredPosts = await getFeaturedPosts()
  return (
    <div>
      {featuredPosts.map((post) => (
        <div key={post.id}>
          <BlogNavLink slug={post.slug}>{post.title}</BlogNavLink>
        </div>
      ))}
      <div>{children}</div>
    </div>
  )
}
