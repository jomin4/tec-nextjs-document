catchErrorcatchError

catchError 함수는 children을 error boundary로 감싸는 component를 만듭니다. error.js file convention의 프로그래밍 방식 대안을 제공하여, component tree 어디에서든 component 레벨의 error 복구를 가능하게 합니다.

The catchError function creates a component that wraps its children in an error boundary. It provides a programmatic alternative to the error.js file convention, enabling component-level error recovery anywhere in your component tree.

custom React error boundary와 비교해 catchError는 별도 설정 없이 Next.js와 함께 동작하도록 설계되었습니다:

Compared to a custom React error boundary, catchError is designed to work with Next.js out of the box:

  • Built-in error recovery — retry()는 Transition 안에서 페이지를 다시 rendering하여 error boundary 바깥의 Client Component state를 보존합니다.
  • Framework-aware integration — redirect()와 notFound() 같은 API는 내부적으로 special error를 throw하는 방식으로 동작합니다. catchError는 이를 매끄럽게 처리하므로 error boundary에 실수로 잡히지 않습니다.
  • Client navigation handling — 다른 route로 client navigation을 하면 error state가 자동으로 초기화됩니다.
  • Built-in error recovery — retry() re-renders the page inside a Transition, preserving Client Components state outside of the error boundary.
  • Framework-aware integration — APIs like redirect() and notFound() work by throwing special errors under the hood. catchError handles these seamlessly, so they're not accidentally caught by your error boundary.
  • Client navigation handling — The error state automatically clears when you do a client navigation to a different route.

catchError는 Client Components에서 호출할 수 있습니다.

catchError can be called from Client Components.

TSJSapp/custom-error-boundary.tsx
'use client'

import { catchError, type ErrorInfo } from 'next/error'

function ErrorFallback(props: { title: string }, { error, retry }: ErrorInfo) {
  const message = error instanceof Error ? error.message : String(error)

  return (
    <div>
      <h2>{props.title}</h2>
      <p>{message}</p>
      <button onClick={() => retry()}>Try again</button>
    </div>
  )
}

export default catchError(ErrorFallback)

Parameters

catchError는 하나의 인자를 받습니다:

catchError accepts a single argument:

const ErrorWrapper = catchError(fallback)

fallback

error가 잡혔을 때 error UI를 rendering하는 함수입니다. 두 개의 인자를 받습니다:

A function that renders the error UI when an error is caught. It receives two arguments:

  • props — wrapper component에 전달된 props (children 제외).
  • errorInfo — error 정보를 담은 객체:
  • props — The props passed to the wrapper component (excluding children).
  • errorInfo — An object containing information about the error:
PropertyTypeDescription
errorunknownthrow된 값입니다. message 같은 속성을 읽기 전에 예를 들어 instanceof Error로 type을 좁히세요(narrow).
retry() => voiderror boundary의 children을 다시 fetch하고 다시 rendering합니다. 성공하면 fallback이 다시 rendering된 결과로 교체됩니다.
reset() => voiderror state를 초기화하고 다시 fetch하지 않고 다시 rendering합니다. 대부분의 경우 retry()를 사용하세요.
PropertyTypeDescription
errorunknownThe value that was thrown. Narrow it, for example with instanceof Error, before reading properties like message.
retry() => voidRe-fetches and re-renders the error boundary's children. If successful, the fallback is replaced with the re-rendered result.
reset() => voidResets the error state and re-renders without re-fetching. Use retry() in most cases.

fallback 함수는 Client Component여야 합니다(또는 'use client' module 안에 정의되어야 합니다).

The fallback function must be a Client Component (or defined in a 'use client' module).

Returns

catchError는 다음과 같은 React component를 반환합니다:

catchError returns a React component that:

  • fallback의 첫 번째 인자와 같은 props에 children을 더한 props를 받습니다.
  • children을 error boundary로 감쌉니다.
  • children에서 error가 잡히면 fallback을 rendering합니다.
  • Accepts the same props as your fallback's first argument, plus children.
  • Wraps children in an error boundary.
  • Renders the fallback when an error is caught in children.

Recovering from errorsError에서 복구하기

retry()를 사용해 사용자가 error에서 복구하도록 유도하세요. 호출되면 이 함수는 error boundary의 children을 다시 fetch하고 다시 rendering합니다. 성공하면 fallback이 다시 rendering된 결과로 교체됩니다.

Use retry() to prompt the user to recover from the error. When called, the function re-fetches and re-renders the error boundary's children. If successful, the fallback is replaced with the re-rendered result.

대부분의 경우 reset() 대신 retry()를 사용하세요. reset() 함수는 error state만 초기화하고 다시 fetch하지 않고 다시 rendering하므로 Server Component error에서는 복구되지 않습니다.

In most cases, use retry() instead of reset(). The reset() function only clears the error state and re-renders without re-fetching, which means it won't recover from Server Component errors.

TSJSapp/custom-error-boundary.tsx
'use client'

import { catchError, type ErrorInfo } from 'next/error'

function ErrorFallback(props: {}, { error, retry, reset }: ErrorInfo) {
  const message = error instanceof Error ? error.message : String(error)

  return (
    <div>
      <p>{message}</p>
      <button onClick={() => retry()}>Try again</button>
      <button onClick={() => reset()}>Reset</button>
    </div>
  )
}

export default catchError(ErrorFallback)

Server-rendered error fallback서버에서 rendering한 error fallback

서버에서 rendering한 콘텐츠를 prop으로 전달해 데이터 기반 fallback UI를 표시할 수 있습니다. 이는 Server Component를 React.ReactNode prop으로 rendering하고, error가 잡혔을 때 fallback이 이를 표시하는 방식으로 동작합니다.

You can pass server-rendered content as a prop to display data-driven fallback UI. This works by rendering a Server Component as a React.ReactNode prop that the fallback displays when an error is caught.

Good to know

이 패턴은 error가 발생하지 않더라도 모든 페이지 render마다 fallback을 미리(eagerly) rendering합니다. 대부분의 use case에서는 더 간단한 client-side fallback으로 충분합니다.

This pattern eagerly renders the fallback on every page render, even when no error occurs. For most use cases, a simpler client-side fallback is sufficient.

TSJSapp/error-boundary.tsx
'use client'

import { catchError, type ErrorInfo } from 'next/error'

function ErrorFallback(
  props: { fallback: React.ReactNode },
  errorInfo: ErrorInfo
) {
  return props.fallback
}

export default catchError(ErrorFallback)
'use client'

import { catchError } from 'next/error'

function ErrorFallback(props, errorInfo) {
  return props.fallback
}

export default catchError(ErrorFallback)
TSJSapp/some-component.tsx
import ErrorBoundary from '../error-boundary'

async function ErrorFallback() {
  const data = await getData()
  return <div>{data.message}</div>
}

export default function Component({ children }: { children: React.ReactNode }) {
  return <ErrorBoundary fallback={<ErrorFallback />}>{children}</ErrorBoundary>
}

Good to know
  • route segment 단위로 범위가 정해지는 error.js file convention과 달리, catchError는 component tree의 어느 부분이든 감싸 component 레벨의 error 복구에 사용할 수 있습니다.
  • wrapper component에 전달된 props는 fallback 함수로 전달되므로, 설정을 달리한 재사용 가능한 error UI를 쉽게 만들 수 있습니다.
  • error.js의 default export를 catchError로 감쌀 필요는 없습니다. error.js file convention은 이미 Next.js가 제공하는 내장 error boundary 안에서 rendering됩니다.
  • Unlike the error.js file convention which is scoped to route segments, catchError can be used to wrap any part of your component tree for component-level error recovery.
  • Props passed to the wrapper component are forwarded to the fallback function, making it easy to create reusable error UIs with different configurations.
  • You don't need to wrap error.js default exports with catchError. The error.js file convention already renders inside a built-in error boundary provided by Next.js.
