CodemodsCodemod

Codemod는 codebase에 프로그램 방식으로 실행되는 변환(transformation)입니다. 이를 통해 모든 파일을 일일이 직접 손대지 않고도 많은 양의 변경을 프로그램으로 적용할 수 있습니다.

Codemods are transformations that run on your codebase programmatically. This allows a large number of changes to be programmatically applied without having to manually go through every file.

Next.js는 API가 업데이트되거나 deprecated될 때 Next.js codebase를 upgrade할 수 있도록 Codemod transformation을 제공합니다.

Next.js provides Codemod transformations to help upgrade your Next.js codebase when an API is updated or deprecated.

Usage사용법

terminal에서 프로젝트 폴더로 이동(cd)한 다음 실행하세요:

In your terminal, navigate (cd) into your project's folder, then run:

>_Terminal
npx @next/codemod <transform> <path>

<transform>과 <path>를 적절한 값으로 바꾸세요.

Replacing <transform> and <path> with appropriate values.

  • transform - transform 이름
  • path - 변환할 파일 또는 directory
  • --dry dry-run을 실행하며, 코드는 수정되지 않습니다
  • --print 비교할 수 있도록 변경된 output을 출력합니다
  • transform - name of transform
  • path - files or directory to transform
  • --dry Do a dry-run, no code will be edited
  • --print Prints the changed output for comparison

Upgrade업그레이드

Next.js 애플리케이션을 upgrade하며, codemod를 자동으로 실행하고 Next.js, React, React DOM을 업데이트합니다.

Upgrades your Next.js application, automatically running codemods and updating Next.js, React, and React DOM.

coding agent가 codemod를 실행하고, 남은 migration 작업을 마무리하고, 앱을 검증하게 하려면 대신 npx next@canary upgrade --agent=latest를 실행하세요. 자세한 내용은 Upgrade with a coding agent를 참고하세요.

To have a coding agent run the codemods, complete the remaining migration work, and verify the app, run npx next@canary upgrade --agent=latest instead. See Upgrade with a coding agent for details.

>_Terminal
npx @next/codemod upgrade [revision]

Options옵션

  • revision(선택): upgrade 유형(patch, minor, major), NPM dist tag(예: latest, canary, rc), 또는 정확한 버전(예: 15.0.0)을 지정합니다. stable 버전에서는 기본값이 minor입니다.
  • --verbose: upgrade 과정에서 더 자세한 output을 보여 줍니다.
  • --skip-react-upgrade: React dependency, type, override를 그대로 유지하고 React codemod를 건너뜁니다.
  • --skip-eslint-upgrade: eslint, eslint-config-next, @next/eslint-plugin-next를 그대로 유지하고 next-lint-to-eslint-cli를 건너뜁니다. 검증 전에 필요한 lint migration은 직접 완료하세요.
  • -y, --yes: 모든 interactive prompt를 건너뛰고 기본값을 받아들입니다(React 18 이후 버전으로 upgrade, Turbopack 활성화, 권장 codemod 모두 적용, React 19 codemod 실행). stdin이 TTY가 아닐 때(CI, AI coding agent, 또는 모든 non-interactive shell)도 자동으로 활성화되므로, 보통은 직접 넘길 필요가 없습니다.
  • revision (optional): Specify the upgrade type (patch, minor, major), an NPM dist tag (e.g. latest, canary, rc), or an exact version (e.g. 15.0.0). Defaults to minor for stable versions.
  • --verbose: Show more detailed output during the upgrade process.
  • --skip-react-upgrade: Preserve React dependencies, types, and overrides, and skip React codemods.
  • --skip-eslint-upgrade: Preserve eslint, eslint-config-next, @next/eslint-plugin-next, and skip next-lint-to-eslint-cli. Complete required lint migrations manually before verification.
  • -y, --yes: Skip every interactive prompt and accept its default (upgrade React past 18, enable Turbopack, apply all recommended codemods, run the React 19 codemods). Also auto-enabled when stdin is not a TTY (CI, an AI coding agent, or any non-interactive shell), so you usually don't need to pass it explicitly.

예를 들면 다음과 같습니다:

For example:

>_Terminal
# Upgrade to the latest patch (e.g. 16.0.7 -> 16.0.8)
npx @next/codemod upgrade patch

# Upgrade to the latest minor (e.g. 15.3.7 -> 15.4.8). This is the default.
npx @next/codemod upgrade minor

# Upgrade to the latest major (e.g. 15.5.7 -> 16.0.7)
npx @next/codemod upgrade major

# Upgrade to a specific version
npx @next/codemod upgrade 16

# Upgrade to the canary release
npx @next/codemod upgrade canary

# Run from an agent or CI: skip every prompt
npx @next/codemod upgrade canary --yes
Good to know
  • target 버전이 현재 버전과 같거나 더 낮으면 command는 아무것도 바꾸지 않고 종료됩니다.
  • skip flag는 target의 peer dependency 요구 사항을 우회하지 않습니다. 이전에 설치가 실패했다면 dependency를 고친 다음 해당 flag와 함께 똑같은 target으로 다시 시도하세요. Next.js가 이미 target과 일치한다면 건너뛴 migration을 아래 guide에 따라 개별적으로 실행하세요.
  • upgrade 중에 어떤 Next.js codemod를 적용할지 선택하라는 prompt가 나올 수 있고, React를 upgrade하는 경우 React 19 codemod를 실행할지 묻는 prompt가 나올 수 있습니다.
  • AI coding agent가 호출하거나 CI에서 실행되면(stdin이 TTY가 아닌 모든 환경) upgrade는 non-interactive로 실행되며 모든 기본값을 받아들입니다. terminal에서도 이 동작을 강제하려면 --yes를 넘기세요.
  • If the target version is the same as or lower than your current version, the command exits without making changes.
  • The skip flags do not bypass the target's peer dependency requirements. If installation previously failed, repair the dependencies and retry the same exact target with the relevant flag. If Next.js already matches the target, run any skipped migrations individually using the guides below.
  • During the upgrade, you may be prompted to choose which Next.js codemods to apply and run React 19 codemods if upgrading React.
  • When invoked by an AI coding agent or in CI (anywhere stdin isn't a TTY), the upgrade runs non-interactively and accepts every default. Pass --yes to force this behavior even from a terminal.

Opt every route out of Cache Components validation모든 route를 Cache Components validation에서 제외하기

cache-components-instant-false
>_Terminal
npx @next/codemod@canary cache-components-instant-false ./app

이 codemod는 app directory에서 아직 instant를 export하지 않는 모든 {page,layout,default} 파일에 export const instant = false를 추가합니다. 덕분에 cacheComponents를 활성화한 다음 route별로 opt-out을 하나씩 제거할 수 있습니다. Client Component("use client")와 이미 instant를 선언한 파일은 건너뜁니다. 생성되는 @next-codemod-ignore comment는 compile을 막지 않으면서 의도적인 opt-out임을 표시합니다.

This codemod adds export const instant = false to every {page,layout,default} file in your app directory that doesn't already export instant, so you can enable cacheComponents and then remove the opt-outs route by route. It skips Client Components ("use client") and files that already declare instant. The generated @next-codemod-ignore comment marks the intentional opt-out without blocking compilation.

Good to know

src/ 프로젝트에서는 ./src/app을 넘기세요. 잘못된 경로를 주면 실패하지 않고 0 ok를 보고하므로 파일 수를 확인하세요.

Pass ./src/app in a src/ project. A wrong path reports 0 ok instead of failing, so check the file count.

+ // Remove this opt-out after verifying the segment passes validation without it.

Migrate to async Dynamic APIsasync Dynamic API로 migrate하기

이전에 동기(synchronous) 접근을 지원하던, dynamic rendering을 사용하게 만드는 API들이 이제 비동기(asynchronous)가 되었습니다. 이 breaking change에 대한 자세한 내용은 upgrade guide에서 읽을 수 있습니다.

APIs that opted into dynamic rendering that previously supported synchronous access are now asynchronous. You can read more about this breaking change in the upgrade guide.

next-async-request-api
>_Terminal
npx @next/codemod@latest next-async-request-api .

이 codemod는 이제 비동기가 된 dynamic API(next/headers의 cookies(), headers(), draftMode())를 올바르게 await하거나, 해당되는 경우 React.use()로 감싸도록 변환합니다. 자동 migration이 불가능한 경우 codemod는 @next-codemod-error comment를 추가하고 임시 UnsafeUnwrapped* cast를 추가할 수 있습니다. 이를 제거하기 전에 migration을 완료하세요. 제안된 변경이 맞지 않으면 directive를 @next-codemod-ignore로 바꾸고 그 이유를 설명하세요.

This codemod will transform dynamic APIs (cookies(), headers() and draftMode() from next/headers) that are now asynchronous to be properly awaited or wrapped with React.use() if applicable. When automatic migration isn't possible, the codemod adds an @next-codemod-error comment and may add a temporary UnsafeUnwrapped* cast. Complete the migration before removing them. If the suggested change doesn't apply, replace the directive with @next-codemod-ignore and explain why.

예시는 Async Request APIs migration guide를 참고하세요.

See the Async Request APIs migration guide for examples.

예를 들면 다음과 같습니다:

For example:

import { cookies, headers } from 'next/headers'
const token = cookies().get('token')

function useToken() {
  const token = cookies().get('token')
  return token
}

export default function Page() {
  const name = cookies().get('name')
}

function getHeader() {
  return headers().get('x-foo')
}

다음과 같이 변환됩니다:

Transforms into:

import { use } from 'react'
import {
  cookies,
  headers,
  type UnsafeUnwrappedCookies,
  type UnsafeUnwrappedHeaders,
} from 'next/headers'
const token =
  /* @next-codemod-error Await this API and update its callers; remove the temporary UnsafeUnwrappedCookies cast after repairing the migration. */
  (cookies() as unknown as UnsafeUnwrappedCookies).get('token')

function useToken() {
  const token = use(cookies()).get('token')
  return token
}

export default async function Page() {
  const name = (await cookies()).get('name')
}

function getHeader() {
  return (
    /* @next-codemod-error Await this API and update its callers; remove the temporary UnsafeUnwrappedHeaders cast after repairing the migration. */
    (headers() as unknown as UnsafeUnwrappedHeaders).get('x-foo')
  )
}

page / route entry(page.js, layout.js, route.js, default.js)나 generateMetadata / generateViewport API에서 params 또는 searchParams props의 property 접근이 감지되면, codemod는 callsite를 sync 함수에서 async 함수로 변환하고 property 접근을 await하려고 시도합니다. async로 만들 수 없는 경우(Client Component 등)에는 React.use를 사용해 promise를 unwrap합니다.

When we detect property access on the params or searchParams props in the page / route entries (page.js, layout.js, route.js, or default.js) or the generateMetadata / generateViewport APIs, it will attempt to transform the callsite from a sync to an async function, and await the property access. If it can't be made async (such as with a Client Component), it will use React.use to unwrap the promise .

예를 들면 다음과 같습니다:

For example:

// page.tsx
export default function Page({
  params,
  searchParams,
}: {
  params: { slug: string }
  searchParams: { [key: string]: string | string[] | undefined }
}) {
  const { value } = searchParams
  if (value === 'foo') {
    // ...
  }
}

export function generateMetadata({ params }: { params: { slug: string } }) {
  const { slug } = params
  return {
    title: `My Page - ${slug}`,
  }
}

다음과 같이 변환됩니다:

Transforms into:

// page.tsx
export default async function Page(props: {
  params: Promise<{ slug: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const searchParams = await props.searchParams
  const { value } = searchParams
  if (value === 'foo') {
    // ...
  }
}

export async function generateMetadata(props: {
  params: Promise<{ slug: string }>
}) {
  const params = await props.params
  const { slug } = params
  return {
    title: `My Page - ${slug}`,
  }
}
Good to know

이 codemod가 수동 개입이 필요할 수 있는 지점을 찾았지만 정확한 수정 방법을 판단할 수 없는 경우, 코드에 comment나 typecast를 추가해 사용자가 직접 업데이트해야 한다는 것을 알려 줍니다. 이 comment에는 @next/codemod prefix가 붙고, typecast에는 UnsafeUnwrapped prefix가 붙습니다. 이 comment들을 명시적으로 제거하기 전까지 build에서 error가 발생합니다. 자세히 알아보기.

When this codemod identifies a spot that might require manual intervention, but we aren't able to determine the exact fix, it will add a comment or typecast to the code to inform the user that it needs to be manually updated. These comments are prefixed with @next/codemod, and typecasts are prefixed with UnsafeUnwrapped. Your build will error until these comments are explicitly removed. Read more.

    }
  }
