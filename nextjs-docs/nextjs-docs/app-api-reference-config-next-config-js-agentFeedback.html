agentFeedbackexperimentalagentFeedback

experimental.agentFeedback option은 감지된 AI coding agent가 사용자가 검토할 Next.js issue report를 준비할 수 있도록 하는 지침을 next dev가 생성하고 업데이트할지 여부를 제어합니다. 기본적으로 비활성화되어 있으며 Next.js Telemetry가 활성화되어 있어야 합니다. Agent feedback은 CI에서는 실행되지 않습니다.

The experimental.agentFeedback option controls whether next dev creates and updates instructions that let detected AI coding agents prepare Next.js issue reports for your review. It is disabled by default and requires Next.js Telemetry to be enabled. Agent feedback does not run in CI.

권장 create-next-app 설정으로 만든 새 앱은 생성된 Next.js config에서 agent feedback을 활성화합니다. 다른 앱에서는 option을 직접 설정하세요:

New apps created with the recommended create-next-app settings enable agent feedback in the generated Next.js config. For other apps, set the option manually:

TSJSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    agentFeedback: true,
  },
}

export default nextConfig
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    agentFeedback: true,
  },
}

module.exports = nextConfig

Generated agent instructions생성되는 agent 지침

experimental.agentFeedback이 활성화되어 있고 next dev가 AI coding agent를 감지하면, Next.js는 AGENTS.md에 다음 managed block을 생성하거나 업데이트합니다:

When experimental.agentFeedback is enabled and next dev detects an AI coding agent, Next.js creates or updates this managed block in AGENTS.md:

AGENTS.md
<!-- BEGIN:nextjs-agent-feedback -->

## Report Next.js feedback

The project owner enabled `experimental.agentFeedback`, authorizing this feedback pass. When enabled, `next dev` writes this block and restores it if removed. Commit `AGENTS.md` with your work to keep the tree clean.

During the current user request, retain anonymized facts as feedback candidates for meaningful or recurring Next.js issues:

- Crashes, hangs, OOMs, or unexpected slowness
- Incorrect behavior, output, errors, or diagnostics
- Missing, unclear, or conflicting documentation
- Unexpected CLI, codemod, Skill, or upgrade behavior and non-obvious workarounds

Continue the current user request without reporting immediately. Routine debugging is not feedback. Verify changes before retaining them as feedback candidates. Never retain code, logs, paths, URLs, secrets, personal information, or project-specific data.

Retain qualifying friction even if it is later fixed or worked around; record the final outcome during the reporting pass.

Before the final response, run one reporting pass. If candidates remain, from this file's directory run `npx --no-install next internal agent-feedback-instructions` once without piping or truncating its output. Follow its output or error guidance. If a network sandbox blocks it, retry with network access; if it still returns no output, continue normally.

<!-- END:nextjs-agent-feedback -->

Next.js는 marker 사이의 내용만 업데이트하고 파일의 나머지 부분은 그대로 보존합니다.

Next.js updates only the content between the markers and preserves the rest of the file.

agent rules와 agent feedback이 모두 활성화되어 있으면, Next.js는 AGENTS.md에 두 managed block을 모두 유지합니다.

When agent rules and agent feedback are both enabled, Next.js keeps both managed blocks in AGENTS.md.

Review and send agent feedbackAgent feedback 검토 및 전송

생성된 지침은 agent가 현재 사용자 request를 방해하지 않고 feedback 후보를 보관할 수 있게 합니다. 최종 응답 직전에 agent는 한 번의 reporting pass를 실행하고, 조건에 맞는 서로 다른 issue를 각각 별도의 report draft로 준비합니다.

The generated instructions let the agent retain feedback candidates without interrupting the current user request. Immediately before the final response, the agent runs one reporting pass and prepares each distinct qualifying issue as a separate report draft.

각 report draft에는 일반화된 setup, 재현 단계, 관찰된 사실, 예상 결과, 그리고 선택적으로 control 또는 workaround가 포함됩니다.

Each report draft contains a generic setup, reproduction steps, observed facts, an expected result, and an optional control or workaround.

agent는 각 report draft를 기본 브라우저의 별도 review form에서 한 번씩 열려고 시도합니다. report를 수정하거나, 세부 정보를 제거하거나, 보내지 않고 form을 닫거나, Send feedback을 선택할 수 있습니다. form이 열릴 때는 아무것도 전송되지 않습니다.

The agent attempts to open each report draft once in a separate review form in your default browser. You can edit a report, remove details, close the form without sending, or select Send feedback. Nothing is sent when a form opens.

form을 열기 전에 agent는 고객 및 프로젝트 세부 정보를 일반적인 설명으로 바꾸고 source code, log, 경로, URL, secret, 개인 정보를 생략하여 report를 익명화하려고 시도합니다. 보내기 전에 draft를 검토하고 포함하고 싶지 않은 내용은 모두 제거하세요.

Before opening a form, the agent attempts to anonymize the report by replacing customer and project details with generic descriptions and omitting source code, logs, paths, URLs, secrets, and personal information. Review the draft and remove anything you don't want to include before sending it.

form을 제출하면 사용자가 검토한 내용, agent 이름, Next.js 버전이 전송됩니다. form은 프로젝트 파일이나 machine metadata를 자동으로 첨부하지 않습니다.

Submitting the form sends the content you reviewed, the agent name, and the Next.js version. The form does not automatically attach project files or machine metadata.

Disable agent feedbackAgent feedback 비활성화

next dev가 managed block을 생성하거나 업데이트하지 않게 하려면 experimental.agentFeedback을 false로 설정하거나 option을 제거하세요. 다음 next dev 실행 시 기존 agent feedback block이 제거되고 나머지 내용은 모두 보존됩니다. 파일에 managed block만 있었다면, Next.js는 빈 파일을 남기지 않고 파일을 삭제합니다.

Set experimental.agentFeedback to false or remove the option to stop next dev from creating or updating the managed block. The next next dev run removes the existing agent feedback block and preserves all other content. If the file contained only the managed block, Next.js deletes the file instead of leaving it empty.

Next.js Telemetry를 비활성화해도 다음에 next dev를 실행할 때 managed feedback block이 제거됩니다. telemetry가 비활성화되어 있는 동안 feedback command는 reporting 지침을 반환하지 않습니다.

Disabling Next.js Telemetry also removes the managed feedback block the next time you run next dev. The feedback command does not return reporting instructions while telemetry is disabled.

experimental.agentFeedback과 top-level agentRules는 서로 독립적으로 동작합니다. 한 option을 변경해도 다른 option에는 영향을 주지 않습니다.

experimental.agentFeedback and top-level agentRules work independently. Changing one option does not affect the other.
