How to use debugging tools with Next.jsNext.js에서 debugging 도구 사용하기

이 문서는 VS Code debugger, Chrome DevTools, Firefox DevTools를 사용해 source map을 완전히 지원하는 상태로 Next.js frontend와 backend 코드를 debug하는 방법을 설명합니다.

This documentation explains how you can debug your Next.js frontend and backend code with full source maps support using the VS Code debugger, Chrome DevTools, or Firefox DevTools.

Node.js에 attach할 수 있는 debugger라면 무엇이든 Next.js 애플리케이션을 debug하는 데 사용할 수 있습니다. 자세한 내용은 Node.js Debugging Guide에서 확인할 수 있습니다.

Any debugger that can attach to Node.js can also be used to debug a Next.js application. You can find more details in the Node.js Debugging Guide.

Debugging with VS CodeVS Code로 debugging하기

프로젝트 root에 다음 내용으로 .vscode/launch.json 파일을 만드세요:

Create a file named .vscode/launch.json at the root of your project with the following content:

launch.json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Next.js: debug server-side",
      "type": "node-terminal",
      "request": "launch",
      "command": "npm run dev -- --inspect"
    },
    {
      "name": "Next.js: debug client-side",
      "type": "chrome",
      "request": "launch",
      "url": "http://localhost:3000"
    },
    {
      "name": "Next.js: debug client-side (Firefox)",
      "type": "firefox",
      "request": "launch",
      "url": "http://localhost:3000",
      "reAttach": true,
      "pathMappings": [
        {
          "url": "webpack://_N_E",
          "path": "${workspaceFolder}"
        }
      ]
    },
    {
      "name": "Next.js: debug full stack",
      "type": "node",
      "request": "launch",
      "program": "${workspaceFolder}/node_modules/next/dist/bin/next",
      "runtimeArgs": ["--inspect"],
      "skipFiles": ["<node_internals>/**"],
      "serverReadyAction": {
        "action": "debugWithEdge",
        "killOnServerStop": true,
        "pattern": "- Local:.+(https?://.+)",
        "uriFormat": "%s",
        "webRoot": "${workspaceFolder}"
      }
    }
  ]
}
Note

VS Code에서 Firefox debugging을 사용하려면 Firefox Debugger extension을 설치해야 합니다.

To use Firefox debugging in VS Code, you'll need to install the Firefox Debugger extension.

Yarn을 사용한다면 npm run dev를 yarn dev로, pnpm을 사용한다면 pnpm dev로 바꿔도 됩니다.

npm run dev can be replaced with yarn dev if you're using Yarn or pnpm dev if you're using pnpm.

"Next.js: debug full stack" configuration에서 serverReadyAction.action은 server가 준비되었을 때 어떤 브라우저를 열지 지정합니다. debugWithEdge는 Edge 브라우저를 실행한다는 뜻입니다. Chrome을 사용한다면 이 값을 debugWithChrome으로 바꾸세요.

In the "Next.js: debug full stack" configuration, serverReadyAction.action specifies which browser to open when the server is ready. debugWithEdge means to launch the Edge browser. If you are using Chrome, change this value to debugWithChrome.

애플리케이션이 시작되는 port 번호를 변경했다면, http://localhost:3000의 3000을 사용 중인 port로 바꾸세요.

If you're changing the port number your application starts on, replace the 3000 in http://localhost:3000 with the port you're using instead.

root가 아닌 다른 directory에서 Next.js를 실행한다면(예: Turborepo를 사용하는 경우) server-side와 full stack debugging task에 cwd를 추가해야 합니다. 예: "cwd": "${workspaceFolder}/apps/web".

If you're running Next.js from a directory other than root (for example, if you're using Turborepo) then you need to add cwd to the server-side and full stack debugging tasks. For example, "cwd": "${workspaceFolder}/apps/web".

이제 Debug panel(Windows/Linux에서는 Ctrl+Shift+D, macOS에서는 ⇧+⌘+D)로 이동해 launch configuration을 선택한 다음, F5를 누르거나 Command Palette에서 Debug: Start Debugging을 선택해 debugging session을 시작하세요.

Now go to the Debug panel (Ctrl+Shift+D on Windows/Linux, ⇧+⌘+D on macOS), select a launch configuration, then press F5 or select Debug: Start Debugging from the Command Palette to start your debugging session.

Using the Debugger in Jetbrains WebStormJetbrains WebStorm에서 Debugger 사용하기

runtime configuration 목록이 있는 drop down 메뉴를 클릭하고 Edit Configurations...를 클릭하세요. URL을 http://localhost:3000으로 하는 JavaScript Debug debug configuration을 만듭니다. 원하는 대로 설정(예: debugging용 브라우저, project 파일로 저장)한 뒤 OK를 클릭하세요. 이 debug configuration을 실행하면 선택한 브라우저가 자동으로 열립니다. 이 시점에는 debug mode인 애플리케이션이 2개 있어야 합니다: Next.js node 애플리케이션과 client/브라우저 애플리케이션입니다.

Click the drop down menu listing the runtime configuration, and click Edit Configurations.... Create a JavaScript Debug debug configuration with http://localhost:3000 as the URL. Customize to your liking (e.g. Browser for debugging, store as project file), and click OK. Run this debug configuration, and the selected browser should automatically open. At this point, you should have 2 applications in debug mode: the Next.js node application, and the client/browser application.

Debugging with Browser DevTools브라우저 DevTools로 debugging하기

Client-side codeClient-side 코드

평소처럼 next dev, npm run dev, yarn dev 중 하나를 실행해 development server를 시작하세요. server가 시작되면 선호하는 브라우저에서 http://localhost:3000(또는 대체 URL)을 여세요.

Start your development server as usual by running next dev, npm run dev, or yarn dev. Once the server starts, open http://localhost:3000 (or your alternate URL) in your preferred browser.

Chrome의 경우:

For Chrome:

  • Chrome Developer Tools 열기(Windows/Linux에서는 Ctrl+Shift+J, macOS에서는 ⌥+⌘+I)
  • Sources tab으로 이동
  • Open Chrome's Developer Tools (Ctrl+Shift+J on Windows/Linux, ⌥+⌘+I on macOS)
  • Go to the Sources tab

Firefox의 경우:

For Firefox:

  • Firefox Developer Tools 열기(Windows/Linux에서는 Ctrl+Shift+I, macOS에서는 ⌥+⌘+I)
  • Debugger tab으로 이동
  • Open Firefox's Developer Tools (Ctrl+Shift+I on Windows/Linux, ⌥+⌘+I on macOS)
  • Go to the Debugger tab

어느 브라우저에서든 client-side 코드가 debugger 문에 도달하면 코드 실행이 일시 정지되고 해당 파일이 debug 영역에 나타납니다. 파일을 검색해 breakpoint를 수동으로 설정할 수도 있습니다:

In either browser, any time your client-side code reaches a debugger statement, code execution will pause and that file will appear in the debug area. You can also search for files to set breakpoints manually:

  • Chrome: Windows/Linux에서는 Ctrl+P, macOS에서는 ⌘+P를 누르세요
  • Firefox: Windows/Linux에서는 Ctrl+P, macOS에서는 ⌘+P를 누르거나 왼쪽 panel의 file tree를 사용하세요
  • In Chrome: Press Ctrl+P on Windows/Linux or ⌘+P on macOS
  • In Firefox: Press Ctrl+P on Windows/Linux or ⌘+P on macOS, or use the file tree in the left panel

검색할 때 source 파일의 경로는 webpack://_N_E/./로 시작한다는 점에 유의하세요.

Note that when searching, your source files will have paths starting with webpack://_N_E/./.

React Developer Tools

React에 특화된 debugging을 하려면 React Developer Tools 브라우저 extension을 설치하세요. 이 필수 도구로 다음을 할 수 있습니다:

For React-specific debugging, install the React Developer Tools browser extension. This essential tool helps you:

  • React component 검사
  • props와 state 수정
  • performance 문제 파악
  • Inspect React components
  • Edit props and state
  • Identify performance problems

Server-side codeServer-side 코드

브라우저 DevTools로 server-side Next.js 코드를 debug하려면 --inspect flag를 전달해야 합니다:

To debug server-side Next.js code with browser DevTools, you need to pass the --inspect flag:

pnpm dev --inspect
npm run dev -- --inspect
yarn dev --inspect
bun run dev --inspect

--inspect의 값은 내부의 Node.js process로 전달됩니다. 고급 사용 사례는 --inspect 문서를 확인하세요.

The value of --inspect is passed to the underlying Node.js process. Check out the --inspect docs for advanced use cases.

Good to know

Docker container에서 앱을 실행하는 경우처럼 localhost 밖에서 원격 debugging 접근을 허용하려면 --inspect=0.0.0.0을 사용하세요.

Use --inspect=0.0.0.0 to allow remote debugging access outside localhost, such as when running the app in a Docker container.

--inspect flag로 Next.js server를 실행하면 다음과 비슷하게 표시됩니다:

Launching the Next.js server with the --inspect flag will look something like this:

>_Terminal
Debugger listening on ws://127.0.0.1:9229/0cf90313-350d-4466-a748-cd60f4e47c95
For help, see: https://nodejs.org/learn/getting-started/debugging
ready - started server on 0.0.0.0:3000, url: http://localhost:3000

Chrome의 경우:

For Chrome:

  1. 새 tab을 열고 chrome://inspect에 방문합니다
  2. Remote Target 섹션에서 Next.js 애플리케이션을 찾습니다
  3. inspect를 클릭해 별도의 DevTools 창을 엽니다
  4. Sources tab으로 이동합니다
  1. Open a new tab and visit chrome://inspect
  2. Look for your Next.js application in the Remote Target section
  3. Click inspect to open a separate DevTools window
  4. Go to the Sources tab

Firefox의 경우:

For Firefox:

  1. 새 tab을 열고 about:debugging에 방문합니다
  2. 왼쪽 sidebar에서 This Firefox를 클릭합니다
  3. Remote Targets 아래에서 Next.js 애플리케이션을 찾습니다
  4. Inspect를 클릭해 debugger를 엽니다
  5. Debugger tab으로 이동합니다
  1. Open a new tab and visit about:debugging
  2. Click This Firefox in the left sidebar
  3. Under Remote Targets, find your Next.js application
  4. Click Inspect to open the debugger
  5. Go to the Debugger tab

server-side 코드 debugging은 client-side debugging과 비슷하게 동작합니다. 파일을 검색할 때(Ctrl+P/⌘+P) source 파일의 경로는 webpack://{application-name}/./로 시작합니다({application-name}은 package.json 파일에 따른 애플리케이션 이름으로 대체됩니다).

Debugging server-side code works similarly to client-side debugging. When searching for files (Ctrl+P/⌘+P), your source files will have paths starting with webpack://{application-name}/./ (where {application-name} will be replaced with the name of your application according to your package.json file).

--inspect-brk나 --inspect-wait를 사용하려면 대신 NODE_OPTIONS를 지정해야 합니다. 예: NODE_OPTIONS=--inspect-brk next dev.

To use --inspect-brk or --inspect-wait, you have to specify NODE_OPTIONS instead. e.g. NODE_OPTIONS=--inspect-brk next dev.

Inspect Server Errors with Browser DevTools브라우저 DevTools로 Server Error 검사하기

error가 발생했을 때 source 코드를 검사하면 error의 근본 원인을 추적하는 데 도움이 됩니다.

When you encounter an error, inspecting the source code can help trace the root cause of errors.

Next.js는 error overlay의 Next.js version indicator 아래에 Node.js 아이콘을 표시합니다. 이 아이콘을 클릭하면 DevTools URL이 clipboard에 복사됩니다. 그 URL로 새 브라우저 tab을 열어 Next.js server process를 검사할 수 있습니다.

Next.js will display a Node.js icon underneath the Next.js version indicator on the error overlay. By clicking that icon, the DevTools URL is copied to your clipboard. You can open a new browser tab with that URL to inspect the Next.js server process.

Debugging on WindowsWindows에서 debugging하기

컴퓨터에서 Windows Defender가 비활성화되어 있는지 확인하세요. 이 외부 서비스는 *모든 파일 읽기*를 검사하는데, 이로 인해 next dev의 Fast Refresh 시간이 크게 늘어난다는 보고가 있습니다. 이는 Next.js와 관련 없는 알려진 문제이지만 Next.js 개발에 영향을 줍니다.

Ensure Windows Defender is disabled on your machine. This external service will check every file read, which has been reported to greatly increase Fast Refresh time with next dev. This is a known issue, not related to Next.js, but it does affect Next.js development.
