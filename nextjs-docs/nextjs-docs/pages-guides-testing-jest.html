How to set up Jest with Next.jsNext.js에 Jest 설정하기

Jest와 React Testing Library는 Unit Testing과 Snapshot Testing에 자주 함께 사용됩니다. 이 가이드에서는 Next.js에 Jest를 설정하고 첫 test를 작성하는 방법을 보여 줍니다.

Jest and React Testing Library are frequently used together for Unit Testing and Snapshot Testing. This guide will show you how to set up Jest with Next.js and write your first tests.

Good to know

async Server Component는 React ecosystem에서 새로운 개념이라 Jest는 현재 이를 지원하지 않습니다. 동기 Server Component와 Client Component에 대해서는 여전히 unit test를 실행할 수 있지만, async component에 대해서는 E2E test를 사용하는 것을 권장합니다.

Since async Server Components are new to the React ecosystem, Jest currently does not support them. While you can still run unit tests for synchronous Server and Client Components, we recommend using an E2E tests for async components.

Quickstart빠른 시작

Next.js with-jest example과 함께 create-next-app을 사용하면 빠르게 시작할 수 있습니다:

You can use create-next-app with the Next.js with-jest example to quickly get started:

pnpm create next-app --example with-jest with-jest-app
npx create-next-app@latest --example with-jest with-jest-app
yarn create next-app --example with-jest with-jest-app
bun create next-app --example with-jest with-jest-app

Manual setup수동 설정

Next.js 12가 release된 이후로 Next.js에는 Jest용 configuration이 내장되어 있습니다.

Since the release of Next.js 12, Next.js now has built-in configuration for Jest.

Jest를 설정하려면 jest와 다음 package들을 dev dependency로 설치하세요:

To set up Jest, install jest and the following packages as dev dependencies:

pnpm add -D jest jest-environment-jsdom @testing-library/react @testing-library/dom @testing-library/jest-dom ts-node @types/jest
npm install -D jest jest-environment-jsdom @testing-library/react @testing-library/dom @testing-library/jest-dom ts-node @types/jest
yarn add -D jest jest-environment-jsdom @testing-library/react @testing-library/dom @testing-library/jest-dom ts-node @types/jest
bun add -D jest jest-environment-jsdom @testing-library/react @testing-library/dom @testing-library/jest-dom ts-node @types/jest

다음 command를 실행해 기본 Jest configuration 파일을 생성하세요:

Generate a basic Jest configuration file by running the following command:

pnpm create jest@latest
npm init jest@latest
yarn create jest@latest
bun create jest@latest

일련의 prompt를 거치며 프로젝트에 Jest를 설정하게 되며, jest.config.ts|js 파일도 자동으로 만들어집니다.

This will take you through a series of prompts to set up Jest for your project, including automatically creating a jest.config.ts|js file.

config 파일이 next/jest를 사용하도록 업데이트하세요. 이 transformer에는 Jest가 Next.js와 함께 동작하는 데 필요한 모든 configuration option이 들어 있습니다:

Update your config file to use next/jest. This transformer has all the necessary configuration options for Jest to work with Next.js:

TSJSjest.config.ts
import type { Config } from 'jest'
import nextJest from 'next/jest.js'

const createJestConfig = nextJest({
  // Provide the path to your Next.js app to load next.config.js and .env files in your test environment
  dir: './',
})

// Add any custom config to be passed to Jest
const config: Config = {
  coverageProvider: 'v8',
  testEnvironment: 'jsdom',
  // Add more setup options before each test is run
  // setupFilesAfterEnv: ['<rootDir>/jest.setup.ts'],
}

// createJestConfig is exported this way to ensure that next/jest can load the Next.js config which is async
export default createJestConfig(config)
const nextJest = require('next/jest')

/** @type {import('jest').Config} */
const createJestConfig = nextJest({
  // Provide the path to your Next.js app to load next.config.js and .env files in your test environment
  dir: './',
})

// Add any custom config to be passed to Jest
const config = {
  coverageProvider: 'v8',
  testEnvironment: 'jsdom',
  // Add more setup options before each test is run
  // setupFilesAfterEnv: ['<rootDir>/jest.setup.ts'],
}

// createJestConfig is exported this way to ensure that next/jest can load the Next.js config which is async
module.exports = createJestConfig(config)

내부적으로 next/jest는 다음을 포함해 Jest를 자동으로 설정해 줍니다:

Under the hood, next/jest is automatically configuring Jest for you, including:

  • Next.js Compiler를 사용하도록 transform 설정.
  • stylesheet(.css, .module.css, 그리고 각각의 scss 변형), 이미지 import, next/font를 자동으로 mocking.
  • .env(및 모든 변형)를 process.env로 로드.
  • test resolving과 transform 대상에서 node_modules 제외.
  • test resolving 대상에서 .next 제외.
  • SWC transform을 활성화하는 flag를 위해 next.config.js 로드.
  • Setting up transform using the Next.js Compiler.
  • Auto mocking stylesheets (.css, .module.css, and their scss variants), image imports and next/font.
  • Loading .env (and all variants) into process.env.
  • Ignoring node_modules from test resolving and transforms.
  • Ignoring .next from test resolving.
  • Loading next.config.js for flags that enable SWC transforms.
Good to know

environment variable을 직접 test하려면 별도의 setup script나 jest.config.ts 파일에서 수동으로 로드하세요. 자세한 내용은 Test Environment Variables를 참고하세요.

To test environment variables directly, load them manually in a separate setup script or in your jest.config.ts file. For more information, please see Test Environment Variables.

Setting up Jest (with Babel)Jest 설정하기 (Babel 사용)

Next.js Compiler를 사용하지 않고 Babel을 대신 사용한다면, Jest를 수동으로 설정하고 위의 package들 외에 babel-jest와 identity-obj-proxy를 설치해야 합니다.

If you opt out of the Next.js Compiler and use Babel instead, you will need to manually configure Jest and install babel-jest and identity-obj-proxy in addition to the packages above.

Next.js용 Jest를 설정할 때 권장되는 option은 다음과 같습니다:

Here are the recommended options to configure Jest for Next.js:

JSjest.config.js
module.exports = {
  collectCoverage: true,
  // on node 14.x coverage provider v8 offers good speed and more or less good report
  coverageProvider: 'v8',
  collectCoverageFrom: [
    '**/*.{js,jsx,ts,tsx}',
    '!**/*.d.ts',
    '!**/node_modules/**',
    '!<rootDir>/out/**',
    '!<rootDir>/.next/**',
    '!<rootDir>/*.config.js',
    '!<rootDir>/coverage/**',
  ],
  moduleNameMapper: {
    // Handle CSS imports (with CSS modules)
    // https://jestjs.io/docs/webpack#mocking-css-modules
    '^.+\\.module\\.(css|sass|scss)$': 'identity-obj-proxy',

    // Handle CSS imports (without CSS modules)
    '^.+\\.(css|sass|scss)$': '<rootDir>/__mocks__/styleMock.js',

    // Handle image imports
    // https://jestjs.io/docs/webpack#handling-static-assets
    '^.+\\.(png|jpg|jpeg|gif|webp|avif|ico|bmp|svg)$': `<rootDir>/__mocks__/fileMock.js`,

    // Handle module aliases
    '^@/components/(.*)$': '<rootDir>/components/$1',

    // Handle @next/font
    '@next/font/(.*)': `<rootDir>/__mocks__/nextFontMock.js`,
    // Handle next/font
    'next/font/(.*)': `<rootDir>/__mocks__/nextFontMock.js`,
    // Disable server-only
    'server-only': `<rootDir>/__mocks__/empty.js`,
  },
  // Add more setup options before each test is run
  // setupFilesAfterEnv: ['<rootDir>/jest.setup.js'],
  testPathIgnorePatterns: ['<rootDir>/node_modules/', '<rootDir>/.next/'],
  testEnvironment: 'jsdom',
  transform: {
    // Use babel-jest to transpile tests with the next/babel preset
    // https://jestjs.io/docs/configuration#transform-objectstring-pathtotransformer--pathtotransformer-object
    '^.+\\.(js|jsx|ts|tsx)$': ['babel-jest', { presets: ['next/babel'] }],
  },
  transformIgnorePatterns: [
    '/node_modules/',
    '^.+\\.module\\.(css|sass|scss)$',
  ],
}

각 configuration option에 대한 자세한 내용은 Jest 문서에서 확인할 수 있습니다. Next.js가 Jest를 어떻게 설정하는지 보려면 next/jest configuration도 살펴보는 것을 권장합니다.

You can learn more about each configuration option in the Jest docs. We also recommend reviewing next/jest configuration to see how Next.js configures Jest.

Handling stylesheets and image importsstylesheet와 이미지 import 처리하기

stylesheet와 이미지는 test에서 사용되지 않지만 import하면 error가 발생할 수 있으므로 mocking해야 합니다.

Stylesheets and images aren't used in the tests but importing them may cause errors, so they will need to be mocked.

위 configuration에서 참조한 mock 파일인 fileMock.js와 styleMock.js를 __mocks__ directory 안에 만드세요:

Create the mock files referenced in the configuration above - fileMock.js and styleMock.js - inside a __mocks__ directory:

JS__mocks__/fileMock.js
module.exports = 'test-file-stub'
JS__mocks__/styleMock.js
module.exports = {}

static asset 처리에 대한 자세한 내용은 Jest 문서를 참고하세요.

For more information on handling static assets, please refer to the Jest Docs.

Handling Fontsfont 처리하기

font를 처리하려면 __mocks__ directory 안에 nextFontMock.js 파일을 만들고 다음 configuration을 추가하세요:

To handle fonts, create the nextFontMock.js file inside the __mocks__ directory, and add the following configuration:

JS__mocks__/nextFontMock.js
module.exports = new Proxy(
  {},
  {
    get: function getter() {
      return () => ({
        className: 'className',
        variable: 'variable',
        style: { fontFamily: 'fontFamily' },
      })
    },
  }
)

Optional: Handling Absolute Imports and Module Path Aliases선택: Absolute Import와 Module Path Alias 처리하기

프로젝트에서 Module Path Aliases를 사용한다면, jsconfig.json 파일의 paths option과 jest.config.js 파일의 moduleNameMapper option을 맞춰서 Jest가 import를 resolve하도록 설정해야 합니다. 예를 들면 다음과 같습니다:

If your project is using Module Path Aliases, you will need to configure Jest to resolve the imports by matching the paths option in the jsconfig.json file with the moduleNameMapper option in the jest.config.js file. For example:

tsconfig.json or jsconfig.json
{
  "compilerOptions": {
    "module": "esnext",
    "moduleResolution": "bundler",
    "baseUrl": "./",
    "paths": {
      "@/components/*": ["components/*"]
    }
  }
}
JSjest.config.js
moduleNameMapper: {
  // ...
  '^@/components/(.*)$': '<rootDir>/components/$1',
}

Optional: Extend Jest with custom matchers선택: custom matcher로 Jest 확장하기

@testing-library/jest-dom에는 .toBeInTheDocument()처럼 test를 더 쉽게 작성하게 해 주는 편리한 custom matcher들이 포함되어 있습니다. Jest configuration 파일에 다음 option을 추가하면 모든 test에서 custom matcher를 import할 수 있습니다:

@testing-library/jest-dom includes a set of convenient custom matchers such as .toBeInTheDocument() making it easier to write tests. You can import the custom matchers for every test by adding the following option to the Jest configuration file:

TSJSjest.config.ts
setupFilesAfterEnv: ['<rootDir>/jest.setup.ts']
setupFilesAfterEnv: ['<rootDir>/jest.setup.js']

그런 다음 jest.setup 안에 다음 import를 추가하세요:

Then, inside jest.setup, add the following import:

TSJSjest.setup.ts
import '@testing-library/jest-dom'
import '@testing-library/jest-dom'
Good to know

extend-expect는 v6.0에서 제거되었으므로, 버전 6 이전의 @testing-library/jest-dom을 사용한다면 대신 @testing-library/jest-dom/extend-expect를 import해야 합니다.

extend-expect was removed in v6.0, so if you are using @testing-library/jest-dom before version 6, you will need to import @testing-library/jest-dom/extend-expect instead.

각 test 전에 setup option을 더 추가해야 한다면 위의 jest.setup 파일에 추가할 수 있습니다.

If you need to add more setup options before each test, you can add them to the jest.setup file above.

Add a test script to package.jsonpackage.json에 test script 추가하기

마지막으로 package.json 파일에 Jest test script를 추가하세요:

Finally, add a Jest test script to your package.json file:

package.json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "test": "jest",
    "test:watch": "jest --watch"
  }
}

jest --watch는 파일이 변경되면 test를 다시 실행합니다. Jest CLI option에 대한 자세한 내용은 Jest 문서를 참고하세요.

jest --watch will re-run tests when a file is changed. For more Jest CLI options, please refer to the Jest Docs.

Creating your first test첫 test 만들기

이제 프로젝트에서 test를 실행할 준비가 되었습니다. 프로젝트 root directory에 __tests__라는 폴더를 만드세요.

Your project is now ready to run tests. Create a folder called __tests__ in your project's root directory.

예를 들어 <Home /> component가 heading을 제대로 render하는지 확인하는 test를 추가할 수 있습니다:

For example, we can add a test to check if the <Home /> component successfully renders a heading:

export default function Home() {
  return <h1>Home</h1>
}
JS__tests__/index.test.js
import '@testing-library/jest-dom'
import { render, screen } from '@testing-library/react'
import Home from '../pages/index'

describe('Home', () => {
  it('renders a heading', () => {
    render(<Home />)

    const heading = screen.getByRole('heading', { level: 1 })

    expect(heading).toBeInTheDocument()
  })
})

선택적으로 snapshot test를 추가해 component의 예상치 못한 변경을 추적할 수 있습니다:

Optionally, add a snapshot test to keep track of any unexpected changes in your component:

JS__tests__/snapshot.js
import { render } from '@testing-library/react'
import Home from '../pages/index'

it('renders homepage unchanged', () => {
  const { container } = render(<Home />)
  expect(container).toMatchSnapshot()
})
Good to know

Pages Router 안의 모든 파일은 route로 간주되므로, test 파일을 Pages Router 안에 두면 안 됩니다.

Test files should not be included inside the Pages Router because any files inside the Pages Router are considered routes.

Then, run the following command to run your tests:
