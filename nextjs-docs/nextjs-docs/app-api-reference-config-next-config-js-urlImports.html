urlImportsexperimentalurlImports

URL import는 (로컬 디스크 대신) 외부 server에서 module을 직접 import할 수 있게 해 주는 experimental 기능입니다.

URL imports are an experimental feature that allows you to import modules directly from external servers (instead of from the local disk).

Warning

내 컴퓨터에서 다운로드하고 실행해도 될 만큼 신뢰하는 domain만 사용하세요. 이 기능이 stable로 지정되기 전까지는 신중하게 판단하고 주의해서 사용하세요.

Only use domains that you trust to download and execute on your machine. Please exercise discretion, and caution until the feature is flagged as stable.

사용하려면(opt-in) next.config.js 안에 허용할 URL prefix를 추가하세요:

To opt-in, add the allowed URL prefixes inside next.config.js:

JSnext.config.js
module.exports = {
  experimental: {
    urlImports: ['https://example.com/assets/', 'https://cdn.skypack.dev'],
  },
}

그러면 URL에서 module을 직접 import할 수 있습니다:

Then, you can import modules directly from URLs:

import { a, b, c } from 'https://example.com/assets/some/module.js'

URL import는 일반 package import를 사용할 수 있는 곳이라면 어디서든 사용할 수 있습니다.

URL Imports can be used everywhere normal package imports can be used.

Security Model보안 모델

이 기능은 보안을 최우선으로 설계되고 있습니다. 우선 URL import를 허용할 domain을 명시적으로 지정하도록 강제하는 experimental flag를 추가했습니다. 더 나아가 Edge Runtime을 사용해 URL import가 브라우저 sandbox 안에서만 실행되도록 제한하는 작업을 진행 중입니다.

This feature is being designed with security as the top priority. To start, we added an experimental flag forcing you to explicitly allow the domains you accept URL imports from. We're working to take this further by limiting URL imports to execute in the browser sandbox using the Edge Runtime.

Lockfile

URL import를 사용하면 Next.js는 lockfile과 가져온 asset을 담은 next.lock directory를 만듭니다. 이 directory는 .gitignore로 무시하지 말고 반드시 Git에 commit해야 합니다.

When using URL imports, Next.js will create a next.lock directory containing a lockfile and fetched assets. This directory must be committed to Git, not ignored by .gitignore.

  • next dev를 실행하면 Next.js는 새로 발견된 모든 URL import를 다운로드해 lockfile에 추가합니다.
  • next build를 실행하면 Next.js는 lockfile만 사용해 production용으로 애플리케이션을 build합니다.
  • When running next dev, Next.js will download and add all newly discovered URL Imports to your lockfile.
  • When running next build, Next.js will use only the lockfile to build the application for production.

일반적으로 network request는 필요하지 않으며, lockfile이 오래되었으면 build가 실패합니다. 한 가지 예외는 Cache-Control: no-cache로 응답하는 resource입니다. 이런 resource는 lockfile에 no-cache 항목으로 기록되며, build할 때마다 항상 network에서 가져옵니다.

Typically, no network requests are needed and any outdated lockfile will cause the build to fail. One exception is resources that respond with Cache-Control: no-cache. These resources will have a no-cache entry in the lockfile and will always be fetched from the network on each build.

Examples예제

Skypack

import confetti from 'https://cdn.skypack.dev/canvas-confetti'
import { useEffect } from 'react'

export default () => {
  useEffect(() => {
    confetti()
  })
  return <p>Hello</p>
}

Static Image ImportsStatic 이미지 import

import Image from 'next/image'
import logo from 'https://example.com/assets/logo.png'

export default () => (
  <div>
    <Image src={logo} placeholder="blur" />
  </div>
)

URLs in CSSCSS 안의 URL

.className {
  background: url('https://example.com/assets/hero.jpg');
}

Asset ImportsAsset import

const logo = new URL('https://example.com/assets/file.txt', import.meta.url)

console.log(logo.pathname)

// prints "/_next/static/media/file.a9727b5d.txt"
