Turbopack FileSystem CachingTurbopack FileSystem Caching

Usage사용법

Turbopack FileSystem Cache를 사용하면 Turbopack이 next dev나 next build command 사이의 작업을 줄일 수 있습니다. 활성화하면 Turbopack이 실행 사이에 .next directory 아래에 데이터를 저장하고 복원하므로, 이후의 build와 dev session 속도가 크게 빨라질 수 있습니다.

Turbopack FileSystem Cache enables Turbopack to reduce work across next dev or next build commands. When enabled, Turbopack will save and restore data under the .next directory between runs, which can greatly speed up subsequent builds and dev sessions.

cache는 두 option으로 제어하며, 하나는 next dev용, 다른 하나는 next build용입니다. 둘 다 기본으로 활성화되어 있습니다:

Two options control the cache, one for next dev and one for next build. Both are enabled by default:

TSJSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    turbopackFileSystemCacheForDev: true,
    turbopackFileSystemCacheForBuild: true,
  },
}

export default nextConfig
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    turbopackFileSystemCacheForDev: true,
    turbopackFileSystemCacheForBuild: true,
  },
}

module.exports = nextConfig

Options

  • turbopackFileSystemCacheForDev (기본값: true): next dev에서의 Turbopack 작업을 .next/dev/cache/turbopack에 cache합니다. dev server를 재시작하면 이전 compilation을 재사용합니다.
  • turbopackFileSystemCacheForBuild (기본값: true): next build에서의 Turbopack 작업을 .next/cache/turbopack에 cache합니다. 이후의 build는 warm 상태로 시작합니다. Build environments를 참고하세요.
  • turbopackFileSystemCacheForDev (default: true): caches Turbopack's work for next dev in .next/dev/cache/turbopack. Restarting the dev server reuses the previous compilation.
  • turbopackFileSystemCacheForBuild (default: true): caches Turbopack's work for next build in .next/cache/turbopack. Subsequent builds start warm. See Build environments.

opt out하려면 둘 중 원하는 option을 false로 설정하세요.

Set either option to false to opt out.

Build environmentsBuild 환경

build cache는 .next/cache에 있습니다. build가 빨라지려면 build할 때마다 그 directory가 미리 복원되어 있어야 합니다.

The build cache lives in .next/cache. Builds only get faster when that directory is restored before each build.

  • Self-hosted build: build 사이에 같은 작업 directory를 재사용하세요. container 기반 build는 깨끗한 layer에서 시작하므로, 명시적으로 cache하거나 mount하지 않으면 .next/cache가 이어지지 않습니다.
  • CI provider: .next/cache에 대해 build caching을 설정하세요.
  • Self-hosted builds: reuse the same working directory between builds. Containerized builds start from a clean layer and do not carry .next/cache over unless you cache or mount it explicitly.
  • CI providers: configure build caching for .next/cache.

build 환경이 .next/cache를 전혀 보존하지 않는다면, 읽히지도 않을 cache를 쓰지 않도록 turbopackFileSystemCacheForBuild: false를 설정하세요.

If your build environment never preserves .next/cache, set turbopackFileSystemCacheForBuild: false to skip writing a cache that will not be read.
