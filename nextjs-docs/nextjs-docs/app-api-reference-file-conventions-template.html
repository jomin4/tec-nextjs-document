template.jstemplate.js

template 파일은 layout이나 page를 감싼다는 점에서 layout과 비슷합니다. route 간에 유지되며 state를 보존하는 layout과 달리, template에는 고유한 key가 부여되므로 자식 Client Component는 navigation 시 state가 초기화됩니다.

A template file is similar to a layout in that it wraps a layout or page. Unlike layouts that persist across routes and maintain state, templates are given a unique key, meaning children Client Components reset their state on navigation.

template은 다음과 같은 경우에 유용합니다:

They are useful when you need to:

  • navigation 시 useEffect를 다시 동기화해야 할 때.
  • navigation 시 자식 Client Component의 state를 초기화해야 할 때. 예를 들어 input field.
  • framework의 기본 동작을 바꾸고 싶을 때. 예를 들어 layout 안의 Suspense boundary는 첫 로드 시에만 fallback을 보여 주지만, template은 모든 navigation마다 fallback을 보여 줍니다.
  • Resynchronize useEffect on navigation.
  • Reset the state of a child Client Components on navigation. For example, an input field.
  • To change default framework behavior. For example, Suspense boundaries inside layouts only show a fallback on first load, while templates show it on every navigation.

Convention

template.js 파일에서 React component를 default export하여 template을 정의할 수 있습니다. 이 component는 children prop을 받아야 합니다.

A template can be defined by exporting a default React component from a template.js file. The component should accept a children prop.

TSJSapp/template.tsx
export default function Template({ children }: { children: React.ReactNode }) {
  return <div>{children}</div>
}
export default function Template({ children }) {
  return <div>{children}</div>
}

중첩 관점에서 template.js는 layout과 그 children 사이에서 rendering됩니다. 단순화한 출력은 다음과 같습니다:

In terms of nesting, template.js is rendered between a layout and its children. Here's a simplified output:

JSOutput
<Layout>
  {/* Note that the template is given a unique key. */}
  <Template key={routeParam}>{children}</Template>
</Layout>

component hierarchy에서 template.js는 layout.js와 error.js 사이에서 rendering됩니다. error.js, loading.js, not-found.js, page.js를 감싸지만, 같은 segment의 layout.js는 감싸지 않습니다.

In the component hierarchy, template.js renders between layout.js and error.js. It wraps error.js, loading.js, not-found.js, and page.js, but does not wrap the layout.js in the same segment.

Props

children (required)

Template은 children prop을 받습니다.

Template accepts a children prop.

JSOutput
<Layout>
  {/* Note that the template is automatically given a unique key. */}
  <Template key={routeParam}>{children}</Template>
</Layout>

Behavior동작

  • Server Components: 기본적으로 template은 Server Component입니다.
  • With navigation: template은 자신의 segment 레벨에 대한 고유한 key를 받습니다. 해당 segment(dynamic params 포함)가 바뀌면 다시 mount됩니다. 더 깊은 segment 안에서의 navigation은 상위 레벨 template을 다시 mount하지 않습니다. search params는 remount를 일으키지 않습니다.
  • State reset: template 안의 모든 Client Component는 navigation 시 state가 초기화됩니다.
  • Effect re-run: component가 다시 mount되면서 useEffect 같은 effect가 다시 동기화됩니다.
  • DOM reset: template 안의 DOM 요소는 완전히 새로 생성됩니다.
  • Server Components: By default, templates are Server Components.
  • With navigation: Templates receive a unique key for their own segment level. They remount when that segment (including its dynamic params) changes. Navigations within deeper segments do not remount higher-level templates. Search params do not trigger remounts.
  • State reset: Any Client Component inside the template will reset its state on navigation.
  • Effect re-run: Effects like useEffect will re-synchronize as the component remounts.
  • DOM reset: DOM elements inside the template are fully recreated.

Templates during navigation and remountingNavigation과 remount 중 template 동작

이 섹션에서는 navigation 중 template이 어떻게 동작하는지 보여 줍니다. 각 route 변경 시 어떤 template이 다시 mount되는지와 그 이유를 단계별로 설명합니다.

This section illustrates how templates behave during navigation. It shows, step by step, which templates remount on each route change and why.

다음 프로젝트 tree를 사용합니다:

Using this project tree:

app
├── about
│   ├── page.tsx
├── blog
│   ├── [slug]
│   │   └── page.tsx
│   ├── page.tsx
│   └── template.tsx
├── layout.tsx
├── page.tsx
└── template.tsx

/에서 시작하면 React tree는 대략 다음과 같습니다.

Starting at /, the React tree looks roughly like this.

Note: 예시에 표시된 key 값은 설명을 위한 것이며, 실제 애플리케이션의 값은 다를 수 있습니다.

Note: The key values shown in the examples are illustrative, the values in your application may differ.

JSOutput
<RootLayout>
  {/* app/template.tsx */}
  <Template key="/">
    <Page />
  </Template>
</RootLayout>

/about으로 이동하면(첫 번째 segment 변경) root template key가 바뀌어 다시 mount됩니다:

Navigating to /about (first segment changes), the root template key changes, it remounts:

JSOutput
<RootLayout>
  {/* app/template.tsx */}
  <Template key="/about">
    <AboutPage />
  </Template>
</RootLayout>

/blog로 이동하면(첫 번째 segment 변경) root template key가 바뀌어 다시 mount되고, blog 레벨 template이 mount됩니다:

Navigating to /blog (first segment changes), the root template key changes, it remounts and the blog-level template mounts:

JSOutput
<RootLayout>
  {/* app/template.tsx (root) */}
  <Template key="/blog">
    {/* app/blog/template.tsx */}
    <Template key="/blog">
      <BlogIndexPage />
    </Template>
  </Template>
</RootLayout>

같은 첫 번째 segment 안에서 /blog/first-post로 이동하면(자식 segment 변경) root template key는 바뀌지 않지만 blog 레벨 template key가 바뀌어 다시 mount됩니다:

Navigating within the same first segment to /blog/first-post (child segment changes), the root template key doesn't change, but the blog-level template key changes, it remounts:

JSOutput
<RootLayout>
  {/* app/template.tsx (root) */}
  <Template key="/blog">
    {/* app/blog/template.tsx */}
    {/* remounts because the child segment at this level changed */}
    <Template key="/blog/first-post">
      <BlogPostPage slug="first-post" />
    </Template>
  </Template>
</RootLayout>

/blog/second-post로 이동하면(같은 첫 번째 segment, 다른 자식 segment) root template key는 바뀌지 않지만 blog 레벨 template key가 바뀌어 다시 한 번 mount됩니다:

Navigating to /blog/second-post (same first segment, different child segment), the root template key doesn't change, but the blog-level template key changes, it remounts again:

JSOutput
<RootLayout>
  {/* app/template.tsx (root) */}
  <Template key="/blog">
    {/* app/blog/template.tsx */}
    {/* remounts again due to changed child segment */}
    <Template key="/blog/second-post">
      <BlogPostPage slug="second-post" />
    </Template>
  </Template>
</RootLayout>
