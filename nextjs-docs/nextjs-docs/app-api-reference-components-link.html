Link ComponentLink 컴포넌트

<Link>는 HTML <a> element를 확장해 route 간 prefetching과 client-side navigation을 제공하는 React component입니다. Next.js에서 route 간에 이동하는 주된 방법입니다.

<Link> is a React component that extends the HTML <a> element to provide prefetching and client-side navigation between routes. It is the primary way to navigate between routes in Next.js.

기본 사용법:

Basic usage:

TSJSapp/page.tsx
import Link from 'next/link'

export default function Page() {
  return <Link href="/dashboard">Dashboard</Link>
}
import Link from 'next/link'

export default function Page() {
  return <Link href="/dashboard">Dashboard</Link>
}

replace

기본값은 false입니다. true이면 next/link는 브라우저 history stack에 새 URL을 추가하는 대신 현재 history state를 교체합니다.

Defaults to false. When true, next/link will replace the current history state instead of adding a new URL into the browser's history stack.

scroll

기본값은 true입니다. Next.js에서 <Link>의 기본 scroll 동작은 브라우저가 뒤로 가기/앞으로 가기 navigation을 처리하는 방식과 비슷하게 scroll 위치를 유지하는 것입니다. 새 Page로 이동할 때, Page가 viewport에 보이는 한 scroll 위치는 그대로 유지됩니다. 하지만 Page가 viewport에 보이지 않으면 Next.js는 첫 번째 Page element의 맨 위로 scroll합니다.

Defaults to true. The default scrolling behavior of <Link> in Next.js is to maintain scroll position, similar to how browsers handle back and forwards navigation. When you navigate to a new Page, scroll position will stay the same as long as the Page is visible in the viewport. However, if the Page is not visible in the viewport, Next.js will scroll to the top of the first Page element.

scroll = {false}이면 Next.js는 첫 번째 Page element로 scroll하려고 시도하지 않습니다.

When scroll = {false}, Next.js will not attempt to scroll to the first Page element.

Good to know

Next.js는 scroll 동작을 관리하기 전에 scroll: false인지 확인합니다. scroll이 활성화되어 있으면 navigation에 관련된 DOM node를 찾아 각 top-level element를 검사합니다. scroll할 수 없는 element와 렌더링된 HTML이 없는 element는 모두 건너뛰며, 여기에는 sticky 또는 fixed로 position이 지정된 element와 getBoundingClientRect로 계산했을 때 보이지 않는 element 등이 포함됩니다. 그런 다음 Next.js는 viewport에 보이는 scroll 가능한 element를 찾을 때까지 sibling element를 계속 탐색합니다.

Next.js checks if scroll: false before managing scroll behavior. If scrolling is enabled, it identifies the relevant DOM node for navigation and inspects each top-level element. All non-scrollable elements and those without rendered HTML are bypassed, this includes sticky or fixed positioned elements, and non-visible elements such as those calculated with getBoundingClientRect. Next.js then continues through siblings until it identifies a scrollable element that is visible in the viewport.

TSJSapp/page.tsx
import Link from 'next/link'

export default function Page() {
  return (
    <Link href="/dashboard" scroll={false}>
      Dashboard
    </Link>
  )
}
import Link from 'next/link'

export default function Page() {
  return (
    <Link href="/dashboard" scroll={false}>
      Dashboard
    </Link>
  )
}

prefetch

Prefetching은 <Link /> component가 사용자의 viewport에 들어올 때(처음부터 또는 scroll을 통해) 일어납니다. Next.js는 client-side navigation의 성능을 높이기 위해 연결된 route(href로 지정)와 그 data를 background에서 prefetch하고 로드합니다. 사용자가 <Link /> 위에 hover할 때 prefetch된 data가 만료되었다면 Next.js는 다시 prefetch를 시도합니다. Prefetching은 production에서만 활성화됩니다.

Prefetching happens when a <Link /> component enters the user's viewport (initially or through scroll). Next.js prefetches and loads the linked route (denoted by the href) and its data in the background to improve the performance of client-side navigations. If the prefetched data has expired by the time the user hovers over a <Link />, Next.js will attempt to prefetch it again. Prefetching is only enabled in production.

prefetch prop에는 다음 값을 전달할 수 있습니다:

The following values can be passed to the prefetch prop:

  • "auto" or null (default): prefetch 동작은 route가 static인지 dynamic인지에 따라 달라집니다. static route의 경우 전체 route가(모든 data 포함) prefetch됩니다. dynamic route의 경우 loading.js boundary가 있는 가장 가까운 segment까지의 부분 route가 prefetch됩니다.
  • true: static route와 dynamic route 모두 전체 route가 prefetch됩니다. Partial Prefetching이 활성화되어 있으면, prefetch에는 App Shell과 link의 URL data에 의존하는 cache된 콘텐츠가 포함됩니다. Optimizing prefetching을 참고하세요.
  • false: viewport에 들어올 때와 hover할 때 모두 prefetching이 일어나지 않습니다.
  • "auto" or null (default): Prefetch behavior depends on whether the route is static or dynamic. For static routes, the full route will be prefetched (including all its data). For dynamic routes, the partial route down to the nearest segment with a loading.js boundary will be prefetched.
  • true: The full route is prefetched for both static and dynamic routes. With Partial Prefetching enabled, the prefetch includes the App Shell and cached content that depends on the link's URL data. See Optimizing prefetching.
  • false: Prefetching will never happen both on entering the viewport and on hover.

With Partial Prefetching enabled (partialPrefetching: true): 기본값이 바뀝니다. auto는 전체 페이지 대신 route별 App Shell(route의 static 콘텐츠와 cache된 콘텐츠)을 prefetch합니다. 전체 동작 변경 사항은 Adopting Partial Prefetching을 참고하세요.

With Partial Prefetching enabled (partialPrefetching: true): the default changes. auto prefetches the per-route App Shell (the route's static and cached content) instead of the full page. See Adopting Partial Prefetching for the full behavior change.

    </Link>
  )
}

onNavigate

client-side navigation 중에 호출되는 event handler입니다. handler는 preventDefault() method를 포함한 event object를 받으므로, 필요하면 navigation을 취소할 수 있습니다.

An event handler called during client-side navigation. The handler receives an event object that includes a preventDefault() method, allowing you to cancel the navigation if needed.

TSJSapp/page.tsx
import Link from 'next/link'

export default function Page() {
  return (
    <Link
      href="/dashboard"
      onNavigate={(e) => {
        // Only executes during SPA navigation
        console.log('Navigating...')

        // Optionally prevent navigation
        // e.preventDefault()
      }}
    >
      Dashboard
    </Link>
  )
}
import Link from 'next/link'

export default function Page() {
  return (
    <Link
      href="/dashboard"
      onNavigate={(e) => {
        // Only executes during SPA navigation
        console.log('Navigating...')

        // Optionally prevent navigation
        // e.preventDefault()
      }}
    >
      Dashboard
    </Link>
  )
}
Good to know

onClick과 onNavigate는 비슷해 보이지만 목적이 다릅니다. onClick은 모든 click event에서 실행되는 반면, onNavigate는 client-side navigation 중에만 실행됩니다. 주요 차이점은 다음과 같습니다:

  • modifier key(Ctrl/Cmd + Click)를 사용하면, Next.js가 새 탭에 대한 기본 navigation을 막기 때문에 onClick은 실행되지만 onNavigate는 실행되지 않습니다.
  • onNavigate는 client-side 및 same-origin navigation 전용이므로 외부 URL에서는 trigger되지 않습니다.
  • download attribute가 있는 link는 브라우저가 연결된 URL을 다운로드로 처리하므로 onClick에서는 동작하지만 onNavigate에서는 동작하지 않습니다.

While onClick and onNavigate may seem similar, they serve different purposes. onClick executes for all click events, while onNavigate only runs during client-side navigation. Some key differences:

  • When using modifier keys (Ctrl/Cmd + Click), onClick executes but onNavigate doesn't since Next.js prevents default navigation for new tabs.
  • External URLs won't trigger onNavigate since it's only for client-side and same-origin navigations.
  • Links with the download attribute will work with onClick but not onNavigate since the browser will treat the linked URL as a download.

transitionTypes

A list of transition types to apply to the navigation. These types are passed to React.addTransitionType inside the navigation transition, enabling <ViewTransition> components to apply different animations based on the type of navigation.

Checking active links활성 link 확인하기

usePathname()을 사용해 link가 활성 상태인지 판단할 수 있습니다. 예를 들어 활성 link에 class를 추가하려면, 현재 pathname이 link의 href와 일치하는지 확인하면 됩니다:

You can use usePathname() to determine if a link is active. For example, to add a class to the active link, you can check if the current pathname matches the href of the link:

TSJSapp/ui/nav-links.tsx
'use client'

import { usePathname } from 'next/navigation'
import Link from 'next/link'

export function Links() {
  const pathname = usePathname()

  return (
    <nav>
      <Link className={`link ${pathname === '/' ? 'active' : ''}`} href="/">
        Home
      </Link>

      <Link
        className={`link ${pathname === '/about' ? 'active' : ''}`}
        href="/about"
      >
        About
      </Link>
    </nav>
  )
}

Scrolling to an idid로 scroll하기

navigation 시 특정 id로 scroll하고 싶다면, URL 뒤에 # hash link를 붙이거나 href prop에 hash link만 전달하면 됩니다. <Link>가 <a> element로 렌더링되기 때문에 가능합니다.

If you'd like to scroll to a specific id on navigation, you can append your URL with a # hash link or just pass a hash link to the href prop. This is possible since <Link> renders to an <a> element.

<Link href="/dashboard#settings">Settings</Link>

// Output
<a href="/dashboard#settings">Settings</a>
Good to know
  • navigation 시 Page가 viewport에 보이지 않으면 Next.js는 해당 Page로 scroll합니다.
  • Next.js will scroll to the Page if it is not visible in the viewport upon navigation.

Disable scrolling to the top of the page페이지 맨 위로 scroll 비활성화

Next.js에서 <Link>의 기본 scroll 동작은 브라우저가 뒤로 가기/앞으로 가기 navigation을 처리하는 방식과 비슷하게 scroll 위치를 유지하는 것입니다. 새 Page로 이동할 때, Page가 viewport에 보이는 한 scroll 위치는 그대로 유지됩니다.

The default scrolling behavior of <Link> in Next.js is to maintain scroll position, similar to how browsers handle back and forwards navigation. When you navigate to a new Page, scroll position will stay the same as long as the Page is visible in the viewport.

하지만 Page가 viewport에 보이지 않으면 Next.js는 첫 번째 Page element의 맨 위로 scroll합니다. 이 동작을 비활성화하려면 <Link> component에 scroll={false}를 전달하거나, router.push() 또는 router.replace()에 scroll: false를 전달하면 됩니다.

However, if the Page is not visible in the viewport, Next.js will scroll to the top of the first Page element. If you'd like to disable this behavior, you can pass scroll={false} to the <Link> component, or scroll: false to router.push() or router.replace().

JSapp/page.js
import Link from 'next/link'

export default function Page() {
  return (
    <Link href="/#hashid" scroll={false}>
      Disables scrolling to the top
    </Link>
  )
}

scroll container에 scroll-padding-top을 사용해 header 높이를 반영할 수 있습니다:

You can account for its height using scroll-padding-top on the scroll container:

app/globals.css
html {
  scroll-padding-top: 64px; /* Match the height of your sticky header */
}

이는 scroll 기반 위치 지정에 offset을 주는 브라우저 CSS property입니다. hash fragment(#id) navigation을 포함해, Next.js가 네이티브 scrollIntoView() API를 사용할 때마다 적용됩니다. 또는 전역 offset을 설정하는 대신 개별 대상 element에 scroll-margin-top을 사용할 수도 있습니다.

This is a browser CSS property that offsets scroll-based positioning. It applies whenever Next.js uses the native scrollIntoView() API, including hash fragment (#id) navigation. Alternatively, you can use scroll-margin-top on individual target elements instead of setting a global offset.

Prefetching links in ProxyProxy에서 link prefetch하기

인증이나 사용자를 다른 페이지로 rewrite하는 등의 목적으로 Proxy를 사용하는 경우가 많습니다. <Link /> component가 Proxy를 통한 rewrite가 있는 link를 올바르게 prefetch하려면, 표시할 URL과 prefetch할 URL을 모두 Next.js에 알려 주어야 합니다. 이는 prefetch할 올바른 route를 알기 위해 proxy에 불필요한 fetch를 보내는 것을 피하기 위해 필요합니다.

It's common to use Proxy for authentication or other purposes that involve rewriting the user to a different page. In order for the <Link /> component to properly prefetch links with rewrites via Proxy, you need to tell Next.js both the URL to display and the URL to prefetch. This is required to avoid un-necessary fetches to proxy to know the correct route to prefetch.

예를 들어 인증된 사용자용 view와 방문자용 view가 있는 /dashboard route를 제공하려면, Proxy에 다음을 추가해 사용자를 올바른 페이지로 redirect할 수 있습니다:

For example, if you want to serve a /dashboard route that has authenticated and visitor views, you can add the following in your Proxy to redirect the user to the correct page:

TSJSproxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  const nextUrl = request.nextUrl
  if (nextUrl.pathname === '/dashboard') {
    if (request.cookies.has('authToken')) {
      return NextResponse.rewrite(new URL('/auth/dashboard', request.url))
    } else {
      return NextResponse.rewrite(new URL('/public/dashboard', request.url))
    }
  }
}
import { NextResponse } from 'next/server'

export function proxy(request) {
  const nextUrl = request.nextUrl
  if (nextUrl.pathname === '/dashboard') {
    if (request.cookies.has('authToken')) {
      return NextResponse.rewrite(new URL('/auth/dashboard', request.url))
    } else {
      return NextResponse.rewrite(new URL('/public/dashboard', request.url))
    }
  }
}

이 경우 <Link /> component에서는 다음 코드를 사용하면 됩니다:

Blocking navigationnavigation 막기

form에 저장되지 않은 변경 사항이 있을 때처럼 특정 조건을 만족하면 onNavigate prop을 사용해 navigation을 막을 수 있습니다. 앱의 여러 component에 걸쳐 navigation을 막아야 할 때(예: form을 편집하는 동안 어떤 link로도 이동하지 못하게 할 때), React Context를 사용하면 이 blocking state를 깔끔하게 공유할 수 있습니다. 먼저 navigation blocking state를 추적할 context를 만듭니다:

You can use the onNavigate prop to block navigation when certain conditions are met, such as when a form has unsaved changes. When you need to block navigation across multiple components in your app (like preventing navigation from any link while a form is being edited), React Context provides a clean way to share this blocking state. First, create a context to track the navigation blocking state:

TSJSapp/contexts/navigation-blocker.tsx
'use client'

import { createContext, useState, useContext } from 'react'

interface NavigationBlockerContextType {
  isBlocked: boolean
  setIsBlocked: (isBlocked: boolean) => void
}

export const NavigationBlockerContext =
  createContext<NavigationBlockerContextType>({
    isBlocked: false,
    setIsBlocked: () => {},
  })

export function NavigationBlockerProvider({
  children,
}: {
  children: React.ReactNode
}) {
  const [isBlocked, setIsBlocked] = useState(false)

  return (
    <NavigationBlockerContext.Provider value={{ isBlocked, setIsBlocked }}>
      {children}
    </NavigationBlockerContext.Provider>
  )
}

export function useNavigationBlocker() {
  return useContext(NavigationBlockerContext)
}
'use client'

import { createContext, useState, useContext } from 'react'

export const NavigationBlockerContext = createContext({
  isBlocked: false,
  setIsBlocked: () => {},
})

export function NavigationBlockerProvider({ children }) {
  const [isBlocked, setIsBlocked] = useState(false)

  return (
    <NavigationBlockerContext.Provider value={{ isBlocked, setIsBlocked }}>

    </NavigationBlockerContext.Provider>
  )
}

  return useContext(NavigationBlockerContext)
}

context를 사용하는 form component를 만듭니다:

Create a form component that uses the context:

TSJSapp/components/form.tsx
'use client'

import { useNavigationBlocker } from '../contexts/navigation-blocker'

export default function Form() {
  const { setIsBlocked } = useNavigationBlocker()

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault()
        setIsBlocked(false)
      }}
      onChange={() => setIsBlocked(true)}
    >
      <input type="text" name="name" />
      <button type="submit">Save</button>
    </form>
  )
}

navigation을 막는 custom Link component를 만듭니다:

Create a custom Link component that blocks navigation:

TSJSapp/components/custom-link.tsx
'use client'

import Link from 'next/link'
import { useNavigationBlocker } from '../contexts/navigation-blocker'

interface CustomLinkProps extends React.ComponentProps<typeof Link> {
  children: React.ReactNode
}

export function CustomLink({ children, ...props }: CustomLinkProps) {
  const { isBlocked } = useNavigationBlocker()

  return (
    <Link
      onNavigate={(e) => {
        if (
          isBlocked &&
          !window.confirm('You have unsaved changes. Leave anyway?')
        ) {
          e.preventDefault()
        }
      }}
      {...props}
    >
      {children}
    </Link>
  )
}
