exportPathMapexportPathMap

이 기능은 next export 전용이며, 현재 pages의 getStaticPaths 또는 app의 generateStaticParams로 대체되어 deprecated 상태입니다.

This feature is exclusive to next export and currently deprecated in favor of getStaticPaths with pages or generateStaticParams with app.

exportPathMap을 사용하면 export 중에 사용할 request path와 page 대상 간의 mapping을 지정할 수 있습니다. exportPathMap에 정의한 path는 next dev를 사용할 때도 사용할 수 있습니다.

exportPathMap allows you to specify a mapping of request paths to page destinations, to be used during export. Paths defined in exportPathMap will also be available when using next dev.

다음과 같은 page가 있는 앱에 custom exportPathMap을 만드는 예시로 시작해 보겠습니다:

Let's start with an example, to create a custom exportPathMap for an app with the following pages:

  • pages/index.js
  • pages/about.js
  • pages/post.js
  • pages/index.js
  • pages/about.js
  • pages/post.js

next.config.js를 열고 다음 exportPathMap config를 추가하세요:

Open next.config.js and add the following exportPathMap config:

JSnext.config.js
module.exports = {
  exportPathMap: async function (
    defaultPathMap,
    { dev, dir, outDir, distDir, buildId }
  ) {
    return {
      '/': { page: '/' },
      '/about': { page: '/about' },
      '/p/hello-nextjs': { page: '/post', query: { title: 'hello-nextjs' } },
      '/p/learn-nextjs': { page: '/post', query: { title: 'learn-nextjs' } },
      '/p/deploy-nextjs': { page: '/post', query: { title: 'deploy-nextjs' } },
    }
  },
}
Good to know

exportPathMap의 query 필드는 automatically statically optimized page나 getStaticProps page에는 사용할 수 없습니다. 이 page들은 build 시점에 HTML 파일로 render되므로 next export 중에 추가 query 정보를 제공할 수 없기 때문입니다.

the query field in exportPathMap cannot be used with automatically statically optimized pages or getStaticProps pages as they are rendered to HTML files at build-time and additional query information cannot be provided during next export.

그러면 page가 HTML 파일로 export됩니다. 예를 들어 /about은 /about.html이 됩니다.

The pages will then be exported as HTML files, for example, /about will become /about.html.

exportPathMap은 2개의 argument를 받는 async 함수입니다. 첫 번째는 Next.js가 사용하는 기본 map인 defaultPathMap입니다. 두 번째 argument는 다음 항목을 가진 object입니다:

exportPathMap is an async function that receives 2 arguments: the first one is defaultPathMap, which is the default map used by Next.js. The second argument is an object with:

  • dev - exportPathMap이 development 중에 호출되면 true, next export를 실행할 때는 false입니다. development 중에는 exportPathMap이 route를 정의하는 데 사용됩니다.
  • dir - 프로젝트 directory의 absolute path
  • outDir - out/ directory의 absolute path (-o로 설정 가능). dev가 true이면 outDir 값은 null입니다.
  • distDir - .next/ directory의 absolute path (distDir config로 설정 가능)
  • buildId - 생성된 build id
  • dev - true when exportPathMap is being called in development. false when running next export. In development exportPathMap is used to define routes.
  • dir - Absolute path to the project directory
  • outDir - Absolute path to the out/ directory (configurable with -o). When dev is true the value of outDir will be null.
  • distDir - Absolute path to the .next/ directory (configurable with the distDir config)
  • buildId - The generated build id

반환되는 object는 page의 map으로, key는 pathname이고 value는 다음 필드를 받는 object입니다:

The returned object is a map of pages where the key is the pathname and the value is an object that accepts the following fields:

  • page: String - render할 pages directory 안의 page
  • query: Object - prerender할 때 getInitialProps에 전달되는 query object. 기본값은 {}
  • page: String - the page inside the pages directory to render
  • query: Object - the query object passed to getInitialProps when prerendering. Defaults to {}

export되는 pathname은 파일 이름(예: /readme.md)일 수도 있지만, 확장자가 .html이 아니라면 콘텐츠를 serve할 때 Content-Type header를 text/html로 설정해야 할 수 있습니다.

The exported pathname can also be a filename (for example, /readme.md), but you may need to set the Content-Type header to text/html when serving its content if it is different than .html.

Adding a trailing slashtrailing slash 추가하기

Next.js가 page를 index.html 파일로 export하고 trailing slash를 요구하도록 설정할 수 있습니다. 이 경우 /about은 /about/index.html이 되고 /about/으로 routing됩니다. 이는 Next.js 9 이전의 기본 동작이었습니다.

It is possible to configure Next.js to export pages as index.html files and require trailing slashes, /about becomes /about/index.html and is routable via /about/. This was the default behavior prior to Next.js 9.

이전 동작으로 되돌려 trailing slash를 추가하려면 next.config.js를 열고 trailingSlash config를 활성화하세요:

To switch back and add a trailing slash, open next.config.js and enable the trailingSlash config:

JSnext.config.js
module.exports = {
  trailingSlash: true,
}

Customizing the output directoryoutput directory customize하기

next export는 기본 output directory로 out을 사용하며, 다음과 같이 -o argument로 이를 customize할 수 있습니다:

next export will use out as the default output directory, you can customize this using the -o argument, like so:

>_Terminal
next export -o outdir
Warning

exportPathMap 사용은 deprecated되었으며 pages 안의 getStaticPaths에 의해 override됩니다. 둘을 함께 사용하는 것은 권장하지 않습니다.

Using exportPathMap is deprecated and is overridden by getStaticPaths inside pages. We don't recommend using them together.
