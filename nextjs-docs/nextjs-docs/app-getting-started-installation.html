  1. my-app이라는 이름으로 새 Next.js 앱을 만듭니다
  2. cd my-app으로 이동한 뒤 dev server를 시작합니다.
  3. http://localhost:3000에 접속합니다.
  1. Create a new Next.js app named my-app
  2. cd my-app and start the dev server.
  3. Visit http://localhost:3000.
pnpm create next-app@latest my-app --yes
cd my-app
pnpm dev
npx create-next-app@latest my-app --yes
cd my-app
npm run dev
yarn create next-app@latest my-app --yes
cd my-app
yarn dev
bun create next-app@latest my-app --yes
cd my-app
bun dev
  • --yes는 저장된 preference나 기본값을 사용해 prompt를 건너뜁니다. 기본 setup은 TypeScript, Tailwind CSS, ESLint, App Router, Turbopack을 활성화하고 import alias @/*를 사용하며, coding agent가 최신 Next.js 코드를 작성하도록 안내하는 AGENTS.md를 포함합니다.
  • --yes skips prompts using saved preferences or defaults. The default setup enables TypeScript, Tailwind CSS, ESLint, App Router, and Turbopack, with import alias @/*, and includes AGENTS.md to guide coding agents to write up-to-date Next.js code.

The quickest way to create a new Next.js app is using create-next-app, which sets up everything automatically for you. To create a project, run:

pnpm create next-app

Manual installation수동 설치

새 Next.js 앱을 직접 만들려면 필요한 package를 설치하세요:

To manually create a new Next.js app, install the required packages:

pnpm i next@latest react@latest react-dom@latest
npm i next@latest react@latest react-dom@latest
yarn add next@latest react@latest react-dom@latest
bun add next@latest react@latest react-dom@latest
Good to know
  • App Router는 React canary release를 내장해서 사용합니다. 여기에는 안정화된 React 19 변경 사항과 framework에서 검증 중인 새 기능이 모두 포함되어 있지만, tooling과 ecosystem 호환성을 위해 package.json에 react와 react-dom은 여전히 선언해 두어야 합니다.
  • Pages Router는 package.json에 있는 React 버전을 사용합니다.
  • The App Router uses React canary releases built-in, which include all the stable React 19 changes, as well as newer features being validated in frameworks, but you should still declare react and react-dom in package.json for tooling and ecosystem compatibility.
  • The Pages Router uses the React version from your package.json.

그다음 package.json 파일에 다음 script를 추가하세요:

Then, add the following scripts to your package.json file:

package.json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "eslint",
    "lint:fix": "eslint --fix"
  }
}

이 script들은 애플리케이션 개발의 각 단계를 가리킵니다:

These scripts refer to the different stages of developing an application:

  • next dev: Turbopack(기본 bundler)으로 development server를 시작합니다.
  • next build: production용으로 애플리케이션을 build합니다.
  • next start: production server를 시작합니다.
  • eslint: ESLint를 실행합니다.
  • next dev: Starts the development server using Turbopack (default bundler).
  • next build: Builds the application for production.
  • next start: Starts the production server.
  • eslint: Runs ESLint.

이제 Turbopack이 기본 bundler입니다. Webpack을 쓰려면 next dev --webpack 또는 next build --webpack을 실행하세요. 설정 방법은 Turbopack 문서를 참고하세요.

Turbopack is now the default bundler. To use Webpack run next dev --webpack or next build --webpack. See the Turbopack docs for configuration details.

Create the app directoryapp directory 만들기

Next.js는 file-system routing을 사용합니다. 즉, 애플리케이션의 route는 파일을 어떻게 구성하느냐에 따라 결정됩니다.

Next.js uses file-system routing, which means the routes in your application are determined by how you structure your files.

app 폴더를 만드세요. 그다음 app 안에 layout.tsx 파일을 만듭니다. 이 파일이 root layout입니다. root layout은 필수이며 <html>과 <body> tag를 반드시 포함해야 합니다.

Create an app folder. Then, inside app, create a layout.tsx file. This file is the root layout. It's required and must contain the <html> and <body> tags.

TSJSapp/layout.tsx
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}

초기 콘텐츠가 들어간 home page app/page.tsx를 만드세요:

Create a home page app/page.tsx with some initial content:

TSJSapp/page.tsx
export default function Page() {
  return <h1>Hello, Next.js!</h1>
}
export default function Page() {
  return <h1>Hello, Next.js!</h1>
}

사용자가 애플리케이션의 root(/)에 방문하면 layout.tsx와 page.tsx가 함께 render됩니다.

Both layout.tsx and page.tsx will be rendered when the user visits the root of your application (/).

Good to know
  • root layout을 만드는 것을 잊더라도, next dev로 development server를 실행하면 Next.js가 이 파일을 자동으로 만들어 줍니다.
  • 원한다면 프로젝트 root에 src 폴더를 두어 애플리케이션 코드와 configuration 파일을 분리할 수 있습니다.
  • If you forget to create the root layout, Next.js will automatically create this file when running the development server with next dev.
  • You can optionally use a src folder in the root of your project to separate your application's code from configuration files.

Create the public folder (optional)public 폴더 만들기 (선택)

프로젝트 root에 public 폴더를 만들어 이미지, font 같은 static asset을 저장하세요. public 안의 파일은 코드에서 base URL(/)부터 시작하는 경로로 참조할 수 있습니다.

Create a public folder at the root of your project to store static assets such as images, fonts, etc. Files inside public can then be referenced by your code starting from the base URL (/).

그러면 root 경로(/)로 이 asset들을 참조할 수 있습니다. 예를 들어 public/profile.png는 /profile.png로 참조할 수 있습니다:

You can then reference these assets using the root path (/). For example, public/profile.png can be referenced as /profile.png:

TSJSapp/page.tsx
import Image from 'next/image'

export default function Page() {
  return <Image src="/profile.png" alt="Profile" width={100} height={100} />
}
import Image from 'next/image'

export default function Page() {
  return <Image src="/profile.png" alt="Profile" width={100} height={100} />
}

  3. app/page.tsx 파일을 수정하고 저장하면 브라우저에서 바뀐 결과를 확인할 수 있습니다.
  1. Run npm run dev to start the development server.

Set up TypeScriptTypeScript 설정하기

최소 TypeScript 버전: v5.1.0

Minimum TypeScript version: v5.1.0

Next.js는 TypeScript를 기본으로(built-in) 지원합니다. 프로젝트에 TypeScript를 추가하려면 파일 이름을 .ts / .tsx로 바꾸고 next dev를 실행하세요. Next.js가 필요한 dependency를 자동으로 설치하고, 권장 config option이 들어간 tsconfig.json 파일을 추가합니다.

Next.js comes with built-in TypeScript support. To add TypeScript to your project, rename a file to .ts / .tsx and run next dev. Next.js will automatically install the necessary dependencies and add a tsconfig.json file with the recommended config options.

Next.js includes a custom TypeScript plugin and type checker, which VSCode and other code editors can use for advanced type-checking and auto-completion.

Set up your editor에디터 설정하기

App Router는 page.tsx, layout.tsx, route.ts처럼 convention(관례)에 따라 파일 이름을 정하기 때문에, 에디터가 금세 같은 이름의 tab으로 가득 찹니다. 각 tab에 blog/[id]처럼 그 파일을 감싸는 폴더 이름을 label로 붙이면 서로 구분할 수 있습니다.

The App Router names files by convention, like page.tsx, layout.tsx, and route.ts, so your editor quickly fills with same-named tabs. Label each tab with its enclosing folders, like blog/[id], so you can tell them apart.

VS Code 1.88+ 또는 Cursor에서는 .vscode/settings.json에 custom editor label을 추가하세요. 폴더를 두 단계까지 label로 붙이면 blog/[id]/page.tsx 같은 dynamic route가 모두 똑같은 [id] label로 뭉개지지 않습니다:

In VS Code 1.88+ or Cursor, add custom editor labels to .vscode/settings.json. Labeling two folders deep keeps dynamic routes like blog/[id]/page.tsx from all collapsing to the same [id] label:

.vscode/settings.json
{
  "workbench.editor.customLabels.patterns": {
    "**/app/**/page.tsx": "${dirname(1)}/${dirname} - page.tsx",
    "**/app/**/layout.tsx": "${dirname(1)}/${dirname} - layout.tsx",
    "**/app/**/loading.tsx": "${dirname(1)}/${dirname} - loading.tsx",
    "**/app/**/error.tsx": "${dirname(1)}/${dirname} - error.tsx",
    "**/app/**/not-found.tsx": "${dirname(1)}/${dirname} - not-found.tsx",
    "**/app/**/template.tsx": "${dirname(1)}/${dirname} - template.tsx",
    "**/app/**/default.tsx": "${dirname(1)}/${dirname} - default.tsx",
    "**/app/**/route.ts": "${dirname(1)}/${dirname} - route.ts"
  }
}

또는 이 prompt를 복사해 coding agent에게 설정을 맡기세요:

Or copy this prompt to have your coding agent set it up:

Set up custom editor labels so my Next.js App Router files are easy to tell apart. Read https://nextjs.org/docs/app/getting-started/installation#set-up-your-editor and add the workbench.editor.customLabels.patterns config shown there to my .vscode/settings.json, creating the file if it doesn't exist. Adjust the labels to taste. If I use a different editor, apply the equivalent setting or tell me it's automatic, and leave my other settings untouched.
Good to know

JetBrains IDE(WebStorm, IntelliJ)는 같은 이름의 파일에 폴더를 자동으로 표시해 주므로 별도 설정이 필요 없습니다.

JetBrains IDEs (WebStorm, IntelliJ) show the folder for same-named files automatically, so no setup is needed.

Set up lintinglinting 설정하기

Next.js는 ESLint와 Biome 중 하나로 linting을 지원합니다. linter를 고른 다음 package.json script로 직접 실행하세요.

Next.js supports linting with either ESLint or Biome. Choose a linter and run it directly via package.json scripts.

  • ESLint 사용(포괄적인 rule):
  • Use ESLint (comprehensive rules):
package.json
{
  "scripts": {
    "lint": "eslint",
    "lint:fix": "eslint --fix"
  }
}
  • 또는 Biome 사용(빠른 linter + formatter):
  • Or use Biome (fast linter + formatter):
package.json
{
  "scripts": {
    "lint": "biome check",
    "format": "biome format --write"
  }
}

프로젝트에서 예전에 next lint를 사용했다면, codemod로 script를 ESLint CLI로 migrate하세요:

If your project previously used next lint, migrate your scripts to the ESLint CLI with the codemod:

>_Terminal
npx @next/codemod@canary next-lint-to-eslint-cli .

ESLint를 사용한다면 명시적인 config를 만드세요(권장: eslint.config.mjs). ESLint는 기존 .eslintrc.* 형식과 새로운 eslint.config.mjs 형식을 모두 지원합니다. 권장 setup은 ESLint API reference를 참고하세요.

If you use ESLint, create an explicit config (recommended eslint.config.mjs). ESLint supports both the legacy .eslintrc.* and the newer eslint.config.mjs formats. See the ESLint API reference for a recommended setup.

Good to know

Next.js 16부터 next build는 더 이상 linter를 자동으로 실행하지 않습니다. 대신 NPM script로 linter를 실행할 수 있습니다.

Starting with Next.js 16, next build no longer runs the linter automatically. Instead, you can run your linter through NPM scripts.

자세한 내용은 ESLint Plugin 페이지를 참고하세요.

See the ESLint Plugin page for more information.

Set up Absolute Imports and Module Path AliasesAbsolute Import와 Module Path Alias 설정하기

Next.js는 tsconfig.json과 jsconfig.json 파일의 "paths", "baseUrl" option을 기본으로 지원합니다.

Next.js has in-built support for the "paths" and "baseUrl" options of tsconfig.json and jsconfig.json files.

이 option들을 사용하면 프로젝트 directory를 absolute path로 alias할 수 있어서, module을 더 쉽고 깔끔하게 import할 수 있습니다. 예를 들면 다음과 같습니다:

These options allow you to alias project directories to absolute paths, making it easier and cleaner to import modules. For example:

// Before
import { Button } from '../../../components/button'

// After
import { Button } from '@/components/button'

absolute import를 설정하려면 tsconfig.json 또는 jsconfig.json 파일에 baseUrl configuration option을 추가하세요. 예를 들면 다음과 같습니다:

To configure absolute imports, add the baseUrl configuration option to your tsconfig.json or jsconfig.json file. For example:

tsconfig.json or jsconfig.json
{
  "compilerOptions": {
    "baseUrl": "src/"
  }
}

baseUrl path를 설정하는 것 외에도, "paths" option으로 module path에 "alias"를 지정할 수 있습니다.

In addition to configuring the baseUrl path, you can use the "paths" option to "alias" module paths.

예를 들어 다음 configuration은 @/components/*를 components/*로 mapping합니다:

For example, the following configuration maps @/components/* to components/*:

tsconfig.json or jsconfig.json
{
  "compilerOptions": {
    "baseUrl": "src/",
    "paths": {
      "@/styles/*": ["styles/*"],
      "@/components/*": ["components/*"]
    }
  }
}

각 "paths"는 baseUrl 위치를 기준으로 한 상대 경로입니다.

Each of the "paths" are relative to the baseUrl location.

Upgrade your Next.js appNext.js 앱 업그레이드하기

Next.js 버전을 최신으로 유지하세요. 각 release에는 새 기능과 함께 security patch, bug fix, performance 최적화가 들어 있고, 꾸준히 최신 상태를 유지하면 한 번 한 번의 upgrade 규모가 작아집니다. upgrade command를 실행하세요:

Keep your Next.js version up to date. Each release ships security patches, bug fixes, and performance optimizations alongside new features, and staying current keeps every individual upgrade small. Run the upgrade command:

pnpm next upgrade
npx next upgrade
yarn next upgrade
bunx next upgrade

upgrade를 하면 next package 안의 node_modules/next/dist/docs/에 들어 있는 문서도 함께 업데이트됩니다. 새 기능은 문서와 함께 들어오고, 기존 페이지에도 그동안 발견된 새 가이드와 주의할 점(pitfall)이 반영됩니다. 그러면 프로젝트의 AI coding agent는 학습 데이터가 아니라 설치된 버전을 기준으로 작업하게 됩니다.

Upgrading also updates the documentation bundled inside the next package at node_modules/next/dist/docs/. New features arrive with their docs, and existing pages pick up new guidance and pitfalls discovered along the way. AI coding agents in your project then work from the version you have installed rather than their training data.

coding agent에게 upgrade를 수행하고 검증하게 하려면 npx next@canary upgrade --agent=latest를 실행하세요. 다른 policy는 Upgrade with a coding agent를 참고하세요.

To have a coding agent perform and verify the upgrade, run npx next@canary upgrade --agent=latest. See Upgrade with a coding agent for other policies.

버전별 가이드와 수동 upgrade 절차는 Upgrading을, stable 버전에 들어가기 전의 기능을 미리 보려면 preview 문서를 참고하세요.

See Upgrading for version guides and manual upgrade steps, or the preview docs to explore features before they ship in a stable version.
