opengraph-image and twitter-imageopengraph-image, twitter-image

opengraph-image와 twitter-image file convention을 사용하면 route segment의 Open Graph 이미지와 Twitter 이미지를 설정할 수 있습니다.

The opengraph-image and twitter-image file conventions allow you to set Open Graph and Twitter images for a route segment.

사용자가 사이트 링크를 공유할 때 소셜 네트워크나 메신저 앱에 표시되는 이미지를 설정할 때 유용합니다.

They are useful for setting the images that appear on social networks and messaging apps when a user shares a link to your site.

Open Graph 이미지와 Twitter 이미지를 설정하는 방법은 두 가지입니다:

There are two ways to set Open Graph and Twitter images:

  • 이미지 파일 사용 (.jpg, .png, .gif)
  • 코드로 이미지 생성 (.js, .ts, .tsx)
  • Using image files (.jpg, .png, .gif)
  • Using code to generate images (.js, .ts, .tsx)

Image files (.jpg, .png, .gif)이미지 파일 (.jpg, .png, .gif)

segment에 opengraph-image 또는 twitter-image 이미지 파일을 두어, 이미지 파일로 route segment의 공유 이미지를 설정합니다.

Use an image file to set a route segment's shared image by placing an opengraph-image or twitter-image image file in the segment.

Next.js는 파일을 평가해 앱의 <head> element에 적절한 tag를 자동으로 추가합니다.

Next.js will evaluate the file and automatically add the appropriate tags to your app's <head> element.

Good to know

twitter-image 파일 크기는 5MB를, opengraph-image 파일 크기는 8MB를 넘으면 안 됩니다. 이미지 파일 크기가 이 제한을 넘으면 build가 실패합니다.

The twitter-image file size must not exceed 5MB, and the opengraph-image file size must not exceed 8MB. If the image file size exceeds these limits, the build will fail.

opengraph-image

아무 route segment에나 opengraph-image.(jpg|jpeg|png|gif) 이미지 파일을 추가하세요.

Add an opengraph-image.(jpg|jpeg|png|gif) image file to any route segment.

Generate images using code (.js, .ts, .tsx)코드로 이미지 생성하기 (.js, .ts, .tsx)

실제 이미지 파일을 사용하는 것 외에도, 코드로 이미지를 프로그래밍 방식으로 생성할 수 있습니다.

In addition to using literal image files, you can programmatically generate images using code.

함수를 default export하는 opengraph-image 또는 twitter-image route를 만들어 route segment의 공유 이미지를 생성합니다.

Generate a route segment's shared image by creating an opengraph-image or twitter-image route that default exports a function.

File convention지원 파일 형식
opengraph-image.js, .ts, .tsx
twitter-image.js, .ts, .tsx
File conventionSupported file types
opengraph-image.js, .ts, .tsx
twitter-image.js, .ts, .tsx
Good to know
  • 기본적으로 생성된 이미지는 Request-time API나 cache되지 않은 데이터를 사용하지 않는 한 statically optimized 됩니다(build 시점에 생성되고 cache됨).
  • generateImageMetadata를 사용하면 같은 파일에서 여러 이미지를 생성할 수 있습니다.
  • opengraph-image.js와 twitter-image.js는 특수한 Route Handler로, Request-time API나 dynamic config option을 사용하지 않는 한 기본적으로 cache됩니다.
  • By default, generated images are statically optimized (generated at build time and cached) unless they use Request-time APIs or uncached data.
  • You can generate multiple Images in the same file using generateImageMetadata.
  • opengraph-image.js and twitter-image.js are special Route Handlers that are cached by default unless it uses a Request-time API or dynamic config option.

이미지를 생성하는 가장 쉬운 방법은 next/og의 ImageResponse API를 사용하는 것입니다.

The easiest way to generate an image is to use the ImageResponse API from next/og.

TSJSapp/about/opengraph-image.tsx
import { ImageResponse } from 'next/og'
import { readFile } from 'node:fs/promises'
import { join } from 'node:path'

// Image metadata
export const alt = 'About Acme'
export const size = {
  width: 1200,
  height: 630,
}

export const contentType = 'image/png'

const interSemiBold = await readFile(
  join(process.cwd(), 'assets/Inter-SemiBold.ttf')
)

// Image generation
export default async function Image() {
  return new ImageResponse(
    (
      // ImageResponse JSX element
      <div
        style={{
          fontSize: 128,
          background: 'white',
          width: '100%',
          height: '100%',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        About Acme
      </div>
    ),
    // ImageResponse options
    {
      // For convenience, we can re-use the exported opengraph-image
      // size config to also set the ImageResponse's width and height.
      ...size,
      fonts: [
        {
          name: 'Inter',
          data: interSemiBold,
          style: 'normal',
          weight: 400,
        },
      ],
    }
  )
}

Route Segment Config

opengraph-image와 twitter-image는 특수한 Route Handler로, Page 및 Layout과 같은 route segment configuration option을 사용할 수 있습니다.

opengraph-image and twitter-image are specialized Route Handlers that can use the same route segment configuration options as Pages and Layouts.

Examples예시

Using external data외부 데이터 사용하기

이 예시는 params 객체와 외부 데이터를 사용해 이미지를 생성합니다.

This example uses the params object and external data to generate the image.

Good to know

기본적으로 이렇게 생성된 이미지는 statically optimized 됩니다. 이 동작을 바꾸려면 개별 fetch options나 route segment option을 설정하세요.

By default, this generated image will be statically optimized. You can configure the individual fetch options or route segments options to change this behavior.

TSJSapp/posts/[slug]/opengraph-image.tsx
import { ImageResponse } from 'next/og'

export const alt = 'About Acme'
export const size = {
  width: 1200,
  height: 630,
}
export const contentType = 'image/png'

export default async function Image({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await fetch(`https://.../posts/${slug}`).then((res) =>
    res.json()
  )

  return new ImageResponse(
    (
      <div
        style={{
          fontSize: 48,
          background: 'white',
          width: '100%',
          height: '100%',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        {post.title}
      </div>
    ),
    {
      ...size,
    }
  )
}

Using Node.js runtime with local assets로컬 asset과 함께 Node.js runtime 사용하기

이 예시들은 Node.js runtime을 사용해 file system에서 로컬 이미지를 가져온 뒤, base64 문자열이나 ArrayBuffer로 <img>의 src attribute에 전달합니다. 로컬 asset은 예시 소스 파일이 아니라 프로젝트 root를 기준으로 배치하세요.

These examples use the Node.js runtime to fetch a local image from the file system and pass it to the <img> src attribute, either as a base64 string or an ArrayBuffer. Place the local asset relative to the project root, not the example source file.

이 asset은 request 데이터에 의존하지 않으므로 module scope에서 한 번만 읽으세요. Predictable values를 참고하세요.

The asset doesn't depend on request data, so read it once at module scope. See Predictable values.

TSJSapp/opengraph-image.tsx
import { ImageResponse } from 'next/og'
import { join } from 'node:path'
import { readFile } from 'node:fs/promises'

const logoData = await readFile(join(process.cwd(), 'logo.png'), 'base64')
const logoSrc = `data:image/png;base64,${logoData}`

export default async function Image() {
  return new ImageResponse(
    (
      <div
        style={{
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        <img src={logoSrc} height="100" />
      </div>
    )
  )
}

<img> element의 src attribute에 ArrayBuffer를 전달하는 것은 HTML spec에 포함되지 않습니다. next/og가 사용하는 rendering engine은 이를 지원하지만, TypeScript 정의는 spec을 따르기 때문에 이 기능을 사용하려면 @ts-expect-error directive 같은 것이 필요합니다.

Passing an ArrayBuffer to the src attribute of an <img> element is not part of the HTML spec. The rendering engine used by next/og supports it, but because TypeScript definitions follow the spec, you need a @ts-expect-error directive or similar to use this feature.

TSJSapp/opengraph-image.tsx
import { ImageResponse } from 'next/og'
import { join } from 'node:path'
import { readFile } from 'node:fs/promises'

const logoData = await readFile(join(process.cwd(), 'logo.png'))
const logoSrc = Uint8Array.from(logoData).buffer

export default async function Image() {
  return new ImageResponse(
    (
      <div
        style={{
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        {/* @ts-expect-error Satori accepts ArrayBuffer/typed arrays for <img src> at runtime */}
        <img src={logoSrc} height="100" />
      </div>
    )
  )
}
