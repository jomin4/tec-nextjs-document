cacheComponentscacheComponents

Cache Components는 use cache directive를 사용해 component 및 function 단위의 caching을 가능하게 합니다. data fetching은 기본적으로 dynamic이며, page, component, function 단위에서 무엇을 cache할지 직접 선택합니다. Next.js는 즉시 제공되는 static HTML shell을 prerender하고, dynamic content는 준비되는 대로 stream되므로 하나의 route 안에서 static content와 dynamic content를 섞어 사용할 수 있습니다.

Cache Components enables component and function-level caching using the use cache directive. Data fetching is dynamic by default, and you choose what to cache at the page, component, or function level. Next.js prerenders a static HTML shell that is served immediately while dynamic content streams in when ready, letting you mix static and dynamic content within a single route.

Usage사용법

cacheComponents flag를 활성화하려면 next.config.ts 파일에서 partialPrefetching과 함께 true로 설정하세요:

To enable the cacheComponents flag, set it to true in your next.config.ts file, together with partialPrefetching:

TSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}

export default nextConfig

partialPrefetching은 명시적으로 설정하세요. Cache Components의 첫 release에는 Partial Prefetching이 포함되지 않았기 때문에, 설정하지 않으면 warning이 출력됩니다. Partial Prefetching 이전에 Cache Components를 도입한 앱을 migration하는 동안에만 false로 설정하세요. 다음 major release에서는 두 기능이 모든 곳에서 활성화되며, 이 option들은 제거됩니다.

Set partialPrefetching explicitly. Leaving it unset logs a warning, because the first release of Cache Components did not include Partial Prefetching. Set it to false only while migrating an app that adopted Cache Components before Partial Prefetching. Both features will be enabled everywhere in the next major release, and the options will be removed.

Good to know

Cache Components는 Node.js runtime이 필요하며 runtime route segment config를 지원하지 않습니다. runtime = 'nodejs'와 deprecated된 runtime = 'edge'를 포함해 모든 runtime export를 제거하세요. 다른 server-side JavaScript runtime은 동작이 보장되지 않습니다. Migrating to Cache Components를 참고하세요.

Cache Components requires the Node.js runtime and does not support the runtime route segment config. Remove any runtime export, including runtime = 'nodejs' and the deprecated runtime = 'edge'. Other server-side JavaScript runtimes are not guaranteed to work. See Migrating to Cache Components.

cacheComponents가 활성화되면 다음 cache 함수와 설정을 사용할 수 있습니다:

When cacheComponents is enabled, you can use the following cache functions and configurations:

  • use cache directive
  • use cache와 함께 사용하는 cacheLife function
  • cacheTag function
  • The use cache directive
  • The cacheLife function with use cache
  • The cacheTag function
Good to know

experimental.useCache 또는 experimental.dynamicIO를 사용했다면 Version 16 upgrade guide를 참고해 migration하세요. route segment config와 기타 caching pattern을 migration하려면 Migrating to Cache Components를 참고하세요.

If you used experimental.useCache or experimental.dynamicIO, migrate using the Version 16 upgrade guide. To migrate route segment configs and other caching patterns, see Migrating to Cache Components.

또한 cacheComponents는 Partial Prerendering (PPR) 방식을 App Router의 기본 동작으로 구현합니다. 따라서 experimental.ppr configuration flag와 experimental_ppr route segment configuration은 더 이상 필요하지 않으며 제거되었습니다.

Additionally, cacheComponents implements Partial Prerendering (PPR) as the default behavior in the App Router. This means the experimental.ppr configuration flag and the experimental_ppr route segment configuration are no longer necessary and have been removed.

static shell과 streaming이 어떻게 함께 동작하는지는 Prerendering을 읽어 보세요.

Read Prerendering for how the static shell and streaming fit together.

Good to know

Next.js 15에서 experimental PPR을 사용했다면, migration 시 Version 16 upgrade guide의 Partial Prerendering (PPR) 섹션을 참고하세요.

If you used experimental PPR in Next.js 15, refer to the Partial Prerendering (PPR) section of the Version 16 upgrade guide when migrating.

Navigation with ActivityActivity를 사용한 navigation

cacheComponents가 활성화되면 Next.js는 React의 <Activity> component를 사용해 client-side navigation 중에 component state를 보존합니다.

When cacheComponents is enabled, Next.js uses React's <Activity> component to preserve component state during client-side navigation.

다른 곳으로 navigate할 때 이전 route를 unmount하는 대신, Next.js는 Activity mode를 "hidden"으로 설정합니다. 이는 다음을 의미합니다:

Rather than unmounting the previous route when you navigate away, Next.js sets the Activity mode to "hidden". This means:

  • route 간에 navigate할 때 component state가 보존됩니다
  • 뒤로 navigate하면 이전 route가 state를 그대로 유지한 채 다시 나타납니다
  • route가 hidden 상태가 되면 Effect가 정리(clean up)되고, 다시 visible 상태가 되면 새로 생성됩니다
  • Component state is preserved when navigating between routes
  • When you navigate back, the previous route reappears with its state intact
  • Effects are cleaned up when a route is hidden, and recreated when it becomes visible again

이 동작은 사용자가 route 사이를 오갈 때 UI state(form 입력값이나 펼친 섹션 등)를 유지하여 navigation 경험을 개선합니다.

This behavior improves the navigation experience by maintaining UI state (form inputs, or expanded sections) when users navigate back and forth between routes.

Good to know

Next.js는 heuristic을 사용해 최근 방문한 몇 개의 route를 "hidden" 상태로 유지하며, 과도한 증가를 막기 위해 오래된 route는 DOM에서 제거합니다.

Next.js uses heuristics to keep a few recently visited routes "hidden", while older routes are removed from the DOM to prevent excessive growth.

일부 UI pattern은 component가 unmount되지 않고 mount된 상태로 유지될 때 다르게 동작합니다. dropdown, dialog, testing 같은 일반적인 pattern을 처리하는 방법은 Preserving UI state guide를 참고하세요.

Some UI patterns behave differently when components stay mounted instead of unmounting. See the Preserving UI state guide for handling common patterns like dropdowns, dialogs, and testing.
