Custom AppCustom App

Next.js는 App component를 사용해 page를 초기화합니다. 이를 override해서 page 초기화를 제어하고 다음을 할 수 있습니다:

Next.js uses the App component to initialize pages. You can override it and control the page initialization and:

  • page 변경 사이에 공유되는 layout 만들기
  • page에 추가 data 주입하기
  • global CSS 추가하기
  • Create a shared layout between page changes
  • Inject additional data into pages
  • Add global CSS

Usage사용법

기본 App을 override하려면 아래처럼 pages/_app 파일을 만드세요:

To override the default App, create the file pages/_app as shown below:

TSJSpages/_app.tsx
import type { AppProps } from 'next/app'

export default function MyApp({ Component, pageProps }: AppProps) {
  return <Component {...pageProps} />
}
export default function MyApp({ Component, pageProps }) {
  return <Component {...pageProps} />
}

Component prop은 현재 활성화된 page이므로, route 사이를 navigate할 때마다 Component가 새 page로 바뀝니다. 따라서 Component에 전달하는 모든 props는 page가 받게 됩니다.

The Component prop is the active page, so whenever you navigate between routes, Component will change to the new page. Therefore, any props you send to Component will be received by the page.

pageProps는 data fetching method 중 하나가 page를 위해 미리 load한 initial props를 담은 object이며, 그렇지 않으면 빈 object입니다.

pageProps is an object with the initial props that were preloaded for your page by one of our data fetching methods, otherwise it's an empty object.

Good to know
  • 앱이 실행 중일 때 custom App을 추가했다면 development server를 재시작해야 합니다. pages/_app.js가 이전에 없었던 경우에만 필요합니다.
  • App은 getStaticProps나 getServerSideProps 같은 Next.js Data Fetching method를 지원하지 않습니다.
  • If your app is running and you added a custom App, you'll need to restart the development server. Only required if pages/_app.js didn't exist before.
  • App does not support Next.js Data Fetching methods like getStaticProps or getServerSideProps.

getInitialProps with AppApp에서 getInitialProps 사용하기

App에서 getInitialProps를 사용하면 getStaticProps가 없는 page에서 Automatic Static Optimization이 비활성화됩니다.

Using getInitialProps in App will disable Automatic Static Optimization for pages without getStaticProps.

이 패턴은 권장하지 않습니다. 대신 App Router를 점진적으로 도입하는 것을 고려하세요. App Router를 사용하면 page와 layout의 data를 더 쉽게 fetch할 수 있습니다.

We do not recommend using this pattern. Instead, consider incrementally adopting the App Router, which allows you to more easily fetch data for pages and layouts.

TSJSpages/_app.tsx
import App, { AppContext, AppInitialProps, AppProps } from 'next/app'

type AppOwnProps = { example: string }

export default function MyApp({
  Component,
  pageProps,
  example,
}: AppProps & AppOwnProps) {
  return (
    <>
      <p>Data: {example}</p>
      <Component {...pageProps} />
    </>
  )
}

MyApp.getInitialProps = async (
  context: AppContext
): Promise<AppOwnProps & AppInitialProps> => {
  const ctx = await App.getInitialProps(context)

  return { ...ctx, example: 'data' }
}
import App from 'next/app'

export default function MyApp({ Component, pageProps, example }) {
  return (
    <>
      <p>Data: {example}</p>
      <Component {...pageProps} />
    </>
  )
}

MyApp.getInitialProps = async (context) => {
  const ctx = await App.getInitialProps(context)

  return { ...ctx, example: 'data' }
}
