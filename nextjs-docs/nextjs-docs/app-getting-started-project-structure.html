Project structure and organization프로젝트 구조와 구성

이 페이지는 Next.js의 모든 폴더·파일 convention(관례)을 한눈에 정리하고, 프로젝트를 구성하는 방법에 대한 권장 사항을 소개합니다.

This page provides an overview of all the folder and file conventions in Next.js, and recommendations for organizing your project.

최상위 폴더는 애플리케이션 코드와 static asset을 정리하는 데 사용합니다.

Top-level folders are used to organize your application's code and static assets.

Top-level files are used to configure your application, manage dependencies, run proxy, integrate monitoring tools, and define environment variables.

Nested routes중첩 route

폴더는 URL segment를 정의합니다. 폴더를 중첩하면 segment도 중첩됩니다. 어느 단계에 있든 layout은 자신의 하위 segment를 감쌉니다. page 또는 route 파일이 있어야 route가 공개됩니다.

Folders define URL segments. Nesting folders nests segments. Layouts at any level wrap their child segments. A route becomes public when a page or route file exists.

Dynamic routesDynamic route

대괄호로 segment를 parameter화합니다. 단일 param에는 [segment], catch‑all에는 [...segment], optional catch‑all에는 [[...segment]]를 사용하세요. 값은 params prop으로 접근합니다.

Parameterize segments with square brackets. Use [segment] for a single param, [...segment] for catch‑all, and [[...segment]] for optional catch‑all. Access values via the params prop.

route group (group)으로 URL을 바꾸지 않고 코드를 정리하고, private 폴더 _folder로 routing되지 않는 파일을 함께 배치(colocate)하세요.

Organize code without changing URLs with route groups (group), and colocate non-routable files with private folders _folder.

Parallel and Intercepted RoutesParallel Route와 Intercepted Route

이 기능들은 slot 기반 layout이나 modal routing 같은 특정 UI 패턴에 잘 맞습니다.

These features fit specific UI patterns, such as slot-based layouts or modal routing.

parent layout이 render하는 이름 있는 slot에는 @slot을 사용하세요. intercept 패턴을 사용하면 URL을 바꾸지 않고 현재 layout 안에서 다른 route를 render할 수 있습니다. 예를 들어 목록 위에 상세 화면을 modal로 띄울 때 사용합니다.

Use @slot for named slots rendered by a parent layout. Use intercept patterns to render another route inside the current layout without changing the URL, for example, to show a details view as a modal over a list.

Organizing your project프로젝트 구성하기

Next.js는 프로젝트 파일을 어떻게 정리하고 함께 배치(colocate)할지에 대해 특정 방식을 강요하지 않습니다(unopinionated). 다만 프로젝트 구성에 도움이 되는 몇 가지 기능을 제공합니다.

Next.js is unopinionated about how you organize and colocate your project files. But it does provide several features to help you organize your project.

Component hierarchyComponent 계층 구조

special 파일에 정의된 component는 특정 계층 구조로 render됩니다:

The components defined in special files are rendered in a specific hierarchy:

  • layout.js
  • template.js
  • error.js (React error boundary)
  • loading.js (React suspense boundary)
  • not-found.js ("not found" UI를 위한 React error boundary)
  • page.js 또는 중첩된 layout.js
  • layout.js
  • template.js
  • error.js (React error boundary)
  • loading.js (React suspense boundary)
  • not-found.js (React error boundary for "not found" UI)
  • page.js or nested layout.js

중첩 route에서는 component가 재귀적으로 render됩니다. 즉, 어떤 route segment의 component는 parent segment의 component 안에 중첩됩니다.

The components are rendered recursively in nested routes, meaning the components of a route segment will be nested inside the components of its parent segment.

ColocationColocation(함께 배치하기)

app directory에서는 중첩된 폴더가 route 구조를 정의합니다. 각 폴더는 URL path의 해당 segment에 mapping되는 route segment를 나타냅니다.

In the app directory, nested folders define route structure. Each folder represents a route segment that is mapped to a corresponding segment in a URL path.

하지만 route 구조가 폴더로 정의되더라도, route segment에 page.js 또는 route.js 파일이 추가되기 전까지는 그 route에 공개적으로 접근할 수 없습니다.

However, even though route structure is defined through folders, a route is not publicly accessible until a page.js or route.js file is added to a route segment.

그리고 route가 공개된 뒤에도 client로 전송되는 것은 page.js 또는 route.js가 return하는 콘텐츠뿐입니다.

And, even when a route is made publicly accessible, only the content returned by page.js or route.js is sent to the client.

따라서 프로젝트 파일을 app directory의 route segment 안에 실수로 routing될 걱정 없이 안전하게 함께 배치(colocate)할 수 있습니다.

This means that project files can be safely colocated inside route segments in the app directory without accidentally being routable.

Good to know

프로젝트 파일을 app 안에 함께 배치할 수는 있지만, 반드시 그렇게 해야 하는 것은 아닙니다. 원한다면 app directory 밖에 둘 수도 있습니다.

While you can colocate your project files in app you don't have to. If you prefer, you can keep them outside the app directory.

Private foldersPrivate 폴더

폴더 이름 앞에 underscore를 붙이면 private 폴더를 만들 수 있습니다: _folderName

Private folders can be created by prefixing a folder with an underscore: _folderName

이는 해당 폴더가 private한 구현 세부 사항이며 routing system이 고려하지 않아야 한다는 뜻이고, 따라서 그 폴더와 모든 하위 폴더까지 routing에서 제외됩니다.

This indicates the folder is a private implementation detail and should not be considered by the routing system, thereby opting the folder and all its subfolders out of routing.

app directory의 파일은 기본적으로 안전하게 함께 배치할 수 있으므로 colocation을 위해 private 폴더가 꼭 필요하지는 않습니다. 하지만 다음과 같은 경우에 유용합니다:

Since files in the app directory can be safely colocated by default, private folders are not required for colocation. However, they can be useful for:

  • UI logic과 routing logic을 분리할 때.
  • 프로젝트 전체와 Next.js ecosystem에 걸쳐 내부 파일을 일관되게 정리할 때.
  • code editor에서 파일을 정렬하고 그룹화할 때.
  • 향후 Next.js 파일 convention과 이름이 충돌할 가능성을 피할 때.
  • Separating UI logic from routing logic.
  • Consistently organizing internal files across a project and the Next.js ecosystem.
  • Sorting and grouping files in code editors.
  • Avoiding potential naming conflicts with future Next.js file conventions.
Good to know
  • framework convention은 아니지만, private 폴더 밖에 있는 파일도 같은 underscore 패턴으로 "private"이라고 표시하는 것을 고려해 볼 수 있습니다.
  • 폴더 이름 앞에 %5F(underscore를 URL-encoding한 형태)를 붙이면 underscore로 시작하는 URL segment를 만들 수 있습니다: %5FfolderName.
  • private 폴더를 사용하지 않는다면, 예상치 못한 이름 충돌을 막기 위해 Next.js의 special 파일 convention을 알아 두면 도움이 됩니다.
  • While not a framework convention, you might also consider marking files outside private folders as "private" using the same underscore pattern.
  • You can create URL segments that start with an underscore by prefixing the folder name with %5F (the URL-encoded form of an underscore): %5FfolderName.
  • If you don't use private folders, it would be helpful to know Next.js special file conventions to prevent unexpected naming conflicts.

Route groupsRoute group

폴더 이름을 괄호로 감싸면 route group을 만들 수 있습니다: (folderName)

Route groups can be created by wrapping a folder in parenthesis: (folderName)

이는 해당 폴더가 정리 목적으로만 쓰이며 route의 URL path에 포함되지 않아야 한다는 뜻입니다.

This indicates the folder is for organizational purposes and should not be included in the route's URL path.

Route group은 다음과 같은 경우에 유용합니다:

Route groups are useful for:

  • 사이트 섹션, 목적, 팀별로 route를 정리할 때. 예: marketing page, admin page 등.
  • 같은 route segment 단계에서 중첩 layout을 사용할 때:
    • 같은 segment에 여러 중첩 layout 만들기(여러 root layout 포함)
    • 공통 segment 안의 일부 route에만 layout 추가하기
  • Organizing routes by site section, intent, or team. e.g. marketing pages, admin pages, etc.
  • Enabling nested layouts in the same route segment level:
    • Creating multiple nested layouts in the same segment, including multiple root layouts
    • Adding a layout to a subset of routes in a common segment

src foldersrc 폴더

Next.js는 애플리케이션 코드(app 포함)를 선택 사항인 src 폴더 안에 저장하는 것을 지원합니다. 이렇게 하면 대부분 프로젝트 root에 있는 프로젝트 configuration 파일과 애플리케이션 코드를 분리할 수 있습니다.

Next.js supports storing application code (including app) inside an optional src folder. This separates application code from project configuration files which mostly live in the root of a project.

Examples예시

다음 섹션은 흔히 쓰이는 전략을 아주 개략적으로 정리한 것입니다. 가장 간단한 교훈은 여러분과 팀에 맞는 전략을 골라 프로젝트 전체에서 일관되게 유지하라는 것입니다.

The following section lists a very high-level overview of common strategies. The simplest takeaway is to choose a strategy that works for you and your team and be consistent across the project.

Good to know

아래 예시에서는 components와 lib 폴더를 일반적인 placeholder로 사용합니다. 이 이름들은 framework에서 특별한 의미가 없으며, 프로젝트에서는 ui, utils, hooks, styles 같은 다른 폴더를 사용할 수도 있습니다.

In our examples below, we're using components and lib folders as generalized placeholders, their naming has no special framework significance and your projects might use other folders like ui, utils, hooks, styles, etc.

Store project files outside of app프로젝트 파일을 app 밖에 두기

이 전략은 모든 애플리케이션 코드를 프로젝트 root에 있는 공유 폴더에 두고, app directory는 순수하게 routing 용도로만 사용합니다.

This strategy stores all application code in shared folders in the root of your project and keeps the app directory purely for routing purposes.

Store project files in top-level folders inside of app프로젝트 파일을 app 안의 최상위 폴더에 두기

이 전략은 모든 애플리케이션 코드를 app directory root에 있는 공유 폴더에 둡니다.

This strategy stores all application code in shared folders in the root of the app directory.

Split project files by feature or route기능 또는 route별로 프로젝트 파일 나누기

이 전략은 전역으로 공유되는 애플리케이션 코드는 root app directory에 두고, 더 구체적인 애플리케이션 코드는 그것을 사용하는 route segment로 나눠서 둡니다.

This strategy stores globally shared application code in the root app directory and splits more specific application code into the route segments that use them.

Organize routes without affecting the URL pathURL path에 영향 없이 route 정리하기

URL에 영향을 주지 않고 route를 정리하려면, 관련 route를 함께 묶는 group을 만드세요. 괄호로 감싼 폴더(예: (marketing) 또는 (shop))는 URL에서 생략됩니다.

To organize routes without affecting the URL, create a group to keep related routes together. The folders in parenthesis will be omitted from the URL (e.g. (marketing) or (shop)).

(marketing)과 (shop) 안의 route는 같은 URL 계층을 공유하지만, 각 폴더 안에 layout.js 파일을 추가하면 group마다 다른 layout을 만들 수 있습니다. 이 layout들은 기존 app layout 안에 중첩됩니다.

Even though routes inside (marketing) and (shop) share the same URL hierarchy, you can create a different layout for each group by adding a layout.js file inside their folders. These layouts nest within the existing app layout.

Opting specific segments into a layout특정 segment에만 layout 적용하기

특정 route에만 layout을 적용하려면, 새 route group(예: (shop))을 만들고 같은 layout을 공유할 route(예: account와 cart)를 그 group으로 옮기세요. group 밖의 route(예: checkout)는 그 layout을 공유하지 않습니다.

To opt specific routes into a layout, create a new route group (e.g. (shop)) and move the routes that share the same layout into the group (e.g. account and cart). The routes outside of the group will not share the layout (e.g. checkout).

Opting for loading skeletons on a specific route특정 route에만 loading skeleton 적용하기

loading.js 파일을 통한 loading skeleton을 특정 route에만 적용하려면, 새 route group(예: /(overview))을 만든 다음 loading.tsx를 그 route group 안으로 옮기세요.

To apply a loading skeleton via a loading.js file to a specific route, create a new route group (e.g., /(overview)) and then move your loading.tsx inside that route group.

이제 loading.tsx 파일은 URL path 구조에 영향을 주지 않으면서, 모든 dashboard page가 아니라 dashboard → overview page에만 적용됩니다.

Now, the loading.tsx file will only apply to your dashboard → overview page instead of all your dashboard pages without affecting the URL path structure.

Creating multiple root layouts여러 root layout 만들기

여러 root layout을 만들려면 최상위 layout.js 파일을 제거하고, 각 route group 안에 layout.js 파일을 추가하세요. 이는 UI나 경험이 완전히 다른 섹션으로 애플리케이션을 나눌 때 유용합니다. <html>과 <body> tag는 각 root layout에 추가해야 합니다.

To create multiple root layouts, remove the top-level layout.js file, and add a layout.js file inside each route group. This is useful for partitioning an application into sections that have a completely different UI or experience. The <html> and <body> tags need to be added to each root layout.

위 예시에서 (marketing)과 (shop)은 각각 자신만의 root layout을 가집니다.

In the example above, both (marketing) and (shop) have their own root layout.
