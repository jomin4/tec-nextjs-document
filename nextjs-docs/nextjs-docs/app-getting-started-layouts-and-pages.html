Layouts and PagesLayout과 Page

Next.js는 file-system 기반 routing을 사용합니다. 즉, 폴더와 파일로 route를 정의할 수 있습니다. 이 페이지에서는 layout과 page를 만들고 서로 연결하는 방법을 안내합니다.

Next.js uses file-system based routing, meaning you can use folders and files to define routes. This page will guide you through how to create layouts and pages, and link between them.

Creating a pagepage 만들기

page는 특정 route에서 render되는 UI입니다. page를 만들려면 app directory 안에 page 파일을 추가하고 React component를 default export하세요. 예를 들어 index page(/)를 만들려면 다음과 같이 합니다:

A page is UI that is rendered on a specific route. To create a page, add a page file inside the app directory and default export a React component. For example, to create an index page (/):

TSJSapp/page.tsx
export default function Page() {
  return <h1>Hello Next.js!</h1>
}
export default function Page() {
  return <h1>Hello Next.js!</h1>
}

Creating a layoutlayout 만들기

layout은 여러 page 사이에서 공유되는 UI입니다. navigation 시 layout은 state를 유지하고, interactive한 상태로 남으며, 다시 render되지 않습니다.

A layout is UI that is shared between multiple pages. On navigation, layouts preserve state, remain interactive, and do not rerender.

layout 파일에서 React component를 default export하면 layout을 정의할 수 있습니다. 이 component는 page 또는 다른 layout이 될 수 있는 children prop을 받아야 합니다.

You can define a layout by default exporting a React component from a layout file. The component should accept a children prop which can be a page or another layout.

예를 들어 index page를 child로 받는 layout을 만들려면 app directory 안에 layout 파일을 추가하세요:

For example, to create a layout that accepts your index page as child, add a layout file inside the app directory:

TSJSapp/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>
        {/* Layout UI */}
        {/* Place children where you want to render a page or nested layout */}
        <main>{children}</main>
      </body>
    </html>
  )
}
export default function DashboardLayout({ children }) {
  return (
    <html lang="en">
      <body>
        {/* Layout UI */}
        {/* Place children where you want to render a page or nested layout */}
        <main>{children}</main>
      </body>
    </html>
  )
}

위 layout은 app directory의 root에 정의되어 있기 때문에 root layout이라고 부릅니다. root layout은 필수이며 html과 body tag를 반드시 포함해야 합니다.

The layout above is called a root layout because it's defined at the root of the app directory. The root layout is required and must contain html and body tags.

Creating a nested route중첩 route 만들기

중첩 route는 여러 URL segment로 구성된 route입니다. 예를 들어 /blog/[slug] route는 세 개의 segment로 구성됩니다:

A nested route is a route composed of multiple URL segments. For example, the /blog/[slug] route is composed of three segments:

  • / (Root Segment)
  • blog (Segment)
  • [slug] (Leaf Segment)
  • / (Root Segment)
  • blog (Segment)
  • [slug] (Leaf Segment)

Next.js에서는:

In Next.js:

  • 폴더로 URL segment에 mapping되는 route segment를 정의합니다.
  • 파일(page, layout 등)로 segment에 표시되는 UI를 만듭니다.
  • Folders are used to define the route segments that map to URL segments.
  • Files (like page and layout) are used to create UI that is shown for a segment.

중첩 route를 만들려면 폴더 안에 폴더를 중첩하면 됩니다. 예를 들어 /blog route를 추가하려면 app directory에 blog라는 폴더를 만드세요. 그다음 /blog를 공개적으로 접근 가능하게 하려면 page.tsx 파일을 추가합니다:

To create nested routes, you can nest folders inside each other. For example, to add a route for /blog, create a folder called blog in the app directory. Then, to make /blog publicly accessible, add a page.tsx file:

TSJSapp/blog/page.tsx
// Dummy imports
import { getPosts } from '@/lib/posts'
import { Post } from '@/ui/post'

export default async function Page() {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <Post key={post.id} post={post} />
      ))}
    </ul>
  )
}
// Dummy imports
import { getPosts } from '@/lib/posts'
import { Post } from '@/ui/post'

export default async function Page() {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <Post key={post.id} post={post} />
      ))}
    </ul>
  )
}

폴더를 계속 중첩해서 중첩 route를 만들 수 있습니다. 예를 들어 특정 blog post를 위한 route를 만들려면 blog 안에 새 [slug] 폴더를 만들고 page 파일을 추가하세요:

You can continue nesting folders to create nested routes. For example, to create a route for a specific blog post, create a new [slug] folder inside blog and add a page file:

TSJSapp/blog/[slug]/page.tsx
export function generateStaticParams() {}

export default function Page() {
  return <h1>Hello, Blog Post Page!</h1>
}
export function generateStaticParams() {}

export default function Page() {
  return <h1>Hello, Blog Post Page!</h1>
}

폴더 이름을 대괄호로 감싸면(예: [slug]) dynamic route segment가 만들어지며, 이는 데이터로부터 여러 page를 생성하는 데 사용됩니다. 예: blog post, 상품 page 등.

Wrapping a folder name in square brackets (e.g. [slug]) creates a dynamic route segment which is used to generate multiple pages from data. e.g. blog posts, product pages, etc.

Nesting layoutslayout 중첩하기

기본적으로 폴더 계층 안의 layout도 중첩됩니다. 즉, layout은 children prop을 통해 child layout을 감쌉니다. 특정 route segment(폴더) 안에 layout을 추가하면 layout을 중첩할 수 있습니다.

By default, layouts in the folder hierarchy are also nested, which means they wrap child layouts via their children prop. You can nest layouts by adding layout inside specific route segments (folders).

예를 들어 /blog route용 layout을 만들려면 blog 폴더 안에 새 layout 파일을 추가하세요.

For example, to create a layout for the /blog route, add a new layout file inside the blog folder.

TSJSapp/blog/layout.tsx
export default function BlogLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return <section>{children}</section>
}
export default function BlogLayout({ children }) {
  return <section>{children}</section>
}

위 두 layout을 합치면 root layout(app/layout.js)이 blog layout(app/blog/layout.js)을 감싸고, blog layout은 다시 blog page(app/blog/page.js)와 blog post page(app/blog/[slug]/page.js)를 감쌉니다.

If you were to combine the two layouts above, the root layout (app/layout.js) would wrap the blog layout (app/blog/layout.js), which would wrap the blog (app/blog/page.js) and blog post page (app/blog/[slug]/page.js).

Creating a dynamic segmentdynamic segment 만들기

Dynamic segment를 사용하면 데이터로부터 생성되는 route를 만들 수 있습니다. 예를 들어 blog post마다 route를 직접 만드는 대신, dynamic segment를 만들어 blog post 데이터를 바탕으로 route를 생성할 수 있습니다.

Dynamic segments allow you to create routes that are generated from data. For example, instead of manually creating a route for each individual blog post, you can create a dynamic segment to generate the routes based on blog post data.

dynamic segment를 만들려면 segment(폴더) 이름을 대괄호로 감싸세요: [segmentName]. 예를 들어 app/blog/[slug]/page.tsx route에서는 [slug]가 dynamic segment입니다.

To create a dynamic segment, wrap the segment (folder) name in square brackets: [segmentName]. For example, in the app/blog/[slug]/page.tsx route, the [slug] is the dynamic segment.

TSJSapp/blog/[slug]/page.tsx
export default async function BlogPostPage({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <div>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </div>
  )
}
export default async function BlogPostPage({ params }) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <div>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </div>
  )
}

Dynamic Segment와 params props에 대해 더 알아보세요.

Learn more about Dynamic Segments and the params props.

Dynamic Segment 안의 중첩 layout도 params props에 접근할 수 있습니다.

Nested layouts within Dynamic Segments can also access the params props.

Rendering with search paramssearch params로 rendering하기

Server Component page에서는 searchParams prop으로 search parameter에 접근할 수 있습니다:

In a Server Component page, you can access search parameters using the searchParams prop:

TSJSapp/page.tsx
export default async function Page({
  searchParams,
}: {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const filters = (await searchParams).filters
}
export default async function Page({ searchParams }) {
  const filters = (await searchParams).filters
}

searchParams를 사용하면 search parameter를 읽어 올 incoming request가 필요하기 때문에 page가 dynamic rendering 방식으로 전환됩니다.

Using searchParams opts your page into dynamic rendering because it requires an incoming request to read the search parameters from.

Client Component는 useSearchParams hook으로 search params를 읽을 수 있습니다.

Client Components can read search params using the useSearchParams hook.

prerender되는 route와 dynamic하게 render되는 route에서의 useSearchParams에 대해 더 알아보세요.

Learn more about useSearchParams in prerendered and dynamically rendered routes.

What to use and when언제 무엇을 쓸까

  • search parameter로 page의 데이터를 load해야 할 때(예: pagination, database에서 filtering)는 searchParams prop을 사용하세요.
  • search parameter를 client에서만 사용할 때(예: props로 이미 load된 목록을 filtering)는 useSearchParams를 사용하세요.
  • 작은 최적화로, callback이나 event handler 안에서 new URLSearchParams(window.location.search)를 사용하면 re-render를 일으키지 않고 search params를 읽을 수 있습니다.
  • Use the searchParams prop when you need search parameters to load data for the page (e.g. pagination, filtering from a database).
  • Use useSearchParams when search parameters are used only on the client (e.g. filtering a list already loaded via props).
  • As a small optimization, you can use new URLSearchParams(window.location.search) in callbacks or event handlers to read search params without triggering re-renders.

Linking between pagespage 사이 연결하기

<Link> component를 사용해 route 사이를 navigation할 수 있습니다. <Link>는 HTML <a> tag를 확장해 prefetching과 client-side navigation을 제공하는 Next.js 내장 component입니다.

You can use the <Link> component to navigate between routes. <Link> is a built-in Next.js component that extends the HTML <a> tag to provide prefetching and client-side navigation.

예를 들어 blog post 목록을 만들려면 next/link에서 <Link>를 import하고 component에 href prop을 전달하세요:

For example, to generate a list of blog posts, import <Link> from next/link and pass a href prop to the component:

TSJSapp/ui/post.tsx
import Link from 'next/link'
import { getPosts } from '@/lib/posts'

export default async function Posts() {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.slug}>
          <Link href={`/blog/${post.slug}`}>{post.title}</Link>
        </li>
      ))}
    </ul>
  )
}
import Link from 'next/link'
import { getPosts } from '@/lib/posts'

export default async function Posts() {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.slug}>
          <Link href={`/blog/${post.slug}`}>{post.title}</Link>
        </li>
      ))}
    </ul>
  )
}
Good to know

<Link>는 Next.js에서 route 사이를 navigation하는 기본 방법입니다. 더 고급 navigation이 필요하면 useRouter hook을 사용할 수도 있습니다.

<Link> is the primary way to navigate between routes in Next.js. You can also use the useRouter hook for more advanced navigation.

Route Props HelpersRoute Props Helper

Next.js는 route 구조로부터 params와 이름 있는 slot을 추론하는 utility type을 제공합니다:

Next.js exposes utility types that infer params and named slots from your route structure:

  • PageProps: params와 searchParams를 포함한 page component용 props입니다.
  • LayoutProps: children과 모든 이름 있는 slot(예: @analytics 같은 폴더)을 포함한 layout component용 props입니다.
  • PageProps: Props for page components, including params and searchParams.
  • LayoutProps: Props for layout components, including children and any named slots (e.g. folders like @analytics).

이 helper들은 전역으로 사용할 수 있으며, next dev, next build, next typegen 중 하나를 실행할 때 생성됩니다.

These are globally available helpers, generated when running either next dev, next build or next typegen.

TSapp/blog/[slug]/page.tsx
export default async function Page(props: PageProps<'/blog/[slug]'>) {
  const { slug } = await props.params
  return <h1>Blog post: {slug}</h1>
}
TSapp/dashboard/layout.tsx
export default function Layout(props: LayoutProps<'/dashboard'>) {
  return (
    <section>
      {props.children}
      {/* If you have app/dashboard/@analytics, it appears as a typed slot: */}
      {/* {props.analytics} */}
    </section>
  )
}
Good to know
  • Static route에서는 params가 {}로 resolve됩니다.
  • PageProps, LayoutProps는 전역 helper이므로 import할 필요가 없습니다.
  • Type은 next dev, next build, next typegen 실행 중에 생성됩니다.
  • Static routes resolve params to {}.
  • PageProps, LayoutProps are global helpers — no imports required.
  • Types are generated during next dev, next build or next typegen.
