rewritesrewrites

Rewrite를 사용하면 들어오는 request path를 다른 destination path로 mapping할 수 있습니다.

Rewrites allow you to map an incoming request path to a different destination path.

Rewrite는 URL proxy처럼 동작하며 destination path를 가려서, 사용자가 사이트 안에서 위치를 바꾸지 않은 것처럼 보이게 합니다. 반면 redirects는 새 페이지로 경로를 바꾸고 URL 변경을 그대로 보여 줍니다.

Rewrites act as a URL proxy and mask the destination path, making it appear the user hasn't changed their location on the site. In contrast, redirects will reroute to a new page and show the URL changes.

rewrite를 사용하려면 next.config.js의 rewrites key를 사용하면 됩니다:

To use rewrites you can use the rewrites key in next.config.js:

JSnext.config.js
module.exports = {
  rewrites() {
    return [
      {
        source: '/about',
        destination: '/',
      },
    ]
  },
}

Rewrite는 client-side routing에도 적용됩니다. 위 예시에서 <Link href="/about">으로 이동하면 URL은 /about으로 유지되면서 /의 콘텐츠가 제공됩니다.

Rewrites are applied to client-side routing. In the example above, navigating to <Link href="/about"> will serve content from / while keeping the URL as /about.

rewrites는 동기 함수 또는 async 함수로 정의할 수 있습니다. 이 함수는 source와 destination property를 가진 객체들을 담은 배열, 또는 배열들로 이루어진 객체(아래 참고)를 반환하거나 그 값으로 resolve되어야 합니다:

rewrites can be defined as a synchronous or async function. It should return, or resolve to, either an array or an object of arrays (see below) holding objects with source and destination properties:

  • source: String - 들어오는 request path pattern입니다.
  • destination: String - route하려는 경로입니다.
  • basePath: false 또는 undefined - false이면 matching할 때 basePath가 포함되지 않습니다. external rewrite에서만 사용할 수 있습니다.
  • locale: false 또는 undefined - matching할 때 locale을 포함하지 않을지 여부입니다.
  • has는 type, key, value property를 가진 has 객체의 배열입니다.
  • missing은 type, key, value property를 가진 missing 객체의 배열입니다.
  • source: String - is the incoming request path pattern.
  • destination: String is the path you want to route to.
  • basePath: false or undefined - if false the basePath won't be included when matching, can be used for external rewrites only.
  • locale: false or undefined - whether the locale should not be included when matching.
  • has is an array of has objects with the type, key and value properties.
  • missing is an array of missing objects with the type, key and value properties.

rewrites 함수가 배열을 반환하면, rewrite는 filesystem(page와 /public 파일)을 확인한 뒤, 그리고 dynamic route보다 먼저 적용됩니다. Next.js v10.1부터는 rewrites 함수가 특정 형태의 배열 객체를 반환하도록 해서 이 동작을 바꾸고 더 세밀하게 제어할 수 있습니다:

When the rewrites function returns an array, rewrites are applied after checking the filesystem (pages and /public files) and before dynamic routes. When the rewrites function returns an object of arrays with a specific shape, this behavior can be changed and more finely controlled, as of v10.1 of Next.js:

JSnext.config.js
module.exports = {
  rewrites() {
    return {
      beforeFiles: [
        // These rewrites are checked after headers/redirects
        // and before all files including _next/static and public files which
        // allows overriding page files
        {
          source: '/some-page',
          destination: '/somewhere-else',
          has: [{ type: 'query', key: 'overrideMe' }],
        },
      ],
      afterFiles: [
        // These rewrites are checked after pages/public files
        // are checked but before dynamic routes
        {
          source: '/non-existent',
          destination: '/somewhere-else',
        },
      ],
      fallback: [
        // These rewrites are checked after both pages/public files
        // and dynamic routes are checked
        {
          source: '/:path*',
          destination: `https://my-old-site.com/:path*`,
        },
      ],
    }
  },
}
Good to know

beforeFiles의 rewrite는 source와 match된 직후 바로 filesystem/dynamic route를 확인하지 않고, 모든 beforeFiles를 확인할 때까지 계속 진행합니다.

rewrites in beforeFiles do not check the filesystem/dynamic routes immediately after matching a source, they continue until all beforeFiles have been checked.

Next.js가 route를 확인하는 순서는 다음과 같습니다:

The order Next.js routes are checked is:

  1. headers를 확인/적용합니다
  2. redirects를 확인/적용합니다
  3. proxy
  4. beforeFiles rewrite: 각 항목마다 source, has, missing이 request와 match되면 destination으로 rewrite됩니다.
  5. public directory의 static 파일, _next/static 파일, dynamic이 아닌 page를 확인/제공합니다
  6. afterFiles rewrite를 순서대로 시도합니다. source, has, missing이 request와 match되면 destination으로 rewrite되며, static 파일, page, dynamic route로 resolve되는 첫 번째 rewrite가 제공됩니다.
  7. dynamic route(예: app/blog/[slug]/page.tsx)를 현재 경로와 match합니다
  8. fallback rewrite를 확인/적용합니다. 이 rewrite는 404 page를 rendering하기 전, 그리고 dynamic route와 모든 static asset을 확인한 뒤에 적용됩니다. getStaticPaths에서 fallback: true/'blocking'을 사용하면, 해당 dynamic route가 next.config.js에 정의한 fallback rewrites보다 우선합니다.
  1. headers are checked/applied
  2. redirects are checked/applied
  3. proxy
  4. beforeFiles rewrites: for each entry, if source, has, and missing matches the request, it's rewritten to destination.
  5. static files from the public directory, _next/static files, and non-dynamic pages are checked/served
  6. afterFiles rewrites are tried in order. If a source, has, and missing matches the request, it's rewritten to destination; the first rewrite that resolves to a static file, page, or dynamic route is served.
  7. dynamic routes (e.g., app/blog/[slug]/page.tsx) are matched against the current path
  8. fallback rewrites are checked/applied, these are applied before rendering the 404 page and after dynamic routes/all static assets have been checked. If you use fallback: true/'blocking' in getStaticPaths, those dynamic routes take priority over the fallback rewrites defined in your next.config.js.

Rewrite parametersRewrite parameter

rewrite에서 parameter를 사용할 때, destination에서 parameter를 하나도 사용하지 않으면 기본적으로 parameter가 query로 전달됩니다.

When using parameters in a rewrite the parameters will be passed in the query by default when none of the parameters are used in the destination.

JSnext.config.js
module.exports = {
  rewrites() {
    return [
      {
        source: '/old-about/:path*',
        destination: '/about', // The :path parameter isn't used here so will be automatically passed in the query
      },
    ]
  },
}

destination에서 parameter를 하나라도 사용하면 어떤 parameter도 query로 자동 전달되지 않습니다.

If a parameter is used in the destination none of the parameters will be automatically passed in the query.

JSnext.config.js
module.exports = {
  rewrites() {
    return [
      {
        source: '/docs/:path*',
        destination: '/:path*', // The :path parameter is used here so will not be automatically passed in the query
      },
    ]
  },
}

destination에서 이미 parameter를 사용하고 있더라도, destination에 query를 지정하면 parameter를 query로 직접 전달할 수 있습니다.

You can still pass the parameters manually in the query if one is already used in the destination by specifying the query in the destination.

JSnext.config.js
module.exports = {
  rewrites() {
    return [
      {
        source: '/:first/:second',
        destination: '/:first?second=:second',
        // Since the :first parameter is used in the destination the :second parameter
        // will not automatically be added in the query although we can manually add it
        // as shown above
      },
    ]
  },
}
Good to know

Automatic Static Optimization이나 prerendering으로 만들어진 static page의 경우, rewrite에서 온 param은 hydration 이후 client에서 parse되어 query로 제공됩니다.

Static pages from Automatic Static Optimization or prerendering params from rewrites will be parsed on the client after hydration and provided in the query.

Path Matching

path match를 사용할 수 있습니다. 예를 들어 /blog/:slug는 /blog/first-post와 match됩니다(nested path는 제외):

Path matches are allowed, for example /blog/:slug will match /blog/first-post (no nested paths):

JSnext.config.js
module.exports = {
  rewrites() {
    return [
      {
        source: '/blog/:slug',
        destination: '/news/:slug', // Matched parameters can be used in the destination
      },
    ]
  },
}

/blog/:slug pattern은 /blog/first-post, /blog/post-1과는 match되지만 /blog/a/b와는 match되지 않습니다(nested path 제외). pattern은 시작 부분에 고정(anchored)되므로 /blog/:slug는 /archive/blog/first-post와 match되지 않습니다.

The pattern /blog/:slug matches /blog/first-post and /blog/post-1 but not /blog/a/b (no nested paths). Patterns are anchored to the start: /blog/:slug will not match /archive/blog/first-post.

parameter에 modifier를 사용할 수 있습니다: *(0개 이상), +(1개 이상), ?(0개 또는 1개). 예를 들어 /blog/:slug*는 /blog, /blog/a, /blog/a/b/c와 match됩니다.

You can use modifiers on parameters: * (zero or more), + (one or more), ? (zero or one). For example, /blog/:slug* matches /blog, /blog/a, and /blog/a/b/c.

자세한 내용은 path-to-regexp 문서를 참고하세요.

Read more details on path-to-regexp documentation.

Wildcard Path Matching

wildcard path를 match하려면 parameter 뒤에 *를 사용하면 됩니다. 예를 들어 /blog/:slug*는 /blog/a/b/c/d/hello-world와 match됩니다:

To match a wildcard path you can use * after a parameter, for example /blog/:slug* will match /blog/a/b/c/d/hello-world:

JSnext.config.js
module.exports = {
  rewrites() {
    return [
      {
        source: '/blog/:slug*',
        destination: '/news/:slug*', // Matched parameters can be used in the destination
      },
    ]
  },
}

Regex Path Matching

regex path를 match하려면 parameter 뒤에 regex를 괄호로 감싸면 됩니다. 예를 들어 /blog/:slug(\\d{1,})는 /blog/123과는 match되지만 /blog/abc와는 match되지 않습니다:

To match a regex path you can wrap the regex in parenthesis after a parameter, for example /blog/:slug(\\d{1,}) will match /blog/123 but not /blog/abc:

JSnext.config.js
module.exports = {
  rewrites() {
    return [
      {
        source: '/old-blog/:post(\\d{1,})',
        destination: '/blog/:post', // Matched parameters can be used in the destination
      },
    ]
  },
}

다음 문자 (, ), {, }, [, ], |, \, ^, ., :, *, +, -, ?, $는 regex path matching에 사용되므로, source에서 특수하지 않은 값으로 사용할 때는 앞에 \\를 붙여 escape해야 합니다:

The following characters (, ), {, }, [, ], |, \, ^, ., :, *, +, -, ?, $ are used for regex path matching, so when used in the source as non-special values they must be escaped by adding \\ before them:

JSnext.config.js
module.exports = {
  rewrites() {
    return [
      {
        // this will match `/english(default)/something` being requested
        source: '/english\\(default\\)/:slug',
        destination: '/en-us/:slug',
      },
    ]
  },
}

Header, Cookie, and Query MatchingHeader, cookie, query matching

header, cookie, query 값이 has field와 match되거나 missing field와 match되지 않을 때만 rewrite를 match하도록 할 수 있습니다. rewrite가 적용되려면 source와 모든 has 항목이 match되어야 하고, 모든 missing 항목은 match되지 않아야 합니다.

To only match a rewrite when header, cookie, or query values also match the has field or don't match the missing field can be used. Both the source and all has items must match and all missing items must not match for the rewrite to be applied.

has와 missing 항목에는 다음 field를 사용할 수 있습니다:

has and missing items can have the following fields:

  • type: String - header, cookie, host, query 중 하나여야 합니다.
  • key: String - 선택한 type에서 match할 key입니다.
  • value: String 또는 undefined - 확인할 값입니다. undefined이면 어떤 값이든 match됩니다. regex 형태의 문자열을 사용해 값의 특정 부분을 capture할 수 있습니다. 예를 들어 first-second에 대해 first-(?<paramName>.*) 값을 사용하면 destination에서 :paramName으로 second를 사용할 수 있습니다.
  • type: String - must be either header, cookie, host, or query.
  • key: String - the key from the selected type to match against.
  • value: String or undefined - the value to check for, if undefined any value will match. A regex like string can be used to capture a specific part of the value, e.g. if the value first-(?<paramName>.*) is used for first-second then second will be usable in the destination with :paramName.
JSnext.config.js
module.exports = {
  rewrites() {
    return [
      // if the header `x-rewrite-me` is present,
      // this rewrite will be applied
      {
        source: '/:path*',
        has: [
          {
            type: 'header',
            key: 'x-rewrite-me',
          },
        ],
        destination: '/another-page',
      },
      // if the header `x-rewrite-me` is not present,
      // this rewrite will be applied
      {
        source: '/:path*',
        missing: [
          {
            type: 'header',
            key: 'x-rewrite-me',
          },
        ],
        destination: '/another-page',
      },
      // if the source, query, and cookie are matched,
      // this rewrite will be applied
      {
        source: '/specific/:path*',
        has: [
          {
            type: 'query',
            key: 'page',
            // the page value will not be available in the
            // destination since value is provided and doesn't
            // use a named capture group e.g. (?<page>home)
            value: 'home',
          },
          {
            type: 'cookie',
            key: 'authorized',
            value: 'true',
          },
        ],
        destination: '/:path*/home',
      },
      // if the header `x-authorized` is present and
      // contains a matching value, this rewrite will be applied
      {
        source: '/:path*',
        has: [
          {
            type: 'header',
            key: 'x-authorized',
            value: '(?<authorized>yes|true)',
          },
        ],
        destination: '/home?authorized=:authorized',
      },
      // if the host is `example.com`,
      // this rewrite will be applied
      {
        source: '/:path*',
        has: [
          {
            type: 'host',
            value: 'example.com',
          },
        ],
        destination: '/another-page',
      },
    ]
  },
}

Rewriting to an external URL외부 URL로 rewrite하기

예시
  • Using Multiple Zones

Rewrite를 사용하면 외부 URL로 rewrite할 수 있습니다. 이는 Next.js를 점진적으로 도입할 때 특히 유용합니다. 다음은 main 앱의 /blog route를 외부 사이트로 redirect하는 rewrite 예시입니다.

Rewrites allow you to rewrite to an external URL. This is especially useful for incrementally adopting Next.js. The following is an example rewrite for redirecting the /blog route of your main app to an external site.

JSnext.config.js
module.exports = {
  rewrites() {
    return [
      {
        source: '/blog',
        destination: 'https://example.com/blog',
      },
      {
        source: '/blog/:slug',
        destination: 'https://example.com/blog/:slug', // Matched parameters can be used in the destination
      },
    ]
  },
}

trailingSlash: true를 사용하고 있다면 source parameter에도 trailing slash를 넣어야 합니다. destination server도 trailing slash를 기대한다면 destination parameter에도 포함해야 합니다.

If you're using trailingSlash: true, you also need to insert a trailing slash in the source parameter. If the destination server is also expecting a trailing slash it should be included in the destination parameter as well.

JSnext.config.js
module.exports = {
  trailingSlash: true,
  rewrites() {
    return [
      {
        source: '/blog/',
        destination: 'https://example.com/blog/',
      },
      {
        source: '/blog/:path*/',
        destination: 'https://example.com/blog/:path*/',
      },
    ]
  },
}

Incremental adoption of Next.jsNext.js 점진적 도입

모든 Next.js route를 확인한 뒤 기존 웹사이트로 proxy하도록 Next.js에 fallback을 둘 수도 있습니다.

You can also have Next.js fall back to proxying to an existing website after checking all Next.js routes.

이렇게 하면 더 많은 page를 Next.js로 migrate할 때 rewrite 설정을 바꾸지 않아도 됩니다

This way you don't have to change the rewrites configuration when migrating more pages to Next.js

JSnext.config.js
module.exports = {
  rewrites() {
    return {
      fallback: [
        {
          source: '/:path*',
          destination: `https://custom-routes-proxying-endpoint.vercel.app/:path*`,
        },
      ],
    }
  },
}

Rewrites with basePath supportbasePath를 지원하는 rewrite

rewrite와 함께 basePath 지원을 활용하면, rewrite에 basePath: false를 추가하지 않는 한 각 source와 destination 앞에 basePath가 자동으로 붙습니다:

When leveraging basePath support with rewrites each source and destination is automatically prefixed with the basePath unless you add basePath: false to the rewrite:

JSnext.config.js
module.exports = {
  basePath: '/docs',

  rewrites() {
    return [
      {
        source: '/with-basePath', // automatically becomes /docs/with-basePath
        destination: '/another', // automatically becomes /docs/another
      },
      {
        // does not add /docs to /without-basePath since basePath: false is set
        // Note: this cannot be used for internal rewrites e.g. `destination: '/another'`
        source: '/without-basePath',
        destination: 'https://example.com',
        basePath: false,
      },
    ]
  },
}
