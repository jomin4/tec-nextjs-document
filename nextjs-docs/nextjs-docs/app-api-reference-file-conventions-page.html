page.jspage.js

page 파일을 사용하면 route에 고유한 UI를 정의할 수 있습니다. 파일에서 component를 default export해 page를 만들 수 있습니다:

The page file allows you to define UI that is unique to a route. You can create a page by default exporting a component from the file:

TSJSapp/blog/[slug]/page.tsx
export default function Page({
  params,
  searchParams,
}: {
  params: Promise<{ slug: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  return <h1>My Page</h1>
}
export default function Page({ params, searchParams }) {
  return <h1>My Page</h1>
}

Good to know알아 두면 좋은 점

  • page에는 .js, .jsx, .tsx 파일 확장자를 사용할 수 있습니다.
  • page는 항상 route subtree의 leaf입니다.
  • route segment를 외부에서 접근 가능하게 만들려면 page 파일이 필요합니다.
  • Page는 기본적으로 Server Component이지만, Client Component로 설정할 수도 있습니다.
  • component hierarchy에서 page.js는 가장 안쪽의 file convention입니다. 같은 segment의 loading.js(Suspense boundary), error.js(error boundary), template.js, layout.js로 감싸집니다.
  • The .js, .jsx, or .tsx file extensions can be used for page.
  • A page is always the leaf of the route subtree.
  • A page file is required to make a route segment publicly accessible.
  • Pages are Server Components by default, but can be set to a Client Component.
  • In the component hierarchy, page.js is the innermost file convention. It is wrapped by loading.js (Suspense boundary), error.js (error boundary), template.js, and layout.js in the same segment.

Reference레퍼런스

Props

params (optional)

root segment부터 해당 page까지의 dynamic route parameter를 담은 object로 resolve되는 promise입니다.

A promise that resolves to an object containing the dynamic route parameters from the root segment down to that page.

TSJSapp/shop/[slug]/page.tsx
export default async function Page({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
}
export default async function Page({ params }) {
  const { slug } = await params
}
예시 RouteURLparams
app/shop/[slug]/page.js/shop/1Promise<{ slug: '1' }>
app/shop/[category]/[item]/page.js/shop/1/2Promise<{ category: '1', item: '2' }>
app/shop/[...slug]/page.js/shop/1/2Promise<{ slug: ['1', '2'] }>
Example RouteURLparams
app/shop/[slug]/page.js/shop/1Promise<{ slug: '1' }>

app/shop/[...slug]/page.js/shop/1/2Promise<{ slug: ['1', '2'] }>
  • params prop은 promise이므로, 값에 접근하려면 async/await 또는 React의 use 함수를 사용해야 합니다.
    • 버전 14 이하에서는 params가 synchronous prop이었습니다. 하위 호환성을 위해 Next.js 15에서도 여전히 synchronous하게 접근할 수 있지만, 이 동작은 앞으로 deprecated될 예정입니다.
  • Since the params prop is a promise, you must use async/await or React's use function to access the values.
    • In version 14 and earlier, params was a synchronous prop. To help with backwards compatibility, you can still access it synchronously in Next.js 15, but this behavior will be deprecated in the future.

searchParams (optional)

현재 URL의 search parameter를 담은 object로 resolve되는 promise입니다. 예를 들면 다음과 같습니다:

A promise that resolves to an object containing the search parameters of the current URL. For example:

TSJSapp/shop/page.tsx
export default async function Page({
  searchParams,
}: {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const filters = (await searchParams).filters
}
export default async function Page({ searchParams }) {
  const filters = (await searchParams).filters
}

Client Component인 page에서도 React의 use hook으로 searchParams에 접근할 수 있습니다:

Client Component pages can also access searchParams using React’s use hook:

TSJSapp/shop/page.tsx
'use client'
import { use } from 'react'

export default function Page({
  searchParams,
}: {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const filters = use(searchParams).filters
}
'use client'
import { use } from 'react'

export default function Page({ searchParams }) {
  const filters = use(searchParams).filters
}
예시 URLsearchParams
/shop?a=1Promise<{ a: '1' }>
/shop?a=1&b=2Promise<{ a: '1', b: '2' }>
/shop?a=1&a=2Promise<{ a: ['1', '2'] }>
Example URLsearchParams

/shop?a=1&b=2Promise<{ a: '1', b: '2' }>

  • searchParams prop은 promise입니다. 값에 접근하려면 async/await 또는 React의 use 함수를 사용해야 합니다.
    • 버전 14 이하에서는 searchParams가 synchronous prop이었습니다. 하위 호환성을 위해 Next.js 15에서도 여전히 synchronous하게 접근할 수 있지만, 이 동작은 앞으로 deprecated될 예정입니다.
  • searchParams는 값을 미리 알 수 없는 Request-time API 중 하나입니다. 이를 사용하면 page가 request 시점에 dynamic rendering 방식으로 전환됩니다.
  • Cache Components를 사용할 때는 component tree의 어디에서 searchParams에 접근하느냐에 따라 page의 얼마만큼이 prerender될 수 있는지가 결정됩니다. Maximizing the static shell을 참고하세요.
  • searchParams는 URLSearchParams instance가 아니라 일반 JavaScript 객체입니다.
  • Since the searchParams prop is a promise. You must use async/await or React's use function to access the values.
    • In version 14 and earlier, searchParams was a synchronous prop. To help with backwards compatibility, you can still access it synchronously in Next.js 15, but this behavior will be deprecated in the future.
  • searchParams is a Request-time API whose values cannot be known ahead of time. Using it will opt the page into dynamic rendering at request time.
  • With Cache Components, where you access searchParams in the component tree determines how much of the page can be prerendered. See Maximizing the static shell.
  • searchParams is a plain JavaScript object, not a URLSearchParams instance.

Page Props Helper

PageProps로 page의 type을 지정하면 route literal로부터 strongly typed params와 searchParams를 얻을 수 있습니다. PageProps는 전역으로 사용할 수 있는 helper입니다.

You can type pages with PageProps to get strongly typed params and searchParams from the route literal. PageProps is a globally available helper.

TSapp/blog/[slug]/page.tsx
export default async function Page(props: PageProps<'/blog/[slug]'>) {
  const { slug } = await props.params
  const query = await props.searchParams
  return <h1>Blog Post: {slug}</h1>
}
Good to know
  • literal route(예: '/blog/[slug]')를 사용하면 params에 대한 autocomplete와 엄격한 key 검사가 가능해집니다.
  • static route에서는 params가 {}로 resolve됩니다.
  • type은 next dev, next build 중에, 또는 next typegen으로 생성됩니다.
  • type 생성 후에는 PageProps helper를 전역으로 사용할 수 있습니다. import할 필요가 없습니다.
  • Using a literal route (e.g. '/blog/[slug]') enables autocomplete and strict keys for params.
  • Static routes resolve params to {}.
  • Types are generated during next dev, next build, or with next typegen.
  • After type generation, the PageProps helper is globally available. It doesn't need to be imported.

Displaying content based on paramsparams에 따라 content 표시하기

dynamic route segment를 사용하면 params prop에 따라 page에 특정 content를 표시하거나 fetch할 수 있습니다.

Using dynamic route segments, you can display or fetch specific content for the page based on the params prop.

TSJSapp/blog/[slug]/page.tsx
export default async function Page({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  return <h1>Blog Post: {slug}</h1>
}
export default async function Page({ params }) {
  const { slug } = await params
  return <h1>Blog Post: {slug}</h1>
}

Handling filtering with searchParamssearchParams로 filtering 처리하기

searchParams prop을 사용해 URL의 query string에 따라 filtering, pagination, sorting을 처리할 수 있습니다.

You can use the searchParams prop to handle filtering, pagination, or sorting based on the query string of the URL.

TSJSapp/shop/page.tsx
export default async function Page({
  searchParams,
}: {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const { page = '1', sort = 'asc', query = '' } = await searchParams

  return (
    <div>
      <h1>Product Listing</h1>
      <p>Search query: {query}</p>
      <p>Current page: {page}</p>
      <p>Sort order: {sort}</p>
    </div>
  )
}
export default async function Page({ searchParams }) {
  const { page = '1', sort = 'asc', query = '' } = await searchParams

  return (
    <div>
      <h1>Product Listing</h1>
      <p>Search query: {query}</p>
      <p>Current page: {page}</p>
      <p>Sort order: {sort}</p>
    </div>
  )
}

Reading searchParams and params in Client ComponentsClient Component에서 searchParams와 params 읽기

(async일 수 없는) Client Component에서 searchParams와 params를 사용하려면 React의 use 함수로 promise를 읽을 수 있습니다:

To use searchParams and params in a Client Component (which cannot be async), you can use React's use function to read the promise:

TSJSapp/page.tsx
'use client'

import { use } from 'react'

export default function Page({
  params,
  searchParams,
}: {
  params: Promise<{ slug: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const { slug } = use(params)
  const { query } = use(searchParams)
}
'use client'

import { use } from 'react'

export default function Page({ params, searchParams }) {
  const { slug } = use(params)
  const { query } = use(searchParams)
}
