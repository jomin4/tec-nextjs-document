How to use a custom webpack version in Next.jsNext.js에서 custom webpack 버전 사용하기

기본적으로 --webpack은 Next.js에 bundle된 webpack 버전을 사용합니다. 대신 애플리케이션에 설치한 webpack을 사용하려면 애플리케이션에 webpack을 설치하고 next dev나 next build에 --custom-webpack을 전달하세요. development command와 production command는 따로 실행하세요. next dev는 중지할 때까지 계속 실행됩니다:

By default, --webpack uses the webpack version bundled with Next.js. To use webpack installed in your application instead, install webpack in your application and pass --custom-webpack to next dev or next build. Run the development and production commands separately; next dev keeps running until stopped:

pnpm add -D webpack@^5.98.0
pnpm next dev --custom-webpack
pnpm next build --custom-webpack
npm install -D webpack@^5.98.0
npx next dev --custom-webpack
npx next build --custom-webpack
yarn add -D webpack@^5.98.0
yarn next dev --custom-webpack
yarn next build --custom-webpack
bun add -D webpack@^5.98.0
bunx next dev --custom-webpack
bunx next build --custom-webpack

custom webpack 버전은 직접 책임지고 사용하세요. Next.js는 설치된 webpack 버전을 검증하지 않으며, 다른 버전과의 호환성도 보장되지 않습니다. 예시에서는 ^5.98.0을 사용합니다. 이 기능은 webpack 5.98.0과 5.111.0에서 테스트되었습니다.

Use a custom webpack version at your own risk. Next.js does not validate the installed webpack version, and compatibility with other versions is not guaranteed. The examples use ^5.98.0; this feature is tested with webpack 5.98.0 and 5.111.0.

install command는 애플리케이션 directory에서 실행하세요. custom 버전은 Next.js가 next.config.js를 평가할 때 사용할 수 있으므로, webpack configuration과 plugin에서 이를 import할 수 있습니다. 애플리케이션에 webpack이 설치되어 있지 않으면 --custom-webpack이 설치 방법을 알려 줍니다.

Run the install command from your application's directory. The custom version is available when Next.js evaluates next.config.js, so your webpack configuration and plugins can import it. If webpack is not installed in the application, --custom-webpack reports how to install it.

hoisting이 제한된 pnpm을 사용하는 경우: Next.js는 pnpm이 webpack을 hoist하지 않더라도 애플리케이션에서 직접 webpack을 resolve합니다. 하지만 custom webpack plugin이나 다른 workspace tooling은 자신의 package 위치에서 webpack을 resolve할 수 있습니다. pnpm의 hoisting을 제한해서 이들이 webpack을 찾지 못한다면, workspace root의 pnpm-workspace.yaml에 있는 기존 hoistPattern에 webpack을 추가하세요:

Using pnpm with restricted hoisting: Next.js resolves webpack directly from your application, even when pnpm does not hoist it. However, custom webpack plugins or other workspace tooling may resolve webpack from their own package locations. If they cannot find it because you have restricted pnpm's hoisting, add webpack to your existing hoistPattern in the workspace root's pnpm-workspace.yaml:

pnpm-workspace.yaml
hoistPattern:
  - '*eslint*' # Example existing pattern; keep your own patterns.
  - webpack

프로젝트에서 이미 사용 중인 다른 패턴은 그대로 유지하세요. pnpm의 기본 hoistPattern(['*'])을 사용한다면 이 설정은 필요 없습니다. hoist: false로 hoisting을 완전히 비활성화했다면 hoistPattern을 사용하기 전에 hoisting을 활성화하세요. 자세한 내용은 pnpm의 node-modules 설정을 참고하세요.

Keep any other patterns your project already uses. If you use pnpm's default hoistPattern (['*']), you do not need this setting. If you have disabled hoisting entirely with hoist: false, enable it before using hoistPattern. See pnpm's node-modules settings for details.
