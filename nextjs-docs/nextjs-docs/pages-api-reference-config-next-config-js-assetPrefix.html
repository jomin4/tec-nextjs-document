assetPrefixassetPrefix

Attention: Vercel에 deploy하면 Next.js 프로젝트에 global CDN이 자동으로 설정됩니다. Asset Prefix를 직접 설정할 필요가 없습니다.

Attention: Deploying to Vercel automatically configures a global CDN for your Next.js project. You do not need to manually set up an Asset Prefix.

Good to know

Next.js 9.5+에서는 customizable Base Path 지원이 추가되었으며, 이는 /docs 같은 sub-path에서 애플리케이션을 hosting하는 데 더 적합합니다. 이런 용도로 custom Asset Prefix를 사용하는 것은 권장하지 않습니다.

Next.js 9.5+ added support for a customizable Base Path, which is better suited for hosting your application on a sub-path like /docs. We do not suggest you use a custom Asset Prefix for this use case.

Set up a CDNCDN 설정하기

CDN을 설정하려면 asset prefix를 설정하고, CDN의 origin이 Next.js가 hosting되는 domain으로 resolve되도록 구성하면 됩니다.

To set up a CDN, you can set up an asset prefix and configure your CDN's origin to resolve to the domain that Next.js is hosted on.

next.config.mjs를 열고 phase에 따라 assetPrefix config를 추가하세요:

Open next.config.mjs and add the assetPrefix config based on the phase:

JSnext.config.mjs
// @ts-check
import { PHASE_DEVELOPMENT_SERVER } from 'next/constants'

export default (phase) => {
  const isDev = phase === PHASE_DEVELOPMENT_SERVER
  /**
   * @type {import('next').NextConfig}
   */
  const nextConfig = {
    assetPrefix: isDev ? undefined : 'https://cdn.mydomain.com',
  }
  return nextConfig
}

Next.js는 /_next/ 경로(.next/static/ 폴더)에서 불러오는 JavaScript와 CSS 파일에 asset prefix를 자동으로 사용합니다. 예를 들어 위 설정을 사용하면 JS chunk에 대한 다음 request는:

Next.js will automatically use your asset prefix for the JavaScript and CSS files it loads from the /_next/ path (.next/static/ folder). For example, with the above configuration, the following request for a JS chunk:

/_next/static/chunks/4b9b41aaa062cbbfeff4add70f256968c51ece5d.4d708494b3aed70c04f0.js

다음과 같이 바뀝니다:

Would instead become:

https://cdn.mydomain.com/_next/static/chunks/4b9b41aaa062cbbfeff4add70f256968c51ece5d.4d708494b3aed70c04f0.js

특정 CDN에 파일을 업로드하는 정확한 설정은 선택한 CDN에 따라 다릅니다. CDN에 hosting해야 하는 폴더는 .next/static/의 내용뿐이며, 위 URL request에서 보듯 _next/static/으로 업로드해야 합니다. server code와 기타 설정을 외부에 노출하면 안 되므로 .next/ 폴더의 나머지 부분은 업로드하지 마세요.

The exact configuration for uploading your files to a given CDN will depend on your CDN of choice. The only folder you need to host on your CDN is the contents of .next/static/, which should be uploaded as _next/static/ as the above URL request indicates. Do not upload the rest of your .next/ folder, as you should not expose your server code and other configuration to the public.

assetPrefix는 _next/static에 대한 request를 처리하지만, 다음 경로에는 영향을 주지 않습니다:

While assetPrefix covers requests to _next/static, it does not influence the following paths:

  • public 폴더의 파일. 이 asset을 CDN으로 제공하려면 prefix를 직접 추가해야 합니다
  • getServerSideProps page에 대한 /_next/data/ request. 이 request는 static이 아니므로 항상 main domain으로 보내집니다.
  • getStaticProps page에 대한 /_next/data/ request. 이 request는 (일관성을 위해) Incremental Static Generation을 사용하지 않더라도 이를 지원하기 위해 항상 main domain으로 보내집니다.
  • Files in the public folder; if you want to serve those assets over a CDN, you'll have to introduce the prefix yourself
  • /_next/data/ requests for getServerSideProps pages. These requests will always be made against the main domain since they're not static.
  • /_next/data/ requests for getStaticProps pages. These requests will always be made against the main domain to support Incremental Static Generation, even if you're not using it (for consistency).
