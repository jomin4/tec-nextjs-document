Note

This feature is superseded by Draft Mode.

Pages 문서와 Data Fetching 문서에서는 getStaticProps와 getStaticPaths를 사용해 build time에 page를 prerender하는 방법(Static Generation)을 다뤘습니다.

In the Pages documentation and the Data Fetching documentation, we talked about how to prerender a page at build time (Static Generation) using getStaticProps and getStaticPaths.

Static Generation은 page가 headless CMS에서 data를 fetch할 때 유용합니다. 하지만 headless CMS에서 draft(초안)를 작성하고 있고 그 draft를 page에서 바로 preview하고 싶을 때는 적합하지 않습니다. 이럴 때는 Next.js가 이 page들을 build time이 아니라 request time에 render하고, 게시된 콘텐츠 대신 draft 콘텐츠를 fetch하기를 원할 것입니다. 즉, 이 특정한 경우에만 Next.js가 Static Generation을 우회하기를 원할 것입니다.

Static Generation is useful when your pages fetch data from a headless CMS. However, it’s not ideal when you’re writing a draft on your headless CMS and want to preview the draft immediately on your page. You’d want Next.js to render these pages at request time instead of build time and fetch the draft content instead of the published content. You’d want Next.js to bypass Static Generation only for this specific case.

Next.js에는 이 문제를 해결하는 Preview Mode라는 기능이 있습니다. 사용 방법은 다음과 같습니다.

Next.js has a feature called Preview Mode which solves this problem. Here are instructions on how to use it.

Step 1: Create and access a preview API route1단계: preview API route 만들고 접근하기

Next.js API Routes에 익숙하지 않다면 먼저 API Routes 문서를 살펴보세요.

Take a look at the API Routes documentation first if you’re not familiar with Next.js API Routes.

먼저 preview API route를 만드세요. 이름은 무엇이든 상관없습니다. 예: pages/api/preview.js (TypeScript를 사용한다면 .ts)

First, create a preview API route. It can have any name - e.g. pages/api/preview.js (or .ts if using TypeScript).

이 API route에서 response object의 setPreviewData를 호출해야 합니다. setPreviewData의 argument는 object여야 하며, 이 값은 getStaticProps에서 사용할 수 있습니다(자세한 내용은 뒤에서 다룹니다). 지금은 {}를 사용하겠습니다.

In this API route, you need to call setPreviewData on the response object. The argument for setPreviewData should be an object, and this can be used by getStaticProps (more on this later). For now, we’ll use {}.

export default function handler(req, res) {
  // ...
  res.setPreviewData({})
  // ...
}

res.setPreviewData는 브라우저에 preview mode를 켜는 몇 가지 cookie를 설정합니다. 이 cookie를 포함한 Next.js로의 모든 request는 preview mode로 간주되며, statically generated page의 동작이 바뀝니다(자세한 내용은 뒤에서 다룹니다).

res.setPreviewData sets some cookies on the browser which turns on the preview mode. Any requests to Next.js containing these cookies will be considered as the preview mode, and the behavior for statically generated pages will change (more on this later).

아래와 같은 API route를 만들고 브라우저에서 직접 접근해 수동으로 테스트해 볼 수 있습니다:

You can test this manually by creating an API route like below and accessing it from your browser manually:

JSpages/api/preview.js
// simple example for testing it manually from your browser.
export default function handler(req, res) {
  res.setPreviewData({})
  res.end('Preview mode enabled')
}

브라우저의 developer tools를 열고 /api/preview에 방문하면 이 request에서 __prerender_bypass와 __next_preview_data cookie가 설정되는 것을 확인할 수 있습니다.

If you open your browser’s developer tools and visit /api/preview, you’ll notice that the __prerender_bypass and __next_preview_data cookies will be set on this request.

Securely accessing it from your Headless CMSHeadless CMS에서 안전하게 접근하기

실제로는 headless CMS에서 이 API route를 안전하게 호출하고 싶을 것입니다. 구체적인 단계는 사용하는 headless CMS에 따라 다르지만, 일반적으로 다음과 같은 단계를 밟을 수 있습니다.

In practice, you’d want to call this API route securely from your headless CMS. The specific steps will vary depending on which headless CMS you’re using, but here are some common steps you could take.

이 단계들은 사용 중인 headless CMS가 custom preview URL 설정을 지원한다고 가정합니다. 지원하지 않더라도 이 방법으로 preview URL을 보호할 수는 있지만, preview URL을 직접 만들고 접근해야 합니다.

These steps assume that the headless CMS you’re using supports setting custom preview URLs. If it doesn’t, you can still use this method to secure your preview URLs, but you’ll need to construct and access the preview URL manually.

먼저, 원하는 token generator로 secret token string을 만드세요. 이 secret은 Next.js 앱과 headless CMS만 알고 있어야 합니다. 이 secret은 CMS 접근 권한이 없는 사람이 preview URL에 접근하지 못하게 막아 줍니다.

First, you should create a secret token string using a token generator of your choice. This secret will only be known by your Next.js app and your headless CMS. This secret prevents people who don’t have access to your CMS from accessing preview URLs.

둘째, headless CMS가 custom preview URL 설정을 지원한다면 다음을 preview URL로 지정하세요. 여기서는 preview API route가 pages/api/preview.js에 있다고 가정합니다.

Second, if your headless CMS supports setting custom preview URLs, specify the following as the preview URL. This assumes that your preview API route is located at pages/api/preview.js.

>_Terminal
https://<your-site>/api/preview?secret=<token>&slug=<path>
  • <your-site>는 deployment domain이어야 합니다.
  • <token>은 생성한 secret token으로 바꿔야 합니다.
  • <path>는 preview하려는 page의 path여야 합니다. /posts/foo를 preview하고 싶다면 &slug=/posts/foo를 사용하세요.
  • <your-site> should be your deployment domain.
  • <token> should be replaced with the secret token you generated.
  • <path> should be the path for the page that you want to preview. If you want to preview /posts/foo, then you should use &slug=/posts/foo.

headless CMS에 따라 preview URL에 변수를 넣어서 <path>가 CMS의 data에 따라 동적으로 설정되게 할 수도 있습니다. 예: &slug=/posts/{entry.fields.slug}

Your headless CMS might allow you to include a variable in the preview URL so that <path> can be set dynamically based on the CMS’s data like so: &slug=/posts/{entry.fields.slug}

마지막으로, preview API route에서 다음을 수행합니다:

Finally, in the preview API route:

  • secret이 일치하는지, 그리고 slug parameter가 존재하는지 확인합니다(그렇지 않으면 request가 실패해야 합니다). -
  • res.setPreviewData를 호출합니다.
  • 그다음 slug로 지정된 path로 브라우저를 redirect합니다. (다음 예제는 307 redirect를 사용합니다.)
  • Check that the secret matches and that the slug parameter exists (if not, the request should fail). -
  • Call res.setPreviewData.
  • Then redirect the browser to the path specified by slug. (The following example uses a 307 redirect).
export default async (req, res) => {
  // Check the secret and next parameters
  // This secret should only be known to this API route and the CMS
  if (req.query.secret !== 'MY_SECRET_TOKEN' || !req.query.slug) {
    return res.status(401).json({ message: 'Invalid token' })
  }

  // Fetch the headless CMS to check if the provided `slug` exists
  // getPostBySlug would implement the required fetching logic to the headless CMS
  const post = await getPostBySlug(req.query.slug)

  // If the slug doesn't exist prevent preview mode from being enabled
  if (!post) {
    return res.status(401).json({ message: 'Invalid slug' })
  }

  // Enable Preview Mode by setting the cookies
  res.setPreviewData({})

  // Redirect to the path from the fetched post
  // We don't redirect to req.query.slug as that might lead to open redirect vulnerabilities
  res.redirect(post.slug)
}

성공하면 브라우저는 preview mode cookie가 설정된 채로 preview하려는 path로 redirect됩니다.

If it succeeds, then the browser will be redirected to the path you want to preview with the preview mode cookies being set.

Step 2: Update getStaticProps2단계: getStaticProps 업데이트하기

다음 단계는 preview mode를 지원하도록 getStaticProps를 업데이트하는 것입니다.

The next step is to update getStaticProps to support the preview mode.

(res.setPreviewData로) preview mode cookie가 설정된 상태에서 getStaticProps가 있는 page를 request하면, getStaticProps는 (build time 대신) request time에 호출됩니다.

If you request a page which has getStaticProps with the preview mode cookies set (via res.setPreviewData), then getStaticProps will be called at request time (instead of at build time).

또한 다음과 같은 context object와 함께 호출됩니다:

Furthermore, it will be called with a context object where:

  • context.preview는 true가 됩니다.
  • context.previewData는 setPreviewData에 사용한 argument와 같습니다.
  • context.preview will be true.
  • context.previewData will be the same as the argument used for setPreviewData.
export async function getStaticProps(context) {
  // If you request this page with the preview mode cookies set:
  //
  // - context.preview will be true
  // - context.previewData will be the same as
  //   the argument used for `setPreviewData`.
}

preview API route에서 res.setPreviewData({})를 사용했으므로 context.previewData는 {}가 됩니다. 필요하다면 이를 이용해 preview API route에서 getStaticProps로 session 정보를 전달할 수 있습니다.

We used res.setPreviewData({}) in the preview API route, so context.previewData will be {}. You can use this to pass session information from the preview API route to getStaticProps if necessary.

getStaticPaths도 사용하고 있다면 context.params도 사용할 수 있습니다.

If you’re also using getStaticPaths, then context.params will also be available.

Fetch preview datapreview data fetch하기

context.preview 및/또는 context.previewData에 따라 다른 data를 fetch하도록 getStaticProps를 업데이트할 수 있습니다.

You can update getStaticProps to fetch different data based on context.preview and/or context.previewData.

예를 들어 headless CMS에 draft post용 API endpoint가 따로 있을 수 있습니다. 그렇다면 아래처럼 context.preview를 사용해 API endpoint URL을 바꿀 수 있습니다:

For example, your headless CMS might have a different API endpoint for draft posts. If so, you can use context.preview to modify the API endpoint URL like below:

export async function getStaticProps(context) {
  // If context.preview is true, append "/preview" to the API endpoint
  // to request draft data instead of published data. This will vary
  // based on which headless CMS you're using.
  const res = await fetch(`https://.../${context.preview ? 'preview' : ''}`)
  // ...
}

이것으로 끝입니다! headless CMS에서 또는 직접 (secret과 slug를 포함해) preview API route에 접근하면 이제 preview 콘텐츠를 볼 수 있습니다. 그리고 게시하지 않고 draft를 업데이트해도 그 draft를 preview할 수 있습니다.

That’s it! If you access the preview API route (with secret and slug) from your headless CMS or manually, you should now be able to see the preview content. And if you update your draft without publishing, you should be able to preview the draft.

이것을 headless CMS의 preview URL로 설정하거나 직접 접근하면 preview를 볼 수 있습니다.

Set this as the preview URL on your headless CMS or access manually, and you should be able to see the preview.

>_Terminal
https://<your-site>/api/preview?secret=<token>&slug=<path>

More Details자세히 알아보기

Good to know

rendering 중에 next/router는 isPreview flag를 노출합니다. 자세한 내용은 router object 문서를 참고하세요.

during rendering next/router exposes an isPreview flag, see the router object docs for more info.

Specify the Preview Mode durationPreview Mode 지속 시간 지정하기

setPreviewData는 선택적인 두 번째 parameter로 options object를 받습니다. 다음 key를 사용할 수 있습니다:

setPreviewData takes an optional second parameter which should be an options object. It accepts the following keys:

  • maxAge: preview session이 지속될 시간(초 단위)을 지정합니다.
  • path: cookie가 적용될 path를 지정합니다. 기본값은 /로, 모든 path에서 preview mode를 활성화합니다.
  • maxAge: Specifies the number (in seconds) for the preview session to last for.
  • path: Specifies the path the cookie should be applied under. Defaults to / enabling preview mode for all paths.
setPreviewData(data, {
  maxAge: 60 * 60, // The preview mode cookies expire in 1 hour
  path: '/about', // The preview mode cookies apply to paths with /about
})

Clear the Preview Mode cookiesPreview Mode cookie 지우기

기본적으로 Preview Mode cookie에는 만료 날짜가 설정되지 않으므로, 브라우저를 닫으면 preview session이 끝납니다.

By default, no expiration date is set for Preview Mode cookies, so the preview session ends when the browser is closed.

Preview Mode cookie를 직접 지우려면 clearPreviewData()를 호출하는 API route를 만드세요:

To clear the Preview Mode cookies manually, create an API route that calls clearPreviewData():

JSpages/api/clear-preview-mode-cookies.js
export default function handler(req, res) {
  res.clearPreviewData({})
}

그다음 /api/clear-preview-mode-cookies로 request를 보내 API Route를 호출합니다. next/link로 이 route를 호출한다면, link prefetching 중에 clearPreviewData가 호출되지 않도록 prefetch={false}를 전달해야 합니다.

Then, send a request to /api/clear-preview-mode-cookies to invoke the API Route. If calling this route using next/link, you must pass prefetch={false} to prevent calling clearPreviewData during link prefetching.

setPreviewData 호출 시 path를 지정했다면 clearPreviewData에도 같은 path를 전달해야 합니다:

If a path was specified in the setPreviewData call, you must pass the same path to clearPreviewData:

JSpages/api/clear-preview-mode-cookies.js
export default function handler(req, res) {
  const { path } = req.query

  res.clearPreviewData({ path })
}

previewData size limitspreviewData 크기 제한

setPreviewData에 object를 전달해 getStaticProps에서 사용할 수 있게 할 수 있습니다. 하지만 data가 cookie에 저장되기 때문에 크기 제한이 있습니다. 현재 preview data는 2KB로 제한됩니다.

You can pass an object to setPreviewData and have it be available in getStaticProps. However, because the data will be stored in a cookie, there’s a size limitation. Currently, preview data is limited to 2KB.

Works with getServerSidePropsgetServerSideProps와 함께 사용하기

preview mode는 getServerSideProps에서도 동작합니다. 이 경우에도 preview와 previewData가 담긴 context object에서 사용할 수 있습니다.

The preview mode works on getServerSideProps as well. It will also be available on the context object containing preview and previewData.

Good to know

Preview Mode를 사용할 때는 Cache-Control header를 설정하면 안 됩니다. 이 header는 우회할 수 없기 때문입니다. 대신 ISR을 사용하는 것을 권장합니다.

You shouldn't set the Cache-Control header when using Preview Mode because it cannot be bypassed. Instead, we recommend using ISR.

Works with API RoutesAPI Routes와 함께 사용하기

API Routes에서는 request object의 preview와 previewData에 접근할 수 있습니다. 예를 들면 다음과 같습니다:

API Routes will have access to preview and previewData under the request object. For example:

export default function myApiRoute(req, res) {
  const isPreview = req.preview
  const previewData = req.previewData
  // ...
}

Unique per next buildnext build마다 고유한 값

next build가 완료되면 bypass cookie 값과 previewData 암호화에 쓰이는 private key가 모두 바뀝니다. 이렇게 해서 bypass cookie를 추측할 수 없도록 보장합니다.

Both the bypass cookie value and the private key for encrypting the previewData change when next build is completed. This ensures that the bypass cookie can’t be guessed.

Good to know

HTTP로 로컬에서 Preview Mode를 테스트하려면 브라우저가 third-party cookie와 local storage 접근을 허용해야 합니다.

To test Preview Mode locally over HTTP your browser will need to allow third-party cookies and local storage access.
