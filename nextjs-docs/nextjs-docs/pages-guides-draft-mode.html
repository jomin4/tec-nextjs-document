How to preview content with Draft Mode in Next.jsNext.js에서 Draft Mode로 콘텐츠 미리보기

Pages 문서와 Data Fetching 문서에서는 getStaticProps와 getStaticPaths를 사용해 build time에 page를 prerender하는 방법(Static Generation)을 다뤘습니다.

In the Pages documentation and the Data Fetching documentation, we talked about how to prerender a page at build time (Static Generation) using getStaticProps and getStaticPaths.

Static Generation은 page가 headless CMS에서 data를 fetch할 때 유용합니다. 하지만 headless CMS에서 draft(초안)를 작성하고 있고 그 draft를 page에서 바로 확인하고 싶을 때는 적합하지 않습니다. 이럴 때는 Next.js가 이 page들을 build time이 아니라 request time에 render하고, 게시된 콘텐츠 대신 draft 콘텐츠를 fetch하기를 원할 것입니다. 즉, 이 특정한 경우에만 Next.js가 Static Generation을 우회하기를 원할 것입니다.

Static Generation is useful when your pages fetch data from a headless CMS. However, it’s not ideal when you’re writing a draft on your headless CMS and want to view the draft immediately on your page. You’d want Next.js to render these pages at request time instead of build time and fetch the draft content instead of the published content. You’d want Next.js to bypass Static Generation only for this specific case.

Next.js에는 이 문제를 해결하는 Draft Mode라는 기능이 있습니다. 사용 방법은 다음과 같습니다.

Next.js has a feature called Draft Mode which solves this problem. Here are instructions on how to use it.

Step 1: Create and access the API route1단계: API route 만들고 접근하기

Next.js API Routes에 익숙하지 않다면 먼저 API Routes 문서를 살펴보세요.

Take a look at the API Routes documentation first if you’re not familiar with Next.js API Routes.

먼저 API route를 만드세요. 이름은 무엇이든 상관없습니다. 예: pages/api/draft.ts

First, create the API route. It can have any name - e.g. pages/api/draft.ts

이 API route에서 response object의 setDraftMode를 호출해야 합니다.

In this API route, you need to call setDraftMode on the response object.

export default function handler(req, res) {
  // ...
  res.setDraftMode({ enable: true })
  // ...
}

이렇게 하면 draft mode를 활성화하는 cookie가 설정됩니다. 이후 이 cookie를 포함한 request는 Draft Mode를 trigger하여 statically generated page의 동작을 바꿉니다(자세한 내용은 뒤에서 다룹니다).

This will set a cookie to enable draft mode. Subsequent requests containing this cookie will trigger Draft Mode changing the behavior for statically generated pages (more on this later).

아래와 같은 API route를 만들고 브라우저에서 직접 접근해 수동으로 테스트해 볼 수 있습니다:

You can test this manually by creating an API route like below and accessing it from your browser manually:

TSpages/api/draft.ts
// simple example for testing it manually from your browser.
export default function handler(req, res) {
  res.setDraftMode({ enable: true })
  res.end('Draft mode is enabled')
}

브라우저의 developer tools를 열고 /api/draft에 방문하면 __prerender_bypass라는 이름의 cookie가 담긴 Set-Cookie response header를 확인할 수 있습니다.

If you open your browser’s developer tools and visit /api/draft, you’ll notice a Set-Cookie response header with a cookie named __prerender_bypass.

Securely accessing it from your Headless CMSHeadless CMS에서 안전하게 접근하기

실제로는 headless CMS에서 이 API route를 안전하게 호출하고 싶을 것입니다. 구체적인 단계는 사용하는 headless CMS에 따라 다르지만, 일반적으로 다음과 같은 단계를 밟을 수 있습니다.

In practice, you’d want to call this API route securely from your headless CMS. The specific steps will vary depending on which headless CMS you’re using, but here are some common steps you could take.

이 단계들은 사용 중인 headless CMS가 custom draft URL 설정을 지원한다고 가정합니다. 지원하지 않더라도 이 방법으로 draft URL을 보호할 수는 있지만, draft URL을 직접 만들고 접근해야 합니다.

These steps assume that the headless CMS you’re using supports setting custom draft URLs. If it doesn’t, you can still use this method to secure your draft URLs, but you’ll need to construct and access the draft URL manually.

먼저, 원하는 token generator로 secret token string을 만드세요. 이 secret은 Next.js 앱과 headless CMS만 알고 있어야 합니다. 이 secret은 CMS 접근 권한이 없는 사람이 draft URL에 접근하지 못하게 막아 줍니다.

First, you should create a secret token string using a token generator of your choice. This secret will only be known by your Next.js app and your headless CMS. This secret prevents people who don’t have access to your CMS from accessing draft URLs.

둘째, headless CMS가 custom draft URL 설정을 지원한다면 다음을 draft URL로 지정하세요. 여기서는 draft API route가 pages/api/draft.ts에 있다고 가정합니다.

Second, if your headless CMS supports setting custom draft URLs, specify the following as the draft URL. This assumes that your draft API route is located at pages/api/draft.ts.

>_Terminal
https://<your-site>/api/draft?secret=<token>&slug=<path>
  • <your-site>는 deployment domain이어야 합니다.
  • <token>은 생성한 secret token으로 바꿔야 합니다.
  • <path>는 보려는 page의 path여야 합니다. /posts/foo를 보고 싶다면 &slug=/posts/foo를 사용하세요.
  • <your-site> should be your deployment domain.
  • <token> should be replaced with the secret token you generated.
  • <path> should be the path for the page that you want to view. If you want to view /posts/foo, then you should use &slug=/posts/foo.

headless CMS에 따라 draft URL에 변수를 넣어서 <path>가 CMS의 data에 따라 동적으로 설정되게 할 수도 있습니다. 예: &slug=/posts/{entry.fields.slug}

Your headless CMS might allow you to include a variable in the draft URL so that <path> can be set dynamically based on the CMS’s data like so: &slug=/posts/{entry.fields.slug}

마지막으로, draft API route에서 다음을 수행합니다:

Finally, in the draft API route:

  • secret이 일치하는지, 그리고 slug parameter가 존재하는지 확인합니다(그렇지 않으면 request가 실패해야 합니다). -
  • res.setDraftMode를 호출합니다.
  • 그다음 slug로 지정된 path로 브라우저를 redirect합니다. (다음 예제는 307 redirect를 사용합니다.)
  • Check that the secret matches and that the slug parameter exists (if not, the request should fail). -
  • Call res.setDraftMode.
  • Then redirect the browser to the path specified by slug. (The following example uses a 307 redirect).
export default async (req, res) => {
  // Check the secret and next parameters
  // This secret should only be known to this API route and the CMS
  if (req.query.secret !== 'MY_SECRET_TOKEN' || !req.query.slug) {
    return res.status(401).json({ message: 'Invalid token' })
  }

  // Fetch the headless CMS to check if the provided `slug` exists
  // getPostBySlug would implement the required fetching logic to the headless CMS
  const post = await getPostBySlug(req.query.slug)

  // If the slug doesn't exist prevent draft mode from being enabled
  if (!post) {
    return res.status(401).json({ message: 'Invalid slug' })
  }

  // Enable Draft Mode by setting the cookie
  res.setDraftMode({ enable: true })

  // Redirect to the path from the fetched post
  // We don't redirect to req.query.slug as that might lead to open redirect vulnerabilities
  res.redirect(post.slug)
}

성공하면 브라우저는 draft mode cookie를 가진 채로 보려는 path로 redirect됩니다.

If it succeeds, then the browser will be redirected to the path you want to view with the draft mode cookie.

Step 2: Update getStaticProps2단계: getStaticProps 업데이트하기

다음 단계는 draft mode를 지원하도록 getStaticProps를 업데이트하는 것입니다.

The next step is to update getStaticProps to support draft mode.

(res.setDraftMode로) cookie가 설정된 상태에서 getStaticProps가 있는 page를 request하면, getStaticProps는 (build time 대신) request time에 호출됩니다.

If you request a page which has getStaticProps with the cookie set (via res.setDraftMode), then getStaticProps will be called at request time (instead of at build time).

또한 context.draftMode가 true인 context object와 함께 호출됩니다.

Furthermore, it will be called with a context object where context.draftMode will be true.

export async function getStaticProps(context) {
  if (context.draftMode) {
    // dynamic data
  }
}

draft API route에서 res.setDraftMode를 사용했으므로 context.draftMode는 true가 됩니다.

We used res.setDraftMode in the draft API route, so context.draftMode will be true.

getStaticPaths도 사용하고 있다면 context.params도 사용할 수 있습니다.

If you’re also using getStaticPaths, then context.params will also be available.

Fetch draft datadraft data fetch하기

context.draftMode에 따라 다른 data를 fetch하도록 getStaticProps를 업데이트할 수 있습니다.

You can update getStaticProps to fetch different data based on context.draftMode.

예를 들어 headless CMS에 draft post용 API endpoint가 따로 있을 수 있습니다. 그렇다면 아래처럼 API endpoint URL을 바꿀 수 있습니다:

For example, your headless CMS might have a different API endpoint for draft posts. If so, you can modify the API endpoint URL like below:

export async function getStaticProps(context) {
  const url = context.draftMode
    ? 'https://draft.example.com'
    : 'https://production.example.com'
  const res = await fetch(url)
  // ...
}

이것으로 끝입니다! headless CMS에서 또는 직접 (secret과 slug를 포함해) draft API route에 접근하면 이제 draft 콘텐츠를 볼 수 있습니다. 그리고 게시하지 않고 draft를 업데이트해도 그 draft를 볼 수 있습니다.

That’s it! If you access the draft API route (with secret and slug) from your headless CMS or manually, you should now be able to see the draft content. And if you update your draft without publishing, you should be able to view the draft.

이것을 headless CMS의 draft URL로 설정하거나 직접 접근하면 draft를 볼 수 있습니다.

Set this as the draft URL on your headless CMS or access manually, and you should be able to see the draft.

>_Terminal
https://<your-site>/api/draft?secret=<token>&slug=<path>

More Details자세히 알아보기

Clear the Draft Mode cookieDraft Mode cookie 지우기

기본적으로 Draft Mode session은 브라우저를 닫으면 끝납니다.

By default, the Draft Mode session ends when the browser is closed.

Draft Mode cookie를 직접 지우려면 setDraftMode({ enable: false })를 호출하는 API route를 만드세요:

To clear the Draft Mode cookie manually, create an API route that calls setDraftMode({ enable: false }):

TSpages/api/disable-draft.ts
export default function handler(req, res) {
  res.setDraftMode({ enable: false })
}

그다음 /api/disable-draft로 request를 보내 API Route를 호출합니다. next/link로 이 route를 호출한다면, prefetch 시 실수로 cookie가 삭제되지 않도록 prefetch={false}를 전달해야 합니다.

Then, send a request to /api/disable-draft to invoke the API Route. If calling this route using next/link, you must pass prefetch={false} to prevent accidentally deleting the cookie on prefetch.

Works with getServerSidePropsgetServerSideProps와 함께 사용하기

Draft Mode는 getServerSideProps와 함께 동작하며, context object의 draftMode key로 사용할 수 있습니다.

Draft Mode works with getServerSideProps, and is available as a draftMode key in the context object.

Good to know

Draft Mode를 사용할 때는 Cache-Control header를 설정하면 안 됩니다. 이 header는 우회할 수 없기 때문입니다. 대신 ISR을 사용하는 것을 권장합니다.

You shouldn't set the Cache-Control header when using Draft Mode because it cannot be bypassed. Instead, we recommend using ISR.

Works with API RoutesAPI Routes와 함께 사용하기

API Routes에서는 request object의 draftMode에 접근할 수 있습니다. 예를 들면 다음과 같습니다:

API Routes will have access to draftMode on the request object. For example:

export default function myApiRoute(req, res) {
  if (req.draftMode) {
    // get draft data
  }
}

Unique per next buildnext build마다 고유한 값

next build를 실행할 때마다 새로운 bypass cookie 값이 생성됩니다.

A new bypass cookie value will be generated each time you run next build.

이렇게 해서 bypass cookie를 추측할 수 없도록 보장합니다.

This ensures that the bypass cookie can’t be guessed.

Good to know

HTTP로 로컬에서 Draft Mode를 테스트하려면 브라우저가 third-party cookie와 local storage 접근을 허용해야 합니다.

To test Draft Mode locally over HTTP, your browser will need to allow third-party cookies and local storage access.
