prefetchInliningexperimentalprefetchInlining

App Router가 route를 prefetch할 때, 작은 segment response를 각각 따로 request하는 대신 하나의 response로 묶을 수 있습니다. 이렇게 하면 prefetch request 수가 줄어드는 대신, 일부 공유 segment data가 route 간에 중복됩니다. 이 동작은 기본적으로 켜져 있으며, 대부분의 앱은 그대로 두는 것이 좋습니다.

When the App Router prefetches a route, it can bundle small segment responses into a single response instead of requesting each one separately. This reduces the number of prefetch requests at the cost of duplicating some shared segment data across routes. This behavior is on by default, and most apps should leave it that way.

experimental.prefetchInlining option을 사용하면 navigation 문제를 debugging하거나 request 양을 측정하는 동안 이 동작을 override하거나 inlining을 비활성화할 수 있습니다. 대부분의 애플리케이션에서는 기본 동작을 바꿀 필요가 없습니다.

The experimental.prefetchInlining option lets you override this behavior or disable inlining while debugging navigation issues or measuring request volume. For most applications, there is no need to change the default behavior.

Good to know

inlining 동작은 App Router의 영구적인 일부입니다. experimental.prefetchInlining configuration만 experimental이므로, 그 option은 아직 바뀔 수 있습니다.

The inlining behavior is a permanent part of the App Router. Only the experimental.prefetchInlining configuration is experimental, so its options may still change.

Usage사용법

prefetch inlining을 끄려면 experimental.prefetchInlining을 false로 설정하세요:

To turn off prefetch inlining, set experimental.prefetchInlining to false:

TSJSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    prefetchInlining: false,
  },
}

export default nextConfig
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    prefetchInlining: false,
  },
}

module.exports = nextConfig

inlining을 비활성화하는 대신 threshold를 override하려면 object를 전달하세요. 생략한 값은 기본값을 유지합니다:

To override the thresholds instead of disabling inlining, pass an object. Any value you omit keeps its default:

TSJSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    prefetchInlining: {
      maxSize: 2048,
      maxBundleSize: 10240,
    },
  },
}

export default nextConfig
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    prefetchInlining: {
      maxSize: 2048,
      maxBundleSize: 10240,
    },
  },
}

module.exports = nextConfig

Reference레퍼런스

값설명
true기본 threshold로 prefetch response를 inline합니다. 기본값입니다.
falseprefetch inlining을 비활성화합니다. 각 segment가 개별 request로 prefetch됩니다.
object설정한 maxSize 또는 maxBundleSize를 사용해 prefetch response를 inline합니다.
ValueDescription
trueInlines prefetch responses with the default thresholds. This is the default.
falseDisables prefetch inlining. Each segment is prefetched as its own request.
objectInlines prefetch responses using the maxSize or maxBundleSize you set.

object를 전달하면 다음 option이 threshold를 제어합니다. 둘 다 gzip으로 압축된 segment response의 byte 단위로 측정됩니다:

When you pass an object, the following options control the thresholds. Both are measured in bytes of the gzip-compressed segment response:

OptionType기본값설명
maxSizenumber2048inlining 대상이 될 수 있는 단일 segment response의 최대 크기입니다.
maxBundleSizenumber10240하나의 path를 따라 하나의 묶인 prefetch response에 inline될 수 있는 최대 전체 크기입니다.
OptionTypeDefaultDescription
maxSizenumber2048Largest a single segment response can be to still be eligible for inlining.
maxBundleSizenumber10240Largest total size that can be inlined into one bundled prefetch response along a path.

threshold를 낮추면 segment별 중복 제거가 더 많이 유지되고, 높이면 더 많은 data가 inline되어 request 수가 더 줄어듭니다.

Lower thresholds keep more per-segment deduplication; higher thresholds inline more data and cut request count further.
