Internationalization국제화

Next.js에서는 여러 언어를 지원하도록 콘텐츠의 routing과 rendering을 설정할 수 있습니다. 사이트를 여러 locale에 맞게 만드는 작업에는 번역된 콘텐츠(localization)와 internationalized route가 포함됩니다.

Next.js enables you to configure the routing and rendering of content to support multiple languages. Making your site adaptive to different locales includes translated content (localization) and internationalized routes.

Terminology용어

  • Locale: 언어와 형식(formatting) 선호 설정의 묶음을 나타내는 식별자입니다. 보통 사용자가 선호하는 언어와, 경우에 따라 사용자의 지리적 지역을 포함합니다.
    • en-US: 미국에서 쓰이는 영어
    • nl-NL: 네덜란드에서 쓰이는 네덜란드어
    • nl: 특정 지역이 없는 네덜란드어
  • Locale: An identifier for a set of language and formatting preferences. This usually includes the preferred language of the user and possibly their geographic region.
    • en-US: English as spoken in the United States
    • nl-NL: Dutch as spoken in the Netherlands
    • nl: Dutch, no specific region

Routing OverviewRouting 개요

어떤 locale을 사용할지 고를 때는 브라우저에 설정된 사용자의 언어 선호를 사용하는 것이 좋습니다. 선호 언어를 바꾸면 애플리케이션으로 들어오는 Accept-Language header가 바뀝니다.

It’s recommended to use the user’s language preferences in the browser to select which locale to use. Changing your preferred language will modify the incoming Accept-Language header to your application.

예를 들어 다음 library를 사용하면 들어오는 Request를 보고 Headers, 지원하려는 locale 목록, 기본 locale을 기준으로 어떤 locale을 선택할지 결정할 수 있습니다.

For example, using the following libraries, you can look at an incoming Request to determine which locale to select, based on the Headers, locales you plan to support, and the default locale.

JSproxy.js
import { match } from '@formatjs/intl-localematcher'
import Negotiator from 'negotiator'

let headers = { 'accept-language': 'en-US,en;q=0.5' }
let languages = new Negotiator({ headers }).languages()
let locales = ['en-US', 'nl-NL', 'nl']
let defaultLocale = 'en-US'

match(languages, locales, defaultLocale) // -> 'en-US'

routing은 sub-path(/fr/products)나 domain(my-site.fr/products)으로 국제화할 수 있습니다. 이 정보를 이용하면 이제 Proxy 안에서 locale을 기준으로 사용자를 redirect할 수 있습니다.

Routing can be internationalized by either the sub-path (/fr/products) or domain (my-site.fr/products). With this information, you can now redirect the user based on the locale inside Proxy.

JSproxy.js
import { NextResponse } from "next/server";

let locales = ['en-US', 'nl-NL', 'nl']

// Get the preferred locale, similar to the above or using a library
function getLocale(request) { ... }

export function proxy(request) {
  // Check if there is any supported locale in the pathname
  const { pathname } = request.nextUrl
  const pathnameHasLocale = locales.some(
    (locale) => pathname.startsWith(`/${locale}/`) || pathname === `/${locale}`
  )

  if (pathnameHasLocale) return

  // Redirect if there is no locale
  const locale = getLocale(request)
  request.nextUrl.pathname = `/${locale}${pathname}`
  // e.g. incoming request is /products
  // The new URL is now /en-US/products
  return NextResponse.redirect(request.nextUrl)
}

export const config = {
  matcher: [
    // Skip all internal paths (_next)
    '/((?!_next).*)',
    // Optional: only run on root (/) URL
    // '/'
  ],
}

마지막으로 app/ 안의 모든 special file이 app/[lang] 아래에 중첩되도록 하세요. 그러면 Next.js router가 route의 여러 locale을 동적으로 처리하고, 모든 layout과 page에 lang parameter를 전달할 수 있습니다. 예를 들면 다음과 같습니다:

Finally, ensure all special files inside app/ are nested under app/[lang]. This enables the Next.js router to dynamically handle different locales in the route, and forward the lang parameter to every layout and page. For example:

TSJSapp/[lang]/page.tsx
// You now have access to the current locale
// e.g. /en-US/products -> `lang` is "en-US"
export default async function Page({ params }: PageProps<'/[lang]'>) {
  const { lang } = await params
  return ...
}
// You now have access to the current locale
// e.g. /en-US/products -> `lang` is "en-US"
export default async function Page({ params }) {
  const { lang } = await params
  return ...
}
Good to know

PageProps와 LayoutProps는 전역에서 사용할 수 있는 TypeScript helper로, route parameter에 강력한 type을 제공합니다. 자세한 내용은 PageProps와 LayoutProps를 참고하세요.

PageProps and LayoutProps are globally available TypeScript helpers that provide strong typing for route parameters. See PageProps and LayoutProps for more details.

root layout도 새 폴더 안에 중첩할 수 있습니다(예: app/[lang]/layout.js).

The root layout can also be nested in the new folder (e.g. app/[lang]/layout.js).

Localization

사용자가 선호하는 locale에 따라 표시되는 콘텐츠를 바꾸는 것, 즉 localization은 Next.js에만 해당하는 것이 아닙니다. 아래에서 설명하는 패턴은 어떤 웹 애플리케이션에서든 똑같이 동작합니다.

Changing displayed content based on the user’s preferred locale, or localization, is not something specific to Next.js. The patterns described below would work the same with any web application.

애플리케이션에서 영어와 네덜란드어 콘텐츠를 모두 지원하고 싶다고 가정해 봅시다. 두 개의 서로 다른 "dictionary"를 관리할 수 있는데, dictionary는 어떤 key를 localized 문자열로 mapping해 주는 객체입니다. 예를 들면 다음과 같습니다:

Let’s assume we want to support both English and Dutch content inside our application. We might maintain two different “dictionaries”, which are objects that give us a mapping from some key to a localized string. For example:

dictionaries/en.json
{
  "products": {
    "cart": "Add to Cart"
  }
}
dictionaries/nl.json
{
  "products": {
    "cart": "Toevoegen aan Winkelwagen"
  }
}

그런 다음 요청된 locale의 번역을 load하는 getDictionary 함수를 만들 수 있습니다:

We can then create a getDictionary function to load the translations for the requested locale:

TSJSapp/[lang]/dictionaries.ts
import 'server-only'

const dictionaries = {
  en: () => import('./dictionaries/en.json').then((module) => module.default),
  nl: () => import('./dictionaries/nl.json').then((module) => module.default),
}

export type Locale = keyof typeof dictionaries

export const hasLocale = (locale: string): locale is Locale =>
  locale in dictionaries

export const getDictionary = async (locale: Locale) => dictionaries[locale]()
import 'server-only'

const dictionaries = {
  en: () => import('./dictionaries/en.json').then((module) => module.default),
  nl: () => import('./dictionaries/nl.json').then((module) => module.default),
}

export const hasLocale = (locale) => locale in dictionaries

export const getDictionary = async (locale) => dictionaries[locale]()

현재 선택된 언어가 주어지면 layout이나 page 안에서 dictionary를 fetch할 수 있습니다.

Given the currently selected language, we can fetch the dictionary inside of a layout or page.

lang은 string으로 type이 지정되므로, hasLocale을 사용하면 type을 지원하는 locale로 좁힐(narrow) 수 있습니다. 또한 번역이 없을 때 runtime error 대신 404가 반환되도록 보장합니다.

Since lang is typed as string, using hasLocale narrows the type to your supported locales. It also ensures a 404 is returned if a translation is missing, rather than a runtime error.

TSJSapp/[lang]/page.tsx
import { notFound } from 'next/navigation'
import { getDictionary, hasLocale } from './dictionaries'

export default async function Page({ params }: PageProps<'/[lang]'>) {
  const { lang } = await params

  if (!hasLocale(lang)) notFound()

  const dict = await getDictionary(lang)
  return <button>{dict.products.cart}</button> // Add to Cart
}
import { notFound } from 'next/navigation'
import { getDictionary, hasLocale } from './dictionaries'

export default async function Page({ params }) {
  const { lang } = await params

  if (!hasLocale(lang)) notFound()

  const dict = await getDictionary(lang)
  return <button>{dict.products.cart}</button> // Add to Cart
}

app/ directory의 모든 layout과 page는 기본적으로 Server Component이므로, 번역 파일의 크기가 client-side JavaScript bundle 크기에 영향을 줄까 걱정할 필요가 없습니다. 이 코드는 server에서만 실행되고, 결과 HTML만 브라우저로 전송됩니다.

Because all layouts and pages in the app/ directory default to Server Components, we do not need to worry about the size of the translation files affecting our client-side JavaScript bundle size. This code will only run on the server, and only the resulting HTML will be sent to the browser.

Sharing the locale across your app앱 전체에서 locale 공유하기

locale은 그것을 받는 page 밖에서도 필요한 경우가 많습니다. 공유 data-fetching utility나 깊이 중첩된 component 같은 곳입니다. 각 계층마다 lang을 prop drilling하는 대신 next/root-params로 직접 읽을 수 있습니다.

The locale is often needed beyond the page that receives it, such as in shared data-fetching utilities or deeply nested components. Instead of prop drilling lang through each layer, we can read it directly with next/root-params.

next/root-params는 root layout 위에 있는 각 dynamic segment에 대한 getter를 export합니다. 모든 route가 app/[lang] 아래에 중첩되어 있으므로 lang은 root parameter이고, 어떤 Server Component나 server-side utility든 그 getter를 호출할 수 있습니다. locale 조회를 getDictionary 안으로 옮기면 호출하는 쪽에서 더 이상 lang을 넘기지 않아도 됩니다:

next/root-params exports a getter for each dynamic segment above the root layout. Since every route is nested under app/[lang], lang is a root parameter, and any Server Component or server-side utility can call its getter. We can move the locale lookup into getDictionary, so callers no longer pass lang:

TSJSapp/[lang]/dictionaries.ts
import { lang } from 'next/root-params'
import { notFound } from 'next/navigation'

const dictionaries = {
  en: () => import('./dictionaries/en.json').then((module) => module.default),
  nl: () => import('./dictionaries/nl.json').then((module) => module.default),
}

export type Locale = keyof typeof dictionaries

export const hasLocale = (locale: string): locale is Locale =>
  locale in dictionaries

export const getDictionary = async () => {
  const locale = await lang()
  if (!hasLocale(locale)) notFound()
  return dictionaries[locale]()
}
import { lang } from 'next/root-params'
import { notFound } from 'next/navigation'

const dictionaries = {
  en: () => import('./dictionaries/en.json').then((module) => module.default),
  nl: () => import('./dictionaries/nl.json').then((module) => module.default),
}

export const hasLocale = (locale) => locale in dictionaries

export const getDictionary = async () => {
  const locale = await lang()
  if (!hasLocale(locale)) notFound()
  return dictionaries[locale]()
}
Good to know

next/root-params에서 import하는 파일에는 import 'server-only'가 필요 없습니다. Client Component에서 사용하면 이 import 자체가 이미 build 시점에 실패합니다.

Files that import from next/root-params do not need import 'server-only'. The import already fails at build time if used in a Client Component.

이제 locale이 내부에서 resolve되므로 page와 component는 인자 없이 getDictionary()를 호출합니다:

Pages and components then call getDictionary() with no arguments, since the locale is resolved internally:

TSJSapp/[lang]/page.tsx
import { getDictionary } from './dictionaries'

export default async function Page() {
  const dict = await getDictionary()
  return <button>{dict.products.cart}</button> // Add to Cart
}
import { getDictionary } from './dictionaries'

export default async function Page() {
  const dict = await getDictionary()
  return <button>{dict.products.cart}</button> // Add to Cart
}
Good to know

root parameter getter는 Server Component와 server-side utility에서 실행되지만, Client Component, Server Action, Route Handler에서는 실행되지 않습니다. 전체 API와 caching 관련 동작은 next/root-params를 참고하세요.

Root parameter getters run in Server Components and server-side utilities, but not in Client Components, Server Actions, or Route Handlers. See next/root-params for the full API and its behavior with caching.

Static Rendering

주어진 locale 집합에 대한 static route를 생성하려면 어떤 page나 layout에서든 generateStaticParams를 사용할 수 있습니다. 예를 들어 root layout에서처럼 전역으로 적용할 수도 있습니다:

To generate static routes for a given set of locales, we can use generateStaticParams with any page or layout. This can be global, for example, in the root layout:

TSJSapp/[lang]/layout.tsx
export async function generateStaticParams() {
  return [{ lang: 'en-US' }, { lang: 'de' }]
}

export default async function RootLayout({
  children,
  params,
}: LayoutProps<'/[lang]'>) {
  return (
    <html lang={(await params).lang}>
      <body>{children}</body>
    </html>
  )
}
export async function generateStaticParams() {
  return [{ lang: 'en-US' }, { lang: 'de' }]
}

export default async function RootLayout({ children, params }) {
  return (
    <html lang={(await params).lang}>
      <body>{children}</body>
    </html>
  )
}
