notFoundnotFound

notFound 함수는 Next.js 404 page를 render하는 error를 throw합니다. 애플리케이션에서 존재하지 않는 resource를 처리할 때 유용합니다. UI는 not-found.js 파일로 customize할 수 있습니다.

The notFound function throws an error that renders a Next.js 404 page. It's useful for handling missing resources in your application. You can customize the UI using the not-found.js file.

notFound()를 호출하면 NEXT_HTTP_ERROR_FALLBACK;404 error를 throw하고, 그것이 throw된 route segment의 rendering을 종료합니다. Next.js는 page가 index되지 않도록 <meta name="robots" content="noindex" /> tag도 삽입합니다. throw하는 방식으로 동작하므로 render 경로, 즉 component나 component가 await하는 함수 안에서 호출하세요. await되지 않은 promise 안에 남겨진 호출은 아무것도 catch하지 않는 곳에서 throw되어 not-found UI가 render되지 않습니다(development에서는 server가 ⨯ unhandledRejection: NEXT_HTTP_ERROR_FALLBACK;404를 log에 남깁니다).

Invoking notFound() throws a NEXT_HTTP_ERROR_FALLBACK;404 error and terminates rendering of the route segment where it was thrown. Next.js also injects a <meta name="robots" content="noindex" /> tag so the page is not indexed. Because it works by throwing, call it in the render path: a component, or a function a component awaits. A call left in an un-awaited promise throws where nothing catches it, and no not-found UI renders (in development the server logs ⨯ unhandledRejection: NEXT_HTTP_ERROR_FALLBACK;404).

notFound()는 Server Component, Server Function, Route Handler에서 호출할 수 있습니다.

notFound() can be invoked in Server Components, Server Functions, and Route Handlers.

TSJSapp/user/[id]/page.tsx
import { notFound } from 'next/navigation'

async function fetchUser(id: string) {
  const res = await fetch('https://...')
  if (!res.ok) return undefined
  return res.json()
}

export default async function Profile({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const user = await fetchUser(id)

  if (!user) {
    notFound()
  }

  // ...
}

Good to know알아 두면 좋은 점

return notFound()라고 쓸 필요는 없습니다. 함수 실행을 중단시키는 exception을 throw하므로 호출하는 것만으로 충분합니다. TypeScript는 never return type을 통해 이를 이해하므로, 먼저 확인한 값은 그 이후에도 narrowing된 상태로 유지됩니다:

You do not need to write return notFound(). Calling it is enough, because it throws an exception that stops function execution. TypeScript understands this from its never return type, so a value you check first stays narrowed afterward:

// fetchUser resolves to a user object, or undefined
const user = await fetchUser(id)

if (!user) {
  notFound()
}

// user is defined here
return <Profile user={user} />

다른 exception과 마찬가지로, 무언가가 catch할 때까지 call stack을 따라 올라갑니다. 호출을 try/catch로 감싸면 exception이 억제되어 not-found UI가 render되지 않습니다. 호출 근처에서 error를 catch해야 한다면 unstable_rethrow를 사용해 interrupt를 먼저 통과시키세요.

Like any exception, it travels up the call stack until something catches it. A try/catch around the call suppresses it, and the not-found UI won't render. If you need to catch errors near the call, use unstable_rethrow to let the interrupt through first.

Examples예시

Calling notFound() after streaming has startedstreaming이 시작된 뒤 notFound() 호출하기

데이터를 load하는 동안 page의 shell과 loading UI를 계속 보이게 하려면, route 전체를 block하는 대신 <Suspense>로 감싼 component 안에서 존재 여부를 확인하세요. 이 확인을 하기에 가장 관용적인 곳은 데이터가 필요한 component가 await하는 data-access 함수 자체입니다:

To keep a page's shell and loading UI visible while data loads, do the existence check inside a component wrapped in <Suspense> instead of blocking the whole route. The idiomatic place for the check is the data-access function itself, awaited by the component that needs the data:

TSJSapp/blog/[slug]/page.tsx
import { Suspense } from 'react'
import Link from 'next/link'
import { notFound } from 'next/navigation'

async function getPost(slug: string) {
  const res = await fetch(`https://api.example.com/posts/${slug}`)
  if (res.status === 404) {
    notFound()
  }
  if (!res.ok) {
    throw new Error(`Failed to load post: ${res.status}`)
  }
  return res.json()
}

async function Article({ slug }: { slug: string }) {
  const post = await getPost(slug)
  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </article>
  )
}

export default async function PostPage({ params }: PageProps<'/blog/[slug]'>) {
  const { slug } = await params

  return (
    <section>
      <Link href="/blog">Blog</Link>
      <Suspense fallback={<p>Loading...</p>}>
        <Article slug={slug} />
      </Suspense>
    </section>
  )
}

post가 존재하지 않으면 getPost가 notFound()를 호출하고, 이것이 throw됩니다. 이는 rendering 중에 일어나므로, page shell이 이미 전송된 뒤라도 exception은 가장 가까운 not-found boundary로 전파되고, 그 boundary가 stream될 콘텐츠 자리에 render됩니다.

When the post doesn't exist, getPost calls notFound(), which throws. Because this happens during rendering, the exception propagates to the nearest not-found boundary, which renders in place of the streamed-in content, even though the page shell has already been sent.

그 UI를 정의하려면 route 옆에 not-found.tsx를 추가하세요. 없으면 가장 가까운 상위 not-found boundary가 render되고, 최종적으로는 Next.js의 기본 404 page로 fallback됩니다:

Add a not-found.tsx alongside the route to define that UI. Without one, the nearest parent not-found boundary renders, falling back to Next.js's default 404 page:

TSJSapp/blog/[slug]/not-found.tsx
export default function NotFound() {
  return (
    <section>
      <h1>Post not found</h1>
      <p>The post you're looking for doesn't exist.</p>
    </section>
  )
}
export default function NotFound() {
  return (
    <section>
      <h1>Post not found</h1>
      <p>The post you're looking for doesn't exist.</p>
    </section>
  )
}

response는 notFound()가 실행되기 전에 <Suspense> boundary부터 streaming을 시작하므로 200 status를 유지합니다. Next.js는 noindex tag를 추가합니다.

The response starts streaming from the <Suspense> boundary before notFound() runs, so it keeps its 200 status. Next.js adds a noindex tag.

streaming이 시작되기 전에 notFound()를 호출하면 404를 반환합니다. prerendering 중에 notFound()에 도달하는 page는 ○ Static으로 남아 404를 제공할 수 있습니다. request 시점의 확인은 page가 render되기 전에 Proxy에서 실행할 수 있습니다. Status codes를 참고하세요.

Calling notFound() before streaming starts returns a 404. A page that reaches notFound() during prerendering can remain ○ Static and serve a 404. A request-time check can run in Proxy before the page renders. See Status codes.

Serving a 404 from a Route HandlerRoute Handler에서 404 제공하기

notFound()는 Route Handler에서도 동작하며, 호출자에게 404를 제공합니다.

notFound() also works in a Route Handler, where it serves a 404 to the caller.

TSJSapp/api/posts/[slug]/route.ts
import { NextResponse } from 'next/server'
import { notFound } from 'next/navigation'

export async function GET(
  request: Request,
  { params }: RouteContext<'/api/posts/[slug]'>
) {
  const { slug } = await params
  const res = await fetch(`https://api.example.com/posts/${slug}`)
  if (!res.ok) {
    notFound()
  }
  return NextResponse.json(await res.json())
}

  return NextResponse.json(await res.json())
}
