How to upgrade to version 9버전 9로 업그레이드하기

버전 9로 업그레이드하려면 다음 command를 실행하세요:

To upgrade to version 9, run the following command:

>_Terminal
npm i next@9
>_Terminal
yarn add next@9
>_Terminal
pnpm up next@9
>_Terminal
bun add next@9
Good to know

TypeScript를 사용한다면 @types/react와 @types/react-dom도 그에 맞는 버전으로 함께 upgrade하세요.

If you are using TypeScript, ensure you also upgrade @types/react and @types/react-dom to their corresponding versions.

Check your Custom App File (pages/_app.js)Custom App 파일(pages/_app.js) 확인하기

이전에 Custom <App> 예제를 복사해 사용했다면, getInitialProps를 제거할 수 있을지도 모릅니다.

If you previously copied the Custom <App> example, you may be able to remove your getInitialProps.

새 Next.js 기능을 활용하려면 (가능한 경우) pages/_app.js에서 getInitialProps를 제거하는 것이 중요합니다!

Removing getInitialProps from pages/_app.js (when possible) is important to leverage new Next.js features!

다음 getInitialProps는 아무 일도 하지 않으므로 제거해도 됩니다:

The following getInitialProps does nothing and may be removed:

class MyApp extends App {
  // Remove me, I do nothing!
  static async getInitialProps({ Component, ctx }) {
    let pageProps = {}

    if (Component.getInitialProps) {
      pageProps = await Component.getInitialProps(ctx)
    }

    return { pageProps }
  }

  render() {
    // ... etc
  }
}

Breaking ChangesBreaking Change

@zeit/next-typescript is no longer necessary@zeit/next-typescript는 더 이상 필요하지 않습니다

이제 Next.js는 @zeit/next-typescript 사용을 무시하고 제거하라는 경고를 표시합니다. next.config.js에서 이 plugin을 제거하세요.

Next.js will now ignore usage @zeit/next-typescript and warn you to remove it. Please remove this plugin from your next.config.js.

custom .babelrc가 있다면 거기에서 @zeit/next-typescript/babel 참조를 제거하세요.

Remove references to @zeit/next-typescript/babel from your custom .babelrc (if present).

fork-ts-checker-webpack-plugin 사용도 next.config.js에서 제거해야 합니다.

The usage of fork-ts-checker-webpack-plugin should also be removed from your next.config.js.

TypeScript Definition은 next package와 함께 배포되므로, 충돌하지 않도록 @types/next를 uninstall해야 합니다.

TypeScript Definitions are published with the next package, so you need to uninstall @types/next as they would conflict.

다음 type들이 다릅니다:

The following types are different:

이 목록은 upgrade를 돕기 위해 커뮤니티가 만들었습니다. 다른 차이점을 발견하면 다른 사용자에게 도움이 되도록 이 목록에 pull-request를 보내 주세요.

This list was created by the community to help you upgrade, if you find other differences please send a pull-request to this list to help other users.

변경 전:

From:

import { NextContext } from 'next'
import { NextAppContext, DefaultAppIProps } from 'next/app'
import { NextDocumentContext, DefaultDocumentIProps } from 'next/document'

변경 후

to

import { NextPageContext } from 'next'
import { AppContext, AppInitialProps } from 'next/app'
import { DocumentContext, DocumentInitialProps } from 'next/document'

The config key is now an export on a page이제 config key는 page의 export입니다

이제 page에서 config라는 이름의 custom 변수를 export할 수 없습니다(즉, export { config } / export const config ...). 이 export된 변수는 이제 Opt-in AMP나 API Route 기능 같은 page 단위 Next.js configuration을 지정하는 데 사용됩니다.

You may no longer export a custom variable named config from a page (i.e. export { config } / export const config ...). This exported variable is now used to specify page-level Next.js configuration like Opt-in AMP and API Route features.

Next.js 용도가 아닌 config export는 다른 이름으로 바꿔야 합니다.

You must rename a non-Next.js-purposed config export to something different.

next/dynamic no longer renders "loading..." by default while loadingnext/dynamic은 loading 중에 더 이상 기본으로 "loading..."을 render하지 않습니다

Dynamic component는 loading 중에 기본적으로 아무것도 render하지 않습니다. loading property를 설정해 이 동작을 여전히 customize할 수 있습니다:

Dynamic components will not render anything by default while loading. You can still customize this behavior by setting the loading property:

import dynamic from 'next/dynamic'

const DynamicComponentWithCustomLoading = dynamic(
  () => import('../components/hello2'),
  {
    loading: () => <p>Loading</p>,
  }
)

withAmp has been removed in favor of an exported configuration objectwithAmp가 제거되고 export된 configuration object로 대체되었습니다

이제 Next.js에는 page 단위 configuration 개념이 있으므로, 일관성을 위해 withAmp higher-order component가 제거되었습니다.

Next.js now has the concept of page-level configuration, so the withAmp higher-order component has been removed for consistency.

이 변경은 Next.js 프로젝트 root에서 다음 command를 실행해 자동으로 migrate할 수 있습니다:

This change can be automatically migrated by running the following commands in the root of your Next.js project:

>_Terminal
curl -L https://github.com/vercel/next-codemod/archive/master.tar.gz | tar -xz --strip=2 next-codemod-master/transforms/withamp-to-config.js npx jscodeshift -t ./withamp-to-config.js pages/**/*.js

이 migration을 직접 수행하거나 codemod가 만들어 낼 결과를 보려면 아래를 참고하세요:

To perform this migration by hand, or view what the codemod will produce, see below:

Before

Before

import { withAmp } from 'next/amp'

function Home() {
  return <h1>My AMP Page</h1>
}

export default withAmp(Home)
// or
export default withAmp(Home, { hybrid: true })

After

After

export default function Home() {
  return <h1>My AMP Page</h1>
}

export const config = {
  amp: true,
  // or
  amp: 'hybrid',
}

next export no longer exports pages as index.htmlnext export는 더 이상 page를 index.html로 export하지 않습니다

이전에는 pages/about.js를 export하면 out/about/index.html이 만들어졌습니다. 이 동작이 바뀌어 이제 out/about.html이 만들어집니다.

Previously, exporting pages/about.js would result in out/about/index.html. This behavior has been changed to result in out/about.html.

다음 내용으로 next.config.js를 만들면 이전 동작으로 되돌릴 수 있습니다:

You can revert to the previous behavior by creating a next.config.js with the following content:

JSnext.config.js
module.exports = {
  trailingSlash: true,
}

pages/api/ is treated differentlypages/api/는 다르게 처리됩니다

이제 pages/api/ 안의 page는 API Routes로 간주됩니다. 이 directory 안의 page에는 더 이상 client-side bundle이 포함되지 않습니다.

Pages in pages/api/ are now considered API Routes. Pages in this directory will no longer contain a client-side bundle.

Deprecated FeaturesDeprecated 기능

next/dynamic has deprecated loading multiple modules at oncenext/dynamic에서 여러 module을 한 번에 load하는 기능이 deprecated되었습니다

React의 구현(React.lazy와 Suspense)에 더 가까워지도록, next/dynamic에서 여러 module을 한 번에 load하는 기능이 deprecated되었습니다.

The ability to load multiple modules at once has been deprecated in next/dynamic to be closer to React's implementation (React.lazy and Suspense).

이 동작에 의존하는 코드를 업데이트하는 것은 비교적 간단합니다! 애플리케이션 migration을 돕기 위해 before/after 예제를 준비했습니다:

Updating code that relies on this behavior is relatively straightforward! We've provided an example of a before/after to help you migrate your application:

Before

Before

import dynamic from 'next/dynamic'

const HelloBundle = dynamic({
  modules: () => {
    const components = {
      Hello1: () => import('../components/hello1').then((m) => m.default),
      Hello2: () => import('../components/hello2').then((m) => m.default),
    }

    return components
  },
  render: (props, { Hello1, Hello2 }) => (
    <div>
      <h1>{props.title}</h1>
      <Hello1 />
      <Hello2 />
    </div>
  ),
})

function DynamicBundle() {
  return <HelloBundle title="Dynamic Bundle" />
}

export default DynamicBundle

After

After

import dynamic from 'next/dynamic'

const Hello1 = dynamic(() => import('../components/hello1'))
const Hello2 = dynamic(() => import('../components/hello2'))

function HelloBundle({ title }) {
  return (
    <div>
      <h1>{title}</h1>
      <Hello1 />
      <Hello2 />
    </div>
  )
}

function DynamicBundle() {
  return <HelloBundle title="Dynamic Bundle" />
}

export default DynamicBundle
