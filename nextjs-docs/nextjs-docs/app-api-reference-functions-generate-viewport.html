generateViewportgenerateViewport

static viewport object나 dynamic generateViewport 함수로 페이지의 초기 viewport를 customize할 수 있습니다.

You can customize the initial viewport of the page with the static viewport object or the dynamic generateViewport function.

Good to know
  • viewport object와 generateViewport 함수 export는 Server Component에서만 지원됩니다.
  • 같은 route segment에서 viewport object와 generateViewport 함수를 동시에 export할 수 없습니다.
  • metadata export에서 migrate하는 중이라면 metadata-to-viewport-export codemod를 사용해 변경 사항을 업데이트할 수 있습니다.
  • The viewport object and generateViewport function exports are only supported in Server Components.
  • You cannot export both the viewport object and generateViewport function from the same route segment.
  • If you're coming from migrating metadata exports, you can use metadata-to-viewport-export codemod to update your changes.

The viewport objectviewport object

viewport option을 정의하려면 layout.jsx 또는 page.jsx 파일에서 viewport object를 export하세요.

To define the viewport options, export a viewport object from a layout.jsx or page.jsx file.

TSJSlayout.tsx | page.tsx
import type { Viewport } from 'next'

export const viewport: Viewport = {
  themeColor: 'black',
}

export default function Page() {}
export const viewport = {
  themeColor: 'black',
}

export default function Page() {}

generateViewport functiongenerateViewport 함수

generateViewport는 하나 이상의 viewport field를 담은 Viewport object를 반환해야 합니다.

generateViewport should return a Viewport object containing one or more viewport fields.

TSlayout.tsx | page.tsx
export function generateViewport({ params }) {
  return {
    themeColor: '...',
  }
}

TypeScript에서는 generateViewport가 정의된 위치에 따라 PageProps<'/route'> 또는 LayoutProps<'/route'>로 params argument의 type을 지정할 수 있습니다.

In TypeScript, the params argument can be typed via PageProps<'/route'> or LayoutProps<'/route'> depending on where generateViewport is defined.

JSlayout.js | page.js
export function generateViewport({ params }) {
  return {
    themeColor: '...',
  }
}
Good to know
  • viewport가 request 정보에 의존하지 않는다면 generateViewport 대신 static viewport object로 정의해야 합니다.
  • If the viewport doesn't depend on request information, it should be defined using the static viewport object rather than generateViewport.

Good to know

viewport meta tag는 자동으로 설정되며, 기본값으로 충분하므로 보통은 직접 설정할 필요가 없습니다. 다만 완전성을 위해 정보를 제공합니다.

The viewport meta tag is automatically set, and manual configuration is usually unnecessary as the default is sufficient. However, the information is provided for completeness.

TSJSlayout.tsx | page.tsx
import type { Viewport } from 'next'

export const viewport: Viewport = {
  width: 'device-width',
  initialScale: 1,
  maximumScale: 1,
  userScalable: false,
  // Also supported but less commonly used
  // interactiveWidget: 'resizes-visual',
}
export const viewport = {
  width: 'device-width',
  initialScale: 1,
  maximumScale: 1,
  userScalable: false,
  // Also supported but less commonly used
  // interactiveWidget: 'resizes-visual',
}
<head> output
<meta
  name="viewport"
  content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no"
/>

With Cache ComponentsCache Components와 함께 사용하기

Cache Components가 활성화되어 있으면 generateViewport는 다른 component와 같은 규칙을 따릅니다. viewport가 runtime 데이터(cookies(), headers(), params, searchParams)에 접근하거나 cache되지 않은 data fetching을 수행하면 request time으로 미뤄집니다.

When Cache Components is enabled, generateViewport follows the same rules as other components. If viewport accesses runtime data (cookies(), headers(), params, searchParams) or performs uncached data fetching, it defers to request time.

metadata와 달리 viewport는 initial page load UI에 영향을 주기 때문에 stream될 수 없습니다. generateViewport가 request time으로 미뤄지면 페이지는 resolve될 때까지 block되어야 합니다.

Unlike metadata, viewport cannot be streamed because it affects initial page load UI. If generateViewport defers to request time, the page would need to block until resolved.

viewport가 외부 데이터에는 의존하지만 runtime 데이터에는 의존하지 않는다면 use cache를 사용하세요:

If viewport depends on external data but not runtime data, use use cache:

TSapp/layout.tsx
export async function generateViewport() {
  'use cache'
  const { width, initialScale } = await db.query('viewport-size')
  return { width, initialScale }
}

viewport가 정말로 runtime 데이터를 필요로 한다면, 문서의 <body>를 <Suspense> boundary로 감싸 route 전체가 dynamic해야 한다는 것을 알리세요. shell은 즉시 전송되고, viewport가 resolve되면 문서가 stream됩니다:

If viewport genuinely requires runtime data, wrap the document <body> in a <Suspense> boundary to signal that the entire route should be dynamic. The shell ships immediately and the document streams in once the viewport resolves:

TSapp/layout.tsx
import { Suspense } from 'react'
import { cookies } from 'next/headers'

export async function generateViewport() {
  const cookieJar = await cookies()
  return {
    themeColor: cookieJar.get('theme-color')?.value,
  }
}

export default function RootLayout({ children }) {
  return (
    <Suspense>
      <html>
        <body>{children}</body>
      </html>
    </Suspense>
  )
}

또는 instant = false로 segment를 instant-navigation 검증에서 제외할 수도 있습니다. 이 경우 route는 매 request마다 render되며, navigation은 render가 완료될 때까지 block됩니다:

Alternatively, opt the segment out of instant-navigation validation with instant = false. The route renders on every request and the navigation blocks until the render completes:

TSapp/dashboard/layout.tsx
import { cookies } from 'next/headers'

export const instant = false

export async function generateViewport() {
  const cookieJar = await cookies()
  return {
    themeColor: cookieJar.get('theme-color')?.value,
  }
}

export default function DashboardLayout({ children }) {
  return <section>{children}</section>
}

instant = false를 설정하면 이를 export한 segment만 제외됩니다. 하위 segment는 여전히 global 기본값에 따라 검증됩니다. 전체 해결 방법, trade-off, subtree 전체를 제외하는 방법은 Next.js encountered runtime data in generateViewport()를 참고하세요.

Setting instant = false opts only the segment that exports it out. Descendant segments are still validated by the global default. See Next.js encountered runtime data in generateViewport() for the full set of fix options, trade-offs, and the subtree-wide opt-out.

Good to know

여러 root layout을 사용하면 완전히 dynamic한 viewport를 특정 route로 격리하면서, 애플리케이션의 다른 route는 여전히 static shell을 생성하도록 할 수 있습니다.

Use multiple root layouts to isolate fully dynamic viewport to specific routes, while still letting other routes in your application generate a static shell.

Types

Viewport type을 사용해 viewport object에 type safety를 더할 수 있습니다. IDE에서 built-in TypeScript plugin을 사용하고 있다면 type을 직접 추가할 필요는 없지만, 원한다면 명시적으로 추가할 수도 있습니다.

You can add type safety to your viewport object by using the Viewport type. If you are using the built-in TypeScript plugin in your IDE, you do not need to manually add the type, but you can still explicitly add it if you want.

viewport object

import type { Viewport } from 'next'

export const viewport: Viewport = {
  themeColor: 'black',
}

generateViewport functiongenerateViewport 함수

Regular function일반 함수

import type { Viewport } from 'next'

export function generateViewport(): Viewport {
  return {
    themeColor: 'black',
  }
}

With segment propssegment props와 함께

import type { Viewport } from 'next'

type Props = {
  params: Promise<{ id: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}

export function generateViewport({ params, searchParams }: Props): Viewport {
  return {
    themeColor: 'black',
  }
}

export default function Page({ params, searchParams }: Props) {}

JavaScript ProjectsJavaScript 프로젝트

JavaScript 프로젝트에서는 JSDoc을 사용해 type safety를 더할 수 있습니다.

For JavaScript projects, you can use JSDoc to add type safety.

/** @type {import("next").Viewport} */
export const viewport = {
  themeColor: 'black',
}
