Custom DocumentCustom Document

custom Document를 사용하면 Page를 render하는 데 쓰이는 <html>과 <body> tag를 수정할 수 있습니다.

A custom Document can update the <html> and <body> tags used to render a Page.

기본 Document를 override하려면 아래처럼 pages/_document 파일을 만드세요:

To override the default Document, create the file pages/_document as shown below:

TSJSpages/_document.tsx
import { Html, Head, Main, NextScript } from 'next/document'

export default function Document() {
  return (
    <Html lang="en">
      <Head />
      <body>
        <Main />
        <NextScript />
      </body>
    </Html>
  )
}
import { Html, Head, Main, NextScript } from 'next/document'

export default function Document() {
  return (
    <Html lang="en">
      <Head />
      <body>
        <Main />
        <NextScript />
      </body>
    </Html>
  )
}
Good to know
  • _document는 server에서만 render되므로 이 파일에서는 onClick 같은 event handler를 사용할 수 없습니다.
  • page가 제대로 render되려면 <Html>, <Head />, <Main />, <NextScript />가 필요합니다.
  • _document is only rendered on the server, so event handlers like onClick cannot be used in this file.
  • <Html>, <Head />, <Main /> and <NextScript /> are required for the page to be properly rendered.

Caveats주의 사항

  • _document에서 사용하는 <Head /> component는 next/head와 같지 않습니다. 여기서 사용하는 <Head /> component는 모든 page에 공통인 <head> 코드에만 사용해야 합니다. <title> tag 같은 그 밖의 모든 경우에는 page나 component에서 next/head를 사용하는 것을 권장합니다.
  • <Main /> 바깥의 React component는 브라우저에서 초기화되지 않습니다. 여기에 애플리케이션 logic이나 custom CSS(styled-jsx 등)를 추가하지 마세요. 모든 page에서 공유하는 component(메뉴나 toolbar 등)가 필요하다면 대신 Layouts를 읽어 보세요.
  • Document는 현재 getStaticProps나 getServerSideProps 같은 Next.js Data Fetching method를 지원하지 않습니다.
  • The <Head /> component used in _document is not the same as next/head. The <Head /> component used here should only be used for any <head> code that is common for all pages. For all other cases, such as <title> tags, we recommend using next/head in your pages or components.
  • React components outside of <Main /> will not be initialized by the browser. Do not add application logic here or custom CSS (like styled-jsx). If you need shared components in all your pages (like a menu or a toolbar), read Layouts instead.
  • Document currently does not support Next.js Data Fetching methods like getStaticProps or getServerSideProps.

Customizing renderPagerenderPage customize하기

renderPage customize는 고급 기능이며, CSS-in-JS 같은 library가 server-side rendering을 지원하기 위해서만 필요합니다. 기본 제공되는 styled-jsx 지원에는 필요하지 않습니다.

Customizing renderPage is advanced and only needed for libraries like CSS-in-JS to support server-side rendering. This is not needed for built-in styled-jsx support.

이 패턴은 권장하지 않습니다. 대신 App Router를 점진적으로 도입하는 것을 고려하세요. App Router를 사용하면 page와 layout의 data를 더 쉽게 fetch할 수 있습니다.

We do not recommend using this pattern. Instead, consider incrementally adopting the App Router, which allows you to more easily fetch data for pages and layouts.

TSJSpages/_document.tsx
import Document, {
  Html,
  Head,
  Main,
  NextScript,
  DocumentContext,
  DocumentInitialProps,
} from 'next/document'

class MyDocument extends Document {
  static async getInitialProps(
    ctx: DocumentContext
  ): Promise<DocumentInitialProps> {
    const originalRenderPage = ctx.renderPage

    // Run the React rendering logic synchronously
    ctx.renderPage = () =>
      originalRenderPage({
        // Useful for wrapping the whole react tree
        enhanceApp: (App) => App,
        // Useful for wrapping in a per-page basis
        enhanceComponent: (Component) => Component,
      })

    // Run the parent `getInitialProps`, it now includes the custom `renderPage`
    const initialProps = await Document.getInitialProps(ctx)

    return initialProps
  }

  render() {
    return (
      <Html lang="en">
        <Head />
        <body>
          <Main />
          <NextScript />
        </body>
      </Html>
    )
  }
}

export default MyDocument

Good to know
  • _document의 getInitialProps는 client-side 전환 중에는 호출되지 않습니다.
  • _document의 ctx object는 getInitialProps에서 받는 것과 같으며, 여기에 renderPage가 추가됩니다.
  • getInitialProps in _document is not called during client-side transitions.
  • The ctx object for _document is equivalent to the one received in getInitialProps, with the addition of renderPage.
