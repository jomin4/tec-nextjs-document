prefetchprefetch

await prefetch()를 호출하면 그 아래의 runtime 작업이 route의 App Shell에서 제외됩니다. 그 작업은 link별 prefetch나 navigation 중에 실행될 수 있고, shell에는 가장 가까운 <Suspense> boundary의 fallback이 render됩니다.

Calling await prefetch() keeps runtime work below it out of the route's App Shell. The work can run during a per-link prefetch or navigation, while the fallback of the nearest <Suspense> boundary renders in the shell.

prefetch()는 원래라면 App Shell이 render했을 콘텐츠 중 생성 비용이 큰 콘텐츠에 사용하세요. static prerender는 여전히 output에 그 콘텐츠를 포함합니다.

Use prefetch() for content that the App Shell would otherwise render but that is expensive to generate. Static prerenders still include the content in their output.

Usage사용법

이 함수는 Cache Components가 필요하며, 활성화되어 있지 않으면 error를 throw합니다. Partial Prefetching이 없으면 route에 App Shell이 없으므로 이 함수는 아무 효과가 없습니다. Partial Prefetching은 전역으로 활성화하거나, Partial Prefetching 도입하기 방식으로 route 하나씩 활성화하세요.

The function requires Cache Components and throws an error if not enabled. Without Partial Prefetching a route has no App Shell, so the function has no effect. Enable Partial Prefetching globally, or one route at a time, by adopting Partial Prefetching.

TSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}

export default nextConfig

Partial Prefetching이 활성화되어 있으면, Next.js는 client navigation 전과 도중에 server-rendered output을 단계적으로 load합니다. 이것이 route의 navigation stage입니다:

With Partial Prefetching enabled, Next.js loads server-rendered output in stages, before and during a client navigation. These are the route's navigation stages:

  1. 기본 <Link>는 App Shell을 load합니다. App Shell에는 route 중 URL에 의존하지 않는 부분이 들어 있습니다.
  2. 선택적으로 <Link prefetch={true}>나 router.prefetch(href, { kind: 'full' })를 사용하면 link의 URL에 의존하는 콘텐츠도 load할 수 있습니다.
  3. 사용자가 link를 따라가면 navigation이 route의 나머지 부분을 render합니다.
  1. A default <Link> loads the App Shell, which holds the part of the route that does not depend on the URL.
  2. An optional <Link prefetch={true}>, or router.prefetch(href, { kind: 'full' }), can also load content that depends on the link's URL.
  3. When the user follows the link, the navigation renders the rest of the route.

runtime rendering 중에 prefetch()를 await하면 콘텐츠가 App Shell에서 제외되어 link별 prefetch나 navigation 중에 render됩니다. static prerender에는 여전히 그 콘텐츠가 포함될 수 있습니다.

During runtime rendering, awaiting prefetch() keeps content out of the App Shell, so it renders during a per-link prefetch or navigation. Static prerenders can still include the content.

Partial Prefetching에서 kind: 'full' 없이 router.prefetch(href)를 호출하면 App Shell만 요청합니다. await prefetch() 아래의 콘텐츠는 render하지 않습니다.

Calling router.prefetch(href) without kind: 'full' requests only the App Shell under Partial Prefetching. It does not render content below await prefetch().

콘텐츠를 link별 prefetch에서도 제외해 navigation에서만 render되게 하려면 navigation()을 사용하세요.

To keep content out of per-link prefetches as well, so it renders only on the navigation, use navigation().

Good to know

prefetch()는 하나의 subtree를 미룹니다. route 전체에 걸쳐 static App Shell을 요구하려면 ensureStatic = 'shell'을 사용하세요. 실제 예시는 Keeping pages static을 참고하세요.

prefetch() defers one subtree. To require a static App Shell across the route, use ensureStatic = 'shell'. See Keeping pages static for a worked example.

prefetch() 위의 모든 것은 App Shell에서 render되고, 그 아래의 모든 것은 link별 prefetch나 navigation에서 render됩니다. 미루기(deferral)의 범위는 이를 await하는 component와 그 아래 tree로 한정되며, 형제 branch는 평소처럼 shell에서 render됩니다. 미룰 작업 위에 배치하고, component를 <Suspense>로 감싸세요:

Everything above prefetch() renders in the App Shell, and everything below renders on a per-link prefetch or on the navigation. Deferral is scoped to the component that awaits it and the tree below: sibling branches render in the shell as usual. Place it above the work to defer, and wrap the component in <Suspense>:

TSJSapp/dashboard/page.tsx
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { cacheLife, prefetch } from 'next/cache'

export default function Page() {
  return (
    <>
      <Suspense fallback={<p>Loading greeting...</p>}>
        <Greeting /> {/* in the App Shell */}
      </Suspense>
      <Suspense fallback={<p>Loading recommendations...</p>}>
        {/* the fallback is in the App Shell, the recommendations are not */}
        <Recommendations />
      </Suspense>
    </>
  )
}

async function Greeting() {
  const session = (await cookies()).get('session')?.value
  return <p>{session ? 'Welcome back' : 'Welcome'}</p>
}

async function Recommendations() {
  await prefetch() // runtime work below renders on a per-link prefetch or navigation
  const items = await getRecommendations()
  return <List items={items} />
}

async function getRecommendations() {
  'use cache: private'
  cacheLife('hours')
  const session = (await cookies()).get('session')?.value
  return db.recommendations.rank({ session })
}

  return <p>{session ? 'Welcome back' : 'Welcome'}</p>

  await prefetch() // runtime work below renders on a per-link prefetch or navigation
  const items = await getRecommendations()
  return <List items={items} />
}

async function getRecommendations() {
  'use cache: private'
  cacheLife('hours')
  const session = (await cookies()).get('session')?.value
  return db.recommendations.rank({ session })
}

인사말(greeting)은 session을 읽고 App Shell에 남습니다. 추천 목록(recommendations)도 getRecommendations 안에서 session을 읽으므로, 그 읽기는 ranking과 함께 미뤄집니다. prefetch()를 제거하면 이들은 route로 들어가는 모든 link가 load하는 App Shell의 일부가 됩니다.

The greeting reads the session and stays in the App Shell. The recommendations read it too, inside getRecommendations, so that read is deferred along with the ranking. Remove prefetch() and they become part of the App Shell that every link into the route loads.

여기서 getRecommendations처럼 directive는 그 아래에서 호출되는 함수에 붙이세요. use cache나 use cache: private 같은 cache된 scope 안에서 prefetch()를 await하는 것은 허용되지 않습니다.

Put the directive on a function called below it, as getRecommendations does here. Awaiting prefetch() inside a cached scope, such as use cache or use cache: private, is not allowed.

How prefetch() differs from connection()prefetch()와 connection()의 차이

connection() 함수는 실제 request를 기다립니다. 뒤이은 코드를 prerendering과 prefetching에서 제외해, 그 작업을 request에 의존하게 만듭니다.

The connection() function waits for a real request. It excludes the code that follows from prerendering and prefetching, making that work request-dependent.

prefetch()를 await하면 뒤이은 코드가 App Shell에서 제외됩니다. 이는 그 작업을 request에 의존하게 만들지 않고 link별 prefetch 중에 resolve될 수 있습니다. 따라서 await prefetch() 뒤에 호출된 함수는 "use cache"를 사용해 cache lifetime을 유지하면서도, route로 들어가는 모든 link마다 결과를 생성하지 않을 수 있습니다.

Awaiting prefetch() excludes the code that follows from the App Shell. It can resolve during a per-link prefetch without making that work request-dependent. A function called after await prefetch() can therefore use "use cache" and keep its cache lifetime without generating its result for every link into the route.

작업이 실제 request에서 실행되어야 한다면 connection()을 사용하세요. 작업이 재사용 가능하지만 선택된 link별 prefetch나 navigation에서만 실행되어야 한다면 prefetch()를 사용하세요.

Use connection() when the work must run for a real request. Use prefetch() when the work is reusable but should only run for a selected per-link prefetch or a navigation.

When to use it언제 사용하나요

그 아래의 콘텐츠가 생성 비용이 크고, route로 들어가는 모든 <Link>가 load하는 App Shell에서 생성되어서는 안 될 때 prefetch()를 사용하세요.

Use prefetch() when the content below it is expensive to produce and should not be generated in the App Shell that every <Link> into the route loads.

App Shell을 생성할 때는 그 코드가 실행되지 않으므로, 해당 upstream request는 link별 prefetch나 navigation 전까지 발생하지 않습니다.

Producing the App Shell does not run that code, so its upstream requests are not issued until a per-link prefetch or the navigation.

콘텐츠를 cache하지 않은 채 두어도 shell에서 제외되지만, 그 대신 cache lifetime을 포기하게 되고 link별 prefetch 중에 콘텐츠를 사용할 수 있게 만들 수도 없습니다. prefetch()를 사용하면 콘텐츠를 use cache나 use cache: private로 cache하고, lifetime을 지정하고, link별 prefetch나 navigation까지 미룰 수 있습니다.

Leaving content uncached also keeps it out of the shell, but gives up its cache lifetime and cannot make it available during a per-link prefetch. With prefetch(), the content can be cached with use cache or use cache: private, given a lifetime, and deferred to a per-link prefetch or navigation.

cache되지 않은 읽기, stale 시간이 짧은 값, 그리고 params나 searchParams 뒤에 있는 모든 것은 이미 그 자체로 shell에서 제외됩니다.

Uncached reads, values with a short stale time, and anything behind params or searchParams are already left out of the shell on their own.

Keeping the App Shell staticApp Shell을 static으로 유지하기

cookies()와 headers()를 읽는 모든 코드가 prefetch() 아래에 있으면, shell prefetch가 trigger할 prerender는 build가 이미 생성한 static output 이상을 만들어 낼 수 없으므로, shell은 대신 그 output에서 제공됩니다. route를 이렇게 구성하는 것은 선택적인 최적화입니다: static response는 CDN에 cache될 수 있으므로, route로 들어가는 기본 <Link>에 server CPU 비용이 전혀 들지 않습니다. params나 searchParams를 resolve하는 route는 대신 그 prerender를 거치며, 위의 예시도 마찬가지입니다: 인사말이 shell에서 session을 읽으므로 shell은 방문자마다 한 번씩 render되고, 추천 목록만 미뤄집니다.

When every read of cookies() and headers() sits below prefetch(), the prerender a shell prefetch would trigger cannot produce more than the static output the build already generated, so the shell is served from that output instead. Shaping a route this way is an optional optimization: a static response can be cached in a CDN, so a default <Link> into the route costs no server CPU at all. A route that resolves params or searchParams gets that prerender instead, and so does the example above: its greeting reads the session in the shell, so the shell renders once per visitor and only the recommendations are deferred.

Good to know알아 두면 좋은 점

  • 이 함수는 page의 initial load에는 아무 영향도 주지 않습니다.
  • connection()과 달리, subtree를 request에 의존하는 것으로 표시하지 않습니다. await prefetch() 아래의 콘텐츠는 완전히 cache 가능한 상태로 남으며 use cache로 감쌀 수 있습니다.
  • <Suspense> boundary 밖에서 호출하면 development에서 Instant Insight가 표시됩니다. 완전히 prerender된 route에는 영향이 없지만, 이 insight는 나중에 route에 runtime rendering이 필요해지면 해당 호출이 fallback 없이 콘텐츠를 미루게 된다는 점을 알려 줍니다.
  • use cache, use cache: private, unstable_cache(), after(), generateStaticParams, 또는 Client Component 안에서 호출하면 throw합니다.
  • prefetch route segment config를 설정한 page나 layout에서는 둘 다 이름이 prefetch이므로, import { prefetch as prefetchStage } from 'next/cache'처럼 함수를 다른 이름으로 import하세요.
  • The function has no effect on the initial load of a page.
  • Unlike connection(), it does not mark the subtree as request-dependent. Content below await prefetch() stays fully cacheable and can be wrapped in use cache.
  • A call outside a <Suspense> boundary surfaces an Instant Insight in development. A fully prerendered route is unaffected, but the insight identifies that the call would defer content without a fallback if the route later requires runtime rendering.
  • Calling it inside use cache, use cache: private, unstable_cache(), after(), generateStaticParams, or a Client Component throws.
  • In a page or layout that sets the prefetch route segment config, import the function under another name, for example import { prefetch as prefetchStage } from 'next/cache', since both are named prefetch.
