getServerSidePropsgetServerSideProps

getServerSideProps는 request time에 data를 fetch하고 page 내용을 render하는 데 사용할 수 있는 Next.js 함수입니다.

getServerSideProps is a Next.js function that can be used to fetch data and render the contents of a page at request time.

Example예제

getServerSideProps는 Page Component에서 export해서 사용할 수 있습니다. 아래 예제는 getServerSideProps에서 3rd party API로부터 data를 fetch하고, 그 data를 props로 page에 전달하는 방법을 보여 줍니다:

You can use getServerSideProps by exporting it from a Page Component. The example below shows how you can fetch data from a 3rd party API in getServerSideProps, and pass the data to the page as props:

TSJSpages/index.tsx
import type { InferGetServerSidePropsType, GetServerSideProps } from 'next'

type Repo = {
  name: string
  stargazers_count: number
}

export const getServerSideProps = (async () => {
  // Fetch data from external API
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo: Repo = await res.json()
  // Pass data to the page via props
  return { props: { repo } }
}) satisfies GetServerSideProps<{ repo: Repo }>

export default function Page({
  repo,
}: InferGetServerSidePropsType<typeof getServerSideProps>) {
  return (
    <main>
      <p>{repo.stargazers_count}</p>
    </main>
  )
}
export async function getServerSideProps() {
  // Fetch data from external API
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo = await res.json()
  // Pass data to the page via props
  return { props: { repo } }
}

export default function Page({ repo }) {
  return (
    <main>
      <p>{repo.stargazers_count}</p>
    </main>
  )
}

When should I use getServerSideProps?getServerSideProps는 언제 사용해야 하나요?

개인화된 사용자 data나 request time에만 알 수 있는 정보에 의존하는 page를 render해야 한다면 getServerSideProps를 사용해야 합니다. 예를 들어 authorization header나 geolocation 같은 정보입니다.

You should use getServerSideProps if you need to render a page that relies on personalized user data, or information that can only be known at request time. For example, authorization headers or a geolocation.

request time에 data를 fetch할 필요가 없거나, data와 prerender된 HTML을 cache하고 싶다면 getStaticProps 사용을 권장합니다.

If you do not need to fetch the data at request time, or would prefer to cache the data and prerendered HTML, we recommend using getStaticProps.

Behavior동작

  • getServerSideProps는 server에서 실행됩니다.
  • getServerSideProps는 page에서만 export할 수 있습니다.
  • getServerSideProps는 JSON을 반환합니다.
  • 사용자가 page를 방문하면 getServerSideProps가 request time에 data를 fetch하는 데 사용되고, 그 data로 page의 initial HTML을 render합니다.
  • page component로 전달된 props는 initial HTML의 일부로 client에서 볼 수 있습니다. 이는 page가 올바르게 hydrate될 수 있도록 하기 위함입니다. client에 노출되면 안 되는 민감한 정보를 props로 전달하지 않도록 주의하세요.
  • 사용자가 next/link나 next/router를 통해 page를 방문하면, Next.js는 server에 API request를 보내고 server는 getServerSideProps를 실행합니다.
  • getServerSideProps를 사용할 때는 함수가 server에서 실행되므로 data를 fetch하기 위해 Next.js API Route를 호출할 필요가 없습니다. 대신 getServerSideProps 안에서 CMS, database 또는 다른 third-party API를 직접 호출할 수 있습니다.
  • getServerSideProps runs on the server.
  • getServerSideProps can only be exported from a page.
  • getServerSideProps returns JSON.
  • When a user visits a page, getServerSideProps will be used to fetch data at request time, and the data is used to render the initial HTML of the page.
  • props passed to the page component can be viewed on the client as part of the initial HTML. This is to allow the page to be hydrated correctly. Make sure that you don't pass any sensitive information that shouldn't be available on the client in props.
  • When a user visits the page through next/link or next/router, Next.js sends an API request to the server, which runs getServerSideProps.
  • You do not have to call a Next.js API Route to fetch data when using getServerSideProps since the function runs on the server. Instead, you can call a CMS, database, or other third-party APIs directly from inside getServerSideProps.
Good to know
  • getServerSideProps와 함께 사용할 수 있는 parameter와 props는 getServerSideProps API reference를 참고하세요.
  • Next.js가 client-side bundle에서 무엇을 제거하는지 확인하려면 next-code-elimination tool을 사용할 수 있습니다.
  • See getServerSideProps API reference for parameters and props that can be used with getServerSideProps.
  • You can use the next-code-elimination tool to verify what Next.js eliminates from the client-side bundle.

Error Handling에러 처리

getServerSideProps 안에서 error가 throw되면 pages/500.js 파일이 표시됩니다. 이 파일을 만드는 방법은 500 page 문서를 참고하세요. development 중에는 이 파일이 사용되지 않고 대신 development error overlay가 표시됩니다.

If an error is thrown inside getServerSideProps, it will show the pages/500.js file. Check out the documentation for 500 page to learn more on how to create it. During development, this file will not be used and the development error overlay will be shown instead.

Edge Cases엣지 케이스

Caching with Server-Side Rendering (SSR)Server-Side Rendering(SSR)에서 caching하기

getServerSideProps 안에서 caching header(Cache-Control)를 사용해 dynamic response를 cache할 수 있습니다. 예를 들어 stale-while-revalidate를 사용할 수 있습니다.

You can use caching headers (Cache-Control) inside getServerSideProps to cache dynamic responses. For example, using stale-while-revalidate.

// This value is considered fresh for ten seconds (s-maxage=10).
// If a request is repeated within the next 10 seconds, the previously
// cached value will still be fresh. If the request is repeated before 59 seconds,
// the cached value will be stale but still render (stale-while-revalidate=59).
//
// In the background, a revalidation request will be made to populate the cache
// with a fresh value. If you refresh the page, you will see the new value.
export async function getServerSideProps({ req, res }) {
  res.setHeader(
    'Cache-Control',
    'public, s-maxage=10, stale-while-revalidate=59'
  )

  return {
    props: {},
  }
}

하지만 cache-control을 사용하기 전에, ISR과 함께 getStaticProps를 사용하는 것이 여러분의 use case에 더 적합한지 먼저 확인해 보길 권장합니다.

However, before reaching for cache-control, we recommend seeing if getStaticProps with ISR is a better fit for your use case.
