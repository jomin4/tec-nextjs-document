navigationnavigation

await navigation()을 호출하면 그 아래의 runtime 작업이 App Shell과 link별 prefetch에서 제외됩니다. 그 작업은 사용자가 navigate할 때 실행되고, prefetch된 output에는 가장 가까운 <Suspense> boundary의 fallback이 render됩니다.

Calling await navigation() keeps runtime work below it out of the App Shell and per-link prefetches. The work runs when the user navigates, while the fallback of the nearest <Suspense> boundary renders in the prefetched output.

navigation()은 생성 비용이 크고 navigation까지 기다려야 하는 재사용 가능한 콘텐츠에 사용하세요. static prerender는 여전히 output에 그 콘텐츠를 포함하므로, static prefetch에는 나타날 수 있습니다.

Use navigation() for reusable content that is expensive to generate and should wait until navigation. Static prerenders still include the content in their output, so it can appear in a static prefetch.

Usage사용법

이 함수는 Cache Components가 필요하며, 없으면 throw합니다. Partial Prefetching을 사용하는 route를 위한 함수이며, Partial Prefetching은 전역으로 활성화하거나 Partial Prefetching 도입하기 방식으로 route 하나씩 활성화할 수 있습니다.

The function requires Cache Components, and throws without it. It is meant for routes using Partial Prefetching, which you can enable globally or one route at a time by adopting Partial Prefetching.

TSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}

export default nextConfig

Partial Prefetching이 활성화되어 있으면, Next.js는 client navigation 전과 도중에 server-rendered output을 단계적으로 load합니다. 이것이 route의 navigation stage입니다:

With Partial Prefetching enabled, Next.js loads server-rendered output in stages, before and during a client navigation. These are the route's navigation stages:

  1. 기본 <Link>는 App Shell을 load합니다. App Shell에는 route 중 URL에 의존하지 않는 부분이 들어 있습니다.
  2. 선택적으로 <Link prefetch={true}>를 사용하면 link의 URL에 의존하는 콘텐츠도 load할 수 있습니다.
  3. 사용자가 link를 따라가면 navigation이 route의 나머지 부분을 render합니다.
  1. A default <Link> loads the App Shell, which holds the part of the route that does not depend on the URL.
  2. An optional <Link prefetch={true}> can also load content that depends on the link's URL.
  3. When the user follows the link, the navigation renders the rest of the route.

runtime rendering 중에 navigation()을 await하면 콘텐츠가 App Shell과 link별 prefetch에서 제외되어 navigation 중에 render됩니다. static prerender에는 여전히 그 콘텐츠가 포함될 수 있습니다.

During runtime rendering, awaiting navigation() keeps content out of the App Shell and per-link prefetches, so it renders during navigation. Static prerenders can still include the content.

Partial Prefetching이 없어도 navigation()은 기본 <Link>에 대해서는 여전히 콘텐츠를 미루지만, <Link prefetch={true}>는 navigation과 마찬가지로 미뤄진 콘텐츠까지 포함한 route 전체를 fetch합니다.

Without Partial Prefetching, navigation() still defers the content for a default <Link>, but <Link prefetch={true}> fetches the whole route, deferred content included, the same as a navigation.

콘텐츠를 App Shell에서는 제외하되 link별 prefetch에는 포함하려면 prefetch()를 사용하세요.

To keep content out of the App Shell while still including it in a per-link prefetch, use prefetch().

Good to know

navigation()은 하나의 subtree를 미룹니다. route 전체에 걸쳐 static App Shell과 static link별 prefetch를 요구하려면 ensureStatic = 'prefetch'를 사용하세요. 실제 예시는 Keeping pages static을 참고하세요.

navigation() defers one subtree. To require a static App Shell and static per-link prefetches across the route, use ensureStatic = 'prefetch'. See Keeping pages static for a worked example.

navigation() 위의 모든 것은 App Shell이나 link별 prefetch에서 render될 수 있고, 그 아래의 모든 것은 navigation을 기다립니다. 미루기(deferral)의 범위는 이를 await하는 component와 그 아래 tree로 한정되며, 형제 branch는 기존 동작을 유지합니다. 미룰 코드 위에 배치하고, component를 <Suspense>로 감싸세요:

Everything above navigation() can render in the App Shell or a per-link prefetch, while everything below waits for navigation. Deferral is scoped to the component that awaits it and the tree below: sibling branches keep their existing behavior. Place it above the code to defer, and wrap the component in <Suspense>:

TSJSapp/post/[slug]/page.tsx
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { cacheLife, navigation } from 'next/cache'

export default function Page({ params }: PageProps<'/post/[slug]'>) {
  return (
    <>
      <Suspense fallback={<p>Loading post...</p>}>
        <PostBody params={params} /> {/* in a per-link prefetch */}
      </Suspense>
      <Suspense fallback={<p>Loading comments...</p>}>
        {/* the fallback is in the prefetch, the comments are not */}
        <Comments params={params} />
      </Suspense>
    </>
  )
}

async function Comments({ params }: { params: Promise<{ slug: string }> }) {
  await navigation() // runtime work below renders on navigation
  const { slug } = await params
  const sort = (await cookies()).get('comment-sort')?.value ?? 'newest'
  const items = await getComments(slug, sort)
  return <CommentList items={items} />
}

async function getComments(slug: string, sort: string) {
  'use cache'
  cacheLife('hours')
  return db.comments.list({ slug, sort })
}

async function Comments({ params }) {

  const { slug } = await params
  const sort = (await cookies()).get('comment-sort')?.value ?? 'newest'
  const items = await getComments(slug, sort)
  return <CommentList items={items} />
}

async function getComments(slug, sort) {
  'use cache'
  cacheLife('hours')
  return db.comments.list({ slug, sort })
}

comment는 slug로 fetch되므로, 이를 prefetch하려면 link별 prefetch가 필요합니다. 그 데이터 접근 전에 navigation()을 await하면 comment가 prefetch에서 제외되어 사용자가 navigate할 때 render됩니다.

Comments are fetched by slug, so prefetching them would take a per-link prefetch. Awaiting navigation() before that data access keeps them out of the prefetch, so they render when the user navigates.

slug와 cookie는 모두 navigation() 아래에서 읽혀 인자로 전달되므로, getComments는 방문자별이 아니라 post와 정렬 순서별로 cache됩니다. 미뤄진 콘텐츠가 render될 시점에는 URL이 resolve되어 있으므로 navigation() 아래에서 params를 사용할 수 있습니다.

The slug and the cookie are both read below navigation() and passed as arguments, so getComments caches per post and sort order rather than per visitor. The URL is resolved by the time the deferred content renders, so params is available below navigation().

여기서 getComments처럼 directive는 그 아래에서 호출되는 함수에 붙이세요. use cache나 use cache: private 같은 cache된 scope 안에서 navigation()을 await하는 것은 허용되지 않습니다.

Put the directive on a function called below it, as getComments does here. Awaiting navigation() inside a cached scope, such as use cache or use cache: private, is not allowed.

How navigation() differs from connection()navigation()과 connection()의 차이

connection() 함수는 실제 request를 기다립니다. 뒤이은 코드를 prerendering과 prefetching에서 제외해, 그 작업을 request에 의존하게 만듭니다.

The connection() function waits for a real request. It excludes the code that follows from prerendering and prefetching, making that work request-dependent.

navigation()을 await하면 뒤이은 코드가 route prefetch에서 제외됩니다. 이는 그 작업을 request에 의존하게 만들지 않고, 사용자가 navigate할 때 resolve됩니다. 따라서 await navigation() 뒤에 호출된 함수는 "use cache"를 사용해 cache lifetime을 유지하면서도 prefetching 중에는 결과를 생성하지 않을 수 있습니다.

Awaiting navigation() excludes the code that follows from route prefetches. It resolves when the user navigates without making that work request-dependent. A function called after await navigation() can therefore use "use cache" and keep its cache lifetime without generating its result during prefetching.

작업이 실제 request에서 실행되어야 한다면 connection()을 사용하세요. 작업이 재사용 가능하지만 사용자가 navigate할 때까지 기다려야 한다면 navigation()을 사용하세요.

Use connection() when the work must run for a real request. Use navigation() when the work is reusable but should wait until the user navigates.

When to use it언제 사용하나요

그 아래의 콘텐츠가 생성 비용이 크고 어떤 prefetch도 그것을 생성해서는 안 될 때 navigation()을 사용하세요.

Use navigation() when the content below it is expensive to produce and no prefetch should generate it.

runtime App Shell도, runtime link별 prefetch도 그 코드를 실행하지 않으므로, 해당 upstream request는 사용자가 navigate할 때까지 발생하지 않습니다.

Neither the runtime App Shell nor a runtime per-link prefetch runs that code, so its upstream requests are not issued until the user navigates.

콘텐츠를 cache하지 않은 채 두어도 prefetch에서 제외되지만, 그 대신 cache lifetime을 포기하게 됩니다.

Leaving content uncached also keeps it out of prefetches, but gives up its cache lifetime.

navigation()을 사용하면 콘텐츠를 use cache로 cache하고, lifetime을 지정하고, navigation까지 미룰 수 있습니다. stale 시간을 5분 이상으로 주면, 사용자가 처음 route에 navigate한 이후로는 client-side router가 이를 재사용합니다. 그보다 짧으면 짧은 lifetime 때문에 App Shell에서 제외되므로, navigation할 때마다 다시 fetch합니다.

With navigation() the content can be cached with use cache, given a lifetime, and deferred to the navigation. Give it a stale time of five minutes or more and the client-side router reuses it after the first time a user navigates into the route. Below that, a short lifetime keeps it out of the App Shell, so each navigation fetches it again.

Keeping a route's prefetch staticroute의 prefetch를 static으로 유지하기

cookies(), headers(), params, searchParams를 읽는 모든 코드가 navigation() 아래에 있으면, prefetch가 trigger할 prerender는 build가 이미 생성한 static output 이상을 만들어 낼 수 없으므로, prefetch는 대신 그 output에서 제공됩니다. route를 이렇게 구성하는 것은 선택적인 최적화입니다: static response는 CDN에 cache될 수 있으므로, route로 들어가는 link에 server CPU 비용이 전혀 들지 않습니다.

When every read of cookies(), headers(), params, and searchParams sits below navigation(), the prerender a prefetch would trigger cannot produce more than the static output the build already generated, so the prefetch is served from that output instead. Shaping a route this way is an optional optimization: a static response can be cached in a CDN, so a link into the route costs no server CPU at all.

TSapp/feed/page.tsx
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { navigation } from 'next/cache'

export default function Page() {
  return (
    <>
      <FeedHeader /> {/* static, and so is the whole prefetch */}
      <Suspense fallback={<p>Loading stories...</p>}>
        <Stories />
      </Suspense>
    </>
  )
}

async function Stories() {
  await navigation()
  const topic = (await cookies()).get('topic')?.value ?? 'all'
  return <StoryList items={await getStories(topic)} />
}

Good to know알아 두면 좋은 점

  • 이 함수는 page의 initial load에는 아무 영향도 주지 않습니다.
  • navigation() 아래에서 cookies()나 headers()를 읽어도 route의 prefetch가 request별로 render되지 않으므로, 여전히 static output에서 제공될 수 있습니다. 그런 접근은 무시되는데, prefetch에서도 어차피 resolve되지 않았을 것이기 때문입니다.
  • <Suspense> boundary 밖에서 호출하면 development에서 Instant Insight가 표시됩니다. 완전히 prerender된 route에는 영향이 없지만, 이 insight는 나중에 route에 runtime rendering이 필요해지면 해당 호출이 fallback 없이 콘텐츠를 미루게 된다는 점을 알려 줍니다.
  • use cache, use cache: private, unstable_cache(), after(), generateStaticParams, 또는 Client Component 안에서 호출하면 throw합니다.
  • The function has no effect on the initial load of a page.
  • Reading cookies() or headers() below navigation() does not make the route's prefetches render per request, so they can still be served from static output. Those accesses are ignored, because they would not have resolved in a prefetch either.
  • A call outside a <Suspense> boundary surfaces an Instant Insight in development. A fully prerendered route is unaffected, but the insight identifies that the call would defer content without a fallback if the route later requires runtime rendering.
  • Calling it inside use cache, use cache: private, unstable_cache(), after(), generateStaticParams, or a Client Component throws.
