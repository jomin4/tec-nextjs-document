How to deploy your Next.js application배포

Next.js는 Node.js server, Docker container, static export로 deploy하거나, 여러 platform에서 실행되도록 adapt할 수 있습니다.

Next.js can be deployed as a Node.js server, Docker container, static export, or adapted to run on different platforms.

Node.js server

Next.js는 Node.js를 지원하는 모든 provider에 deploy할 수 있습니다. package.json에 "build"와 "start" script가 있는지 확인하세요:

Next.js can be deployed to any provider that supports Node.js. Ensure your package.json has the "build" and "start" scripts:

package.json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start"
  }
}

그런 다음 npm run build를 실행해 애플리케이션을 build하고, npm run start로 Node.js server를 시작하세요. 이 server는 모든 Next.js 기능을 지원합니다. 필요하다면 custom server로 eject할 수도 있습니다.

Then, run npm run build to build your application and npm run start to start the Node.js server. This server supports all Next.js features. If needed, you can also eject to a custom server.

Node.js deployment는 모든 Next.js 기능을 지원합니다. 인프라에 맞게 설정하는 방법을 알아보세요.

Node.js deployments support all Next.js features. Learn how to configure them for your infrastructure.

Docker

Next.js는 Docker container를 지원하는 모든 provider에 deploy할 수 있습니다. 여기에는 Kubernetes 같은 container orchestrator나 Docker를 실행하는 cloud provider가 포함됩니다. 앱을 containerize하는 best practice는 Docker 공식 Next.js 및 React.js 가이드를 참고하세요.

Next.js can be deployed to any provider that supports Docker containers. This includes container orchestrators like Kubernetes or a cloud provider that runs Docker. For best practices on containerizing your app, refer to Docker's official Next.js and React.js guides.

Docker deployment는 모든 Next.js 기능을 지원합니다. 인프라에 맞게 설정하는 방법을 알아보세요.

Docker deployments support all Next.js features. Learn how to configure them for your infrastructure.

Note for development

Docker는 production deployment에 아주 좋지만, Mac과 Windows에서 개발할 때는 더 나은 성능을 위해 Docker 대신 로컬 개발 환경(npm run dev)을 사용하는 것을 고려하세요. 로컬 개발 최적화에 대해 더 알아보기.

While Docker is excellent for production deployments, consider using local development (npm run dev) instead of Docker during development on Mac and Windows for better performance. Learn more about optimizing local development.

다음 예제들은 Next.js 애플리케이션을 containerize하는 best practice를 보여 줍니다:

The following examples demonstrate best practices for containerizing Next.js applications:

  • Docker Standalone Output - output: "standalone"을 사용해 필요한 runtime 파일과 dependency만 담은 최소한의 production-ready Docker image를 생성하여 Next.js 애플리케이션을 deploy합니다.
  • Docker Export Output - output: "export"를 사용해 가벼운 container나 어떤 static hosting 환경에서도 제공할 수 있는 최적화된 HTML 파일을 생성하여 완전히 static한 Next.js 애플리케이션을 deploy합니다.
  • Docker Multi-Environment - 서로 다른 environment variable을 사용하는 development, staging, production 환경별로 Docker configuration을 따로 관리합니다.
  • Docker Standalone Output - Deploy a Next.js application using output: "standalone" to generate a minimal, production-ready Docker image with only the required runtime files and dependencies.
  • Docker Export Output - Deploy a fully static Next.js application using output: "export" to generate optimized HTML files that can be served from a lightweight container or any static hosting environment.
  • Docker Multi-Environment - Manage separate Docker configurations for development, staging, and production environments with different environment variables.

Static export

Next.js는 static site나 Single-Page Application (SPA)로 시작한 뒤, 나중에 필요하면 server가 필요한 기능을 사용하도록 upgrade할 수 있습니다.

Next.js enables starting as a static site or Single-Page Application (SPA), then later optionally upgrading to use features that require a server.

Next.js는 static export를 지원하므로 HTML/CSS/JS static asset을 제공할 수 있는 어떤 web server에도 deploy하고 hosting할 수 있습니다. 여기에는 AWS S3, Nginx, Apache 같은 도구가 포함됩니다.

Since Next.js supports static exports, it can be deployed and hosted on any web server that can serve HTML/CSS/JS static assets. This includes tools like AWS S3, Nginx, or Apache.

static export로 실행하면 server가 필요한 Next.js 기능은 지원되지 않습니다. 더 알아보기.

Running as a static export does not support Next.js features that require a server. Learn more.

Adapters

Next.js는 여러 platform의 인프라 기능을 지원하도록 해당 platform에서 실행되게 adapt할 수 있습니다. Deployment Adapter API를 사용하면 platform이 Next.js 애플리케이션의 build 및 deploy 방식을 customize할 수 있습니다.

Next.js can be adapted to run on different platforms to support their infrastructure capabilities. The Deployment Adapter API lets platforms customize how Next.js applications are built and deployed.

Verified Adapters

Verified adapter는 open source이며, 전체 Next.js compatibility test suite를 실행하고, Next.js GitHub organization 아래에서 hosting됩니다. Next.js 팀은 major release 전에 이 platform들과 함께 test를 조율합니다. 각 adapter의 공개 test 결과도 곧 제공될 예정입니다. verified adapter에 대해 더 알아보기.

Verified adapters are open source, run the full Next.js compatibility test suite, and are hosted under the Next.js GitHub organization. The Next.js team coordinates testing with these platforms before major releases. Publicly visible test results for each adapter are coming soon. Learn more about verified adapters.

  • Vercel
  • Bun
  • Vercel
  • Bun

Cloudflare와 Netlify는 Adapter API 기반의 verified adapter를 개발하고 있습니다. 그동안에는 각자의 Next.js integration을 제공합니다(아래 참고).

Cloudflare and Netlify are working on verified adapters built on the Adapter API. In the meantime, they offer their own Next.js integrations (see below).

Other Platforms기타 Platform

다음 platform들은 자체 Next.js integration을 제공합니다. 이들은 공개 Adapter API 기반이 아니고 Next.js 팀의 검증을 받지 않았으므로 기능 지원과 호환성이 다를 수 있습니다. 자세한 내용은 각 provider의 문서를 참고하세요:

The following platforms offer their own Next.js integrations. These are not built on the public Adapter API and are not verified by the Next.js team, so feature support and compatibility may vary. Refer to each provider's documentation for details:

  • Appwrite Sites
  • AWS Amplify Hosting
  • Cloudflare
  • Deno Deploy
  • Firebase App Hosting
  • Netlify
  • Appwrite Sites
  • AWS Amplify Hosting
  • Cloudflare
  • Deno Deploy

어떤 Next.js 기능에 특정 platform 기능이 필요한지에 대한 자세한 내용은 Deploying to Platforms를 참고하세요.

For details on which Next.js features require specific platform capabilities, see Deploying to Platforms.
