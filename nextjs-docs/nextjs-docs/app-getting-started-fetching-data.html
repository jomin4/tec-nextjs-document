Fetching Data데이터 가져오기

이 페이지에서는 Server Component와 Client Component에서 데이터를 fetch하는 방법, 그리고 cache되지 않은 데이터에 의존하는 component를 stream하는 방법을 안내합니다.

This page will walk you through how you can fetch data in Server and Client Components, and how to stream components that depend on uncached data.

Fetching data데이터 가져오기

Server Components

Server Component에서는 다음과 같은 모든 비동기 I/O로 데이터를 fetch할 수 있습니다:

You can fetch data in Server Components using any asynchronous I/O, such as:

  1. fetch API
  2. ORM 또는 database
  1. The fetch API
  2. An ORM or database

With the fetch APIfetch API 사용하기

fetch API로 데이터를 가져오려면 component를 비동기 함수로 바꾸고 fetch 호출을 await하세요. 예를 들면 다음과 같습니다:

To fetch data with the fetch API, turn your component into an asynchronous function, and await the fetch call. For example:

TSJSapp/blog/page.tsx
export default async function Page() {
  const data = await fetch('https://api.vercel.app/blog')
  const posts = await data.json()
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
export default async function Page() {
  const data = await fetch('https://api.vercel.app/blog')
  const posts = await data.json()
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
Good to know
  • React component tree 안에서 동일한 fetch request는 기본적으로 memoize되므로, props를 여러 단계로 내려보내는(drilling) 대신 데이터가 필요한 component에서 직접 fetch할 수 있습니다.
  • fetch request는 기본적으로 cache되지 않으며, request가 완료될 때까지 page rendering을 막습니다(block). 결과를 cache하려면 use cache directive를 사용하고, request 시점에 최신 데이터를 stream하려면 fetch하는 component를 <Suspense>로 감싸세요. 자세한 내용은 caching을 참고하세요.
  • 개발 중에는 fetch 호출을 log로 남겨 가시성을 높이고 디버깅에 활용할 수 있습니다. logging API reference를 참고하세요.
  • Identical fetch requests in a React component tree are memoized by default, so you can fetch data in the component that needs it instead of drilling props.
  • fetch requests are not cached by default and will block the page from rendering until the request is complete. Use the use cache directive to cache results, or wrap the fetching component in <Suspense> to stream fresh data at request time. See caching for details.
  • During development, you can log fetch calls for better visibility and debugging. See the logging API reference.

With an ORM or databaseORM 또는 database 사용하기

Server Component는 server에서 render되므로 credential과 query 로직이 client bundle에 포함되지 않습니다. 따라서 ORM이나 database client를 사용해 안전하게 database query를 실행할 수 있습니다.

Since Server Components are rendered on the server, credentials and query logic will not be included in the client bundle so you can safely make database queries using an ORM or database client.

TSJSapp/blog/page.tsx
import { db, posts } from '@/lib/db'

export default async function Page() {
  const allPosts = await db.select().from(posts)
  return (
    <ul>
      {allPosts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
import { db, posts } from '@/lib/db'

export default async function Page() {
  const allPosts = await db.select().from(posts)
  return (
    <ul>
      {allPosts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}

그래도 request가 제대로 authentication 및 authorization되었는지는 반드시 확인해야 합니다. server-side 데이터 접근을 안전하게 하는 best practice는 data security 가이드를 참고하세요.

You should still ensure requests are properly authenticated and authorized. For best practices on securing server-side data access, see the data security guide.

Streaming

Server Component에서 데이터를 fetch하면, 데이터는 request마다 server에서 fetch되고 render됩니다. 느린 data request가 하나라도 있으면 모든 데이터를 가져올 때까지 route 전체의 rendering이 막힙니다.

When you fetch data in Server Components, the data is fetched and rendered on the server for each request. If you have any slow data requests, the whole route will be blocked from rendering until all the data is fetched.

초기 로딩 시간과 사용자 경험을 개선하려면 page를 더 작은 chunk 로 나누고, 그 chunk들을 server에서 client로 점진적으로 보낼 수 있습니다. 이것을 streaming이라고 합니다. HTTP contract, 인프라 고려 사항, performance trade-off 등 streaming이 동작하는 방식을 더 깊이 알아보려면 Streaming 가이드를 참고하세요.

To improve the initial load time and user experience, you can break the page into smaller chunks and progressively send those chunks from the server to the client. This is called streaming. See the Streaming guide for a deeper look at how streaming works, including the HTTP contract, infrastructure considerations, and performance trade-offs.

애플리케이션에서 streaming을 사용하는 방법은 두 가지입니다:

There are two ways you can use streaming in your application:

  1. page를 loading.js 파일로 감싸기
  2. component를 <Suspense>로 감싸기
  1. Wrapping a page with a loading.js file
  2. Wrapping a component with <Suspense>
Good to know

bot과 crawler에는 브라우저와 다른 방식으로 응답합니다. Next.js는 점진적으로 stream하는 대신 data fetching이 끝날 때까지 기다렸다가 완전히 render된 page를 보냅니다. Bots and crawlers를 참고하세요.

Bots and crawlers are served differently from browsers. Next.js waits for data fetching to finish and sends the fully rendered page instead of streaming it progressively. See Bots and crawlers.

With loading.jsloading.js 사용하기

page와 같은 폴더에 loading.js 파일을 만들면, 데이터를 가져오는 동안 entire page 단위로 stream할 수 있습니다. 예를 들어 app/blog/page.js를 stream하려면 app/blog 폴더 안에 이 파일을 추가하세요.

You can create a loading.js file in the same folder as your page to stream the entire page while the data is being fetched. For example, to stream app/blog/page.js, add the file inside the app/blog folder.

TSJSapp/blog/loading.tsx
export default function Loading() {
  // Define the Loading UI here
  return <div>Loading...</div>
}
export default function Loading() {
  // Define the Loading UI here
  return <div>Loading...</div>
}

navigation 시 page가 render되는 동안 사용자는 layout과 loading state를 즉시 보게 됩니다. rendering이 끝나면 새 콘텐츠로 자동으로 교체됩니다.

On navigation, the user will immediately see the layout and a loading state while the page is being rendered. The new content will then be automatically swapped in once rendering is complete.

내부적으로 loading.js는 layout.js 안에 중첩되며, page.js 파일과 그 아래의 모든 children을 <Suspense> boundary로 자동으로 감쌉니다.

Behind the scenes, loading.js will be nested inside layout.js, and will automatically wrap the page.js file and any children below in a <Suspense> boundary.

이 때문에 cache되지 않은 데이터나 runtime 데이터(예: cookies(), headers(), cache되지 않은 fetch)에 접근하는 layout은 같은 route segment의 loading.js로 fallback되지 않습니다. 대신 layout rendering이 끝날 때까지 navigation을 막습니다. Cache Components는 build 시점 error로 이를 안내해 이런 상황을 방지합니다.

Because of this, a layout that accesses uncached or runtime data (e.g. cookies(), headers(), or uncached fetches) does not fall back to a same route segment loading.js. Instead, it blocks navigation until the layout finishes rendering. Cache Components prevents this by guiding you with a build-time error.

이를 해결하려면 cache되지 않은 접근을 fallback이 있는 별도의 <Suspense> boundary로 감싸거나, data fetching을 loading.js가 감쌀 수 있는 page.js로 옮기세요. 자세한 내용은 loading.js를 참고하세요.

To fix this, wrap the uncached access in its own <Suspense> boundary with a fallback, or move the data fetching into page.js where loading.js can cover it. See loading.js for more details.

그래서 loading.js가 route segment를 stream하는 데는 잘 동작하지만, runtime 데이터나 cache되지 않은 데이터에 접근하는 곳에 더 가깝게 <Suspense>를 사용하는 것을 권장합니다.

This is why, while loading.js works well for streaming route segments, using <Suspense> closer to the runtime or uncached data access is recommended.

With <Suspense><Suspense> 사용하기

<Suspense>를 사용하면 page의 어느 부분을 stream할지 더 세밀하게 정할 수 있습니다. 예를 들어 <Suspense> boundary 밖에 있는 page 콘텐츠는 즉시 보여 주고, boundary 안의 blog post 목록은 stream으로 받아올 수 있습니다.

<Suspense> allows you to be more granular about what parts of the page to stream. For example, you can immediately show any page content that falls outside of the <Suspense> boundary, and stream in the list of blog posts inside the boundary.

TSJSapp/blog/page.tsx
import { Suspense } from 'react'
import BlogList from '@/components/BlogList'
import BlogListSkeleton from '@/components/BlogListSkeleton'

export default function BlogPage() {
  return (
    <div>
      {/* This content will be sent to the client immediately */}
      <header>
        <h1>Welcome to the Blog</h1>
        <p>Read the latest posts below.</p>
      </header>
      <main>
        {/* If there's any dynamic content inside this boundary, it will be streamed in */}
        <Suspense fallback={<BlogListSkeleton />}>
          <BlogList />
        </Suspense>
      </main>
    </div>
  )
}
import { Suspense } from 'react'
import BlogList from '@/components/BlogList'
import BlogListSkeleton from '@/components/BlogListSkeleton'

          <BlogList />

  )
}

Creating meaningful loading states의미 있는 loading state 만들기

instant loading state는 navigation 직후 사용자에게 즉시 보여 주는 fallback UI입니다. 최상의 사용자 경험을 위해, 앱이 응답하고 있다는 것을 사용자가 이해할 수 있도록 의미 있는 loading state를 디자인하는 것을 권장합니다. 예를 들어 skeleton과 spinner를 사용하거나, cover 사진, 제목처럼 앞으로 나올 화면의 작지만 의미 있는 일부를 보여 줄 수 있습니다.

An instant loading state is fallback UI that is shown immediately to the user after navigation. For the best user experience, we recommend designing loading states that are meaningful and help users understand the app is responding. For example, you can use skeletons and spinners, or a small but meaningful part of future screens such as a cover photo, title, etc.

개발 중에는 React Devtools를 사용해 component의 loading state를 미리 보고 검사할 수 있습니다.

In development, you can preview and inspect the loading state of your components using the React Devtools.

Client Components

Client Component에서 데이터를 fetch하는 방법은 두 가지입니다:

There are two ways to fetch data in Client Components, using:

  1. React의 use API
  2. SWR이나 React Query 같은 community library
  1. React's use API
  2. A community library like SWR or React Query

Streaming data with the use APIuse API로 데이터 streaming하기

React의 use API를 사용해 server에서 client로 데이터를 stream할 수 있습니다. 먼저 Server component에서 데이터를 fetch하고, 그 promise를 Client Component에 prop으로 전달하세요:

You can use React's use API to stream data from the server to client. Start by fetching data in your Server component, and pass the promise to your Client Component as prop:

TSJSapp/blog/page.tsx
import Posts from '@/app/ui/posts'
import { Suspense } from 'react'

export default function Page() {
  // Don't await the data fetching function
  const posts = getPosts()

  return (
    <Suspense fallback={<div>Loading...</div>}>
      <Posts posts={posts} />
    </Suspense>
  )
}
import Posts from '@/app/ui/posts'
import { Suspense } from 'react'

export default function Page() {
  // Don't await the data fetching function
  const posts = getPosts()

  return (
    <Suspense fallback={<div>Loading...</div>}>
      <Posts posts={posts} />
    </Suspense>
  )
}

그런 다음 Client Component에서 use API로 promise를 읽습니다:

Then, in your Client Component, use the use API to read the promise:

TSJSapp/ui/posts.tsx
'use client'
import { use } from 'react'

export default function Posts({
  posts,
}: {
  posts: Promise<{ id: string; title: string }[]>
}) {
  const allPosts = use(posts)

  return (
    <ul>
      {allPosts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
'use client'
import { use } from 'react'

export default function Posts({ posts }) {
  const allPosts = use(posts)

  return (
    <ul>
      {allPosts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}

위 예제에서 <Posts> component는 <Suspense> boundary로 감싸져 있습니다. 즉, promise가 resolve되는 동안 fallback이 표시됩니다. streaming에 대해 더 알아보세요.

In the example above, the <Posts> component is wrapped in a <Suspense> boundary. This means the fallback will be shown while the promise is being resolved. Learn more about streaming.

promise는 server에서 await로 resolve하거나, Client Component에서 use()로 resolve할 수 있습니다. Server Component와 Client Component 중 어디에서 Promise를 resolve할지는 React 문서에서 다룹니다. 하나의 promise를 prop으로 전달하는 대신 여러 Client Component와 공유하려면 context를 통해 제공하세요. Using React's use within a Context Provider를 참고하세요.

You can resolve a promise on the server with await or in a Client Component with use(). React covers when to resolve a Promise in a Server or Client Component. To share one promise with many Client Components instead of passing it as a prop, provide it through context. See Using React's use within a Context Provider.

Community librariesCommunity library

SWR이나 React Query 같은 community library를 사용해 Client Component에서 데이터를 fetch할 수 있습니다. 이 library들은 caching, streaming 및 기타 기능에 대해 자체적인 semantics를 가지고 있습니다. 예를 들어 SWR을 사용하면 다음과 같습니다:

You can use a community library like SWR or React Query to fetch data in Client Components. These libraries have their own semantics for caching, streaming, and other features. For example, with SWR:

TSJSapp/blog/page.tsx
'use client'
import useSWR from 'swr'

const fetcher = (url) => fetch(url).then((r) => r.json())

export default function BlogPage() {
  const { data, error, isLoading } = useSWR(
    'https://api.vercel.app/blog',
    fetcher
  )

  if (isLoading) return <div>Loading...</div>
  if (error) return <div>Error: {error.message}</div>

  return (
    <ul>
      {data.map((post: { id: string; title: string }) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}

Examples예제

Sequential data fetching순차적 data fetching

순차적(sequential) data fetching은 한 request가 다른 request의 데이터에 의존할 때 발생합니다.

Sequential data fetching happens when one request depends on data from another.

예를 들어 <Playlists>는 artistID가 필요하기 때문에 getArtist()가 resolve된 후에야 데이터를 fetch할 수 있습니다:

For example, <Playlists> can only fetch data after getArtist() resolves because it needs the artistID:

TSJSapp/artist/[username]/page.tsx
export default async function Page({
  params,
}: {
  params: Promise<{ username: string }>
}) {
  const { username } = await params
  // Get artist information
  const artist = await getArtist(username)

  return (
    <>
      <h1>{artist.name}</h1>
      {/* Show fallback UI while the Playlists component is loading */}
      <Suspense fallback={<div>Loading...</div>}>
        {/* Pass the artist ID to the Playlists component */}
        <Playlists artistID={artist.id} />
      </Suspense>
    </>
  )
}

async function Playlists({ artistID }: { artistID: string }) {
  // Use the artist ID to fetch playlists
  const playlists = await getArtistPlaylists(artistID)

  return (
    <ul>

        <li key={playlist.id}>{playlist.name}</li>

이 예제에서 <Suspense>는 artist 데이터가 로드된 후 playlist가 stream되어 들어오게 해 줍니다. 하지만 page는 여전히 artist 데이터를 기다린 후에야 무언가를 표시합니다. 이를 방지하려면 page component 전체를 <Suspense> boundary로 감싸서(예: loading.js 파일 사용) loading state를 즉시 보여 줄 수 있습니다.

In this example, <Suspense> allows the playlists to stream in after the artist data loads. However, the page still waits for the artist data before displaying anything. To prevent this, you can wrap the entire page component in a <Suspense> boundary (for example, using a loading.js file) to show a loading state immediately.

첫 번째 request는 나머지 모든 것을 막으므로, data source가 이 request를 빠르게 resolve할 수 있도록 하세요. request를 더 이상 최적화할 수 없다면, 데이터가 자주 바뀌지 않는 경우 결과를 caching하는 것을 고려하세요.

Ensure your data source can resolve the first request quickly, as it blocks everything else. If you can't optimize the request further, consider caching the result if the data changes infrequently.

Parallel data fetching병렬 data fetching

병렬(parallel) data fetching은 route 안의 data request들이 미리(eagerly) 시작되어 동시에 진행될 때 발생합니다.

Parallel data fetching happens when data requests in a route are eagerly initiated and start at the same time.

기본적으로 layout과 page는 병렬로 render됩니다. 따라서 각 segment는 가능한 한 빨리 데이터를 fetch하기 시작합니다.

By default, layouts and pages are rendered in parallel. So each segment starts fetching data as soon as possible.

하지만 어떤 component 안에서든, 여러 async/await request를 차례로 배치하면 여전히 순차적으로 실행될 수 있습니다. 예를 들어 getAlbums는 getArtist가 resolve될 때까지 막힙니다:

However, within any component, multiple async/await requests can still be sequential if placed after the other. For example, getAlbums will be blocked until getArtist is resolved:

TSapp/artist/[username]/page.tsx
import { getArtist, getAlbums } from '@/app/lib/data'

export default async function Page({ params }) {
  // These requests will be sequential
  const { username } = await params
  const artist = await getArtist(username)
  const albums = await getAlbums(username)
  return <div>{artist.name}</div>
}

fetch를 호출해 여러 request를 시작한 다음, Promise.all로 await하세요. request는 fetch가 호출되는 즉시 시작됩니다.

Start multiple requests by calling fetch, then await them with Promise.all. Requests begin as soon as fetch is called.

TSJSapp/artist/[username]/page.tsx
import Albums from './albums'

async function getArtist(username: string) {
  const res = await fetch(`https://api.example.com/artist/${username}`)
  return res.json()
}

async function getAlbums(username: string) {
  const res = await fetch(`https://api.example.com/artist/${username}/albums`)
  return res.json()
}

export default async function Page({
  params,
}: {
  params: Promise<{ username: string }>
}) {
  const { username } = await params

  // Initiate requests
  const artistData = getArtist(username)
  const albumsData = getAlbums(username)

  const [artist, albums] = await Promise.all([artistData, albumsData])

  return (
    <>
      <h1>{artist.name}</h1>
      <Albums list={albums} />
    </>
  )
}
import Albums from './albums'

async function getArtist(username) {
  const res = await fetch(`https://api.example.com/artist/${username}`)
  return res.json()
}

async function getAlbums(username) {
  const res = await fetch(`https://api.example.com/artist/${username}/albums`)
  return res.json()
}

export default async function Page({ params }) {
  const { username } = await params

  // Initiate requests
  const artistData = getArtist(username)
  const albumsData = getAlbums(username)

  const [artist, albums] = await Promise.all([artistData, albumsData])

  return (
    <>
      <h1>{artist.name}</h1>
      <Albums list={albums} />
    </>
  )
}
Good to know

Promise.all을 사용할 때 request 하나가 실패하면 전체 작업이 실패합니다. 이를 처리하려면 대신 Promise.allSettled method를 사용할 수 있습니다.

If one request fails when using Promise.all, the entire operation will fail. To handle this, you can use the Promise.allSettled method instead.

Reusing data with React.cacheReact.cache로 데이터 재사용하기

ORM이나 database query처럼 fetch를 사용하지 않는 데이터 접근은 함수를 React.cache로 감싸세요. 그러면 여러 component가 같은 request 안에서 이 함수를 호출하면서 하나의 결과를 공유할 수 있습니다:

For data access that does not use fetch, such as an ORM or database query, wrap the function in React.cache. Multiple components can then call the function within the same request while sharing one result:

TSJSapp/lib/user.ts
import { cache } from 'react'
import { db, eq, users } from '@/lib/db'

export const getUser = cache(async (id: string) => {
  return db.query.users.findFirst({
    where: eq(users.id, id),
  })
})
import { cache } from 'react'
import { db, eq, users } from '@/lib/db'

export const getUser = cache(async (id) => {
  return db.query.users.findFirst({
    where: eq(users.id, id),
  })
})

Server Component는 getUser()를 직접 호출할 수 있습니다:

Server Components can call getUser() directly:

TSJSapp/dashboard/page.tsx
import { getUser } from '../lib/user'

export default async function DashboardPage() {
  const user = await getUser('1')

  if (!user) {
    return null
  }

  return <h1>Dashboard for {user.name}</h1>
}
import { getUser } from '../lib/user'

export default async function DashboardPage() {
  const user = await getUser('1')

  if (!user) {
    return null
  }

  return <h1>Dashboard for {user.name}</h1>
}

getUser가 React.cache로 감싸져 있으므로, 한 request 안에서 같은 id로 호출하면 memoize된 같은 결과가 반환됩니다.

Since getUser is wrapped with React.cache, calls with the same id within one request return the same memoized result.

Good to know

React.cache는 현재 request 범위로만 한정됩니다. 각 request는 자체 memoization 범위를 가지며, request 사이에서는 공유되지 않습니다.

React.cache is scoped to the current request only. Each request gets its own memoization scope with no sharing between requests.

Preloading data데이터 preload하기

component가 다른 blocking 작업 이후에 render되면, request 입력값이 이미 준비되어 있더라도 data request가 늦게 시작됩니다. preload는 request를 더 일찍 시작해 그 작업과 병렬로 실행되게 하여 request waterfall을 피합니다.

When a component renders after other blocking work, its data request starts late even if the request inputs are already available. Preloading starts the request earlier so it can run in parallel with that work and avoid a request waterfall.

데이터를 preload하려면 blocking 작업 전에 data-fetching 함수를 await 없이 호출하고, 결과를 사용하는 component에서 같은 함수를 다시 호출하세요.

To preload data, call the data-fetching function without await before blocking work, then call the same function in the component that consumes the result.

component가 preload 중에 시작된 request를 재사용할 수 있도록, data-fetching 함수는 일치하는 호출을 deduplicate해야 합니다. 다음 방법 중 하나를 사용하세요:

The data-fetching function must deduplicate matching calls so the component can reuse the request started during preloading. Use one of the following approaches:

  • fetch는 동일한 request가 자동으로 memoize됩니다.
  • ORM이나 database는 data-fetching 함수를 React.cache로 감싸세요.
  • Cache Components를 사용한다면 data-fetching 함수에 'use cache'를 추가하세요. 함수가 cookies()나 headers() 같은 request API를 읽는다면 'use cache: private'를 사용하세요.
  • For fetch, identical requests are memoized automatically.
  • For an ORM or database, wrap the data-fetching function in React.cache.
  • With Cache Components, add 'use cache' to the data-fetching function. If the function reads request APIs such as cookies() or headers(), use 'use cache: private'.

production에서는 private Cache Function에 대한 일치하는 호출들이 한 request 안에서 같은 결과를 재사용할 수 있습니다. 덕분에 component는 결과를 request 간 server cache에 저장하지 않고도 preload 중에 시작된 request를 재사용할 수 있습니다.

In production, matching calls to a private Cache Function can reuse the same result within one request. This lets a component reuse a request started during preloading without storing the result in a server cache across requests.

preload 함수는 데이터를 사용하는 component 옆에 두세요. 그러면 component를 옮기거나 제거할 때 dependency를 더 쉽게 찾을 수 있습니다:

Keep the preload function next to the component that consumes the data. This makes the dependency easier to find if you move or remove the component:

TSJSapp/item/[id]/item.tsx
async function getItem(id: string) {
  const res = await fetch(`https://api.example.com/items/${id}`)
  return res.json()
}

export const preload = (id: string) => {
  void getItem(id)
}

export default async function Item({ id }: { id: string }) {
  const item = await getItem(id)
  return <div>{item.name}</div>
}
async function getItem(id) {
  const res = await fetch(`https://api.example.com/items/${id}`)
  return res.json()
}

export const preload = (id) => {
  void getItem(id)
}

export default async function Item({ id }) {
  const item = await getItem(id)
  return <div>{item.name}</div>
}

다른 blocking request 전에 preload()를 호출해 item 로딩을 더 일찍 시작하세요:

Call preload() before another blocking request to start loading the item earlier:

TSJSapp/item/[id]/page.tsx
import Item, { preload } from './item'
import { checkIsAvailable } from '@/app/lib/data'

export default async function Page({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params

  preload(id)
  const isAvailable = await checkIsAvailable(id)

  return isAvailable ? <Item id={id} /> : null
}
import Item, { preload } from './item'
import { checkIsAvailable } from '@/app/lib/data'

export default async function Page({ params }) {
  const { id } = await params

  preload(id)
  const isAvailable = await checkIsAvailable(id)

  return isAvailable ? <Item id={id} /> : null
}

checkIsAvailable()이 실행되는 동안 item request는 계속 진행됩니다. page가 <Item>을 render하면, 동일한 fetch 호출이 preload()가 시작한 request를 재사용합니다.

The item request continues while checkIsAvailable() runs. If the page renders <Item>, the identical fetch call reuses the request that preload() started.
