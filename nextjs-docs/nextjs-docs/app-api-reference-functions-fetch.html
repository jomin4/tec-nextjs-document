fetchfetch

Next.js는 Web fetch() API를 확장해서, server의 각 request가 자체적인 persistent caching과 revalidation 방식을 설정할 수 있도록 합니다.

Next.js extends the Web fetch() API to allow each request on the server to set its own persistent caching and revalidation semantics.

브라우저에서 cache option은 fetch request가 브라우저의 HTTP cache와 어떻게 상호작용할지를 나타냅니다. 이 확장을 사용하면 cache는 server-side fetch request가 framework의 persistent cache와 어떻게 상호작용할지를 나타냅니다.

In the browser, the cache option indicates how a fetch request will interact with the browser's HTTP cache. With this extension, cache indicates how a server-side fetch request will interact with the framework's persistent cache.

Server Component 안에서 async와 await로 fetch를 직접 호출할 수 있습니다.

You can call fetch with async and await directly within Server Components.

TSJSapp/page.tsx
export default async function Page() {
  let data = await fetch('https://api.vercel.app/blog')
  let posts = await data.json()
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
export default async function Page() {
  let data = await fetch('https://api.vercel.app/blog')
  let posts = await data.json()
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}

fetch(url, options)

Next.js는 Web fetch() API를 확장하므로, 사용 가능한 모든 native option을 사용할 수 있습니다.

Since Next.js extends the Web fetch() API, you can use any of the native options available.

options.cache

request가 Next.js caching과 어떻게 상호작용할지 설정합니다.

Configure how the request should interact with Next.js caching.

fetch(`https://...`, { cache: 'force-cache' | 'no-store' })
  • auto no cache (기본값): development에서는 매 request마다 remote server에서 resource를 fetch하지만, next build 중에는 route가 static하게 prerender되므로 한 번만 fetch합니다. route에서 Request-time API가 감지되면 Next.js는 매 request마다 resource를 fetch합니다.
  • no-store: route에서 Request-time API가 감지되지 않더라도 Next.js는 매 request마다 remote server에서 resource를 fetch합니다.
  • force-cache: Next.js는 server-side cache에서 일치하는 request를 찾습니다. request는 URL, method, header, body를 기준으로 일치 여부를 판단하므로, 이 중 하나라도 다른 request는 별도로 cache됩니다.
    • 일치하는 항목이 있고 fresh 상태라면 cache에서 반환됩니다.
    • 일치하는 항목이 없거나 stale 상태라면, Next.js는 remote server에서 resource를 fetch하고 다운로드한 resource로 cache를 업데이트합니다. HTTP status code가 200인 response만 저장됩니다.
  • auto no cache (default): Next.js fetches the resource from the remote server on every request in development, but will fetch once during next build because the route will be statically prerendered. If Request-time APIs are detected on the route, Next.js will fetch the resource on every request.
  • no-store: Next.js fetches the resource from the remote server on every request, even if Request-time APIs are not detected on the route.
  • force-cache: Next.js looks for a matching request in its server-side cache. A request matches on its URL, method, headers, and body, so requests that differ in any of these are cached separately.
    • If there is a match and it is fresh, it will be returned from the cache.
    • If there is no match or a stale match, Next.js fetches the resource from the remote server and updates the cache with the downloaded resource. Only responses with a 200 HTTP status code are stored.
Good to know

caching은 opt-in 방식입니다. POST나 authorization·cookie header를 보내는 request를 포함해 어떤 request든 cache하려면 cache: 'force-cache'를 설정하세요. Draft Mode는 cache를 완전히 우회합니다(읽기도 쓰기도 하지 않음).

Caching is opt-in. Set cache: 'force-cache' to cache any request, including POST and requests that send authorization or cookie headers. Draft Mode bypasses the cache entirely (no read or write).

options.next.revalidate

fetch(`https://...`, { next: { revalidate: false | 0 | number } })

resource의 cache 수명(초 단위)을 설정합니다.

Set the cache lifetime of a resource (in seconds).

  • false - resource를 무기한 cache합니다. 의미상 revalidate: Infinity와 같습니다. HTTP cache는 시간이 지나면서 오래된 resource를 제거할 수 있습니다.
  • 0 - resource가 cache되지 않도록 합니다.
  • number - (초 단위) resource의 cache 수명을 최대 n초로 지정합니다.
  • false - Cache the resource indefinitely. Semantically equivalent to revalidate: Infinity. The HTTP cache may evict older resources over time.
  • 0 - Prevent the resource from being cached.
  • number - (in seconds) Specify the resource should have a cache lifetime of at most n seconds.
Good to know
  • 개별 fetch() request가 route의 기본 revalidate보다 낮은 revalidate 값을 설정하면, route 전체의 revalidation 주기가 줄어듭니다.
  • 같은 route 안에서 같은 URL을 가진 두 fetch request의 revalidate 값이 다르면 더 낮은 값이 사용됩니다.
  • { revalidate: 3600, cache: 'no-store' }처럼 서로 충돌하는 option은 허용되지 않으며, 둘 다 무시되고 development mode에서는 terminal에 warning이 출력됩니다.
  • If an individual fetch() request sets a revalidate number lower than the default revalidate of a route, the whole route revalidation interval will be decreased.
  • If two fetch requests with the same URL in the same route have different revalidate values, the lower value will be used.
  • Conflicting options such as { revalidate: 3600, cache: 'no-store' } are not allowed, both will be ignored, and in development mode a warning will be printed to the terminal.

options.next.tags

fetch(`https://...`, { next: { tags: ['collection'] } })

resource의 cache tag를 설정합니다. 그러면 revalidateTag를 사용해 on-demand로 데이터를 revalidate할 수 있습니다. custom tag의 최대 길이는 256자이고, tag 항목은 최대 128개입니다.

Set the cache tags of a resource. Data can then be revalidated on-demand using revalidateTag. The max length for a custom tag is 256 characters and the max tag items is 128.

Memoization

같은 URL과 option으로 GET을 사용하는 fetch request는 server render pass 동안 자동으로 memoize됩니다. 여러 Server Component, layout, page, generateStaticParams, generateViewport에서 같은 fetch를 호출하면 Next.js는 이를 한 번만 실행하고 결과를 공유합니다. 이는 persistent caching과는 별개입니다. memoization은 한 번의 render pass 동안만 유지되고, cache된 response는 여러 request에 걸쳐 유지됩니다.

fetch requests using GET with the same URL and options are automatically memoized during a server render pass. If you call the same fetch in multiple Server Components, layouts, pages, generateStaticParams and generateViewport, Next.js executes it only once and shares the result. This is separate from persistent caching: memoization lasts only for a single render pass, while cached responses persist across requests.

opt out하려면 fetch에 AbortController signal을 전달하세요:

To opt out, pass an AbortController signal to fetch:

const { signal } = new AbortController()
fetch(url, { signal })
Good to know

Route Handlers는 React component tree에 속하지 않으므로 memoization이 적용되지 않습니다.

Memoization does not apply in Route Handlers, since they are not part of the React component tree.

Troubleshooting문제 해결

Fetch default auto no cache and cache: 'no-store' not showing fresh data in developmentdevelopment에서 기본값 auto no cache와 cache: 'no-store'가 최신 데이터를 보여 주지 않는 경우

Next.js는 로컬 development에서 더 빠른 response와 유료 API 호출 비용 절감을 위해 Server Component의 fetch response를 Hot Module Replacement(HMR) 간에 cache합니다.

Next.js caches fetch responses in Server Components across Hot Module Replacement (HMR) in local development for faster responses and to reduce costs for billed API calls.

기본적으로 HMR cache는 기본값 auto no cache와 cache: 'no-store' option을 사용하는 request를 포함해 모든 fetch request에 적용됩니다. 즉, cache되지 않는 request도 HMR refresh 사이에는 최신 데이터를 보여 주지 않습니다. 하지만 navigation이나 full-page reload 시에는 cache가 지워집니다.

By default, the HMR cache applies to all fetch requests, including those with the default auto no cache and cache: 'no-store' option. This means uncached requests will not show fresh data between HMR refreshes. However, the cache will be cleared on navigation or full-page reloads.

자세한 내용은 serverComponentsHmrCache 문서를 참고하세요.

See the serverComponentsHmrCache docs for more information.

Hard refresh and caching in developmentdevelopment에서의 hard refresh와 caching

development mode에서 request에 cache-control: no-cache header가 포함되어 있으면 options.cache, options.next.revalidate, options.next.tags는 무시되고 fetch request는 원본(source)에서 제공됩니다.

In development mode, if the request includes the cache-control: no-cache header, options.cache, options.next.revalidate, and options.next.tags are ignored, and the fetch request is served from the source.

브라우저는 일반적으로 developer tools에서 cache가 비활성화되어 있거나 hard refresh 중일 때 cache-control: no-cache를 포함합니다.

Browsers typically include cache-control: no-cache when the cache is disabled in developer tools or during a hard refresh.
