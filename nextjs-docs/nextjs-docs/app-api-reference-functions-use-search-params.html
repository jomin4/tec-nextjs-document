useSearchParamsuseSearchParams

useSearchParams는 현재 URL의 query string을 읽을 수 있게 해 주는 Client Component hook입니다.

useSearchParams is a Client Component hook that lets you read the current URL's query string.

useSearchParams는 URLSearchParams interface의 read-only 버전을 반환합니다.

useSearchParams returns a read-only version of the URLSearchParams interface.

TSJSapp/dashboard/search-bar.tsx
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // URL -> `/dashboard?search=my-project`
  // `search` -> 'my-project'
  return <>Search: {search}</>
}
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // URL -> `/dashboard?search=my-project`
  // `search` -> 'my-project'
  return <>Search: {search}</>
}

Parameters

const searchParams = useSearchParams()

useSearchParams는 parameter를 받지 않습니다.

useSearchParams does not take any parameters.

Returns

useSearchParams는 URLSearchParams interface의 read-only 버전을 반환하며, 여기에는 URL의 query string을 읽기 위한 utility method가 포함되어 있습니다:

useSearchParams returns a read-only version of the URLSearchParams interface, which includes utility methods for reading the URL's query string:

  • URLSearchParams.get(): search parameter에 연결된 첫 번째 값을 반환합니다. 예를 들면 다음과 같습니다:

    URLsearchParams.get("a")
    /dashboard?a=1'1'
    /dashboard?a=''
    /dashboard?b=3null
    /dashboard?a=1&a=2'1' - 모든 값을 가져오려면 getAll()을 사용하세요

  • URLSearchParams.has(): 주어진 parameter가 존재하는지를 나타내는 boolean 값을 반환합니다. 예를 들면 다음과 같습니다:

    URLsearchParams.has("a")
    /dashboard?a=1true
    /dashboard?b=3false
  • getAll(), keys(), values(), entries(), forEach(), toString()을 포함한 URLSearchParams의 다른 read-only method에 대해 더 알아보세요.

  • URLSearchParams.get(): Returns the first value associated with the search parameter. For example:

    URLsearchParams.get("a")
    /dashboard?a=1'1'
    /dashboard?a=''
    /dashboard?b=3null
    /dashboard?a=1&a=2'1' - use getAll() to get all values

  • URLSearchParams.has(): Returns a boolean value indicating if the given parameter exists. For example:

    URLsearchParams.has("a")
    /dashboard?a=1true
    /dashboard?b=3false
  • Learn more about other read-only methods of URLSearchParams, including the getAll(), keys(), values(), entries(), forEach(), and toString().
Good to know
  • useSearchParams는 Client Component hook이며, partial rendering 중에 stale 값이 생기는 것을 막기 위해 Server Components에서는 지원되지 않습니다.
  • Server Component에서 search params를 기반으로 data를 fetch하려면, 대개 해당 Page의 searchParams prop을 읽는 것이 더 나은 방법입니다. 그런 다음 그 Page 안의 어떤 component(Server 또는 Client)에든 props로 전달할 수 있습니다.
  • 애플리케이션에 /pages directory가 포함되어 있으면 useSearchParams는 ReadonlyURLSearchParams | null을 반환합니다. null 값은 migration 중의 호환성을 위한 것으로, getServerSideProps를 사용하지 않는 page를 prerendering하는 동안에는 search params를 알 수 없기 때문입니다
  • useSearchParams is a Client Component hook and is not supported in Server Components to prevent stale values during partial rendering.
  • If you want to fetch data in a Server Component based on search params, it's often a better option to read the searchParams prop of the corresponding Page. You can then pass it down by props to any component (Server or Client) within that Page.
  • If an application includes the /pages directory, useSearchParams will return ReadonlyURLSearchParams | null. The null value is for compatibility during migration since search params cannot be known during prerendering of a page that doesn't use getServerSideProps

Behavior동작

Prerendering

route가 prerender되는 경우, useSearchParams를 호출하면 가장 가까운 Suspense boundary까지의 Client Component tree가 client-side rendering됩니다.

If a route is prerendered, calling useSearchParams will cause the Client Component tree up to the closest Suspense boundary to be client-side rendered.

이렇게 하면 route의 일부는 prerender되고, useSearchParams를 사용하는 dynamic 부분은 client-side rendering될 수 있습니다.

This allows a part of the route to be prerendered while the dynamic part that uses useSearchParams is client-side rendered.

Cache Components를 사용하면 route의 나머지 부분이 prerender될 때만 boundary가 client-side rendering됩니다. route의 어떤 component라도 cookies() 같은 request data를 읽으면, Next.js는 request 시점에 실제 search params로 server에서 boundary를 render합니다. sessionStorage처럼 브라우저 전용 API를 읽는 component를 server render에서 제외하려면, useSearchParams boundary에 의존하지 말고 use(browser())를 사용하세요.

With Cache Components, the boundary is client-side rendered only when the rest of the route is prerendered. If any component on the route reads request data, such as cookies(), Next.js renders the boundary on the server at request time with the real search params. To keep a component that reads browser-only APIs, such as sessionStorage, out of the server render, use use(browser()) instead of relying on the useSearchParams boundary.

useSearchParams를 사용하는 Client Component를 <Suspense/> boundary로 감싸는 것을 권장합니다. 그러면 그 위에 있는 Client Component들이 prerender되어 initial HTML의 일부로 전송될 수 있습니다.

We recommend wrapping the Client Component that uses useSearchParams in a <Suspense/> boundary. This will allow any Client Components above it to be prerendered and sent as part of initial HTML.

전체 해결 방법과 trade-off는 Next.js encountered URL data in a Client Component outside of Suspense를 참고하세요.

See Next.js encountered URL data in a Client Component outside of Suspense for full fix options and trade-offs.

예를 들면 다음과 같습니다:

For example:

TSJSapp/dashboard/search-bar.tsx
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // This will not be logged on the server during prerendering
  console.log(search)

  return <>Search: {search}</>
}

import SearchBar from './search-bar'

// This component passed as a fallback to the Suspense boundary
// will be rendered in place of the search bar in the initial HTML.
// When the value is available during React hydration the fallback
// will be replaced with the `<SearchBar>` component.
function SearchBarFallback() {
  return <>placeholder</>
}

export default function Page() {
  return (
    <>
      <nav>
        <Suspense fallback={<SearchBarFallback />}>
          <SearchBar />
        </Suspense>
      </nav>
      <h1>Dashboard</h1>
    </>
  )
}

Good to know
  • development 환경에서는 route가 on-demand로 render되므로 useSearchParams가 suspend되지 않으며, Suspense 없이도 동작하는 것처럼 보일 수 있습니다.
  • production build 중에는 Client Component에서 useSearchParams를 호출하는 static page를 Suspense boundary로 감싸야 합니다. 그렇지 않으면 Missing Suspense boundary with useSearchParams error와 함께 build가 실패합니다.
  • route를 dynamic하게 render하려는 의도라면, Server Component에서 먼저 connection 함수를 사용해 들어오는 request를 기다리는 방식을 선호하세요. 이렇게 하면 그 아래의 모든 것이 prerendering에서 제외됩니다. 무엇이 route를 dynamic하게 만드는지는 Dynamic Rendering 가이드를 참고하세요.
  • 이미 Server Component Page 안에 있다면 searchParams prop을 사용해 값을 Client Component에 전달하는 것을 고려하세요.
  • Page의 searchParams prop을 Client Component에 직접 전달하고 React의 use()로 unwrap할 수도 있습니다. 다만 이 경우 suspend되므로 Client Component를 Suspense boundary로 감싸야 합니다.
  • In development, routes are rendered on-demand, so useSearchParams doesn't suspend and things may appear to work without Suspense.
  • During production builds, a static page that calls useSearchParams from a Client Component must be wrapped in a Suspense boundary, otherwise the build fails with the Missing Suspense boundary with useSearchParams error.
  • If you intend the route to be dynamically rendered, prefer using the connection function first in a Server Component to wait for an incoming request, this excludes everything below from prerendering. See what makes a route dynamic in the Dynamic Rendering guide.
  • If you're already in a Server Component Page, consider using the searchParams prop and passing the values to Client Components.
  • You can also pass the Page searchParams prop directly to a Client Component and unwrap it with React's use(). Although this will suspend, so the Client Component should be wrapped with a Suspense boundary.

Dynamic Rendering

route가 dynamic하게 render되면, Client Component의 initial server render 중에 server에서 useSearchParams를 사용할 수 있습니다.

If a route is dynamically rendered, useSearchParams will be available on the server during the initial server render of the Client Component.

예를 들면 다음과 같습니다:

For example:

TSJSapp/dashboard/search-bar.tsx
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // This will be logged on the server during the initial render
  // and on the client on subsequent navigations.
  console.log(search)

  return <>Search: {search}</>
}
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {

  const search = searchParams.get('search')

  // This will be logged on the server during the initial render
  // and on the client on subsequent navigations.
  console.log(search)

  return <>Search: {search}</>
}

    <>

        <SearchBar />
      </nav>

Good to know
  • 이전에는 dynamic rendering을 강제하기 위해 page에 export const dynamic = 'force-dynamic'을 설정했습니다. 대신 connection()을 사용하는 것을 선호하세요. dynamic rendering을 들어오는 request와 의미적으로 연결해 주기 때문입니다.
  • Previously, setting export const dynamic = 'force-dynamic' on the page was used to force dynamic rendering. Prefer using connection() instead, as it semantically ties dynamic rendering to the incoming request.

Server Components

Pages

Pages(Server Components)에서 search params에 접근하려면 searchParams prop을 사용하세요.

To access search params in Pages (Server Components), use the searchParams prop.

Layouts

Page와 달리 Layouts(Server Components)는 searchParams prop을 받지 않습니다. 공유 layout은 navigation 중에 re-render되지 않기 때문에 navigation 사이에 searchParams가 stale해질 수 있기 때문입니다. 자세한 설명을 참고하세요.

Unlike Pages, Layouts (Server Components) do not receive the searchParams prop. This is because a shared layout is not re-rendered during navigation which could lead to stale searchParams between navigations. View detailed explanation.

대신 Page의 searchParams prop이나, 최신 searchParams로 client에서 re-render되는 Client Component의 useSearchParams hook을 사용하세요.

Instead, use the Page searchParams prop or the useSearchParams hook in a Client Component, which is re-rendered on the client with the latest searchParams.

Examples예시

Updating searchParamssearchParams 업데이트하기

useRouter나 Link를 사용해 새 searchParams를 설정할 수 있습니다. navigation이 수행된 후 현재 page.js는 업데이트된 searchParams prop을 받습니다.

You can use useRouter or Link to set new searchParams. After a navigation is performed, the current page.js will receive an updated searchParams prop.

TSJSapp/example-client-component.tsx
'use client'

export default function ExampleClientComponent() {
  const router = useRouter()
  const pathname = usePathname()
  const searchParams = useSearchParams()

  // Get a new searchParams string by merging the current
  // searchParams with a provided key/value pair
  const createQueryString = useCallback(
    (name: string, value: string) => {
      const params = new URLSearchParams(searchParams.toString())
      params.set(name, value)

      return params.toString()
    },
    [searchParams]
  )

  return (
    <>
      <p>Sort By</p>

      {/* using useRouter */}
      <button
        onClick={() => {
          // <pathname>?sort=asc
          router.push(pathname + '?' + createQueryString('sort', 'asc'))
        }}
      >
        ASC
      </button>

      {/* using <Link> */}
      <Link
        href={
          // <pathname>?sort=desc
          pathname + '?' + createQueryString('sort', 'desc')
        }
      >
        DESC
      </Link>
    </>
  )
}
