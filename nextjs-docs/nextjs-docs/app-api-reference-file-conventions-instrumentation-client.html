instrumentation-client.jsinstrumentation-client.js

instrumentation-client.js|ts 파일을 사용하면 애플리케이션이 interactive 상태가 되기 전에 실행되는 monitoring, analytics 코드 및 기타 side-effect를 추가할 수 있습니다. performance tracking, error monitoring, polyfill, 또는 기타 client-side observability 도구를 설정할 때 유용합니다.

The instrumentation-client.js|ts file allows you to add monitoring, analytics code, and other side-effects that run before your application becomes interactive. This is useful for setting up performance tracking, error monitoring, polyfills, or any other client-side observability tools.

사용하려면 이 파일을 애플리케이션의 root나 src 폴더 안에 두세요.

To use it, place the file in the root of your application or inside a src folder.

Usage사용법

server-side instrumentation과 달리 특정 함수를 export할 필요가 없습니다. 파일 안에 monitoring 코드를 바로 작성하면 됩니다:

Unlike server-side instrumentation, you do not need to export any specific functions. You can write your monitoring code directly in the file:

TSJSinstrumentation-client.ts
// Set up performance monitoring
performance.mark('app-init')

// Initialize analytics
console.log('Analytics initialized')

// Set up error tracking
window.addEventListener('error', (event) => {
  // Send to your error tracking service
  reportError(event.error)
})
// Set up performance monitoring
performance.mark('app-init')

// Initialize analytics
console.log('Analytics initialized')

// Set up error tracking
window.addEventListener('error', (event) => {
  // Send to your error tracking service
  reportError(event.error)
})

Error handling: 견고한 monitoring을 위해 instrumentation 코드를 try-catch block으로 감싸세요. 이렇게 하면 개별 tracking 실패가 다른 instrumentation 기능에 영향을 주지 않습니다.

Error handling: Implement try-catch blocks around your instrumentation code to ensure robust monitoring. This prevents individual tracking failures from affecting other instrumentation features.

Router navigation trackingRouter navigation 추적

onRouterTransitionStart를 export하면 App Router navigation의 시작을 관찰할 수 있습니다:

You can export onRouterTransitionStart to observe the start of App Router navigations:

TSinstrumentation-client.ts
export function onRouterTransitionStart(
  url: string,
  navigationType: 'push' | 'replace' | 'traverse'
) {
  console.log(url, navigationType)
}

추가적인 router transition 정보는 experimental 기능입니다. 이를 활성화하면 세 번째 인자로 event를 받을 수 있습니다:

Additional router transition information is experimental. Enable it to receive a third event argument:

TSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    instrumentationClientRouterTransitionEvents: true,
  },
}

export default nextConfig

event에는 navigation이 dispatch될 때 알 수 있는 transition metadata와 source context가 포함됩니다:

The event includes the transition metadata and source context known when the navigation is dispatched:

TSJSinstrumentation-client.ts
import type { RouterTransitionStartEvent, RouterTransitionType } from 'next'

export function onRouterTransitionStart(
  url: string,
  navigationType: RouterTransitionType,
  { id, timestamp, fromRoutes, prefetchIntent }: RouterTransitionStartEvent
) {
  console.log(id, timestamp, url, navigationType, fromRoutes, prefetchIntent)
}
export function onRouterTransitionStart(url, navigationType, event) {
  console.log(
    event.id,
    event.timestamp,
    url,
    navigationType,
    event.fromRoutes,
    event.prefetchIntent
  )
}

onRouterTransitionStart는 다음을 받습니다:

onRouterTransitionStart receives:

  • url: string - 이동하려는 URL
  • navigationType: 'push' | 'replace' | 'traverse' - navigation의 종류
  • event.id - 이 transition에 대한 event들이 공유하는 불투명한(opaque) ID
  • event.timestamp - framework가 capture한 millisecond 단위 Unix timestamp
  • event.fromRoutes - navigation 전에 보이던 route pattern. 기본 children route가 먼저 오고, 그 뒤에 parallel slot들이 결정적인(deterministic) 순서로 이어집니다
  • event.prefetchIntent - link navigation의 경우, 클릭한 link가 full prefetching을 요청했는지(full), automatic prefetching을 사용했는지(auto), prefetching을 요청하지 않았는지(none)를 나타냅니다. 연결된 link가 없는 navigation(programmatic router.push()/router.replace(), 또는 브라우저 뒤로/앞으로 가기)에서는 적용할 link prefetch intent가 없으므로 null입니다
  • url: string - The URL being navigated to
  • navigationType: 'push' | 'replace' | 'traverse' - The type of navigation
  • event.id - An opaque ID shared by events for this transition
  • event.timestamp - A framework-captured Unix timestamp in milliseconds
  • event.fromRoutes - Route patterns visible before navigation. The primary children route is first, followed by parallel slots in deterministic order
  • event.prefetchIntent - For link navigations, whether the clicked link requested full prefetching (full), used automatic prefetching (auto), or did not request prefetching (none). For navigations with no associated link (programmatic router.push()/router.replace(), or browser back/forward) this is null, since no link prefetch intent applies

route 항목은 filesystem 형식의 pattern을 사용하므로, /blog/hello에서 다른 곳으로 이동하는 navigation은 /blog/[slug]로 보고될 수 있습니다.

Route entries use filesystem-style patterns, so a navigation away from /blog/hello may report /blog/[slug].

hook error는 격리되어 있어 navigation이나 다른 hook에 영향을 주지 않습니다.

Hook errors are isolated and do not affect navigation or other hooks.

Performance considerationsPerformance 고려 사항

instrumentation 코드는 가볍게 유지하세요.

Keep instrumentation code lightweight.

Next.js는 development에서 초기화 시간을 monitoring하며, 16ms보다 오래 걸리면 warning을 log에 남깁니다. 이는 매끄러운 page loading에 영향을 줄 수 있습니다.

Next.js monitors initialization time in development and will log warnings if it takes longer than 16ms, which could impact smooth page loading.

Execution timing실행 시점

instrumentation-client.js 파일은 애플리케이션 lifecycle의 특정 시점에 실행됩니다:

The instrumentation-client.js file executes at a specific point in the application lifecycle:

  1. HTML document가 load된 후
  2. React hydration이 시작되기 전
  3. 사용자 interaction이 가능해지기 전
  1. After the HTML document is loaded
  2. Before React hydration begins
  3. Before user interactions are possible

이 시점 덕분에 애플리케이션 lifecycle 초기의 event를 capture해야 하는 error tracking, analytics, performance monitoring을 설정하기에 이상적입니다.

This timing makes it ideal for setting up error tracking, analytics, and performance monitoring that needs to capture early application lifecycle events.

hydration 전에 완료가 보장되는 것은 synchronous한 top-level 코드뿐입니다. 여기서 시작한 asynchronous 작업(Promise, import(), 또는 top-level await)은 await되지 않으며 hydration이 시작된 후에 resolve될 수 있으므로, fire-and-forget으로 취급하세요. component가 실행되기 전에 반드시 준비되어 있어야 하는 것이 있다면 Polyfills의 synchronous pattern 중 하나를 사용하세요.

Only synchronous, top-level code is guaranteed to complete before hydration. Asynchronous work started here (a Promise, import(), or top-level await) is not awaited and may resolve after hydration has begun, so treat it as fire-and-forget. When something must be in place before your components run, use one of the synchronous patterns in Polyfills.

See also함께 보기

next.config.js plugin(예: withSentry 같은 wrapper)은 instrumentationClientInject option을 통해 자체 client instrumentation module을 등록할 수 있습니다. 주입된 module은 배열 순서대로 이 파일보다 먼저 실행되며, 같은 router transition start hook을 export할 수 있습니다. 애플리케이션 코드는 계속 이 file convention을 직접 사용해야 합니다.

next.config.js plugins (for example, wrappers like withSentry) can register their own client instrumentation module via the instrumentationClientInject option. Injected modules run before this file, in array order, and may export the same router transition start hook. Application code should continue to use this file convention directly.

Performance monitoring

Performance Observer API와 performance mark를 사용해 Time to Interactive와 navigation performance를 추적합니다.

Track Time to Interactive and navigation performance using the Performance Observer API and performance marks.

TSJSinstrumentation-client.ts
const startTime = performance.now()

const observer = new PerformanceObserver(
  (list: PerformanceObserverEntryList) => {
    for (const entry of list.getEntries()) {
      if (entry instanceof PerformanceNavigationTiming) {
        console.log('Time to Interactive:', entry.loadEventEnd - startTime)
      }
    }
  }
)

observer.observe({ entryTypes: ['navigation'] })

export function onRouterTransitionStart(url: string) {
  performance.mark(`nav-start-${url}`)
}

Polyfills

Execution timing에서 언급했듯이, 여기서는 synchronous한 top-level 코드만 hydration 전에 실행되므로 조건부 import()나 top-level await는 hydration이 이미 시작된 후에 resolve될 수 있습니다.

As noted in Execution timing, only synchronous, top-level code here runs before hydration, so a conditional import() or top-level await may resolve after hydration has already started.

component가 실행되기 전에 polyfill이 확실히 적용되도록 하려면, polyfill을 static import하고 feature detection 후 synchronous하게 적용하세요. import가 static이므로 polyfill은 모든 방문자에게 전송됩니다:

To guarantee a polyfill is applied before your components run, statically import it and apply it synchronously after feature detection. Because the import is static, the polyfill ships to every visitor:

TSinstrumentation-client.ts
import ResizeObserverPolyfill from './lib/polyfills/resize-observer'

if (!window.ResizeObserver) {
  window.ResizeObserver = ResizeObserverPolyfill
}

여기서 조건부 import()로 polyfill을 load하는 것은 피하세요. import가 fire-and-forget이므로 polyfill이 hydration이 이미 시작된 후에 적용될 수 있고, 이는 component에게 너무 늦을 수 있습니다:

Avoid loading a polyfill with a conditional import() here. The import is fire-and-forget, so the polyfill may be applied after hydration has already begun, which can be too late for your components:

TSinstrumentation-client.ts
// Avoid: the dynamic import is fire-and-forget, so `ResizeObserver`
// may still be undefined when your components run.
if (!window.ResizeObserver) {
  import('./lib/polyfills/resize-observer').then((mod) => {
    window.ResizeObserver = mod.default
  })
}

필요할 때 load되는 것이라면 해당 기능을 사용하는 코드에서 polyfill하는 편이 좋습니다. 이 방법과 다른 전략은 Custom Polyfills를 참고하세요.

For anything loaded on demand, prefer polyfilling in the code that uses the feature. See Custom Polyfills for that and other strategies.

Next.js는 필요한 브라우저를 위해 이미 널리 사용되는 polyfill(fetch, URL, Object.assign 등)의 기본 세트를 주입하므로, 그 기본 세트에 포함되지 않은 기능에 대해서만 polyfill을 추가하면 됩니다.

Next.js already injects a baseline of widely used polyfills (such as fetch, URL, and Object.assign) for the browsers that need them, so you only need to add polyfills for features outside that baseline.
