not-found.jsnot-found.js

Next.js는 not found 상황을 처리하기 위한 두 가지 convention을 제공합니다:

Next.js provides two conventions to handle not found cases:

  • not-found.js: route segment에서 notFound 함수를 호출할 때 사용됩니다.
  • global-not-found.js: 앱 전체에서 match되지 않는 route에 대한 global 404 page를 정의할 때 사용됩니다. routing 수준에서 처리되며 layout이나 page의 rendering에 의존하지 않습니다.
  • not-found.js: Used when you call the notFound function in a route segment.
  • global-not-found.js: Used to define a global 404 page for unmatched routes across your entire app. This is handled at the routing level and doesn't depend on rendering a layout or page.

not-found.js

not-found 파일은 route segment 안에서 notFound 함수가 throw될 때 UI를 render합니다.

The not-found file renders UI when the notFound function is thrown within a route segment.

streaming이 시작되기 전에는 Next.js가 404 status code를 반환합니다. streaming이 시작된 후에는 status code가 200으로 유지되고 not-found UI가 response 안에서 render됩니다. 두 경우 모두 Next.js는 <meta name="robots" content="noindex" /> tag를 주입합니다. 자세한 내용은 Status codes를 참고하세요.

Before streaming starts, Next.js returns a 404 status code. After streaming starts, the status code remains 200 and the not-found UI renders in the response. Next.js injects a <meta name="robots" content="noindex" /> tag in both cases. See Status codes for details.

TSJSapp/not-found.tsx
import Link from 'next/link'

export default function NotFound() {
  return (
    <div>
      <h2>Not Found</h2>
      <p>Could not find requested resource</p>
      <Link href="/">Return Home</Link>
    </div>
  )
}

component hierarchy에서 not-found.js는 loading.js와 page.js 사이에서 render됩니다. 같은 segment의 loading.js가 만드는 <Suspense> boundary와 error.js가 만드는 error boundary로 감싸집니다.

In the component hierarchy, not-found.js renders between loading.js and page.js. It is wrapped by the <Suspense> boundary from loading.js and the error boundary from error.js in the same segment.

Good to know

기본 not found UI는 prefers-color-scheme을 통해 운영체제의 color scheme을 따르며, 앱 수준의 theme(예: <html>의 class나 data-theme attribute)은 읽지 않습니다. 이 UI는 root layout 안에서 render되므로, 명시적인 theme에 맞추는 가장 빠른 방법은 global stylesheet에 theme selector 범위로 한정된, specificity가 더 높은 rule 쌍을 추가하는 것입니다. 예를 들면 html[data-theme='light'] body와 html[data-theme='dark'] body입니다. markup을 완전히 제어하려면 직접 not-found.js를 만드세요.

The default not found UI follows the operating system's color scheme via prefers-color-scheme and does not read an app-level theme (such as a class or data-theme attribute on <html>). Because it renders inside your root layout, the quickest way to match an explicit theme is to add a higher-specificity rule pair in your global stylesheet, scoped to your theme selector — for example html[data-theme='light'] body and html[data-theme='dark'] body. For full control over the markup, provide your own not-found.js.

global-not-found.js (experimental)

global-not-found.js 파일을 사용하면 애플리케이션 전체에 대한 404 page를 정의할 수 있습니다. route 수준에서 동작하는 not-found.js와 달리, 이 파일은 요청된 URL이 어떤 route와도 전혀 match되지 않을 때 사용됩니다. Next.js는 rendering을 건너뛰고 이 global page를 바로 반환합니다.

The global-not-found.js file lets you define a 404 page for your entire application. Unlike not-found.js, which works at the route level, this is used when a requested URL doesn't match any route at all. Next.js skips rendering and directly returns this global page.

global-not-found.js 파일은 앱의 일반적인 rendering을 우회하므로, 404 page에 필요한 global style, font 등 기타 dependency를 직접 import해야 합니다. theme도 마찬가지입니다. global-not-found.js는 layout을 우회하기 때문에 기본 UI가 볼 수 있는 신호는 OS color scheme뿐이므로, 이 파일 안에서 theme(class나 attribute)을 적용하세요.

The global-not-found.js file bypasses your app's normal rendering, which means you'll need to import any global styles, fonts, or other dependencies that your 404 page requires. This includes your theme: because global-not-found.js bypasses your layout, the OS color scheme is the only signal the default UI sees, so apply your theme (class or attribute) inside this file.

Good to know

global style을 더 작게 줄인 버전과 더 단순한 font family를 사용하면 이 page의 performance를 개선할 수 있습니다.

A smaller version of your global styles, and a simpler font family could improve performance of this page.

global-not-found.js는 layout.js와 not-found.js를 조합해서 404 page를 만들 수 없을 때 유용합니다. 이런 상황은 두 가지 경우에 생길 수 있습니다:

global-not-found.js is useful when you can't build a 404 page using a combination of layout.js and not-found.js. This can happen in two cases:

  • 앱에 여러 개의 root layout이 있어서(예: app/(admin)/layout.tsx와 app/(shop)/layout.tsx) global 404를 구성할 단일 layout이 없는 경우.
  • root layout이 top-level dynamic segment(예: app/[country]/layout.tsx)로 정의되어 있어서 일관된 404 page를 구성하기 어려운 경우.
  • Your app has multiple root layouts (e.g. app/(admin)/layout.tsx and app/(shop)/layout.tsx), so there's no single layout to compose a global 404 from.
  • Your root layout is defined using top-level dynamic segments (e.g. app/[country]/layout.tsx), which makes composing a consistent 404 page harder.

활성화하려면 next.config.ts에 globalNotFound flag를 추가하세요:

To enable it, add the globalNotFound flag in next.config.ts:

TSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    globalNotFound: true,
  },
}

export default nextConfig

그다음 app directory의 root에 파일을 만드세요: app/global-not-found.js:

Then, create a file in the root of the app directory: app/global-not-found.js:

TSJSapp/global-not-found.tsx
// Import global styles and fonts
import './globals.css'
import { Inter } from 'next/font/google'
import type { Metadata } from 'next'

const inter = Inter({ subsets: ['latin'] })

export const metadata: Metadata = {
  title: '404 - Page Not Found',
  description: 'The page you are looking for does not exist.',
}

export default function GlobalNotFound() {
  return (
    <html lang="en" className={inter.className}>
      <body>
        <h1>404 - Page Not Found</h1>
        <p>This page does not exist.</p>
      </body>
    </html>
  )
}

not-found.js와 달리 이 파일은 <html>과 <body> tag를 포함한 완전한 HTML document를 반환해야 합니다.

Unlike not-found.js, this file must return a full HTML document, including <html> and <body> tags.

Reference레퍼런스

Props

not-found.js나 global-not-found.js component는 어떤 props도 받지 않습니다.

not-found.js or global-not-found.js components do not accept any props.

Good to know

예상된 notFound() error를 catch하는 것 외에도, root의 app/not-found.js와 app/global-not-found.js 파일은 애플리케이션 전체에서 match되지 않는 모든 URL을 처리합니다. 즉, 앱이 처리하지 않는 URL을 방문한 사용자에게는 export된 UI가 표시됩니다.

In addition to catching expected notFound() errors, the root app/not-found.js and app/global-not-found.js files handle any unmatched URLs for your whole application. This means users that visit a URL that is not handled by your app will be shown the exported UI.

Data Fetching

기본적으로 not-found는 Server Component입니다. async로 표시해 data를 fetch하고 표시할 수 있습니다:

By default, not-found is a Server Component. You can mark it as async to fetch and display data:

TSJSapp/not-found.tsx
import Link from 'next/link'
import { headers } from 'next/headers'

export default async function NotFound() {
  const headersList = await headers()
  const domain = headersList.get('host')
  const data = await getSiteData(domain)
  return (
    <div>
      <h2>Not Found: {data.name}</h2>
      <p>Could not find requested resource</p>
      <p>
        View <Link href="/blog">all posts</Link>
      </p>
    </div>
  )
}
import Link from 'next/link'
import { headers } from 'next/headers'

export default async function NotFound() {
  const headersList = await headers()
  const domain = headersList.get('host')
  const data = await getSiteData(domain)

      <h2>Not Found: {data.name}</h2>
      <p>Could not find requested resource</p>
      <p>
        View <Link href="/blog">all posts</Link>
      </p>
    </div>

경로에 따라 content를 표시하기 위해 usePathname 같은 Client Component hook을 사용해야 한다면, 대신 client-side에서 data를 fetch해야 합니다.

If you need to use Client Component hooks like usePathname to display content based on the path, you must fetch data on the client-side instead.

Good to know

Next.js는 global-not-found.js page를 포함해 404 status code를 반환하는 page에 <meta name="robots" content="noindex" />를 자동으로 주입합니다.

Next.js automatically injects <meta name="robots" content="noindex" /> for pages that return a 404 status code, including global-not-found.js pages.
