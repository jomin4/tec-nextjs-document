allowedDevOriginsallowedDevOrigins

Next.js는 무단 접근을 막기 위해 기본적으로 개발 중 dev 전용 asset과 endpoint에 대한 cross-origin request를 차단합니다.

Next.js blocks cross-origin requests to dev-only assets and endpoints during development by default to prevent unauthorized access.

server가 초기화될 때 사용된 hostname(기본값 localhost) 이외의 origin에서 오는 request를 허용하도록 Next.js 애플리케이션을 설정하려면 allowedDevOrigins config option을 사용하세요.

To configure a Next.js application to allow requests from origins other than the hostname the server was initialized with (localhost by default), use the allowedDevOrigins config option.

allowedDevOrigins를 사용하면 development mode에서 dev server에 request를 보낼 수 있는 추가 origin을 설정할 수 있습니다. 예를 들어 localhost뿐 아니라 local-origin.dev도 사용하려면 next.config.js를 열고 allowedDevOrigins config를 추가하세요:

allowedDevOrigins lets you set additional origins that can request the dev server in development mode. For example, to use local-origin.dev instead of only localhost, open next.config.js and add the allowedDevOrigins config:

JSnext.config.js
module.exports = {
  allowedDevOrigins: ['local-origin.dev', '*.local-origin.dev'],
}

request의 Origin header 중 hostname만 항목과 비교됩니다. http://local-origin.dev:3000/dashboard?tab=1에서 온 request라면 local-origin.dev가 비교 대상입니다. scheme, port, path, query string은 무시됩니다. 항목도 같은 방식으로 https://와 port 없이 작성하세요.

Only the hostname of the request's Origin header is matched against your entries. For a request from http://local-origin.dev:3000/dashboard?tab=1, that is local-origin.dev. The scheme, the port, the path, and the query string are ignored. Write your entries that way too, without https:// and without a port.

dev asset을 불러오는 script tag처럼 no-cors cross-site request는 Origin header를 보내지 않습니다. 이런 request는 대신 Referer의 hostname으로 비교됩니다.

A no-cors cross-site request, such as a script tag loading a dev asset, sends no Origin header. Those are matched on the Referer hostname instead.

항목은 두 가지 wildcard로 확장할 수도 있습니다. *는 hostname의 label 정확히 하나를, **는 하나 이상의 label을 대신합니다. 그래서 위 예제에는 bare hostname용과 subdomain용, 두 개의 항목이 있습니다.

Entries can also expand, through two wildcards: a * stands in for exactly one label of the hostname, and ** for one or more. That is why the example above lists two entries, one for the bare hostname and one for its subdomains.

부분 치환은 지원되지 않습니다. team-*.local-origin.dev 대신 *.local-origin.dev로 작성하세요. **는 pattern의 맨 앞에서만 사용할 수 있습니다.

Partial replacement is not supported. Write *.local-origin.dev, rather than team-*.local-origin.dev. Using ** is only supported at the start of the pattern.

dev server는 이미 localhost, 그 subdomain, 그리고 server를 시작할 때 사용한 hostname을 허용합니다. 원격 개발에 사용하는 tunnel처럼 그 밖의 hostname은 항목을 추가해야 합니다:

The dev server already allows localhost, its subdomains, and the hostname it was started with. Any other hostname needs an entry, such as a tunnel used for remote development:

JSnext.config.js
module.exports = {
  allowedDevOrigins: ['*.tunnel.example.com'],
}
