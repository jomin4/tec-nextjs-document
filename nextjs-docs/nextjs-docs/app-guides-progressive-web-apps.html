How to build a Progressive Web Application (PWA) with Next.jsNext.js로 PWA 만들기

Progressive Web Application(PWA)은 웹 애플리케이션의 도달 범위와 접근성에 native mobile 앱의 기능과 사용자 경험을 결합한 것입니다. Next.js를 사용하면 여러 codebase나 app store 승인 없이도 모든 플랫폼에서 매끄럽고 앱 같은 경험을 제공하는 PWA를 만들 수 있습니다.

Progressive Web Applications (PWAs) offer the reach and accessibility of web applications combined with the features and user experience of native mobile apps. With Next.js, you can create PWAs that provide a seamless, app-like experience across all platforms without the need for multiple codebases or app store approvals.

PWA를 사용하면 다음과 같은 것이 가능합니다:

PWAs allow you to:

  • app store 승인을 기다리지 않고 업데이트를 즉시 deploy
  • 하나의 codebase로 cross-platform 애플리케이션 제작
  • 홈 화면 설치, push notification 같은 native에 가까운 기능 제공
  • Deploy updates instantly without waiting for app store approval
  • Create cross-platform applications with a single codebase
  • Provide native-like features such as home screen installation and push notifications

Next.js는 App Router를 사용한 web app manifest 생성을 기본으로 지원합니다. static 또는 dynamic manifest 파일 중 하나를 만들 수 있습니다:

Next.js provides built-in support for creating a web app manifest using the App Router. You can create either a static or dynamic manifest file:

예를 들어 app/manifest.ts 또는 app/manifest.json 파일을 만드세요:

이 파일에는 이름, icon, 그리고 사용자 기기에서 icon으로 어떻게 표시될지에 대한 정보가 들어 있어야 합니다. 그러면 사용자가 PWA를 홈 화면에 설치할 수 있어 native 앱 같은 경험을 제공할 수 있습니다.

function urlBase64ToUint8Array(base64String: string) {
  const padding = '='.repeat((4 - (base64String.length % 4)) % 4)
  const base64 = (base64String + padding).replace(/-/g, '+').replace(/_/g, '/')

  const rawData = window.atob(base64)
  const outputArray = new Uint8Array(rawData.length)

  for (let i = 0; i < rawData.length; ++i) {
    outputArray[i] = rawData.charCodeAt(i)
  }
  return outputArray
}

Let’s now add a component to manage subscribing, unsubscribing, and sending push notifications.

TSJS
function PushNotificationManager() {
  const [isSupported, setIsSupported] = useState(false)
  const [subscription, setSubscription] = useState<PushSubscription | null>(
    null
  )
  const [message, setMessage] = useState('')

  useEffect(() => {
    if ('serviceWorker' in navigator && 'PushManager' in window) {
      setIsSupported(true)
      registerServiceWorker()
    }
  }, [])

  async function registerServiceWorker() {
    const registration = await navigator.serviceWorker.register(
      new URL('../lib/service-worker.js', import.meta.url),
      {
        scope: '/',
        updateViaCache: 'none',
      }
    )
    const sub = await registration.pushManager.getSubscription()
    setSubscription(sub)
  }

  async function subscribeToPush() {
    const registration = await navigator.serviceWorker.ready
    const sub = await registration.pushManager.subscribe({
      userVisibleOnly: true,
      applicationServerKey: urlBase64ToUint8Array(
        process.env.NEXT_PUBLIC_VAPID_PUBLIC_KEY!
      ),
    })
    setSubscription(sub)
    const serializedSub = JSON.parse(JSON.stringify(sub))
    await subscribeUser(serializedSub)
  }

  async function unsubscribeFromPush() {
    await subscription?.unsubscribe()
    setSubscription(null)
    await unsubscribeUser()
  }

  async function sendTestNotification() {
    if (subscription) {
      await sendNotification(message)
      setMessage('')
    }
  }

  if (!isSupported) {
    return <p>Push notifications are not supported in this browser.</p>
  }

  return (
    <div>
      <h3>Push Notifications</h3>
      {subscription ? (
        <>
          <p>You are subscribed to push notifications.</p>
          <button onClick={unsubscribeFromPush}>Unsubscribe</button>
          <input
            type="text"
            placeholder="Enter notification message"
            value={message}
            onChange={(e) => setMessage(e.target.value)}
          />
          <button onClick={sendTestNotification}>Send Test</button>
        </>
      ) : (
        <>
          <p>You are not subscribed to push notifications.</p>
          <button onClick={subscribeToPush}>Subscribe</button>
        </>
      )}
    </div>
  )
}

5. Creating a Service Worker5. Service Worker 만들기

service worker용 lib/service-worker.js 파일을 만드세요:

Create a lib/service-worker.js file for your service worker:

JSlib/service-worker.js
self.addEventListener('push', function (event) {
  if (event.data) {
    const data = event.data.json()
    const options = {
      body: data.body,
      icon: data.icon || '/icon.png',
      badge: '/badge.png',
      vibrate: [100, 50, 100],
      data: {
        dateOfArrival: Date.now(),
        primaryKey: '2',
      },
    }
    event.waitUntil(self.registration.showNotification(data.title, options))
  }
})

self.addEventListener('notificationclick', function (event) {
  console.log('Notification click received.')
  event.notification.close()
  event.waitUntil(clients.openWindow('<https://your-website.com>'))
})

이 service worker는 custom image와 notification을 지원합니다. 들어오는 push event와 notification 클릭을 처리합니다.

This service worker supports custom images and notifications. It handles incoming push events and notification clicks.

  • icon과 badge property로 notification의 custom icon을 설정할 수 있습니다.
  • vibrate pattern을 조정해 지원되는 기기에서 custom 진동 알림을 만들 수 있습니다.
  • data property로 notification에 추가 data를 첨부할 수 있습니다.
  • You can set custom icons for notifications using the icon and badge properties.
  • The vibrate pattern can be adjusted to create custom vibration alerts on supported devices.
  • Additional data can be attached to the notification using the data property.

service worker가 다양한 기기와 브라우저에서 예상대로 동작하는지 철저히 테스트하세요. 또한 notificationclick event listener 안의 'https://your-website.com' link를 애플리케이션에 맞는 URL로 바꾸는 것을 잊지 마세요.

Remember to test your service worker thoroughly to ensure it behaves as expected across different devices and browsers. Also, make sure to update the 'https://your-website.com' link in the notificationclick event listener to the appropriate URL for your application.

2단계에서 정의한 InstallPrompt component는 iOS 기기에서 홈 화면에 설치하도록 안내하는 메시지를 보여 줍니다.

애플리케이션을 mobile 홈 화면에 설치할 수 있게 하려면 다음이 필요합니다:

To ensure your application can be installed to a mobile home screen, you must have:

  1. 유효한 web app manifest(1단계에서 만든 것)
  2. HTTPS로 제공되는 웹사이트
  1. A valid web app manifest (created in step 1)
  2. The website served over HTTPS

이 조건이 충족되면 최신 브라우저는 사용자에게 설치 prompt를 자동으로 보여 줍니다. beforeinstallprompt로 custom 설치 버튼을 제공할 수도 있지만, 브라우저와 플랫폼 간에 호환되지 않기 때문에(Safari iOS에서 동작하지 않음) 권장하지 않습니다.

Modern browsers will automatically show an installation prompt to users when these criteria are met. You can provide a custom installation button with beforeinstallprompt, however, we do not recommend this as it is not cross browser and platform (does not work on Safari iOS).

7. Testing Locally7. 로컬에서 테스트하기

로컬에서 notification을 볼 수 있으려면 다음을 확인하세요:

To ensure you can view notifications locally, ensure that:

  • HTTPS로 로컬 실행하고 있는지
    • 테스트할 때는 next dev --experimental-https를 사용하세요
  • 브라우저(Chrome, Safari, Firefox)에서 notification이 활성화되어 있는지
    • 로컬에서 prompt가 나타나면 notification 사용 권한을 허용하세요
    • 브라우저 전체에서 notification이 전역으로 비활성화되어 있지 않은지 확인하세요
    • 그래도 notification이 보이지 않으면 다른 브라우저로 debug해 보세요
  • You are running locally with HTTPS
    • Use next dev --experimental-https for testing
  • Your browser (Chrome, Safari, Firefox) has notifications enabled
    • When prompted locally, accept permissions to use notifications
    • Ensure notifications are not disabled globally for the entire browser
    • If you are still not seeing notifications, try using another browser to debug

8. Securing your application8. 애플리케이션 보안 강화하기

보안은 모든 웹 애플리케이션, 특히 PWA에서 매우 중요한 요소입니다. Next.js에서는 next.config.js 파일로 security header를 설정할 수 있습니다. 예를 들면 다음과 같습니다:

Security is a crucial aspect of any web application, especially for PWAs. Next.js allows you to configure security headers using the next.config.js file. For example:

JSnext.config.js
module.exports = {
  async headers() {
    return [
      {
        source: '/(.*)',
        headers: [

각 option을 살펴보겠습니다:

Let’s go over each of these options:

  1. Global Header(모든 route에 적용):
    1. X-Content-Type-Options: nosniff: MIME type sniffing을 막아 악성 파일 업로드 위험을 줄입니다.
    2. X-Frame-Options: DENY: 사이트가 iframe에 embed되지 않도록 해 clickjacking 공격을 막습니다.
    3. Referrer-Policy: strict-origin-when-cross-origin: request에 referrer 정보를 얼마나 포함할지 제어해 보안과 기능의 균형을 맞춥니다.
  2. Service Worker 전용 Header:
    1. Content-Type: application/javascript; charset=utf-8: service worker가 JavaScript로 올바르게 해석되도록 합니다.
    2. Cache-Control: no-cache, no-store, must-revalidate: service worker가 cache되지 않게 해 사용자가 항상 최신 버전을 받도록 합니다.
    3. Content-Security-Policy: default-src 'self'; script-src 'self': service worker에 엄격한 Content Security Policy를 적용해 같은 origin의 script만 허용합니다.
  1. Global Headers (applied to all routes):
    1. X-Content-Type-Options: nosniff: Prevents MIME type sniffing, reducing the risk of malicious file uploads.
    2. X-Frame-Options: DENY: Protects against clickjacking attacks by preventing your site from being embedded in iframes.
    3. Referrer-Policy: strict-origin-when-cross-origin: Controls how much referrer information is included with requests, balancing security and functionality.
  2. Service Worker Specific Headers:
    1. Content-Type: application/javascript; charset=utf-8: Ensures the service worker is interpreted correctly as JavaScript.
    2. Cache-Control: no-cache, no-store, must-revalidate: Prevents caching of the service worker, ensuring users always get the latest version.
    3. Content-Security-Policy: default-src 'self'; script-src 'self': Implements a strict Content Security Policy for the service worker, only allowing scripts from the same origin.

Extending your PWAPWA 확장하기

  1. Exploring PWA Capabilities: PWA는 다양한 web API를 활용해 고급 기능을 제공할 수 있습니다. background sync, periodic background sync, File System Access API 같은 기능을 살펴보며 애플리케이션을 개선해 보세요. PWA 기능에 대한 아이디어와 최신 정보는 What PWA Can Do Today 같은 자료를 참고할 수 있습니다.
  2. Static Exports: 애플리케이션이 server를 실행하지 않고 파일의 static export를 사용해야 한다면, Next.js configuration을 업데이트해 이를 활성화할 수 있습니다. 자세한 내용은 Next.js Static Export 문서를 참고하세요. 다만 Server Action을 외부 API 호출로 바꾸고, 정의한 header를 proxy로 옮겨야 합니다.
  3. Offline Support: Next.js는 연결 상태를 인식하는 UI와, 실패한 navigation 및 Server Action request의 자동 재시도를 위한 experimental useOffline hook과 이에 대응하는 experimental.useOffline config를 제공합니다. service worker 기반의 완전한 offline caching이 필요하다면 Serwist가 한 가지 선택지이며, Turbopack과 webpack 모두에 대한 Next.js 통합 예제를 제공합니다.
  4. Security Considerations: service worker가 제대로 보호되고 있는지 확인하세요. 여기에는 HTTPS 사용, push message 출처 검증, 적절한 error 처리 구현이 포함됩니다.
  5. User Experience: 사용자의 브라우저가 특정 PWA 기능을 지원하지 않을 때도 앱이 잘 동작하도록 progressive enhancement 기법 적용을 고려하세요.
  1. Exploring PWA Capabilities: PWAs can leverage various web APIs to provide advanced functionality. Consider exploring features like background sync, periodic background sync, or the File System Access API to enhance your application. For inspiration and up-to-date information on PWA capabilities, you can refer to resources like What PWA Can Do Today.
  2. Static Exports: If your application requires not running a server, and instead using a static export of files, you can update the Next.js configuration to enable this change. Learn more in the Next.js Static Export documentation. However, you will need to move from Server Actions to calling an external API, as well as moving your defined headers to your proxy.
  3. Offline Support: Next.js provides an experimental useOffline hook and matching experimental.useOffline config for connectivity-aware UI and automatic retries of failed navigation and Server Action requests. For full service-worker-based offline caching, one option is Serwist, which provides Next.js integration examples for both Turbopack and webpack.
  4. Security Considerations: Ensure that your service worker is properly secured. This includes using HTTPS, validating the source of push messages, and implementing proper error handling.
  5. User Experience: Consider implementing progressive enhancement techniques to ensure your app works well even when certain PWA features are not supported by the user's browser.
