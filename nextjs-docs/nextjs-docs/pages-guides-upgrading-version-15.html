How to upgrade to version 15버전 15로 업그레이드하기

Upgrading from 14 to 1514에서 15로 업그레이드하기

Next.js 버전 15로 업데이트하려면 upgrade codemod를 사용할 수 있습니다:

To update to Next.js version 15, you can use the upgrade codemod:

pnpm dlx @next/codemod@canary upgrade latest
npx @next/codemod@canary upgrade latest
yarn dlx @next/codemod@canary upgrade latest
bunx @next/codemod@canary upgrade latest

직접 하고 싶다면 최신 Next와 React 버전을 설치하고 있는지 확인하세요:

If you prefer to do it manually, ensure that you're installing the latest Next & React versions:

pnpm add next@latest react@latest react-dom@latest eslint-config-next@latest
npm install next@latest react@latest react-dom@latest eslint-config-next@latest
yarn add next@latest react@latest react-dom@latest eslint-config-next@latest
bun add next@latest react@latest react-dom@latest eslint-config-next@latest
Good to know
  • peer dependency 경고가 보이면 react와 react-dom을 제안된 버전으로 업데이트하거나, --force 또는 --legacy-peer-deps flag를 사용해 경고를 무시해야 할 수 있습니다. Next.js 15와 React 19가 모두 stable이 되면 이 작업은 필요 없어집니다.
  • If you see a peer dependencies warning, you may need to update react and react-dom to the suggested versions, or use the --force or --legacy-peer-deps flag to ignore the warning. This won't be necessary once both Next.js 15 and React 19 are stable.

React 19

  • Pages Router는 React 18과 React 19를 모두 지원하므로, react와 react-dom을 19로 upgrade하는 것은 선택 사항입니다.
  • useFormState는 useActionState로 대체되었습니다. useFormState hook은 React 19에서도 여전히 사용할 수 있지만 deprecated되었으며 향후 release에서 제거됩니다. useActionState 사용을 권장하며, 여기에는 pending state를 직접 읽는 것 같은 추가 property가 포함되어 있습니다. 자세히 알아보기.
  • 이제 useFormStatus에는 data, method, action 같은 추가 key가 포함됩니다. React 19를 사용하지 않는다면 pending key만 사용할 수 있습니다. 자세히 알아보기.
  • 자세한 내용은 React 19 upgrade guide에서 읽어 보세요.
  • The Pages Router supports both React 18 and React 19, so upgrading react and react-dom to 19 is optional.
  • useFormState has been replaced by useActionState. The useFormState hook is still available in React 19, but it is deprecated and will be removed in a future release. useActionState is recommended and includes additional properties like reading the pending state directly. Learn more.
  • useFormStatus now includes additional keys like data, method, and action. If you are not using React 19, only the pending key is available. Learn more.
  • Read more in the React 19 upgrade guide.
Good to know

TypeScript를 사용한다면 @types/react와 @types/react-dom도 최신 버전으로 upgrade하세요.

If you are using TypeScript, ensure you also upgrade @types/react and @types/react-dom to their latest versions.

next/font

@next/font package가 제거되고 built-in next/font로 대체되었습니다. import 이름을 안전하고 자동으로 바꿔 주는 codemod가 제공됩니다.

The @next/font package has been removed in favor of the built-in next/font. A codemod is available to safely and automatically rename your imports.

JSapp/layout.js
// Before
import { Inter } from '@next/font/google'

// After
import { Inter } from 'next/font/google'

bundlePagesRouterDependencies

experimental.bundlePagesExternals가 이제 stable이 되었고 이름이 bundlePagesRouterDependencies로 바뀌었습니다.

experimental.bundlePagesExternals is now stable and renamed to bundlePagesRouterDependencies.

JSnext.config.js
/** @type {import('next').NextConfig} */
const nextConfig = {
  // Before
  experimental: {
    bundlePagesExternals: true,
  },

  // After
  bundlePagesRouterDependencies: true,
}

module.exports = nextConfig

serverExternalPackages

experimental.serverComponentsExternalPackages가 이제 stable이 되었고 이름이 serverExternalPackages로 바뀌었습니다.

experimental.serverComponentsExternalPackages is now stable and renamed to serverExternalPackages.

JSnext.config.js
/** @type {import('next').NextConfig} */
const nextConfig = {
  // Before
  experimental: {
    serverComponentsExternalPackages: ['package-name'],
  },

  // After
  serverExternalPackages: ['package-name'],
}

module.exports = nextConfig

Speed Insights

Next.js 15에서 Speed Insights의 자동 instrumentation이 제거되었습니다.

Auto instrumentation for Speed Insights was removed in Next.js 15.

Speed Insights를 계속 사용하려면 Vercel Speed Insights Quickstart guide를 따르세요.

To continue using Speed Insights, follow the Vercel Speed Insights Quickstart guide.

NextRequest Geolocation

NextRequest의 geo와 ip property는 hosting provider가 제공하는 값이므로 제거되었습니다. 이 migration을 자동화하는 codemod가 제공됩니다.

The geo and ip properties on NextRequest have been removed as these values are provided by your hosting provider. A codemod is available to automate this migration.

Vercel을 사용한다면 대신 @vercel/functions의 geolocation과 ipAddress 함수를 사용할 수 있습니다:

If you are using Vercel, you can alternatively use the geolocation and ipAddress functions from @vercel/functions instead:

TSmiddleware.ts
import { geolocation } from '@vercel/functions'
import type { NextRequest } from 'next/server'

export function middleware(request: NextRequest) {
  const { city } = geolocation(request)

  // ...
}
TSmiddleware.ts
import { ipAddress } from '@vercel/functions'
import type { NextRequest } from 'next/server'

export function middleware(request: NextRequest) {
  const ip = ipAddress(request)

  // ...
}

Troubleshooting문제 해결

Installation fails after upgrading to React 19React 19로 upgrade한 뒤 설치가 실패하는 경우

  • [ ] 다른 package의 peer dependency가 React 19를 거부한다면, target Next.js 버전과 router가 지원하는 한 react, react-dom, 그 type, 그리고 (있다면) react-is를 이전 버전으로 되돌리세요.
  • [ ] upgrade가 package.json이나 pnpm-workspace.yaml에 추가한 React type override 또는 resolution을 원래대로 되돌리거나 제거하세요.
  • [ ] 설치 때문에 upgrade command가 중단되었다면, 고친 dependency를 유지하도록 --skip-react-upgrade와 함께 똑같은 target으로 다시 시도하세요. Next.js가 이미 target과 일치한다면 dependency를 설치하고 건너뛴 codemod를 개별적으로 실행하세요. 그런 다음 앱의 check를 실행하세요.
  • [ ] If another package's peer dependencies reject React 19, revert react, react-dom, their types, and react-is (if present) to the previous versions, provided the target Next.js version and router support them.
  • [ ] Restore or remove React type overrides or resolutions added by the upgrade in package.json or pnpm-workspace.yaml.
  • [ ] If installation interrupted the upgrade command, retry the same exact target with --skip-react-upgrade to preserve the repaired dependencies. If Next.js already matches the target, install dependencies and run any skipped codemods individually. Run the app's checks.

Installation fails after upgrading to ESLint 9ESLint 9로 upgrade한 뒤 설치가 실패하는 경우

  • [ ] 다른 package의 peer dependency가 ESLint 9를 거부한다면, eslint, eslint-config-next, (있다면) @next/eslint-plugin-next의 이전 호환 버전과 이전 lint configuration을 복원하세요.
  • [ ] 설치 때문에 upgrade command가 중단되었다면, 고친 dependency를 유지하도록 --skip-eslint-upgrade와 함께 똑같은 target으로 다시 시도하세요. Next.js가 이미 target과 일치한다면 dependency를 설치하고 건너뛴 codemod를 개별적으로 실행하세요. 필요한 lint migration을 직접 완료한 다음 앱의 lint check를 실행하세요.
  • [ ] If another package's peer dependencies reject ESLint 9, restore the previous compatible versions of eslint, eslint-config-next, and @next/eslint-plugin-next (if present), along with the previous lint configuration.
  • [ ] If installation interrupted the upgrade command, retry the same exact target with --skip-eslint-upgrade to preserve the repaired dependency. If Next.js already matches the target, install dependencies and run any skipped codemods individually. Complete any required lint migration manually, then run the app's lint checks.

Review migration checklistmigration checklist 검토하기

앱에 해당하는 변경을 적용한 뒤, migration이 완료되었다고 판단하기 전에 다음 action item들을 검토하세요:

After applying the changes relevant to your app, review these action items before you consider the migration complete:

  • [ ] React dependency와 type이 앱의 router에 대한 React 19 요구 사항을 충족합니다.
  • [ ] font import가 @next/font 대신 next/font를 사용합니다.
  • [ ] 기존 bundlePagesExternals와 serverComponentsExternalPackages 설정이 package configuration을 유지한 채 문서화된 stable 이름을 사용합니다.
  • [ ] NextRequest의 geo와 ip를 사용하는 곳이 실제 hosting provider에 맞는 적절한 source를 사용합니다.
  • [ ] 자동 Speed Insights instrumentation에 의존하던 앱이 여전히 필요하다면 명시적인 integration을 갖추고 있습니다.
  • [ ] 앱이 지원하는 check와 영향을 받는 runtime 동작이 모두 통과합니다. 꼭 통과해야 하는 check가 아직 실패한다면 migration은 완료되지 않은 것입니다.
  • [ ] React dependencies and types meet the React 19 requirements for the app's router.
  • [ ] Font imports use next/font instead of @next/font.
  • [ ] Existing bundlePagesExternals and serverComponentsExternalPackages settings use their documented stable names while preserving package configuration.
  • [ ] NextRequest geo and ip consumers use an appropriate source for the actual hosting provider.
  • [ ] Apps that relied on automatic Speed Insights instrumentation have an explicit integration if they still need it.
  • [ ] The app's supported checks and affected runtime behavior pass. Remaining required failures keep the migration incomplete.
