LinkLink 컴포넌트

<Link>는 HTML <a> element를 확장해 route 간 prefetching과 client-side navigation을 제공하는 React component입니다. Next.js에서 route 간에 이동하는 주된 방법입니다.

<Link> is a React component that extends the HTML <a> element to provide prefetching and client-side navigation between routes. It is the primary way to navigate between routes in Next.js.

기본 사용법:

Basic usage:

TSJSpages/index.tsx
import Link from 'next/link'

export default function Home() {
  return <Link href="/dashboard">Dashboard</Link>
}
import Link from 'next/link'

export default function Home() {
  return <Link href="/dashboard">Dashboard</Link>
}

scroll

기본값은 true입니다. Next.js에서 <Link>의 기본 scroll 동작은 브라우저가 뒤로 가기/앞으로 가기 navigation을 처리하는 방식과 비슷하게 scroll 위치를 유지하는 것입니다. 새 Page로 이동할 때, Page가 viewport에 보이는 한 scroll 위치는 그대로 유지됩니다. 하지만 Page가 viewport에 보이지 않으면 Next.js는 첫 번째 Page element의 맨 위로 scroll합니다.

Defaults to true. The default scrolling behavior of <Link> in Next.js is to maintain scroll position, similar to how browsers handle back and forwards navigation. When you navigate to a new Page, scroll position will stay the same as long as the Page is visible in the viewport. However, if the Page is not visible in the viewport, Next.js will scroll to the top of the first Page element.

scroll = {false}이면 Next.js는 첫 번째 Page element로 scroll하려고 시도하지 않습니다.

When scroll = {false}, Next.js will not attempt to scroll to the first Page element.

Good to know

Next.js는 scroll 동작을 관리하기 전에 scroll: false인지 확인합니다. scroll이 활성화되어 있으면 navigation에 관련된 DOM node를 찾아 각 top-level element를 검사합니다. scroll할 수 없는 element와 렌더링된 HTML이 없는 element는 모두 건너뛰며, 여기에는 sticky 또는 fixed로 position이 지정된 element와 getBoundingClientRect로 계산했을 때 보이지 않는 element 등이 포함됩니다. 그런 다음 Next.js는 viewport에 보이는 scroll 가능한 element를 찾을 때까지 sibling element를 계속 탐색합니다.

Next.js checks if scroll: false before managing scroll behavior. If scrolling is enabled, it identifies the relevant DOM node for navigation and inspects each top-level element. All non-scrollable elements and those without rendered HTML are bypassed, this includes sticky or fixed positioned elements, and non-visible elements such as those calculated with getBoundingClientRect. Next.js then continues through siblings until it identifies a scrollable element that is visible in the viewport.

import Link from 'next/link'

export default function Home() {
  return (
    <Link href="/dashboard" scroll={false}>
      Dashboard
    </Link>
  )
}
import Link from 'next/link'

export default function Home() {
  return (
    <Link href="/dashboard" scroll={false}>
      Dashboard
    </Link>
  )
}

prefetch

Prefetching은 <Link /> component가 사용자의 viewport에 들어올 때(처음부터 또는 scroll을 통해) 일어납니다. Next.js는 client-side navigation의 성능을 높이기 위해 연결된 route(href로 지정)와 data를 background에서 prefetch하고 로드합니다. Prefetching은 production에서만 활성화됩니다.

Prefetching happens when a <Link /> component enters the user's viewport (initially or through scroll). Next.js prefetches and loads the linked route (denoted by the href) and data in the background to improve the performance of client-side navigation. Prefetching is only enabled in production.

prefetch prop에는 다음 값을 전달할 수 있습니다:

The following values can be passed to the prefetch prop:

  • true (default): 전체 route와 그 data가 prefetch됩니다.
  • false: viewport에 들어올 때는 prefetching이 일어나지 않지만, hover할 때는 일어납니다. hover 시의 fetching까지 완전히 없애고 싶다면 <a> tag를 사용하거나, hover 시 prefetching 비활성화도 지원하는 App Router를 점진적으로 도입하는 것을 고려하세요.
  • true (default): The full route and its data will be prefetched.
  • false: Prefetching will not happen when entering the viewport, but will happen on hover. If you want to completely remove fetching on hover as well, consider using an <a> tag or incrementally adopting the App Router, which enables disabling prefetching on hover too.

    </Link>

locale

활성 locale이 자동으로 앞에 붙습니다. locale을 사용하면 다른 locale을 지정할 수 있습니다. false이면 기본 동작이 비활성화되므로 href에 locale을 직접 포함해야 합니다.

The active locale is automatically prepended. locale allows for providing a different locale. When false href has to include the locale as the default behavior is disabled.

TSJSpages/index.tsx
import Link from 'next/link'

export default function Home() {
  return (
    <>
      {/* Default behavior: locale is prepended */}
      <Link href="/dashboard">Dashboard (with locale)</Link>

      {/* Disable locale prepending */}
      <Link href="/dashboard" locale={false}>
        Dashboard (without locale)
      </Link>

      {/* Specify a different locale */}
      <Link href="/dashboard" locale="fr">
        Dashboard (French)
      </Link>
    </>
  )
}

onNavigate

client-side navigation 중에 호출되는 event handler입니다. handler는 preventDefault() method를 포함한 event object를 받으므로, 필요하면 navigation을 취소할 수 있습니다.

An event handler called during client-side navigation. The handler receives an event object that includes a preventDefault() method, allowing you to cancel the navigation if needed.

TSJSapp/page.tsx
import Link from 'next/link'

export default function Page() {
  return (
    <Link
      href="/dashboard"
      onNavigate={(e) => {
        // Only executes during SPA navigation
        console.log('Navigating...')

        // Optionally prevent navigation
        // e.preventDefault()
      }}
    >
      Dashboard
    </Link>
  )
}

Good to know

onClick과 onNavigate는 비슷해 보이지만 목적이 다릅니다. onClick은 모든 click event에서 실행되는 반면, onNavigate는 client-side navigation 중에만 실행됩니다. 주요 차이점은 다음과 같습니다:

  • modifier key(Ctrl/Cmd + Click)를 사용하면, Next.js가 새 탭에 대한 기본 navigation을 막기 때문에 onClick은 실행되지만 onNavigate는 실행되지 않습니다.
  • onNavigate는 client-side 및 same-origin navigation 전용이므로 외부 URL에서는 trigger되지 않습니다.
  • download attribute가 있는 link는 브라우저가 연결된 URL을 다운로드로 처리하므로 onClick에서는 동작하지만 onNavigate에서는 동작하지 않습니다.

While onClick and onNavigate may seem similar, they serve different purposes. onClick executes for all click events, while onNavigate only runs during client-side navigation. Some key differences:

  • When using modifier keys (Ctrl/Cmd + Click), onClick executes but onNavigate doesn't since Next.js prevents default navigation for new tabs.
  • External URLs won't trigger onNavigate since it's only for client-side and same-origin navigations.
  • Links with the download attribute will work with onClick but not onNavigate since the browser will treat the linked URL as a download.

This is a browser CSS property that offsets scroll-based positioning. It applies whenever Next.js uses the native scrollIntoView() API, including hash fragment (#id) navigation. Alternatively, you can use scroll-margin-top on individual target elements instead of setting a global offset.

Prefetching links in ProxyProxy에서 link prefetch하기

인증이나 사용자를 다른 페이지로 rewrite하는 등의 목적으로 Proxy를 사용하는 경우가 많습니다. <Link /> component가 Proxy를 통한 rewrite가 있는 link를 올바르게 prefetch하려면, 표시할 URL과 prefetch할 URL을 모두 Next.js에 알려 주어야 합니다. 이는 prefetch할 올바른 route를 알기 위해 proxy에 불필요한 fetch를 보내는 것을 피하기 위해 필요합니다.

It's common to use Proxy for authentication or other purposes that involve rewriting the user to a different page. In order for the <Link /> component to properly prefetch links with rewrites via Proxy, you need to tell Next.js both the URL to display and the URL to prefetch. This is required to avoid un-necessary fetches to proxy to know the correct route to prefetch.

예를 들어 인증된 사용자용 view와 방문자용 view가 있는 /dashboard route를 제공하려면, Proxy에 다음을 추가해 사용자를 올바른 페이지로 redirect할 수 있습니다:

For example, if you want to serve a /dashboard route that has authenticated and visitor views, you can add the following in your Proxy to redirect the user to the correct page:

TSJSproxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  const nextUrl = request.nextUrl
  if (nextUrl.pathname === '/dashboard') {
    if (request.cookies.has('authToken')) {
      return NextResponse.rewrite(new URL('/auth/dashboard', request.url))
    } else {
      return NextResponse.rewrite(new URL('/public/dashboard', request.url))
    }
  }
}
import { NextResponse } from 'next/server'

export function proxy(request) {
  const nextUrl = request.nextUrl
  if (nextUrl.pathname === '/dashboard') {
    if (request.cookies.has('authToken')) {
      return NextResponse.rewrite(new URL('/auth/dashboard', request.url))
    } else {
      return NextResponse.rewrite(new URL('/public/dashboard', request.url))
    }
  }
}

이 경우 <Link /> component에서는 다음 코드를 사용하면 됩니다:

In this case, you would want to use the following code in your <Link /> component:

import Link from 'next/link'
import useIsAuthed from './hooks/useIsAuthed' // Your auth hook

export default function Home() {
  const isAuthed = useIsAuthed()
  const path = isAuthed ? '/auth/dashboard' : '/public/dashboard'
  return (
    <Link as="/dashboard" href={path}>
      Dashboard
    </Link>
  )
}

Good to know

Dynamic Routes를 사용한다면 as와 href props를 조정해야 합니다. 예를 들어 proxy를 통해 다르게 보여 주고 싶은 /dashboard/authed/[user] 같은 Dynamic Route가 있다면 다음과 같이 작성합니다: <Link href={{ pathname: '/dashboard/authed/[user]', query: { user: username } }} as="/dashboard/[user]">Profile</Link>.

If you're using Dynamic Routes, you'll need to adapt your as and href props. For example, if you have a Dynamic Route like /dashboard/authed/[user] that you want to present differently via proxy, you would write: <Link href={{ pathname: '/dashboard/authed/[user]', query: { user: username } }} as="/dashboard/[user]">Profile</Link>.
