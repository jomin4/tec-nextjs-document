Mutating Data데이터 변경하기

Next.js에서는 React Server Functions를 사용해 데이터를 mutate할 수 있습니다. 이 페이지에서는 Server Function을 만드는 방법과 호출하는 방법을 살펴봅니다. Next.js 고유의 동작(single-roundtrip response, sequential dispatch, security, deployment)은 Server Actions and Mutations를 참고하세요.

You can mutate data in Next.js using React Server Functions. This page will go through how you can create and invoke Server Functions. For Next.js-specific behaviors (single-roundtrip response, sequential dispatch, security, deployment), see Server Actions and Mutations.

What are Server Functions?Server Function이란?

Server Function은 server에서 실행되는 비동기 함수입니다. client에서 network request를 통해 호출할 수 있으며, 그래서 반드시 비동기여야 합니다.

A Server Function is an asynchronous function that runs on the server. You can call them from the client through a network request, which is why they must be asynchronous.

action이나 mutation 맥락에서는 Server Actions라고도 부릅니다.

In an action or mutation context, they are also called Server Actions.

convention(관례)상 Server Action은 startTransition과 함께 사용되는 async 함수입니다. 함수가 다음과 같이 전달되면 이 처리가 자동으로 이루어집니다:

By convention, a Server Action is an async function used with startTransition. This happens automatically when the function is:

  • action prop으로 <form>에 전달될 때.
  • formAction prop으로 <button>에 전달될 때.
  • Passed to a <form> using the action prop.
  • Passed to a <button> using the formAction prop.

action이 호출되면 Next.js는 업데이트된 UI와 새 데이터를 한 번의 server roundtrip으로 함께 반환할 수 있습니다.

When an action is invoked, Next.js can return both the updated UI and new data in a single server roundtrip.

내부적으로 action은 POST method를 사용하며, 오직 이 HTTP method로만 호출할 수 있습니다.

Behind the scenes, actions use the POST method, and only this HTTP method can invoke them.

Warning

Server Function은 애플리케이션 UI를 통해서만이 아니라 직접 보낸 POST request로도 접근할 수 있습니다. 모든 Server Function 안에서 항상 authentication과 authorization을 확인하세요. 권장 패턴은 Data Security 가이드를 참고하세요.

Server Functions are reachable via direct POST requests, not just through your application's UI. Always verify authentication and authorization inside every Server Function. See the Data Security guide for recommended patterns.

Good to know

Server Action은 특정한 방식(form 제출과 mutation 처리)으로 사용되는 Server Function입니다. Server Function이 더 넓은 의미의 용어입니다.

A Server Action is a Server Function used in a specific way (for handling form submissions and mutations). Server Function is the broader term.

Creating Server FunctionsServer Function 만들기

Server Function은 use server directive를 사용해 정의할 수 있습니다. directive를 비동기 함수의 맨 위에 두면 그 함수를 Server Function으로 표시하고, 별도 파일의 맨 위에 두면 그 파일의 모든 export를 표시합니다.

A Server Function can be defined by using the use server directive. You can place the directive at the top of an asynchronous function to mark the function as a Server Function, or at the top of a separate file to mark all exports of that file.

TSJSapp/lib/actions.ts
import { auth } from '@/lib/auth'

export async function createPost(formData: FormData) {
  'use server'
  const session = await auth()
  if (!session?.user) {
    throw new Error('Unauthorized')
  }

  const title = formData.get('title')
  const content = formData.get('content')

  // Mutate data
  // Revalidate cache
}

export async function deletePost(formData: FormData) {

    throw new Error('Unauthorized')
  }

Server Components

Server Component 안에서는 함수 본문 맨 위에 "use server" directive를 추가해 Server Function을 inline으로 정의할 수 있습니다:

Server Functions can be inlined in Server Components by adding the "use server" directive to the top of the function body:

TSJSapp/page.tsx
export default function Page() {
  // Server Action
  async function createPost(formData: FormData) {
    'use server'
    // ...
  }

  return <></>
}
export default function Page() {
  // Server Action
  async function createPost(formData) {
    'use server'
    // ...
  }

  return <></>
}
Good to know

Server Component는 기본적으로 progressive enhancement를 지원합니다. 즉, Server Action을 호출하는 form은 JavaScript가 아직 로드되지 않았거나 비활성화되어 있어도 제출됩니다.

Server Components support progressive enhancement by default, meaning forms that call Server Actions will be submitted even if JavaScript hasn't loaded yet or is disabled.

Client Components

Client Component 안에서는 Server Function을 정의할 수 없습니다. 하지만 맨 위에 "use server" directive가 있는 파일에서 import하면 Client Component에서 호출할 수 있습니다:

It's not possible to define Server Functions in Client Components. However, you can invoke them in Client Components by importing them from a file that has the "use server" directive at the top of it:

TSJSapp/actions.ts
'use server'

export async function createPost() {}
'use server'

export async function createPost() {}
TSJSapp/ui/button.tsx
'use client'

import { createPost } from '@/app/actions'

export function Button() {
  return <button formAction={createPost}>Create</button>
}
'use client'

import { createPost } from '@/app/actions'

export function Button() {
  return <button formAction={createPost}>Create</button>
}
Good to know

Client Component에서 Server Action을 호출하는 form은 JavaScript가 아직 로드되지 않았다면 제출을 queue에 쌓아 두며, hydration 시 우선 처리됩니다. hydration 이후에는 form을 제출해도 브라우저가 새로고침되지 않습니다.

In Client Components, forms invoking Server Actions will queue submissions if JavaScript isn't loaded yet, and will be prioritized for hydration. After hydration, the browser does not refresh on form submission.

Passing actions as propsaction을 props로 전달하기

action을 prop으로 Client Component에 전달할 수도 있습니다:

You can also pass an action to a Client Component as a prop:

<ClientComponent updateItemAction={updateItem} />
TSJSapp/client-component.tsx
'use client'

export default function ClientComponent({
  updateItemAction,
}: {
  updateItemAction: (formData: FormData) => void
}) {
  return <form action={updateItemAction}>{/* ... */}</form>
}
'use client'

export default function ClientComponent({ updateItemAction }) {
  return <form action={updateItemAction}>{/* ... */}</form>
}

Invoking Server FunctionsServer Function 호출하기

Server Function을 호출하는 주요 방법은 두 가지입니다:

There are two main ways you can invoke a Server Function:

  1. Server Component와 Client Component의 Form
  2. Client Component의 Event Handler와 useEffect
  1. Forms in Server and Client Components
  2. Event Handlers and useEffect in Client Components
Good to know

Server Function은 server-side mutation을 위해 설계되었습니다. client는 이를 한 번에 하나씩 dispatch하고 await합니다. Sequential dispatch on the client를 참고하세요. 병렬 data fetching이 필요하다면 Server Component에서 data fetching을 사용하거나, 하나의 Server Function 또는 Route Handler 안에서 병렬 작업을 수행하세요.

Server Functions are designed for server-side mutations. The client dispatches and awaits them one at a time. See Sequential dispatch on the client. If you need parallel data fetching, use data fetching in Server Components, or perform parallel work inside a single Server Function or Route Handler.

Forms

React는 HTML <form> element를 확장해, HTML action prop으로 Server Function을 호출할 수 있게 합니다.

React extends the HTML <form> element to allow a Server Function to be invoked with the HTML action prop.

form에서 호출되면 함수는 FormData object를 자동으로 받습니다. native FormData method를 사용해 데이터를 추출할 수 있습니다:

When invoked in a form, the function automatically receives the FormData object. You can extract the data using the native FormData methods:

TSJSapp/ui/form.tsx
import { createPost } from '@/app/actions'

export function Form() {
  return (
    <form action={createPost}>
      <input type="text" name="title" />
      <input type="text" name="content" />
      <button type="submit">Create</button>
    </form>
  )
}

Event Handlers

Client Component에서는 onClick 같은 event handler를 사용해 Server Function을 호출할 수 있습니다.

You can invoke a Server Function in a Client Component by using event handlers such as onClick.

TSJSapp/like-button.tsx
'use client'

import { incrementLike } from './actions'
import { useState } from 'react'

export default function LikeButton({ initialLikes }: { initialLikes: number }) {
  const [likes, setLikes] = useState(initialLikes)

  return (
    <>
      <p>Total Likes: {likes}</p>
      <button
        onClick={async () => {
          const updatedLikes = await incrementLike()
          setLikes(updatedLikes)
        }}
      >
        Like
      </button>
    </>
  )
}

Examples예제

Showing a pending statepending state 표시하기

Server Function을 실행하는 동안 React의 useActionState hook으로 loading indicator를 보여 줄 수 있습니다. 이 hook은 pending boolean을 반환합니다:

While executing a Server Function, you can show a loading indicator with React's useActionState hook. This hook returns a pending boolean:

TSJSapp/ui/button.tsx
'use client'

import { useActionState, startTransition } from 'react'
import { createPost } from '@/app/actions'
import { LoadingSpinner } from '@/app/ui/loading-spinner'

export function Button() {
  const [state, action, pending] = useActionState(createPost, false)

  return (
    <button onClick={() => startTransition(action)}>
      {pending ? <LoadingSpinner /> : 'Create Post'}
    </button>
  )
}
'use client'

import { useActionState, startTransition } from 'react'
import { createPost } from '@/app/actions'
import { LoadingSpinner } from '@/app/ui/loading-spinner'

export function Button() {
  const [state, action, pending] = useActionState(createPost, false)

  return (
    <button onClick={() => startTransition(action)}>
      {pending ? <LoadingSpinner /> : 'Create Post'}
    </button>
  )
}

pending feedback, optimistic UI, transition, error handling 등 반응성 있는 interaction을 더 깊이 살펴보려면 Building interactive apps 가이드를 참고하세요.

See the Building interactive apps guide for a deeper walkthrough of responsive interactions, including pending feedback, optimistic UI, transitions, and error handling.

Good to know

experimental 기능인 useOffline config를 활성화하면, 연결이 끊겨 중단된 Server Action은 pending 상태로 남아 있다가 network가 돌아오면 완료됩니다.

With the experimental useOffline config enabled, a Server Action interrupted by a connectivity drop stays pending and completes when the network returns.

Refresh data데이터 새로고침

mutation 후에는 최신 데이터를 보여 주기 위해 현재 page를 새로고침하고 싶을 수 있습니다. Server Action 안에서 next/cache의 refresh를 호출하면 됩니다:

After a mutation, you may want to refresh the current page to show the latest data. You can do this by calling refresh from next/cache in a Server Action:

TSJSapp/lib/actions.ts
'use server'

import { auth } from '@/lib/auth'
import { refresh } from 'next/cache'

export async function updatePost(formData: FormData) {
  const session = await auth()
  if (!session?.user) {
    throw new Error('Unauthorized')
  }
  // Mutate data
  // ...

  refresh()
}
'use server'

import { auth } from '@/lib/auth'
import { refresh } from 'next/cache'

export async function updatePost(formData) {
  const session = await auth()
  if (!session?.user) {
    throw new Error('Unauthorized')
  }
  // Mutate data
  // ...

  refresh()
}

이렇게 하면 client router가 새로고침되어 UI가 최신 state를 반영합니다. refresh() 함수는 tag가 지정된 데이터를 revalidate하지 않습니다. tag가 지정된 데이터를 revalidate하려면 대신 updateTag나 revalidateTag를 사용하세요.

This refreshes the client router, ensuring the UI reflects the latest state. The refresh() function does not revalidate tagged data. To revalidate tagged data, use updateTag or revalidateTag instead.

Revalidate data데이터 revalidate하기

mutation을 수행한 후 Server Function 안에서 revalidatePath나 revalidateTag를 호출하면 Next.js cache를 revalidate하고 업데이트된 데이터를 보여 줄 수 있습니다:

After performing a mutation, you can revalidate the Next.js cache and show the updated data by calling revalidatePath or revalidateTag within the Server Function:

TSJSapp/lib/actions.ts
import { auth } from '@/lib/auth'
import { revalidatePath } from 'next/cache'

export async function createPost(formData: FormData) {
  'use server'
  const session = await auth()
  if (!session?.user) {
    throw new Error('Unauthorized')
  }
  // Mutate data
  // ...

  revalidatePath('/posts')
}
import { auth } from '@/lib/auth'
import { revalidatePath } from 'next/cache'

export async function createPost(formData) {
  'use server'
  const session = await auth()
  if (!session?.user) {
    throw new Error('Unauthorized')
  }
  // Mutate data
  // ...
  revalidatePath('/posts')
}

Redirect after a mutationmutation 후 redirect하기

mutation 후 사용자를 다른 page로 redirect하고 싶을 수 있습니다. Server Function 안에서 redirect를 호출하면 됩니다.

You may want to redirect the user to a different page after a mutation. You can do this by calling redirect within the Server Function.

TSJSapp/lib/actions.ts
'use server'

import { auth } from '@/lib/auth'
import { revalidatePath } from 'next/cache'
import { redirect } from 'next/navigation'

export async function createPost(formData: FormData) {
  const session = await auth()
  if (!session?.user) {
    throw new Error('Unauthorized')
  }
  // Mutate data
  // ...

  revalidatePath('/posts')
  redirect('/posts')
}
'use server'

import { auth } from '@/lib/auth'
import { revalidatePath } from 'next/cache'
import { redirect } from 'next/navigation'

export async function createPost(formData) {
  const session = await auth()
  if (!session?.user) {
    throw new Error('Unauthorized')
  }
  // Mutate data
  // ...

  revalidatePath('/posts')
  redirect('/posts')
}

redirect를 호출하면 framework가 처리하는 control-flow exception을 throw합니다. 그 뒤의 코드는 실행되지 않습니다. 최신 데이터가 필요하다면 그 전에 revalidatePath나 revalidateTag를 호출하세요.

Calling redirect throws a framework handled control-flow exception. Any code after it won't execute. If you need fresh data, call revalidatePath or revalidateTag beforehand.

Cookies

Server Action 안에서 cookies API를 사용해 cookie를 get, set, delete할 수 있습니다.

You can get, set, and delete cookies inside a Server Action using the cookies API.

Server Action에서 cookie를 set하거나 delete하면, Next.js는 server에서 현재 page와 그 layout을 다시 render하여 UI가 새 cookie 값을 반영하도록 합니다.

When you set or delete a cookie in a Server Action, Next.js re-renders the current page and its layouts on the server so the UI reflects the new cookie value.

Good to know

server 업데이트는 현재 React tree에 적용되며, 필요에 따라 component를 re-render, mount, unmount합니다. re-render되는 component의 client state는 유지되고, effect는 dependency가 바뀐 경우 다시 실행됩니다.

The server update applies to the current React tree, re-rendering, mounting, or unmounting components, as needed. Client state is preserved for re-rendered components, and effects re-run if their dependencies changed.

TSJSapp/actions.ts
'use server'

import { cookies } from 'next/headers'

export async function exampleAction() {
  const cookieStore = await cookies()

  // Get cookie
  cookieStore.get('name')?.value

  // Set cookie
  cookieStore.set('name', 'Delba')

  // Delete cookie
  cookieStore.delete('name')
}

useEffect

React의 useEffect hook을 사용하면 component가 mount되거나 dependency가 바뀔 때 Server Action을 호출할 수 있습니다. 이는 global event에 의존하거나 자동으로 trigger되어야 하는 mutation에 유용합니다. 예를 들어 앱 단축키를 위한 onKeyDown, 무한 스크롤을 위한 intersection observer hook, 또는 component가 mount될 때 조회수를 업데이트하는 경우가 있습니다:

You can use the React useEffect hook to invoke a Server Action when the component mounts or a dependency changes. This is useful for mutations that depend on global events or need to be triggered automatically. For example, onKeyDown for app shortcuts, an intersection observer hook for infinite scrolling, or when the component mounts to update a view count:

TSJSapp/view-count.tsx
'use client'

import { incrementViews } from './actions'
import { useState, useEffect, useTransition } from 'react'

export default function ViewCount({ initialViews }: { initialViews: number }) {
  const [views, setViews] = useState(initialViews)
  const [isPending, startTransition] = useTransition()

  useEffect(() => {
    startTransition(async () => {
      const updatedViews = await incrementViews()
      setViews(updatedViews)
    })
  }, [])

  // You can use `isPending` to give users feedback
  return <p>Total Views: {views}</p>
}
