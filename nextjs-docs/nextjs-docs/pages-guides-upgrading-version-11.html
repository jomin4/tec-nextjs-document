How to upgrade to version 11버전 11로 업그레이드하기

버전 11로 upgrade하려면 다음 command를 실행하세요:

To upgrade to version 11, run the following command:

>_Terminal
npm i next@11 react@17 react-dom@17
>_Terminal
yarn add next@11 react@17 react-dom@17
>_Terminal
pnpm up next@11 react@17 react-dom@17
>_Terminal
bun add next@11 react@17 react-dom@17
Good to know

TypeScript를 사용한다면 @types/react와 @types/react-dom도 해당 버전에 맞게 upgrade하세요.

If you are using TypeScript, ensure you also upgrade @types/react and @types/react-dom to their corresponding versions.

Webpack 5

이제 Webpack 5가 모든 Next.js 애플리케이션의 기본값입니다. custom webpack configuration이 없었다면 애플리케이션은 이미 webpack 5를 사용하고 있습니다. custom webpack configuration이 있다면 upgrade 안내는 Next.js webpack 5 문서를 참고하세요.

Webpack 5 is now the default for all Next.js applications. If you did not have a custom webpack configuration, your application is already using webpack 5. If you do have a custom webpack configuration, you can refer to the Next.js webpack 5 documentation for upgrade guidance.

Cleaning the distDir is now a default이제 distDir 정리가 기본 동작

build output directory(기본값 .next)는 이제 Next.js cache를 제외하고 기본적으로 비워집니다. 자세한 내용은 distDir 정리 RFC를 참고하세요.

The build output directory (defaults to .next) is now cleared by default except for the Next.js caches. You can refer to the cleaning distDir RFC for more information.

애플리케이션이 이전 동작에 의존하고 있었다면 next.config.js에 cleanDistDir: false flag를 추가해 새 기본 동작을 비활성화할 수 있습니다.

If your application was relying on this behavior previously you can disable the new default behavior by adding the cleanDistDir: false flag in next.config.js.

PORT is now supported for next dev and next start이제 next dev와 next start에서 PORT 지원

Next.js 11은 애플리케이션이 실행될 port를 설정하는 PORT environment variable을 지원합니다. 여전히 -p/--port 사용을 권장하지만, 어떤 이유로든 -p를 쓸 수 없었다면 이제 대안으로 PORT를 사용할 수 있습니다:

Next.js 11 supports the PORT environment variable to set the port the application runs on. Using -p/--port is still recommended but if you were prohibited from using -p in any way you can now use PORT as an alternative:

예시:

Example:

PORT=4000 next start

next.config.js customization to import images이미지 import를 위한 next.config.js 커스터마이징

Next.js 11은 next/image로 static image import를 지원합니다. 이 새 기능은 image import를 처리할 수 있어야 동작합니다. 이전에 next-images나 next-optimized-images package를 추가했다면 next/image를 사용하는 새 built-in 지원으로 옮기거나, 이 기능을 비활성화할 수 있습니다:

Next.js 11 supports static image imports with next/image. This new feature relies on being able to process image imports. If you previously added the next-images or next-optimized-images packages you can either move to the new built-in support using next/image or disable the feature:

JSnext.config.js
module.exports = {
  images: {
    disableStaticImages: true,
  },
}

Remove super.componentDidCatch() from pages/_app.jspages/_app.js에서 super.componentDidCatch() 제거

next/app component의 componentDidCatch는 더 이상 필요하지 않아 Next.js 9에서 deprecated되었고, 그 이후로는 아무 동작도 하지 않았습니다(no-op). Next.js 11에서 제거되었습니다.

The next/app component's componentDidCatch was deprecated in Next.js 9 as it's no longer needed and has since been a no-op. In Next.js 11, it was removed.

pages/_app.js에 custom componentDidCatch method가 있다면 더 이상 필요 없으므로 super.componentDidCatch를 제거해도 됩니다.

If your pages/_app.js has a custom componentDidCatch method you can remove super.componentDidCatch as it is no longer needed.

Remove Container from pages/_app.jspages/_app.js에서 Container 제거

이 export는 더 이상 필요하지 않아 Next.js 9에서 deprecated되었고, 그 이후로는 development 중 경고만 띄우는 no-op이었습니다. Next.js 11에서 제거되었습니다.

This export was deprecated in Next.js 9 as it's no longer needed and has since been a no-op with a warning during development. In Next.js 11 it was removed.

pages/_app.js에서 next/app의 Container를 import하고 있다면, 제거되었으므로 Container를 지워도 됩니다. 자세한 내용은 문서를 참고하세요.

If your pages/_app.js imports Container from next/app you can remove Container as it was removed. Learn more in the documentation.

Remove props.url usage from page componentspage component에서 props.url 사용 제거

이 property는 Next.js 4에서 deprecated되었고 그 이후로 development 중 경고를 표시해 왔습니다. getStaticProps / getServerSideProps가 도입되면서 이 method들은 이미 props.url 사용을 허용하지 않았습니다. Next.js 11에서 완전히 제거되었습니다.

This property was deprecated in Next.js 4 and has since shown a warning during development. With the introduction of getStaticProps / getServerSideProps these methods already disallowed the usage of props.url. In Next.js 11, it was removed completely.

자세한 내용은 문서를 참고하세요.

You can learn more in the documentation.

Remove unsized property on next/imagenext/image의 unsized property 제거

next/image의 unsized property는 Next.js 10.0.1에서 deprecated되었습니다. 대신 layout="fill"을 사용할 수 있습니다. Next.js 11에서 unsized가 제거되었습니다.

The unsized property on next/image was deprecated in Next.js 10.0.1. You can use layout="fill" instead. In Next.js 11 unsized was removed.

Remove modules property on next/dynamicnext/dynamic의 modules property 제거

next/dynamic의 modules와 render option은 Next.js 9.5에서 deprecated되었습니다. 이는 next/dynamic API를 React.lazy에 더 가깝게 만들기 위해서였습니다. Next.js 11에서 modules와 render option이 제거되었습니다.

The modules and render option for next/dynamic were deprecated in Next.js 9.5. This was done in order to make the next/dynamic API closer to React.lazy. In Next.js 11, the modules and render options were removed.

이 option은 Next.js 8 이후로 문서에서 언급되지 않았으므로 애플리케이션에서 사용하고 있을 가능성은 낮습니다.

This option hasn't been mentioned in the documentation since Next.js 8 so it's less likely that your application is using it.

애플리케이션에서 modules와 render를 사용하고 있다면 문서를 참고하세요.

If your application does use modules and render you can refer to the documentation.

Remove Head.rewindHead.rewind 제거

Head.rewind는 Next.js 9.5부터 no-op이었고, Next.js 11에서 제거되었습니다. Head.rewind 사용 부분은 안전하게 제거해도 됩니다.

Head.rewind has been a no-op since Next.js 9.5, in Next.js 11 it was removed. You can safely remove your usage of Head.rewind.

Moment.js locales excluded by defaultMoment.js locale 기본 제외

Moment.js는 기본적으로 많은 locale의 번역을 포함하고 있습니다. 이제 Next.js는 Moment.js를 사용하는 애플리케이션의 bundle 크기를 최적화하기 위해 이 locale들을 기본적으로 자동 제외합니다.

Moment.js includes translations for a lot of locales by default. Next.js now automatically excludes these locales by default to optimize bundle size for applications using Moment.js.

특정 locale을 load하려면 다음 snippet을 사용하세요:

To load a specific locale use this snippet:

import moment from 'moment'
import 'moment/locale/ja'

moment.locale('ja')

새 동작을 원하지 않는다면 next.config.js에 excludeDefaultMomentLocales: false를 추가해 이 새 기본값을 opt-out할 수 있습니다. 다만 이 최적화는 Moment.js의 크기를 크게 줄여 주므로 비활성화하지 않는 것을 강력히 권장합니다.

You can opt-out of this new default by adding excludeDefaultMomentLocales: false to next.config.js if you do not want the new behavior, do note it's highly recommended to not disable this new optimization as it significantly reduces the size of Moment.js.

Update usage of router.eventsrouter.events 사용 방식 업데이트

rendering 중에 router.events에 접근하고 있다면, Next.js 11에서는 prerendering 중에 router.events가 더 이상 제공되지 않습니다. useEffect 안에서 router.events에 접근하도록 하세요:

In case you're accessing router.events during rendering, in Next.js 11 router.events is no longer provided during prerendering. Ensure you're accessing router.events in useEffect:

useEffect(() => {
  const handleRouteChange = (url, { shallow }) => {
    console.log(
      `App is changing to ${url} ${
        shallow ? 'with' : 'without'
      } shallow routing`
    )
  }

  router.events.on('routeChangeStart', handleRouteChange)

  // If the component is unmounted, unsubscribe
  // from the event with the `off` method:
  return () => {
    router.events.off('routeChangeStart', handleRouteChange)
  }
}, [router])

애플리케이션에서 공개되지 않은 internal property였던 router.router.events를 사용하고 있다면, 이 역시 router.events를 사용하도록 바꾸세요.

If your application uses router.router.events which was an internal property that was not public please make sure to use router.events as well.

React 16 to 17React 16에서 17로

React 17은 오랫동안 Next.js에 있던 기능, 즉 JSX를 사용할 때 import React from 'react'를 쓰지 않아도 되는 기능을 더 넓은 React ecosystem으로 가져온 새로운 JSX Transform을 도입했습니다. React 17을 사용하면 Next.js는 자동으로 새 transform을 사용합니다. 이 transform은 React 변수를 global로 만들지 않는데, 이는 이전 Next.js 구현의 의도치 않은 side-effect였습니다. 실수로 import 없이 React를 사용한 경우를 자동으로 고쳐 주는 codemod를 사용할 수 있습니다.

React 17 introduced a new JSX Transform that brings a long-time Next.js feature to the wider React ecosystem: Not having to import React from 'react' when using JSX. When using React 17 Next.js will automatically use the new transform. This transform does not make the React variable global, which was an unintended side-effect of the previous Next.js implementation. A codemod is available to automatically fix cases where you accidentally used React without importing it.

대부분의 애플리케이션은 이미 최신 버전의 React를 사용하고 있으며, Next.js 11에서는 최소 React 버전이 17.0.2로 업데이트되었습니다.

Most applications already use the latest version of React, with Next.js 11 the minimum React version has been updated to 17.0.2.

upgrade하려면 다음 command를 실행하세요:

To upgrade you can run the following command:

npm install react@latest react-dom@latest

또는 yarn을 사용하세요:

Or using yarn:

yarn add react@latest react-dom@latest
