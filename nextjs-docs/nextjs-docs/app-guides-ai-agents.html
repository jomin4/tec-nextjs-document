How Next.js supports AI coding agentsNext.js가 AI coding agent를 지원하는 방법

AI coding agent는 프로젝트에 설치된 Next.js 버전보다 오래된 학습 데이터에 의존할 수 있습니다. agent가 최신 API를 사용하고 작업 결과를 검증할 수 있도록, Next.js는 버전에 맞는 문서, 관리되는 프로젝트 지침(managed project instruction), agent 주도 upgrade, runtime 도구, 구조화된 error, 재사용 가능한 Skill, 선택적인 agent feedback을 제공하고 그 효과를 평가합니다. 결과는 Next.js agent evaluations에서 확인하세요.

AI coding agents may rely on training data that predates the Next.js version installed in a project. To help agents use current APIs and verify their work, Next.js provides and evaluates version-matched documentation, managed project instructions, agent-guided upgrades, runtime tools, structured errors, reusable Skills, and optional agent feedback. See the results in the Next.js agent evaluations.

더 자세한 배경은 Next.js 16.2와 Next.js 16.3에서 소개된 AI tooling에 대한 글을 읽어 보세요.

For more background, read about the AI tooling introduced in Next.js 16.2 and Next.js 16.3.

Version-matched documentation버전에 맞는 문서

Next.js 16.2 이상에는 설치된 framework 버전에 맞는 문서가 포함되어 있습니다. 이 문서는 node_modules/next/dist/docs/에 있으며 Next.js 문서 사이트와 같은 구조를 따릅니다:

Next.js 16.2 and later include documentation that matches the installed framework version. The documentation is available at node_modules/next/dist/docs/ and mirrors the structure of the Next.js documentation site:

node_modules/next/dist/docs/
├── 01-app/
│   ├── 01-getting-started/
│   ├── 02-guides/
│   └── 03-api-reference/
├── 02-pages/
├── 03-architecture/
└── index.mdx

번들된 사본 덕분에 coding agent는 network request나 외부 조회 없이도 프로젝트가 지원하는 API와 패턴을 참고할 수 있습니다. Next.js를 upgrade하면 번들된 문서도 함께 업데이트됩니다.

The bundled copy gives coding agents access to the APIs and patterns supported by the project without a network request or external lookup. Upgrading Next.js also updates the bundled documentation.

Managed documentation instructions관리되는 문서 지침

Next.js는 프로젝트 root의 AGENTS.md에 있는 managed instruction을 통해 번들된 문서를 agent가 찾을 수 있게 합니다. Claude Code, Codex, Cursor, GitHub Copilot 같은 coding agent는 session을 시작할 때 이 파일을 읽습니다.

Next.js makes the bundled documentation discoverable through managed instructions in AGENTS.md at the project root. Coding agents such as Claude Code, Codex, Cursor, and GitHub Copilot read this file when they start a session.

create-next-app은 새 프로젝트에 agent 파일을 만듭니다. 기존 프로젝트에서는 next dev가 coding agent를 감지하면 managed instruction을 만들거나 업데이트합니다. 이 block은 agent가 프로젝트와 함께 설치된 문서를 보도록 안내합니다:

create-next-app creates the agent files for new projects. When next dev detects a coding agent, it creates or updates the managed instructions for existing projects. The block directs the agent to the documentation installed with the project:

AGENTS.md
<!-- BEGIN:nextjs-agent-rules -->

## This is NOT the Next.js you know

This version has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` (resolved from this file's directory; in monorepos the `next` package may not be visible from the repo root) before writing any code. Heed deprecation notices.

This block is written and re-added by `next dev` — verify at `node_modules/next/dist/server/lib/generate-agent-files.js`. Removing it from a diff only re-creates the uncommitted change; committing it with your work keeps the tree clean.

<!-- END:nextjs-agent-rules -->

Next.js는 agent rules marker 사이의 내용만 업데이트하고 AGENTS.md의 나머지 부분은 그대로 유지합니다.

Next.js updates only the content between the agent rules markers and preserves the rest of AGENTS.md.

AGENTS.md와 knowledge Skill을 비교한 연구에 따르면 번들된 문서를 사용했을 때 통과율은 100%였고, Skill 기반 접근 방식은 최대 79%였습니다. 최신 Next.js agent evaluation 결과를 확인하세요.

Research comparing AGENTS.md with knowledge Skills found a 100% pass rate with bundled documentation, compared with up to 79% for Skill-based approaches. See the current Next.js agent evaluation results.

Managed documentation instruction은 Next.js 16.3 이상에서 기본으로 활성화되어 있습니다. 설정하거나 비활성화하려면 agentRules API reference를 참고하세요.

Managed documentation instructions are enabled by default in Next.js 16.3 and later. See the agentRules API reference to configure or disable them.

Version support버전 지원

Next.js 16.3 이상은 번들된 문서를 포함하고 managed agent instruction을 지원합니다. Next.js 16.2는 번들된 문서를 포함하지만 지침을 자동으로 생성하지는 않습니다.

Next.js 16.3 and later include bundled documentation and support managed agent instructions. Next.js 16.2 includes the bundled documentation but does not generate instructions automatically.

Next.js 16.1 이하에는 번들된 문서가 포함되어 있지 않습니다. legacy agents-md command는 버전에 맞는 사본을 .next-docs/에 다운로드하고 AGENTS.md에 index를 만듭니다:

Next.js 16.1 and earlier do not include the bundled documentation. The legacy agents-md command downloads a version-matched copy to .next-docs/ and indexes it in AGENTS.md:

npx @next/codemod@canary agents-md

Docs over the networknetwork를 통한 문서

Next.js 문서는 node_modules를 읽는 대신 페이지를 fetch하는 agent를 위해 network를 통해 Markdown으로도 제공됩니다. nextjs.org/docs의 모든 페이지는 .md URL에 plain Markdown 버전이 있으며, Accept: text/markdown header를 보내는 client는 Markdown을 받습니다. 여기에는 번들에 포함되지 않는 /docs/messages 아래의 error별 페이지도 포함됩니다.

The Next.js documentation is also available as Markdown over the network for agents that fetch pages instead of reading node_modules. Every page on nextjs.org/docs has a plain Markdown version at its .md URL, and clients that send an Accept: text/markdown header receive Markdown. This includes the per-error pages under /docs/messages, which are not bundled.

/docs/llms.txt의 index와 단일 파일인 /docs/llms-full.txt는 llms.txt convention을 따르므로, 이미 다른 도구에서 llms.txt를 읽는 agent는 같은 방식으로 Next.js 문서를 찾을 수 있습니다.

The index at /docs/llms.txt and the single-file /docs/llms-full.txt follow the llms.txt convention, so agents that already read llms.txt for other tools can discover the Next.js docs the same way.

Automatic agent feedback자동 agent feedback

Automatic agent feedback을 사용하면 coding agent가 현재 사용자 request를 방해하지 않고 잠재적인 Next.js 문제를 기록해 둘 수 있습니다. 최종 응답 전에 agent는 그 문제들을 평가하고, 조건에 맞는 각 report를 기본 브라우저의 별도 review form으로 엽니다.

Automatic agent feedback lets coding agents keep track of potential Next.js issues without interrupting the current user request. Before the final response, the agent evaluates those issues and opens each qualifying report in a separate review form in your default browser.

form을 열기 전에 agent는 고객과 프로젝트 세부 정보를 일반적인 설명으로 바꾸고 source code, log, path, URL, secret, 개인 정보를 빼서 report를 익명화하려고 시도합니다. 초안을 검토하고 포함하고 싶지 않은 내용은 삭제하세요. Send feedback 버튼을 선택하기 전까지는 아무것도 전송되지 않습니다.

Before opening a form, the agent attempts to anonymize the report by replacing customer and project details with generic descriptions and omitting source code, logs, paths, URLs, secrets, and personal information. Review the draft and remove anything you don't want to include. Nothing is sent until you select Send feedback.

이 option을 활성화하면 next dev는 AI coding agent를 감지했을 때 agent 파일에 다음 managed feedback instruction을 추가합니다:

With the option enabled, next dev adds the following managed feedback instructions to the agent file when it detects an AI coding agent:

AGENTS.md
<!-- BEGIN:nextjs-agent-feedback -->

## Report Next.js feedback

The project owner enabled `experimental.agentFeedback`, authorizing this feedback pass. When enabled, `next dev` writes this block and restores it if removed. Commit `AGENTS.md` with your work to keep the tree clean.

During the current user request, retain anonymized facts as feedback candidates for meaningful or recurring Next.js issues:

- Crashes, hangs, OOMs, or unexpected slowness
- Incorrect behavior, output, errors, or diagnostics
- Missing, unclear, or conflicting documentation
- Unexpected CLI, codemod, Skill, or upgrade behavior and non-obvious workarounds

Continue the current user request without reporting immediately. Routine debugging is not feedback. Verify changes before retaining them as feedback candidates. Never retain code, logs, paths, URLs, secrets, personal information, or project-specific data.

Retain qualifying friction even if it is later fixed or worked around; record the final outcome during the reporting pass.

Before the final response, run one reporting pass. If candidates remain, from this file's directory run `npx --no-install next internal agent-feedback-instructions` once without piping or truncating its output. Follow its output or error guidance. If a network sandbox blocks it, retry with network access; if it still returns no output, continue normally.

<!-- END:nextjs-agent-feedback -->

Next.js는 agent feedback marker 사이의 내용만 업데이트하고 파일의 나머지 부분은 그대로 유지합니다.

Next.js updates only the content between the agent feedback markers and preserves the rest of the file.

Automatic agent feedback은 실험적 기능으로 기본적으로 비활성화되어 있으며, Next.js Telemetry가 활성화된 경우에만 사용할 수 있습니다. CI에서는 실행되지 않습니다. 활성화하려면 agentFeedback API reference를 참고하세요.

Automatic agent feedback is experimental, disabled by default, and available only when Next.js Telemetry is enabled. It does not run in CI. See the agentFeedback API reference to enable it.

Agent-guided upgradesAgent 주도 upgrade

next upgrade --agent는 사용 가능한 upgrade가 있는지 확인하고, 버전에 맞는 migration 가이드를 모은 뒤, 작업을 coding agent에게 넘깁니다. agent는 변경 사항을 적용하고 앱을 검증합니다:

next upgrade --agent checks for an available upgrade, gathers the version-matched migration guides, and hands the task to a coding agent. The agent applies the changes and verifies the app:

>_Terminal
npx next@canary upgrade --agent=latest

실험적 option인 agentUpgrade는 기본적으로 next dev와 next build 중에 security upgrade reminder를 보여 줍니다. 사용 가능한 policy와 workflow는 Upgrade with a coding agent를 참고하세요.

The experimental agentUpgrade option shows security upgrade reminders during next dev and next build by default. See Upgrade with a coding agent for the available policies and workflow.

Runtime visibilityRuntime 가시성

실행 중인 애플리케이션을 검증하려면 agent에게 framework 상태와 브라우저 상태가 모두 필요합니다. Next.js와 관련 도구들은 서로 보완하는 이 두 관점을 구조화된 text로 노출합니다.

Agents need both framework and browser state to verify a running application. Next.js and its supporting tools expose these complementary views as structured text.

먼저 next dev는 브라우저 console의 error와 warning을 terminal로 전달합니다(logging.browserToTerminal config). 그래서 agent가 이미 읽고 있는 출력에 고쳐야 할 client-side 실패 정보가 담깁니다.

First, next dev forwards browser console errors and warnings to the terminal (the logging.browserToTerminal config), so the output agents already read carries the client-side failures they're asked to fix.

next dev는 또한 PID, port, URL을 .next/dev/lock에 기록합니다. 프로젝트에 대해 이미 다른 development server가 실행 중일 때 next dev를 실행하면, command는 기존 server의 URL과 PID를 server를 중지하는 command와 함께 출력합니다. 진행 중인 development session을 방해하지 않도록 가능하면 기존 server를 계속 사용하세요.

next dev also writes its PID, port, and URL to .next/dev/lock. If you run next dev while another development server is already running for the project, the command prints the existing server's URL and PID, along with a command to stop it. Continue with the existing server when possible to avoid interrupting the active development session.

framework 관점 정보는 /_next/mcp의 Next.js MCP server에서 얻습니다. 이 server는 실행 중인 dev server의 route, server log, compilation issue를 노출합니다. get_compilation_issues와 compile_route 도구가 dev server에서 바로 코드가 compile되는지 알려 주므로, agent는 이를 확인하려고 전체 next build를 실행할 필요가 없습니다.

The framework's view comes from the Next.js MCP server at /_next/mcp, which exposes the running dev server's routes, server logs, and compilation issues. Its get_compilation_issues and compile_route tools report whether the code compiles straight from the dev server, so an agent doesn't have to run a full next build to find out.

next-dev-loop skill은 DOM, console, network, Web Vitals를 구조화된 text로 노출하는 CLI인 agent-browser를 통해 브라우저 관점 정보를 더합니다. 이 Skill은 React DevTools를 활성화한 상태로 agent-browser를 열기 때문에 component tree와 대기 중인 Suspense boundary도 노출됩니다. agent는 react tree 같은 command를 실행하고 그 구조화된 출력을 보고 다음에 무엇을 살펴볼지 결정할 수 있습니다.

The next-dev-loop skill adds the browser's view through agent-browser, a CLI that exposes the DOM, console, network, and Web Vitals as structured text. The Skill opens agent-browser with React DevTools enabled, which also exposes the component tree and pending Suspense boundaries. An agent can run a command such as react tree and use the structured output to decide what to inspect next.

next-dev-loop는 Next.js MCP server와 함께 framework 관점과 브라우저 관점을 하나의 edit-and-verify loop로 결합합니다.

Together with the Next.js MCP server, next-dev-loop combines the framework's and the browser's perspectives into one edit-and-verify loop.

Built-in guidance for errorserror에 대한 내장 가이드

Cache Components가 활성화되어 있으면, blocking error는 각기 다른 trade-off를 가진 이름 붙은 fix들을 보여 줍니다. dev overlay에는 선택한 fix를 바로 붙여 넣을 수 있는 prompt로 묶어 주는 Copy prompt 버튼이 추가됩니다. 이 prompt는 agent가 해당 error 페이지를 읽고, 표준(canonical) 패턴을 적용하고, runtime에서 결과를 검증하도록 단계별로 안내합니다.

With Cache Components enabled, a blocking error presents labeled fixes, each making a different trade-off. The dev overlay adds a Copy prompt button that packages the chosen fix into a paste-ready prompt. The prompt walks the agent through reading the matching error page, applying the canonical pattern, and verifying the result at runtime.

같은 menu가 next dev terminal과 next build 출력에도 표시되므로, CI log를 읽는 agent도 이를 볼 수 있습니다:

The same menu prints in the next dev terminal and in next build output, so an agent reading CI logs sees it too:

>_Terminal
Route "/products/[slug]": Next.js encountered uncached data during prerendering.

`fetch(...)` or `connection()` accessed outside of `<Suspense>` prevents the route
from being prerendered, blocking the page load and leading to a slower user experience.

Ways to fix this:
  - [stream] Provide a placeholder with `<Suspense fallback={...}>` around the data access
  - [cache] Cache the data access with `"use cache"` (does not apply to `connection()`)
  - [block] Set `export const instant = false` to allow a blocking route

Learn more: https://nextjs.org/docs/messages/blocking-prerender-dynamic
    at ProductPage (app/products/[slug]/page.tsx:52:32)
    ...

next dev는 overlay와 terminal에 source map이 적용된 stack과 함께 모든 validation error를 보여 줍니다. production build는 server 코드를 minify하고 route 하나가 실패하면 멈춥니다. server source map을 활성화하고 다른 route도 계속 검사하려면 next build --debug-prerender를 사용하세요.

next dev shows all validation errors with source-mapped stacks in the overlay and terminal. Production builds minify server code and stop after a route fails. Use next build --debug-prerender to enable server source maps and continue checking other routes.

Learn more link는 agent가 읽도록 작성된 /docs/messages 아래의 error별 페이지로 연결됩니다. 각 페이지는 같은 형식을 따르며, 모든 fix의 표준 패턴, 다른 fix와 비교한 trade-off, 그리고 agent가 첫 시도에서 놓치기 쉬운 함정(gotcha)을 담고 있습니다. Instant navigation 가이드는 insight를 읽는 것부터 fix 전에는 실패하고 fix 적용 후에는 통과하는 instant() test를 작성하는 것까지, agent가 이런 error에 대해 수행하는 전체 loop를 설명합니다.

The Learn more link resolves to a per-error page under /docs/messages written for agents to read. Each page follows the same shape, with the canonical patterns for every fix, the trade-offs against the other fixes, and the gotchas an agent is likely to miss on a first attempt. The Instant navigation guide walks through the full loop an agent runs on these errors, from reading the insight to writing an instant() test that fails before the fix and passes once it's in place.

Skills for multi-step workflows여러 단계 workflow를 위한 Skill

framework 지식은 Skill이 아니라 번들된 문서에서 옵니다. Benchmark 결과에 따르면 항상 사용할 수 있는 context가 필요할 때 가져오는(on-demand) retrieval보다 성능이 좋습니다. Skill은 앱 전체에 Cache Components나 Partial Prefetching을 도입하는 것처럼 조회가 아니라 workflow에 해당하는 작업을 다룹니다. Next.js Skill은 이런 작업을 agent가 설치해 따를 수 있는 구조화된 지침으로 묶어, 작업 순서를 정하고 그 과정에서 관련 문서와 runtime tooling을 안내합니다.

Framework knowledge comes from the bundled docs, not from Skills. Benchmark results show that always-available context outperforms on-demand retrieval. Skills cover the tasks that are workflows rather than lookups, such as adopting Cache Components or Partial Prefetching across an app. Next.js Skills package these as structured instructions an agent installs and follows, sequencing the work and pointing at the relevant docs and runtime tooling along the way.

Next.js 저장소에서 이 Skill들의 source를 살펴보거나 skills.sh에서 찾아볼 수 있습니다.

You can browse the source for these Skills in the Next.js repository and find them on skills.sh.

Skill은 세 가지 유형의 workflow를 담당합니다:

The Skills serve three different workflow types:

  • next-dev-loop 같은 Runtime foundation 은 어떤 coding 작업에든 반복 가능한 inspect, edit, verify 주기를 제공합니다.
  • Interactive workflow 는 앱 전체에 Cache Components나 Partial Prefetching을 도입하는 것처럼 사용자 checkpoint를 두고 더 넓은 범위의 변경을 수행합니다.
  • Unattended loop 는 검증 가능한 목표를 향해 작업하며 꼭 필요한 결정이 있을 때만 멈춥니다.
  • Runtime foundations such as next-dev-loop give any coding task a repeatable inspect, edit, and verify cycle.
  • Interactive workflows make broader changes with user checkpoints, such as adopting Cache Components or Partial Prefetching across an app.
  • Unattended loops work toward a verifiable goal and stop only for genuine decisions.

next-cache-components-adoption

next-cache-components-adoption Skill은 앱을 Cache Components로 migrate합니다:

The next-cache-components-adoption Skill migrates an app to Cache Components:

  1. flag를 켜고 prerender할 수 없는 route를 찾습니다.
  2. 기능 하나씩 고치면서, 다음으로 넘어가기 전에 사용자에게 확인을 받습니다.
  3. 기능 하나를 마치기 전에 next dev와 next build로 확인합니다.
  1. Turns the flag on and finds the routes that can't prerender.
  2. Fixes them one feature at a time, checking in with you before moving on.
  3. Confirms a feature against next dev and next build before leaving it.

The Skill supports both a series of pull requests and a single-branch migration.

next-cache-components-optimizer

next-cache-components-optimizer Skill은 대상 route의 static shell을 확장해 initial load 때 보여 주고 싶은 유용한 UI를 포함시킵니다:

The next-cache-components-optimizer Skill expands a target route's static shell to include the useful UI you want available on an initial load:

  1. 지정한 static-shell UI에 대해 실패하는 instant() test를 작성합니다.
  2. test가 통과할 때까지 route를 refactor합니다. 흔히 data read를 <Suspense> boundary 아래로 옮기는 방식입니다.
  3. 통과한 test를 refactoring과 함께 commit해 향후 regression을 잡아내도록 합니다.
  1. Writes a failing instant() test for the static-shell UI you named.
  2. Refactors the route until it passes, often by moving a data read below a <Suspense> boundary.
  3. Commits the passing test with the refactoring, so it catches future regressions.

Cache Components를 도입한 뒤 initial load나 client navigation을 최적화할 때 사용하세요. 이미 instant한 destination에 대해 URL-specific content를 prefetch하려면 대신 next-partial-prefetching-optimizer를 사용하세요.

Use it after adopting Cache Components to optimize an initial load or client navigation. To prefetch URL-specific content for an already-instant destination, use the next-partial-prefetching-optimizer instead.

next-partial-prefetching-adoption

next-partial-prefetching-adoption Skill은 link들이 하나의 App Shell을 공유하는 Partial Prefetching으로 앱을 옮깁니다:

The next-partial-prefetching-adoption Skill moves an app onto Partial Prefetching, where links share one App Shell:

  1. 기존 <Link prefetch={true}> navigation을 검토하고 보존해야 할 prefetch된 UI를 찾습니다.
  2. Partial Prefetching을 활성화하기 전에 그 UI를 통과하는 instant() test로 기록한 다음, 같은 test가 수정 없이 통과할 때까지 각 destination을 migrate합니다.
  3. flag를 활성화하고, 이때 나타나는 URL-data insight를 해결하며, 선택적인 per-link prefetching 후보를 나중을 위해 표시해 둡니다.
  1. Audits existing <Link prefetch={true}> navigations and identifies the prefetched UI to preserve.
  2. Captures that UI in passing instant() tests before enabling Partial Prefetching, then migrates each destination until the same tests pass unchanged.
  3. Enables the flag, resolves the URL-data insights it surfaces, and marks optional per-link prefetching candidates for later.

이 Skill을 사용하려면 Cache Components가 이미 도입되어 있어야 하고, prefetch 검증을 위해 실행할 수 있는 production과 유사한 build가 필요합니다.

It needs Cache Components already adopted and a production-like build it can run for prefetch verification.

next-partial-prefetching-optimizer

next-partial-prefetching-optimizer Skill은 대상 navigation 하나 또는 여러 개를 받아, 각 클릭 전에 준비되어 있기를 원하는 UI를 목표로 작업합니다:

The next-partial-prefetching-optimizer Skill takes a target navigation or set of navigations and works toward the UI you want ready before each click:

  1. 각 navigation에 대해 요청된 동작을 무엇이 prefetch되는지, 무엇이 navigation을 기다리는지, prefetching이 언제 시작되는지에 대한 contract로 바꿉니다.
  2. 각 contract를 instant() test로 기록합니다.
  3. Optimizing prefetching 패턴을 적용하고, 통과한 test를 regression coverage로 유지합니다.
  1. Turns the requested behavior for each navigation into a contract for what is prefetched, what waits for navigation, and when prefetching begins.
  2. Captures each contract in an instant() test.
  3. Applies the Optimizing prefetching patterns and keeps the passing tests as regression coverage.

이 Skill을 사용하려면 Cache Components와 Partial Prefetching이 이미 도입되어 있어야 합니다.

It needs Cache Components and Partial Prefetching already adopted.
