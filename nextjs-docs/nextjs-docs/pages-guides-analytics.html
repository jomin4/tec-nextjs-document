How to set up analyticsNext.js 애플리케이션에 analytics 추가하기

Next.js는 성능 지표(performance metric)를 측정하고 보고하는 기능을 기본으로 지원합니다. useReportWebVitals hook을 사용해 reporting을 직접 관리할 수도 있고, 또는 Vercel이 제공하는 managed service를 이용해 지표를 자동으로 수집하고 시각화할 수도 있습니다.

Next.js has built-in support for measuring and reporting performance metrics. You can either use the useReportWebVitals hook to manage reporting yourself, or alternatively, Vercel provides a managed service to automatically collect and visualize metrics for you.

Client Instrumentation

더 고급 analytics와 monitoring이 필요한 경우를 위해, Next.js는 애플리케이션의 frontend 코드가 실행되기 전에 실행되는 instrumentation-client.js|ts 파일을 제공합니다. 이 파일은 global analytics, error tracking, performance monitoring 도구를 설정하기에 적합합니다.

For more advanced analytics and monitoring needs, Next.js provides a instrumentation-client.js|ts file that runs before your application's frontend code starts executing. This is ideal for setting up global analytics, error tracking, or performance monitoring tools.

사용하려면 애플리케이션의 root directory에 instrumentation-client.js 또는 instrumentation-client.ts 파일을 만드세요:

To use it, create an instrumentation-client.js or instrumentation-client.ts file in your application's root directory:

JSinstrumentation-client.js
// Initialize analytics before the app starts
console.log('Analytics initialized')

// Set up global error tracking
window.addEventListener('error', (event) => {
  // Send to your error tracking service
  reportError(event.error)
})

Build Your Own직접 만들기

JSpages/_app.js
import { useReportWebVitals } from 'next/web-vitals'

function MyApp({ Component, pageProps }) {
  useReportWebVitals((metric) => {
    console.log(metric)
  })

  return <Component {...pageProps} />
}

자세한 내용은 API Reference를 참고하세요.

View the API Reference for more information.

Web Vitals

Web Vitals는 웹 페이지의 사용자 경험을 포착하기 위한 유용한 지표들의 모음입니다. 다음 web vital이 모두 포함됩니다:

Web Vitals are a set of useful metrics that aim to capture the user experience of a web page. The following web vitals are all included:

  • Time to First Byte (TTFB)
  • First Contentful Paint (FCP)
  • Largest Contentful Paint (LCP)
  • Cumulative Layout Shift (CLS)
  • Interaction to Next Paint (INP)
  • Time to First Byte (TTFB)
  • First Contentful Paint (FCP)
  • Largest Contentful Paint (LCP)
  • Cumulative Layout Shift (CLS)
  • Interaction to Next Paint (INP)

name property를 사용해 이 지표들의 모든 결과를 처리할 수 있습니다.

You can handle all the results of these metrics using the name property.

JSpages/_app.js
import { useReportWebVitals } from 'next/web-vitals'

function MyApp({ Component, pageProps }) {
  useReportWebVitals((metric) => {
    switch (metric.name) {
      case 'FCP': {
        // handle FCP results
      }
      case 'LCP': {
        // handle LCP results
      }
      // ...
    }
  })

  return <Component {...pageProps} />
}

Custom Metrics

위에 나열한 core metric 외에도, 페이지가 hydrate되고 render되는 데 걸리는 시간을 측정하는 추가 custom metric이 있습니다:

In addition to the core metrics listed above, there are some additional custom metrics that measure the time it takes for the page to hydrate and render:

  • Next.js-hydration: 페이지가 hydration을 시작해서 끝내기까지 걸리는 시간(ms 단위)
  • Next.js-route-change-to-render: route 변경 후 페이지가 rendering을 시작하기까지 걸리는 시간(ms 단위)
  • Next.js-render: route 변경 후 페이지가 render를 마치기까지 걸리는 시간(ms 단위)
  • Next.js-hydration: Length of time it takes for the page to start and finish hydrating (in ms)
  • Next.js-route-change-to-render: Length of time it takes for a page to start rendering after a route change (in ms)
  • Next.js-render: Length of time it takes for a page to finish render after a route change (in ms)

이 지표들의 모든 결과를 각각 따로 처리할 수 있습니다:

You can handle all the results of these metrics separately:

export function reportWebVitals(metric) {
  switch (metric.name) {
    case 'Next.js-hydration':
      // handle hydration results
      break
    case 'Next.js-route-change-to-render':
      // handle route-change to render results
      break
    case 'Next.js-render':
      // handle render results
      break
    default:
      break
  }
}

이 지표들은 User Timing API를 지원하는 모든 브라우저에서 동작합니다.

These metrics work in all browsers that support the User Timing API.

Sending results to external systems외부 시스템으로 결과 보내기

결과를 어떤 endpoint로든 보내서 사이트의 실제 사용자 성능을 측정하고 추적할 수 있습니다. 예를 들면 다음과 같습니다:

You can send results to any endpoint to measure and track real user performance on your site. For example:

useReportWebVitals((metric) => {
  const body = JSON.stringify(metric)
  const url = 'https://example.com/analytics'

  // Use `navigator.sendBeacon()` if available, falling back to `fetch()`.
  if (navigator.sendBeacon) {
    navigator.sendBeacon(url, body)
  } else {
    fetch(url, { body, method: 'POST', keepalive: true })
  }
})
Good to know

Google Analytics를 사용한다면, id 값을 사용해 metric 분포를 직접 구성할 수 있습니다(percentile 계산 등을 위해)

If you use Google Analytics, using the id value can allow you to construct metric distributions manually (to calculate percentiles, etc.)

useReportWebVitals((metric) => {
  // Use `window.gtag` if you initialized Google Analytics as this example:
  // https://github.com/vercel/next.js/blob/canary/examples/with-google-analytics
  window.gtag('event', metric.name, {
    value: Math.round(
      metric.name === 'CLS' ? metric.value * 1000 : metric.value
    ), // values must be integers
    event_label: metric.id, // id unique to current page load
    non_interaction: true, // avoids affecting bounce rate.
  })
})
