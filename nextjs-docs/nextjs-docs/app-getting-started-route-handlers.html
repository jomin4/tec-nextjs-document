Route Handlers

Route Handler를 사용하면 Web Request와 Response API로 특정 route에 대한 custom request handler를 만들 수 있습니다.

Route Handlers allow you to create custom request handlers for a given route using the Web Request and Response APIs.

Good to know

Route Handler는 app directory 안에서만 사용할 수 있습니다. Route Handler는 pages directory 안의 API Routes와 같은 역할을 하므로, API Routes와 Route Handler를 함께 사용할 필요가 없습니다.

Route Handlers are only available inside the app directory. They are the equivalent of API Routes inside the pages directory meaning you do not need to use API Routes and Route Handlers together.

Convention관례

Route Handler는 app directory 안의 route.js|ts 파일에 정의합니다:

Route Handlers are defined in a route.js|ts file inside the app directory:

TSJSapp/api/route.ts
export async function GET(request: Request) {}
export async function GET(request) {}

Route Handler는 page.js, layout.js와 마찬가지로 app directory 안 어디에나 중첩할 수 있습니다. 하지만 page.js와 같은 route segment 수준에 route.js 파일이 있을 수는 없습니다.

Route Handlers can be nested anywhere inside the app directory, similar to page.js and layout.js. But there cannot be a route.js file at the same route segment level as page.js.

Supported HTTP Methods지원되는 HTTP Method

다음 HTTP method가 지원됩니다: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS. 지원되지 않는 method가 호출되면 Next.js는 405 Method Not Allowed response를 반환합니다.

The following HTTP methods are supported: GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS. If an unsupported method is called, Next.js will return a 405 Method Not Allowed response.

Extended NextRequest and NextResponse APIs확장된 NextRequest와 NextResponse API

Next.js는 native Request와 Response API를 지원할 뿐 아니라, 이를 NextRequest와 NextResponse로 확장해 고급 사용 사례를 위한 편리한 helper를 제공합니다.

In addition to supporting the native Request and Response APIs, Next.js extends them with NextRequest and NextResponse to provide convenient helpers for advanced use cases.

Caching

Route Handler는 기본적으로 cache되지 않습니다. 하지만 GET method에 대해서는 caching을 opt in할 수 있습니다. 지원되는 다른 HTTP method는 cache되지 않습니다. GET method를 cache하려면 Route Handler 파일에서 export const dynamic = 'force-static' 같은 route config option을 사용하세요.

Route Handlers are not cached by default. You can, however, opt into caching for GET methods. Other supported HTTP methods are not cached. To cache a GET method, use a route config option such as export const dynamic = 'force-static' in your Route Handler file.

TSJSapp/items/route.ts
export const dynamic = 'force-static'

export async function GET() {
  const res = await fetch('https://data.mongodb-api.com/...', {
    headers: {
      'Content-Type': 'application/json',
      'API-Key': process.env.DATA_API_KEY,
    },
  })
  const data = await res.json()

  return Response.json({ data })
}
export const dynamic = 'force-static'

export async function GET() {
  const res = await fetch('https://data.mongodb-api.com/...', {
    headers: {
      'Content-Type': 'application/json',
      'API-Key': process.env.DATA_API_KEY,
    },
  })
  const data = await res.json()

  return Response.json({ data })
}
Good to know

지원되는 다른 HTTP method는 같은 파일 안에서 cache되는 GET method와 함께 있더라도 cache되지 않습니다.

Other supported HTTP methods are not cached, even if they are placed alongside a GET method that is cached, in the same file.

With Cache ComponentsCache Components와 함께 사용하기

Cache Components가 활성화되어 있으면 GET Route Handler는 애플리케이션의 일반 UI route와 같은 모델을 따릅니다. 기본적으로 request 시점에 실행되고, uncached data나 runtime data에 접근하지 않으면 prerender될 수 있으며, use cache를 사용해 uncached data를 static response에 포함할 수 있습니다.

When Cache Components is enabled, GET Route Handlers follow the same model as normal UI routes in your application. They run at request time by default, can be prerendered when they don't access uncached or runtime data, and you can use use cache to include uncached data in the static response.

Static 예시 - uncached data나 runtime data에 접근하지 않으므로 build 시점에 prerender됩니다:

Static example - doesn't access uncached or runtime data, so it will be prerendered at build time:

TSapp/api/project-info/route.ts
export async function GET() {
  return Response.json({
    projectName: 'Next.js',
  })
}

Dynamic 예시 - 비결정적(non-deterministic) 연산에 접근합니다. build 중 Math.random()이 호출되면 prerendering이 멈추고 request 시점 rendering으로 넘어갑니다:

Dynamic example - accesses non-deterministic operations. During the build, prerendering stops when Math.random() is called, deferring to request-time rendering:

TSapp/api/random-number/route.ts
export async function GET() {
  return Response.json({
    randomNumber: Math.random(),
  })
}

Runtime data 예시 - request별 data에 접근합니다. headers() 같은 runtime API가 호출되면 prerendering이 종료됩니다:

Runtime data example - accesses request-specific data. Prerendering terminates when runtime APIs like headers() are called:

TSapp/api/user-agent/route.ts
import { headers } from 'next/headers'

export async function GET() {
  const headersList = await headers()
  const userAgent = headersList.get('user-agent')

  return Response.json({ userAgent })
}
Good to know

GET handler가 network request, database query, async file system 작업, request 객체 property(req.url, request.headers, request.cookies, request.body 등), cookies(), headers(), connection() 같은 runtime API, 또는 비결정적 연산에 접근하면 prerendering이 멈춥니다.

Prerendering stops if the GET handler accesses network requests, database queries, async file system operations, request object properties (like req.url, request.headers, request.cookies, request.body), runtime APIs like cookies(), headers(), connection(), or non-deterministic operations.

Cached 예시 - uncached data(database query)에 접근하지만 use cache로 cache하므로 prerender된 response에 포함될 수 있습니다:

Cached example - accesses uncached data (database query) but caches it with use cache, allowing it to be included in the prerendered response:

TSapp/api/products/route.ts
import { cacheLife } from 'next/cache'

export async function GET() {
  const products = await getProducts()
  return Response.json(products)
}

async function getProducts() {
  'use cache'
  cacheLife('hours')

  return await db.query('SELECT * FROM products')
}
Good to know

use cache는 Route Handler 본문 안에서 직접 사용할 수 없으므로 helper 함수로 분리하세요. cache된 response는 새 request가 들어올 때 cacheLife에 따라 revalidate됩니다.

use cache cannot be used directly inside a Route Handler body; extract it to a helper function. Cached responses revalidate according to cacheLife when a new request arrives.

Special Route Handlers특수 Route Handler

sitemap.ts, opengraph-image.tsx, icon.tsx 같은 특수 Route Handler와 기타 metadata 파일은 Request-time API나 dynamic config option을 사용하지 않는 한 기본적으로 static으로 유지됩니다.

Special Route Handlers like sitemap.ts, opengraph-image.tsx, and icon.tsx, and other metadata files remain static by default unless they use Request-time APIs or dynamic config options.

Route ResolutionRoute 결정 방식

route는 가장 낮은 수준의 routing primitive라고 생각할 수 있습니다.

You can consider a route the lowest level routing primitive.

  • page와 달리 layout이나 client-side navigation에 참여하지 않습니다.
  • page.js와 같은 route에 route.js 파일이 있을 수 없습니다.
  • They do not participate in layouts or client-side navigations like page.
  • There cannot be a route.js file at the same route as page.js.

app/page.jsapp/api/route.js✓ 유효

app/page.jsapp/route.js✕ Conflict
app/page.jsapp/api/route.js✓ Valid
app/[user]/page.jsapp/api/route.js✓ Valid

각 route.js 또는 page.js 파일은 해당 route의 모든 HTTP verb를 담당합니다.

Each route.js or page.js file takes over all HTTP verbs for that route.

TSJSapp/page.ts
export default function Page() {
  return <h1>Hello, Next.js!</h1>
}

// Conflict
// `app/route.ts`
export async function POST(request: Request) {}
export default function Page() {
  return <h1>Hello, Next.js!</h1>
}

// Conflict
// `app/route.js`
export async function POST(request) {}

Route Context Helper

TypeScript에서는 전역으로 사용할 수 있는 RouteContext helper로 Route Handler의 context parameter에 type을 지정할 수 있습니다:

In TypeScript, you can type the context parameter for Route Handlers with the globally available RouteContext helper:

TSapp/users/[id]/route.ts
import type { NextRequest } from 'next/server'

export async function GET(_req: NextRequest, ctx: RouteContext<'/users/[id]'>) {
  const { id } = await ctx.params
  return Response.json({ id })
}
Good to know
  • type은 next dev, next build 또는 next typegen 실행 중에 생성됩니다.
  • Types are generated during next dev, next build or next typegen.
