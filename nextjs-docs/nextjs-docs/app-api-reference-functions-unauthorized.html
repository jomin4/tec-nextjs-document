unauthorizedexperimentalunauthorized

unauthorized 함수는 Next.js 401 page를 render하는 error를 throw합니다. request가 로그인되어 있지 않은 경우의 authentication error를 처리할 때 유용합니다. unauthorized.js 파일로 UI를 customize할 수 있습니다.

The unauthorized function throws an error that renders a Next.js 401 page. It's useful for handling authentication errors, when a request is not signed in. You can customize the UI using the unauthorized.js file.

unauthorized()를 호출하면 NEXT_HTTP_ERROR_FALLBACK;401 error가 throw되고, 이 error가 throw된 route segment의 rendering이 종료됩니다. 또한 Next.js는 page가 index되지 않도록 <meta name="robots" content="noindex" /> tag를 삽입합니다. throw하는 방식으로 동작하기 때문에 render path 안에서 호출해야 합니다. 즉, component 안이나 component가 await하는 function 안에서 호출하세요. await되지 않은 promise 안에 남겨진 호출은 아무것도 catch하지 않는 곳에서 throw되므로 unauthorized UI가 render되지 않습니다.

Invoking unauthorized() throws a NEXT_HTTP_ERROR_FALLBACK;401 error and terminates rendering of the route segment where it was thrown. Next.js also injects a <meta name="robots" content="noindex" /> tag so the page is not indexed. Because it works by throwing, call it in the render path: a component, or a function a component awaits. A call left in an un-awaited promise throws where nothing catches it, and no unauthorized UI renders.

unauthorized를 사용하려면 next.config.js 파일에서 experimental authInterrupts configuration option을 활성화하세요:

To start using unauthorized, enable the experimental authInterrupts configuration option in your next.config.js file:

TSJSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    authInterrupts: true,
  },
}

export default nextConfig
module.exports = {
  experimental: {
    authInterrupts: true,
  },
}

unauthorized는 Server Components, Server Functions, Route Handlers에서 호출할 수 있습니다.

unauthorized can be invoked in Server Components, Server Functions, and Route Handlers.

TSJSapp/dashboard/page.tsx
import { verifySession } from '@/app/lib/dal'
import { unauthorized } from 'next/navigation'

export default async function DashboardPage() {
  const session = await verifySession()

  if (!session) {
    unauthorized()
  }

  // Render the dashboard for authenticated users
  return (
    <main>
      <h1>Welcome to the Dashboard</h1>
      <p>Hi, {session.user.name}.</p>
    </main>
  )
}

Good to know알아두면 좋은 점

  • unauthorized 함수는 root layout에서 호출할 수 없습니다.
  • return unauthorized()라고 쓸 필요는 없습니다. 이 함수는 throw하므로(TypeScript never return type) 실행이 멈춥니다. 호출을 try/catch로 감싸면 interrupt가 억제되어 unauthorized UI가 render되지 않습니다. 이를 통과시키려면 unstable_rethrow를 사용하세요.
  • await되지 않은 promise 안에 남겨진 unauthorized()는 아무것도 catch하지 않는 곳에서 throw되므로 unauthorized UI가 render되지 않습니다. development 환경에서는 server가 ⨯ unhandledRejection: NEXT_HTTP_ERROR_FALLBACK;401을 log로 남깁니다. 이 함수를 호출할 수 있는 function은 항상 await하세요.
  • The unauthorized function cannot be called in the root layout.
  • You do not need to write return unauthorized(). It throws (its TypeScript never return type), so execution stops. A try/catch around the call suppresses the interrupt and no unauthorized UI renders. Use unstable_rethrow to let it through.
  • An unauthorized() left in an un-awaited promise throws where nothing catches it, so no unauthorized UI renders. In development the server logs ⨯ unhandledRejection: NEXT_HTTP_ERROR_FALLBACK;401. Always await the function that may call it.

Examples예시

Calling unauthorized() after streaming has startedstreaming이 시작된 후 unauthorized() 호출하기

session을 검증하는 동안 page의 shell과 loading UI가 계속 보이도록 하려면, auth check를 data를 로드하는 Data Access Layer function 안에 넣고, 이를 <Suspense>로 감싼 component에서 render하세요. check가 boundary 안에서 실행되므로 session이 resolve되는 동안 shell이 stream됩니다:

To keep the page's shell and loading UI visible while the session is verified, put the auth check in the Data Access Layer function that loads the data, and render it in a component wrapped in <Suspense>. The check runs inside the boundary, so the shell streams while the session resolves:

TSJSapp/account/page.tsx
import { Suspense } from 'react'
import { verifySession } from '@/app/lib/dal'
import { unauthorized } from 'next/navigation'

async function getAccount() {
  const session = await verifySession()
  if (!session) {
    unauthorized()
  }
  return db.accounts.findByUserId(session.userId)
}

async function AccountDetails() {
  const account = await getAccount()
  return <p>Signed in as {account.email}</p>
}

export default function AccountPage() {
  return (
    <main>
      <h1>Account</h1>
      <Suspense fallback={<p>Loading...</p>}>
        <AccountDetails />
      </Suspense>
    </main>
  )
}
import { Suspense } from 'react'

}

request가 로그인되어 있지 않으면 getAccount가 unauthorized()를 호출하고, 이 함수가 throw합니다. 이 일이 rendering 중에 일어나므로 exception은 가장 가까운 unauthorized boundary까지 전파되고, page shell이 이미 전송되었더라도 stream되어 들어올 content 자리에 이 boundary가 render됩니다.

When the request isn't signed in, getAccount calls unauthorized(), which throws. Because this happens during rendering, the exception propagates to the nearest unauthorized boundary, which renders in place of the streamed-in content, even though the page shell has already been sent.

그 UI를 정의하려면 route 옆에 unauthorized.tsx를 추가하세요:

Add an unauthorized.tsx alongside the route to define that UI:

TSJSapp/account/unauthorized.tsx
import Link from 'next/link'

export default function Unauthorized() {
  return (
    <main>
      <h1>401 - Unauthorized</h1>
      <p>
        Please <Link href="/login">sign in</Link> to view your account.
      </p>
    </main>
  )
}

response는 unauthorized()가 실행되기 전에 <Suspense> boundary에서 streaming을 시작하므로 200 status를 유지합니다. Next.js는 noindex tag를 추가합니다.

The response starts streaming from the <Suspense> boundary before unauthorized() runs, so it keeps its 200 status. Next.js adds a noindex tag.

streaming이 시작되기 전에 unauthorized()를 호출하면 401이 반환됩니다. prerendering 중에 unauthorized()에 도달하는 page는 ○ Static으로 남아 401을 제공할 수 있습니다. request 시점의 check는 page가 render되기 전에 Proxy에서 실행할 수 있습니다. Status codes를 참고하세요.

Calling unauthorized() before streaming starts returns a 401. A page that reaches unauthorized() during prerendering can remain ○ Static and serve a 401. A request-time check can run in Proxy before the page renders. See Status codes.

Mutations with Server ActionsServer Action으로 mutation 처리하기

Server Action에서 unauthorized를 호출해 인증된 사용자만 특정 mutation을 수행할 수 있도록 할 수 있습니다.

You can invoke unauthorized in Server Actions to ensure only authenticated users can perform specific mutations.

TSJSapp/actions/update-profile.ts
'use server'

import { verifySession } from '@/app/lib/dal'
import { unauthorized } from 'next/navigation'
import db from '@/app/lib/db'

export async function updateProfile(data: FormData) {
  const session = await verifySession()

  // If the user is not authenticated, return a 401
  if (!session) {
    unauthorized()
  }

  // Proceed with mutation
  // ...
}

Fetching data with Route HandlersRoute Handler로 data fetching하기

Route Handler에서 unauthorized를 사용해 인증된 사용자만 endpoint에 접근할 수 있도록 할 수 있습니다.

You can use unauthorized in Route Handlers to ensure only authenticated users can access the endpoint.

TSJSapp/api/profile/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { verifySession } from '@/app/lib/dal'
import { unauthorized } from 'next/navigation'

export async function GET(req: NextRequest): Promise<NextResponse> {
  // Verify the user's session
  const session = await verifySession()

  // If no session exists, return a 401 and render unauthorized.tsx
  if (!session) {
    unauthorized()
  }

  // Fetch data
  // ...
}
