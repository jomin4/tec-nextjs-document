How to implement internationalization in Next.jsNext.js에서 국제화(i18n) 구현하기

예제
  • i18n routing

Next.js는 v10.0.0부터 internationalized(i18n) routing을 기본으로 지원합니다. locale 목록, default locale, domain별 locale을 제공하면 Next.js가 routing을 자동으로 처리합니다.

Next.js has built-in support for internationalized (i18n) routing since v10.0.0. You can provide a list of locales, the default locale, and domain-specific locales and Next.js will automatically handle the routing.

i18n routing 지원은 현재 route와 locale parsing을 간소화하여 react-intl, react-i18next, lingui, rosetta, next-intl, next-translate, next-multilingual, tolgee, paraglide-next, next-intlayer, gt-react 등 기존 i18n library solution을 보완하기 위한 것입니다.

The i18n routing support is currently meant to complement existing i18n library solutions like react-intl, react-i18next, lingui, rosetta, next-intl, next-translate, next-multilingual, tolgee, paraglide-next, next-intlayer, gt-react and others by streamlining the routes and locale parsing.

Getting started시작하기

시작하려면 next.config.js 파일에 i18n config를 추가하세요.

To get started, add the i18n config to your next.config.js file.

locale은 locale을 정의하는 표준화된 형식인 UTS Locale Identifiers를 따릅니다.

Locales are UTS Locale Identifiers, a standardized format for defining locales.

일반적으로 Locale Identifier는 language, region, script를 dash로 구분해 구성합니다: language-region-script. region과 script는 선택 사항입니다. 예시:

Generally a Locale Identifier is made up of a language, region, and script separated by a dash: language-region-script. The region and script are optional. An example:

  • en-US - 미국에서 쓰는 영어
  • nl-NL - 네덜란드에서 쓰는 네덜란드어
  • nl - 특정 region이 없는 네덜란드어
  • en-US - English as spoken in the United States
  • nl-NL - Dutch as spoken in the Netherlands
  • nl - Dutch, no specific region

사용자 locale이 nl-BE이고 이것이 configuration에 없다면, nl이 있으면 nl로, 없으면 default locale로 redirect됩니다. 따라서 한 국가의 모든 region을 지원할 계획이 없다면 fallback 역할을 할 국가 locale을 포함해 두는 것이 좋은 practice입니다.

If user locale is nl-BE and it is not listed in your configuration, they will be redirected to nl if available, or to the default locale otherwise. If you don't plan to support all regions of a country, it is therefore a good practice to include country locales that will act as fallbacks.

JSnext.config.js
module.exports = {
  i18n: {
    // These are all the locales you want to support in
    // your application
    locales: ['en-US', 'fr', 'nl-NL'],
    // This is the default locale you want to be used when visiting
    // a non-locale prefixed path e.g. `/hello`
    defaultLocale: 'en-US',
    // This is a list of locale domains and the default locale they
    // should handle (these are only required when setting up domain routing)
    // Note: subdomains must be included in the domain value to be matched e.g. "fr.example.com".
    domains: [
      {
        domain: 'example.com',
        defaultLocale: 'en-US',
      },
      {
        domain: 'example.nl',
        defaultLocale: 'nl-NL',
      },
      {
        domain: 'example.fr',
        defaultLocale: 'fr',
        // an optional http field can also be used to test
        // locale domains locally with http instead of https
        http: true,
      },
    ],
  },
}

Locale StrategiesLocale 전략

locale 처리 전략에는 Sub-path Routing과 Domain Routing 두 가지가 있습니다.

There are two locale handling strategies: Sub-path Routing and Domain Routing.

Sub-path Routing

Sub-path Routing은 locale을 url path에 넣습니다.

Sub-path Routing puts the locale in the url path.

JSnext.config.js
module.exports = {
  i18n: {
    locales: ['en-US', 'fr', 'nl-NL'],
    defaultLocale: 'en-US',
  },
}

위 configuration에서는 en-US, fr, nl-NL로 route할 수 있고, en-US가 default locale입니다. pages/blog.js가 있다면 다음 url을 사용할 수 있습니다:

With the above configuration en-US, fr, and nl-NL will be available to be routed to, and en-US is the default locale. If you have a pages/blog.js the following urls would be available:

  • /blog
  • /fr/blog
  • /nl-nl/blog
  • /blog
  • /fr/blog
  • /nl-nl/blog

default locale에는 prefix가 붙지 않습니다.

The default locale does not have a prefix.

Domain Routing

domain routing을 사용하면 locale별로 서로 다른 domain에서 제공되도록 설정할 수 있습니다:

By using domain routing you can configure locales to be served from different domains:

JSnext.config.js
module.exports = {
  i18n: {
    locales: ['en-US', 'fr', 'nl-NL', 'nl-BE'],
    defaultLocale: 'en-US',

    domains: [
      {
        // Note: subdomains must be included in the domain value to be matched
        // e.g. www.example.com should be used if that is the expected hostname
        domain: 'example.com',
        defaultLocale: 'en-US',
      },
      {
        domain: 'example.fr',
        defaultLocale: 'fr',
      },
      {
        domain: 'example.nl',
        defaultLocale: 'nl-NL',
        // specify other locales that should be redirected
        // to this domain
        locales: ['nl-BE'],
      },
    ],
  },
}

예를 들어 pages/blog.js가 있다면 다음 url을 사용할 수 있습니다:

For example if you have pages/blog.js the following urls will be available:

  • example.com/blog
  • www.example.com/blog
  • example.fr/blog
  • example.nl/blog
  • example.nl/nl-BE/blog
  • example.com/blog
  • www.example.com/blog
  • example.fr/blog
  • example.nl/blog
  • example.nl/nl-BE/blog

Automatic Locale Detection자동 Locale 감지

사용자가 애플리케이션 root(일반적으로 /)에 방문하면, Next.js는 Accept-Language header와 현재 domain을 기반으로 사용자가 선호하는 locale을 자동으로 감지하려고 합니다.

When a user visits the application root (generally /), Next.js will try to automatically detect which locale the user prefers based on the Accept-Language header and the current domain.

default locale이 아닌 locale이 감지되면 사용자는 다음 중 하나로 redirect됩니다:

If a locale other than the default locale is detected, the user will be redirected to either:

  • Sub-path Routing을 사용할 때: locale prefix가 붙은 path
  • Domain Routing을 사용할 때: 해당 locale이 default로 지정된 domain
  • When using Sub-path Routing: The locale prefixed path
  • When using Domain Routing: The domain with that locale specified as the default

Domain Routing을 사용할 때 Accept-Language header가 fr;q=0.9인 사용자가 example.com에 방문하면, example.fr domain이 기본적으로 fr locale을 처리하므로 그쪽으로 redirect됩니다.

When using Domain Routing, if a user with the Accept-Language header fr;q=0.9 visits example.com, they will be redirected to example.fr since that domain handles the fr locale by default.

Sub-path Routing을 사용할 때는 사용자가 /fr로 redirect됩니다.

When using Sub-path Routing, the user would be redirected to /fr.

Prefixing the Default LocaleDefault Locale에 prefix 붙이기

Next.js 12와 Proxy를 사용하면 workaround로 default locale에 prefix를 붙일 수 있습니다.

With Next.js 12 and Proxy, we can add a prefix to the default locale with a workaround.

예를 들어 다음은 몇 가지 언어를 지원하는 next.config.js 파일입니다. "default" locale이 의도적으로 추가되어 있다는 점에 주목하세요.

For example, here's a next.config.js file with support for a few languages. Note the "default" locale has been added intentionally.

JSnext.config.js
module.exports = {
  i18n: {
    locales: ['default', 'en', 'de', 'fr'],
    defaultLocale: 'default',
    localeDetection: false,
  },
  trailingSlash: true,
}

다음으로 Proxy를 사용해 custom routing rule을 추가할 수 있습니다:

Next, we can use Proxy to add custom routing rules:

TSproxy.ts
import { NextRequest, NextResponse } from 'next/server'

const PUBLIC_FILE = /\.(.*)$/

export async function proxy(req: NextRequest) {
  if (
    req.nextUrl.pathname.startsWith('/_next') ||
    req.nextUrl.pathname.includes('/api/') ||
    PUBLIC_FILE.test(req.nextUrl.pathname)
  ) {
    return
  }

  if (req.nextUrl.locale === 'default') {
    const locale = req.cookies.get('NEXT_LOCALE')?.value || 'en'

    return NextResponse.redirect(
      new URL(`/${locale}${req.nextUrl.pathname}${req.nextUrl.search}`, req.url)
    )
  }
}

이 Proxy는 API Routes와 font나 이미지 같은 public 파일에는 default prefix를 붙이지 않습니다. default locale로 request가 들어오면 prefix /en으로 redirect합니다.

This Proxy skips adding the default prefix to API Routes and public files like fonts or images. If a request is made to the default locale, we redirect to our prefix /en.

Disabling Automatic Locale Detection자동 Locale 감지 비활성화

자동 locale 감지는 다음과 같이 비활성화할 수 있습니다:

The automatic locale detection can be disabled with:

JSnext.config.js
module.exports = {
  i18n: {
    localeDetection: false,
  },
}

localeDetection을 false로 설정하면 Next.js는 더 이상 사용자가 선호하는 locale에 따라 자동으로 redirect하지 않으며, 위에서 설명한 locale 기반 domain이나 locale path에서 감지된 locale 정보만 제공합니다.

When localeDetection is set to false Next.js will no longer automatically redirect based on the user's preferred locale and will only provide locale information detected from either the locale based domain or locale path as described above.

Accessing the locale informationLocale 정보 접근하기

Next.js router를 통해 locale 정보에 접근할 수 있습니다. 예를 들어 useRouter() hook을 사용하면 다음 property를 사용할 수 있습니다:

You can access the locale information via the Next.js router. For example, using the useRouter() hook the following properties are available:

  • locale에는 현재 활성화된 locale이 들어 있습니다.
  • locales에는 설정된 모든 locale이 들어 있습니다.
  • defaultLocale에는 설정된 default locale이 들어 있습니다.
  • locale contains the currently active locale.
  • locales contains all configured locales.
  • defaultLocale contains the configured default locale.

getStaticProps나 getServerSideProps로 page를 prerendering할 때는 function에 전달되는 context에 locale 정보가 제공됩니다.

When prerendering pages with getStaticProps or getServerSideProps, the locale information is provided in the context provided to the function.

getStaticPaths를 활용할 때는 function의 context parameter에서 설정된 locale이 locales로, 설정된 defaultLocale이 defaultLocale로 제공됩니다.

When leveraging getStaticPaths, the configured locales are provided in the context parameter of the function under locales and the configured defaultLocale under defaultLocale.

Transition between localesLocale 간 전환

next/link나 next/router를 사용해 locale 간에 전환할 수 있습니다.

You can use next/link or next/router to transition between locales.

next/link에서는 locale prop을 제공해 현재 활성화된 locale과 다른 locale로 전환할 수 있습니다. locale prop을 제공하지 않으면 client-transition 중에 현재 활성화된 locale이 사용됩니다. 예를 들면 다음과 같습니다:

For next/link, a locale prop can be provided to transition to a different locale from the currently active one. If no locale prop is provided, the currently active locale is used during client-transitions. For example:

import Link from 'next/link'

export default function IndexPage(props) {
  return (
    <Link href="/another" locale="fr">
      To /fr/another
    </Link>
  )
}

next/router method를 직접 사용할 때는 transition option으로 사용할 locale을 지정할 수 있습니다. 예를 들면 다음과 같습니다:

When using the next/router methods directly, you can specify the locale that should be used via the transition options. For example:

import { useRouter } from 'next/router'

export default function IndexPage(props) {
  const router = useRouter()

  return (
    <div
      onClick={() => {
        router.push('/another', '/another', { locale: 'fr' })
      }}
    >
      to /fr/another
    </div>
  )
}

dynamic route의 query 값이나 숨겨진 href query 값 같은 모든 routing 정보를 유지하면서 locale만 전환하려면, href parameter를 object로 제공할 수 있습니다:

Note that to handle switching only the locale while preserving all routing information such as dynamic route query values or hidden href query values, you can provide the href parameter as an object:

import { useRouter } from 'next/router'
const router = useRouter()
const { pathname, asPath, query } = router
// change just the locale and maintain all other route information including href's query
router.push({ pathname, query }, asPath, { locale: nextLocale })

router.push의 object 구조에 대한 자세한 내용은 여기를 참고하세요.

See here for more information on the object structure for router.push.

href에 이미 locale이 포함되어 있다면 locale prefix 자동 처리를 opt-out할 수 있습니다:

If you have a href that already includes the locale you can opt-out of automatically handling the locale prefixing:

import Link from 'next/link'

export default function IndexPage(props) {
  return (
    <Link href="/fr/another" locale={false}>
      To /fr/another
    </Link>
  )
}

Leveraging the NEXT_LOCALE cookieNEXT_LOCALE cookie 활용하기

Next.js에서는 accept-language header보다 우선순위가 높은 NEXT_LOCALE=the-locale cookie를 설정할 수 있습니다. 이 cookie는 language switcher로 설정할 수 있으며, 사용자가 사이트에 다시 방문하면 /에서 올바른 locale 위치로 redirect할 때 cookie에 지정된 locale을 활용합니다.

Next.js allows setting a NEXT_LOCALE=the-locale cookie, which takes priority over the accept-language header. This cookie can be set using a language switcher and then when a user comes back to the site it will leverage the locale specified in the cookie when redirecting from / to the correct locale location.

예를 들어 사용자의 accept-language header에서는 fr locale을 선호하지만 NEXT_LOCALE=en cookie가 설정되어 있다면, /에 방문할 때 cookie가 삭제되거나 만료될 때까지 사용자는 en locale 위치로 redirect됩니다.

For example, if a user prefers the locale fr in their accept-language header but a NEXT_LOCALE=en cookie is set the en locale when visiting / the user will be redirected to the en locale location until the cookie is removed or expired.

Search Engine Optimization검색 엔진 최적화

Next.js는 사용자가 어떤 언어로 방문하는지 알기 때문에 <html> tag에 lang attribute를 자동으로 추가합니다.

Since Next.js knows what language the user is visiting it will automatically add the lang attribute to the <html> tag.

Next.js는 page의 variant를 알지 못하므로 next/head를 사용해 hreflang meta tag를 추가하는 것은 직접 해야 합니다. hreflang에 대해서는 Google Webmasters 문서에서 더 알아볼 수 있습니다.

Next.js doesn't know about variants of a page so it's up to you to add the hreflang meta tags using next/head. You can learn more about hreflang in the Google Webmasters documentation.

How does this work with Static Generation?Static Generation과는 어떻게 동작하나요?

Internationalized Routing은 Next.js routing layer를 활용하지 않는 output: 'export'와는 통합되지 않는다는 점에 유의하세요. output: 'export'를 사용하지 않는 hybrid Next.js 애플리케이션은 완전히 지원됩니다.

Note that Internationalized Routing does not integrate with output: 'export' as it does not leverage the Next.js routing layer. Hybrid Next.js applications that do not use output: 'export' are fully supported.

Dynamic Routes and getStaticProps PagesDynamic Routes와 getStaticProps Page

Dynamic Routes와 함께 getStaticProps를 사용하는 page에서는, prerender하려는 page의 모든 locale variant를 getStaticPaths에서 반환해야 합니다. paths로 반환하는 params object와 함께, render할 locale을 지정하는 locale field도 반환할 수 있습니다. 예를 들면 다음과 같습니다:

For pages using getStaticProps with Dynamic Routes, all locale variants of the page desired to be prerendered need to be returned from getStaticPaths. Along with the params object returned for paths, you can also return a locale field specifying which locale you want to render. For example:

JSpages/blog/[slug].js
export const getStaticPaths = ({ locales }) => {
  return {
    paths: [
      // if no `locale` is provided only the defaultLocale will be generated
      { params: { slug: 'post-1' }, locale: 'en-US' },
      { params: { slug: 'post-1' }, locale: 'fr' },
    ],
    fallback: true,
  }
}

Automatically Statically Optimized page와 non-dynamic getStaticProps page의 경우, locale마다 page의 버전이 하나씩 생성됩니다. getStaticProps 안에 설정된 locale 수에 따라 build time이 늘어날 수 있으므로 고려해야 할 중요한 점입니다.

For Automatically Statically Optimized and non-dynamic getStaticProps pages, a version of the page will be generated for each locale. This is important to consider because it can increase build times depending on how many locales are configured inside getStaticProps.

예를 들어 50개의 locale이 설정되어 있고 getStaticProps를 사용하는 non-dynamic page가 10개라면 getStaticProps는 500번 호출됩니다. 매 build마다 10개 page의 50개 버전이 생성됩니다.

For example, if you have 50 locales configured with 10 non-dynamic pages using getStaticProps, this means getStaticProps will be called 500 times. 50 versions of the 10 pages will be generated during each build.

getStaticProps를 사용하는 dynamic page의 build time을 줄이려면 fallback mode를 사용하세요. 이렇게 하면 build 중 prerendering을 위해 getStaticPaths에서 가장 인기 있는 path와 locale만 반환할 수 있습니다. 그러면 Next.js는 나머지 page를 request될 때 runtime에 build합니다.

To decrease the build time of dynamic pages with getStaticProps, use a fallback mode. This allows you to return only the most popular paths and locales from getStaticPaths for prerendering during the build. Then, Next.js will build the remaining pages at runtime as they are requested.

Automatically Statically Optimized PagesAutomatically Statically Optimized Page

automatically statically optimized page의 경우 locale마다 page의 버전이 하나씩 생성됩니다.

For pages that are automatically statically optimized, a version of the page will be generated for each locale.

Non-dynamic getStaticProps PagesNon-dynamic getStaticProps Page

non-dynamic getStaticProps page의 경우에도 위와 같이 locale마다 버전이 생성됩니다. getStaticProps는 render되는 각 locale과 함께 호출됩니다. 특정 locale을 prerender 대상에서 opt-out하고 싶다면 getStaticProps에서 notFound: true를 반환하면 해당 page variant는 생성되지 않습니다.

For non-dynamic getStaticProps pages, a version is generated for each locale like above. getStaticProps is called with each locale that is being rendered. If you would like to opt-out of a certain locale from being prerendered, you can return notFound: true from getStaticProps and this variant of the page will not be generated.

export async function getStaticProps({ locale }) {
  // Call an external API endpoint to get posts.
  // You can use any data fetching library
  const res = await fetch(`https://.../posts?locale=${locale}`)
  const posts = await res.json()

  if (posts.length === 0) {
    return {
      notFound: true,
    }
  }

  // By returning { props: posts }, the Blog component
  // will receive `posts` as a prop at build time
  return {
    props: {
      posts,
    },
  }
}

Limits for the i18n configi18n config의 제한

  • locales: 총 100개 locale
  • domains: 총 100개 locale domain 항목
  • locales: 100 total locales
  • domains: 100 total locale domain items
Good to know

이 제한은 처음에 잠재적인 build time performance 문제를 막기 위해 추가되었습니다. Next.js 12에서는 Proxy를 사용한 custom routing으로 이 제한을 우회할 수 있습니다.

These limits have been added initially to prevent potential performance issues at build time. You can workaround these limits with custom routing using Proxy in Next.js 12.
