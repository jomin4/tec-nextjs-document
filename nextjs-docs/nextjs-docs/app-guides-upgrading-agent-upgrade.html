Upgrade with a coding agentexperimentalcoding agent로 업그레이드하기

next upgrade --agent를 사용하면 coding agent가 앱을 upgrade하고 검증하게 할 수 있습니다. 이 command는 설정된 policy에서 target 버전을 결정하고, 관련 migration guide와 Skill을 준비한 다음, 작업을 agent에게 넘깁니다.

Use next upgrade --agent to have a coding agent upgrade and verify your app. The command determines the target version from the configured policy, prepares the relevant migration guides and Skills, and hands the task to the agent.

이 command는 App Router와 Pages Router 프로젝트를 모두 지원합니다. --agent 없이 실행하면 next upgrade는 대신 interactive codemod workflow를 실행합니다.

The command supports App Router and Pages Router projects. Without --agent, next upgrade runs the interactive codemod workflow instead.

Start an upgradeupgrade 시작하기

앱 directory에서 최신 upgrade CLI를 실행하세요:

Run the latest upgrade CLI from your app's directory:

>_Terminal
npx next@canary upgrade --agent=latest

workspace root에서는 앱 directory를 전달하세요:

From a workspace root, pass the app directory:

>_Terminal
npx next@canary upgrade apps/web --agent=latest

next@canary를 사용하면 앱이 더 오래된 Next.js 버전을 쓰고 있더라도 최신 upgrade tooling이 실행됩니다. CLI는 앱에 설치된 버전을 읽고, 앱이 이미 canary 버전을 사용하는 경우에만 canary target을 선택합니다. 프로젝트의 package manager가 minimum release age를 설정해 두었다면, CLI는 그 policy가 허용하는 가장 최신 canary를 사용합니다.

Using next@canary runs the latest upgrade tooling, even when the app uses an older Next.js version. The CLI reads the version installed in the app and selects a canary target only when the app already uses a canary version. If the project's package manager sets a minimum release age, the CLI uses the newest canary that policy allows.

Choose a policypolicy 선택하기

Policy동작
security영향을 받는 stable 버전에 대해, 적용 가능한 가장 이른 major에서 가장 최신의 안전한 release를 선택합니다.
lateststable, RC, beta, preview 앱은 npm의 latest stable release로, canary 앱은 canary release로 옮깁니다.
experimental-futurelatest policy를 적용한 다음, 해당되는 Future Defaults를 도입합니다.
PolicyBehavior
securityFor an affected stable version, selects the latest safe release in the earliest eligible major.
latestMoves stable, RC, beta, and preview apps to npm's latest stable release, or a canary app to the canary release.
experimental-futureApplies the latest policy, then adopts applicable Future Defaults.

policy를 생략하면 experimental.agentUpgrade의 string 값을 사용합니다. 그 값도 없으면 command는 security를 사용합니다:

Omit the policy to use the string value from experimental.agentUpgrade. Otherwise, the command uses security:

>_Terminal
npx next@canary upgrade --agent

--agent는 --revision과 함께 사용할 수 없습니다.

--agent cannot be combined with --revision.

security는 stable 설치를 지원합니다. canary 설치는 latest 또는 experimental-future를 사용할 수 있습니다. RC, beta, preview 설치는 latest를 사용해 더 새로운 stable release로 옮길 수 있습니다. 그 밖의 prerelease channel은 지원되지 않습니다.

security supports stable installations. Canary installations can use latest or experimental-future. RC, beta, and preview installations can use latest to move to a newer stable release. Other prerelease channels are not supported.

Adopt future defaultsfuture default 도입하기

Future Defaults는 Cache Components와 Partial Prefetching처럼 Next.js가 기본으로 활성화할 계획인 기능입니다. experimental-future policy는 앱이 이미 최신 Next.js 버전을 사용하고 있더라도 upgrade가 이런 기능의 도입을 돕는 방식의 초기 버전입니다. 그러면 새 default로 옮겨가는 일이 별도의 migration이 아니라 upgrade의 일부가 됩니다.

Future Defaults are features Next.js plans to enable by default, such as Cache Components and Partial Prefetching. The experimental-future policy is an early version of how upgrades will help apps adopt them, even when the app already uses the latest Next.js version. Moving to a new default then becomes part of the upgrade instead of a separate migration.

Next.js 16.3 이상의 App Router 프로젝트에서는 현재 이 policy가 Cache Components guide와 adoption Skill을 준비합니다:

For App Router projects on Next.js 16.3 or later, the policy currently prepares the Cache Components guide and adoption Skill:

>_Terminal
npx next@canary upgrade --agent=experimental-future

Pages Router 프로젝트도 버전 upgrade에는 이 policy를 사용할 수 있지만, 프로젝트가 App Router를 사용하기 전까지는 Cache Components를 제공하지 않습니다.

Pages Router projects can use it for version upgrades, but it does not offer Cache Components until the project uses the App Router.

지금 바로 새 기능을 도입하려면 해당 adoption Skill을 직접 사용하세요. Migrating to Cache Components와 Adopting Partial Prefetching을 참고하세요.

To adopt new features today, use their adoption Skills directly. See Migrating to Cache Components and Adopting Partial Prefetching.

What the command doescommand가 하는 일

agent session을 시작하기 전에 CLI는 설치된 버전, release metadata, 그리고 선택한 policy에 필요한 security data를 확인합니다. upgrade가 필요 없거나 target을 정할 수 없으면 설명과 함께 중단합니다.

Before starting an agent session, the CLI checks the installed version, release metadata, and any security data required by the selected policy. It stops with an explanation when no upgrade is needed or it cannot establish a target.

upgrade 준비가 되면 CLI는 관련 migration guide를 임시 directory로 복사하고, 해당되는 Skill을 준비하고, 선택한 target에 대한 task를 만듭니다. major upgrade의 경우 task에는 거쳐 가는 모든 major 버전의 guide가 포함됩니다. 또한 agent에게 중복 작업이 있는지 확인하고, 가능하면 별도의 Git worktree를 사용하고, 관련 check를 실행하고, 결과를 검증하도록 요청합니다.

For a ready upgrade, the CLI copies the relevant migration guides into a temporary directory, prepares the applicable Skills, and creates a task for the selected target. For a major upgrade, the task includes the guide for every major version crossed. It also asks the agent to check for duplicate work, use a separate Git worktree when available, run the relevant checks, and verify the result.

task는 agent에게 이후 upgrade reminder를 위해 선택한 policy를 next.config에 experimental.agentUpgrade로 저장하도록 요청하기도 합니다. reminder를 끄려면 이 option을 false로 설정하세요.

The task also asks the agent to save the selected policy as experimental.agentUpgrade in next.config for future upgrade reminders. To disable reminders, set the option to false.

coding agent 안에서 command를 실행하면 CLI는 현재 agent가 따를 task를 출력합니다. interactive terminal에서는 설치된 Codex 또는 Claude Code session을 시작하거나, 다른 agent를 위해 task를 복사할 수 있습니다. non-interactive terminal에서는 task를 출력합니다.

When you run the command inside a coding agent, the CLI prints the task for the current agent to follow. In an interactive terminal, it can start an installed Codex or Claude Code session, or copy the task for another agent. In a non-interactive terminal, it prints the task.

Choose how to run the agentagent 실행 방식 선택하기

interactive terminal에서 command를 시작하면 설치된 agent 중 어떤 것을 사용할지 묻습니다. 새 agent session의 경우 model, reasoning effort, Auto permission 사용 여부, 별도의 Git worktree 사용 여부도 선택할 수 있습니다. 선택 가능한 항목은 선택한 agent와 CLI 버전에 따라 달라집니다.

When you start the command from an interactive terminal, it asks which installed agent to use. For a new agent session, you can also choose its model, reasoning effort, whether to use Auto permissions, and whether to use a separate Git worktree. The available choices depend on the selected agent and CLI version.

기존 coding agent에서 command를 실행하면 준비된 task를 그 agent에게 대신 제공합니다. agent는 해당 session에 이미 설정된 model, reasoning effort, permission을 그대로 유지합니다.

When you run the command from an existing coding agent, it provides the prepared task to that agent instead. The agent keeps the model, reasoning effort, and permissions already configured for its session.

Configure upgrade remindersupgrade reminder 설정하기

upgrade reminder는 기본적으로 security policy로 활성화되어 있습니다. 다른 policy를 선택하거나 reminder를 끄려면 experimental.agentUpgrade를 설정하세요:

Upgrade reminders are enabled by default with the security policy. Set experimental.agentUpgrade to choose another policy or disable reminders:

TSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    agentUpgrade: 'latest',
  },
}

export default nextConfig

reminder를 끄려면 이 option을 false로 설정하세요.

Set the option to false to disable reminders.

이 option이 앱을 자동으로 upgrade하지는 않습니다. interactive terminal에서는 reminder가 열려 있는 동안에도 next dev 또는 next build가 계속 실행되며 그 output을 buffer에 담아 둡니다. Upgrade now는 upgrade를 시작하기 전에 command를 중단합니다. Skip은 실행 중인 command로 돌아가서 그 output을 다시 보여 줍니다. Skip until next version은 설치된 버전에 대한 reminder를 닫습니다. 자세한 내용은 Reminder behavior를 참고하세요.

The option does not upgrade the app automatically. In an interactive terminal, next dev or next build continues while the reminder is open and buffers its output. Upgrade now stops the command before starting the upgrade. Skip returns to the running command and replays that output. Skip until next version dismisses the reminder for the installed version. See Reminder behavior for details.

coding agent가 reminder를 만나면 사용 가능한 upgrade를 보고하고, command를 다시 시도한 뒤 원래 작업을 이어 갈 수 있습니다.

When a coding agent encounters a reminder, it reports the available upgrade and can continue the original task after retrying the command.

next dev 실행 중에 설치된 버전이 알려진 security vulnerability의 영향을 받는 경우, Next.js DevTools가 Vulnerability Insight를 표시할 수도 있습니다. 이 insight는 coding agent로 security upgrade를 시작할 수 있도록 복사 가능한 prompt를 제공합니다.

During next dev, Next.js DevTools can also show a Vulnerability Insight when the installed version is affected by a known security vulnerability. The insight provides a copyable prompt for starting a security upgrade with a coding agent.

CLI는 release metadata에 접근할 수 있어야 하고, stable target의 경우 security advisory data에도 접근할 수 있어야 합니다. target을 정할 수 없으면 agent session을 시작하지 않고 그 이유를 보고합니다.

The CLI needs access to release metadata and, for stable targets, security advisory data. If it cannot establish a target, it reports the reason without starting an agent session.
