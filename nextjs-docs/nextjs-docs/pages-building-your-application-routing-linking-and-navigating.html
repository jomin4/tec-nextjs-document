Linking and NavigatingLink와 Navigation

Next.js router를 사용하면 single-page application처럼 page 사이에서 client-side route 전환을 할 수 있습니다.

The Next.js router allows you to do client-side route transitions between pages, similar to a single-page application.

이 client-side route 전환을 위해 Link라는 React component가 제공됩니다.

A React component called Link is provided to do this client-side route transition.

import Link from 'next/link'

function Home() {
  return (
    <ul>
      <li>
        <Link href="/">Home</Link>
      </li>
      <li>
        <Link href="/about">About Us</Link>
      </li>
      <li>
        <Link href="/blog/hello-world">Blog Post</Link>
      </li>
    </ul>
  )
}

export default Home

위 예시는 여러 link를 사용합니다. 각 link는 path(href)를 알려진 page에 mapping합니다:

The example above uses multiple links. Each one maps a path (href) to a known page:

  • / → pages/index.js
  • /about → pages/about.js
  • /blog/hello-world → pages/blog/[slug].js
  • / → pages/index.js
  • /about → pages/about.js
  • /blog/hello-world → pages/blog/[slug].js

viewport 안에 있는(처음부터 보이거나 scroll로 보이게 된) 모든 <Link />는 Static Generation을 사용하는 page라면 기본적으로 (해당 data를 포함해) prefetch됩니다. server-rendered route의 해당 data는 <Link />를 클릭했을 때만 fetch됩니다.

Any <Link /> in the viewport (initially or through scroll) will be prefetched by default (including the corresponding data) for pages using Static Generation. The corresponding data for server-rendered routes is fetched only when the <Link /> is clicked.

Linking to dynamic pathsdynamic path로 link하기

interpolation을 사용해 path를 만들 수도 있으며, 이는 dynamic route segment에 유용합니다. 예를 들어 component에 prop으로 전달된 post 목록을 보여 주려면 다음과 같이 합니다:

You can also use interpolation to create the path, which comes in handy for dynamic route segments. For example, to show a list of posts which have been passed to the component as a prop:

import Link from 'next/link'

function Posts({ posts }) {
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>
          <Link href={`/blog/${encodeURIComponent(post.slug)}`}>
            {post.title}
          </Link>
        </li>
      ))}
    </ul>
  )
}

export default Posts

예시에서는 path가 utf-8과 호환되도록 encodeURIComponent를 사용합니다.

encodeURIComponent is used in the example to keep the path utf-8 compatible.

또는 URL Object를 사용할 수도 있습니다:

Alternatively, using a URL Object:

import Link from 'next/link'

function Posts({ posts }) {
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>
          <Link
            href={{
              pathname: '/blog/[slug]',
              query: { slug: post.slug },
            }}
          >
            {post.title}
          </Link>
        </li>
      ))}
    </ul>
  )
}

export default Posts

이제 interpolation으로 path를 만드는 대신 href에 URL object를 사용합니다. 여기서:

Now, instead of using interpolation to create the path, we use a URL object in href where:

  • pathname은 pages directory 안의 page 이름입니다. 이 경우 /blog/[slug]입니다.
  • query는 dynamic segment를 담은 object입니다. 이 경우 slug입니다.
  • pathname is the name of the page in the pages directory. /blog/[slug] in this case.
  • query is an object with the dynamic segment. slug in this case.

Injecting the routerrouter 주입하기

React component에서 router object에 접근하려면 useRouter 또는 withRouter를 사용할 수 있습니다.

To access the router object in a React component you can use useRouter or withRouter.

일반적으로는 useRouter 사용을 권장합니다.

In general we recommend using useRouter.

Imperative Routing명령형 Routing

대부분의 routing 요구는 next/link로 충분히 해결할 수 있지만, 이것 없이도 client-side navigation을 할 수 있습니다. next/router 문서를 살펴보세요.

next/link should be able to cover most of your routing needs, but you can also do client-side navigations without it, take a look at the documentation for next/router.

다음 예시는 useRouter로 기본적인 page navigation을 하는 방법을 보여 줍니다:

The following example shows how to do basic page navigations with useRouter:

import { useRouter } from 'next/router'

export default function ReadMore() {
  const router = useRouter()

  return (
    <button onClick={() => router.push('/about')}>
      Click here to read more
    </button>
  )
}

Shallow Routing

예시
  • Shallow Routing

Shallow routing을 사용하면 data fetching method를 다시 실행하지 않고 URL을 바꿀 수 있습니다. 여기에는 getServerSideProps, getStaticProps, getInitialProps가 포함됩니다.

Shallow routing allows you to change the URL without running data fetching methods again, that includes getServerSideProps, getStaticProps, and getInitialProps.

state를 잃지 않은 채, (useRouter나 withRouter가 추가해 주는) router object를 통해 업데이트된 pathname과 query를 받게 됩니다.

You'll receive the updated pathname and the query via the router object (added by useRouter or withRouter), without losing state.

shallow routing을 활성화하려면 shallow option을 true로 설정하세요. 다음 예시를 살펴보세요:

To enable shallow routing, set the shallow option to true. Consider the following example:

import { useEffect } from 'react'
import { useRouter } from 'next/router'

// Current URL is '/'
function Page() {
  const router = useRouter()

  useEffect(() => {
    // Always do navigations after the first render
    router.push('/?counter=10', undefined, { shallow: true })
  }, [])

  useEffect(() => {
    // The counter changed!
  }, [router.query.counter])
}

export default Page

URL은 /?counter=10으로 업데이트되고 page는 교체되지 않으며, route의 state만 바뀝니다.

The URL will get updated to /?counter=10 and the page won't get replaced, only the state of the route is changed.

아래처럼 componentDidUpdate로 URL 변경을 감지할 수도 있습니다:

You can also watch for URL changes via componentDidUpdate as shown below:

componentDidUpdate(prevProps) {
  const { pathname, query } = this.props.router
  // verify props have changed to avoid an infinite loop
  if (query.counter !== prevProps.router.query.counter) {
    // fetch data based on the new query
  }
}

Caveats주의 사항

Shallow routing은 현재 page 안에서의 URL 변경에만 동작합니다. 예를 들어 pages/about.js라는 다른 page가 있다고 가정하고 다음을 실행해 봅시다:

Shallow routing only works for URL changes in the current page. For example, let's assume we have another page called pages/about.js, and you run this:

router.push('/?counter=10', '/about?counter=10', { shallow: true })

이는 새 page이므로, shallow routing을 요청했더라도 현재 page를 unload하고 새 page를 load한 뒤 data fetching을 기다립니다.

Since that's a new page, it'll unload the current page, load the new one and wait for data fetching even though we asked to do shallow routing.

shallow routing을 proxy와 함께 사용하면, proxy가 없을 때처럼 새 page가 현재 page와 match되는지 보장하지 않습니다. proxy는 dynamic하게 rewrite할 수 있고, 이는 data fetch 없이는 client-side에서 검증할 수 없는데 shallow에서는 그 data fetch를 건너뛰기 때문입니다. 따라서 shallow route 변경은 항상 shallow로 취급되어야 합니다.

When shallow routing is used with proxy it will not ensure the new page matches the current page like previously done without proxy. This is due to proxy being able to rewrite dynamically and can't be verified client-side without a data fetch which is skipped with shallow, so a shallow route change must always be treated as shallow.
