instrumentation.jsinstrumentation.js

instrumentation.js|ts 파일은 observability 도구를 애플리케이션에 통합하는 데 사용되며, 이를 통해 performance와 동작을 추적하고 production에서 발생한 문제를 디버깅할 수 있습니다.

The instrumentation.js|ts file is used to integrate observability tools into your application, allowing you to track the performance and behavior, and to debug issues in production.

사용하려면 이 파일을 애플리케이션의 root에 두거나, src 폴더를 사용 중이라면 그 안에 두세요.

To use it, place the file in the root of your application or inside a src folder if using one.

Exports

register (optional)

이 파일은 새 Next.js server instance가 시작될 때 한 번 호출되는 register 함수를 export하며, 이 함수는 server가 request를 처리할 준비가 되기 전에 완료되어야 합니다. register는 async 함수일 수 있습니다.

The file exports a register function that is called once when a new Next.js server instance is initiated, and must complete before the server is ready to handle requests. register can be an async function.

TSJSinstrumentation.ts
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}

onRequestError (optional)

선택적으로 onRequestError 함수를 export해 server error를 원하는 custom observability provider로 추적할 수 있습니다.

You can optionally export an onRequestError function to track server errors to any custom observability provider.

  • onRequestError에서 async 작업을 실행한다면 반드시 await하세요. onRequestError는 Next.js server가 error를 capture할 때 trigger됩니다.
  • error instance는 throw된 원래 error instance가 아닐 수 있습니다. Server Component rendering 중에 발생한 error라면 React가 처리했을 수 있기 때문입니다. 이런 경우 error의 digest property를 사용해 실제 error type을 식별할 수 있습니다.
  • If you're running any async tasks in onRequestError, make sure they're awaited. onRequestError will be triggered when the Next.js server captures the error.
  • The error instance might not be the original error instance thrown, as it may be processed by React if encountered during Server Components rendering. If this happens, you can use digest property on an error to identify the actual error type.
TSJSinstrumentation.ts
import { type Instrumentation } from 'next'

export const onRequestError: Instrumentation.onRequestError = async (
  err,
  request,
  context
) => {
  const message = err instanceof Error ? err.message : String(err)
  const digest =
    typeof err === 'object' && err !== null && 'digest' in err
      ? String(err.digest)
      : undefined

  await fetch('https://.../report-error', {
    method: 'POST',
    body: JSON.stringify({
      message,
      digest,
      request,
      context,
    }),
    headers: {
      'Content-Type': 'application/json',
    },
  })
}

Parameters

이 함수는 error, request, context 세 개의 parameter를 받습니다.

The function accepts three parameters: error, request, and context.

TSTypes
export function onRequestError(
  error: unknown,
  request: {
    path: string // resource path, e.g. /blog?name=foo
    method: string // request method. e.g. GET, POST, etc
    headers: { [key: string]: string | string[] }
  },
  context: {
    routerKind: 'Pages Router' | 'App Router' // the router type
    routePath: string // the route file path, e.g. /app/blog/[dynamic]
    routeType: 'render' | 'route' | 'action' | 'proxy' // the context in which the error occurred
    renderSource:
      | 'react-server-components'
      | 'react-server-components-payload'
      | 'server-rendering'
    revalidateReason: 'on-demand' | 'stale' | undefined // undefined is a normal request without revalidation
    renderType: 'dynamic' | 'dynamic-resume' // 'dynamic-resume' for PPR
  }
): void | Promise<void>
  • error: catch된 값은 unknown type입니다. message나 digest 같은 property를 읽기 전에 type을 좁히세요.
  • request: error와 관련된 읽기 전용 request 정보입니다.
  • context: error가 발생한 context입니다. router의 종류(App 또는 Pages Router), 그리고/또는 (Server Components('render'), Route Handlers('route'), Server Actions('action'), Proxy('proxy'))가 될 수 있습니다.
  • error: The caught value is typed as unknown. Narrow it before reading properties like message or digest.
  • request: Read-only request information associated with the error.
  • context: The context in which the error occurred. This can be the type of router (App or Pages Router), and/or (Server Components ('render'), Route Handlers ('route'), Server Actions ('action'), or Proxy ('proxy')).

Specifying the runtimeruntime 지정하기

instrumentation.js 파일은 Node.js와 Edge runtime 모두에서 동작하지만, process.env.NEXT_RUNTIME을 사용해 특정 runtime을 target으로 지정할 수 있습니다.

The instrumentation.js file works in both the Node.js and Edge runtime, however, you can use process.env.NEXT_RUNTIME to target a specific runtime.

JSinstrumentation.js
export function register() {
  if (process.env.NEXT_RUNTIME === 'edge') {
    return require('./register.edge')
  } else {
    return require('./register.node')
  }
}

export function onRequestError() {
  if (process.env.NEXT_RUNTIME === 'edge') {
    return require('./on-request-error.edge')
  } else {
    return require('./on-request-error.node')
  }
}
