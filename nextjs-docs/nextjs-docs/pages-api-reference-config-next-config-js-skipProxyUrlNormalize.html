skipProxyUrlNormalizeskipProxyUrlNormalize

skipProxyUrlNormalize를 활성화하면 Proxy가 Next.js가 normalize한 버전 대신 원래 request를 보게 됩니다. 여기에는 client-side navigation 중에 사용되는 내부 URL, query parameter, header가 포함됩니다.

Enabling skipProxyUrlNormalize lets Proxy see the original request instead of Next.js's normalized version. This includes internal URLs, query parameters, and headers used during client-side navigation.

대부분의 프로젝트에는 이 option이 필요하지 않습니다. 이 option은 advanced Proxy flag 중 하나로, 특정 routing 상황과 debugging을 위한 것입니다.

Most projects don't need this option. It is one of the advanced Proxy flags, meant for specific routing cases and debugging.

TSJSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  skipProxyUrlNormalize: true,
}

export default nextConfig
/** @type {import('next').NextConfig} */
const nextConfig = {
  skipProxyUrlNormalize: true,
}

module.exports = nextConfig

Reference레퍼런스

client-side navigation 중에 Next.js는 destination URL을 전체 document load로 요청하는 대신 내부 request를 사용합니다. 기본적으로 Next.js는 이 request가 Proxy에 도달하기 전에 normalize하므로, Proxy는 client-side navigation과 전체 페이지 load 모두에서 같은 destination URL을 보게 됩니다.

During client-side navigation, Next.js uses an internal request rather than requesting the destination URL as a full document load. By default, Next.js normalizes that request before it reaches Proxy, so Proxy sees the same destination URL for both client-side navigation and a full page load.

Next.js는 Proxy가 반환하는 값도 normalize하므로, rewrite 또는 redirect하는 URL도 그에 맞게 다시 작성됩니다.

Next.js also normalizes what Proxy returns, so any URL you rewrite or redirect to is rewritten to match.

skipProxyUrlNormalize: true를 사용하면 두 normalize 모두 실행되지 않습니다. Proxy는 보내진 그대로의 request를 받고, Proxy가 rewrite 또는 redirect하는 destination은 작성한 그대로 전송됩니다:

With skipProxyUrlNormalize: true, neither normalization runs. Proxy receives the request as sent, and the destinations it rewrites or redirects to are sent as written:

Deprecated aliasDeprecated된 alias

이 option의 이전 이름은 Proxy가 Middleware로 불리던 시절의 skipMiddlewareUrlNormalize입니다. 이 이름은 여전히 동작하며 deprecation warning을 log로 남깁니다. 둘을 동시에 설정하면 error가 발생합니다:

The former name of this option is skipMiddlewareUrlNormalize, from when Proxy was called Middleware. It still works and logs a deprecation warning. Setting both at once throws:

>_Terminal
Config options `skipProxyUrlNormalize` and `skipMiddlewareUrlNormalize` cannot be set at the same time. Please use `skipProxyUrlNormalize` instead.

version 16 codemod가 이름을 자동으로 바꿔 줍니다.

The version 16 codemod renames it for you.

Good to know알아 두면 좋은 점

  • client-side navigation과 전체 페이지 load에서 서로 다른 콘텐츠를 반환하기 위해 내부 navigation header를 사용하는 것은 피하세요.
  • Proxy가 실행되는 route를 제한하려고 이 option을 쓸 필요는 없습니다. matcher config는 어느 경우든 여전히 destination URL과 match됩니다.
  • 바뀌는 것은 Proxy가 보는 request와 response뿐입니다. filesystem routing과 next.config.js의 redirects, rewrites는 똑같이 동작합니다.
  • Avoid using the internal navigation headers to return different content for client-side navigation and full page loads.
  • You do not need this option to limit which routes Proxy runs on. The matcher config still matches the destination URL either way.
  • Only the request and response Proxy sees change. Filesystem routing, redirects, and rewrites from next.config.js behave the same.

Examples예시

Reading the URL as the client sent itclient가 보낸 그대로 URL 읽기

client-side navigation 중에 Next.js는 destination URL 대신 /_next/data URL을 요청합니다. 이 option을 활성화하면 Proxy는 그 URL을 보내진 그대로 보게 됩니다.

During client-side navigation, Next.js requests a /_next/data URL instead of the destination URL. With the option enabled, Proxy sees that URL as sent.

TSJSproxy.ts
import type { NextRequest } from 'next/server'

export default function proxy(request: NextRequest) {
  const { pathname } = request.nextUrl

  // Request: GET /_next/data/build-id/hello.json
  console.log(pathname)
  // Enabled: /_next/data/build-id/hello.json
  // Disabled: /hello
}
export default function proxy(request) {
  const { pathname } = request.nextUrl

  // Request: GET /_next/data/build-id/hello.json
  console.log(pathname)
  // Enabled: /_next/data/build-id/hello.json
  // Disabled: /hello
}
