cookiescookies

cookies는 Server Components에서 들어오는 HTTP request의 cookie를 읽고, Server Functions나 Route Handlers에서 나가는 request의 cookie를 읽고 쓸 수 있게 해 주는 async 함수입니다.

cookies is an async function that allows you to read the HTTP incoming request cookies in Server Components, and read/write outgoing request cookies in Server Functions or Route Handlers.

TSJSapp/page.tsx
import { cookies } from 'next/headers'

export default async function Page() {
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')
  return '...'
}
import { cookies } from 'next/headers'

export default async function Page() {
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')
  return '...'
}

Good to know

  • cookies는 promise를 반환하는 asynchronous 함수입니다. cookie에 접근하려면 async/await나 React의 use 함수를 사용해야 합니다.
    • 버전 14 이하에서 cookies는 synchronous 함수였습니다. 하위 호환성을 위해 Next.js 15에서도 여전히 synchronous하게 접근할 수 있지만, 이 동작은 앞으로 deprecated될 예정입니다.
  • cookies는 반환값을 미리 알 수 없는 Request-time API입니다. layout이나 page에서 사용하면 해당 route는 dynamic rendering으로 전환됩니다.
  • Cache Components를 사용할 때 <Suspense> boundary 바깥에서 cookies()를 호출하면 route가 prerender되지 않습니다. 해결 방법은 Next.js encountered runtime data during prerendering을 참고하세요.
  • .delete method는 다음 경우에만 호출할 수 있습니다:
    • Server Function이나 Route Handler 안에서.
    • .set을 호출한 곳과 같은 domain에 속할 때. wildcard domain의 경우 특정 subdomain이 정확히 일치해야 합니다. 또한 코드는 삭제하려는 cookie와 같은 protocol(HTTP 또는 HTTPS)에서 실행되어야 합니다.
  • HTTP는 streaming이 시작된 뒤에 cookie를 설정하는 것을 허용하지 않으므로, .set은 반드시 Server Function이나 Route Handler에서 사용해야 합니다.
  • cookies is an asynchronous function that returns a promise. You must use async/await or React's use function to access cookies.
    • In version 14 and earlier, cookies was a synchronous function. To help with backwards compatibility, you can still access it synchronously in Next.js 15, but this behavior will be deprecated in the future.
  • cookies is a Request-time API whose returned values cannot be known ahead of time. Using it in a layout or page will opt a route into dynamic rendering.
  • With Cache Components, calling cookies() outside of a <Suspense> boundary prevents the route from being prerendered. See Next.js encountered runtime data during prerendering for fix options.
  • The .delete method can only be called:
    • In a Server Function or Route Handler.
    • If it belongs to the same domain from which .set is called. For wildcard domains, the specific subdomain must be an exact match. Additionally, the code must be executed on the same protocol (HTTP or HTTPS) as the cookie you want to delete.
  • HTTP does not allow setting cookies after streaming starts, so you must use .set in a Server Function or Route Handler.

Understanding Cookie Behavior in Server ComponentsServer Component에서의 cookie 동작 이해하기

Server Component에서 cookie를 다룰 때는 cookie가 근본적으로 client-side 저장 메커니즘이라는 점을 이해하는 것이 중요합니다:

When working with cookies in Server Components, it's important to understand that cookies are fundamentally a client-side storage mechanism:

  • cookie 읽기는 Server Component에서 동작합니다. client의 브라우저가 HTTP request header에 담아 server로 보내는 cookie 데이터에 접근하는 것이기 때문입니다.
  • cookie 설정은 Server Component rendering 중에는 지원되지 않습니다. cookie를 수정하려면 client에서 Server Function을 호출하거나 Route Handler를 사용하세요.
  • Reading cookies works in Server Components because you're accessing the cookie data that the client's browser sends to the server in the HTTP request headers.
  • Setting cookies is not supported during Server Component rendering. To modify cookies, invoke a Server Function from the client or use a Route Handler.

server는 브라우저에게 cookie를 저장하라는 지시(Set-Cookie header를 통해)만 보낼 수 있으며, 실제 저장은 client side에서 일어납니다. 그래서 state를 수정하는 cookie 작업(.set, .delete)은 response header를 제대로 설정할 수 있는 Server Function이나 Route Handler에서 수행해야 합니다.

The server can only send instructions (via Set-Cookie headers) to tell the browser to store cookies - the actual storage happens on the client side. This is why cookie operations that modify state (.set, .delete) must be performed in a Server Function or Route Handler where the response headers can be properly set.

Understanding Cookie Behavior in Server FunctionsServer Function에서의 cookie 동작 이해하기

Server Function에서 cookie를 설정하거나 삭제한 뒤, 그 함수가 Server Action으로 사용되면(예: form의 action prop으로 전달된 경우) Next.js는 업데이트된 UI와 새 데이터를 한 번의 server roundtrip으로 함께 반환할 수 있습니다. Caching and Revalidating을 참고하세요.

After you set or delete a cookie in a Server Function, Next.js can return both the updated UI and new data in a single server roundtrip when the function is used as a Server Action (e.g., passed to a form's action prop). See Caching and Revalidating.

UI는 unmount되지 않지만, server에서 오는 데이터에 의존하는 effect는 다시 실행됩니다.

The UI is not unmounted, but effects that depend on data coming from the server will re-run.

cache된 데이터도 새로 고치려면 함수 안에서 revalidatePath나 revalidateTag를 호출하세요.

To refresh cached data too, call revalidatePath or revalidateTag inside the function.

Getting a cookiecookie 가져오기

(await cookies()).get('name') method로 cookie 하나를 가져올 수 있습니다:

You can use the (await cookies()).get('name') method to get a single cookie:

TSJSapp/page.tsx

export default async function Page() {
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')
  return '...'
}
import { cookies } from 'next/headers'

export default async function Page() {
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')
  return '...'
}

Getting all cookies모든 cookie 가져오기

(await cookies()).getAll() method로 이름이 일치하는 모든 cookie를 가져올 수 있습니다. name을 지정하지 않으면 사용 가능한 모든 cookie를 반환합니다.

You can use the (await cookies()).getAll() method to get all cookies with a matching name. If name is unspecified, it returns all the available cookies.

TSJSapp/page.tsx
import { cookies } from 'next/headers'

export default async function Page() {
  const cookieStore = await cookies()
  return cookieStore.getAll().map((cookie) => (
    <div key={cookie.name}>
      <p>Name: {cookie.name}</p>
      <p>Value: {cookie.value}</p>
    </div>
  ))
}
import { cookies } from 'next/headers'

export default async function Page() {
  const cookieStore = await cookies()
  return cookieStore.getAll().map((cookie) => (
    <div key={cookie.name}>
      <p>Name: {cookie.name}</p>
      <p>Value: {cookie.value}</p>
    </div>
  ))
}

Setting a cookiecookie 설정하기

Server Function이나 Route Handler에서 (await cookies()).set(name, value, options) method로 cookie를 설정할 수 있습니다. options object는 선택 사항입니다.

You can use the (await cookies()).set(name, value, options) method in a Server Function or Route Handler to set a cookie. The options object is optional.

TSJSapp/actions.ts
'use server'

import { cookies } from 'next/headers'

export async function create(data) {
  const cookieStore = await cookies()

  cookieStore.set('name', 'lee')
  // or
  cookieStore.set('name', 'lee', { secure: true })
  // or
  cookieStore.set({
    name: 'name',
    value: 'lee',
    httpOnly: true,
    path: '/',
  })
}
'use server'

import { cookies } from 'next/headers'

export async function create(data) {
  const cookieStore = await cookies()

  cookieStore.set('name', 'lee')
  // or
  cookieStore.set('name', 'lee', { secure: true })
  // or
  cookieStore.set({
    name: 'name',
    value: 'lee',
    httpOnly: true,
    path: '/',
  })
}

Deleting cookiescookie 삭제하기

cookie를 삭제하는 방법은 세 가지가 있습니다.

There are three ways you can delete a cookie.

delete() method 사용하기:

Using the delete() method:

TSJSapp/actions.ts
'use server'

import { cookies } from 'next/headers'

export async function deleteCookie(data) {
  const cookieStore = await cookies()
  cookieStore.delete('name')
}
'use server'

import { cookies } from 'next/headers'

export async function deleteCookie(data) {
  const cookieStore = await cookies()
  cookieStore.delete('name')
}

같은 이름에 빈 값을 가진 새 cookie 설정하기:

Setting a new cookie with the same name and an empty value:

TSJSapp/actions.ts
'use server'

import { cookies } from 'next/headers'

export async function deleteCookie(data) {
  const cookieStore = await cookies()
  cookieStore.set('name', '')
}
'use server'

import { cookies } from 'next/headers'

export async function deleteCookie(data) {
  const cookieStore = await cookies()
  cookieStore.set('name', '')
}

maxAge를 0으로 설정하면 cookie가 즉시 만료됩니다. maxAge는 초 단위 값을 받습니다.

Setting the maxAge to 0 will immediately expire a cookie. maxAge accepts a value in seconds.

TSJSapp/actions.ts
'use server'

import { cookies } from 'next/headers'

export async function deleteCookie(data) {
  const cookieStore = await cookies()
  cookieStore.set('name', 'value', { maxAge: 0 })
}
'use server'

import { cookies } from 'next/headers'

export async function deleteCookie(data) {
  const cookieStore = await cookies()
  cookieStore.set('name', 'value', { maxAge: 0 })
}
