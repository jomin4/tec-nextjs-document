skipTrailingSlashRedirectskipTrailingSlashRedirect

skipTrailingSlashRedirect를 활성화하면 trailing slash를 추가하거나 제거하는 자동 redirect가 꺼집니다. 그래도 필요한 redirect는 Proxy에서 직접 처리합니다.

Enabling skipTrailingSlashRedirect turns off the automatic redirects that add or remove a trailing slash. You handle any redirecting you still want in Proxy.

대부분의 프로젝트에는 이 option이 필요하지 않습니다. 이 option은 advanced Proxy flag 중 하나로, 특정 routing 상황과 debugging을 위한 것입니다.

Most projects don't need this option. It is one of the advanced Proxy flags, meant for specific routing cases and debugging.

TSJSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  skipTrailingSlashRedirect: true,
}

export default nextConfig
/** @type {import('next').NextConfig} */
const nextConfig = {
  skipTrailingSlashRedirect: true,
}

module.exports = nextConfig

Reference레퍼런스

기본적으로 Next.js는 trailing slash가 trailingSlash 설정과 일치하도록 모든 request를 redirect합니다.

By default, Next.js redirects every request so the trailing slash matches your trailingSlash setting.

skipTrailingSlashRedirect를 활성화하면 server response와 client-side navigation 모두에 영향을 줍니다:

Enabling skipTrailingSlashRedirect affects both server responses and client-side navigation:

  • /about과 /about/ 모두 200을 반환합니다. 어느 쪽도 다른 쪽으로 redirect되지 않습니다.
  • Next.js가 client-side navigation 중에 trailing slash를 바꾸지 않습니다. <Link>와 router URL은 작성한 경로를 정확히 그대로 유지합니다.
  • Both /about and /about/ return 200. Neither redirects to the other.
  • Next.js stops changing trailing slashes during client-side navigation. <Link> and router URLs keep the path exactly as written.

next.config.js에 직접 작성한 redirects와 rewrites는 여전히 적용됩니다.

Your own redirects and rewrites from next.config.js still apply.

Paths that contain a dot점(.)이 포함된 경로

마지막 path segment에 점이 있으면 Next.js는 trailingSlash 설정과 관계없이 그 경로를 파일로 취급하고 trailing slash를 제거합니다. 앞쪽 segment에 있는 점은 영향을 주지 않습니다. 단, .well-known/ 아래는 예외로, trailingSlash가 true일 때 기본 redirect에서 제외됩니다.

If the last path segment contains a dot, Next.js treats the path as a file and removes the trailing slash, regardless of the trailingSlash setting. A dot in an earlier segment has no effect, except under .well-known/, which is exempt from the default redirects when trailingSlash is true.

skipTrailingSlashRedirect를 활성화하면 이러한 redirect가 하나도 생성되지 않고, 모든 경로가 요청된 형태 그대로 제공됩니다.

With skipTrailingSlashRedirect enabled, none of these redirects are generated and every path is served at whichever form was requested.

Good to know알아 두면 좋은 점

  • trailingSlash는 이전처럼 계속 설정하세요. 이 설정은 여전히 Next.js가 생성하는 URL과 output: 'export'의 출력 파일 이름을 제어합니다.
  • output: 'export'에서는 /me를 /me/로 resolve하지 않고 href를 그대로 유지합니다. Static Exports를 참고하세요.
  • 하나의 page를 /about과 /about/ 둘 다에서 제공하면 검색 엔진에 그 page의 URL이 두 개 생깁니다. metadata에 canonical URL을 설정하거나 Proxy에서 redirect하세요.
  • Keep setting trailingSlash as you did before. It still controls the URLs Next.js generates and the output filenames for output: 'export'.
  • With output: 'export', this preserves the href instead of resolving /me to /me/. See Static Exports.
  • Serving one page at both /about and /about/ gives search engines two URLs for it. Set a canonical URL in your metadata, or redirect in Proxy.

Examples예시

Handling trailing slashes in ProxyProxy에서 trailing slash 처리하기

skipTrailingSlashRedirect를 활성화하면 Next.js는 더 이상 trailing slash를 추가하지 않지만, Proxy에서 선택적으로 추가할 수는 있습니다. 이 예시는 legacy prefix 집합은 건드리지 않은 채 자신의 route에만 trailing slash를 추가하므로, 점진적인 migration이 더 쉬워집니다.

With skipTrailingSlashRedirect enabled, Next.js no longer adds trailing slashes, but Proxy can still add them selectively. This example adds a trailing slash to your own routes while leaving a set of legacy prefixes untouched, which makes an incremental migration easier.

TSJSproxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

const legacyPrefixes = ['/docs', '/blog']

export default function proxy(request: NextRequest) {
  const { pathname } = request.nextUrl

  if (legacyPrefixes.some((prefix) => pathname.startsWith(prefix))) {
    return NextResponse.next()
  }

  // Apply trailing slash handling, skipping files and `.well-known` paths
  if (
    !pathname.endsWith('/') &&
    !pathname.match(/((?!\.well-known(?:\/.*)?)(?:[^/]+\/)*[^/]+\.\w+)/)
  ) {
    return NextResponse.redirect(new URL(`${pathname}/`, request.nextUrl))
  }
}
