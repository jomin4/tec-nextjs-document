Edge RuntimeEdge Runtime

Next.js에는 애플리케이션에서 사용할 수 있는 두 가지 server runtime이 있습니다:

Next.js has two server runtimes you can use in your application:

  • Node.js Runtime (기본값): 모든 Node.js API에 접근할 수 있으며 애플리케이션을 rendering하는 데 사용됩니다.
  • Edge Runtime: 더 제한된 API 집합을 포함하며, Proxy에서 사용됩니다.
  • The Node.js Runtime (default), which has access to all Node.js APIs and is used for rendering your application.
  • The Edge Runtime which contains a more limited set of APIs, used in Proxy.

Caveats주의 사항

  • Edge Runtime은 모든 Node.js API를 지원하지는 않습니다. 일부 package는 예상대로 동작하지 않을 수 있습니다.
  • Edge Runtime은 Incremental Static Regeneration(ISR)을 지원하지 않습니다.
  • 두 runtime 모두 deployment adapter에 따라 streaming을 지원할 수 있습니다.
  • The Edge Runtime does not support all Node.js APIs. Some packages may not work as expected.
  • The Edge Runtime does not support Incremental Static Regeneration (ISR).
  • Both runtimes can support streaming depending on your deployment adapter.

Unsupported APIs지원하지 않는 API

Edge Runtime에는 다음과 같은 제약이 있습니다:

The Edge Runtime has some restrictions including:

  • Native Node.js API는 지원되지 않습니다. 예를 들어 filesystem을 읽거나 쓸 수 없습니다.
  • node_modules는 ES Modules를 구현하고 native Node.js API를 사용하지 않는다면 사용할 수 있습니다.
  • require를 직접 호출하는 것은 허용되지 않습니다. 대신 ES Modules를 사용하세요.
  • Native Node.js APIs are not supported. For example, you can't read or write to the filesystem.
  • node_modules can be used, as long as they implement ES Modules and do not use native Node.js APIs.
  • Calling require directly is not allowed. Use ES Modules instead.

드물게 코드에 runtime에 도달할 수 없고 treeshaking으로도 제거할 수 없는 dynamic code evaluation 문이 포함되거나 import될 수 있습니다. Proxy 설정에서 특정 파일을 허용하도록 이 검사를 완화할 수 있습니다:

In rare cases, your code could contain (or import) some dynamic code evaluation statements which cannot be reached at runtime and which cannot be removed by treeshaking. You can relax the check to allow specific files with your Proxy configuration:

JSproxy.ts
export const config = {
  unstable_allowDynamic: [
    // allows a single file
    '/lib/utilities.js',
    // use a glob to allow anything in the function-bind 3rd party module
    '**/node_modules/function-bind/**',
  ],
}

unstable_allowDynamic은 특정 파일에 대해 dynamic code evaluation을 무시하는 glob 또는 glob 배열입니다. glob은 애플리케이션 root 폴더를 기준으로 한 상대 경로입니다.

unstable_allowDynamic is a glob, or an array of globs, ignoring dynamic code evaluation for specific files. The globs are relative to your application root folder.

이 문들이 Edge에서 실행되면 throw되어 runtime error를 일으킨다는 점에 유의하세요.

Be warned that if these statements are executed on the Edge, they will throw and cause a runtime error.
