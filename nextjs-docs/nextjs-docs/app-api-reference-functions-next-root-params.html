next/root-paramsnext/root-params

next/root-params module은 Server Components에서 root 수준 parameter에 접근하기 위한 getter 함수를 제공합니다. 각 root parameter는 현재 route의 parameter 값으로 resolve되는 async 함수로 export됩니다.

The next/root-params module provides getter functions for accessing root-level parameters in Server Components. Each root parameter is exported as an async function that resolves to the parameter value for the current route.

export 이름은 dynamic segment 폴더 이름에서 생성됩니다. 예를 들어 root layout이 app/[locale] 안에 있다면 next/root-params에서 locale을 import합니다.

The export names are generated from your dynamic segment folder names. For example, if your root layout is inside app/[locale], you import locale from next/root-params.

이는 언어나 locale segment처럼 애플리케이션 전반, 예를 들어 공유 utility, layout, 깊이 중첩된 component 등에서 props로 내려 주지 않고 접근해야 하는 값에 유용합니다.

This is useful for values like a language or locale segment that need to be accessed across your application, for example in shared utilities, layouts, and deeply nested components, without passing them down as props.

TSJSapp/[lang]/layout.tsx
import { lang } from 'next/root-params'

export default async function RootLayout(props: LayoutProps<'/[lang]'>) {
  return (
    <html lang={await lang()}>
      <body>{props.children}</body>
    </html>
  )
}
import { lang } from 'next/root-params'

export default async function RootLayout({ children }) {
  return (
    <html lang={await lang()}>
      <body>{children}</body>
    </html>
  )
}

root parameter는 root layout 앞에 나타나는 dynamic segment입니다. 일반 params prop과 달리, root parameter getter는 prop drilling 없이 애플리케이션의 어떤 Server Component에서든 호출할 수 있습니다. 자세한 내용은 Why root parameters are special을 참고하세요.

Root parameters are the dynamic segments that appear before the root layout. Unlike the regular params prop, root parameter getters can be called from any Server Component in your application without prop drilling. See Why root parameters are special for more details.

Good to know
  • root parameter 이름은 유효한 JavaScript 함수 identifier여야 합니다. kebab-case segment 이름(예: [post-slug])은 지원되지 않으며, dev 중이나 build 중에 error가 발생합니다.
  • next/root-params는 Server Component에서 사용할 수 있습니다. Client Component, Server Action, Route Handler에서는 사용할 수 없습니다. Route Handler 지원은 향후 release에서 계획되어 있습니다.
  • next/root-params export의 type은 PageProps와 LayoutProps와 마찬가지로 next dev, next build, 또는 next typegen 중에 생성됩니다.
  • Root parameter names must be valid JavaScript function identifiers. Kebab-cased segment names (e.g. [post-slug]) are not supported and will cause an error at dev time or during build.
  • next/root-params can be used in Server Components. It cannot be used in Client Components, Server Actions, or Route Handlers. Support for Route Handlers is planned for a future release.
  • Types for the next/root-params exports are generated during next dev, next build, or next typegen, the same as PageProps and LayoutProps.

Root parameters and generateStaticParamsRoot parameter와 generateStaticParams

root parameter는 이를 정의하는 route를 만드는 즉시 사용할 수 있습니다. generateStaticParams 함수는 Cache Components를 사용할 때만 필요하며, 이 경우 각 root parameter에 최소 하나의 값이 있어야 하고 그렇지 않으면 build가 실패합니다.

Root parameters are available as soon as you create the routes that define them. A generateStaticParams function is only required with Cache Components, where each root parameter must have at least one value or the build fails.

root parameter가 하나인 경우:

With a single root parameter:

TSJSapp/[lang]/layout.tsx
import { lang } from 'next/root-params'

export default async function RootLayout(props: LayoutProps<'/[lang]'>) {
  return (
    <html lang={await lang()}>
      <body>{props.children}</body>
    </html>
  )
}

export async function generateStaticParams() {
  return [{ lang: 'en' }, { lang: 'fr' }]
}
import { lang } from 'next/root-params'

export default async function RootLayout({ children }) {
  return (
    <html lang={await lang()}>
      <body>{children}</body>
    </html>
  )
}

export async function generateStaticParams() {
  return [{ lang: 'en' }, { lang: 'fr' }]
}

root parameter가 여러 개인 경우, 각각에 대한 값을 반환하세요:

With multiple root parameters, return a value for each:

TSapp/[lang]/[locale]/layout.tsx
export async function generateStaticParams() {
  return [
    { lang: 'en', locale: 'us' },
    { lang: 'en', locale: 'uk' },
  ]
}

Reading root parameters in a nested generateStaticParams중첩된 generateStaticParams에서 root parameter 읽기

중첩된 segment의 generateStaticParams 안에서는 params 인자에서 destructuring하는 대신 getter로 root parameter를 직접 읽을 수 있습니다:

Inside a nested segment's generateStaticParams, you can read a root parameter directly with its getter, instead of destructuring it from the params argument:

TSJSapp/[lang]/posts/[slug]/page.tsx
import { lang } from 'next/root-params'

export async function generateStaticParams() {
  const language = await lang()
  const posts = await fetch(
    `https://api.example.com/posts?lang=${language}`
  ).then((res) => res.json())
  return posts.map((post) => ({ slug: post.slug }))
}

export default async function Page() {
  // ...
}
import { lang } from 'next/root-params'

export async function generateStaticParams() {
  const language = await lang()
  const posts = await fetch(
    `https://api.example.com/posts?lang=${language}`
  ).then((res) => res.json())
  return posts.map((post) => ({ slug: post.slug }))
}

export default async function Page() {
  // ...
}

Root parameters and other route parametersRoot parameter와 다른 route parameter

root parameter는 root layout 파일까지의 경로에 나타나는 dynamic segment의 route parameter입니다. route tree에서 더 깊은 곳의 다른 route parameter는 params prop을 통해 접근합니다.

Root parameters are the route parameters from dynamic segments that appear in the path up to the root layout file. Other route parameters deeper in the route tree are accessed through the params prop.

다음과 같은 파일 구조가 있다고 해 봅시다:

Given this file structure:

  • app/[lang]/layout.tsx (root layout)
  • app/[lang]/posts/[slug]/page.tsx
  • app/[lang]/layout.tsx (root layout)
  • app/[lang]/posts/[slug]/page.tsx

lang만 root parameter입니다. slug는 일반 route parameter입니다:

Only lang is a root parameter. slug is a regular route parameter:

TSJSapp/[lang]/posts/[slug]/page.tsx
import { lang } from 'next/root-params'

export default async function PostPage(
  props: PageProps<'/[lang]/posts/[slug]'>
) {
  const { slug } = await props.params
  const language = await lang()

  return (
    <article>
      <p>Language: {language}</p>
      <p>Post: {slug}</p>
    </article>
  )
}
import { lang } from 'next/root-params'

export default async function PostPage({ params }) {
  const { slug } = await params
  const language = await lang()

  return (
    <article>
      <p>Language: {language}</p>
      <p>Post: {slug}</p>
    </article>
  )
}

Accessing root parameters in shared code공유 코드에서 root parameter 접근하기

root parameter getter는 module import이므로, layout과 page뿐 아니라 어떤 Server Component나 server-side utility에서도 호출할 수 있습니다:

Root parameter getters are module imports, they can be called from any Server Component or server-side utility, not just layouts and pages:

TSlib/get-translations.ts
import { lang } from 'next/root-params'

export async function getTranslations() {
  const language = await lang()
  // Load translations based on the root language parameter
  return import(`@/locales/${language}.json`)
}
Good to know

next/root-params를 사용하는 파일에 import 'server-only'를 추가할 필요가 없습니다. Client Component에서 사용하면 이미 build 시점에 import가 실패합니다.

You do not need to add import 'server-only' to files that use next/root-params. The import already fails at build time if used in a Client Component.

Behavior with caching directivesCaching directive와 함께 쓸 때의 동작

root parameter getter는 import된 함수이므로, Next.js는 cache된 함수가 어떤 getter를 사용하는지 추적할 수 있습니다. 그 root parameter만 cache key의 일부가 되므로, 관련 없는 parameter 값 때문에 cache entry가 나뉘지 않습니다.

Because root parameter getters are imported functions, Next.js can track which ones a cached function uses. Only those root parameters become part of the cache key, so cache entries are not split across unrelated parameter values.

TSJSapp/[lang]/components/cached-nav.tsx
import { lang } from 'next/root-params'

// The cache key for this function only includes `lang`,
// not every dynamic segment in the route.
async function getNavigation() {
  'use cache'
  const language = await lang()
  const res = await fetch(`https://api.example.com/nav?lang=${language}`)
  return res.json()
}

export default async function CachedNav() {
  const nav = await getNavigation()
  return <nav>{/* render nav items */}</nav>
}
import { lang } from 'next/root-params'

// The cache key for this function only includes `lang`,
// not every dynamic segment in the route.
async function getNavigation() {
  'use cache'
  const language = await lang()
  const res = await fetch(`https://api.example.com/nav?lang=${language}`)
  return res.json()
}

export default async function CachedNav() {
  const nav = await getNavigation()
  return <nav>{/* render nav items */}</nav>
}

일반 params prop을 사용하면 cache된 함수 밖에서 await params를 하고 그 값을 인자로 넘겨야 합니다:

With the regular params prop, you would need to await params outside the cached function and pass the value in as an argument:

TSJSapp/[lang]/page.tsx
import { lang } from 'next/root-params'

// With root params: call directly inside the cached function
async function getDataWithRootParams() {
  'use cache'
  const language = await lang()
  return fetch(`https://api.example.com/data?lang=${language}`)
}

// Without root params: await params outside, pass as argument
async function getDataWithParams(language: string) {
  'use cache'
  return fetch(`https://api.example.com/data?lang=${language}`)
}

export default async function Page(props: PageProps<'/[lang]'>) {
  const { lang: language } = await props.params
  const data = await getDataWithParams(language)
  // ...
}
import { lang } from 'next/root-params'

// With root params: call directly inside the cached function
async function getDataWithRootParams() {
  'use cache'
  const language = await lang()
  return fetch(`https://api.example.com/data?lang=${language}`)
}

// Without root params: await params outside, pass as argument
async function getDataWithParams(language) {
  'use cache'
  return fetch(`https://api.example.com/data?lang=${language}`)
}

export default async function Page({ params }) {
  const { lang: language } = await params
  const data = await getDataWithParams(language)
  // ...
}

Multiple root layouts여러 개의 root layout

애플리케이션에 서로 다른 parameter를 가진 root layout이 여러 개 있으면, getter 함수는 가능한 모든 route 중 어디에서든 사용될 수 있다는 점을 고려해 type이 지정됩니다. 모든 root layout에 존재하지는 않는 parameter는 string | undefined type을 가집니다.

When an application has multiple root layouts with different parameters, getter functions are typed to account for usage in any of all possible routes. A parameter that does not exist in every root layout has the type string | undefined.

다음과 같은 파일 구조가 있다고 해 봅시다:

Given this file structure:

  • app/dashboard/[id]/layout.tsx (id가 있는 root layout)
  • app/marketing/layout.tsx (id가 없는 root layout)
  • app/dashboard/[id]/layout.tsx (root layout with id)
  • app/marketing/layout.tsx (root layout without id)
TSJSapp/dashboard/[id]/page.tsx
import { id } from 'next/root-params'

export default async function DashboardPage() {
  const dashboardId = await id() // string | undefined
  return <div>Dashboard: {dashboardId}</div>
}
import { id } from 'next/root-params'

export default async function DashboardPage() {
  const dashboardId = await id() // string | undefined
  return <div>Dashboard: {dashboardId}</div>
}

marketing root layout에는 id가 없으므로, marketing route에서 접근하면 await id()는 undefined를 반환합니다.

Since id does not exist in the marketing root layout, await id() returns undefined when accessed from marketing routes.

Catch-all and optional catch-all segmentsCatch-all 및 optional catch-all segment

root parameter는 catch-all 및 optional catch-all segment에서도 동작합니다:

Root parameters work with catch-all and optional catch-all segments:

TSJSapp/docs/[...path]/layout.tsx
import { path } from 'next/root-params'

export default async function DocsLayout(
  props: LayoutProps<'/docs/[...path]'>
) {
  const segments = await path() // string[] | undefined
  return (
    <div>
      <nav>Path: {segments?.join(' / ')}</nav>
      {props.children}
    </div>
  )
}
import { path } from 'next/root-params'

export default async function DocsLayout({ children }) {
  const segments = await path() // string[] | undefined
  return (
    <div>
      <nav>Path: {segments?.join(' / ')}</nav>
      {children}
    </div>
  )
}

Returns

각 root parameter getter는 다음 중 하나로 resolve되는 Promise를 반환합니다:

Each root parameter getter returns a Promise that resolves to one of the following:

Segment typeExampleReturn type
Dynamic[id]string
Catch-all[...path]string[]
Optional catch-all[[...path]]string[] | undefined
Segment typeExampleReturn type
Dynamic[id]string
Catch-all[...path]string[]
Optional catch-all[[...path]]string[] | undefined

현재 route의 root layout에 parameter가 존재하지 않으면(Multiple root layouts 참고), return type에 undefined가 포함됩니다.

If the parameter does not exist in the current route's root layout (see Multiple root layouts), the return type includes undefined.

Restrictions제한 사항

이 중 대부분은 root parameter의 동작 방식에서 오는 영구적인 제약입니다. 예외는 Route Handler로, 아직 지원되지 않지만 향후 release에서 지원될 예정입니다.

Most of these are permanent constraints of how root parameters work. The exception is Route Handlers, which are not supported yet but are planned for a future release.

Server Components onlyServer Component 전용

root parameter getter는 Server Component에서만 사용할 수 있습니다:

Root parameter getters can only be used in Server Components:

// This will cause a build error
'use client'

import { lang } from 'next/root-params' // Error: Cannot import in Client Component

Not available in unstable_cacheunstable_cache에서는 사용 불가

unstable_cache 안에서 root parameter getter를 호출하면 runtime error가 발생합니다. 대신 "use cache"를 사용하세요.

Calling a root parameter getter inside unstable_cache will throw a runtime error. Use "use cache" instead.

import { lang } from 'next/root-params'
import { unstable_cache } from 'next/cache'

const getCachedData = unstable_cache(async () => {
  const language = await lang() // Error: Not supported inside unstable_cache
  return fetch(`https://api.example.com/data?lang=${language}`)
})

Not available in Server ActionsServer Action에서는 사용 불가

import { lang } from 'next/root-params'

async function submitForm() {
  'use server'
  const language = await lang() // Error: Not supported in Server Actions
}

Why root parameters are specialroot parameter가 특별한 이유

root layout은 최상위 rendering boundary입니다. 그 앞의 route parameter는 해당 root layout 아래의 모든 route가 공유하며, 이 덕분에 그 tree의 어떤 Server Component에서든 안전하게 접근할 수 있습니다. route에서 더 깊은 곳의 route parameter는 어떤 child page가 render되느냐에 따라 달라지므로, 이를 정의하는 page나 layout의 params prop을 통해서만 사용할 수 있습니다.

The root layout is the top-level rendering boundary. The route parameters before it are shared by all routes under that root layout, which is what makes them safe to access from any Server Component in that tree. Route parameters deeper in the route vary depending on which child page is being rendered, so they are only available through the params prop in the page or layout that defines them.

app/
  [lang]/              ← root parameter (shared by all routes below)
    layout.tsx         ← root layout
    page.tsx           ← has no slug, doesn't know about blog or store
    blog/
      [slug]/          ← route parameter
        page.tsx
    store/
      [...slug]/       ← catch-all route parameter with the same name
        page.tsx

이 예시에서 root parameter는 lang 하나뿐입니다. root layout 바로 아래의 page.tsx에는 slug가 전혀 없습니다. blog와 store branch는 둘 다 slug를 정의하지만, segment type이 서로 다릅니다([slug] vs [...slug]). 각 route는 자기 자신의 route parameter만 압니다. 같은 이름이라도 route에 따라 type이 다르거나, 의미가 다르거나, 아예 존재하지 않을 수 있습니다. 이것이 root layout 아래의 route parameter를 global getter가 아니라 params prop으로 접근하는 이유입니다.

In this example, lang is the only root parameter. The page.tsx directly under the root layout has no slug at all. The blog and store branches both define slug, but with different segment types ([slug] vs [...slug]). Each route only knows about its own route parameters. The same name can have different types, different meanings, or not exist at all depending on the route. This is why route parameters below the root layout are accessed through the params prop rather than as global getters.

예외는 여러 개의 root layout입니다. 서로 다른 root layout이 서로 다른 route parameter를 정의하면, getter 함수는 특정 parameter가 존재하지 않을 수 있는 route를 고려해 return type에 undefined를 포함합니다.

The exception is multiple root layouts. When different root layouts define different route parameters, the getter functions include undefined in their return type to account for routes where a given parameter may not exist.
