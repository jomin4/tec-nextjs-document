prefetchprefetch

prefetch route segment config는 client-side navigation 중에 segment가 prefetch되는 방식을 제어합니다. 기본적으로 framework는 앱의 partialPrefetching 설정에 따라 strategy를 관리합니다. segment별로 이를 override하려면 이 export를 아래 값 중 하나로 설정하세요.

The prefetch route segment config controls how a segment is prefetched during client-side navigation. By default, the framework manages the strategy based on the app's partialPrefetching setting. To override per segment, set this export to one of the values below.

Good to know
  • prefetch export는 cacheComponents가 활성화되어 있을 때만 동작합니다.
  • segment가 Client Component이면 prefetch를 사용할 수 없습니다.
  • 설정할 의미가 있는 값은 'partial'과 'force-disabled'입니다. 'auto'는 default이며 export를 생략한 것과 같으므로 prefetch = 'auto'를 명시적으로 쓰지 마세요.
  • prefetch() 함수도 호출하는 page나 layout에서는 이 함수를 다른 이름으로 import해야 합니다. 예: import { prefetch as prefetchStage } from 'next/cache'.
  • The prefetch export only works when cacheComponents is enabled.
  • prefetch cannot be used when the segment is a Client Component.
  • The meaningful values to set are 'partial' and 'force-disabled'. 'auto' is the default and is equivalent to omitting the export; don't write prefetch = 'auto' explicitly.
  • A page or layout that also calls the prefetch() function needs to import it under another name, for example import { prefetch as prefetchStage } from 'next/cache'.
TSJSlayout.tsx | page.tsx
export const prefetch = 'partial'

export default function Page() {
  return <div>...</div>
}

  return <div>...</div>

Options

'partial'

전역 partialPrefetching flag를 활성화하지 않고도 segment에 Partial Prefetching을 적용합니다. prefetch = 'partial'인 segment를 가리키는 <Link>는 기존의 full prefetch 대신 route별 App Shell을 load합니다. 이 값은 link가 아니라 목적지 segment에 설정하세요.

Opts the segment into Partial Prefetching without enabling the global partialPrefetching flag. A <Link> pointing at a segment with prefetch = 'partial' loads the per-route App Shell instead of the legacy full prefetch. Set this on the destination, not the link.

<Link prefetch={true}>로 더 넓은 prefetch를 선택한 link에 대해서는 Next.js가 link별 prefetching을 사용합니다. server는 URL 데이터(params, searchParams, 전체 URL)를 resolve하는 새 response를 rendering합니다. 모든 콘텐츠가 static으로 rendering 가능한 page에서는 Next.js가 static cache에서 prefetch를 serve합니다. page가 non-static 데이터에 접근하면 runtime에 prefetch됩니다.

For links that opt into a wider prefetch with <Link prefetch={true}>, Next.js uses per-link prefetching. The server renders a fresh response that resolves URL data (params, searchParams, and the full URL). On pages where all the content is statically renderable, Next.js serves prefetches from the static cache. If a page accesses non-static data, it's prefetched at runtime.

앱 전체에 한 번에 partialPrefetching을 활성화할 수 없을 때 점진적으로 도입하는 용도로 사용하세요. 대상 범위의 모든 route에 prefetch = 'partial'이 설정되면, 전역 flag를 활성화하고 route별 export를 제거하세요.

Use this for incremental adoption when you can't enable partialPrefetching for the entire app at once. Once every route in scope has prefetch = 'partial', enable the global flag and remove the per-route exports.

Good to know

Next.js가 segment에 대해 link별 prefetch를 수행하면, 그 아래의 모든 segment가 같은 request에 포함됩니다. tree에서 더 깊은 곳에 'force-disabled'로 설정된 segment도 response의 일부로 prefetch됩니다.

When Next.js performs a per-link prefetch for a segment, all downstream segments are included in the same request. Segments deeper in the tree that are configured with 'force-disabled' will still be prefetched as part of the response.

TSpage.tsx
export const prefetch = 'partial'

'force-disabled'

이 segment를 절대 prefetch하지 않습니다. client는 navigation 전에 segment 데이터를 request하지 않습니다. 거의 방문하지 않는 인증 뒤의 page처럼, prefetching이 낭비가 되는 segment에 사용하세요.

Never prefetch this segment. The client will not request segment data ahead of navigation. Use this for segments where prefetching would be wasteful, for example pages behind authentication that are rarely visited.

Good to know

'force-disabled'가 Next.js의 route metadata prefetching까지 막지는 않습니다. 하지만 이 segment와 그보다 깊은 모든 segment의 실제 segment 데이터는 prefetching에서 제외됩니다.

'force-disabled' does not prevent Next.js from prefetching metadata about the route. However, the actual segment data for this segment and all deeper segments will be omitted from prefetching.

Relationship with the <Link prefetch> prop<Link prefetch> prop과의 관계

prefetch는 의도(이 목적지를 prefetch해야 하는지, 얼마나 적극적으로 할지)를 표현하는 <Link>에서 시작해서, 비용 상한(이곳을 가리키는 어떤 link에 대해서든 미리 얼마만큼의 작업을 해도 되는지)을 정하는 segment에서 끝납니다.

A prefetch starts with a <Link> that expresses intent (should this destination be prefetched, and how eagerly), and ends at a segment that sets a cost ceiling (how much work is it OK to do ahead of time, for any link that points here).

목적지는 어떤 link가 자신을 가리키는지 알 수 없으므로, segment config가 <Link prefetch={true}>가 가져오는 범위에 상한을 둡니다:

A destination can't know which links target it, so the segment config caps what any <Link prefetch={true}> pulls:

  • 'partial': default link에는 App Shell을 제공하고, <Link prefetch={true}>는 여기에 더해 URL 데이터(params, searchParams, 전체 URL)와 그 뒤의 cache된 콘텐츠까지 resolve합니다.
  • 'force-disabled': segment 데이터를 완전히 건너뜁니다.
  • 'partial': App Shell for default links; a <Link prefetch={true}> additionally resolves URL data (params, searchParams, and the full URL) and the cached content behind it.
  • 'force-disabled': skip segment data entirely.

<Link prefetch={false}>는 목적지가 어떻게 설정되어 있든 link 수준에서 prefetching을 건너뜁니다.

<Link prefetch={false}> skips prefetching at the link level regardless of how the destination is configured.

Good to know

모든 콘텐츠가 static으로 rendering 가능한 page에서는 Next.js가 static cache(또는 CDN)에서 prefetch를 serve합니다. page가 cookie나 header 같은 non-static 데이터에 접근하면, runtime에 새 server render로 prefetch되며 page view마다 server CPU 비용이 듭니다.

On pages where all the content is statically renderable, Next.js serves prefetches from the static cache (or a CDN). If a page accesses non-static data like cookies or headers, it's prefetched at runtime with a fresh server render, which costs server CPU per page view.

TypeScript

type Prefetch = 'auto' | 'partial' | 'force-disabled'

export const prefetch: Prefetch = 'partial'
