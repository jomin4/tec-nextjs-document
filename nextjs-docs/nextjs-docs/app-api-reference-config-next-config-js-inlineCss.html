inlineCssexperimentalinlineCss

Usage사용법

<head>에 CSS를 inline으로 넣는 experimental 지원입니다. 이 flag를 활성화하면, 평소 <link> tag를 생성하던 모든 위치에 대신 <style> tag가 생성됩니다.

Experimental support for inlining CSS in the <head>. When this flag is enabled, all places where we normally generate a <link> tag will instead have a generated <style> tag.

TSJSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    inlineCss: true,
  },
}

export default nextConfig
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    inlineCss: true,
  },
}

module.exports = nextConfig

Trade-Offs장단점

  • atomic CSS(Tailwind 등)를 사용하고 새 방문자의 first-load 성능을 최적화하고 싶다면 활성화하세요
  • 재방문자가 많고 그들이 cache된 stylesheet의 이점을 누리기를 원한다면 건너뛰세요
  • Enable if you use atomic CSS (like Tailwind) and want to optimize first-load performance for new visitors
  • Skip if returning visitors are common and you want them to benefit from cached stylesheets

When Inline CSS Helpsinline CSS가 도움이 되는 경우

보통 브라우저는 render하기 전에 HTML을 다운로드하고, parse하고, CSS <link> tag를 발견한 다음 stylesheet를 request해야 합니다. inline으로 넣으면 이 request waterfall이 사라져 style이 HTML과 함께 도착하므로 브라우저가 즉시 render할 수 있습니다.

Normally, the browser must download HTML, parse it, discover CSS <link> tags, then request stylesheets before it can render. Inlining eliminates this request waterfall, so that styles arrive with the HTML, so the browser can render immediately.

이 이점은 다음 경우에 가장 큽니다:

This benefit is strongest with:

  • 처음 방문하는 사용자: CSS 파일은 render-blocking이므로, inline으로 넣으면 처음 방문하는 사용자가 겪는 초기 다운로드 지연이 사라집니다. cache된 stylesheet를 가진 재방문자는 이 이점을 보지 못합니다.
  • 성능 지표: CSS 파일에 대한 추가 network request를 없애므로, inline으로 넣으면 First Contentful Paint (FCP)와 Largest Contentful Paint (LCP)가 크게 개선될 수 있습니다.
  • 느린 연결: latency가 높은 network의 사용자에게는 추가 request 하나하나가 지연을 더합니다. inline으로 넣으면 round trip이 줄어들며, 이는 연결이 느릴 때 가장 중요합니다.
  • Atomic CSS (Tailwind): utility-first framework는 사용하는 class만 생성하므로 CSS가 작게 유지됩니다. page의 style은 page 복잡도에 비례해 커지지 않으며, UI를 얼마나 많이 만들든 보통 작게 유지됩니다. 따라서 HTML을 크게 부풀리지 않고도 성능 이점을 얻을 수 있어 inline으로 넣는 것이 실용적입니다.
  • First-time visitors: Since CSS files are render-blocking, inlining eliminates the initial download delay that first-time visitors experience. Returning visitors with cached stylesheets won't see this benefit.
  • Performance metrics: By removing additional network requests for CSS files, inlining can significantly improve First Contentful Paint (FCP) and Largest Contentful Paint (LCP).
  • Slow connections: For users on high-latency networks, each additional request adds delay. Inlining reduces round trips, which matters most when connections are slow.
  • Atomic CSS (Tailwind): Utility-first frameworks generate only the classes you use, keeping CSS small. The styles for a page don't grow proportionally with page complexity—they're typically compact regardless of how much UI you build. This makes inlining practical since you get the performance benefit without significantly bloating HTML.

When External CSS is Betterexternal CSS가 더 나은 경우

inline style은 HTML과 별도로 cache될 수 없습니다. page를 load할 때마다 같은 CSS를 다시 다운로드합니다.

Inlined styles cannot be cached separately from HTML. Every page load re-downloads the same CSS.

이 장단점은 다음 경우에 가장 중요합니다:

This trade-off matters most with:

  • 재방문자: 사이트를 반복해서 방문하는 사용자는 cache된 external stylesheet의 이점을 누릴 수 있습니다. inline으로 넣으면 방문할 때마다 style을 다시 다운로드합니다.
  • 큰 CSS bundle: external stylesheet는 독립적으로 cache되며 최신 infrastructure에서 효율적으로 load됩니다. inline CSS는 모든 HTML response와 함께 전달되므로 Time to First Byte (TTFB)가 늘어나고, 브라우저가 style을 따로 cache할 수 없게 됩니다. 이 방식은 작은 CSS(Tailwind 같은 atomic framework)에는 잘 맞지만, 더 큰 bundle(Bootstrap이나 Material UI 같은 component library)에는 overhead를 더합니다.
  • style을 공유하는 많은 page: 한 page에서 cache된 external stylesheet는 다른 page로의 navigation을 빠르게 해 줍니다. inline style은 page 간 caching 이점을 제공하지 않습니다.
  • Returning visitors: Users who visit your site repeatedly would benefit from cached external stylesheets. With inlining, they re-download styles on every visit.
  • Large CSS bundles: External stylesheets cache independently and load efficiently on modern infrastructure. Inlined CSS arrives with every HTML response, increasing Time to First Byte (TTFB) and preventing browsers from caching styles separately. This trade-off works for small CSS (atomic frameworks like Tailwind), but adds overhead for larger bundles (component libraries like Bootstrap or Material UI).
  • Many pages sharing styles: External stylesheets cached on one page speed up navigation to other pages. Inlined styles provide no cross-page caching benefit.
Good to know

이 기능은 현재 experimental이며 몇 가지 알려진 제약이 있습니다:

  • CSS inlining은 전역으로 적용되며 page 단위로 설정할 수 없습니다
  • 초기 page load 중에 style이 중복됩니다. SSR을 위해 <style> tag 안에 한 번, RSC payload 안에 한 번 들어갑니다
  • prerender된 page로 navigation할 때는 중복을 피하기 위해 inline CSS 대신 <link> tag를 사용합니다
  • 이 기능은 development mode에서는 사용할 수 없고 production build에서만 동작합니다

This feature is currently experimental and has some known limitations:

  • CSS inlining is applied globally and cannot be configured on a per-page basis
  • Styles are duplicated during initial page load - once within <style> tags for SSR and once in the RSC payload
  • When navigating to prerendered pages, styles will use <link> tags instead of inline CSS to avoid duplication
  • This feature is not available in development mode and only works in production builds
