How to set up a custom server in Next.jsNext.js에서 custom server 설정하기

Next.js에는 기본적으로 next start로 실행되는 자체 server가 포함되어 있습니다. 기존 backend가 있다면 Next.js와 함께 그대로 사용할 수 있습니다(이것은 custom server가 아닙니다). custom Next.js server를 사용하면 custom 패턴을 위해 server를 programmatic하게 시작할 수 있습니다. 대부분의 경우에는 이 방식이 필요하지 않습니다. 하지만 eject해야 한다면 사용할 수 있습니다.

Next.js includes its own server with next start by default. If you have an existing backend, you can still use it with Next.js (this is not a custom server). A custom Next.js server allows you to programmatically start a server for custom patterns. The majority of the time, you will not need this approach. However, it's available if you need to eject.

Good to know
  • custom server 사용을 결정하기 전에, Next.js의 통합 router가 앱의 요구 사항을 충족하지 못할 때만 사용해야 한다는 점을 기억하세요.
  • standalone output mode를 사용하면 custom server 파일은 trace되지 않습니다. 대신 이 mode는 별도의 최소화된 server.js 파일을 출력합니다. 둘은 함께 사용할 수 없습니다.
  • Before deciding to use a custom server, keep in mind that it should only be used when the integrated router of Next.js can't meet your app requirements.
  • When using standalone output mode, it does not trace custom server files. This mode outputs a separate minimal server.js file, instead. These cannot be used together.

custom server의 다음 예시를 살펴보세요:

Take a look at the following example of a custom server:

TSJSserver.ts
import { createServer } from 'http'
import next from 'next'

const port = parseInt(process.env.PORT || '3000', 10)
const dev = process.env.NODE_ENV !== 'production'
const app = next({ dev })
const handle = app.getRequestHandler()

app.prepare().then(() => {
  createServer((req, res) => {
    handle(req, res)
  }).listen(port)

  console.log(
    `> Server listening at http://localhost:${port} as ${
      dev ? 'development' : process.env.NODE_ENV
    }`
  )
})

handle을 호출하기 전에 직접 관리하는 response header를 설정하세요: Next.js는 handle(req, res) 안에서 response 전송을 시작하므로, 그 promise가 resolve될 무렵에는 res.headersSent가 이미 true이고 이후의 res.setHeader() 호출은 아무 경고 없이 무시됩니다. Set-Cookie처럼 직접 관리하는 header는 request를 Next.js에 넘기기 전에 설정하세요:

res.setHeader('Set-Cookie', 'sessionId=abc123; Max-Age=2592000')

await handle(req, res)

다른 framework로 Next.js를 감쌀 때도 같은 순서가 적용됩니다. 예를 들어 Fastify의 reply.raw나 Express의 res가 그렇습니다.

Set your own response headers before calling handle: Next.js begins sending the response inside handle(req, res), so by the time its promise resolves res.headersSent is already true and any later res.setHeader() call is silently discarded. Set headers you own, such as Set-Cookie, before handing the request to Next.js:

res.setHeader('Set-Cookie', 'sessionId=abc123; Max-Age=2592000')

await handle(req, res)

The same ordering applies when wrapping Next.js in another framework, for example reply.raw in Fastify or res in Express.

server.js는 Next.js Compiler나 bundling 과정을 거치지 않습니다. 이 파일이 사용하는 문법과 source code가 현재 사용 중인 Node.js 버전과 호환되는지 확인하세요. 예시 보기.

server.js does not run through the Next.js Compiler or bundling process. Make sure the syntax and source code this file requires are compatible with the current Node.js version you are using. View an example.

custom server를 실행하려면 package.json의 scripts를 다음과 같이 업데이트해야 합니다:

To run the custom server, you'll need to update the scripts in package.json like so:

package.json
{
  "scripts": {
    "dev": "node server.js",
    "build": "next build",
    "start": "NODE_ENV=production node server.js"
  }
}

또는 nodemon을 설정할 수도 있습니다(예시). custom server는 다음 import를 사용해 server를 Next.js 애플리케이션과 연결합니다:

Alternatively, you can set up nodemon (example). The custom server uses the following import to connect the server with the Next.js application:

import next from 'next'

const app = next({})

위의 next import는 다음 option을 가진 object를 받는 함수입니다:

The above next import is a function that receives an object with the following options:

OptionType설명
confObjectnext.config.js에서 사용하는 것과 같은 object. 기본값은 {}
devBoolean(선택) Next.js를 dev mode로 실행할지 여부. 기본값은 false
dirString(선택) Next.js 프로젝트의 위치. 기본값은 '.'
quietBoolean(선택) server 정보가 담긴 error message를 숨김. 기본값은 false

turbopackBoolean(선택) Turbopack 활성화(기본적으로 활성화됨)
webpackBoolean(선택) webpack 활성화

그러면 반환된 app을 사용해 필요에 따라 Next.js가 request를 처리하도록 할 수 있습니다.

The returned app can then be used to let Next.js handle requests as required.

Disabling file-system routingfile-system routing 비활성화하기

기본적으로 Next는 pages 폴더의 각 파일을 파일 이름과 일치하는 pathname으로 제공합니다. 프로젝트에서 custom server를 사용한다면 이 동작 때문에 같은 콘텐츠가 여러 path에서 제공될 수 있고, 이는 SEO와 UX에 문제를 일으킬 수 있습니다.

By default, Next will serve each file in the pages folder under a pathname matching the filename. If your project uses a custom server, this behavior may result in the same content being served from multiple paths, which can present problems with SEO and UX.

이 동작을 비활성화하고 pages의 파일을 기반으로 한 routing을 막으려면 next.config.js를 열고 useFileSystemPublicRoutes config를 비활성화하세요:

To disable this behavior and prevent routing based on files in pages, open next.config.js and disable the useFileSystemPublicRoutes config:

JSnext.config.js
module.exports = {
  useFileSystemPublicRoutes: false,
}

useFileSystemPublicRoutes는 SSR에서 파일 이름 route를 비활성화할 뿐이며, client-side routing은 여전히 그 path에 접근할 수 있다는 점에 유의하세요. 이 option을 사용할 때는 원하지 않는 route로의 navigation을 programmatic하게 막아야 합니다.

Note that useFileSystemPublicRoutes disables filename routes from SSR; client-side routing may still access those paths. When using this option, you should guard against navigation to routes you do not want programmatically.

client-side router가 파일 이름 route로의 client-side redirect를 허용하지 않도록 설정하고 싶을 수도 있습니다. 이에 대해서는 router.beforePopState를 참고하세요.

You may also wish to configure the client-side router to disallow client-side redirects to filename routes; for that refer to router.beforePopState.
