use cache: privateuse cache: private

'use cache: private' directive를 사용하면 함수가 cache된 scope 안에서 cookies(), headers(), searchParams 같은 runtime request API에 접근할 수 있습니다. production에서는 하나의 request 안에서 일치하는 호출들이 같은 결과를 재사용할 수 있지만, Next.js는 이를 여러 request에 걸쳐 server cache에 저장하지 않습니다. development에서는 Next.js가 request의 cookie와 header를 key로 하여 메모리에 저장하고, 백그라운드에서 새 결과를 생성하는 동안 다음 일치하는 request에 이를 제공합니다.

The 'use cache: private' directive allows functions to access runtime request APIs like cookies(), headers(), and searchParams within a cached scope. In production, matching calls within one request can reuse the same result, but Next.js does not store it in a server cache across requests. In development, Next.js stores it in memory, keyed by the request's cookies and headers, and serves it to the next matching request while a fresh result is generated in the background.

client router는 cacheLife로 설정한 stale time 동안 render된 출력을 브라우저 메모리에 보관할 수 있습니다. 이 client-side cache는 페이지를 새로 고침하면 유지되지 않습니다.

The client router can keep the rendered output in browser memory for the stale time configured with cacheLife. This client-side cache does not persist across page reloads.

다음과 같은 경우 'use cache: private'를 사용하세요:

Reach for 'use cache: private' when:

  • 이미 runtime 데이터에 접근하는 함수를 cache하고 싶은데, runtime 접근을 밖으로 옮기고 값을 인자로 전달하도록 refactoring하는 것이 현실적이지 않을 때.
  • request별 데이터를 production request 간에 유지되는 server cache에서 제외해야 할 때.
  • You want to cache a function that already accesses runtime data, and refactoring to move the runtime access outside and pass values as arguments is not practical.
  • You need request-specific data to be excluded from server caches that persist across production requests.

Private Cache Function은 request time에 실행되며 static shell 생성에서 제외됩니다. component가 결과를 필요로 하기 전에 private Cache Function을 시작하려면 데이터 preload하기를 참고하세요.

Private Cache Functions run at request time and are excluded from static shell generation. To start a private Cache Function before a component needs its result, see Preloading data.

'use cache: private'에는 커스텀 cache handler를 설정하는 것이 불가능합니다.

It is not possible to configure custom cache handlers for 'use cache: private'.

여러 cache directive의 비교는 How use cache: remote differs from use cache and use cache: private를 참고하세요.

For a comparison of the different cache directives, see How use cache: remote differs from use cache and use cache: private.

Usage사용법

'use cache: private'를 사용하려면 next.config.ts 파일에서 cacheComponents flag를 활성화하세요:

To use 'use cache: private', enable the cacheComponents flag in your next.config.ts file:

TSJSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
}

export default nextConfig
/** @type {import('next').NextConfig} */
const nextConfig = {
  cacheComponents: true,
}

module.exports = nextConfig

그런 다음 함수에 cacheLife 설정과 함께 'use cache: private'를 추가하세요.

Then add 'use cache: private' to your function along with a cacheLife configuration.

Basic example기본 예시

이 예시에서는 'use cache: private' scope 안에서 cookie에 접근할 수 있음을 보여 줍니다:

In this example, we demonstrate that you can access cookies within a 'use cache: private' scope:

TSJSapp/product/[id]/page.tsx
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { cacheLife, cacheTag } from 'next/cache'

export async function generateStaticParams() {
  return [{ id: '1' }]
}

export default async function ProductPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params

  return (
    <div>
      <ProductDetails id={id} />
      <Suspense fallback={<div>Loading recommendations...</div>}>
        <Recommendations productId={id} />
      </Suspense>
    </div>
  )
}

async function Recommendations({ productId }: { productId: string }) {
  const recommendations = await getRecommendations(productId)

  return (
    <div>
      {recommendations.map((rec) => (
        <ProductCard key={rec.id} product={rec} />
      ))}
    </div>
  )
}

async function getRecommendations(productId: string) {
  'use cache: private'
  cacheTag(`recommendations-${productId}`)
  cacheLife({ stale: 60 })

  // Access cookies within private cache functions
  const sessionId = (await cookies()).get('session-id')?.value || 'guest'

  return getPersonalizedRecommendations(productId, sessionId)
}

Good to know

링크별 prefetching이 동작하려면 stale time이 최소 30초여야 하고, 콘텐츠가 route의 App Shell에 포함되려면 최소 5분이어야 합니다. 자세한 내용은 cacheLife prerendering 동작을 참고하세요.

The stale time must be at least 30 seconds for per-link prefetching to work, and at least 5 minutes for the content to be included in the route's App Shell. See cacheLife prerendering behavior for details.

Configuring the client stale timeClient stale time 설정하기

Private Cache Function은 자신의 stale time을 route의 Client Cache에 반영합니다. 함수가 request 범위의 중복 제거(deduplication)만 필요하다면 cacheLife({ stale: Infinity })를 사용해 route의 stale time을 낮추지 않도록 하세요.

Private Cache Functions contribute their stale time to the route's Client Cache. If a function only needs request-scoped deduplication, use cacheLife({ stale: Infinity }) to keep it from lowering the route's stale time.

Next.js는 route의 cache 항목들 중 가장 짧은 stale time을 사용하므로, 다른 cache나 route 설정이 여전히 유한한 값을 설정할 수 있습니다. stale을 Infinity로 설정해도 private 결과가 production request 간에 서버에 저장되지는 않습니다. client router가 정해진 간격 후에 개인화된 출력을 revalidate해야 한다면 유한한 값을 사용하세요.

Next.js uses the shortest stale time from the route's cache entries, so another cache or route setting can still set a finite value. Setting stale to Infinity does not store the private result on the server across production requests. Use a finite value when the client router should revalidate personalized output after a known interval.

Request APIs allowed in private cachesPrivate cache에서 허용되는 Request API

다음 request별 API는 'use cache: private' 함수 안에서 사용할 수 있습니다:

The following request-specific APIs can be used inside 'use cache: private' functions:

APIuse cache에서 허용'use cache: private'에서 허용
cookies()아니요예
headers()아니요예
searchParams아니요예
connection()아니요아니요
APIAllowed in use cacheAllowed in 'use cache: private'
cookies()NoYes
headers()NoYes
searchParamsNoYes
connection()NoNo
Note

connection() API는 안전하게 cache할 수 없는 connection별 정보를 제공하므로 use cache와 'use cache: private' 모두에서 금지됩니다.

The connection() API is prohibited in both use cache and 'use cache: private' as it provides connection-specific information that cannot be safely cached.
