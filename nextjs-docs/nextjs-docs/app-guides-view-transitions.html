Designing view transitionsView transition 설계하기

웹 앱에서 route가 바뀌면 페이지 전체가 한 번에 교체됩니다. 한 세트의 요소가 사라지고 다른 세트가 나타나지만, 둘 사이에는 시각적 연결이 없습니다. 사용자가 사진 썸네일을 선택해 다른 페이지에서 자세히 봅니다. 같은 이미지이지만, 화면의 어떤 것도 그 사실을 전달하지 않습니다.

In web apps, route changes replace the entire page at once. One set of elements disappears, another appears, with no visual connection between them. A user selects a photo thumbnail to view it in detail on another page. They are the same image, but nothing on screen communicates that.

이런 transition이 필요한 앱은 보통 요소가 진입하고, 퇴장하고, 상태 사이를 이동하는 방식을 애니메이션하기 위해 mount/unmount lifecycle을 관리하고, route 간 요소 위치를 추적하고, 타이밍을 수동으로 조율하는 복잡한 애니메이션 라이브러리에 의존합니다.

Apps that need these transitions typically rely on complex animation libraries that manage mount/unmount lifecycles, track element positions across routes, and coordinate timing manually, to animate how elements enter, exit, and move between states.

React의 <ViewTransition> component는 브라우저의 View Transitions API와 통합되어 이를 선언적으로 처리합니다. 유지되어야 할 요소에 이름을 붙이면, 브라우저가 이전 위치와 새 위치 사이를 애니메이션합니다.

React's <ViewTransition> component integrates with the browser's View Transitions API to handle this declaratively. You name the elements that should persist, and the browser animates between their old and new positions.

이 가이드에서는 가장 흔한 경우를 다루는 네 가지 패턴을 살펴봅니다: shared element morphing, 로딩 상태 애니메이션, 방향성 있는 navigation 추가, 같은 route 안에서의 콘텐츠 crossfade입니다.

This guide walks through four patterns that cover the most common cases: morphing shared elements, animating loading states, adding directional navigation, and crossfading content within the same route.

View transition은 App Router에서 별도 설정 없이 동작합니다. React 19.3에는 이 가이드에서 사용하는 <ViewTransition> component와 addTransitionType API가 포함되어 있습니다.

View transitions work in the App Router with no configuration. React 19.3 includes the <ViewTransition> component and addTransitionType API used in this guide.

Note

React의 통합 기능은 더 새로운 View Transitions API 기능(transition type과 view-transition-class)을 사용하며, 이는 Chromium 125+와 최신 Safari, Firefox 버전에서 사용할 수 있습니다. 일부 애니메이션은 Safari에서 다르게 동작할 수 있습니다. 브라우저가 지원하지 않아도 애플리케이션은 정상적으로 동작하며, transition만 애니메이션되지 않습니다.

React's integration uses newer View Transitions API features (transition types and view-transition-class), available in Chromium 125+ and recent Safari and Firefox versions. Some animations may behave differently in Safari. Without browser support, your application works normally; the transitions do not animate.

React에서 ViewTransition component를 import하세요:

Import the ViewTransition component from React:

import { ViewTransition } from 'react'

<ViewTransition> 애니메이션은 Transitions, <Suspense>, useDeferredValue에 의해 활성화됩니다. 일반적인 setState 호출로는 trigger되지 않습니다. Next.js에서 route navigation은 transition이므로, navigation 중에 <ViewTransition> 애니메이션이 자동으로 활성화됩니다.

<ViewTransition> animations are activated by Transitions, <Suspense>, and useDeferredValue. Regular setState calls do not trigger them. In Next.js, route navigations are transitions, so <ViewTransition> animations activate automatically during navigation.

Step 1: Morph a thumbnail into a hero image1단계: 썸네일을 hero 이미지로 morph하기

갤러리는 사진을 grid로 표시합니다. 사진을 클릭하면 같은 이미지를 더 크게 보여 주는 상세 페이지가 열립니다. transition이 없으면 썸네일이 사라지고 hero가 나타납니다. 둘을 시각적으로 연결하는 것은 아무것도 없습니다. 사용자는 자신이 올바른 사진을 클릭했는지 확인하려고 상세 페이지를 훑어봐야 합니다.

The gallery displays photos in a grid. Clicking a photo opens a detail page with a larger version of the same image. Without transitions, the thumbnail disappears and the hero appears. Nothing connects them visually. The user has to scan the detail page to confirm they clicked the right photo.

모션 디자인에서 어떤 객체가 컷을 넘어 유지되면 연속성을 전달합니다. 보는 사람은 대체물이 아니라 같은 것을 보고 있다는 것을 이해합니다. 이것이 가장 중요한 transition 패턴인 shared element morphing입니다.

In motion design, when an object persists across a cut, it communicates continuity. The viewer understands they are looking at the same thing, not a replacement. This is the most important transition pattern: shared element morphing.

grid 썸네일과 상세 hero를 모두 같은 name을 가진 <ViewTransition>으로 감싸세요:

Wrap both the grid thumbnail and the detail hero in <ViewTransition> with the same name:

TScomponents/photo-grid.tsx
import { ViewTransition } from 'react'
import Image from 'next/image'
import Link from 'next/link'

function PhotoGrid({ photos }) {
  return (
    <div className="grid grid-cols-3 gap-3">
      {photos.map((photo) => (
        <Link key={photo.id} href={`/photo/${photo.id}`}>
          <ViewTransition name={`photo-${photo.id}`}>
            <Image src={photo.src} alt={photo.title} />
          </ViewTransition>
        </Link>
      ))}
    </div>
  )
}
TSapp/photo/[id]/photo-content.tsx
import { ViewTransition } from 'react'
import Image from 'next/image'

async function PhotoContent({ id }) {
  const photo = await getPhoto(id)

  return (
    <ViewTransition name={`photo-${photo.id}`}>
      <div style={{ position: 'relative', aspectRatio: '3 / 2' }}>
        <Image src={photo.src} alt={photo.title} fill />
      </div>
    </ViewTransition>
  )
}

name prop은 정체성(identity)을 만듭니다. React는 이전 페이지와 새 페이지에서 같은 이름을 가진 요소를 찾은 다음, 크기와 위치 사이를 자동으로 애니메이션합니다. morph가 동작하는 데 추가 props는 필요하지 않습니다.

The name prop creates identity. React finds elements with the same name on the old and new pages, then animates between their size and position automatically. No additional props are needed for the morph to work.

이제 썸네일을 클릭하면 이미지가 grid 셀에서 hero 자리로 크기와 위치를 바꿉니다. 뒤로 이동하면 morph가 반대로 진행됩니다. 사용자는 두 객체가 바뀌는 것이 아니라 하나의 객체가 움직이는 것을 보게 됩니다.

If we click a thumbnail now, the image scales and repositions from its grid cell to the hero slot. Navigating back reverses the morph. The user sees one object moving, not two objects swapping.

morph는 이동할 페이지의 콘텐츠가 navigation과 같은 commit에서 render될 때 재생되며, prefetch된(cache된) 페이지가 이에 해당합니다. 이동할 페이지가 먼저 fallback으로 suspend되면 짝이 만들어지지 않고, 콘텐츠는 도착할 때 대신 enter 애니메이션으로 애니메이션됩니다.

The morph plays when the destination content renders in the same commit as the navigation, which is the case with prefetched (cached) pages. If the destination suspends into a fallback first, no pair forms, and the content animates with its enter animation instead when it arrives.

Customizing the morph animationMorph 애니메이션 커스터마이즈하기

morph는 CSS 없이도 동작합니다. 커스터마이즈하려면 share="morph"와 default="none"을 함께 추가하세요. share prop은 view transition에 morph class를 지정하며, CSS pseudo-element로 이를 target할 수 있습니다. 예를 들어 blur keyframe으로 morph 도중에 부드럽게 만들려면 다음과 같이 합니다:

The morph works without any CSS. To customize it, add share="morph" together with default="none". The share prop assigns the morph class to the view transition, which you can target with CSS pseudo-elements. For example, to soften the morph mid-flight with a blur keyframe:

<ViewTransition name={`photo-${photo.id}`} share="morph" default="none">
  <Image src={photo.src} alt={photo.title} />
</ViewTransition>

1단계의 두 코드(photo-grid.tsx와 photo-content.tsx) 모두에 같은 props를 추가하세요. default="none"은 이름이 붙은 각 이미지가 관련 없는 모든 transition마다 자체 crossfade를 실행하지 않도록 합니다. 이것이 없으면 이름이 붙은 모든 <ViewTransition>이 페이지에서 어떤 transition이 실행될 때마다 애니메이션됩니다. 이름이 붙은 짝에 default="none"을 추가할 때는 명시적인 share를 유지하세요. default="none"만 있고 share prop이 없으면, 그 짝은 아무런 경고 없이 morph를 멈춥니다.

Add the same props to both Step 1 snippets (photo-grid.tsx and photo-content.tsx). default="none" keeps each named image from running its own crossfade on every unrelated transition. Without it, every named <ViewTransition> animates whenever any transition runs on the page. When you add default="none" to a named pair, keep the explicit share. With default="none" and no share prop, the pair silently stops morphing.

app/globals.css
::view-transition-group(.morph) {
  animation-duration: 400ms;
}
::view-transition-image-pair(.morph) {
  animation-name: via-blur;
}
@keyframes via-blur {
  30% {
    filter: blur(3px);
  }
}

blur는 transition 중 픽셀 단위 보간 artifact를 가려 줍니다. 400ms라면 morph가 인지될 만큼 느리면서도 직접적으로 느껴질 만큼 빠릅니다.

The blur hides pixel-level interpolation artifacts during the transition. At 400ms, the morph is slow enough to register but fast enough to feel direct.

Step 2: Animate loading states with Suspense reveals2단계: Suspense reveal로 로딩 상태 애니메이션하기

사진 상세 페이지는 콘텐츠를 비동기로 로드합니다. 데이터를 가져오는 동안 Suspense boundary가 skeleton을 보여 줍니다. 데이터가 resolve되면 skeleton이 실제 콘텐츠로 교체됩니다.

The photo detail page loads its content asynchronously. While data is in flight, a Suspense boundary shows a skeleton. When the data resolves, the skeleton is replaced by the real content.

transition이 없으면 교체가 즉시 일어납니다. skeleton이 사라지고 콘텐츠가 툭 튀어나옵니다.

Without a transition, the swap is instant. The skeleton vanishes and the content pops in.

모션 디자인에서 수직 방향은 위계를 나타냅니다. 위로 slide하는 콘텐츠는 도착을 전달합니다. 아래로 slide하는 콘텐츠는 떠남을 전달합니다. 이 둘을 함께 쓰면 placeholder가 실제 콘텐츠에 자리를 넘겨주는 인계(handoff)가 만들어집니다.

In motion design, vertical direction encodes hierarchy. Content sliding up communicates arrival. Content sliding down communicates departure. The pair together creates a handoff: the placeholder yields to the real thing.

Suspense fallback은 exit 애니메이션이 있는 ViewTransition으로, 콘텐츠는 enter 애니메이션이 있는 ViewTransition으로 감싸세요:

Wrap the Suspense fallback in a ViewTransition with an exit animation, and the content in a ViewTransition with an enter animation:

TSapp/photo/[id]/page.tsx
import { Suspense, ViewTransition } from 'react'

export default async function PhotoPage({ params }) {
  const { id } = await params

  return (
    <Suspense
      fallback={
        <ViewTransition exit="slide-down" default="none">
          <PhotoContentSkeleton />
        </ViewTransition>
      }
    >
      <ViewTransition enter="slide-up" default="none">
        <PhotoContent id={id} />
      </ViewTransition>
    </Suspense>
  )
}

1단계와 마찬가지로 default="none"은 이 ViewTransition이 shared element morph 같은 관련 없는 transition 중에 애니메이션되지 않도록 합니다.

As in Step 1, default="none" prevents this ViewTransition from animating during unrelated transitions, like the shared element morph.

CSS 애니메이션은 비대칭 타이밍을 사용합니다. exit은 빠릅니다(150ms). enter fade는 더 느리고(210ms) exit이 끝날 때까지 지연되며, slide 움직임은 더 오래(400ms) 진행됩니다:

The CSS animations use asymmetric timing. The exit is fast (150ms). The enter fade is slower (210ms) and delayed until the exit completes, while its slide movement runs longer (400ms):

app/globals.css
:root {
  --duration-exit: 150ms;
  --duration-enter: 210ms;
  --duration-move: 400ms;
}

::view-transition-old(.slide-down) {
  animation:
    var(--duration-exit) ease-out both fade reverse,
    var(--duration-exit) ease-out both slide-y reverse;
}
::view-transition-new(.slide-up) {
  animation:
    var(--duration-enter) ease-in var(--duration-exit) both fade,
    var(--duration-move) ease-in both slide-y;
}

@keyframes fade {
  from {
    filter: blur(3px);
    opacity: 0;
  }
  to {
    filter: blur(0);
    opacity: 1;
  }
}
@keyframes slide-y {
  from {
    transform: translateY(10px);
  }
  to {
    transform: translateY(0);
  }
}

이 비대칭은 의도된 것입니다. 이전 콘텐츠는 주의를 끌며 경쟁하지 않도록 빨리 떠나야 합니다. 새 콘텐츠는 사용자가 인지할 시간을 갖도록 더 부드럽게 도착해야 합니다. enter fade의 var(--duration-exit) delay는 새 콘텐츠가 보이기 전에 이전 콘텐츠가 떠나기를 기다린다는 뜻입니다.

The asymmetry is deliberate. Old content should leave quickly so it does not compete for attention. New content should arrive more gently so the user has time to register it. The var(--duration-exit) delay on the enter fade means the new content waits for the old content to finish leaving before it becomes visible.

페이지를 새로 고침하면 skeleton이 아래로 slide하며 fade out되고, 잠시 후 실제 콘텐츠가 위로 slide하며 fade in됩니다.

If we refresh the page, the skeleton slides down and fades out, and a moment later the real content slides up and fades in.

Step 3: Add directional motion for navigation3단계: Navigation에 방향성 있는 모션 추가하기

이제 갤러리에는 morph되는 이미지와 애니메이션되는 로딩 상태가 있습니다. 하지만 페이지 사이를 이동할 때는 여전히 방향 신호가 없습니다. 앞으로 이동과 뒤로 이동이 똑같아 보입니다. 사용자는 애니메이션만 보고 앱 안으로 더 깊이 들어갔는지, 이전 페이지로 돌아왔는지 알 수 없습니다.

The gallery now has morphing images and animated loading states. But navigating between pages still has no directional signal. Forward and back navigations look identical. The user cannot tell from the animation whether they moved deeper into the app or returned to a previous page.

영화와 애니메이션에서 수평 방향은 공간적 위치를 나타냅니다. 왼쪽으로 움직이는 것은 앞으로 나아가는 것을 의미합니다(왼쪽에서 오른쪽으로 읽는 언어에서 페이지를 넘기는 것처럼). 오른쪽으로 움직이는 것은 뒤로 가는 것을 의미합니다. 이 convention(관례)은 너무 깊이 자리 잡고 있어서 이를 어기면 방향 감각을 잃은 느낌이 듭니다.

In film and animation, horizontal direction encodes spatial position. Moving left means progressing forward (like turning a page in a left-to-right language). Moving right means going back. This convention is so ingrained that violating it feels disorienting.

<Link>의 transitionTypes prop을 사용해 앞으로 가는 navigation에 태그를 붙이세요:

Use the transitionTypes prop on <Link> to tag forward navigations:

TScomponents/photo-grid.tsx
<Link href={`/photo/${photo.id}`} transitionTypes={['nav-forward']}>
  {/* photo thumbnail */}
</Link>

같은 패턴은 앱 안의 어떤 navigation에도 적용됩니다. 예를 들어 사진 상세 페이지의 이전/다음 화살표는 nav-back과 nav-forward를 사용해 해당 방향으로 애니메이션할 수 있습니다.

The same pattern works for any navigation within the app. For example, previous/next arrows on a photo detail page can use nav-back and nav-forward to animate in the corresponding direction.

사용자를 이전 페이지로 돌려보내는 링크에는 nav-back을 사용하세요:

For links that return the user to a previous page, use nav-back:

TSapp/photo/[id]/page.tsx
<Link href="/" transitionTypes={['nav-back']}>
  ← Gallery
</Link>

transition type은 자동으로 정해지지 않습니다. 앱의 navigation 계층 구조에 따라 어떤 링크가 "forward"이고 어떤 링크가 "back"인지 직접 결정합니다.

The transition type is not automatic. You decide which links are "forward" and which are "back" based on your app's navigation hierarchy.

그런 다음 transition type을 방향성 있는 애니메이션에 매핑하는 ViewTransition으로 페이지 콘텐츠를 감싸세요:

Then wrap page content in a ViewTransition that maps transition types to directional animations:

TSapp/photo/[id]/page.tsx
<ViewTransition
  enter={{
    'nav-forward': 'nav-forward',
    'nav-back': 'nav-back',
    default: 'none',
  }}
  exit={{
    'nav-forward': 'nav-forward',
    'nav-back': 'nav-back',
    default: 'none',
  }}
  default="none"
>
  {/* page content */}
</ViewTransition>

enter와 exit props는 transition type을 key로 하는 객체를 받습니다. navigation이 nav-forward type을 가지고 있으면, exit 애니메이션은 이전 콘텐츠를 왼쪽으로 slide시키고 enter 애니메이션은 새 콘텐츠를 오른쪽에서 slide시켜 들여옵니다. default: "none"은 type이 없는 transition(브라우저 뒤로/앞으로, router.refresh(), Suspense reveal)이 방향성 있는 애니메이션을 만들지 않도록 보장합니다.

The enter and exit props accept an object keyed by transition type. When a navigation carries the nav-forward type, the exit animation slides old content left and the enter animation slides new content in from the right. The default: "none" ensures that transitions without a type (browser back/forward, router.refresh(), Suspense reveals) produce no directional animation.

참여하는 모든 페이지를 같은 방식으로 감싸세요. 갤러리가 forward navigation에서 slide out되고 nav-back에서 다시 slide in되려면, 그 페이지에도 같은 wrapper가 필요합니다. wrapper는 layout이 아니라 각 page.tsx에 넣으세요. layout은 navigation 간에 유지되므로 거기서는 enter와 exit이 절대 발생하지 않습니다:

Wrap every participating page the same way. For the gallery to slide out on forward navigation and back in on nav-back, its page needs the same wrapper. Put the wrapper in each page.tsx, not the layout. Layouts persist across navigations, so enter and exit never fire there:

TSapp/page.tsx
<ViewTransition
  enter={{
    'nav-forward': 'nav-forward',
    'nav-back': 'nav-back',
    default: 'none',
  }}
  exit={{
    'nav-forward': 'nav-forward',
    'nav-back': 'nav-back',
    default: 'none',
  }}
  default="none"
>
  <PhotoGrid photos={photos} />
</ViewTransition>

방향성 있는 slide를 위한 CSS:

The CSS for directional slides:

app/globals.css
::view-transition-old(.nav-forward) {
  --slide-offset: -60px;
  animation:
    150ms ease-in both fade reverse,
    400ms ease-in-out both slide reverse;
}
::view-transition-new(.nav-forward) {
  --slide-offset: 60px;
  animation:
    210ms ease-out 150ms both fade,
    400ms ease-in-out both slide;
}

::view-transition-old(.nav-back) {
  --slide-offset: 60px;
  animation:
    150ms ease-in both fade reverse,
    400ms ease-in-out both slide reverse;
}
::view-transition-new(.nav-back) {
  --slide-offset: -60px;
  animation:
    210ms ease-out 150ms both fade,
    400ms ease-in-out both slide;
}

@keyframes slide {
  from {
    translate: var(--slide-offset);
  }
  to {
    translate: 0;
  }
}

60px 오프셋은 사용자가 화면을 가로질러 빠르게 움직이는 요소를 눈으로 쫓게 만들지 않으면서도 방향을 전달하기에 충분합니다.

The 60px offset is enough to communicate direction without making the user track a fast-moving element across the screen.

Anchoring the headerHeader 고정하기

방향성 있는 slide 중에 header는 움직이지 않아야 합니다. header가 slide하면 사용자의 공간적 기준점이 깨집니다. viewport 전체가 아니라 콘텐츠 가 움직였다는 것을 이해하려면 고정된 기준점이 하나 필요합니다.

During directional slides, the header should not move. A sliding header breaks the user's spatial anchor. They need one fixed reference point to understand that the content moved, not the entire viewport.

header에 viewTransitionName을 지정하고 CSS에서 애니메이션을 억제하세요:

Assign the header a viewTransitionName and suppress its animation in CSS:

TScomponents/header.tsx
<header style={{ viewTransitionName: 'site-header' }}>
  {/* navigation links */}
</header>
app/globals.css
::view-transition-group(site-header) {
  animation: none;
  z-index: 100;
}
::view-transition-old(site-header) {
  display: none;
}
::view-transition-new(site-header) {
  animation: none;
}

이전 snapshot의 display: none은 이전 header와 새 header가 잠깐 동시에 보이는 깜빡임을 방지합니다. z-index: 100은 header가 slide하는 콘텐츠 위에 render되도록 합니다.

The display: none on the old snapshot prevents a flash where both old and new headers are briefly visible. The z-index: 100 ensures the header renders above the sliding content.

사진으로 forward navigation하면 콘텐츠가 왼쪽으로 slide합니다. (nav-back 태그가 붙은) "← Gallery" 링크를 클릭하면 콘텐츠가 오른쪽으로 slide합니다. 두 transition 내내 header는 고정되어 있습니다.

If we navigate forward to a photo, content slides left. If we click the "← Gallery" link (tagged with nav-back), content slides right. The header stays fixed throughout both transitions.

브라우저가 시작한 뒤로 가기 navigation(뒤로 가기 버튼이나 swipe 제스처)은 transition type을 가지지 않으므로 방향성 있는 slide가 재생되지 않습니다. 두 페이지에 일치하는 name props가 있다면 1단계의 shared element morph는 여전히 적용됩니다.

Browser-initiated back navigations (the back button or swipe gestures) do not carry a transition type, so the directional slide does not play. The shared element morph from Step 1 still applies if both pages have matching name props.

Keeping the page interactive페이지 상호작용 유지하기

transition이 실행되는 동안 ::view-transition overlay가 pointer event를 가로채므로 애니메이션 중의 클릭은 사라집니다. 클릭이 실제 페이지로 통과하도록 하세요:

While a transition runs, the ::view-transition overlay captures pointer events, so clicks during the animation are lost. Let them pass through to the live page:

app/globals.css
::view-transition {
  pointer-events: none;
}

이렇게 하면 이름이 없는 콘텐츠의 상호작용이 복원됩니다. hit-testing은 transition이 진행되는 동안 여전히 이름이 붙은 참여 요소(고정된 header 등)를 건너뛰므로, transition은 짧게 유지하고 사용자가 빠르게 클릭하는 요소에는 이름을 붙이지 마세요.

This restores interactivity for unnamed content. Hit-testing still skips named participants (like the anchored header) for the transition's duration, so keep transitions short and avoid naming elements the user clicks rapidly.

Respecting reduced motionReduced motion 존중하기

방향성 있는 slide는 viewport를 가로지르는 물리적 움직임을 흉내 냅니다. 이는 모션 민감성을 일으키는 가장 흔한 원인입니다. morph, reveal, crossfade는 더 작은 영역에 영향을 주거나 위치 대신 opacity에 의존하므로 위험이 덜합니다.

Directional slides simulate physical movement across the viewport. This is the most common trigger for motion sensitivity. Morphs, reveals, and crossfades carry less risk since they affect smaller areas or rely on opacity rather than position.

가장 간단한 방법은 모든 애니메이션 duration을 비활성화하는 것입니다:

The simplest approach is to disable all animation durations:

app/globals.css
@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(*),
  ::view-transition-new(*),
  ::view-transition-group(*) {
    animation-duration: 0s !important;
    animation-delay: 0s !important;
  }
}

애니메이션이 없으면 콘텐츠가 즉시 교체되며, 이것이 브라우저의 기본 동작입니다. 더 정교한 방법은 위치 이동은 제거하되 crossfade와 opacity transition은 유지하는 것입니다. 자세한 내용은 "No Motion Isn't Always prefers-reduced-motion"을 참고하세요.

Without animation, content swaps instantly, which is the browser's default behavior. A more refined approach would preserve crossfades and opacity transitions while removing positional movement. See "No Motion Isn't Always prefers-reduced-motion" for more on this.

Step 4: Crossfade content within the same route4단계: 같은 route 안에서 콘텐츠 crossfade하기

갤러리에는 탭이 있는 사진작가 섹션이 있습니다. 각 탭은 다른 사진작가의 사진을 보여 주지만 route 구조는 /collection/[slug]로 같습니다. 탭 사이를 클릭하는 것은 새 페이지로 이동하는 느낌이 아닙니다. 같은 컨테이너 안에서 콘텐츠를 전환하는 느낌입니다.

The gallery has a photographer section with tabs. Each tab shows a different photographer's photos, but the route structure is the same: /collection/[slug]. Clicking between tabs does not feel like navigating to a new page. It feels like switching content within the same container.

여기서는 방향성 있는 slide가 맞지 않습니다. slide는 "새로운 곳으로 간다"는 것을 전달합니다. crossfade는 "같은 곳, 다른 콘텐츠"를 전달합니다. 컨테이너는 유지되고(연속성), 안쪽의 grid만 바뀝니다(교체).

A directional slide would be wrong here. Slides communicate "going to a new place." A crossfade communicates "same place, different content." The container persists (continuity), only the grid inside changes (swap).

key를 현재 slug로 설정한 ViewTransition을 사용하세요. key가 바뀌면 React가 이전 콘텐츠와 새 콘텐츠 사이에 transition을 trigger합니다:

Use a ViewTransition with key set to the current slug. When the key changes, React triggers a transition between the old and new content:

TSapp/collection/[slug]/page.tsx
import { Suspense, ViewTransition } from 'react'

export default async function CollectionPage({ params }) {
  const { slug } = await params

  return (
    <Suspense fallback={<CollectionGridSkeleton />}>
      <ViewTransition
        key={slug}
        name="collection-content"
        share="auto"
        enter="auto"
        default="none"
      >
        <CollectionGrid slug={slug} />
      </ViewTransition>
    </Suspense>
  )
}

share="auto"와 enter="auto" props는 React에게 기본 crossfade 애니메이션을 사용하라고 알려 줍니다. name prop은 컨테이너에 정체성을 부여해 React가 무엇을 애니메이션할지 알게 합니다. navigation이 transition을 trigger하고, key={slug} 변경은 React가 이전 콘텐츠와 새 콘텐츠를 in-place 업데이트가 아니라 exit/enter 짝으로 취급하게 만듭니다(share 활성화).

The share="auto" and enter="auto" props tell React to use its default crossfade animation. The name prop gives the container an identity so React knows what to animate. The navigation triggers the transition; the key={slug} change makes React treat the old and new content as an exit/enter pair (activating share) instead of an in-place update.

사진작가 탭 사이를 클릭하면 grid가 crossfade됩니다. 탭 바와 주변 layout은 움직이지 않습니다. 사진 grid만 상태 사이를 전환합니다.

If we click between photographer tabs, the grid crossfades. The tab bar and surrounding layout do not move. Only the photo grid transitions between states.

Next steps다음 단계

이제 navigation 중에 view transition으로 의미를 전달하는 방법을 알게 되었습니다. shared element는 route 간 연속성을 전달합니다. Suspense reveal은 로딩 인계를 애니메이션합니다. 방향성 있는 slide는 navigation 기록을 나타냅니다. crossfade는 같은 위치 안에서의 콘텐츠 변경을 알립니다.

You now know how to use view transitions to communicate meaning during navigation. Shared elements communicate continuity across routes. Suspense reveals animate loading handoffs. Directional slides encode navigation history. Crossfades signal content changes within the same location.
