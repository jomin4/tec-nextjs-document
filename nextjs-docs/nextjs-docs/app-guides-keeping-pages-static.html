Keeping pages static페이지를 static으로 유지하기

Cache Components 이전에는 dynamic = 'force-static', dynamic = 'force-dynamic', dynamic = 'error' 같은 route segment config가 route 전체의 rendering mode를 선택했습니다. Cache Components를 사용하면 하나의 route 안에서 prerender된 UI, cache된 콘텐츠, request 시점에 render되는 request별 콘텐츠를 조합할 수 있습니다.

Before Cache Components, route segment configs such as dynamic = 'force-static', dynamic = 'force-dynamic', and dynamic = 'error' selected a rendering mode for an entire route. Cache Components lets one route combine prerendered UI, cached content, and request-specific content rendered at request time.

이런 유연성은 personalization이 필요한 route에 유용합니다. 예측 가능한 성능과 compute 비용을 위해 route의 일부 또는 전체가 request 시점의 server rendering을 피해야 한다면 ensureStatic을 사용하세요.

This flexibility is useful for routes that need personalization. Use ensureStatic when some or all of a route must avoid request-time server rendering for predictable performance and compute costs.

Decide what should stay static무엇을 static으로 유지할지 정하기

static 출력은 request별 데이터에 의존하지 않습니다. Next.js는 request가 오기 전에 이를 생성해 두고 여러 request에 걸쳐 재사용할 수 있습니다.

Static output does not depend on request-specific data. Next.js can generate it before a request and reuse it across requests.

Partial Prefetching을 사용하면 route 출력은 세 가지 navigation stage에서 사용 가능해집니다:

With Partial Prefetching, route output becomes available in three navigation stages:

  1. 기본 <Link>는 App Shell을 load합니다.
  2. <Link prefetch={true}>는 그 link의 URL에 대한 콘텐츠도 load할 수 있습니다.
  3. navigation은 click 이후에 남은 나머지를 render합니다.
  1. A default <Link> loads the App Shell.
  2. <Link prefetch={true}> can also load content for that link's URL.
  3. The navigation renders anything that remains after the click.

각 ensureStatic level은 static 요구 사항을 이 stage들 중 하나까지 확장합니다. 다음 diagram에서 회색은 static 출력을, 파란색은 request 시점에 render될 수 있는 콘텐츠를 나타냅니다:

Each ensureStatic level extends the static requirement through one of these stages. In the following diagram, gray marks static output and blue marks content that can render at request time:

어떤 request가 static 출력만 사용해야 하는지에 따라 level을 고르세요:

Choose a level based on which request must use only static output:

  • 'shell': 기본 <Link>가 load하는 App Shell.
  • 'prefetch': App Shell과 <Link prefetch={true}>의 per-link prefetch. 여기에는 params 같은 link의 URL data에 대한 콘텐츠가 포함될 수 있습니다.
  • 'navigation': 사용자가 navigate한 뒤 반환되는 response를 포함한 route 전체.
  • 'shell': the App Shell loaded by a default <Link>.
  • 'prefetch': the App Shell and the per-link prefetch from <Link prefetch={true}>, which can include content for the link's URL data, such as params.
  • 'navigation': the complete route, including the response returned after the user navigates.

Example예제

다음 예제는 온라인 스토어의 세 부분, 즉 공유 cart, 상품 페이지, 공개 구매 가이드에 static 요구 사항을 추가합니다.

The following example adds static requirements to three parts of an online store: its shared cart, product pages, and public buying guides.

│   ├── page.tsx           # Product catalog
│   └── products/

│           └── page.tsx   # Product details and cart status
├── guides/
│   └── [id]/

└── ui/

Cache Components와 Partial Prefetching을 활성화하세요:

Enable Cache Components and Partial Prefetching:

TSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}

export default nextConfig

Step 1: Load a static App Shell1단계: static App Shell load하기

공유 store layout은 방문자의 cart 개수를 표시합니다. CartButton은 server에서 cookie로부터 개수를 읽습니다:

The shared store layout displays a visitor's cart count. CartButton reads the count from a cookie on the server:

TSapp/ui/cart.tsx
import { cookies } from 'next/headers'

export async function CartButton() {
  const value = Number((await cookies()).get('cart-count')?.value ?? 0)
  return <button>Cart ({value})</button>
}

layout은 CartButton을 <Suspense> 안에 두는데, 이 <Suspense>는 현재 개수가 render되는 동안 static fallback을 제공합니다:

The layout places CartButton inside <Suspense>, which provides a static fallback while the current count renders:

TSapp/store/layout.tsx
import Link from 'next/link'
import { Suspense } from 'react'
import { CartButton } from '@/app/ui/cart'

export default function StoreLayout({ children }: LayoutProps<'/store'>) {
  return (
    <>
      <nav>
        <Link href="/store">Products</Link>
        <Link href="/guides">Buying guides</Link>
        <Suspense fallback={<button>Cart (0)</button>}>
          <CartButton />
        </Suspense>
      </nav>
      <main>{children}</main>
    </>
  )
}

navigation과 cart fallback은 모든 방문자가 공유합니다. store로 가는 link를 load할 때, 사용자가 click하기 전에 server에서 개인화된 cart 개수를 render해서는 안 됩니다. ensureStatic = 'shell'을 추가해 기본 <Link>가 static App Shell만 request하도록 하세요:

The navigation and cart fallback are shared across visitors. Loading a link to the store should not render the personalized cart count on the server before the user clicks. Add ensureStatic = 'shell' to make a default <Link> request only the static App Shell:

TSapp/store/layout.tsx
import Link from 'next/link'
import { Suspense } from 'react'
import { CartButton } from '@/app/ui/cart'

export const ensureStatic = 'shell'

export default function StoreLayout({ children }: LayoutProps<'/store'>) {
  // ...
}

이제 store로 가는 기본 <Link>는 navigation과 Cart (0) fallback을 static 출력에서 load합니다. 이후 per-link prefetch나 navigation이 요청하기 전까지 server는 현재 cart 개수를 render하지 않습니다. 이렇게 하면 사용자가 끝내 click하지 않을 수도 있는 link에 대해 request 시점의 server 작업을 피할 수 있습니다.

A default <Link> into the store now loads the navigation and Cart (0) fallback from static output. The server does not render the current cart count until a later per-link prefetch or navigation requests it. This avoids request-time server work for links that the user may never click.

Good to know

App Shell에서 CartButton만 미뤄야 했다면 그 subtree 안에서 await prefetch()를 호출할 수 있습니다. 여기서는 앞으로의 변경까지 포함해 store shell 전체에 요구 사항이 적용되므로, layout에서 ensureStatic = 'shell'을 사용합니다.

If only CartButton needed to be deferred from the App Shell, you could call await prefetch() inside that subtree. Here, the requirement applies to the entire store shell, including future changes, so the layout uses ensureStatic = 'shell'.

Step 2: Prefetch static product details2단계: static 상품 상세 prefetch하기

각 상품 페이지는 방문자 간에 재사용할 수 있는 상세 정보와, 현재 방문자에 따라 달라지는 cart action을 함께 담고 있습니다. ProductDetails는 use cache로 query를 cache하고, ProductCartStatus는 cookie를 읽어 상품이 이미 cart에 있는지 확인합니다:

Each product page combines details that can be reused across visitors with a cart action that depends on the current visitor. ProductDetails caches its query with use cache, while ProductCartStatus reads a cookie to check whether the product is already in the cart:

TSapp/ui/product.tsx
import { cookies } from 'next/headers'
import { db } from '@/lib/db'

type Params = Promise<{ slug: string }>

export async function ProductDetails({ params }: { params: Params }) {
  const { slug } = await params
  const product = await getProduct(slug)
  return <h1>{product.name}</h1>
}

export async function ProductCartStatus({ params }: { params: Params }) {
  const { slug } = await params
  const cart = (await cookies()).get('cart')?.value?.split(',') ?? []
  return (
    <button>{cart.includes(slug) ? 'Remove from cart' : 'Add to cart'}</button>
  )
}

async function getProduct(slug: string) {
  'use cache'
  return db.product.findUniqueOrThrow({ where: { slug } })
}

상품 route는 generateStaticParams()로 catalog의 상품 URL을 prerender합니다. <Suspense> boundary를 따로 두면 상품 상세가 static cart fallback과 함께 render될 수 있습니다:

The product route prerenders the catalog's product URL with generateStaticParams(). Separate <Suspense> boundaries let the product details render with a static cart fallback:

TSapp/store/products/[slug]/page.tsx
import { Suspense } from 'react'
import { ProductCartStatus, ProductDetails } from '@/app/ui/product'

export function generateStaticParams() {
  return [{ slug: 'coffee-grinder' }]
}

export default function ProductPage({
  params,
}: PageProps<'/store/products/[slug]'>) {
  return (
    <>
      <Suspense fallback={<p>Loading product...</p>}>
        <ProductDetails params={params} />
      </Suspense>
      <Suspense fallback={<button>Add to cart</button>}>
        <ProductCartStatus params={params} />
      </Suspense>
    </>
  )
}

기본 상품 link는 상품 fallback이 들어 있는 App Shell을 load합니다. 상품 상세는 이미 prerender되어 있으므로, catalog는 prefetch={true}를 설정해 click 전에 이를 포함할 수 있습니다:

A default product link loads the App Shell, which contains the product fallback. Because the product details are already prerendered, the catalog can include them before the click by setting prefetch={true}:

TSapp/store/page.tsx
<Link href="/store/products/coffee-grinder" prefetch={true}>
  Coffee grinder
</Link>

화면에 보이는 각 prefetch={true} link는 해당 상품의 cart action을 개인화하기 위해 ProductCartStatus를 render할 수 있습니다. 따라서 상품 20개가 보이는 grid는 사용자가 상품을 click하기도 전에 request 시점의 server render를 20번 trigger할 수 있습니다.

Each visible prefetch={true} link can render ProductCartStatus to personalize the cart action for that product. A grid with 20 visible products can therefore trigger 20 request-time server renders before the user clicks a product.

ensureStatic = 'prefetch'를 추가해 모든 상품 prefetch가 static 출력만 사용하도록 하세요:

Add ensureStatic = 'prefetch' to make every product prefetch use only static output:

TSapp/store/products/[slug]/page.tsx
import { Suspense } from 'react'
import { ProductCartStatus, ProductDetails } from '@/app/ui/product'

export const ensureStatic = 'prefetch'

export default function ProductPage({
  params,
}: PageProps<'/store/products/[slug]'>) {
  // ...
}

이제 각 상품 prefetch는 request 시점의 server rendering을 호출하지 않고, cache된 상품 상세와 static Add to cart fallback을 포함합니다. 현재 cart 상태는 사용자가 link를 따라간 뒤에 render됩니다.

Each product prefetch now includes the cached product details and the static Add to cart fallback without invoking request-time server rendering. The current cart status renders after the user follows the link.

ensureStatic 값은 그것을 export한 segment 위의 layout까지 포함해 route 전체에 적용됩니다. 상품 route에서 'prefetch'는 per-link prefetch 동안 store layout도 static으로 유지합니다.

An ensureStatic value covers the whole route, including layouts above the segment that exports it. On product routes, 'prefetch' also keeps the store layout static through the per-link prefetch.

Good to know

per-link prefetch에서 ProductCartStatus만 미뤄야 했다면 cookie를 읽기 전에 await navigation()을 호출할 수 있습니다. 여기서는 모든 상품 prefetch가 request 시점의 server rendering을 피해야 하므로, page에서 ensureStatic = 'prefetch'를 사용합니다.

If only ProductCartStatus needed to be deferred from per-link prefetches, you could call await navigation() before reading the cookie. Here, every product prefetch must avoid request-time server rendering, so the page uses ensureStatic = 'prefetch'.

Step 3: Prerender the buying guides3단계: 구매 가이드 prerender하기

store에는 공개 구매 가이드도 있습니다. 각 가이드는 database에서 콘텐츠를 읽고 cookie에서 theme을 적용합니다:

The store also has public buying guides. Each guide reads its content from the database and applies a theme from a cookie:

TSapp/guides/[id]/page.tsx
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { getGuide } from '@/lib/guides'

export default function GuidePage({ params }: PageProps<'/guides/[id]'>) {
  return (
    <Suspense fallback={<p>Loading guide...</p>}>
      <Guide params={params} />
    </Suspense>
  )
}

async function Guide({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const guide = await getGuide(id)
  const theme = (await cookies()).get('theme')?.value
  return <article data-theme={theme}>{guide.content}</article>
}

기존 getGuide() helper가 database query를 수행합니다:

The existing getGuide() helper performs the database query:

TSlib/guides.ts
import { db } from '@/lib/db'

export async function getGuide(id: string) {
  return db.guide.findUniqueOrThrow({ where: { id } })
}

generateStaticParams()를 export하고 구매 가이드 ID를 하나 이상 반환하세요. Next.js는 반환된 ID를 build 중에 prerender합니다. 허용된 다른 ID는 첫 request 때 생성하고 그 결과를 이후 request를 위해 저장할 수 있습니다. 'navigation'에서는 그 첫 request가 fallback을 streaming하는 대신 완전한 static 페이지를 기다립니다. ISR with Cache Components를 참고하세요.

Export generateStaticParams() and return at least one buying guide ID. Next.js prerenders the returned IDs during the build. It can generate other allowed IDs on their first request and store the result for later requests. With 'navigation', that first request waits for the complete static page instead of streaming a fallback. See ISR with Cache Components.

prerender할 가이드 ID를 반환하는 helper를 추가하세요:

export async function generateStaticParams() {
  const ids = await getGuideIds()
  return ids.map((id) => ({ id }))

The listed guide is now fully prerendered. For an unlisted guide ID, the first request waits while Next.js generates and stores the complete static page. The buying guides no longer perform request-time server rendering, and ensureStatic will report future changes that would break that requirement.

이제 store는 static App Shell에서 공유 navigation을 load하고, server를 호출하지 않고 per-link prefetch에 cache된 상품 상세를 포함하며, 구매 가이드에 대해 완전한 static 출력을 반환합니다. 개인화된 cart 데이터는 필요할 때 여전히 render됩니다.

The store now loads shared navigation from its static App Shell, includes cached product details in per-link prefetches without invoking the server, and returns complete static output for buying guides. Personalized cart data still renders when it is needed.

  • Migrate to Cache Components: 기존 앱에서 dynamic = 'force-static' 같은 route 수준 config를 대체합니다.
  • Optimize prefetching to control when individual subtrees render.
  • Ensure instant navigations to validate that client navigations into the store show UI immediately.
  • Migrate to Cache Components to replace route-level configs such as dynamic = 'force-static' in an existing app.
