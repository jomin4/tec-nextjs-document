TurbopackTurbopack

Turbopack은 Rust로 작성되고 Next.js에 내장된, JavaScript와 TypeScript에 최적화된 incremental bundler입니다. Pages Router와 App Router 모두에서 Turbopack을 사용해 훨씬 빠른 로컬 개발 경험을 얻을 수 있습니다.

Turbopack is an incremental bundler optimized for JavaScript and TypeScript, written in Rust, and built into Next.js. You can use Turbopack with both the Pages and App Router for a much faster local development experience.

Why Turbopack?왜 Turbopack인가?

저희는 다음과 같은 부분에서 Next.js의 성능을 끌어올리기 위해 Turbopack을 만들었습니다:

We built Turbopack to push the performance of Next.js, including:

  • Unified Graph: Next.js는 여러 output environment(예: client와 server)를 지원합니다. 여러 compiler를 관리하고 bundle을 이어 붙이는 일은 번거로울 수 있습니다. Turbopack은 모든 environment에 대해 하나의 통합된 graph를 사용합니다.
  • Bundling vs Native ESM: 일부 도구는 development에서 bundling을 건너뛰고 브라우저의 native ESM에 의존합니다. 이 방식은 작은 앱에서는 잘 동작하지만, 큰 앱에서는 과도한 network request 때문에 느려질 수 있습니다. Turbopack은 dev에서도 bundling을 하지만, 큰 앱도 빠르게 유지되도록 최적화된 방식으로 합니다.
  • Incremental Computation: Turbopack은 작업을 여러 core에 걸쳐 병렬로 처리하고 결과를 function 수준까지 cache합니다. 한 번 끝난 작업은 다시 반복하지 않습니다. 결과는 실행 사이에도 disk에 유지됩니다.
  • Lazy Bundling: Turbopack은 dev server가 실제로 요청한 것만 bundling합니다. 이 lazy 방식은 초기 compile 시간과 memory 사용량을 줄여 줄 수 있습니다.
  • Unified Graph: Next.js supports multiple output environments (e.g., client and server). Managing multiple compilers and stitching bundles together can be tedious. Turbopack uses a single, unified graph for all environments.
  • Bundling vs Native ESM: Some tools skip bundling in development and rely on the browser's native ESM. This works well for small apps but can slow down large apps due to excessive network requests. Turbopack bundles in dev, but in an optimized way to keep large apps fast.
  • Incremental Computation: Turbopack parallelizes work across cores and caches results down to the function level. Once a piece of work is done, Turbopack won’t repeat it. Results persist to disk between runs.
  • Lazy Bundling: Turbopack only bundles what is actually requested by the dev server. This lazy approach can reduce initial compile times and memory usage.

On platforms without native bindings (e.g. FreeBSD, OpenBSD), Next.js falls back to WebAssembly (WASM) bindings. WASM bindings support core SWC features like compilation and minification, but do not support Turbopack. On these platforms, use the --webpack flag:

next dev --webpack
next build --webpack

Getting started시작하기

이제 Turbopack은 Next.js의 기본 bundler입니다. Turbopack을 사용하는 데 별도 설정은 필요 없습니다:

Turbopack is now the default bundler in Next.js. No configuration is needed to use Turbopack:

package.json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start"
  }
}

Using Webpack instead대신 Webpack 사용하기

Turbopack 대신 Webpack을 사용해야 한다면 --webpack flag로 opt-in할 수 있습니다:

If you need to use Webpack instead of Turbopack, you can opt-in with the --webpack flag:

package.json
{
  "scripts": {
    "dev": "next dev --webpack",
    "build": "next build --webpack",
    "start": "next start"
  }
}

Good to know

import.meta.env는 Turbopack이 필요합니다. custom VITE_* 변수, Vite custom mode, envPrefix, envDir는 지원되지 않습니다. BASE_URL은 Next.js basePath 설정을 반영하며, Vite 형식에 맞추기 위해 끝에 slash를 포함합니다.

import.meta.glob

Turbopack은 glob pattern을 사용해 여러 module을 한 번에 import하는 Vite 호환 API인 import.meta.glob()을 지원합니다. 결과는 호출한 파일을 기준으로 한 파일 경로를 key로 하는 object입니다.

Turbopack supports import.meta.glob(), a Vite-compatible API for importing multiple modules at once using glob patterns. The result is an object keyed by the file path relative to the calling file.

const modules = import.meta.glob('./dir/*.js')
// {
//   './dir/foo.js': () => import('./dir/foo.js'),
//   './dir/bar.js': () => import('./dir/bar.js'),
// }
Good to know

import.meta.glob은 Turbopack이 필요합니다. webpack을 사용할 때는 사용할 수 없습니다.

import.meta.glob requires Turbopack. It is not available when using webpack.

Patterns패턴

pattern은 import하는 파일 기준의 상대 경로(./, ../)이거나 프로젝트 root 기준의 절대 경로(/)입니다:

A pattern is either relative to the importing file (./, ../) or absolute from the project root (/):

// Relative to the importing file
const siblings = import.meta.glob('./dir/*.js')
const parent = import.meta.glob('../docs/*.js')

// Absolute from the project root
const content = import.meta.glob('/content/*.md')

결과의 key는 pattern을 따릅니다: 상대 pattern은 상대 key('./dir/foo.js', '../docs/intro.js')를, 프로젝트 root 기준 절대 pattern은 프로젝트 root 기준 절대 key('/content/alpha.md')를 만듭니다.

The keys of the result follow the pattern: relative patterns produce relative keys ('./dir/foo.js', '../docs/intro.js'), project-root-absolute patterns produce project-root-absolute keys ('/content/alpha.md').

node_modules도 다른 폴더와 똑같이 매칭되므로, import.meta.glob('/**/*.js') 같은 넓은 pattern은 dependency까지 탐색해서 몇 초가 걸릴 수 있습니다. pattern을 좁히거나, 필요 없는 것은 negative pattern으로 제외하세요. build output 폴더(.next)는 절대 탐색되지 않습니다.

node_modules is matched like any other directory, so a broad pattern such as import.meta.glob('/**/*.js') walks your dependencies as well and can take seconds. Narrow the pattern, or exclude what you don't need with a negative pattern. The build output directory (.next) is never traversed.

key는 항상 정렬되며, development와 production에서 결정적이고 동일하게 정렬됩니다. 정렬은 key의 bytewise 비교이므로 자연스러운 순서나 표시용 순서가 아닙니다. '10-ten.js'가 '2-two.js'보다 앞에 오고, 대문자가 _보다, _가 소문자보다 앞에 오며, 하위 폴더의 파일은 그룹으로 묶이지 않고 형제 파일들 사이에 섞여 정렬됩니다. 여러 pattern은 pattern 순서대로 이어 붙여지는 것이 아니라 하나의 정렬된 object로 병합됩니다.

The keys are always sorted, deterministically and identically in development and production. The sort is a bytewise comparison of the key, so it is not a natural or display order — '10-ten.js' sorts before '2-two.js', uppercase before _ before lowercase, and files in subdirectories are interleaved with their siblings rather than grouped. Multiple patterns are merged into a single sorted object, not concatenated in pattern order.

Lazy loading (default)Lazy loading (기본값)

기본적으로 결과 object의 각 값은 thunk, 즉 module에 대한 Promise를 반환하는 함수입니다. 이를 통해 lazy loading이 가능합니다:

By default, each value in the result object is a thunk — a function that returns a Promise for the module. This enables lazy loading:

const modules = import.meta.glob('./dir/*.js')

for (const path in modules) {
  const module = await modules[path]()
  console.log(path, module)
}

Eager loading

매칭되는 모든 module을 미리 import하려면 { eager: true }를 전달하세요. 각 값은 thunk가 아니라 module object 자체가 됩니다:

Pass { eager: true } to import all matching modules up front. Each value is the module object directly instead of a thunk:

const modules = import.meta.glob('./dir/*.js', { eager: true })

for (const path in modules) {
  console.log(path, modules[path].default)
}

Named imports

매칭된 각 module에서 특정 named export를 선택하려면 import option을 사용하세요. lazy mode와 eager mode 모두에서 동작합니다:

Use the import option to select a specific named export from each matched module. This works in both lazy and eager modes:

// Lazy: each value is () => Promise<exportValue>
const defaults = import.meta.glob('./dir/*.js', { import: 'default' })

// Eager: each value is the export value directly
const setups = import.meta.glob('./dir/*.js', { import: 'setup', eager: true })

Query strings

모든 import request에 query string을 붙이려면 query option을 사용하세요:

Use the query option to append a query string to every import request:

const rawFiles = import.meta.glob('./dir/*.txt', { query: '?raw' })

query option은 object도 받습니다. key와 value는 URL-encode된 뒤 query string으로 합쳐집니다:

The query option also accepts an object. Keys and values are URL-encoded and joined into a query string:

const modules = import.meta.glob('./*.ts', {
  query: { bar: 'foo', raw: true },
})
// equivalent to: { query: '?bar=foo&raw=true' }

query는 module rule로 그대로 전달될 뿐, 그 자체로는 아무 의미가 없습니다. Vite와 달리 Turbopack에는 ?raw나 ?url을 처리하는 내장 기능이 없으므로, rule로 query를 매칭해 해당 파일을 어떻게 load할지 정하세요:

The query is passed through to the module rules, it has no meaning on its own. Unlike Vite, Turbopack has no built-in ?raw or ?url handling, so match the query with a rule to decide how those files are loaded:

TSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  turbopack: {
    rules: {
      // `import.meta.glob('./dir/*.txt', { query: '?raw' })` returns the file contents as strings
      '*.txt': { condition: { query: '?raw' }, type: 'text' },
    },
  },
}

export default nextConfig

Multiple patterns and negation여러 패턴과 부정

첫 번째 인자로 glob pattern 배열을 전달하세요. 매칭되는 파일을 제외하려면 pattern 앞에 !를 붙이세요:

Pass an array of glob patterns as the first argument. Prefix a pattern with ! to exclude matching files:

// Combine multiple directories
const modules = import.meta.glob(['./dir/*.js', './other/*.js'])

// Exclude specific files
const withoutTests = import.meta.glob(['./src/**/*.js', '!**/*.test.js'])

Base path

다른 폴더를 기준으로 pattern을 해석하려면 base option을 사용하세요. 그러면 결과의 key는 import하는 파일이 아니라 base를 기준으로 한 상대 경로가 됩니다:

Use the base option to resolve the patterns against a different directory. The keys of the result are then relative to base rather than to the importing file:

const modules = import.meta.glob('*.md', { base: '../../content' })
// {
//   './alpha.md': () => import('../../content/alpha.md'),
//   './nested/deep.md': () => import('../../content/nested/deep.md'),

TypeScript

import.meta.glob의 TypeScript type은 Next.js에 포함되어 있습니다. tsconfig.json에 "moduleResolution": "bundler"(또는 "node16" / "nodenext")가 설정되어 있으면 자동으로 사용할 수 있으며, 이는 새 Next.js 프로젝트의 기본값입니다.

TypeScript types for import.meta.glob are included in Next.js. They are available automatically when "moduleResolution": "bundler" (or "node16" / "nodenext") is set in your tsconfig.json, which is the default for new Next.js projects.

반환 type은 eager option에 따라 다릅니다:

The return type differs based on the eager option:

// Lazy (default) — Record<string, () => Promise<unknown>>
const lazy = import.meta.glob('./dir/*.ts')

// Eager — Record<string, unknown>
const eager = import.meta.glob('./dir/*.ts', { eager: true })

매칭된 파일이 export하는 내용을 설명하려면 module type을 전달하세요:

Pass the module type to describe what the matched files export:

interface Mod {
  name: string
  default: () => string
}

// Record<string, () => Promise<Mod>>
const lazy = import.meta.glob<Mod>('./dir/*.ts')

// Record<string, Mod>
const eager = import.meta.glob<Mod>('./dir/*.ts', { eager: true })

Known gaps with webpackwebpack과의 알려진 차이

webpack과 Turbopack 사이에는 애플리케이션을 migration할 때 알아 두어야 할 사소하지 않은 동작 차이가 여럿 있습니다. 일반적으로 새 애플리케이션에서는 크게 신경 쓸 부분이 아닙니다.

There are a number of non-trivial behavior differences between webpack and Turbopack that are important to be aware of when migrating an application. Generally, these are less of a concern for new applications.

Filesystem Root

Turbopack은 module을 해석할 때 root 폴더를 사용합니다. 프로젝트 root 밖에 있는 파일은 해석되지 않습니다.

Turbopack uses the root directory to resolve modules. Files outside of the project root are not resolved.

예를 들어 프로젝트 root 밖에 있는 linked dependency(npm link, yarn link, pnpm link 등으로 연결한 것)는 기본적으로 해석되지 않습니다. symlink된 dependency에는 experimental.turbopackAdditionalRoots를 설정하세요.

For example, linked dependencies outside the project root (via npm link, yarn link, pnpm link, etc.) are not resolved by default. Configure experimental.turbopackAdditionalRoots for symlinked dependencies.

애플리케이션이 symlink를 통하지 않고 감지된 root 밖의 파일을 직접 import한다면 turbopack.root를 사용하세요.

Use turbopack.root when your application directly imports files outside the detected root rather than reaching them through symlinks.

CSS Module OrderingCSS Module 순서

Turbopack은 달리 순서가 정해지지 않은 CSS modules의 순서를 JS import 순서에 따라 정합니다. 예를 들면:

Turbopack will follow JS import order to order CSS modules which are not otherwise ordered. For example:

JScomponents/BlogPost.jsx
import utilStyles from './utils.module.css'
import buttonStyles from './button.module.css'
export default function BlogPost() {
  return (
    <div className={utilStyles.container}>
      <button className={buttonStyles.primary}>Click me</button>
    </div>
  )
}

이 예시에서 Turbopack은 import 순서에 따라, 생성된 CSS chunk에서 utils.module.css가 button.module.css보다 앞에 오도록 보장합니다

In this example, Turbopack will ensure that utils.module.css will appear before button.module.css in the produced CSS chunk, following the import order

Webpack도 일반적으로 이렇게 하지만, 예를 들어 JS 파일이 side-effect-free라고 추론하는 경우처럼 JS에서 추론한 순서를 무시하는 경우가 있습니다.

Webpack generally does this as well, but there are cases where it will ignore JS inferred ordering, for example if it infers the JS file is side-effect-free.

애플리케이션이 임의의 순서에 의존하게 되었다면, Turbopack을 도입할 때 미묘한 rendering 변화가 생길 수 있습니다. 일반적으로 해결 방법은 간단합니다. 예를 들어 button.module.css에서 @import utils.module.css를 해서 순서를 강제하거나, 충돌하는 rule을 찾아 같은 property를 target으로 하지 않도록 바꾸면 됩니다.

This can lead to subtle rendering changes when adopting Turbopack, if applications have come to rely on an arbitrary ordering. Generally, the solution is easy, e.g. have button.module.css @import utils.module.css to force the ordering, or identify the conflicting rules and change them to not target the same properties.

Sass node_modules importsSass node_modules import

Turbopack은 node_modules의 Sass 파일 import를 기본으로 지원합니다. Webpack은 이를 위해 legacy tilde ~ 문법을 지원하지만, Turbopack은 이 문법을 지원하지 않습니다.

Turbopack supports importing node_modules Sass files out of the box. Webpack supports a legacy tilde ~ syntax for this, which is not supported by Turbopack.

변경 전:

From:

styles/globals.scss
@import '~bootstrap/dist/css/bootstrap.min.css';

변경 후:

To:

styles/globals.scss
@import 'bootstrap/dist/css/bootstrap.min.css';

import를 수정할 수 없다면 turbopack.resolveAlias 설정을 추가해 ~ 문법을 실제 경로에 매핑할 수 있습니다:

If you can't update the imports, you can add a turbopack.resolveAlias configuration to map the ~ syntax to the actual path:

JSnext.config.js
module.exports = {
  turbopack: {
    resolveAlias: {
      '~*': '*',
    },
  },
}

CSS / Sass / SCSS decimal precisionCSS / Sass / SCSS 소수점 정밀도

Turbopack은 CSS를 compile하는 데 Lightning CSS를 사용합니다. Lightning CSS는 숫자 CSS 값에 소수점 5자리 정밀도를 사용하는 반면, webpack은 10자리를 사용합니다. 이는 일반 CSS와 Sass/SCSS output 모두에 적용됩니다. 예를 들어 25/17로 계산되는 값은 다음과 같이 출력됩니다:

Turbopack uses Lightning CSS to compile CSS. Lightning CSS uses 5 digits of decimal precision for numeric CSS values, while webpack uses 10 digits. This applies to both plain CSS and Sass/SCSS output. For example, a value that evaluates to 25/17 produces:

  • Webpack: line-height: 1.4705882353 (10자리)
  • Turbopack: line-height: 1.47059 (5자리)
  • Webpack: line-height: 1.4705882353 (10 digits)
  • Turbopack: line-height: 1.47059 (5 digits)

이 때문에 webpack에서 Turbopack으로 migration할 때, 특히 line-height, letter-spacing 등 높은 정밀도가 중요한 계산 값에서 미묘한 rendering 차이가 생길 수 있습니다.

This can lead to subtle rendering differences when migrating from webpack to Turbopack, especially for properties like line-height, letter-spacing, or other calculated values where high precision matters.

Webpack plugins

Turbopack은 webpack plugin을 지원하지 않습니다. 이는 통합을 위해 webpack의 plugin 시스템에 의존하는 third-party 도구에 영향을 줍니다. webpack loaders는 지원합니다. webpack plugin에 의존하고 있다면 Turbopack 호환 대안을 찾거나, 동등한 기능이 제공될 때까지 webpack을 계속 사용해야 합니다.

Turbopack does not support webpack plugins. This affects third-party tools that rely on webpack's plugin system for integration. We do support webpack loaders. If you depend on webpack plugins, you'll need to find Turbopack-compatible alternatives or continue using webpack until equivalent functionality is available.

  • next.config.js의 webpack() configuration Turbopack은 webpack을 대체하므로 webpack() config는 인식되지 않습니다. 대신 turbopack config를 사용하세요.
  • Yarn PnP Next.js에서 Turbopack 지원 계획이 없습니다.
  • experimental.urlImports Turbopack에서 지원 계획이 없습니다.
  • experimental.esmExternals 계획에 없습니다. Turbopack은 Next.js의 legacy esmExternals 설정을 지원하지 않습니다.
  • 일부 Next.js Experimental Flag
    • experimental.nextScriptWorkers
    • experimental.fallbackNodePolyfills 앞으로 구현할 계획입니다.
  • Legacy CSS Modules features
    • Standalone :local and :global pseudo-classes (only the function variant :global(...) is supported).
    • The @value rule (superseded by CSS variables).
    • :import and :export ICSS rules.
    • composes in .module.css composing a .css file. In webpack this would treat the .css file as a CSS Module, with Turbopack the .css file will always be global. This means that if you want to use composes in a CSS Module, you need to change the .css file to a .module.css file.
    • @import in CSS Modules importing .css as a CSS Module. In webpack this would treat the .css file as a CSS Module, with Turbopack the .css file will always be global. This means that if you want to use @import in a CSS Module, you need to change the .css file to a .module.css file.

If you're using custom Sass functions, you'll need to use webpack instead of Turbopack.
  • webpack() configuration in next.config.js Turbopack replaces webpack, so webpack() configs are not recognized. Use the turbopack config instead.
  • Yarn PnP Not planned for Turbopack support in Next.js.
  • experimental.urlImports Not planned for Turbopack.

  • Some Next.js Experimental Flags

    • experimental.fallbackNodePolyfills We plan to implement these in the future.

Generating trace files for performance debugging성능 디버깅을 위한 trace 파일 생성

성능이나 memory 문제가 발생해 Next.js 팀이 진단하도록 돕고 싶다면, dev 명령에 --internal-trace flag를 추가해 trace 파일을 생성할 수 있습니다:

If you encounter performance or memory issues and want to help the Next.js team diagnose them, you can generate a trace file by adding the --internal-trace flag to your dev command:

next dev --internal-trace

이렇게 하면 .next-profiles/trace-turbopack.bin 파일이 생성됩니다. 조사에 도움이 되도록 Next.js repo에 GitHub issue를 만들 때 이 파일을 첨부해 주세요.

This will produce a .next-profiles/trace-turbopack.bin file. Include that file when creating a GitHub issue on the Next.js repo to help us investigate.

Summary요약

Turbopack은 local development와 build를, 특히 큰 애플리케이션에서 빠르게 만들기 위해 설계된 Rust 기반의 incremental bundler입니다. Next.js에 통합되어 있으며, 설정 없이 CSS, React, TypeScript를 지원합니다.

Turbopack is a Rust-based, incremental bundler designed to make local development and builds fast—especially for large applications. It is integrated into Next.js, offering zero-config CSS, React, and TypeScript support.
