updateTagupdateTag

updateTag를 사용하면 Server Actions 안에서 특정 cache tag에 해당하는 cached data를 on-demand로 업데이트할 수 있습니다.

updateTag allows you to update cached data on-demand for a specific cache tag from within Server Actions.

이 함수는 read-your-own-writes 시나리오를 위해 설계되었습니다. 즉, 사용자가 변경(예: 글 작성)을 하면 UI가 stale data 대신 그 변경 사항을 즉시 보여 주는 경우입니다.

This function is designed for read-your-own-writes scenarios, where a user makes a change (like creating a post), and the UI immediately shows the change, rather than stale data.

Usage사용법

updateTag는 Server Actions 안에서만 호출할 수 있습니다. Route Handler, Client Component, 그 밖의 어떤 context에서도 사용할 수 없습니다.

updateTag can only be called from within Server Actions. It cannot be used in Route Handlers, Client Components, or any other context.

Route Handler나 다른 context에서 cache tag를 무효화해야 한다면 대신 revalidateTag를 사용하세요.

If you need to invalidate cache tags in Route Handlers or other contexts, use revalidateTag instead.

Good to know

updateTag는 지정한 tag의 cached data를 즉시 만료시킵니다. 다음 request는 cache에서 stale content를 제공하는 대신 새 data를 fetch할 때까지 기다리므로, 사용자는 자신의 변경 사항을 즉시 보게 됩니다.

updateTag immediately expires the cached data for the specified tag. The next request will wait to fetch fresh data rather than serving stale content from the cache, ensuring users see their changes immediately.

Parameters

updateTag(tag: string): void;
  • tag: 업데이트하려는 data에 연결된 cache tag를 나타내는 string입니다. 256자를 넘으면 안 됩니다. 이 값은 대소문자를 구분합니다.
  • tag: A string representing the cache tag associated with the data you want to update. Must not exceed 256 characters. This value is case-sensitive.

tag는 먼저 cached data에 할당되어 있어야 합니다. 두 가지 방법이 있습니다:

Tags must first be assigned to cached data. You can do this in two ways:

  • 외부 API request를 caching할 때 fetch의 next.tags option 사용:
  • Using the next.tags option with fetch for caching external API requests:
fetch(url, { next: { tags: ['posts'] } })
  • 'use cache' directive가 있는 cached function이나 component 안에서 cacheTag 사용:
  • Using cacheTag inside cached functions or components with the 'use cache' directive:
import { cacheTag } from 'next/cache'

async function getData() {
  'use cache'
  cacheTag('posts')
  // ...
}

Returns

updateTag는 값을 반환하지 않습니다.

updateTag does not return a value.

Differences from revalidateTagrevalidateTag와의 차이점

updateTag와 revalidateTag는 둘 다 cached data를 무효화하지만, 목적이 다릅니다:

While both updateTag and revalidateTag invalidate cached data, they serve different purposes:

  • updateTag:
    • Server Action에서만 사용 가능
    • 다음 request는 새 data를 기다림 (stale content를 제공하지 않음)
    • read-your-own-writes 시나리오를 위해 설계됨
  • revalidateTag:
    • Server Action과 Route Handler에서 사용 가능
    • profile="max" 사용 시 (권장): background에서 새 data를 fetch하는 동안 cached data를 제공 (stale-while-revalidate)
    • custom profile 사용 시: 고급 사용을 위해 어떤 cache life profile로든 설정 가능
    • profile 없이 사용 시: updateTag와 동일한 legacy 동작
  • updateTag:
    • Can only be used in Server Actions
    • Next request waits for fresh data (no stale content served)
    • Designed for read-your-own-writes scenarios
  • revalidateTag:
    • Can be used in Server Actions and Route Handlers
    • With profile="max" (recommended): Serves cached data while fetching fresh data in the background (stale-while-revalidate)
    • With custom profile: Can be configured to any cache life profile for advanced usage
    • Without profile: legacy behavior which is equivalent to updateTag

Examples예시

Server Action with Read-Your-Own-WritesRead-Your-Own-Writes를 사용하는 Server Action

TSJSapp/actions.ts
'use server'

import { updateTag } from 'next/cache'
import { redirect } from 'next/navigation'

export async function createPost(formData: FormData) {
  const title = formData.get('title')
  const content = formData.get('content')

  // Create the post in your database
  const post = await db.post.create({
    data: { title, content },
  })

  // Invalidate cache tags so the new post is immediately visible
  // 'posts' tag: affects any page that displays a list of posts
  updateTag('posts')
  // 'post-{id}' tag: affects the individual post detail page
  updateTag(`post-${post.id}`)

  // Redirect to the new post - user will see fresh data, not cached
  redirect(`/posts/${post.id}`)
}

Error when used outside Server ActionsServer Action 밖에서 사용할 때의 error

TSapp/api/posts/route.ts
import { revalidateTag, updateTag } from 'next/cache'

export async function POST() {
  // This will throw an error
  updateTag('posts')
  // Error: updateTag can only be called from within a Server Action

  // Use revalidateTag instead in Route Handlers
  revalidateTag('posts', 'max')
}

When to use updateTagupdateTag를 사용해야 할 때

다음과 같은 경우 updateTag를 사용하세요:

Use updateTag when:

  • Server Action 안에 있을 때
  • read-your-own-writes를 위해 즉각적인 cache invalidation이 필요할 때
  • 다음 request가 업데이트된 data를 보도록 보장하고 싶을 때
  • You're in a Server Action
  • You need immediate cache invalidation for read-your-own-writes
  • You want to ensure the next request sees updated data

다음과 같은 경우에는 대신 revalidateTag를 사용하세요:

Use revalidateTag instead when:

  • Route Handler나 action이 아닌 다른 context에 있을 때
  • stale-while-revalidate semantics를 원할 때
  • cache invalidation을 위한 webhook이나 API endpoint를 만들 때
  • You're in a Route Handler or other non-action context
  • You want stale-while-revalidate semantics
  • You're building a webhook or API endpoint for cache invalidation

Related관련 항목

  • revalidateTag - Route Handler에서 tag를 무효화할 때
  • revalidatePath - 특정 경로를 무효화할 때
  • revalidateTag - For invalidating tags in Route Handlers
  • revalidatePath - For invalidating specific paths
