How to configure PostCSS in Next.jsNext.js에서 PostCSS 설정하기

Default Behavior기본 동작

Next.js는 built-in CSS support를 위해 PostCSS로 CSS를 compile합니다.

Next.js compiles CSS for its built-in CSS support using PostCSS.

별도 configuration 없이도 Next.js는 다음과 같은 변환을 적용해 CSS를 compile합니다:

Out of the box, with no configuration, Next.js compiles CSS with the following transformations:

  • Autoprefixer가 CSS rule에 vendor prefix를 자동으로 추가합니다(IE11까지).
  • Cross-browser Flexbox bug를 수정해 spec대로 동작하게 합니다.
  • 새로운 CSS 기능을 Internet Explorer 11 호환성을 위해 자동으로 compile합니다:
    • all Property
    • Break Properties
    • font-variant Property
    • Gap Properties
    • Media Query Ranges
  • Autoprefixer automatically adds vendor prefixes to CSS rules (back to IE11).
  • Cross-browser Flexbox bugs are corrected to behave like the spec.
  • New CSS features are automatically compiled for Internet Explorer 11 compatibility:
    • all Property
    • Break Properties
    • font-variant Property
    • Gap Properties
    • Media Query Ranges

기본적으로 CSS Grid와 Custom Properties(CSS 변수)는 IE11 지원을 위해 compile되지 않습니다.

By default, CSS Grid and Custom Properties (CSS variables) are not compiled for IE11 support.

IE11용으로 CSS Grid Layout을 compile하려면 CSS 파일 맨 위에 다음 주석을 넣으면 됩니다:

To compile CSS Grid Layout for IE11, you can place the following comment at the top of your CSS file:

/* autoprefixer grid: autoplace */

아래(접힌 부분)에 있는 configuration으로 autoprefixer를 설정하면 프로젝트 전체에서 CSS Grid Layout의 IE11 지원을 활성화할 수도 있습니다. 자세한 내용은 아래 "Customizing Plugins"를 참고하세요.

You can also enable IE11 support for CSS Grid Layout in your entire project by configuring autoprefixer with the configuration shown below (collapsed). See "Customizing Plugins" below for more information.

CSS Grid Layout을 활성화하는 configuration 보기
postcss.config.json
{
  "plugins": [
    "postcss-flexbugs-fixes",
    [
      "postcss-preset-env",
      {
        "autoprefixer": {
          "flexbox": "no-2009",
          "grid": "autoplace"
        },
        "stage": 3,
        "features": {
          "custom-properties": false
        }
      }
    ]
  ]
}

CSS 변수는 안전하게 compile하는 것이 불가능하기 때문에 compile되지 않습니다. 꼭 변수를 사용해야 한다면 Sass가 compile 과정에서 제거해 주는 Sass variables 같은 것을 사용하는 것을 고려해 보세요.

CSS variables are not compiled because it is not possible to safely do so. If you must use variables, consider using something like Sass variables which are compiled away by Sass.

Customizing Target BrowsersTarget 브라우저 커스터마이징

Next.js에서는 Browserslist를 통해 (Autoprefixer와 compile되는 CSS 기능의) target 브라우저를 설정할 수 있습니다.

Next.js allows you to configure the target browsers (for Autoprefixer and compiled css features) through Browserslist.

browserslist를 커스터마이징하려면 package.json에 다음과 같이 browserslist key를 만드세요:

To customize browserslist, create a browserslist key in your package.json like so:

package.json
{
  "browserslist": [">0.3%", "not dead", "not op_mini all"]
}

browsersl.ist 도구를 사용하면 어떤 브라우저를 target으로 하고 있는지 시각적으로 확인할 수 있습니다.

You can use the browsersl.ist tool to visualize what browsers you are targeting.

CSS Modules

CSS Modules를 지원하는 데 별도 configuration은 필요 없습니다. 파일에 CSS Modules를 활성화하려면 파일 확장자를 .module.css로 바꾸세요.

No configuration is needed to support CSS Modules. To enable CSS Modules for a file, rename the file to have the extension .module.css.

Next.js의 CSS Module 지원에 대해 여기서 더 알아볼 수 있습니다.

You can learn more about Next.js' CSS Module support here.

Customizing PluginsPlugin 커스터마이징

Warning

custom PostCSS configuration 파일을 정의하면 Next.js는 기본 동작을 완전히 비활성화합니다. Autoprefixer를 포함해 compile에 필요한 모든 기능을 직접 설정해야 합니다. custom configuration에 포함된 plugin도 모두 직접 설치해야 합니다. 예: npm install postcss-flexbugs-fixes postcss-preset-env.

When you define a custom PostCSS configuration file, Next.js completely disables the default behavior. Be sure to manually configure all the features you need compiled, including Autoprefixer. You also need to install any plugins included in your custom configuration manually, i.e. npm install postcss-flexbugs-fixes postcss-preset-env.

PostCSS configuration을 커스터마이징하려면 프로젝트 root에 postcss.config.json 파일을 만드세요.

To customize the PostCSS configuration, create a postcss.config.json file in the root of your project.

다음은 Next.js가 사용하는 기본 configuration입니다:

This is the default configuration used by Next.js:

postcss.config.json
{
  "plugins": [
    "postcss-flexbugs-fixes",
    [
      "postcss-preset-env",
      {
        "autoprefixer": {
          "flexbox": "no-2009"
        },
        "stage": 3,
        "features": {
          "custom-properties": false
        }
      }
    ]
  ]
}
Good to know

Next.js에서는 파일 이름을 .postcssrc.json으로 하거나, package.json의 postcss key에서 읽게 할 수도 있습니다.

Next.js also allows the file to be named .postcssrc.json, or, to be read from the postcss key in package.json.

postcss.config.js 파일로 PostCSS를 설정할 수도 있으며, environment에 따라 조건부로 plugin을 포함하고 싶을 때 유용합니다:

It is also possible to configure PostCSS with a postcss.config.js file, which is useful when you want to conditionally include plugins based on environment:

JSpostcss.config.js
module.exports = {
  plugins:
    process.env.NODE_ENV === 'production'
      ? [
          'postcss-flexbugs-fixes',
          [
            'postcss-preset-env',
            {
              autoprefixer: {
                flexbox: 'no-2009',
              },
              stage: 3,
              features: {
                'custom-properties': false,
              },
            },
          ],
        ]
      : [
          // No transformations in development
        ],
}
Good to know

Next.js에서는 파일 이름을 .postcssrc.js로 할 수도 있습니다.

Next.js also allows the file to be named .postcssrc.js.

PostCSS Plugin을 import할 때 require()를 사용하지 마세요. plugin은 문자열로 제공해야 합니다.

Do not use require() to import the PostCSS Plugins. Plugins must be provided as strings.

Good to know

같은 프로젝트에서 postcss.config.js가 Next.js가 아닌 다른 도구도 지원해야 한다면, 대신 상호 호환되는 object 기반 형식을 사용해야 합니다:

module.exports = {
  plugins: {
    'postcss-flexbugs-fixes': {},
    'postcss-preset-env': {
      autoprefixer: {
        flexbox: 'no-2009',
      },
      stage: 3,
      features: {
        'custom-properties': false,
      },
    },
  },
}

If your postcss.config.js needs to support other non-Next.js tools in the same project, you must use the interoperable object-based format instead:

module.exports = {
  plugins: {
    'postcss-flexbugs-fixes': {},
    'postcss-preset-env': {
      autoprefixer: {
        flexbox: 'no-2009',
      },
      stage: 3,
      features: {
        'custom-properties': false,
      },
    },
  },
}
