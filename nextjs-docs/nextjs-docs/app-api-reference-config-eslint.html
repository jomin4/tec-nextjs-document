ESLint PluginESLint 플러그인

Next.js는 애플리케이션에서 흔히 발생하는 이슈를 쉽게 잡아낼 수 있도록 ESLint configuration package인 eslint-config-next를 제공합니다. 여기에는 @next/eslint-plugin-next plugin과 함께 eslint-plugin-react, eslint-plugin-react-hooks의 권장 rule-set이 포함되어 있습니다.

Next.js provides an ESLint configuration package, eslint-config-next, that makes it easy to catch common issues in your application. It includes the @next/eslint-plugin-next plugin along with recommended rule-sets from eslint-plugin-react and eslint-plugin-react-hooks.

이 package는 두 가지 주요 configuration을 제공합니다:

The package provides two main configurations:

  • eslint-config-next: Next.js, React, React Hooks rule이 들어간 기본 configuration입니다. JavaScript와 TypeScript 파일을 모두 지원합니다.
  • eslint-config-next/core-web-vitals: 기본 config의 모든 내용을 포함하며, Core Web Vitals에 영향을 주는 rule을 warning에서 error로 격상합니다. 대부분의 프로젝트에 권장됩니다.
  • eslint-config-next: Base configuration with Next.js, React, and React Hooks rules. Supports both JavaScript and TypeScript files.
  • eslint-config-next/core-web-vitals: Includes everything from the base config, plus upgrades rules that impact Core Web Vitals from warnings to errors. Recommended for most projects.

또한 TypeScript 프로젝트를 위해 다음이 제공됩니다:

Additionally, for TypeScript projects:

  • eslint-config-next/typescript: typescript-eslint의 TypeScript 전용 linting rule을 추가합니다. 기본 config 또는 core-web-vitals config와 함께 사용하세요.
  • eslint-config-next/typescript: Adds TypeScript-specific linting rules from typescript-eslint. Use this alongside the base or core-web-vitals config.

Setup ESLintESLint 설정하기

ESLint CLI(flat config)로 빠르게 linting을 시작하세요:

Get linting working quickly with the ESLint CLI (flat config):

  1. ESLint와 Next.js config를 설치합니다:

    pnpm add -D eslint eslint-config-next
    npm i -D eslint eslint-config-next
    yarn add --dev eslint eslint-config-next
    bun add -d eslint eslint-config-next

  2. Next.js config로 eslint.config.mjs를 만듭니다:

    JSeslint.config.mjs
    import { defineConfig, globalIgnores } from 'eslint/config'
import nextVitals from 'eslint-config-next/core-web-vitals'

const eslintConfig = defineConfig([
  ...nextVitals,
  // Override default ignores of eslint-config-next.
  globalIgnores([
    // Default ignores of eslint-config-next:
    '.next/**',
    'out/**',
    'build/**',
    'next-env.d.ts',
  ]),
])

export default eslintConfig

  3. ESLint를 실행합니다:

    pnpm exec eslint .
    npx eslint .
    yarn eslint .
    bunx eslint .

Good to know
  • eslint-config-next는 ESLint 9와 ESLint 10을 지원합니다. ESLint 10에는 Node.js ^20.19.0, ^22.13.0, 또는 >=24가 필요합니다.
  • eslint-config-next@16.4.0부터 기본 React 버전 감지가 ESLint 10에서 동작합니다. context.getFilename error를 우회하기 위해 추가했던 settings.react.version override는 제거해도 됩니다.
  • eslint-config-next에 포함된 일부 plugin은 아직 peer dependency에 ESLint 10을 명시하지 않았기 때문에, package manager가 peer dependency warning을 표시하거나 strict peer dependency가 활성화된 경우 실패할 수 있습니다.
  • eslint-config-next supports ESLint 9 and ESLint 10. ESLint 10 requires Node.js ^20.19.0, ^22.13.0, or >=24.
  • Starting with eslint-config-next@16.4.0, the default React version detection works with ESLint 10. You can remove a settings.react.version override added as a workaround for a context.getFilename error.
  • Some of the plugins included in eslint-config-next don't list ESLint 10 in their peer dependencies yet, so your package manager may show peer dependency warnings, or fail when strict peer dependencies are enabled.

next lint 제거

Next.js 16부터 next lint가 제거되었습니다.

이 제거에 따라 Next config 파일의 eslint option도 더 이상 필요 없으며 안전하게 제거할 수 있습니다.

Examples예제

Specifying a root directory within a monorepomonorepo에서 root directory 지정하기

Next.js가 root directory에 설치되어 있지 않은 프로젝트(예: monorepo)에서 @next/eslint-plugin-next를 사용한다면, eslint.config.mjs의 settings property로 @next/eslint-plugin-next에 Next.js 애플리케이션의 위치를 알려 줄 수 있습니다:

If you're using @next/eslint-plugin-next in a project where Next.js isn't installed in your root directory (such as a monorepo), you can tell @next/eslint-plugin-next where to find your Next.js application using the settings property in your eslint.config.mjs:

JSeslint.config.mjs
import { defineConfig } from 'eslint/config'
import eslintNextPlugin from '@next/eslint-plugin-next'

const eslintConfig = defineConfig([
  {
    files: ['**/*.{js,jsx,ts,tsx}'],
    plugins: {
      '@next/next': eslintNextPlugin,
    },
    settings: {
      next: {
        rootDir: 'packages/my-app/',
      },
    },
  },
])

export default eslintConfig

rootDir은 경로(상대 또는 절대), glob(예: "packages/*/"), 또는 경로와 glob의 배열일 수 있습니다.

rootDir can be a path (relative or absolute), a glob (i.e. "packages/*/"), or an array of paths and/or globs.

Disabling rulesrule 비활성화하기

지원되는 plugin(react, react-hooks, next)이 제공하는 rule을 수정하거나 비활성화하려면, eslint.config.mjs의 rules property로 직접 변경할 수 있습니다:

If you would like to modify or disable any rules provided by the supported plugins (react, react-hooks, next), you can directly change them using the rules property in your eslint.config.mjs:

JSeslint.config.mjs
import { defineConfig, globalIgnores } from 'eslint/config'
import nextVitals from 'eslint-config-next/core-web-vitals'

const eslintConfig = defineConfig([
  ...nextVitals,
  {
    rules: {
      'react/no-unescaped-entities': 'off',
      '@next/next/no-page-custom-font': 'off',
    },
  },
  // Override default ignores of eslint-config-next.
  globalIgnores([
    // Default ignores of eslint-config-next:
    '.next/**',
    'out/**',
    'build/**',
    'next-env.d.ts',
  ]),
])

export default eslintConfig

Running lint on staged filesstaged 파일에 lint 실행하기

lint-staged와 함께 ESLint를 사용해 staged git 파일에 linter를 실행하려면, 프로젝트 root의 .lintstagedrc.js 파일에 다음을 추가하세요:

If you would like to use ESLint with lint-staged to run the linter on staged git files, add the following to the .lintstagedrc.js file in the root of your project:

JS.lintstagedrc.js
const path = require('path')

const buildEslintCommand = (filenames) =>
  `eslint --fix ${filenames
    .map((f) => `"${path.relative(process.cwd(), f)}"`)
    .join(' ')}`

module.exports = {
  '*.{js,jsx,ts,tsx}': [buildEslintCommand],
}

Migrating existing config기존 config migrate하기

애플리케이션에 이미 ESLint가 설정되어 있다면, setup에 따라 Next.js linting rule을 통합하는 두 가지 방법이 있습니다.

If you already have ESLint configured in your application, there are two approaches to integrate Next.js linting rules, depending on your setup.

Using the plugin directlyplugin 직접 사용하기

다음 중 하나라도 이미 설정되어 있다면 @next/eslint-plugin-next를 직접 사용하세요:

Use @next/eslint-plugin-next directly if you have any of the following already configured:

  • 별도로 설치했거나 다른 config(airbnb, react-app 등)를 통해 설치된 충돌 가능한 plugin:
    • react
    • react-hooks
    • jsx-a11y
    • import
  • Next.js 기본값과 다른 custom parserOptions(Babel configuration을 customize한 경우에만 해당)
  • custom Node.js 및/또는 TypeScript resolver를 사용하는 eslint-plugin-import
  • Conflicting plugins installed separately or through another config (such as airbnb or react-app):
    • react
    • react-hooks
    • jsx-a11y
    • import
  • Custom parserOptions different from Next.js defaults (only if you have customized your Babel configuration)
  • eslint-plugin-import with custom Node.js and/or TypeScript resolvers

이런 경우에는 충돌을 피하기 위해 @next/eslint-plugin-next를 직접 사용하세요:

In these cases, use @next/eslint-plugin-next directly to avoid conflicts:

먼저 plugin을 설치하세요:

First, install the plugin:

pnpm add -D @next/eslint-plugin-next
npm i -D @next/eslint-plugin-next
yarn add --dev @next/eslint-plugin-next
bun add -d @next/eslint-plugin-next

그런 다음 ESLint config에 추가하세요:

Then add it to your ESLint config:

JSeslint.config.mjs
import { defineConfig } from 'eslint/config'
import nextPlugin from '@next/eslint-plugin-next'

const eslintConfig = defineConfig([
  // Your other configurations...
  {
    files: ['**/*.{js,jsx,ts,tsx}'],
    plugins: {
      '@next/next': nextPlugin,
    },
    rules: {
      ...nextPlugin.configs.recommended.rules,
    },
  },
])

export default eslintConfig

이 방법을 사용하면 같은 plugin이나 parser가 여러 configuration에서 import될 때 생길 수 있는 충돌이나 error의 위험이 없어집니다.

This approach eliminates the risk of collisions or errors that can occur when the same plugins or parsers are imported across multiple configurations.

Adding to existing config기존 config에 추가하기

기존 ESLint setup에 Next.js를 추가하는 경우, Next.js config를 배열 안에 spread하세요:

If you're adding Next.js to an existing ESLint setup, spread the Next.js config into your array:

JSeslint.config.mjs
import nextConfig from 'eslint-config-next/core-web-vitals'
// Your other config imports...

const eslintConfig = [
  // Your other configurations...
  ...nextConfig,
]

export default eslintConfig

...nextConfig를 spread하면 file pattern, plugin, rule, ignore, parser 설정을 포함한 여러 config object가 추가됩니다. ESLint는 config를 순서대로 적용하므로, 일치하는 파일에 대해서는 뒤의 rule이 앞의 rule을 override할 수 있습니다.

When you spread ...nextConfig, you're adding multiple config objects that include file patterns, plugins, rules, ignores, and parser settings. ESLint applies configs in order, so later rules can override earlier ones for matching files.

Good to know

이 방법은 단순한 setup에 잘 맞습니다. 특정 file pattern이나 plugin 설정이 충돌하는 복잡한 기존 config가 있다면, 더 세밀하게 제어할 수 있도록 (위에서 설명한 대로) plugin을 직접 사용하는 것을 고려하세요.

This approach works well for straightforward setups. If you have a complex existing config with specific file patterns or plugin configurations that conflict, consider using the plugin directly (as shown above) for more granular control.
