forbiddenexperimentalforbidden

forbidden 함수는 Next.js 403 페이지를 render하는 error를 throw합니다. 애플리케이션에서 authorization error를 처리할 때 유용합니다. forbidden.js 파일로 UI를 customize할 수 있습니다.

The forbidden function throws an error that renders a Next.js 403 page. It's useful for handling authorization errors in your application. You can customize the UI using the forbidden.js file.

forbidden()을 호출하면 NEXT_HTTP_ERROR_FALLBACK;403 error가 throw되고, error가 발생한 route segment의 rendering이 종료됩니다. 또한 Next.js는 페이지가 색인되지 않도록 <meta name="robots" content="noindex" /> tag를 삽입합니다. throw 방식으로 동작하므로 render 경로, 즉 component 안이나 component가 await하는 함수 안에서 호출하세요. await되지 않은 promise 안에 남겨진 호출은 아무것도 catch하지 않는 곳에서 throw되므로 forbidden UI가 render되지 않습니다.

Invoking forbidden() throws a NEXT_HTTP_ERROR_FALLBACK;403 error and terminates rendering of the route segment where it was thrown. Next.js also injects a <meta name="robots" content="noindex" /> tag so the page is not indexed. Because it works by throwing, call it in the render path: a component, or a function a component awaits. A call left in an un-awaited promise throws where nothing catches it, and no forbidden UI renders.

forbidden을 사용하려면 next.config.js 파일에서 experimental authInterrupts configuration option을 활성화하세요:

To start using forbidden, enable the experimental authInterrupts configuration option in your next.config.js file:

TSJSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    authInterrupts: true,
  },
}

export default nextConfig
module.exports = {
  experimental: {
    authInterrupts: true,
  },
}

forbidden은 Server Components, Server Functions, Route Handlers에서 호출할 수 있습니다.

forbidden can be invoked in Server Components, Server Functions, and Route Handlers.

TSJSapp/admin/page.tsx
import { verifySession } from '@/app/lib/dal'
import { forbidden } from 'next/navigation'

export default async function AdminPage() {
  const session = await verifySession()

  // Check if the user has the 'admin' role
  if (session.role !== 'admin') {
    forbidden()
  }

  // Render the admin page for authorized users
  return <></>
}

Good to know

  • forbidden 함수는 root layout에서 호출할 수 없습니다.
  • return forbidden()이라고 쓸 필요가 없습니다. 이 함수는 throw하므로(TypeScript never return type) 실행이 멈춥니다. 호출을 try/catch로 감싸면 interrupt가 억제되어 forbidden UI가 render되지 않습니다. 그대로 통과시키려면 unstable_rethrow를 사용하세요.
  • await되지 않은 promise 안에 남겨진 forbidden()은 아무것도 catch하지 않는 곳에서 throw되므로 forbidden UI가 render되지 않습니다. development에서는 server가 ⨯ unhandledRejection: NEXT_HTTP_ERROR_FALLBACK;403을 log로 남깁니다. 이 함수를 호출할 수 있는 함수는 항상 await하세요.
  • The forbidden function cannot be called in the root layout.
  • You do not need to write return forbidden(). It throws (its TypeScript never return type), so execution stops. A try/catch around the call suppresses the interrupt and no forbidden UI renders. Use unstable_rethrow to let it through.
  • A forbidden() left in an un-awaited promise throws where nothing catches it, so no forbidden UI renders. In development the server logs ⨯ unhandledRejection: NEXT_HTTP_ERROR_FALLBACK;403. Always await the function that may call it.

Examples예제

Calling forbidden() after streaming has startedstreaming이 시작된 뒤 forbidden() 호출하기

session을 확인하는 동안 페이지의 shell과 loading UI를 계속 보이게 하려면, 데이터를 불러오는 Data Access Layer 함수에 role 확인 로직을 넣고, <Suspense>로 감싼 component 안에서 render하세요. 확인은 boundary 안에서 실행되므로 session이 resolve되는 동안 shell이 stream됩니다:

To keep the page's shell and loading UI visible while the session is checked, put the role check in the Data Access Layer function that loads the data, and render it in a component wrapped in <Suspense>. The check runs inside the boundary, so the shell streams while the session resolves:

TSJSapp/projects/page.tsx
import { Suspense } from 'react'
import { verifySession } from '@/app/lib/dal'
import { forbidden } from 'next/navigation'

async function getProjects() {
  const session = await verifySession()
  if (session?.role !== 'admin') {
    forbidden()
  }
  return db.projects.findMany()
}

async function Projects() {
  const projects = await getProjects()
  return (
    <ul>
      {projects.map((project) => (
        <li key={project.id}>{project.name}</li>
      ))}
    </ul>
  )
}

export default function ProjectsPage() {
  return (
    <main>
      <h1>Projects</h1>
      <Suspense fallback={<p>Loading...</p>}>
        <Projects />
      </Suspense>
    </main>
  )
}

session에 접근 권한이 없으면 getProjects가 forbidden()을 호출하고, 이 함수가 throw합니다. 이는 rendering 중에 발생하므로 exception은 가장 가까운 forbidden boundary로 전파되고, 페이지 shell이 이미 전송되었더라도 이 boundary가 stream될 콘텐츠 자리에 render됩니다.

When the session lacks access, getProjects calls forbidden(), which throws. Because this happens during rendering, the exception propagates to the nearest forbidden boundary, which renders in place of the streamed-in content, even though the page shell has already been sent.

그 UI를 정의하려면 route 옆에 forbidden.tsx를 추가하세요:

Add a forbidden.tsx alongside the route to define that UI:

export default function Forbidden() {
  return (
    <main>
      <h1>403 - Forbidden</h1>

    </main>
  )
}

response는 forbidden()이 실행되기 전에 <Suspense> boundary에서 streaming을 시작하므로 200 status를 유지합니다. Next.js는 noindex tag를 추가합니다.

The response starts streaming from the <Suspense> boundary before forbidden() runs, so it keeps its 200 status. Next.js adds a noindex tag.

streaming이 시작되기 전에 forbidden()을 호출하면 403을 반환합니다. prerendering 중에 forbidden()에 도달하는 페이지는 ○ Static으로 유지되면서 403을 제공할 수 있습니다. request-time 확인은 페이지가 render되기 전에 Proxy에서 실행할 수 있습니다. Status codes를 참고하세요.

Calling forbidden() before streaming starts returns a 403. A page that reaches forbidden() during prerendering can remain ○ Static and serve a 403. A request-time check can run in Proxy before the page renders. See Status codes.

Role-based route protectionRole 기반 route 보호

forbidden을 사용해 사용자 role에 따라 특정 route에 대한 접근을 제한할 수 있습니다. 이렇게 하면 인증은 되었지만 필요한 권한이 없는 사용자가 해당 route에 접근하지 못하도록 할 수 있습니다.

You can use forbidden to restrict access to certain routes based on user roles. This ensures that users who are authenticated but lack the required permissions cannot access the route.

TSJSapp/admin/page.tsx
import { verifySession } from '@/app/lib/dal'
import { forbidden } from 'next/navigation'

export default async function AdminPage() {
  const session = await verifySession()

  // Check if the user has the 'admin' role
  if (session.role !== 'admin') {
    forbidden()
  }

  // Render the admin page for authorized users
  return (
    <main>
      <h1>Admin Dashboard</h1>
      <p>Welcome, {session.user.name}!</p>
    </main>
  )
}
import { verifySession } from '@/app/lib/dal'
import { forbidden } from 'next/navigation'

    </main>
  )
}

Mutations with Server ActionsServer Action을 이용한 mutation

Server Action에서 mutation을 구현할 때 forbidden을 사용해 특정 role을 가진 사용자만 민감한 데이터를 업데이트하도록 허용할 수 있습니다.

When implementing mutations in Server Actions, you can use forbidden to only allow users with a specific role to update sensitive data.

TSJSapp/actions/update-role.ts
'use server'

import { verifySession } from '@/app/lib/dal'
import { forbidden } from 'next/navigation'
import db from '@/app/lib/db'

export async function updateRole(formData: FormData) {
  const session = await verifySession()

  // Ensure only admins can update roles
  if (session.role !== 'admin') {
    forbidden()
  }

  // Perform the role update for authorized users
  // ...
}
