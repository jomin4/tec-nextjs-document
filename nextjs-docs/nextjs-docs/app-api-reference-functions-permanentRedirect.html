permanentRedirectpermanentRedirect

permanentRedirect 함수를 사용하면 사용자를 다른 URL로 redirect할 수 있습니다. permanentRedirect는 Server Component, Client Component, Route Handler, Server Function에서 사용할 수 있습니다.

The permanentRedirect function allows you to redirect the user to another URL. permanentRedirect can be used in Server Components, Client Components, Route Handlers, and Server Functions.

streaming context에서 사용하면 client side에서 redirect를 발생시키는 meta tag를 삽입합니다. Server Action에서 permanentRedirect는 JavaScript를 사용할 수 있으면 client-side navigation을 수행합니다. progressive enhancement form 제출에서는 303 HTTP redirect response를 제공합니다. 그 외에는 308(Permanent) HTTP redirect response를 제공합니다.

When used in a streaming context, this will insert a meta tag to emit the redirect on the client side. In a Server Action, permanentRedirect performs a client-side navigation when JavaScript is available. For progressive enhancement form submissions, it serves a 303 HTTP redirect response. Otherwise, it serves a 308 (Permanent) HTTP redirect response.

resource가 존재하지 않는다면 대신 notFound 함수를 사용할 수 있습니다.

If a resource doesn't exist, you can use the notFound function instead.

Parameters

permanentRedirect 함수는 두 개의 인자를 받습니다:

The permanentRedirect function accepts two arguments:

permanentRedirect(path, type)
ParameterTypeDescription
pathstringredirect할 URL입니다. 상대 경로나 절대 경로를 사용할 수 있습니다.
type'replace'(기본값) 또는 'push'(Server Action에서의 기본값)수행할 redirect의 type입니다.
ParameterTypeDescription
pathstringThe URL to redirect to. Can be a relative or absolute path.
type'replace' (default) or 'push' (default in Server Actions)The type of redirect to perform.

기본적으로 permanentRedirect는 Server Action에서는 push(브라우저 history stack에 새 entry 추가)를, 그 외의 모든 곳에서는 replace(브라우저 history stack의 현재 URL 대체)를 사용합니다. type parameter를 지정해 이 동작을 override할 수 있습니다.

By default, permanentRedirect will use push (adding a new entry to the browser history stack) in Server Actions and replace (replacing the current URL in the browser history stack) everywhere else. You can override this behavior by specifying the type parameter.

RedirectType object에는 type parameter에 사용할 수 있는 option이 들어 있습니다.

The RedirectType object contains the available options for the type parameter.

import { permanentRedirect, RedirectType } from 'next/navigation'

permanentRedirect('/redirect-to', RedirectType.replace)
// or
permanentRedirect('/redirect-to', RedirectType.push)

type parameter는 Server Component에서 사용할 때는 아무 효과가 없습니다.

The type parameter has no effect when used in Server Components.

Returns

permanentRedirect는 값을 반환하지 않습니다.

permanentRedirect does not return a value.

Behavior동작 방식

  • Server Action과 Route Handler에서 try/catch 문을 사용할 때, permanentRedirect는 error를 throw하므로 try block 밖에서 호출해야 합니다.
  • 308(Permanent) 대신 307(Temporary) HTTP redirect를 반환하고 싶다면 redirect 함수를 대신 사용할 수 있습니다.
  • In Server Actions and Route Handlers, permanentRedirect should be called outside the try block when using try/catch statements because it throws an error.
  • If you prefer to return a 307 (Temporary) HTTP redirect instead of 308 (Permanent), you can use the redirect function instead.

Example예시

permanentRedirect() 함수를 호출하면 NEXT_REDIRECT error를 throw하고, 그것이 throw된 route segment의 rendering을 종료합니다.

Invoking the permanentRedirect() function throws a NEXT_REDIRECT error and terminates rendering of the route segment in which it was thrown.

JSapp/team/[id]/page.js
import { permanentRedirect } from 'next/navigation'

async function fetchTeam(id) {
  const res = await fetch('https://...')
  if (!res.ok) return undefined
  return res.json()
}

export default async function Profile({ params }) {
  const { id } = await params
  const team = await fetchTeam(id)
  if (!team) {
    permanentRedirect('/login')
  }

  // ...
}
Good to know

permanentRedirect는 TypeScript never type을 사용하므로 return permanentRedirect()처럼 쓸 필요가 없습니다.

permanentRedirect does not require you to use return permanentRedirect() as it uses the TypeScript never type.
