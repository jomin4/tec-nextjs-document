useRouteruseRouter

useRouter hook을 사용하면 Client Components 안에서 프로그래밍 방식으로 route를 변경할 수 있습니다.

The useRouter hook allows you to programmatically change routes inside Client Components.

Recommendation

useRouter를 사용해야 하는 특별한 요구 사항이 없다면 navigation에는 <Link> component를 사용하세요.

Use the <Link> component for navigation unless you have a specific requirement for using useRouter.

TSJSapp/example-client-component.tsx
'use client'

import { useRouter } from 'next/navigation'

export default function Page() {
  const router = useRouter()

  return (
    <button type="button" onClick={() => router.push('/dashboard')}>
      Dashboard
    </button>
  )
}
'use client'

import { useRouter } from 'next/navigation'

export default function Page() {
  const router = useRouter()

  return (
    <button type="button" onClick={() => router.push('/dashboard')}>
      Dashboard
    </button>
  )
}

useRouter()

router.push()

router.push(href: string, {
  scroll: boolean
  transitionTypes: string[]
})

제공된 route로 client-side navigation을 수행합니다. 브라우저의 history stack에 새 entry를 추가합니다. 선택적인 transitionTypes는 navigation Transition 안에서 React.addTransitionType에 전달됩니다.

Perform a client-side navigation to the provided route. Adds a new entry into the browser's history stack. The optional transitionTypes are passed to React.addTransitionType inside the navigation Transition.

router.replace()

router.replace(href: string, {
  scroll: boolean
  transitionTypes: string[]
})

브라우저의 history stack에 새 entry를 추가하지 않고 제공된 route로 client-side navigation을 수행합니다. 선택적인 transitionTypes는 navigation Transition 안에서 React.addTransitionType에 전달됩니다.

Perform a client-side navigation to the provided route without adding a new entry into the browser’s history stack. The optional transitionTypes are passed to React.addTransitionType inside the navigation Transition.

router.refresh()

router.refresh()

현재 route를 refresh합니다. server에 새 request를 보내고, data request를 다시 fetch하고, Server Component를 re-render합니다. client는 영향을 받지 않는 client-side React state(예: useState)나 브라우저 state(예: scroll 위치)를 잃지 않고 업데이트된 React Server Component payload를 merge합니다. 이 작업은 현재 route의 Client Cache를 비우지만, server-side cache는 무효화하지 않습니다. server-side cached data를 무효화하려면 revalidatePath나 revalidateTag를 사용하세요.

Refresh the current route. Making a new request to the server, re-fetching data requests, and re-rendering Server Components. The client will merge the updated React Server Component payload without losing unaffected client-side React (e.g. useState) or browser state (e.g. scroll position). This clears the Client Cache for the current route, but does not invalidate the server-side cache. Use revalidatePath or revalidateTag to invalidate server-side cached data.

router.prefetch()

router.prefetch(
  href: string,
  options?: {
    kind?: 'auto' | 'full'
    onInvalidate?: () => void
  }
)

더 빠른 client-side 전환을 위해 제공된 route를 Prefetch합니다. 선택적인 kind는 route를 얼마나 prefetch할지 제어합니다. 선택적인 onInvalidate callback은 prefetch된 data가 stale해질 때 호출됩니다.

Prefetch the provided route for faster client-side transitions. The optional kind controls how much of the route to prefetch. The optional onInvalidate callback is called when the prefetched data becomes stale.

Partial Prefetching을 사용하면 각 router.prefetch() 호출은 <Link> prefetch option과 대응됩니다:

With Partial Prefetching, each router.prefetch() call matches a <Link> prefetch option:

| `router.prefetch()` 호출 | 동일한 `
` | | ----------------------------------------- | ------------------------------------ | | `router.prefetch(href)` | `
` | | `router.prefetch(href, { kind: 'auto' })` | `
` | | `router.prefetch(href, { kind: 'full' })` | `
` |

기본값과 'auto' option은 route의 App Shell을 prefetch합니다. 'full' option은 await prefetch() 아래의 content를 포함한 link별 단계까지 함께 prefetch합니다.

The default and 'auto' options prefetch the route's App Shell. The 'full' option also prefetches the per-link stage, including content below await prefetch().

두 값 모두 await navigation()으로 지연된 content는 포함하지 않습니다. 그 content는 navigation이 시작될 때 render됩니다.

Neither value includes content deferred with await navigation(). That content renders when navigation begins.

router.back()

router.back()

브라우저의 history stack에서 이전 route로 뒤로 이동합니다.

Navigate back to the previous route in the browser’s history stack.

router.forward()

router.forward()

브라우저의 history stack에서 다음 page로 앞으로 이동합니다.

Navigate forwards to the next page in the browser’s history stack.

router.bfcacheId

현재 route segment에 scope가 지정된 불투명한(opaque) string 식별자입니다. 감싸고 있는 segment가 push 또는 replace navigation으로 새로 생성될 때 바뀌며, back/forward navigation, router.refresh(), 그리고 search param이나 hash만 바뀌는 navigation에서는 그대로 유지됩니다. 자세한 내용은 아래의 bfcacheId를 참고하세요.

An opaque string identifier scoped to the current route segment. It changes when the surrounding segment is freshly created by a push or replace navigation, and stays the same for back/forward navigations, router.refresh(), and search-param- or hash-only navigations. See bfcacheId below for details.

Good to know
  • 신뢰할 수 없거나 sanitize되지 않은 URL을 router.push나 router.replace에 전달하면 안 됩니다. 사이트가 cross-site scripting (XSS) 취약점에 노출될 수 있기 때문입니다. 예를 들어 router.push나 router.replace에 전달된 javascript: URL은 page의 context에서 실행됩니다.
  • <Link> component는 viewport에 보이게 되면 route를 자동으로 prefetch합니다.
  • fetch request가 cache되어 있다면 refresh()가 같은 결과를 다시 만들어 낼 수 있습니다. cookies나 headers 같은 다른 Request-time API도 response를 바꿀 수 있습니다.
  • onInvalidate callback은 prefetch request당 최대 한 번 호출됩니다. 업데이트된 route data를 위해 새 prefetch를 trigger하고 싶을 수 있는 시점을 알려 줍니다.
  • You must not send untrusted or unsanitized URLs to router.push or router.replace, as this can open your site to cross-site scripting (XSS) vulnerabilities. For example, javascript: URLs sent to router.push or router.replace will be executed in the context of your page.
  • The <Link> component automatically prefetch routes as they become visible in the viewport.
  • refresh() could re-produce the same result if fetch requests are cached. Other Request-time APIs like cookies and headers could also change the response.
  • The onInvalidate callback is called at most once per prefetch request. It signals when you may want to trigger a new prefetch for updated route data.

Migrating from next/routernext/router에서 migrate하기

  • App Router를 사용할 때 useRouter hook은 next/router가 아니라 next/navigation에서 import해야 합니다
  • pathname string은 제거되었으며 usePathname()으로 대체되었습니다
  • query object는 제거되었으며 useSearchParams()로 대체되었습니다
  • router.events는 대체되었습니다. 아래를 참고하세요.
  • The useRouter hook should be imported from next/navigation and not next/router when using the App Router
  • The pathname string has been removed and is replaced by usePathname()
  • The query object has been removed and is replaced by useSearchParams()
  • router.events has been replaced. See below.

Examples예시

Router eventsRouter event

usePathname, useSearchParams 같은 다른 Client Component hook을 조합해 page 변경을 감지할 수 있습니다.

You can listen for page changes by composing other Client Component hooks like usePathname and useSearchParams.

JSapp/components/navigation-events.js
'use client'

import { useEffect } from 'react'
import { usePathname, useSearchParams } from 'next/navigation'

export function NavigationEvents() {
  const pathname = usePathname()
  const searchParams = useSearchParams()

  useEffect(() => {
    const url = `${pathname}?${searchParams}`
    console.log(url)
    // You can now use the current URL
    // ...
  }, [pathname, searchParams])

  return '...'
}

이 component는 layout에 import할 수 있습니다.

Which can be imported into a layout.

JSapp/layout.js
import { Suspense } from 'react'
import { NavigationEvents } from './components/navigation-events'

export default function Layout({ children }) {
  return (
    <html lang="en">
      <body>
        {children}

        <Suspense fallback={null}>
          <NavigationEvents />
        </Suspense>
      </body>
    </html>
  )
}
Good to know

prerendering 중에 useSearchParams()는 가장 가까운 Suspense boundary까지 client-side rendering을 일으키기 때문에 <NavigationEvents>는 Suspense boundary로 감싸져 있습니다. 더 알아보기.

<NavigationEvents> is wrapped in a Suspense boundary becauseuseSearchParams() causes client-side rendering up to the closest Suspense boundary during prerendering. Learn more.

Disabling scroll to top맨 위로 scroll 비활성화하기

기본적으로 Next.js는 새 route로 이동할 때 page 맨 위로 scroll합니다. router.push()나 router.replace()에 scroll: false를 전달하면 이 동작을 비활성화할 수 있습니다.

By default, Next.js will scroll to the top of the page when navigating to a new route. You can disable this behavior by passing scroll: false to router.push() or router.replace().

TSJSapp/example-client-component.tsx
'use client'

import { useRouter } from 'next/navigation'

export default function Page() {
  const router = useRouter()

  return (
    <button
      type="button"
      onClick={() => router.push('/dashboard', { scroll: false })}
    >
      Dashboard
    </button>
  )
}
'use client'

import { useRouter } from 'next/navigation'

export default function Page() {
  const router = useRouter()

  return (
    <button
      type="button"
      onClick={() => router.push('/dashboard', { scroll: false })}
    >
      Dashboard
    </button>
  )
}

bfcacheId

router.bfcacheId는 현재 route segment에 scope가 지정된 불투명한(opaque) string 식별자입니다. 감싸고 있는 segment가 push 또는 replace navigation으로 새로 생성될 때 바뀌며, back/forward navigation, router.refresh(), 그리고 search param이나 hash만 바뀌는 navigation에서는 그대로 유지됩니다.

router.bfcacheId is an opaque string identifier scoped to the current route segment. It changes when the surrounding segment is freshly created by a push or replace navigation, and stays the same for back/forward navigations, router.refresh(), and search-param- or hash-only navigations.

권장 사용법은 이 값을 React key로 전달해, 새 navigation에서는 state 보존을 opt out하면서 back/forward navigation 중에는 state를 복원하는 것입니다:

The recommended use is to pass it as a React key to opt out of state preservation on fresh navigations, while still restoring it during a back/forward navigation:

TSapp/example/page.tsx
'use client'

import { useRouter } from 'next/navigation'

export default function Page() {
  const { bfcacheId } = useRouter()
  return <form key={bfcacheId}>{/* ... */}</form>
}

cacheComponents가 활성화되어 있으면 App Router는 React <Activity>를 사용해 navigation 간에 Client Component state를 보존합니다. component에 bfcacheId를 key로 지정하면 새 navigation마다 component가 reset되지만, 브라우저 back/forward navigation 간에는 state가 계속 보존됩니다. pattern별 권장 reset 방법은 Preserving UI state를 참고하세요.

When cacheComponents is enabled, the App Router preserves Client Component state across navigations using React <Activity>. Keying a component on bfcacheId resets it on each fresh navigation while still preserving its state across browser back/forward navigations. See Preserving UI state for the recommended per-pattern resets.

Good to know

bfcacheId 대신 event handler(예: onSubmit)에서 state를 명시적으로 reset하거나 data에서 key를 도출(예: server에서 받은 draft id)하는 방식을 선호하세요. bfcacheId는 기존 codebase를 migrate할 때처럼 최후의 수단으로만 사용하세요.

Instead of bfcacheId, prefer resetting state explicitly in an event handler (for example, onSubmit) or deriving a key from your data (for example, a draft id from the server). Use bfcacheId only as a last resort, like when migrating an existing codebase.
