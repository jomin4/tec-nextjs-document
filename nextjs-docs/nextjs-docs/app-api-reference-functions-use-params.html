useParamsuseParams

useParams는 현재 URL로 채워진 route의 dynamic params를 읽을 수 있게 해 주는 Client Component hook입니다.

useParams is a Client Component hook that lets you read a route's dynamic params filled in by the current URL.

TSJSapp/example-client-component.tsx
'use client'

import { useParams } from 'next/navigation'

export default function ExampleClientComponent() {
  const params = useParams<{ tag: string; item: string }>()

  // Route -> /shop/[tag]/[item]
  // URL -> /shop/shoes/nike-air-max-97
  // `params` -> { tag: 'shoes', item: 'nike-air-max-97' }
  console.log(params)

  return '...'
}
'use client'

import { useParams } from 'next/navigation'

export default function ExampleClientComponent() {
  const params = useParams()

  // Route -> /shop/[tag]/[item]
  // URL -> /shop/shoes/nike-air-max-97
  // `params` -> { tag: 'shoes', item: 'nike-air-max-97' }
  console.log(params)

  return '...'
}

Parameters

const params = useParams()

useParams는 parameter를 받지 않습니다.

useParams does not take any parameters.

Returns

useParams는 현재 route의 채워진 dynamic parameters를 담은 object를 반환합니다.

useParams returns an object containing the current route's filled in dynamic parameters.

  • object의 각 property는 활성화된 dynamic segment입니다.
  • property 이름은 segment의 이름이고, property 값은 그 segment에 채워진 값입니다.
  • property 값은 dynamic segment의 종류에 따라 string이거나 string의 array입니다.
  • route에 dynamic parameter가 없으면 useParams는 빈 object를 반환합니다.
  • Pages Router에서 사용하면 useParams는 initial render에서 null을 반환하고, router가 준비되면 위 규칙에 따라 property가 채워진 값으로 업데이트됩니다.
  • Each property in the object is an active dynamic segment.
  • The properties name is the segment's name, and the properties value is what the segment is filled in with.
  • The properties value will either be a string or array of string's depending on the type of dynamic segment.
  • If the route contains no dynamic parameters, useParams returns an empty object.
  • If used in Pages Router, useParams will return null on the initial render and updates with properties following the rules above once the router is ready.

예를 들면 다음과 같습니다:

For example:

app/shop/[slug]/page.js/shop/1{ slug: '1' }
app/shop/[tag]/[item]/page.js/shop/1/2{ tag: '1', item: '2' }
app/shop/[...slug]/page.js/shop/1/2{ slug: ['1', '2'] }

app/shop/[slug]/page.js/shop/1{ slug: '1' }

app/shop/[...slug]/page.js/shop/1/2{ slug: ['1', '2'] }

Behavior동작

Cache Components

cacheComponents가 활성화되어 있으면 useParams에 Suspense boundary가 필요할 수 있습니다. 이는 prerendering 중에 params를 resolve할 수 있는지에 따라 달라집니다.

When cacheComponents is enabled, useParams may require a Suspense boundary. This depends on whether the params can be resolved during prerendering.

  • Static route와 generateStaticParams가 있는 route: 모든 dynamic param을 build 시점에 알 수 있습니다. useParams는 server에서 resolve되며 Suspense boundary가 필요하지 않습니다.
  • generateStaticParams로 다루지 않는 dynamic param이 있는 route: param을 request 시점까지 알 수 없습니다. useParams는 suspend됩니다. prerendering 중에 fallback이 render될 수 있도록 component(또는 상위 component)를 Suspense boundary로 감싸세요. 그렇지 않으면 build가 실패합니다.
  • Static routes and routes with generateStaticParams: every dynamic param is known at build time. useParams resolves on the server and no Suspense boundary is required.
  • Routes with dynamic params not covered by generateStaticParams: the param is not known until request time. useParams suspends. Wrap the component (or a parent) in a Suspense boundary so its fallback can be rendered during prerendering; otherwise, the build fails.

전체 해결 방법과 trade-off는 Next.js encountered URL data in a Client Component outside of Suspense를 참고하세요.

See Next.js encountered URL data in a Client Component outside of Suspense for full fix options and trade-offs.
