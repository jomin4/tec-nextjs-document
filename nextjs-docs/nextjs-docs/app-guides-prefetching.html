PrefetchingPrefetching

Prefetching은 route 간 이동을 즉각적으로 느끼게 해 줍니다. 기본적으로 Next.js는 애플리케이션 코드에 있는 link를 기준으로 route를 prefetch합니다.

Prefetching makes navigating between routes feel instant. By default, Next.js prefetches routes based on the links in your application code.

이 가이드에서는 prefetching이 어떻게 동작하는지, Next.js가 무엇을 대신 prefetch해 주는지, 그리고 이를 제어하는 방법을 설명합니다:

This guide explains how prefetching works, what Next.js prefetches for you, and how to control it:

Using Partial Prefetching? partialPrefetching을 활성화하면, <Link>는 기본적으로 page 전체 대신 route별 App Shell을 prefetch합니다. 아래의 Partial Prefetching과, 도입 방법은 Adopting Partial Prefetching을 참고하세요.

Using Partial Prefetching? With partialPrefetching enabled, <Link> defaults to prefetching a per-route App Shell rather than the full page. See Partial Prefetching below and Adopting Partial Prefetching for the adoption path.

How does prefetching work?prefetching은 어떻게 동작하나요?

route 간에 이동할 때 브라우저는 HTML, JavaScript 파일 같은 page의 asset을 요청합니다. Prefetching은 새 route로 이동하기 전에 이런 리소스를 미리 가져오는 과정입니다.

When navigating between routes, the browser requests assets for the page like HTML and JavaScript files. Prefetching is the process of fetching these resources ahead of time, before you navigate to a new route.

Next.js는 route를 기준으로 애플리케이션을 더 작은 JavaScript chunk로 자동 분할합니다. 기존 SPA처럼 모든 코드를 처음에 한꺼번에 load하는 대신, 현재 route에 필요한 코드만 load됩니다. 이렇게 하면 initial load 시간이 줄어들고, 앱의 다른 부분은 background에서 load됩니다. link를 클릭할 즈음에는 새 route의 리소스가 이미 browser cache에 load되어 있습니다.

Next.js automatically splits your application into smaller JavaScript chunks based on routes. Instead of loading all the code upfront like traditional SPAs, only the code needed for the current route is loaded. This reduces the initial load time while other parts of the app are loaded in the background. By the time you click the link, the resources for the new route have already been loaded into the browser cache.

새 page로 이동할 때 전체 page reload나 브라우저 loading spinner가 없습니다. 대신 Next.js가 client-side transition을 수행해서 page 이동이 즉각적으로 느껴지게 합니다.

When navigating to the new page, there's no full page reload or browser loading spinner. Instead, Next.js performs a client-side transition, making the page navigation feel instant.

What Next.js prefetches automaticallyNext.js가 자동으로 prefetch하는 것

Next.js는 production에서 자동으로 prefetch합니다. 각 <Link>가 viewport에 들어올 때 Next.js는 그 뒤의 route를 prefetch하며, link로 가득 찬 page가 network를 과부하시키지 않도록 작업을 scheduling합니다. 각 route를 얼마나 prefetch할지는 route가 static인지 dynamic인지에 따라 달라지며, Partial Prefetching을 활성화하면 바뀝니다.

Next.js prefetches automatically in production. As each <Link> enters the viewport, Next.js prefetches the route behind it and schedules the work so a page full of links doesn't flood the network. How much of each route it prefetches depends on whether the route is static or dynamic, and changes when Partial Prefetching is enabled.

Prefetching static vs. dynamic routesstatic route와 dynamic route의 prefetching

Cache Components가 없으면 static route는 전체가 prefetch되고, dynamic route는 loading.js boundary가 없는 한 건너뜁니다.

Without Cache Components, a static route is prefetched in full, while a dynamic route is skipped unless it has a loading.js boundary.

Good to know

첫 navigation 동안 브라우저는 HTML, JavaScript, React Server Components(RSC) Payload를 가져옵니다. 이후 navigation에서는 Server Component용 RSC Payload와 Client Component용 JS bundle을 가져옵니다.

During the initial navigation, the browser fetches the HTML, JavaScript, and React Server Components (RSC) Payload. For subsequent navigations, the browser will fetch the RSC Payload for Server Components and JS bundle for Client Components.

자동 prefetching은 production에서만 실행됩니다. prefetch={false}로 비활성화하거나 Disabled Prefetch의 wrapper를 사용하세요.

Automatic prefetching runs only in production. Disable with prefetch={false} or use the wrapper in Disabled Prefetch.

Prefetch scheduling

Next.js는 작은 task queue를 유지하며, 다음 순서로 prefetch합니다:

Next.js maintains a small task queue, which prefetches in the following order:

  1. viewport 안의 link
  2. 사용자 의도(hover 또는 touch)를 보이는 link
  3. 새 link가 이전 link를 대체
  4. 화면 밖으로 scroll된 link는 폐기
  1. Links in the viewport
  2. Links showing user intent (hover or touch)
  3. Newer links replace older ones
  4. Links scrolled off-screen are discarded

scheduler는 사용되지 않는 다운로드를 최소화하면서 실제로 이동할 가능성이 높은 navigation을 우선시합니다.

The scheduler prioritizes likely navigations while minimizing unused downloads.

Good to know

experimental useOffline config를 활성화하면, 앱이 연결 끊김에서 회복될 때 대기 중인 prefetch가 이 queue를 통해 재개됩니다.

With the experimental useOffline config enabled, pending prefetches resume through this queue when the app recovers from a connectivity drop.

Client cache

Next.js는 prefetch한 React Server Component payload를 route segment를 key로 하여 memory에 저장합니다. 형제 route 간에 이동할 때(예: /dashboard/settings → /dashboard/analytics), Next.js는 부모 layout을 재사용하고 업데이트된 leaf page만 가져옵니다.

Next.js stores prefetched React Server Component payloads in memory, keyed by route segments. When navigating between sibling routes (e.g. /dashboard/settings → /dashboard/analytics), Next.js reuses the parent layout and only fetches the updated leaf page.

Partial Prefetching

partialPrefetching config(Cache Components 필요)로 Partial Prefetching을 활성화하면, prefetching이 위의 all-or-nothing 모델에서 route별 App Shell 모델로 바뀝니다:

With Partial Prefetching enabled via the partialPrefetching config (which requires Cache Components), prefetching switches from the all-or-nothing model above to a per-route App Shell:

  • route당 shell 하나를 여러 link가 공유합니다. <Link>는 route의 App Shell을 prefetch하며, 여기에는 route의 static output과 session output이 들어 있습니다. 같은 route로 가는 link가 몇 개든 그 하나의 shell을 재사용하고, shell은 첫 link가 viewport에 들어올 때 한 번만 가져오므로, link가 많은 page에서도 각 route를 전부 prefetch하는 것보다 prefetch request가 적습니다.
  • 나머지는 stream되어 들어옵니다. uncached data는 navigation 이후 shell의 <Suspense> boundary 뒤에서 stream되어 들어옵니다. link는 prefetch={true}로 prefetch 시점에 URL data(searchParams, params)를 resolve할 수도 있습니다.
  • invalidation이 prefetch를 갱신합니다. data invalidation(revalidateTag, revalidatePath)은 관련 prefetch를 조용히 갱신합니다.
  • One shell per route, shared across links. <Link> prefetches the route's App Shell, which holds its static and session output. Any number of links to the same route reuse that one shell, fetched once as the first link enters the viewport, so a page with many links makes fewer prefetch requests than prefetching each route in full.
  • The rest streams in. Uncached data streams in after navigation, behind the shell's <Suspense> boundaries. A link can also resolve its URL data (searchParams, params) at prefetch time with prefetch={true}.
  • Invalidations refresh prefetches. Data invalidations (revalidateTag, revalidatePath) silently refresh associated prefetches.

동작 변화와 권장 도입 방법은 Adopting Partial Prefetching을 참고하세요. prefetch={true}로 navigation 전에 cache된 URL별 콘텐츠를 resolve하려면 Optimizing prefetching을 참고하세요.

See Adopting Partial Prefetching for the behavior change and the recommended adoption path. See Optimizing prefetching to resolve cached URL-specific content before navigation with prefetch={true}.

Controlling prefetchingprefetching 제어하기

Next.js는 기본값으로 prefetch하지만, 리소스 예산이나 navigation 패턴에 맞지 않을 때는 link별로 조정할 수 있습니다.

Next.js prefetches with defaults you can tune per link when they don't fit your resource budget or navigation patterns.

Manual prefetch수동 prefetch

수동으로 prefetch하려면 next/navigation에서 useRouter hook을 import한 다음, router.prefetch()를 호출해 viewport 밖의 route를 미리 데우거나(warm) analytics, hover, scroll에 반응해 prefetch하세요.

To prefetch manually, import the useRouter hook from next/navigation, then call router.prefetch() to warm routes outside the viewport or in response to analytics, hover, or scroll.

Partial Prefetching에서는 router.prefetch(href)가 기본 <Link>와 같은 App Shell을 요청합니다. { kind: 'full' }을 전달하면 <Link prefetch={true}>와 마찬가지로 link별 단계도 함께 요청합니다. link별 단계에는 await prefetch() 아래의 cache 가능한 콘텐츠가 포함될 수 있습니다.

With Partial Prefetching, router.prefetch(href) requests the same App Shell as a default <Link>. Pass { kind: 'full' } to also request the per-link stage, matching <Link prefetch={true}>. The per-link stage can include cacheable content below await prefetch().

'use client'

import { useRouter } from 'next/navigation'
import { CustomLink } from '@components/link'

export function PricingCard() {
  const router = useRouter()

  return (
    <div onMouseEnter={() => router.prefetch('/pricing', { kind: 'full' })}>
      {/* other UI elements */}
      <CustomLink href="/pricing">View Pricing</CustomLink>
    </div>
  )
}

component가 load될 때 URL을 prefetch하려면 Extending or ejecting link를 참고하세요.

To prefetch a URL when a component loads, see Extending or ejecting link.

Hover-triggered prefetchHover로 시작하는 prefetch

Proceed with caution: Link를 확장하면 prefetching, cache invalidation, accessibility 문제를 직접 관리해야 합니다. 기본값으로 충분하지 않을 때만 이렇게 하세요.

Proceed with caution: Extending Link opts you into maintaining prefetching, cache invalidation, and accessibility concerns. Do this only when the defaults are insufficient.

기본적으로 <Link>는 viewport에 들어올 때 prefetch합니다. 사용자가 방문할 가능성이 높은 link만 prefetch하려면, 사용자가 link에 hover할 때까지 prefetching을 미루세요:

By default, <Link> prefetches when it enters the viewport. To prefetch only the links a user is likely to visit, defer prefetching until they hover over a link:

'use client'

import Link from 'next/link'
import { useState } from 'react'

export function HoverPrefetchLink({
  href,
  children,
}: {
  href: string
  children: React.ReactNode
}) {
  const [active, setActive] = useState(false)

  return (
    <Link
      href={href}
      prefetch={active ? null : false}
      onMouseEnter={() => setActive(true)}
    >
      {children}
    </Link>
  )
}

prefetch={null}은 사용자가 의도를 보이면 기본 prefetching을 되살립니다.

prefetch={null} restores default prefetching once the user shows intent.

Partial Prefetching에서는 대신 prefetch={active ? true : 'auto'}를 사용하세요. 'auto' 값은 사용자가 의도를 보이기 전에는 공유 App Shell을 prefetch된 상태로 유지하고, 의도를 보인 후에는 true가 navigation 전에 cache된 URL별 콘텐츠를 resolve합니다. 의도를 보이기 전에 false를 사용하면 App Shell prefetch가 비활성화됩니다.

With Partial Prefetching, use prefetch={active ? true : 'auto'} instead. The 'auto' value keeps the shared App Shell prefetched before the user shows intent, while true resolves cached URL-specific content before navigation after they do. Using false before intent disables the App Shell prefetch.

Extending or ejecting linklink 확장하거나 직접 구현하기

<Link> component를 확장해 자신만의 custom prefetching 전략을 만들 수 있습니다. 예를 들어 사용자 cursor의 방향을 예측해 link를 prefetch하는 ForesightJS library를 사용할 수 있습니다.

You can extend the <Link> component to create your own custom prefetching strategy. For example, using the ForesightJS library which prefetches links by predicting the direction of the user's cursor.

또는 useRouter를 사용해 기본 <Link> 동작의 일부를 재현할 수도 있습니다. 하지만 이렇게 하면 prefetching과 cache invalidation을 직접 관리해야 한다는 점에 유의하세요.

Alternatively, you can use useRouter to recreate some of the native <Link> behavior. However, be aware this opts you into maintaining prefetching and cache invalidation.

'use client'

import { useRouter } from 'next/navigation'
import { useEffect } from 'react'

function ManualPrefetchLink({
  href,
  children,
}: {
  href: string
  children: React.ReactNode
}) {
  const router = useRouter()

  useEffect(() => {
    let cancelled = false
    const poll = () => {
      if (!cancelled) router.prefetch(href, { onInvalidate: poll })
    }
    poll()
    return () => {
      cancelled = true
    }
  }, [href, router])

  return (
    <a
      href={href}
      onClick={(event) => {
        event.preventDefault()
        router.push(href)
      }}
    >
      {children}
    </a>
  )
}

Next.js는 cache된 data가 stale하다고 의심될 때 onInvalidate를 호출하므로, 이때 prefetch를 갱신할 수 있습니다.

Next.js invokes onInvalidate when it suspects cached data is stale, so you can refresh the prefetch.

Good to know

a tag는 전체 page navigation을 일으킵니다. onClick으로 이를 막은 다음 router.push를 호출해 client에서 이동하세요.

An a tag triggers a full page navigation. Use onClick to prevent it, then call router.push to navigate on the client.

Disabled prefetchprefetch 비활성화

리소스 소비를 더 세밀하게 제어하기 위해 특정 route의 prefetching을 완전히 비활성화할 수 있습니다.

You can fully disable prefetching for certain routes for more fine-grained control over resource consumption.

'use client'

import Link, { LinkProps } from 'next/link'

function NoPrefetchLink({
  prefetch,
  ...rest
}: LinkProps & { children: React.ReactNode }) {
  return <Link {...rest} prefetch={false} />
}

예를 들어 애플리케이션 전체에서 <Link>를 일관되게 사용하고 싶지만, footer의 link는 viewport에 들어올 때 prefetch할 필요가 없을 수 있습니다.

For example, you may still want to have consistent usage of <Link> in your application, but links in your footer might not need to be prefetched when entering the viewport.

Triggering unwanted side-effects during prefetchingprefetching 중 원치 않는 side-effect 발생

layout이나 page가 pure하지 않고 side-effect(예: analytics tracking)를 가지고 있다면, Next.js는 사용자가 page를 방문할 때가 아니라 route가 prefetch될 때 이를 실행할 수 있습니다.

If your layouts or pages are not pure and have side-effects (e.g. tracking analytics), Next.js might run them when the route is prefetched, not when the user visits the page.

이를 피하려면 side-effect를 useEffect hook이나 Client Component에서 호출하는 Server Action으로 옮기세요.

To avoid this, move side-effects to a useEffect hook or a Server Action triggered from a Client Component.

Preventing too many prefetches너무 많은 prefetch 막기

Next.js는 <Link> component를 사용할 때 viewport 안의 link를 자동으로 prefetch합니다.

Next.js automatically prefetches links in the viewport when using the <Link> component.

link 목록이 아주 긴 경우(예: infinite scroll table)처럼 불필요한 리소스 사용을 피하기 위해 이를 막고 싶을 수 있습니다.

You might want to prevent this to avoid unnecessary resource usage, such as when rendering a large list of links (e.g. an infinite scroll table).

<Link> component의 prefetch prop을 false로 설정하면 prefetching을 비활성화할 수 있습니다.

You can disable prefetching by setting the prefetch prop of the <Link> component to false.

TSapp/ui/no-prefetch-link.tsx
<Link prefetch={false} href={`/blog/${post.id}`}>
  {post.title}
</Link>

하지만 이렇게 하면 static route는 클릭할 때만 가져오고, dynamic route는 이동하기 전에 server가 render할 때까지 기다리게 됩니다.

However, this means static routes will only be fetched on click, and dynamic routes will wait for the server to render before navigating.

prefetch를 완전히 비활성화하지 않고 리소스 사용을 줄이려면, 사용자가 link에 hover할 때까지 prefetching을 미룰 수 있습니다. 이렇게 하면 사용자가 방문할 가능성이 높은 link만 대상으로 합니다.

To reduce resource usage without disabling prefetch entirely, you can defer prefetching until the user hovers over a link. This targets only links the user is likely to visit.
