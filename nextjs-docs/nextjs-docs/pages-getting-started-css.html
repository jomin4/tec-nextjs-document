How to use CSS in your applicationCSS

Next.js는 CSS로 애플리케이션을 스타일링하는 여러 방법을 제공합니다:

Next.js provides several ways to style your application using CSS, including:

  • Tailwind CSS
  • CSS Modules
  • Global CSS
  • External Stylesheets
  • Sass
  • CSS-in-JS
  • Tailwind CSS
  • CSS Modules
  • Global CSS

Tailwind CSS

Tailwind CSS는 custom 디자인을 만들 수 있도록 low-level utility class를 제공하는 utility-first CSS framework입니다.

Tailwind CSS is a utility-first CSS framework that provides low-level utility classes to build custom designs.

Tailwind CSS를 설치하세요:

Install Tailwind CSS:

pnpm add -D tailwindcss @tailwindcss/postcss
npm install -D tailwindcss @tailwindcss/postcss
yarn add -D tailwindcss @tailwindcss/postcss
bun add -D tailwindcss @tailwindcss/postcss

postcss.config.mjs 파일에 PostCSS plugin을 추가하세요:

Add the PostCSS plugin to your postcss.config.mjs file:

JSpostcss.config.mjs
export default {
  plugins: {
    '@tailwindcss/postcss': {},
  },
}

global CSS 파일에서 Tailwind를 import하세요:

Import Tailwind in your global CSS file:

styles/globals.css
@import 'tailwindcss';

pages/_app.js 파일에서 CSS 파일을 import하세요:

Import the CSS file in your pages/_app.js file:

JSpages/_app.js
import '@/styles/globals.css'

export default function MyApp({ Component, pageProps }) {
  return <Component {...pageProps} />
}

이제 애플리케이션에서 Tailwind의 utility class를 사용할 수 있습니다:

Now you can start using Tailwind's utility classes in your application:

TSJSpages/index.tsx
export default function Home() {
  return (
    <main className="flex min-h-screen flex-col items-center justify-between p-24">
      <h1 className="text-4xl font-bold">Welcome to Next.js!</h1>
    </main>
  )
}
export default function Home() {
  return (
    <main className="flex min-h-screen flex-col items-center justify-between p-24">
      <h1 className="text-4xl font-bold">Welcome to Next.js!</h1>
    </main>
  )
}
Good to know

아주 오래된 브라우저까지 폭넓게 지원해야 한다면 Tailwind CSS v3 설정 방법을 참고하세요.

If you need broader browser support for very old browsers, see the Tailwind CSS v3 setup instructions.

CSS Modules

CSS Modules는 고유한 class 이름을 생성해 CSS의 범위를 로컬로 한정(local scope)합니다. 덕분에 이름 충돌을 걱정하지 않고 서로 다른 파일에서 같은 class를 사용할 수 있습니다.

CSS Modules locally scope CSS by generating unique class names. This allows you to use the same class in different files without worrying about naming collisions.

CSS Modules를 사용하려면 확장자가 .module.css인 새 파일을 만들고, pages directory 안의 아무 component에서나 import하세요:

To start using CSS Modules, create a new file with the extension .module.css and import it into any component inside the pages directory:

styles/blog.module.css
.blog {
  padding: 24px;
}
TSJSpages/blog/index.tsx
import styles from '@/styles/blog.module.css'

export default function Page() {
  return <main className={styles.blog}></main>
}
import styles from '@/styles/blog.module.css'

export default function Page() {
  return <main className={styles.blog}></main>
}

Global CSS

global CSS를 사용하면 애플리케이션 전체에 스타일을 적용할 수 있습니다.

You can use global CSS to apply styles across your application.

pages/_app.js 파일에서 stylesheet를 import하면 애플리케이션의 모든 route에 스타일이 적용됩니다:

Import the stylesheet in the pages/_app.js file to apply the styles to every route in your application:

JSpages/_app.js
import '@/styles/global.css'

export default function MyApp({ Component, pageProps }) {
  return <Component {...pageProps} />
}

stylesheet는 global한 성격을 가지므로, 충돌을 피하려면 pages/_app.js 안에서 import해야 합니다.

Due to the global nature of stylesheets, and to avoid conflicts, you should import them inside pages/_app.js.

External stylesheets외부 stylesheet

Next.js에서는 JavaScript 파일에서 CSS 파일을 import할 수 있습니다. Next.js가 import의 개념을 JavaScript 너머로 확장했기 때문에 가능한 일입니다.

Next.js allows you to import CSS files from a JavaScript file. This is possible because Next.js extends the concept of import beyond JavaScript.

Import styles from node_modulesnode_modules에서 스타일 import하기

Next.js 9.5.4 버전부터는 애플리케이션 어디서든 node_modules의 CSS 파일을 import할 수 있습니다.

Since Next.js 9.5.4, importing a CSS file from node_modules is permitted anywhere in your application.

bootstrap이나 nprogress 같은 global stylesheet는 pages/_app.js 안에서 import해야 합니다. 예를 들면 다음과 같습니다:

For global stylesheets, like bootstrap or nprogress, you should import the file inside pages/_app.js. For example:

JSpages/_app.js
import 'bootstrap/dist/css/bootstrap.css'

export default function MyApp({ Component, pageProps }) {
  return <Component {...pageProps} />
}

third-party component에 필요한 CSS는 해당 component에서 import할 수 있습니다. 예를 들면 다음과 같습니다:

To import CSS required by a third-party component, you can do so in your component. For example:

JScomponents/example-dialog.js
import { useState } from 'react'
import { Dialog } from '@reach/dialog'
import VisuallyHidden from '@reach/visually-hidden'
import '@reach/dialog/styles.css'

function ExampleDialog(props) {
  const [showDialog, setShowDialog] = useState(false)
  const open = () => setShowDialog(true)
  const close = () => setShowDialog(false)

  return (
    <div>
      <button onClick={open}>Open Dialog</button>
      <Dialog isOpen={showDialog} onDismiss={close}>
        <button className="close-button" onClick={close}>
          <VisuallyHidden>Close</VisuallyHidden>
          <span aria-hidden>×</span>
        </button>
        <p>Hello there. I am a dialog</p>
      </Dialog>
    </div>
  )
}

Ordering and Merging순서와 병합

Next.js는 production build 중에 stylesheet를 자동으로 chunking(병합)해 CSS를 최적화합니다. CSS의 순서는 코드에서 스타일을 import하는 순서에 따라 결정됩니다.

Next.js optimizes CSS during production builds by automatically chunking (merging) stylesheets. The order of your CSS depends on the order you import styles in your code.

예를 들어 <BaseButton>이 page.module.css보다 먼저 import되므로 base-button.module.css가 page.module.css보다 앞에 배치됩니다:

For example, base-button.module.css will be ordered before page.module.css since <BaseButton> is imported before page.module.css:

TSJSpage.tsx
import { BaseButton } from './base-button'
import styles from './page.module.css'

export default function Page() {
  return <BaseButton className={styles.primary} />
}
import { BaseButton } from './base-button'
import styles from './page.module.css'

export default function Page() {
  return <BaseButton className={styles.primary} />
}
TSJSbase-button.tsx
import styles from './base-button.module.css'

export function BaseButton() {
  return <button className={styles.primary} />
}
import styles from './base-button.module.css'

export function BaseButton() {
  return <button className={styles.primary} />
}

Recommendations권장 사항

CSS 순서를 예측 가능하게 유지하려면:

To keep CSS ordering predictable:

  • CSS import를 하나의 JavaScript 또는 TypeScript entry 파일로 모으도록 하세요
  • global style과 Tailwind stylesheet는 애플리케이션의 root에서 import하세요.
  • 대부분의 스타일링에는 Tailwind CSS를 사용하세요. utility class로 일반적인 디자인 패턴을 다룰 수 있습니다.
  • Tailwind utility로 충분하지 않을 때는 component별 스타일에 CSS Modules를 사용하세요.
  • CSS module에는 일관된 naming convention을 사용하세요. 예를 들어 <name>.tsx보다 <name>.module.css를 사용하세요.
  • 공유되는 스타일은 공유 component로 추출해 중복 import를 피하세요.
  • ESLint의 sort-imports처럼 import를 자동 정렬하는 linter나 formatter는 끄세요.
  • next.config.js의 cssChunking option을 사용해 CSS가 chunk되는 방식을 제어할 수 있습니다.
  • Try to contain CSS imports to a single JavaScript or TypeScript entry file
  • Import global styles and Tailwind stylesheets in the root of your application.
  • Use Tailwind CSS for most styling needs as it covers common design patterns with utility classes.
  • Use CSS Modules for component-specific styles when Tailwind utilities aren't sufficient.
  • Use a consistent naming convention for your CSS modules. For example, using <name>.module.css over <name>.tsx.
  • Extract shared styles into shared components to avoid duplicate imports.
  • Turn off linters or formatters that auto-sort imports like ESLint’s sort-imports.
  • You can use the cssChunking option in next.config.js to control how CSS is chunked.

Development vs ProductionDevelopment와 Production

  • development(next dev)에서는 Fast Refresh로 CSS 업데이트가 즉시 적용됩니다.
  • production(next build)에서는 모든 CSS 파일이 자동으로 많은 수의 minify되고 code-split된 .css 파일로 합쳐져, route에 필요한 최소한의 CSS만 로드되도록 합니다.
  • production에서는 JavaScript가 비활성화되어 있어도 CSS가 로드되지만, development에서는 Fast Refresh를 위해 JavaScript가 필요합니다.
  • CSS 순서는 development에서 다르게 동작할 수 있으므로, 항상 build(next build)를 확인해 최종 CSS 순서를 검증하세요.
  • In development (next dev), CSS updates apply instantly with Fast Refresh.
  • In production (next build), all CSS files are automatically concatenated into many minified and code-split .css files, ensuring the minimal amount of CSS is loaded for a route.
  • CSS still loads with JavaScript disabled in production, but JavaScript is required in development for Fast Refresh.
  • CSS ordering can behave differently in development, always ensure to check the build (next build) to verify the final CSS order.
