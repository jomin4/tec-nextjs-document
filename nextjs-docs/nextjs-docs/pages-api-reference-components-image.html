ImageImage 컴포넌트

Next.js Image component는 자동 이미지 최적화를 위해 HTML <img> element를 확장합니다.

The Next.js Image component extends the HTML <img> element for automatic image optimization.

JSapp/page.js
import Image from 'next/image'

export default function Page() {
  return (
    <Image
      src="/profile.png"
      width={500}
      height={500}
      alt="Picture of the author"
    />
  )
}
Good to know

Next.js 13 이전 버전을 사용 중이라면, component 이름이 바뀌었으므로 next/legacy/image 문서를 참고하세요.

If you are using a version of Next.js prior to 13, you'll want to use the next/legacy/image documentation since the component was renamed.

src

이미지의 source입니다. 다음 중 하나를 사용할 수 있습니다:

The source of the image. Can be one of the following:

내부 경로 문자열.

An internal path string.

<Image src="/profile.png" />

절대 외부 URL (remotePatterns로 설정해야 함).

An absolute external URL (must be configured with remotePatterns).

<Image src="https://example.com/profile.png" />

static import.

A static import.

import profile from './profile.png'

export default function Page() {
  return <Image src={profile} />
}
Good to know

보안상의 이유로, 기본 loader를 사용하는 Image Optimization API는 src 이미지를 가져올 때 header를 전달하지 않습니다. src 이미지에 인증이 필요하다면 unoptimized property를 사용해 Image Optimization을 비활성화하는 것을 고려하세요.

For security reasons, the Image Optimization API using the default loader will not forward headers when fetching the src image. If the src image requires authentication, consider using the unoptimized property to disable Image Optimization.

alt

alt property는 screen reader와 검색 엔진을 위해 이미지를 설명하는 데 사용됩니다. 또한 이미지가 비활성화되었거나 이미지를 불러오는 중 오류가 발생했을 때 보여 주는 fallback 텍스트이기도 합니다.

The alt property is used to describe the image for screen readers and search engines. It is also the fallback text if images have been disabled or an error occurs while loading the image.

이 값에는 페이지의 의미를 바꾸지 않고 이미지를 대체할 수 있는 텍스트가 들어가야 합니다. 이미지를 보충하기 위한 것이 아니므로, 이미지 위나 아래의 caption에서 이미 제공한 정보를 반복해서는 안 됩니다.

It should contain text that could replace the image without changing the meaning of the page. It is not meant to supplement the image and should not repeat information that is already provided in the captions above or below the image.

이미지가 순전히 장식용이거나 사용자를 위한 것이 아니라면, alt property는 빈 문자열(alt="")이어야 합니다.

If the image is purely decorative or not intended for the user, the alt property should be an empty string (alt="").

이미지 접근성 가이드라인에 대해 더 알아보세요.

Learn more about image accessibility guidelines.

width and heightwidth와 height

width와 height property는 intrinsic(고유) 이미지 크기를 pixel 단위로 나타냅니다. 이 property는 브라우저가 이미지 공간을 미리 확보하고 로딩 중 layout shift를 피하기 위해 사용하는 올바른 aspect ratio(종횡비)를 추론하는 데 쓰입니다. 이미지의 _렌더링 크기_를 결정하지는 않으며, 렌더링 크기는 CSS로 제어됩니다.

The width and height properties represent the intrinsic image size in pixels. This property is used to infer the correct aspect ratio used by browsers to reserve space for the image and avoid layout shift during loading. It does not determine the rendered size of the image, which is controlled by CSS.

<Image src="/profile.png" width={500} height={500} />

다음 경우가 아니라면 width와 height property를 반드시 모두 설정해야 합니다:

You must set both width and height properties unless:

  • 이미지가 static import된 경우.
  • 이미지에 fill property가 있는 경우
  • The image is statically imported.
  • The image has the fill property

height와 width를 알 수 없다면 fill property 사용을 권장합니다.

If the height and width are unknown, we recommend using the fill property.

fill

이미지가 부모 element의 크기에 맞게 확장되도록 하는 boolean입니다.

A boolean that causes the image to expand to the size of the parent element.

<Image src="/profile.png" fill={true} />

Positioning:

Positioning:

  • 부모 element는 반드시 position: "relative", "fixed", "absolute" 중 하나를 지정해야 합니다.
  • 기본적으로 <img> element는 position: "absolute"를 사용합니다.
  • The parent element must assign position: "relative", "fixed", "absolute".
  • By default, the <img> element uses position: "absolute".

Object Fit:

Object Fit:

이미지에 아무 style도 적용하지 않으면 이미지가 container에 맞게 늘어납니다. objectFit을 사용해 잘라내기(cropping)와 크기 조정(scaling)을 제어할 수 있습니다.

If no styles are applied to the image, the image will stretch to fit the container. You can use objectFit to control cropping and scaling.

  • "contain": 이미지가 aspect ratio를 유지한 채 container에 맞게 축소됩니다.
  • "cover": 이미지가 container를 가득 채우고 잘립니다.
  • "contain": The image will be scaled down to fit the container and preserve aspect ratio.
  • "cover": The image will fill the container and be cropped.

loader

이미지 URL을 생성하는 데 사용하는 custom 함수입니다. 이 함수는 다음 parameter를 받아 이미지의 URL 문자열을 반환합니다:

A custom function used to generate the image URL. The function receives the following parameters, and returns a URL string for the image:

  • src
  • width
  • quality
  • src
  • width
  • quality
import Image from 'next/image'

const imageLoader = ({ src, width, quality }) => {
  return `https://example.com/${src}?w=${width}&q=${quality || 75}`
}

export default function Page() {
  return (
    <Image
      loader={imageLoader}
      src="me.png"
      alt="Picture of the author"
      width={500}
      height={500}
    />
  )
}

또는 prop을 전달하지 않고 next.config.js의 loaderFile 설정을 사용해 애플리케이션의 모든 next/image instance를 설정할 수도 있습니다.

Alternatively, you can use the loaderFile configuration in next.config.js to configure every instance of next/image in your application, without passing a prop.

sizes

여러 breakpoint에서의 이미지 크기를 정의합니다. 브라우저가 생성된 srcset에서 가장 적절한 크기를 고르는 데 사용합니다.

Define the sizes of the image at different breakpoints. Used by the browser to choose the most appropriate size from the generated srcset.

import Image from 'next/image'

export default function Page() {
  return (
    <div className="grid-element">
      <Image
        fill
        src="/example.png"
        sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 33vw"
      />
    </div>
  )
}

sizes는 다음과 같은 경우에 사용해야 합니다:

sizes should be used when:

  • 이미지가 fill prop을 사용하는 경우
  • CSS를 사용해 이미지를 responsive하게 만드는 경우
  • The image is using the fill prop
  • CSS is used to make the image responsive

sizes가 없으면 브라우저는 이미지가 viewport만큼 넓다고(100vw) 가정합니다. 이로 인해 불필요하게 큰 이미지가 다운로드될 수 있습니다.

If sizes is missing, the browser assumes the image will be as wide as the viewport (100vw). This can cause unnecessarily large images to be downloaded.

또한 sizes는 srcset이 생성되는 방식에도 영향을 줍니다:

In addition, sizes affects how srcset is generated:

  • width가 있는 이미지에서 sizes가 없으면: Next.js는 고정 크기 이미지에 적합한 제한된 srcset(예: 1x, 2x)을 생성합니다.
  • fill 이미지에서 sizes가 없으면: Next.js는 이미지가 viewport 전체에 걸쳐 있는 것처럼 deviceSizes만으로 srcset을 생성합니다.
  • sizes가 있으면: Next.js는 responsive layout에 최적화된 전체 srcset(예: 640w, 750w 등)을 생성합니다.
  • Without sizes, on an image with a width: Next.js generates a limited srcset (e.g. 1x, 2x), suitable for fixed-size images.
  • Without sizes, on a fill image: Next.js generates a srcset from deviceSizes only, as if the image spans the full viewport.
  • With sizes: Next.js generates a full srcset (e.g. 640w, 750w, etc.), optimized for responsive layouts.

web.dev와 mdn에서 srcset과 sizes에 대해 더 알아보세요.

Learn more about srcset and sizes on web.dev and mdn.

quality

최적화된 이미지의 품질을 설정하는 1에서 100 사이의 정수입니다. 값이 높을수록 파일 크기와 시각적 충실도가 높아집니다. 값이 낮을수록 파일 크기는 줄어들지만 선명도가 떨어질 수 있습니다.

An integer between 1 and 100 that sets the quality of the optimized image. Higher values increase file size and visual fidelity. Lower values reduce file size but may affect sharpness.

// Default quality is 75
<Image quality={75} />

next.config.js에 qualities를 설정했다면, 그 목록에 없는 값은 허용된 값 중 가장 가까운 값으로 강제 변환됩니다. 예를 들어 qualities: [50, 75, 100]일 때 quality가 80이면 75로 제공됩니다. 개발 중에는 warning을 log로 남기므로 해당 값을 allowlist에 추가할 수 있습니다.

If you’ve configured qualities in next.config.js, a value outside that list is coerced to the closest allowed entry. For example, with qualities: [50, 75, 100], a quality of 80 is served as 75. Development logs a warning so you can add the value to the allowlist.

Good to know

원본 이미지가 이미 저품질이라면, 높은 quality 값을 설정해도 보기에는 나아지지 않고 파일 크기만 커집니다.

If the original image is already low quality, setting a high quality value will increase the file size without improving appearance.

style

내부 image element에 CSS style을 전달할 수 있게 합니다.

Allows passing CSS styles to the underlying image element.

const imageStyle = {
  borderRadius: '50%',
  border: '1px solid #fff',
  width: '100px',
  height: 'auto',
}

export default function ProfileImage() {
  return <Image src="..." style={imageStyle} />

Good to know

style prop으로 custom width를 설정한다면, 이미지의 aspect ratio를 유지하기 위해 height: 'auto'도 함께 설정하세요.

If you’re using the style prop to set a custom width, be sure to also set height: 'auto' to preserve the image’s aspect ratio.

preload

이미지를 preload할지 여부를 나타내는 boolean입니다.

A boolean that indicates if the image should be preloaded.

// Default preload is false
<Image preload={false} />
  • true: <head>에 <link>를 삽입해 이미지를 preload합니다.
  • false: 이미지를 preload하지 않습니다.
  • true: Preloads the image by inserting a <link> in the <head>.
  • false: Does not preload the image.

사용해야 할 때:

When to use it:

  • 이미지가 Largest Contentful Paint (LCP) element인 경우.
  • 이미지가 above the fold(스크롤 없이 보이는 영역)에 있는 경우, 보통 hero 이미지.
  • 이미지가 나중에 <body>에서 발견되기 전에 <head>에서 로딩을 시작하고 싶은 경우.
  • The image is the Largest Contentful Paint (LCP) element.
  • The image is above the fold, typically the hero image.
  • You want to begin loading the image in the <head>, before its discovered later in the <body>.

사용하지 말아야 할 때:

When not to use it:

  • viewport에 따라 Largest Contentful Paint (LCP) element로 간주될 수 있는 이미지가 여러 개인 경우.
  • loading property를 사용하는 경우.
  • fetchPriority property를 사용하는 경우.
  • When you have multiple images that could be considered the Largest Contentful Paint (LCP) element depending on the viewport.
  • When the loading property is used.
  • When the fetchPriority property is used.

대부분의 경우 preload 대신 loading="eager" 또는 fetchPriority="high"를 사용해야 합니다.

In most cases, you should use loading="eager" or fetchPriority="high" instead of preload.

priority

Next.js 16부터는 동작을 명확히 하기 위해 priority property가 deprecated되었고 preload property로 대체되었습니다.

Starting with Next.js 16, the priority property has been deprecated in favor of the preload property in order to make the behavior clear.

loading

이미지가 언제 로딩을 시작할지 제어합니다.

Controls when the image should start loading.

// Defaults to lazy
<Image loading="lazy" />
  • lazy: 이미지가 viewport로부터 계산된 거리에 도달할 때까지 로딩을 미룹니다.
  • eager: 페이지 내 위치와 관계없이 이미지를 즉시 로드합니다.
  • lazy: Defer loading the image until it reaches a calculated distance from the viewport.
  • eager: Load the image immediately, regardless of its position in the page.

이미지가 즉시 로드되도록 보장하고 싶을 때만 eager를 사용하세요.

Use eager only when you want to ensure the image is loaded immediately.

placeholder

이미지를 불러오는 동안 사용할 placeholder를 지정해 체감 로딩 성능을 개선합니다.

Specifies a placeholder to use while the image is loading, improving the perceived loading performance.

// defaults to empty
<Image placeholder="empty" />

blurDataURL

이미지가 성공적으로 로드되기 전에 placeholder 이미지로 사용할 Data URL입니다. 자동으로 설정되거나 placeholder="blur" property와 함께 사용할 수 있습니다.

A Data URL to be used as a placeholder image before the image successfully loads. Can be automatically set or used with the placeholder="blur" property.

<Image placeholder="blur" blurDataURL="..." />

이미지는 자동으로 확대되고 흐리게 처리되므로, 아주 작은 이미지(10px 이하)를 권장합니다.

The image is automatically enlarged and blurred, so a very small image (10px or less) is recommended.

onLoad

이미지가 완전히 로드되고 placeholder가 제거된 후 호출되는 callback 함수입니다.

A callback function that is invoked once the image is completely loaded and the placeholder has been removed.

<Image onLoad={(e) => console.log(e.target.naturalWidth)} />

callback 함수는 하나의 인자, 즉 내부 <img> element를 참조하는 target을 가진 event와 함께 호출됩니다.

The callback function will be called with one argument, the event which has a target that references the underlying <img> element.

onError

이미지 로드에 실패하면 호출되는 callback 함수입니다.

A callback function that is invoked if the image fails to load.

unoptimized

이미지를 최적화할지 여부를 나타내는 boolean입니다. 작은 이미지(1KB 미만), vector 이미지(SVG), 애니메이션 이미지(GIF)처럼 최적화의 이점이 없는 이미지에 유용합니다.

A boolean that indicates if the image should be optimized. This is useful for images that do not benefit from optimization such as small images (less than 1KB), vector images (SVG), or animated images (GIF).

import Image from 'next/image'

const UnoptimizedImage = (props) => {
  // Default is false
  return <Image {...props} unoptimized />
}
  • true: quality, 크기, format을 바꾸지 않고 source 이미지를 src에서 그대로 제공합니다.
  • false: source 이미지를 최적화합니다.
  • true: The source image will be served as-is from the src instead of changing quality, size, or format.
  • false: The source image will be optimized.

Next.js 12.3.0부터는 next.config.js를 다음 설정으로 업데이트해 모든 이미지에 이 prop을 지정할 수 있습니다:

Since Next.js 12.3.0, this prop can be assigned to all images by updating next.config.js with the following configuration:

JSnext.config.js
module.exports = {
  images: {
    unoptimized: true,
  },
}

overrideSrc

<Image> component에 src prop을 제공하면, 결과로 만들어지는 <img>에 srcset과 src attribute가 모두 자동으로 생성됩니다.

When providing the src prop to the <Image> component, both the srcset and src attributes are generated automatically for the resulting <img>.

JSinput.js
<Image src="/profile.jpg" />
output.html
<img
  srcset="
    /_next/image?url=%2Fprofile.jpg&w=640&q=75 1x,
    /_next/image?url=%2Fprofile.jpg&w=828&q=75 2x
  "
  src="/_next/image?url=%2Fprofile.jpg&w=828&q=75"
/>

경우에 따라 src attribute가 생성되는 것이 바람직하지 않을 수 있으며, 이때 overrideSrc prop으로 이를 override할 수 있습니다.

In some cases, it is not desirable to have the src attribute generated and you may wish to override it using the overrideSrc prop.

예를 들어 기존 웹사이트를 <img>에서 <Image>로 업그레이드할 때, 이미지 순위 유지나 recrawl 방지 같은 SEO 목적으로 동일한 src attribute를 유지하고 싶을 수 있습니다.

For example, when upgrading an existing website from <img> to <Image>, you may wish to maintain the same src attribute for SEO purposes such as image ranking or avoiding recrawl.

JSinput.js
<Image src="/profile.jpg" overrideSrc="/override.jpg" />
output.html
<img
  srcset="

다른 콘텐츠 업데이트를 표시하기 전에 이미지가 decode될 때까지 기다려야 하는지를 브라우저에 알려 주는 hint입니다.

A hint to the browser indicating if it should wait for the image to be decoded before presenting other content updates or not.

// Default is async

  • async: 이미지를 비동기로 decode하고, 완료되기 전에 다른 콘텐츠가 렌더링되도록 허용합니다.
  • sync: 다른 콘텐츠와 함께 원자적으로(atomic) 표시되도록 이미지를 동기로 decode합니다.

  • sync: Synchronously decode the image for atomic presentation with other content.

Configuration options설정 옵션

next.config.js에서 Image Component를 설정할 수 있습니다. 사용할 수 있는 옵션은 다음과 같습니다:

You can configure the Image Component in next.config.js. The following options are available:

localPatterns

next.config.js 파일에서 localPatterns를 사용해 특정 로컬 경로의 이미지만 최적화하도록 허용하고 나머지는 모두 차단합니다.

Use localPatterns in your next.config.js file to allow images from specific local paths to be optimized and block all others.

JSnext.config.js
module.exports = {
  images: {
    localPatterns: [
      {
        pathname: '/assets/images/**',
        search: '',
      },
    ],
  },
}

위 예시는 next/image의 src property가 반드시 /assets/images/로 시작하고 query string이 없도록 보장합니다. 다른 경로를 최적화하려고 하면 400 Bad Request 오류로 응답합니다.

The example above will ensure the src property of next/image must start with /assets/images/ and must not have a query string. Attempting to optimize any other path will respond with 400 Bad Request error.

Good to know

search property를 생략하면 모든 search parameter가 허용되어, 악의적인 사용자가 의도하지 않은 URL을 최적화할 수 있게 됩니다. 정확히 일치하도록 search: '?v=2' 같은 구체적인 값을 사용해 보세요.

Omitting the search property allows all search parameters which could allow malicious actors to optimize URLs you did not intend. Try using a specific value like search: '?v=2' to ensure an exact match.

remotePatterns

next.config.js 파일에서 remotePatterns를 사용해 특정 외부 경로의 이미지만 허용하고 나머지는 모두 차단합니다. 이렇게 하면 내 account의 외부 이미지만 제공되도록 보장할 수 있습니다.

Use remotePatterns in your next.config.js file to allow images from specific external paths and block all others. This ensures that only external images from your account can be served.

JSnext.config.js
module.exports = {
  images: {
    remotePatterns: [new URL('https://example.com/account123/**')],
  },
}

object를 사용해 remotePatterns를 설정할 수도 있습니다:

You can also configure remotePatterns using the object:

JSnext.config.js
module.exports = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'example.com',
        port: '',
        pathname: '/account123/**',
        search: '',
      },
    ],
  },
}

위 예시는 next/image의 src property가 반드시 https://example.com/account123/로 시작하고 query string이 없도록 보장합니다. 그 외의 protocol, hostname, port, 또는 일치하지 않는 경로는 400 Bad Request로 응답합니다.

The example above will ensure the src property of next/image must start with https://example.com/account123/ and must not have a query string. Any other protocol, hostname, port, or unmatched path will respond with 400 Bad Request.

Wildcard Patterns:

Wildcard Patterns:

Wildcard pattern은 pathname과 hostname 모두에 사용할 수 있으며 문법은 다음과 같습니다:

Wildcard patterns can be used for both pathname and hostname and have the following syntax:

  • *는 하나의 path segment 또는 subdomain과 일치합니다
  • **는 끝부분의 여러 path segment 또는 앞부분의 여러 subdomain과 일치합니다. 이 문법은 pattern의 중간에서는 동작하지 않습니다.
  • * match a single path segment or subdomain
  • ** match any number of path segments at the end or subdomains at the beginning. This syntax does not work in the middle of the pattern.
JSnext.config.js
module.exports = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: '**.example.com',
        port: '',
        search: '',
      },
    ],
  },
}

이렇게 하면 image.example.com 같은 subdomain이 허용됩니다. query string과 custom port는 여전히 차단됩니다.

This allows subdomains like image.example.com. Query strings and custom ports are still blocked.

Good to know

protocol, port, pathname, search를 생략하면 wildcard **가 적용된 것으로 간주됩니다. 악의적인 사용자가 의도하지 않은 url을 최적화할 수 있으므로 권장하지 않습니다.

When omitting protocol, port, pathname, or search then the wildcard ** is implied. This is not recommended because it may allow malicious actors to optimize urls you did not intend.

Query Strings:

Query Strings:

search property를 사용해 query string을 제한할 수도 있습니다:

You can also restrict query strings using the search property:

JSnext.config.js
module.exports = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'assets.example.com',
        search: '?v=1727111025337',
      },
    ],
  },
}

위 예시는 next/image의 src property가 반드시 https://assets.example.com으로 시작하고 정확히 ?v=1727111025337 query string을 갖도록 보장합니다. 그 외의 protocol이나 query string은 400 Bad Request로 응답합니다.

The example above will ensure the src property of next/image must start with https://assets.example.com and must have the exact query string ?v=1727111025337. Any other protocol or query string will respond with 400 Bad Request.

허용된 remotePatterns가 redirect로 응답하는 경우, redirect 위치에 대해 remotePatterns를 다시 검증하지 않고 remote 이미지 서버의 redirect를 따라간다는 점에 유의하세요. maximumRedirects를 설정해 redirect를 줄이거나 비활성화할 수 있습니다.

Note that any allowed remotePatterns that respond with a redirect will follow the redirect from the remote image server without validating remotePatterns again on the redirect location. You can reduce or disable redirects by configuring maximumRedirects.

deviceSizes allows you to specify a list of device width breakpoints. These widths are used when the next/image component uses the sizes prop, or the fill prop without sizes, to ensure the correct image is served for the user's device.

설정을 제공하지 않으면 아래 기본값이 사용됩니다:

JSnext.config.js
module.exports = {

imageSizes로 이미지 width 목록을 지정할 수 있습니다. 이 width들은 device sizes 배열과 이어 붙여져, 이미지 srcset을 생성하는 데 쓰이는 전체 크기 배열을 구성합니다.

imageSizes allows you to specify a list of image widths. These widths are concatenated with the array of device sizes to form the full array of sizes used to generate image srcset.

설정을 제공하지 않으면 아래 기본값이 사용됩니다:

If no configuration is provided, the default below is used:

JSnext.config.js
module.exports = {
  images: {
    imageSizes: [32, 48, 64, 96, 128, 256, 384],
  },
}

imageSizes는 sizes prop을 제공하는 이미지에만 사용되며, 이는 이미지가 화면 전체 width보다 작다는 것을 의미합니다. 따라서 imageSizes의 크기는 모두 deviceSizes의 가장 작은 크기보다 작아야 합니다.

qualities allows you to specify a list of image quality values.

module.exports = {

위 예시에서는 25, 50, 75, 100 네 가지 quality만 허용됩니다.

이 배열의 값과 일치하지 않는 quality로 REST API에 직접 접근하면, 서버는 400 Bad Request response를 반환합니다.

formats

formats로 사용할 이미지 format 목록을 지정할 수 있습니다.

formats allows you to specify a list of image formats to be used.

JSnext.config.js
module.exports = {
  images: {
    // Default
    formats: ['image/webp'],
  },
}

Next.js는 최적의 출력 format을 결정하기 위해 request의 Accept header를 통해 브라우저가 지원하는 이미지 format을 자동으로 감지합니다.

Next.js automatically detects the browser's supported image formats via the request's Accept header in order to determine the best output format.

Accept header가 설정된 format 중 둘 이상과 일치하면 배열에서 첫 번째로 일치하는 것이 사용됩니다. 따라서 배열 순서가 중요합니다. 일치하는 것이 없거나(또는 source 이미지가 애니메이션이면) 원본 이미지의 format을 사용합니다.

If the Accept header matches more than one of the configured formats, the first match in the array is used. Therefore, the array order matters. If there is no match (or the source image is animated), it will use the original image's format.

AVIF 지원을 활성화할 수 있으며, 브라우저가 AVIF를 지원하지 않으면 src 이미지의 원본 format으로 fallback합니다:

You can enable AVIF support, which will fallback to the original format of the src image if the browser does not support AVIF:

JSnext.config.js
module.exports = {
  images: {
    formats: ['image/avif'],
  },
}

AVIF와 WebP format을 함께 활성화할 수도 있습니다. AVIF를 지원하는 브라우저에서는 AVIF가 우선 사용되고, WebP가 fallback이 됩니다:

You can also enable both AVIF and WebP formats together. AVIF will be preferred for browsers that support it, with WebP as a fallback:

JSnext.config.js
module.exports = {
  images: {
    formats: ['image/avif', 'image/webp'],
  },
}
Good to know
  • 대부분의 경우에는 여전히 WebP 사용을 권장합니다.
  • AVIF는 일반적으로 encode하는 데 50% 더 오래 걸리지만 WebP보다 20% 더 작게 압축됩니다. 즉, 이미지를 처음 request할 때는 보통 더 느리지만, cache된 이후의 request는 더 빠릅니다.
  • 여러 format을 사용하면 Next.js는 각 format을 따로 cache합니다. 서로 다른 브라우저 지원을 위해 이미지의 AVIF 버전과 WebP 버전이 모두 저장되므로, 단일 format을 사용할 때보다 저장 공간이 더 필요합니다.
  • Next.js 앞단에 Proxy/CDN을 두고 self-host한다면, Proxy가 Accept header를 전달하도록 설정해야 합니다.
  • We still recommend using WebP for most use cases.
  • AVIF generally takes 50% longer to encode but it compresses 20% smaller compared to WebP. This means that the first time an image is requested, it will typically be slower, but subsequent requests that are cached will be faster.
  • When using multiple formats, Next.js will cache each format separately. This means increased storage requirements compared to using a single format, as both AVIF and WebP versions of images will be stored for different browser support.
  • If you self-host with a Proxy/CDN in front of Next.js, you must configure the Proxy to forward the Accept header.

minimumCacheTTL

minimumCacheTTL로 cache된 최적화 이미지의 TTL(Time to Live)을 초 단위로 설정할 수 있습니다. 많은 경우 파일 내용을 자동으로 hash하고 수명이 긴 immutable Cache-Control header로 이미지를 cache하는 Static Image Import를 사용하는 편이 더 좋습니다.

minimumCacheTTL allows you to configure the Time to Live (TTL) in seconds for cached optimized images. In many cases, it's better to use a Static Image Import which will automatically hash the file contents and cache the image with a long-lived immutable Cache-Control header.

설정을 제공하지 않으면 아래 기본값이 사용됩니다.

If no configuration is provided, the default below is used.

JSnext.config.js
module.exports = {
  images: {
    minimumCacheTTL: 14400, // 4 hours
  },
}

TTL을 늘려 revalidation 횟수를 줄이고 비용을 낮출 수 있습니다:

You can increase the TTL to reduce the number of revalidations and potentially lower cost:

JSnext.config.js
module.exports = {
  images: {
    minimumCacheTTL: 2678400, // 31 days
  },
}

최적화된 이미지의 만료(정확히는 Max Age)는 minimumCacheTTL과 upstream 이미지의 Cache-Control header 중 더 큰 값으로 정의됩니다.

The expiration (or rather Max Age) of the optimized image is defined by either the minimumCacheTTL or the upstream image Cache-Control header, whichever is larger.

이미지별로 caching 동작을 바꿔야 한다면, headers를 설정해 upstream 이미지(예: /_next/image 자체가 아니라 /some-asset.jpg)에 Cache-Control header를 지정할 수 있습니다.

If you need to change the caching behavior per image, you can configure headers to set the Cache-Control header on the upstream image (e.g. /some-asset.jpg, not /_next/image itself).

현재는 cache를 무효화하는 방법이 없으므로 minimumCacheTTL을 낮게 유지하는 것이 좋습니다. 그렇지 않으면 src prop을 수동으로 바꾸거나 cache된 파일 <distDir>/cache/images를 삭제해야 할 수 있습니다.

There is no mechanism to invalidate the cache at this time, so its best to keep minimumCacheTTL low. Otherwise you may need to manually change the src prop or delete the cached file <distDir>/cache/images.

maximumDiskCacheSize

기본 이미지 최적화 loader는 최적화된 이미지를 disk에 기록하여, 이후의 request를 disk cache에서 더 빠르게 제공할 수 있게 합니다.

The default image optimization loader will write optimized images to disk so subsequent requests can be served faster from the disk cache.

최대 disk cache 크기를 byte 단위로 설정할 수 있습니다. 예를 들어 500 MB는 다음과 같습니다:

You can configure the maximum disk cache size in bytes, for example 500 MB:

JSnext.config.js
module.exports = {
  images: {
    maximumDiskCacheSize: 500_000_000,
  },
}

값을 0으로 설정해 disk cache를 완전히 비활성화할 수도 있습니다.

You can also disable the disk cache entirely by setting the value to 0.

JSnext.config.js
module.exports = {
  images: {
    maximumDiskCacheSize: 0,
  },
}

값을 설정하지 않으면, 기본 동작은 시작 시 한 번 현재 사용 가능한 disk 공간을 확인하고 그 50%를 사용하는 것입니다.

If no value is configured, the default behavior is to check the current available disk space once during startup and use 50%.

disk cache가 설정된 크기를 초과하면, cache가 다시 한도 아래로 내려갈 때까지 가장 오래 사용되지 않은(least recently used) 최적화 이미지가 삭제됩니다.

When the disk cache exceeds the configured size, the least recently used optimized images will be deleted until the cache is under the limit again.

또는 cacheHandler를 사용해 직접 cache handler를 구현할 수 있으며, 이 경우 maximumDiskCacheSize 설정은 무시됩니다.

Alternatively, you can implement your own cache handler using cacheHandler which will ignore the maximumDiskCacheSize configuration.

dangerouslyAllowSVG

기본적으로 Next.js는 몇 가지 이유로 SVG 이미지를 최적화하지 않습니다:

By default, Next.js does not optimize SVG images for a few reasons:

  • SVG는 vector format이므로 손실 없이 크기를 조정할 수 있습니다.
  • SVG는 HTML/CSS와 동일한 기능을 많이 가지고 있어, 적절한 Content Security Policy (CSP) headers 없이는 취약점으로 이어질 수 있습니다.
  • SVG is a vector format meaning it can be resized losslessly.
  • SVG has many of the same features as HTML/CSS, which can lead to vulnerabilities without proper Content Security Policy (CSP) headers.

src prop이 SVG임을 알고 있다면 unoptimized prop 사용을 권장합니다. src가 ".svg"로 끝나면 이는 자동으로 적용됩니다.

We recommend using the unoptimized prop when the src prop is known to be SVG. This happens automatically when src ends with ".svg".

<Image src="/my-image.svg" unoptimized />

Art direction

모바일과 데스크톱에서 서로 다른 이미지를 표시하고 싶다면(이를 Art Direction이라고도 합니다), getImageProps()에 서로 다른 src, width, height, quality props를 제공할 수 있습니다.

If you want to display a different image for mobile and desktop, sometimes called Art Direction, you can provide different src, width, height, and quality props to getImageProps().

JSapp/page.js
import { getImageProps } from 'next/image'

export default function Home() {
  const common = { alt: 'Art Direction Example', sizes: '100vw' }
  const {
    props: { srcSet: desktop },
  } = getImageProps({
    ...common,
    width: 1440,
    height: 875,
    quality: 80,
    src: '/desktop.jpg',
  })
  const {
    props: { srcSet: mobile, ...rest },
  } = getImageProps({
    ...common,
    width: 750,
    height: 1334,
    quality: 70,
    src: '/mobile.jpg',
  })

  return (
    <picture>
      <source media="(min-width: 1000px)" srcSet={desktop} />
      <source media="(min-width: 500px)" srcSet={mobile} />
      <img {...rest} style={{ width: '100%', height: 'auto' }} />
    </picture>
  )
}

Background CSS

srcSet 문자열을 image-set() CSS 함수로 변환해 배경 이미지를 최적화할 수도 있습니다.

You can even convert the srcSet string to the image-set() CSS function to optimize a background image.

JSapp/page.js
import { getImageProps } from 'next/image'

function getBackgroundImage(srcSet = '') {
  const imageSet = srcSet
    .split(', ')
    .map((str) => {
      const [url, dpi] = str.split(' ')
      return `url("${url}") ${dpi}`
    })
    .join(', ')
  return `image-set(${imageSet})`
}

export default function Home() {
  const {
    props: { srcSet },
  } = getImageProps({ alt: '', width: 128, height: 128, src: '/img.png' })
  const backgroundImage = getBackgroundImage(srcSet)
  const style = { height: '100vh', width: '100vw', backgroundImage }

  return (
    <main style={style}>
      <h1>Hello World</h1>
    </main>
  )
