Metadata and OG imagesMetadata와 OG 이미지

Metadata API를 사용하면 SEO와 웹 공유성(web shareability)을 높이기 위해 애플리케이션의 metadata를 정의할 수 있으며, 다음이 포함됩니다:

The Metadata APIs can be used to define your application metadata for improved SEO and web shareability and include:

  1. static metadata 객체
  2. dynamic generateMetadata 함수
  3. static 또는 동적으로 생성되는 favicon과 OG 이미지를 추가하는 데 쓸 수 있는 특수한 file convention.
  1. The static metadata object
  2. The dynamic generateMetadata function
  3. Special file conventions that can be used to add static or dynamically generated favicons and OG images.

위의 모든 option에 대해 Next.js는 페이지에 맞는 <head> tag를 자동으로 생성하며, 이는 브라우저의 개발자 도구에서 확인할 수 있습니다.

With all the options above, Next.js will automatically generate the relevant <head> tags for your page, which can be inspected in the browser's developer tools.

metadata 객체와 generateMetadata 함수 export는 Server Component에서만 지원됩니다.

The metadata object and generateMetadata function exports are only supported in Server Components.

Default fields기본 field

route가 metadata를 정의하지 않더라도 항상 추가되는 기본 meta tag가 두 개 있습니다:

There are two default meta tags that are always added even if a route doesn't define metadata:

  • meta charset tag는 웹사이트의 character encoding을 설정합니다.
  • meta viewport tag는 다양한 기기에 맞출 수 있도록 웹사이트의 viewport 너비와 배율(scale)을 설정합니다.
  • The meta charset tag sets the character encoding for the website.
  • The meta viewport tag sets the viewport width and scale for the website to adjust for different devices.
<meta charset="utf-8" />
<meta name="viewport" content="width=device-width, initial-scale=1" />

나머지 metadata field는 Metadata 객체(static metadata용) 또는 generateMetadata 함수(generated metadata용)로 정의할 수 있습니다.

The other metadata fields can be defined with the Metadata object (for static metadata) or the generateMetadata function (for generated metadata).

Static metadata

static metadata를 정의하려면 static layout.js 또는 page.js 파일에서 Metadata 객체를 export하세요. 예를 들어 blog route에 title과 description을 추가하려면 다음과 같이 합니다:

To define static metadata, export a Metadata object from a static layout.js or page.js file. For example, to add a title and description to the blog route:

TSJSapp/blog/layout.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'My Blog',
  description: '...',
}

export default function Layout() {}
export const metadata = {
  title: 'My Blog',
  description: '...',
}

export default function Layout() {}

사용 가능한 option의 전체 목록은 generateMetadata 문서에서 볼 수 있습니다.

You can view a full list of available options, in the generateMetadata documentation.

Generated metadata

generateMetadata 함수를 사용하면 data에 의존하는 metadata를 fetch할 수 있습니다. 예를 들어 특정 blog post의 title과 description을 fetch하려면 다음과 같이 합니다:

You can use generateMetadata function to fetch metadata that depends on data. For example, to fetch the title and description for a specific blog post:

TSJSapp/blog/[slug]/page.tsx
import type { Metadata, ResolvingMetadata } from 'next'

type Props = {
  params: Promise<{ slug: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}

export async function generateMetadata(
  { params, searchParams }: Props,
  parent: ResolvingMetadata
): Promise<Metadata> {
  const slug = (await params).slug

  // fetch post information
  const post = await fetch(`https://api.vercel.app/blog/${slug}`).then((res) =>
    res.json()
  )

  return {
    title: post.title,
    description: post.description,
  }
}

export default function Page({ params, searchParams }: Props) {}
export async function generateMetadata({ params, searchParams }, parent) {
  const slug = (await params).slug

  // fetch post information
  const post = await fetch(`https://api.vercel.app/blog/${slug}`).then((res) =>
    res.json()
  )

  return {
    title: post.title,
    description: post.description,
  }
}

export default function Page({ params, searchParams }) {}

Streaming metadata

동적으로 rendering되는 페이지의 경우, Next.js는 metadata를 따로 stream하여 generateMetadata가 resolve되면 UI rendering을 막지 않고 HTML에 주입합니다.

For dynamically rendered pages, Next.js streams metadata separately, injecting it into the HTML once generateMetadata resolves, without blocking UI rendering.

Streaming metadata는 시각적 콘텐츠가 먼저 stream되도록 해 체감 성능(perceived performance)을 높여 줍니다.

Streaming metadata improves perceived performance by allowing visual content to stream first.

Streaming metadata는 metadata가 <head> tag 안에 있기를 기대하는 bot과 crawler에 대해서는 비활성화됩니다 (예: Twitterbot, Slackbot, Bingbot). 이들은 들어오는 request의 User Agent header로 감지합니다.

Streaming metadata is disabled for bots and crawlers that expect metadata to be in the <head> tag (e.g. Twitterbot, Slackbot, Bingbot). These are detected by using the User Agent header from the incoming request.

Next.js config 파일의 htmlLimitedBots option으로 streaming metadata를 customize하거나 완전히 비활성화(disable) 할 수 있습니다.

You can customize or disable streaming metadata completely, with the htmlLimitedBots option in your Next.js config file.

Prerender된 페이지는 metadata가 build 시점에 resolve되므로 streaming을 사용하지 않습니다.

Prerendered pages don’t use streaming since metadata is resolved at build time.

streaming metadata에 대해 더 알아보세요.

Learn more about streaming metadata.

Memoizing data requestsdata request memoize하기

metadata와 페이지 자체에 같은 data를 fetch해야 하는 경우가 있을 수 있습니다. 중복 request를 피하려면 React의 cache 함수로 반환값을 memoize하여 data를 한 번만 fetch할 수 있습니다. 예를 들어 metadata와 페이지 양쪽에서 blog post 정보를 fetch하려면 다음과 같이 합니다:

There may be cases where you need to fetch the same data for metadata and the page itself. To avoid duplicate requests, you can use React's cache function to memoize the return value and only fetch the data once. For example, to fetch the blog post information for both the metadata and the page:

TSJSapp/lib/data.ts
import { cache } from 'react'
import { db } from '@/app/lib/db'

// getPost will be used twice, but execute only once
export const getPost = cache(async (slug: string) => {
  const res = await db.query.posts.findFirst({ where: eq(posts.slug, slug) })
  return res
})

  return res

import { getPost } from '@/app/lib/data'

export async function generateMetadata({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await getPost(slug)
  return {
    title: post.title,
    description: post.description,
  }
}

export default async function Page({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await getPost(slug)
  return <div>{post.title}</div>
}

File-based metadata파일 기반 metadata

metadata용으로 다음 특수 파일을 사용할 수 있습니다:

The following special files are available for metadata:

  • favicon.ico, apple-icon.jpg, icon.jpg
  • opengraph-image.jpg, twitter-image.jpg
  • robots.txt
  • sitemap.xml
  • favicon.ico, apple-icon.jpg, and icon.jpg
  • opengraph-image.jpg and twitter-image.jpg
  • robots.txt
  • sitemap.xml

이 파일들을 static metadata로 사용할 수도 있고, 코드로 프로그래밍 방식으로 생성할 수도 있습니다.

You can use these for static metadata, or you can programmatically generate these files with code.

Favicons

Favicon은 bookmark와 검색 결과에서 사이트를 나타내는 작은 아이콘입니다. 애플리케이션에 favicon을 추가하려면 favicon.ico를 만들어 app 폴더의 root에 넣으세요.

Favicons are small icons that represent your site in bookmarks and search results. To add a favicon to your application, create a favicon.ico and add to the root of the app folder.

코드로 favicon을 프로그래밍 방식으로 생성할 수도 있습니다. 자세한 내용은 favicon 문서를 참고하세요.

You can also programmatically generate favicons using code. See the favicon docs for more information.

Static Open Graph imagesStatic Open Graph 이미지

Open Graph(OG) 이미지는 소셜 미디어에서 사이트를 나타내는 이미지입니다. 애플리케이션에 static OG 이미지를 추가하려면 app 폴더의 root에 opengraph-image.jpg 파일을 만드세요.

Open Graph (OG) images are images that represent your site in social media. To add a static OG image to your application, create a opengraph-image.jpg file in the root of the app folder.

폴더 구조의 더 깊은 곳에 opengraph-image.jpg를 만들어 특정 route용 OG 이미지를 추가할 수도 있습니다. 예를 들어 /blog route 전용 OG 이미지를 만들려면 blog 폴더 안에 opengraph-image.jpg 파일을 추가하세요.

You can also add OG images for specific routes by creating a opengraph-image.jpg deeper down the folder structure. For example, to create an OG image specific to the /blog route, add a opengraph-image.jpg file inside the blog folder.

더 구체적인 이미지가 폴더 구조상 그 위에 있는 OG 이미지보다 우선합니다.

The more specific image will take precedence over any OG images above it in the folder structure.

jpeg, png, gif 같은 다른 이미지 형식도 지원됩니다. 자세한 내용은 Open Graph Image 문서를 참고하세요.

Other image formats such as jpeg, png, and gif are also supported. See the Open Graph Image docs for more information.

Generated Open Graph images생성된 Open Graph 이미지

ImageResponse constructor를 사용하면 JSX와 CSS로 dynamic 이미지를 생성할 수 있습니다. 이는 data에 의존하는 OG 이미지에 유용합니다.

The ImageResponse constructor allows you to generate dynamic images using JSX and CSS. This is useful for OG images that depend on data.

예를 들어 blog post마다 고유한 OG 이미지를 생성하려면 blog/[slug] 폴더 안에 opengraph-image.tsx 파일을 추가하고 next/og에서 ImageResponse constructor를 import하세요:

For example, to generate a unique OG image for each blog post, add an opengraph-image.tsx file inside the blog/[slug] folder, and import the ImageResponse constructor from next/og:

TSJSapp/blog/[slug]/opengraph-image.tsx
import { ImageResponse } from 'next/og'
import { getPost } from '@/app/lib/data'

// Image metadata
export const size = {
  width: 1200,
  height: 630,
}

export const contentType = 'image/png'

// Image generation
export default async function Image({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await getPost(slug)

  return new ImageResponse(
    (
      // ImageResponse JSX element
      <div
        style={{
          fontSize: 128,
          background: 'white',
          width: '100%',
          height: '100%',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        {post.title}
      </div>
    )
  )
}
import { ImageResponse } from 'next/og'
import { getPost } from '@/app/lib/data'

// Image metadata
export const size = {
  width: 1200,
  height: 630,
}

export const contentType = 'image/png'

// Image generation
export default async function Image({ params }) {
  const { slug } = await params
  const post = await getPost(slug)

  return new ImageResponse(
    (
      // ImageResponse JSX element
      <div
        style={{
          fontSize: 128,
          background: 'white',
          width: '100%',
          height: '100%',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        {post.title}
      </div>
    )
  )
}

ImageResponse는 flexbox와 absolute positioning, custom font, text wrapping, 가운데 정렬, 중첩 이미지 등 일반적인 CSS property를 지원합니다. 지원되는 CSS property 전체 목록 보기.

ImageResponse supports common CSS properties including flexbox and absolute positioning, custom fonts, text wrapping, centering, and nested images. See the full list of supported CSS properties.

Good to know
  • 예제는 Vercel OG Playground에서 볼 수 있습니다.
  • ImageResponse는 @vercel/og, satori, resvg를 사용해 HTML과 CSS를 PNG로 변환합니다.
  • flexbox와 일부 CSS property만 지원됩니다. 고급 layout(예: display: grid)은 동작하지 않습니다.
  • Examples are available in the Vercel OG Playground.
  • ImageResponse uses @vercel/og, satori, and resvg to convert HTML and CSS into PNG.
  • Only flexbox and a subset of CSS properties are supported. Advanced layouts (e.g. display: grid) will not work.
