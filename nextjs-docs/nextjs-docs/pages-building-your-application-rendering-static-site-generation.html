page가 Static Generation을 사용하면, page HTML은 build 시점에 생성됩니다. 즉, production에서는 next build를 실행할 때 page HTML이 생성됩니다. 이 HTML은 이후 각 request마다 재사용되며, CDN에 cache될 수 있습니다.

If a page uses Static Generation, the page HTML is generated at build time. That means in production, the page HTML is generated when you run next build. This HTML will then be reused on each request. It can be cached by a CDN.

Next.js에서는 data가 있든 없든 page를 static하게 생성할 수 있습니다. 각 경우를 살펴보겠습니다.

In Next.js, you can statically generate pages with or without data. Let's take a look at each case.

Static Generation without datadata 없는 Static Generation

기본적으로 Next.js는 data를 fetch하지 않고 Static Generation으로 page를 prerender합니다. 예시는 다음과 같습니다:

By default, Next.js prerenders pages using Static Generation without fetching data. Here's an example:

function About() {
  return <div>About</div>
}

export default About

이 page는 prerender를 위해 외부 data를 fetch할 필요가 없다는 점에 주목하세요. 이런 경우 Next.js는 build 중에 page마다 HTML 파일을 하나씩 생성합니다.

Note that this page does not need to fetch any external data to be prerendered. In cases like this, Next.js generates a single HTML file per page during build time.

Static Generation with datadata가 있는 Static Generation

어떤 page는 prerender를 위해 외부 data를 fetch해야 합니다. 두 가지 시나리오가 있으며, 둘 중 하나 또는 둘 다 해당될 수 있습니다. 각 경우에 Next.js가 제공하는 다음 함수를 사용할 수 있습니다:

Some pages require fetching external data for prerendering. There are two scenarios, and one or both might apply. In each case, you can use these functions that Next.js provides:

  1. page content가 외부 data에 의존하는 경우: getStaticProps를 사용하세요.
  2. page paths가 외부 data에 의존하는 경우: getStaticPaths를 사용하세요(보통 getStaticProps와 함께 사용).
  1. Your page content depends on external data: Use getStaticProps.
  2. Your page paths depend on external data: Use getStaticPaths (usually in addition to getStaticProps).

Scenario 1: Your page content depends on external data시나리오 1: page content가 외부 data에 의존하는 경우

예시: 블로그 page에서 CMS(content management system)로부터 블로그 글 목록을 fetch해야 할 수 있습니다.

Example: Your blog page might need to fetch the list of blog posts from a CMS (content management system).

// TODO: Need to fetch `posts` (by calling some API endpoint)
//       before this page can be prerendered.
export default function Blog({ posts }) {
  return (
    <ul>
      {posts.map((post) => (
        <li>{post.title}</li>
      ))}
    </ul>
  )
}

prerender 시 이 data를 fetch할 수 있도록, Next.js에서는 같은 파일에서 getStaticProps라는 async 함수를 export할 수 있습니다. 이 함수는 build 시점에 호출되며, prerender 시 fetch한 data를 page의 props로 전달할 수 있게 해 줍니다.

To fetch this data on prerender, Next.js allows you to export an async function called getStaticProps from the same file. This function gets called at build time and lets you pass fetched data to the page's props on prerender.

export default function Blog({ posts }) {
  // Render posts...
}

// This function gets called at build time
export async function getStaticProps() {
  // Call an external API endpoint to get posts
  const res = await fetch('https://.../posts')
  const posts = await res.json()

  // By returning { props: { posts } }, the Blog component
  // will receive `posts` as a prop at build time
  return {
    props: {
      posts,
    },
  }
}

getStaticProps의 동작 방식을 더 알아보려면 Data Fetching 문서를 확인하세요.

To learn more about how getStaticProps works, check out the Data Fetching documentation.

Scenario 2: Your page paths depend on external data시나리오 2: page path가 외부 data에 의존하는 경우

Next.js에서는 dynamic route를 가진 page를 만들 수 있습니다. 예를 들어 pages/posts/[id].js라는 파일을 만들어 id에 따라 블로그 글 하나를 보여 줄 수 있습니다. 그러면 posts/1에 접근했을 때 id: 1인 블로그 글을 보여 줄 수 있습니다.

Next.js allows you to create pages with dynamic routes. For example, you can create a file called pages/posts/[id].js to show a single blog post based on id. This will allow you to show a blog post with id: 1 when you access posts/1.

dynamic routing에 대해 더 알아보려면 Dynamic Routing 문서를 확인하세요.

To learn more about dynamic routing, check the Dynamic Routing documentation.

하지만 build 시점에 어떤 id를 prerender할지는 외부 data에 따라 달라질 수 있습니다.

However, which id you want to prerender at build time might depend on external data.

예시: database에 블로그 글을 하나만(id: 1) 추가했다고 가정해 봅시다. 이 경우 build 시점에 posts/1만 prerender하고 싶을 것입니다.

Example: suppose that you've only added one blog post (with id: 1) to the database. In this case, you'd only want to prerender posts/1 at build time.

나중에 id: 2인 두 번째 글을 추가할 수도 있습니다. 그러면 posts/2도 prerender하고 싶을 것입니다.

Later, you might add the second post with id: 2. Then you'd want to prerender posts/2 as well.

따라서 prerender되는 page paths는 외부 data에 의존합니다. 이를 처리하기 위해 Next.js에서는 dynamic page(이 경우 pages/posts/[id].js)에서 getStaticPaths라는 async 함수를 export할 수 있습니다. 이 함수는 build 시점에 호출되며, prerender할 path를 지정할 수 있게 해 줍니다.

So your page paths that are prerendered depend on external data. To handle this, Next.js lets you export an async function called getStaticPaths from a dynamic page (pages/posts/[id].js in this case). This function gets called at build time and lets you specify which paths you want to prerender.

// This function gets called at build time
export async function getStaticPaths() {
  // Call an external API endpoint to get posts
  const res = await fetch('https://.../posts')
  const posts = await res.json()

  // Get the paths we want to prerender based on posts
  const paths = posts.map((post) => ({
    params: { id: post.id },
  }))

  // We'll prerender only these paths at build time.
  // { fallback: false } means other routes should 404.
  return { paths, fallback: false }
}

또한 pages/posts/[id].js에서 getStaticProps도 export해야 이 id에 해당하는 글의 data를 fetch하고 이를 사용해 page를 prerender할 수 있습니다:

Also in pages/posts/[id].js, you need to export getStaticProps so that you can fetch the data about the post with this id and use it to prerender the page:

export default function Post({ post }) {
  // Render post...
}

export async function getStaticPaths() {
  // ...
}

// This also gets called at build time
export async function getStaticProps({ params }) {
  // params contains the post `id`.
  // If the route is like /posts/1, then params.id is 1
  const res = await fetch(`https://.../posts/${params.id}`)
  const post = await res.json()

  // Pass post data to the page via props
  return { props: { post } }
}

getStaticPaths의 동작 방식을 더 알아보려면 Data Fetching 문서를 확인하세요.

To learn more about how getStaticPaths works, check out the Data Fetching documentation.

When should I use Static Generation?Static Generation은 언제 사용해야 하나요?

가능하면 (data가 있든 없든) Static Generation을 사용하는 것을 권장합니다. page를 한 번 build해 CDN으로 제공할 수 있으므로, 모든 request마다 server가 page를 render하는 것보다 훨씬 빠르기 때문입니다.

We recommend using Static Generation (with and without data) whenever possible because your page can be built once and served by CDN, which makes it much faster than having a server render the page on every request.

Static Generation은 다음을 포함한 다양한 종류의 page에 사용할 수 있습니다:

You can use Static Generation for many types of pages, including:

  • 마케팅 page
  • 블로그 글과 포트폴리오
  • E-commerce 상품 목록
  • 도움말과 문서
  • Marketing pages
  • Blog posts and portfolios
  • E-commerce product listings
  • Help and documentation

스스로에게 이렇게 물어보세요: "이 page를 사용자의 request 이전에 prerender할 수 있는가?" 답이 '예'라면 Static Generation을 선택해야 합니다.

You should ask yourself: "Can I prerender this page ahead of a user's request?" If the answer is yes, then you should choose Static Generation.

반면 사용자의 request 이전에 page를 prerender할 수 없다면 Static Generation은 좋은 선택이 아닙니다. page가 자주 업데이트되는 data를 보여 주고, request마다 page content가 바뀔 수도 있습니다.

On the other hand, Static Generation is not a good idea if you cannot prerender a page ahead of a user's request. Maybe your page shows frequently updated data, and the page content changes on every request.

이런 경우에는 다음 중 하나를 할 수 있습니다:

In cases like this, you can do one of the following:

  • Static Generation과 Client-side data fetching을 함께 사용하기: page의 일부는 prerender를 건너뛰고 client-side JavaScript로 채울 수 있습니다. 이 방식에 대해 더 알아보려면 Data Fetching 문서를 확인하세요.
  • Server-Side Rendering 사용하기: Next.js가 각 request마다 page를 prerender합니다. page를 CDN에 cache할 수 없으므로 더 느리지만, prerender된 page는 항상 최신 상태입니다. 이 방식은 아래에서 다룹니다.
  • Use Static Generation with Client-side data fetching: You can skip prerendering some parts of a page and then use client-side JavaScript to populate them. To learn more about this approach, check out the Data Fetching documentation.
  • Use Server-Side Rendering: Next.js prerenders a page on each request. It will be slower because the page cannot be cached by a CDN, but the prerendered page will always be up-to-date. We'll talk about this approach below.
