layout.jslayout.js

layout 파일은 Next.js 애플리케이션에서 layout을 정의하는 데 사용합니다.

The layout file is used to define a layout in your Next.js application.

TSJSapp/dashboard/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return <section>{children}</section>
}
export default function DashboardLayout({ children }) {
  return <section>{children}</section>
}

component hierarchy에서 layout.js는 route segment의 가장 바깥쪽 component입니다. template.js, error.js, loading.js, not-found.js, page.js를 감쌉니다.

In the component hierarchy, layout.js is the outermost component in a route segment. It wraps template.js, error.js, loading.js, not-found.js, and page.js.

root layout은 root app directory의 가장 최상위 layout입니다. <html>과 <body> tag, 그리고 전역으로 공유되는 기타 UI를 정의하는 데 사용합니다.

A root layout is the top-most layout in the root app directory. It is used to define the <html> and <body> tags and other globally shared UI.

TSJSapp/layout.tsx
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}

Reference레퍼런스

Props

children (required)

Layout component는 children prop을 받아서 사용해야 합니다. rendering 중에 children에는 layout이 감싸고 있는 route segment가 채워집니다. 주로 하위 Layout(있는 경우)이나 Page의 component가 되지만, 해당하는 경우 Loading이나 Error 같은 다른 special file일 수도 있습니다.

Layout components should accept and use a children prop. During rendering, children will be populated with the route segments the layout is wrapping. These will primarily be the component of a child Layout (if it exists) or Page, but could also be other special files like Loading or Error when applicable.

params (optional)

root segment부터 해당 layout까지의 dynamic route parameter 객체를 담은 object로 resolve되는 promise입니다.

A promise that resolves to an object containing the dynamic route parameters object from the root segment down to that layout.

TSJSapp/dashboard/[team]/layout.tsx
export default async function Layout({
  children,
  params,
}: {
  children: React.ReactNode
  params: Promise<{ team: string }>
}) {
  const { team } = await params
}
export default async function Layout({ children, params }) {
  const { team } = await params
}

app/shop/[tag]/[item]/layout.js/shop/1/2Promise<{ tag: '1', item: '2' }>
app/blog/[...slug]/layout.js/blog/1/2Promise<{ slug: ['1', '2'] }>

  • params prop은 promise입니다. 값에 접근하려면 async/await 또는 React의 use 함수를 사용해야 합니다.
    • 버전 14 이하에서는 params가 synchronous prop이었습니다. 하위 호환성을 위해 Next.js 15에서도 여전히 synchronous하게 접근할 수 있지만, 이 동작은 앞으로 deprecated될 예정입니다.
  • Since the params prop is a promise. You must use async/await or React's use function to access the values.
    • In version 14 and earlier, params was a synchronous prop. To help with backwards compatibility, you can still access it synchronously in Next.js 15, but this behavior will be deprecated in the future.

Layout Props Helper

LayoutProps로 layout의 type을 지정하면 directory 구조로부터 추론된 strongly typed params와 named slot을 얻을 수 있습니다. LayoutProps는 전역으로 사용할 수 있는 helper입니다.

You can type layouts with LayoutProps to get a strongly typed params and named slots inferred from your directory structure. LayoutProps is a globally available helper.

TSapp/dashboard/layout.tsx
export default function Layout(props: LayoutProps<'/dashboard'>) {
  return (
    <section>
      {props.children}
      {/* If you have app/dashboard/@analytics, it appears as a typed slot: */}
      {/* {props.analytics} */}
    </section>
  )
}
Good to know
  • type은 next dev, next build, 또는 next typegen 중에 생성됩니다.
  • type 생성 후에는 LayoutProps helper를 전역으로 사용할 수 있습니다. import할 필요가 없습니다.
  • Types are generated during next dev, next build or next typegen.
  • After type generation, the LayoutProps helper is globally available. It doesn't need to be imported.

Root Layout

app directory에는 root app directory의 최상위 layout인 root layout이 반드시 있어야 합니다. 일반적으로 root layout은 app/layout.js입니다.

The app directory must include a root layout, which is the top-most layout in the root app directory. Typically, the root layout is app/layout.js.

TSJSapp/layout.tsx
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html>
      <body>{children}</body>
    </html>
  )
}
export default function RootLayout({ children }) {
  return (
    <html>
      <body>{children}</body>
    </html>
  )
}
  • root layout은 <html>과 <body> tag를 반드시 정의해야 합니다.
    • root layout에 <title>, <meta> 같은 <head> tag를 직접 추가하면 안 됩니다. 대신 streaming, <head> element 중복 제거 같은 고급 요구 사항을 자동으로 처리해 주는 Metadata API를 사용하세요.
  • 여러 개의 root layout을 만들 수 있습니다. 위에 layout.js가 없는 layout은 모두 root layout입니다. 흔히 쓰는 두 가지 방법은 다음과 같습니다:
    • app/(shop)/layout.js와 app/(marketing)/layout.js처럼 route group 사용하기
    • app/layout.js를 생략해 app/dashboard/layout.js, app/blog/layout.js 같은 하위 directory의 layout이 각자의 directory에서 root layout이 되게 하기.
    • 여러 root layout을 넘나드는 navigation은 (client-side navigation과 달리) full page load를 일으킵니다.
  • root layout은 dynamic segment 아래에 있을 수 있습니다. 예를 들어 app/[lang]/layout.js로 internationalization을 구현하는 경우입니다. root layout 앞에 있는 dynamic segment는 root parameter이며, next/root-params로 어떤 Server Component에서든 읽을 수 있습니다.
  • The root layout must define <html> and <body> tags.
    • You should not manually add <head> tags such as <title> and <meta> to root layouts. Instead, you should use the Metadata API which automatically handles advanced requirements such as streaming and de-duplicating <head> elements.
  • You can create multiple root layouts. Any layout without a layout.js above it is a root layout. Two common approaches:
    • Using route groups like app/(shop)/layout.js and app/(marketing)/layout.js
    • Omitting app/layout.js so layouts in subdirectories like app/dashboard/layout.js and app/blog/layout.js each become root layouts for their respective directories.
    • Navigating across multiple root layouts will cause a full page load (as opposed to a client-side navigation).
  • The root layout can be under a dynamic segment, for example when implementing internationalization with app/[lang]/layout.js. Dynamic segments before the root layout are root parameters and can be read from any Server Component with next/root-params.

Caveats주의 사항

Request Object

Layout은 불필요한 server request를 피하기 위해 navigation 중 client에 cache됩니다.

Layouts are cached in the client during navigation to avoid unnecessary server requests.

Layout은 rerender되지 않습니다. page 사이를 이동할 때 불필요한 연산을 피하기 위해 cache되고 재사용될 수 있습니다. layout이 raw request에 접근하지 못하게 제한함으로써, Next.js는 performance에 나쁜 영향을 줄 수 있는 느리거나 비용이 큰 사용자 코드가 layout 안에서 실행되는 것을 막을 수 있습니다.

Layouts do not rerender. They can be cached and reused to avoid unnecessary computation when navigating between pages. By restricting layouts from accessing the raw request, Next.js can prevent the execution of potentially slow or expensive user code within the layout, which could negatively impact performance.

request 객체에 접근하려면 Server Component와 Function에서 headers와 cookies API를 사용할 수 있습니다.

To access the request object, you can use headers and cookies APIs in Server Components and Functions.

TSJSapp/shop/layout.tsx
import { cookies } from 'next/headers'

export default async function Layout({ children }) {
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')
  return '...'
}
import { cookies } from 'next/headers'

export default async function Layout({ children }) {
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')
  return '...'
}

Query params

Layout은 navigation 시 rerender되지 않으므로, 그렇지 않으면 오래된(stale) 값이 될 search param에 접근할 수 없습니다.

Layouts do not rerender on navigation, so they cannot access search params which would otherwise become stale.

업데이트된 query parameter에 접근하려면 Page의 searchParams prop을 사용하거나, Client Component 안에서 useSearchParams hook으로 읽을 수 있습니다. Client Component는 navigation 시 re-render되므로 최신 query parameter에 접근할 수 있습니다.

To access updated query parameters, you can use the Page searchParams prop, or read them inside a Client Component using the useSearchParams hook. Since Client Components re-render on navigation, they have access to the latest query parameters.

TSJSapp/ui/search.tsx
'use client'

import { useSearchParams } from 'next/navigation'

export default function Search() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  return '...'
}
'use client'

import { useSearchParams } from 'next/navigation'

export default function Search() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  return '...'
}

Pathname

Layout은 navigation 시 re-render되지 않으므로, 그렇지 않으면 오래된(stale) 값이 될 pathname에 접근하지 않습니다.

Layouts do not re-render on navigation, so they do not access pathname which would otherwise become stale.

현재 pathname에 접근하려면 Client Component 안에서 usePathname hook으로 읽을 수 있습니다. Client Component는 navigation 중에 re-render되므로 최신 pathname에 접근할 수 있습니다.

To access the current pathname, you can read it inside a Client Component using the usePathname hook. Since Client Components re-render during navigation, they have access to the latest pathname.

TSJSapp/ui/breadcrumbs.tsx
'use client'

import { usePathname } from 'next/navigation'

// Simplified breadcrumbs logic
export default function Breadcrumbs() {
  const pathname = usePathname()
  const segments = pathname.split('/')

  return (
    <nav>
      {segments.map((segment, index) => (
        <span key={index}>
          {' > '}
          {segment}
        </span>
      ))}
    </nav>
  )
}

Interaction with loading.jsloading.js와의 상호작용

component hierarchy에서 loading.js는 layout.js 아래에 있기 때문에, cookies()나 headers() 호출, uncached fetch 같은 layout 자체의 uncached 또는 runtime data 접근에 대해서는 fallback을 보여 줄 수 없습니다.

Because loading.js sits below layout.js in the component hierarchy, it cannot show a fallback for uncached or runtime data access in the layout itself, such as calling cookies(), headers(), or making uncached fetches.

동작은 Cache Components가 활성화되어 있는지에 따라 달라집니다:

The behavior depends on whether Cache Components is enabled:

  • Cache Components 없이: layout의 rendering이 끝날 때까지 navigation이 block되며, loading.js fallback은 표시되지 않습니다.
  • Cache Components와 함께: loading.js는 특별한 prefetch marker가 아니라 일반적인 <Suspense> boundary로 취급됩니다. layout의 uncached 또는 runtime data 접근은 반드시 자체 <Suspense> boundary로 명시적으로 감싸야 하며, 그렇지 않으면 Next.js가 build-time error로 안내합니다. static shell은 즉시 stream되고, uncached content는 resolve되는 대로 교체되어 들어갑니다.
  • Without Cache Components: The navigation will block until the layout finishes rendering, and the loading.js fallback will not be shown.
  • With Cache Components: loading.js is treated as a regular <Suspense> boundary rather than a special prefetch marker. Uncached or runtime data access in the layout must be explicitly wrapped in its own <Suspense> boundary, otherwise Next.js guides you with a build-time error. The static shell streams immediately, and the uncached content swaps in as it resolves.

두 경우 모두 즉각적인 navigation을 보장하려면 다음 중 하나를 하세요:

In both cases, to ensure instant navigation, either:

  • layout의 runtime data 접근을 fallback이 있는 자체 <Suspense> boundary로 감쌉니다.
  • uncached data fetching을 layout.js에서 loading.js가 fallback을 보여 줄 수 있는 page.js로 옮깁니다.
  • Wrap runtime data access in your layout in its own <Suspense> boundary with a fallback.
  • Move uncached data fetching from layout.js into page.js where loading.js can show a fallback.
TSJSapp/dashboard/layout.tsx
import { Suspense } from 'react'
import { NavSkeleton } from './nav-skeleton'
import { DashboardNav } from './dashboard-nav'

export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <Suspense fallback={<NavSkeleton />}>
        <DashboardNav />
      </Suspense>
      <main>{children}</main>
    </>
  )
}

Fetching DataData 가져오기

Layout은 children에게 data를 전달할 수 없습니다. 하지만 한 route에서 같은 data를 여러 번 fetch하고, React cache를 사용해 performance에 영향을 주지 않고 request를 dedupe할 수 있습니다.

Layouts cannot pass data to their children. However, you can fetch the same data in a route more than once, and use React cache to dedupe the requests without affecting performance.

또는 Next.js에서 fetch를 사용하면 request가 자동으로 dedupe됩니다.

Alternatively, when using fetchin Next.js, requests are automatically deduped.

  return res.json()
}

Accessing child segments하위 segment에 접근하기

Layout은 자신보다 아래에 있는 route segment에 접근할 수 없습니다. 모든 route segment에 접근하려면 Client Component에서 useSelectedLayoutSegment 또는 useSelectedLayoutSegments를 사용할 수 있습니다.

Layouts do not have access to the route segments below itself. To access all route segments, you can use useSelectedLayoutSegment or useSelectedLayoutSegments in a Client Component.

TSJSapp/ui/nav-link.tsx
'use client'

import Link from 'next/link'
import { useSelectedLayoutSegment } from 'next/navigation'

export default function NavLink({
  slug,
  children,
}: {
  slug: string
  children: React.ReactNode
}) {
  const segment = useSelectedLayoutSegment()
  const isActive = slug === segment

  return (
    <Link
      href={`/blog/${slug}`}
      // Change style depending on whether the link is active
      style={{ fontWeight: isActive ? 'bold' : 'normal' }}
    >
      {children}
    </Link>
  )
}
'use client'

import Link from 'next/link'
import { useSelectedLayoutSegment } from 'next/navigation'

      >

      </Link>

  )
}

Using dynamic route segments, you can display or fetch specific content based on the params prop.

TSJSapp/dashboard/layout.tsx
export default async function DashboardLayout({
  children,
  params,
}: {
  children: React.ReactNode
  params: Promise<{ team: string }>
}) {
  const { team } = await params

  return (
    <section>
      <header>
        <h1>Welcome to {team}'s Dashboard</h1>
      </header>
      <main>{children}</main>
    </section>
  )
}
export default async function DashboardLayout({ children, params }) {
  const { team } = await params

  return (
    <section>
      <header>
        <h1>Welcome to {team}'s Dashboard</h1>
      </header>
      <main>{children}</main>
    </section>
  )
}

Reading params in Client ComponentsClient Component에서 params 읽기

(async일 수 없는) Client Component에서 params를 사용하려면 React의 use 함수로 promise를 읽을 수 있습니다:

To use params in a Client Component (which cannot be async), you can use React's use function to read the promise:

TSJSapp/page.tsx
'use client'

import { use } from 'react'

export default function Page({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = use(params)
}
'use client'

import { use } from 'react'

export default function Page({ params }) {
  const { slug } = use(params)
}
