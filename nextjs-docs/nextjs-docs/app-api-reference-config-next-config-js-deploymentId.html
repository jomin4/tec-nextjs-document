deploymentIddeploymentId

deploymentId option을 사용하면 deployment의 identifier를 설정할 수 있습니다. 이 identifier는 rolling deployment 중 version skew 보호와 cache busting에 사용됩니다.

The deploymentId option allows you to set an identifier for your deployment. This identifier is used for version skew protection and cache busting during rolling deployments.

JSnext.config.js
module.exports = {
  deploymentId: 'my-deployment-id',
}

NEXT_DEPLOYMENT_ID environment variable로 deployment ID를 설정할 수도 있습니다:

You can also set the deployment ID using the NEXT_DEPLOYMENT_ID environment variable:

NEXT_DEPLOYMENT_ID=my-deployment-id next build
Good to know

둘 다 설정되어 있으면 next.config.js의 deploymentId 값이 NEXT_DEPLOYMENT_ID environment variable보다 우선합니다.

If both are set, the deploymentId value in next.config.js takes precedence over the NEXT_DEPLOYMENT_ID environment variable.

How it works동작 방식

deploymentId가 설정되면 Next.js는 다음을 수행합니다:

When a deploymentId is configured, Next.js:

  1. static asset URL(JavaScript, CSS, 이미지)에 ?dpl=<deploymentId>를 덧붙입니다
  2. client-side navigation request에 x-deployment-id header를 추가합니다
  3. navigation response에 x-nextjs-deployment-id header를 추가합니다
  4. <html> element에 data-dpl-id attribute를 주입합니다
  5. 'use cache' cache key에 deploymentId를 포함하여, deployment ID가 바뀌면 cache entry를 invalidate합니다
  1. Appends ?dpl=<deploymentId> to static asset URLs (JavaScript, CSS, images)
  2. Adds an x-deployment-id header to client-side navigation requests
  3. Adds an x-nextjs-deployment-id header to navigation responses
  4. Injects a data-dpl-id attribute on the <html> element
  5. Includes the deploymentId in the 'use cache' cache key, invalidating cache entries when the deployment ID changes

client가 (response header를 통해) 자신의 deployment ID와 server의 deployment ID가 일치하지 않음을 감지하면, client-side navigation 대신 hard navigation(전체 page reload)을 trigger합니다. 이를 통해 사용자는 asset과 Server Functions에 대해 항상 일관된 deployment 버전을 받게 됩니다.

When the client detects a mismatch between its deployment ID and the server's (via the response header), it triggers a hard navigation (full page reload) instead of a client-side navigation. This ensures users always receive assets and Server Functions from a consistent deployment version.

Good to know

Next.js는 들어오는 request의 ?dpl= query parameter를 읽지 않습니다. 이 query parameter는 routing이 아니라 cache busting(브라우저와 CDN이 새 asset을 fetch하도록 보장)을 위한 것입니다. 버전을 인식하는 routing이 필요하다면, deployment 기반 routing 구현에 대해 hosting provider나 CDN의 문서를 참고하세요.

Next.js does not read the ?dpl= query parameter on incoming requests. The query parameter is for cache busting (ensuring browsers and CDNs fetch fresh assets), not for routing. If you need version-aware routing, consult your hosting provider or CDN's documentation for implementing deployment-based routing.

Use cases사용 사례

Rolling deployments

rolling deployment 중에는 일부 server instance가 새 버전을 실행하는 동안 다른 instance는 여전히 이전 버전을 실행하고 있을 수 있습니다. deployment ID가 없으면 사용자가 이전 asset과 새 asset을 섞어서 받아 error가 발생할 수 있습니다.

During a rolling deployment, some server instances may be running the new version while others are still running the old version. Without a deployment ID, users might receive a mix of old and new assets, causing errors.

deployment마다 일관된 deploymentId를 설정하면 다음이 보장됩니다:

Setting a consistent deploymentId per deployment ensures:

  • client는 항상 일치하는 deployment 버전에서 asset을 request합니다
  • 불일치가 발생하면 올바른 asset을 가져오기 위해 전체 reload가 trigger됩니다
  • Server Functions가 deployment 경계를 넘어서도 올바르게 동작합니다
  • Clients always request assets from a matching deployment version
  • Mismatches trigger a full reload to fetch the correct assets
  • Server Functions work correctly across deployment boundaries

Multi-server environments다중 server 환경

load balancer 뒤에서 Next.js 애플리케이션의 여러 instance를 실행할 때는, 같은 deployment의 모든 instance가 같은 deploymentId를 사용해야 합니다.

When running multiple instances of your Next.js application behind a load balancer, all instances for the same deployment should use the same deploymentId.

JSnext.config.js
module.exports = {
  deploymentId: process.env.DEPLOYMENT_VERSION || process.env.GIT_SHA,
}

deployment별 값은 request도 deployment 기준으로 routing될 때만 skew를 방지합니다. Next.js는 ?dpl=로 routing하지 않으므로, 이 routing은 host나 CDN이 담당합니다. 그렇지 않으면 rollout 중에 다른 deployment의 instance에 도달한 client는 navigate하지 않고 reload하게 됩니다.

A per-deployment value only avoids skew if requests are also routed by deployment. Next.js does not route on ?dpl=, so that routing comes from your host or CDN. Without it, clients that reach an instance from another deployment during a rollout will reload rather than navigate.
