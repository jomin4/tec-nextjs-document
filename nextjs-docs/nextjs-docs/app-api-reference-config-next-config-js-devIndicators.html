devIndicatorsdevIndicators

devIndicators를 사용하면 개발 중 현재 보고 있는 route에 대한 정보를 제공하는 화면 indicator를 설정할 수 있습니다.

devIndicators allows you to configure the on-screen indicator that gives context about the current route you're viewing during development.

next.config.ts를 열고 position을 설정하여 indicator가 render될 위치를 선택하세요. 기본값은 bottom-left입니다.

Open next.config.ts and set position to choose where the indicator renders. The default is bottom-left.

TSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  devIndicators: {
    position: 'bottom-right', // 'bottom-left' | 'bottom-right' | 'top-left' | 'top-right'
  },
}

export default nextConfig

indicator를 완전히 숨기려면 devIndicators를 false로 설정하세요. 그래도 Next.js는 발생한 compile error나 runtime error를 계속 표시합니다.

To hide the indicator entirely, set devIndicators to false. Next.js will still surface any compile or runtime errors that were encountered.

TSnext.config.ts
const nextConfig: NextConfig = {
  devIndicators: false,
}

export default nextConfig

Troubleshooting문제 해결

Indicator not marking a route as staticIndicator가 route를 static으로 표시하지 않는 경우

route가 static일 것으로 예상했는데 indicator가 dynamic으로 표시했다면, 해당 route가 prerendering에서 opt out했을 가능성이 높습니다.

If you expect a route to be static and the indicator has marked it as dynamic, it's likely the route has opted out of prerendering.

next build --debug로 애플리케이션을 build하고 terminal의 output을 확인하면 route가 prerender되었는지 dynamic rendering되었는지 확인할 수 있습니다. static(또는 prerender된) route는 ○ 기호로, dynamic route는 ƒ 기호로 표시됩니다. 예를 들면 다음과 같습니다:

You can confirm if a route is prerendered or dynamically rendered by building your application using next build --debug, and checking the output in your terminal. Static (or prerendered) routes will display a ○ symbol, whereas dynamic routes will display a ƒ symbol. For example:

>_Build Output
Route (app)
┌ ○ /_not-found
└ ƒ /products/[id]

○  (Static)   prerendered as static content
ƒ  (Dynamic)  server-rendered on demand

route가 prerendering에서 opt out하는 이유는 두 가지입니다:

There are two reasons a route might opt out of prerendering:

  • request 정보에 의존하는 Request-time APIs가 있는 경우.
  • ORM이나 database driver 호출처럼 cache되지 않은 data request가 있는 경우.
  • The presence of Request-time APIs which rely on request information.
  • An uncached data request, like a call to an ORM or database driver.

route에 이런 조건이 있는지 확인하고, route를 static rendering할 수 없다면 loading.js나 <Suspense />를 사용해 streaming을 활용하는 것을 고려하세요.

Check your route for any of these conditions, and if you are not able to statically render the route, then consider using loading.js or <Suspense /> to leverage streaming.
