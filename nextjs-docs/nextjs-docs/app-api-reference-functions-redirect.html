redirectredirect

redirect 함수를 사용하면 사용자를 다른 URL로 redirect할 수 있습니다. redirect는 Server Component와 Client Component의 rendering 중, Route Handler, Server Function에서 사용할 수 있습니다.

The redirect function allows you to redirect the user to another URL. redirect can be used while rendering in Server and Client Components, Route Handlers, and Server Functions.

streaming context에서 사용하면 client side에서 redirect를 발생시키는 meta tag를 삽입합니다. Server Action에서 redirect는 JavaScript를 사용할 수 있으면 client-side navigation을 수행합니다. progressive enhancement form 제출에서는 303 HTTP redirect response를 제공합니다. 그 외에는 307 HTTP redirect response를 제공합니다.

When used in a streaming context, this will insert a meta tag to emit the redirect on the client side. In a Server Action, redirect performs a client-side navigation when JavaScript is available. For progressive enhancement form submissions, it serves a 303 HTTP redirect response. Otherwise, it serves a 307 HTTP redirect response.

resource가 존재하지 않는다면 대신 notFound 함수를 사용할 수 있습니다.

If a resource doesn't exist, you can use the notFound function instead.

Reference

Parameters

redirect 함수는 두 개의 인자를 받습니다:

The redirect function accepts two arguments:

redirect(path, type)
ParameterTypeDescription
pathstringredirect할 URL입니다. 상대 경로나 절대 경로를 사용할 수 있습니다.
type'replace'(기본값) 또는 'push'(Server Action에서의 기본값)수행할 redirect의 type입니다.
ParameterTypeDescription
pathstringThe URL to redirect to. Can be a relative or absolute path.
type'replace' (default) or 'push' (default in Server Actions)The type of redirect to perform.

기본적으로 redirect는 Server Action에서는 push(브라우저 history stack에 새 entry 추가)를, 그 외의 모든 곳에서는 replace(브라우저 history stack의 현재 URL 대체)를 사용합니다. type parameter를 지정해 이 동작을 override할 수 있습니다.

By default, redirect will use push (adding a new entry to the browser history stack) in Server Actions and replace (replacing the current URL in the browser history stack) everywhere else. You can override this behavior by specifying the type parameter.

RedirectType object에는 type parameter에 사용할 수 있는 option이 들어 있습니다.

The RedirectType object contains the available options for the type parameter.

import { redirect, RedirectType } from 'next/navigation'

redirect('/redirect-to', RedirectType.replace)
// or
redirect('/redirect-to', RedirectType.push)

type parameter는 Server Component에서 사용할 때는 아무 효과가 없습니다.

The type parameter has no effect when used in Server Components.

Returns

redirect는 값을 반환하지 않습니다.

redirect does not return a value.

Behavior동작 방식

  • Server Action과 Route Handler에서 try/catch 문을 사용할 때, redirect는 try block 밖에서 호출해야 합니다.
  • 307(Temporary) 대신 308(Permanent) HTTP redirect를 반환하고 싶다면 permanentRedirect 함수를 대신 사용할 수 있습니다.
  • redirect는 error를 throw하므로 try/catch 문을 사용할 때는 try block 밖에서 호출해야 합니다.
  • redirect는 Client Component에서 rendering 과정 중에는 호출할 수 있지만 event handler에서는 호출할 수 없습니다. 대신 useRouter hook을 사용할 수 있습니다.
  • redirect는 절대 URL도 받으므로 외부 link로 redirect하는 데에도 사용할 수 있습니다.
  • render 과정 전에 redirect하고 싶다면 next.config.js나 Proxy를 사용하세요.
  • In Server Actions and Route Handlers, redirect should be called outside the try block when using try/catch statements.
  • If you prefer to return a 308 (Permanent) HTTP redirect instead of 307 (Temporary), you can use the permanentRedirect function instead.
  • redirect throws an error so it should be called outside the try block when using try/catch statements.
  • redirect can be called in Client Components during the rendering process but not in event handlers. You can use the useRouter hook instead.
  • redirect also accepts absolute URLs and can be used to redirect to external links.
  • If you'd like to redirect before the render process, use next.config.js or Proxy.

Server Component

redirect() 함수를 호출하면 NEXT_REDIRECT error를 throw하고, 그것이 throw된 route segment의 rendering을 종료합니다.

Invoking the redirect() function throws a NEXT_REDIRECT error and terminates rendering of the route segment in which it was thrown.

  params,

  params: Promise<{ id: string }>

  if (!team) {

  }

  // ...
}

Good to know

redirect는 TypeScript never type을 사용하므로 return redirect()처럼 쓸 필요가 없습니다.

redirect does not require you to use return redirect() as it uses the TypeScript never type.

Client Component

redirect는 Client Component에서 직접 사용할 수 있습니다.

redirect can be directly used in a Client Component.

TSJScomponents/client-redirect.tsx
'use client'

import { redirect, usePathname } from 'next/navigation'

export function ClientRedirect() {
  const pathname = usePathname()

  if (pathname.startsWith('/admin') && !pathname.includes('/login')) {
    redirect('/admin/login')
  }

  return <div>Login Page</div>
}

Good to know

Server-Side Rendering(SSR) 중 initial page load 시점에 Client Component에서 redirect를 사용하면 server-side redirect가 수행됩니다.

When using redirect in a Client Component on initial page load during Server-Side Rendering (SSR), it will perform a server-side redirect.

redirect는 Server Action을 통해 Client Component에서 사용할 수 있습니다. event handler로 사용자를 redirect해야 한다면 useRouter hook을 사용할 수 있습니다.

redirect can be used in a Client Component through a Server Action. If you need to use an event handler to redirect the user, you can use the useRouter hook.

TSJSapp/client-redirect.tsx
'use client'

import { navigate } from './actions'

export function ClientRedirect() {
  return (
    <form action={navigate}>
      <input type="text" name="id" />
      <button>Submit</button>
    </form>
  )
}

FAQ

Why does redirect use 307 and 308?redirect는 왜 307과 308을 사용하나요?

redirect()를 사용하다 보면 temporary redirect에는 307, permanent redirect에는 308 status code가 사용된다는 것을 알 수 있습니다. 전통적으로는 temporary redirect에 302, permanent redirect에 301을 사용했지만, 많은 브라우저가 302를 사용할 때 원래 request method와 관계없이 redirect의 request method를 POST에서 GET request로 바꿨습니다.

When using redirect() you may notice that the status codes used are 307 for a temporary redirect, and 308 for a permanent redirect. While traditionally a 302 was used for a temporary redirect, and a 301 for a permanent redirect, many browsers changed the request method of the redirect, from a POST to GET request when using a 302, regardless of the origins request method.

/users에서 /people로 redirect하는 다음 예시를 생각해 봅시다. 새 사용자를 만들기 위해 /users로 POST request를 보냈는데 302 temporary redirect를 따르게 되면, request method가 POST에서 GET request로 바뀝니다. 새 사용자를 만들려면 /people로 GET request가 아니라 POST request를 보내야 하므로, 이는 말이 되지 않습니다.

Taking the following example of a redirect from /users to /people, if you make a POST request to /users to create a new user, and are conforming to a 302 temporary redirect, the request method will be changed from a POST to a GET request. This doesn't make sense, as to create a new user, you should be making a POST request to /people, and not a GET request.

307 status code가 도입되면서 request method가 POST로 유지됩니다.

The introduction of the 307 status code means that the request method is preserved as POST.

  • 302 - Temporary redirect, request method를 POST에서 GET으로 바꿉니다
  • 307 - Temporary redirect, request method를 POST로 유지합니다
  • 302 - Temporary redirect, will change the request method from POST to GET
  • 307 - Temporary redirect, will preserve the request method as POST

redirect() method는 기본적으로 302 temporary redirect 대신 307을 사용하므로 request method가 유지됩니다. Server Action form 제출은 예외입니다: 브라우저가 GET request로 redirect를 따르도록 303 response를 사용합니다. JavaScript를 사용할 수 있으면 Server Action은 HTTP redirect 대신 client-side navigation을 수행합니다.

The redirect() method uses a 307 by default, instead of a 302 temporary redirect, meaning the request method is preserved. Server Action form submissions are an exception: they use a 303 response so the browser follows the redirect with a GET request. When JavaScript is available, Server Actions perform a client-side navigation instead of an HTTP redirect.
