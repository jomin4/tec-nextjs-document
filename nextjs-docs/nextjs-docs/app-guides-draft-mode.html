How to preview content with Draft Mode in Next.jsNext.js에서 Draft Mode로 content 미리 보기

Draft Mode를 사용하면 편집자가 revalidation을 기다리지 않고도 초안이나 작업 중인 content가 사이트에서 어떻게 render될지 확인할 수 있습니다. 편집자가 Draft Mode에 있는 동안에는 cache되거나 pre-render된 content를 건너뛰고 upstream source에서 직접 fetch합니다. 다른 방문자는 계속해서 page의 cache되거나 pre-render된 버전을 보게 됩니다.

Draft Mode lets editors see how draft or in-progress content will render on your site, without waiting for revalidation. While an editor is in Draft Mode, cached or pre-rendered content is bypassed, and fetched from upstream sources directly. Other visitors continue to see the cached or pre-rendered version of the page.

CMS가 초안과 게시된 content를 같은 URL에서 제공한다면 data-fetching 코드를 바꿀 필요가 없습니다. 그렇지 않다면 CMS가 별도의 draft endpoint를 사용하는 경우를 참고하세요.

Your data-fetching code does not need to change if your CMS serves draft and published content from the same URL. Otherwise, see When your CMS uses a separate draft endpoint.

What Draft Mode doesDraft Mode가 하는 일

request에 Draft Mode가 활성화되면:

When Draft Mode is enabled for a request:

  • fetch() 호출은 Next.js fetch cache를 건너뛰고 network에 직접 요청합니다.
  • 'use cache' 안의 component와 함수는 매 request마다 다시 실행되며, 그 결과는 cache에 저장되지 않습니다.
  • unstable_cache의 읽기와 쓰기도 같은 방식으로 우회됩니다.
  • page는 ISR response cache에서 제외되며 Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate와 함께 제공됩니다.
  • fetch() calls skip the Next.js fetch cache and hit the network directly.
  • Components and functions inside 'use cache' re-execute on every request, and their results are not saved to the cache.
  • unstable_cache reads and writes are bypassed in the same way.
  • The page is excluded from the ISR response cache and is served with Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate.

이 효과는 page가 statically 생성되었든, cache에서 제공되든, ISR로 revalidate되든 상관없이 적용됩니다.

The effect applies whether the page is statically generated, served from cache, or revalidated through ISR.

What this guide covers이 가이드에서 다루는 내용

이 가이드는 다음을 가정합니다:

This guide assumes:

  • headless CMS가 설정 가능한 preview URL을 지원합니다(대부분 지원합니다).
  • 편집자가 "Preview"를 클릭하면 CMS가 새 tab에서 /api/draft?secret=XXX&slug=/posts/foo 같은 URL을 엽니다. secret은 공유 token이고, slug는 미리 볼 경로입니다.
  • Next.js 앱은 secret을 검증하고, Draft Mode를 활성화한 뒤 slug로 redirect합니다.
  • Your headless CMS supports configurable preview URLs (most do).
  • The CMS opens a URL like /api/draft?secret=XXX&slug=/posts/foo in a new tab when an editor clicks "Preview". The secret is a shared token; the slug is the path to preview.
  • Your Next.js app validates the secret, enables Draft Mode, and redirects to the slug.

이 계약을 염두에 두고, 이 가이드의 나머지 부분에서는 다음을 차례로 살펴봅니다:

With that contract in mind, the rest of this guide walks through:

  1. cookie를 설정해 Draft Mode를 활성화하는 Route Handler 만들기.
  2. CMS에서 받은 공유 secret과 slug로 그 handler 보호하기.
  3. 최신 초안을 읽는 page render하기.
  4. 종료 form이 있는 preview banner 보여 주기.
  1. Creating a Route Handler that enables Draft Mode by setting a cookie.
  2. Securing that handler with the shared secret and slug from the CMS.
  3. Rendering pages that read the latest draft.
  4. Showing a preview banner with an exit form.

그다음 설정에 따라:

Then, depending on your setup:

  • 'use cache' 경계에서 preview 상태를 드러내려면 Cache Components와 함께 쓰는 Draft Mode.
  • isEnabled에 따라 fetch URL을 분기하려면 CMS가 별도의 draft endpoint를 사용하는 경우.
  • Draft Mode with Cache Components for surfacing the preview state from a 'use cache' boundary.
  • When your CMS uses a separate draft endpoint for branching the fetch URL on isEnabled.
Good to know

GET은 안전한 읽기 전용 method로 의도된 것입니다. cookie로 Draft Mode를 활성화하는 것처럼 이후 request에 영향을 주는 작업은 POST를 사용해야 합니다. 진입 handler가 GET을 사용하는 이유는 CMS preview integration을 가정하기 때문입니다: CMS는 새 브라우저 tab에서 URL을 여는데, 이것이 GET request입니다. Step 4의 종료 흐름은 (Server Action 또는 POST Route Handler를 통해) POST를 사용합니다.

GET is meant to be a safe, read-only method. Operations that affect future requests, like enabling Draft Mode via a cookie, should use POST. The entry handler uses GET because we're assuming a CMS preview integration: the CMS opens the URL in a new browser tab, which is a GET request. The exit flow in Step 4 uses POST (via Server Action or POST Route Handler).

Step 1: Create a Route HandlerStep 1: Route Handler 만들기

Draft Mode cookie를 설정하는 Route Handler를 만드세요. 이름은 무엇이든 될 수 있습니다. 예: app/api/draft/route.ts.

Create a Route Handler that sets the Draft Mode cookie. It can have any name, for example, app/api/draft/route.ts.

TSJSapp/api/draft/route.ts
import { draftMode } from 'next/headers'

export async function GET(request: Request) {
  const draft = await draftMode()
  draft.enable()
  return new Response('Draft mode is enabled')
}
import { draftMode } from 'next/headers'

export async function GET(request) {
  const draft = await draftMode()
  draft.enable()
  return new Response('Draft mode is enabled')
}

draft.enable()은 __prerender_bypass라는 이름의 cookie를 설정합니다. 이후 이 cookie를 가진 request는 위에 나열한 모든 cache layer를 건너뜁니다.

draft.enable() sets a cookie named __prerender_bypass. Subsequent requests that carry this cookie skip every cache layer listed above.

/api/draft에 방문한 뒤 브라우저의 developer tools를 보면 직접 테스트해 볼 수 있습니다. Set-Cookie response header를 확인하세요.

You can test this manually by visiting /api/draft and looking at your browser's developer tools. Notice the Set-Cookie response header.

작성된 그대로라면 이 handler는 공개되어 있습니다: /api/draft에 접속한 누구나 자신에게 Draft Mode를 활성화할 수 있습니다. Step 2에서는 공유 secret으로 이를 막아 CMS만 호출할 수 있게 합니다.

As written, the handler is public: anyone who hits /api/draft enables Draft Mode for themselves. Step 2 closes that with a shared secret so only your CMS can call it.

Step 2: Access the Route Handler from your headless CMSStep 2: headless CMS에서 Route Handler에 접근하기

이 단계는 사용 중인 headless CMS가 custom draft URL 설정을 지원한다고 가정합니다. 지원하지 않더라도 이 방법으로 draft URL을 보호할 수는 있지만, draft URL을 직접 구성하고 접근해야 합니다. 구체적인 단계는 사용하는 headless CMS에 따라 달라집니다.

These steps assume that the headless CMS you're using supports setting custom draft URLs. If it doesn't, you can still use this method to secure your draft URLs, but you'll need to construct and access the draft URL manually. The specific steps will vary depending on which headless CMS you're using.

headless CMS에서 Route Handler에 안전하게 접근하려면:

To securely access the Route Handler from your headless CMS:

  1. 원하는 token 생성기로 secret token string을 만드세요. 이 secret은 Next.js 앱과 headless CMS만 알고 있습니다.
  2. headless CMS가 custom draft URL 설정을 지원한다면 draft URL을 지정하세요(Route Handler가 app/api/draft/route.ts에 있다고 가정합니다). 예를 들면 다음과 같습니다:
  1. Create a secret token string using a token generator of your choice. This secret is only known to your Next.js app and your headless CMS.
  2. If your headless CMS supports setting custom draft URLs, specify a draft URL (this assumes that your Route Handler is located at app/api/draft/route.ts). For example:
>_Terminal
https://<your-site>/api/draft?secret=<token>&slug=<path>
  • <your-site>는 deployment domain이어야 합니다.
  • <token>은 생성한 secret token으로 바꿔야 합니다.
  • <path>는 보고 싶은 page의 경로여야 합니다. /posts/one을 보고 싶다면 &slug=/posts/one을 사용하세요.

headless CMS에 따라 draft URL에 변수를 넣을 수 있어서, <path>를 CMS 데이터에 따라 다음과 같이 동적으로 설정할 수 있습니다: &slug=/posts/{entry.fields.slug}

  • <your-site> should be your deployment domain.
  • <token> should be replaced with the secret token you generated.
  • <path> should be the path for the page that you want to view. If you want to view /posts/one, then you should use &slug=/posts/one.

Your headless CMS might allow you to include a variable in the draft URL so that <path> can be set dynamically based on the CMS's data like so: &slug=/posts/{entry.fields.slug}

  1. Route Handler에서 secret이 일치하는지, slug parameter가 존재하는지 확인하고(그렇지 않으면 request가 실패해야 합니다), draft.enable()을 호출해 cookie를 설정한 다음, 브라우저를 slug로 지정된 경로로 redirect하세요:
  1. In your Route Handler, check that the secret matches and that the slug parameter exists (if not, the request should fail), call draft.enable() to set the cookie, then redirect the browser to the path specified by slug:
TSJSapp/api/draft/route.ts
import { draftMode } from 'next/headers'
import { redirect } from 'next/navigation'

export async function GET(request: Request) {
  const { searchParams } = new URL(request.url)
  const secret = searchParams.get('secret')
  const slug = searchParams.get('slug')

  // This secret should only be known to this Route Handler and the CMS
  if (secret !== 'MY_SECRET_TOKEN' || !slug) {
    return new Response('Invalid token', { status: 401 })
  }

  // Verify the slug exists in the CMS before enabling Draft Mode
  const post = await getPostBySlug(slug)
  if (!post) {
    return new Response('Invalid slug', { status: 401 })
  }

  const draft = await draftMode()
  draft.enable()

  // Redirect to the path from the fetched post, not from searchParams,
  // to avoid open redirect vulnerabilities
  redirect(post.slug)
}
import { draftMode } from 'next/headers'
import { redirect } from 'next/navigation'

export async function GET(request) {
  const { searchParams } = new URL(request.url)
  const secret = searchParams.get('secret')
  const slug = searchParams.get('slug')

  if (secret !== 'MY_SECRET_TOKEN' || !slug) {
    return new Response('Invalid token', { status: 401 })
  }

  const post = await getPostBySlug(slug)
  if (!post) {
    return new Response('Invalid slug', { status: 401 })
  }

  const draft = await draftMode()
  draft.enable()

  redirect(post.slug)
}

성공하면 Draft Mode cookie가 설정된 상태로 브라우저가 대상 경로로 redirect됩니다.

If it succeeds, the browser is redirected to the target path with the Draft Mode cookie set.

Step 3: Preview the draft contentStep 3: 초안 content 미리 보기

Draft Mode는 cache를 자동으로 우회하므로, page는 최신 content를 받기 위해 Draft Mode가 켜져 있는지 알 필요가 없습니다. 평소처럼 fetch하세요:

Because Draft Mode bypasses the cache automatically, your page does not need to know whether Draft Mode is on to receive fresh content. Fetch as you normally would:

TSJSapp/posts/[slug]/page.tsx
async function getPost(slug: string) {
  const res = await fetch(`https://cms.example.com/posts/${slug}`)
  return res.json()
}

export default async function Page({ params }: PageProps<'/posts/[slug]'>) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <main>
      <h1>{post.title}</h1>
      <article>{post.content}</article>
    </main>
  )
}
async function getPost(slug) {
  const res = await fetch(`https://cms.example.com/posts/${slug}`)
  return res.json()
}

export default async function Page({ params }) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <main>
      <h1>{post.title}</h1>
      <article>{post.content}</article>
    </main>
  )
}

Draft Mode cookie가 있으면 위의 fetch는 Next.js fetch cache를 건너뛰고 CMS에 현재 초안을 요청합니다. cookie가 없으면 같은 request가 평소처럼 cache에서 제공될 수 있습니다.

When the Draft Mode cookie is present, the fetch above skips the Next.js fetch cache and hits your CMS for the current draft. When it is not, the same request can be served from cache as usual.

CMS가 초안을 같은 endpoint에서 제공하지 않고 다른 URL을 사용한다면 CMS가 별도의 draft endpoint를 사용하는 경우를 참고하세요.

If your CMS uses a different URL for drafts rather than serving them from the same endpoint, see When your CMS uses a separate draft endpoint.

Step 4: Show a preview indicatorStep 4: preview indicator 보여 주기

isEnabled는 편집자에게 보내는 신호로 가장 유용합니다: 초안 content를 보고 있다는 것을 확인해 주는 banner와 종료 방법을 함께 제공하는 것이죠. 모든 preview page에 나타나도록 root layout에서 indicator를 render하세요.

isEnabled is most useful as a signal to the editor: a banner that confirms they are looking at draft content, plus a way to exit. Render an indicator from your root layout so it appears on every preview page.

TSJSapp/preview-banner.tsx
import { draftMode } from 'next/headers'
import { redirect } from 'next/navigation'

async function exitPreview() {
  'use server'
  const draft = await draftMode()
  draft.disable()
  redirect('/')
}

export async function PreviewBanner() {
  const { isEnabled } = await draftMode()
  if (!isEnabled) return null

  return (
    <aside role="status">
      Preview mode is on.{' '}
      <form action={exitPreview}>
        <button type="submit">Exit preview</button>
      </form>
    </aside>
  )
}
import { draftMode } from 'next/headers'
import { redirect } from 'next/navigation'

async function exitPreview() {
  'use server'
  const draft = await draftMode()
  draft.disable()
  redirect('/')
}

export async function PreviewBanner() {
  const { isEnabled } = await draftMode()
  if (!isEnabled) return null

  return (
    <aside role="status">
      Preview mode is on.{' '}
      <form action={exitPreview}>
        <button type="submit">Exit preview</button>
      </form>
    </aside>
  )
}

Draft Mode 종료는 GET Route Handler로도 동작하지만, 의미상으로는 POST가 더 올바릅니다. 예를 들어 Server Action을 통해 제출되는 form이나 POST Route Handler로 보내는 방법이 있습니다.

Exiting Draft Mode also works with a GET Route Handler, but a POST is semantically more correct, for example via a form submitted through a Server Action or to a POST Route Handler.

GET Route Handler를 사용한다면 <Link>가 아니라 <form method="GET">에서 트리거하세요. Next.js는 기본적으로 <Link> component를 prefetch하므로, 편집자가 클릭하기도 전에 cookie가 지워질 수 있습니다. form은 method와 상관없이 prefetch되지 않습니다.

If you do use a GET Route Handler, trigger it from a <form method="GET"> rather than a <Link>. Next.js prefetches <Link> components by default, which would clear the cookie before the editor clicks. Forms are not prefetched, regardless of method.

Draft Mode with Cache ComponentsCache Components와 함께 쓰는 Draft Mode

'use cache' scope 안에서 isEnabled를 읽어 cache된 component에서 preview indicator를 render할 수 있습니다. cache 우회는 여전히 적용되므로, 해당 component는 모든 draft request마다 최신 데이터로 다시 실행됩니다.

You can read isEnabled inside a 'use cache' scope to render a preview indicator from a cached component. The cache bypass still applies, so the component re-executes with fresh data on every draft request.

TSJSapp/posts/[slug]/page.tsx
import { draftMode } from 'next/headers'

async function Post({ slug }: { slug: string }) {
  'use cache'

  const post = await fetch(`https://cms.example.com/posts/${slug}`).then((r) =>
    r.json()
  )
  const { isEnabled } = await draftMode()

  return (
    <article>
      {isEnabled && <p role="status">Draft preview</p>}
      <h1>{post.title}</h1>
      <div>{post.content}</div>
    </article>
  )
}
import { draftMode } from 'next/headers'

async function Post({ slug }) {
  'use cache'

  const post = await fetch(`https://cms.example.com/posts/${slug}`).then((r) =>
    r.json()
  )
  const { isEnabled } = await draftMode()

  return (
    <article>
      {isEnabled && <p role="status">Draft preview</p>}
      <h1>{post.title}</h1>
      <div>{post.content}</div>
    </article>
  )
}
Good to know

draftMode().enable()과 draftMode().disable()은 caching directive scope 안에서 호출할 수 없습니다. 대신 Route Handler나 Server Action에서 Draft Mode를 켜고 끄세요.

draftMode().enable() and draftMode().disable() cannot be called inside a caching directive scope; toggle Draft Mode from a Route Handler or Server Action instead.

When your CMS uses a separate draft endpointCMS가 별도의 draft endpoint를 사용하는 경우

CMS가 초안 content를 다른 URL에서 제공하거나 다른 credential을 요구한다면 isEnabled에 따라 fetch를 분기하세요:

If your CMS exposes draft content at a different URL or requires different credentials, branch your fetch on isEnabled:

TSJSapp/posts/[slug]/page.tsx
import { draftMode } from 'next/headers'

async function getPost(slug: string) {
  const { isEnabled } = await draftMode()
  const baseUrl = isEnabled
    ? 'https://cms.example.com/preview'
    : 'https://cms.example.com/published'

  const res = await fetch(`${baseUrl}/posts/${slug}`)
  return res.json()
}
import { draftMode } from 'next/headers'

async function getPost(slug) {
  const { isEnabled } = await draftMode()
  const baseUrl = isEnabled
    ? 'https://cms.example.com/preview'
    : 'https://cms.example.com/published'

  const res = await fetch(`${baseUrl}/posts/${slug}`)
  return res.json()
}

cache 우회는 두 분기 모두에 여전히 적용됩니다. 분기는 어디에서 읽을지만 선택합니다.

The cache bypass still applies to both branches; the fork only chooses where to read from.
