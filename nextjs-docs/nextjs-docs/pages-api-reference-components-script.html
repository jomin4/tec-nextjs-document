ScriptScript 컴포넌트

이 API reference는 Script Component에서 사용할 수 있는 props를 이해하는 데 도움을 줍니다. 기능과 사용법은 Optimizing Scripts 페이지를 참고하세요.

This API reference will help you understand how to use props available for the Script Component. For features and usage, please see the Optimizing Scripts page.

TSJSapp/dashboard/page.tsx
import Script from 'next/script'

export default function Dashboard() {
  return (
    <>
      <Script src="https://example.com/script.js" />
    </>
  )
}
import Script from 'next/script'

export default function Dashboard() {
  return (
    <>
      <Script src="https://example.com/script.js" />
    </>
  )
}

Required Props필수 Props

<Script /> component에는 다음 property가 필요합니다.

The <Script /> component requires the following properties.

src

외부 script의 URL을 지정하는 path 문자열입니다. 절대 외부 URL이나 내부 path 모두 사용할 수 있습니다. inline script를 사용하지 않는 한 src property는 필수입니다.

A path string specifying the URL of an external script. This can be either an absolute external URL or an internal path. The src property is required unless an inline script is used.

Optional Props선택 Props

<Script /> component는 필수 property 외에도 여러 추가 property를 받습니다.

The <Script /> component accepts a number of additional properties beyond those which are required.

strategy

script의 loading strategy입니다. 사용할 수 있는 strategy는 네 가지입니다:

The loading strategy of the script. There are four different strategies that can be used:

  • beforeInteractive: 모든 Next.js 코드보다 먼저, 그리고 page hydration이 일어나기 전에 load합니다.
  • afterInteractive: (default) 일찍 load하되, page에서 hydration이 어느 정도 일어난 뒤에 load합니다.
  • lazyOnload: 브라우저의 idle time 동안 load합니다.
  • worker: (experimental) web worker에서 load합니다.
  • beforeInteractive: Load before any Next.js code and before any page hydration occurs.
  • afterInteractive: (default) Load early but after some hydration on the page occurs.
  • lazyOnload: Load during browser idle time.
  • worker: (experimental) Load in a web worker.

beforeInteractive

beforeInteractive strategy로 load되는 script는 server에서 initial HTML에 inject되고, 모든 Next.js module보다 먼저 download되며, 배치된 순서대로 실행됩니다.

Scripts that load with the beforeInteractive strategy are injected into the initial HTML from the server, downloaded before any Next.js module, and executed in the order they are placed.

이 strategy가 지정된 script는 모든 first-party 코드보다 먼저 preload되고 fetch되지만, 그 실행이 page hydration이 일어나는 것을 막지는 않습니다.

Scripts denoted with this strategy are preloaded and fetched before any first-party code, but their execution does not block page hydration from occurring.

beforeInteractive script는 Document Component(pages/_document.js) 안에 배치해야 하며, 사이트 전체에 필요한 script를 load하도록 설계되었습니다(즉, 애플리케이션의 어떤 page든 server-side에서 load되면 script가 load됩니다).

beforeInteractive scripts must be placed inside the Document Component (pages/_document.js) and are designed to load scripts that are needed by the entire site (i.e. the script will load when any page in the application has been loaded server-side).

이 strategy는 가능한 한 빨리 fetch해야 하는 중요한 script에만 사용해야 합니다.

This strategy should only be used for critical scripts that need to be fetched as soon as possible.

JSpages/_document.js
import { Html, Head, Main, NextScript } from 'next/document'
import Script from 'next/script'

export default function Document() {
  return (
    <Html>
      <Head />
      <body>
        <Main />
        <NextScript />
        <Script
          src="https://example.com/script.js"
          strategy="beforeInteractive"
        />
      </body>
    </Html>
  )
}
Good to know

beforeInteractive script는 component 안 어디에 배치하든 항상 HTML document의 head 안에 inject됩니다.

Scripts with beforeInteractive will always be injected inside the head of the HTML document regardless of where it's placed in the component.

beforeInteractive로 가능한 한 빨리 fetch해야 하는 script의 예는 다음과 같습니다:

Some examples of scripts that should be fetched as soon as possible with beforeInteractive include:

  • Bot detector
  • Cookie consent manager
  • Bot detectors
  • Cookie consent managers

afterInteractive

afterInteractive strategy를 사용하는 script는 client-side에서 HTML에 inject되며, page에서 hydration이 일부(또는 전부) 일어난 뒤에 load됩니다. 이것이 Script component의 default strategy이며, 가능한 한 빨리 load해야 하지만 first-party Next.js 코드보다 먼저 load될 필요는 없는 script에 사용해야 합니다.

Scripts that use the afterInteractive strategy are injected into the HTML client-side and will load after some (or all) hydration occurs on the page. This is the default strategy of the Script component and should be used for any script that needs to load as soon as possible but not before any first-party Next.js code.

afterInteractive script는 어떤 page나 layout 안에든 배치할 수 있으며, 해당 page(또는 page 그룹)가 브라우저에서 열릴 때만 load되고 실행됩니다.

afterInteractive scripts can be placed inside of any page or layout and will only load and execute when that page (or group of pages) is opened in the browser.

JSapp/page.js
import Script from 'next/script'

export default function Page() {
  return (
    <>
      <Script src="https://example.com/script.js" strategy="afterInteractive" />
    </>
  )
}

afterInteractive에 적합한 script의 예는 다음과 같습니다:

Some examples of scripts that are good candidates for afterInteractive include:

  • Tag manager
  • Analytics
  • Tag managers
  • Analytics

lazyOnload

lazyOnload strategy를 사용하는 script는 브라우저의 idle time 동안 client-side에서 HTML에 inject되며, page의 모든 resource가 fetch된 뒤에 load됩니다. 이 strategy는 일찍 load할 필요가 없는 background 또는 우선순위가 낮은 script에 사용해야 합니다.

Scripts that use the lazyOnload strategy are injected into the HTML client-side during browser idle time and will load after all resources on the page have been fetched. This strategy should be used for any background or low priority scripts that do not need to load early.

lazyOnload script는 어떤 page나 layout 안에든 배치할 수 있으며, 해당 page(또는 page 그룹)가 브라우저에서 열릴 때만 load되고 실행됩니다.

lazyOnload scripts can be placed inside of any page or layout and will only load and execute when that page (or group of pages) is opened in the browser.

JSapp/page.js
import Script from 'next/script'

export default function Page() {
  return (
    <>
      <Script src="https://example.com/script.js" strategy="lazyOnload" />
    </>
  )
}

즉시 load할 필요가 없어서 lazyOnload로 fetch할 수 있는 script의 예는 다음과 같습니다:

Examples of scripts that do not need to load immediately and can be fetched with lazyOnload include:

  • Chat support plugin
  • Social media widget
  • Chat support plugins
  • Social media widgets

worker

Warning

worker strategy는 아직 stable하지 않으며 App Router에서는 아직 동작하지 않습니다. 주의해서 사용하세요.

The worker strategy is not yet stable and does not yet work with the App Router. Use with caution.

worker strategy를 사용하는 script는 main thread의 부담을 덜고 중요한 first-party resource만 main thread에서 처리되도록 web worker로 off-load됩니다. 이 strategy는 어떤 script에든 사용할 수 있지만, 모든 third-party script를 지원한다고 보장할 수 없는 고급 사용 사례입니다.

Scripts that use the worker strategy are off-loaded to a web worker in order to free up the main thread and ensure that only critical, first-party resources are processed on it. While this strategy can be used for any script, it is an advanced use case that is not guaranteed to support all third-party scripts.

worker를 strategy로 사용하려면 next.config.js에서 nextScriptWorkers flag를 활성화해야 합니다:

To use worker as a strategy, the nextScriptWorkers flag must be enabled in next.config.js:

JSnext.config.js
module.exports = {
  experimental: {
    nextScriptWorkers: true,
  },
}

worker script는 현재 pages/ directory에서만 사용할 수 있습니다:

worker scripts can only currently be used in the pages/ directory:

TSJSpages/home.tsx
import Script from 'next/script'

export default function Home() {
  return (
    <>
      <Script src="https://example.com/script.js" strategy="worker" />
    </>
  )
}
import Script from 'next/script'

export default function Home() {
  return (
    <>
      <Script src="https://example.com/script.js" strategy="worker" />
    </>
  )
}

onLoad

Warning

onLoad는 아직 Server Component에서 동작하지 않으며 Client Component에서만 사용할 수 있습니다. 또한 onLoad는 beforeInteractive와 함께 사용할 수 없으니, 대신 onReady 사용을 고려하세요.

onLoad does not yet work with Server Components and can only be used in Client Components. Further, onLoad can't be used with beforeInteractive – consider using onReady instead.

일부 third-party script는 콘텐츠를 instantiate하거나 함수를 호출하기 위해, script load가 끝난 뒤 사용자가 JavaScript 코드를 한 번 실행해야 합니다. loading strategy로 afterInteractive나 lazyOnload를 사용해 script를 load한다면, onLoad property로 load가 끝난 뒤 코드를 실행할 수 있습니다.

Some third-party scripts require users to run JavaScript code once after the script has finished loading in order to instantiate content or call a function. If you are loading a script with either afterInteractive or lazyOnload as a loading strategy, you can execute code after it has loaded using the onLoad property.

다음은 library가 load된 뒤에만 lodash method를 실행하는 예시입니다.

Here's an example of executing a lodash method only after the library has been loaded.

TSJSapp/page.tsx
'use client'

import Script from 'next/script'

export default function Page() {
  return (
    <>
      <Script
        src="https://cdnjs.cloudflare.com/ajax/libs/lodash.js/4.17.20/lodash.min.js"
        onLoad={() => {
          console.log(_.sample([1, 2, 3, 4]))
        }}
      />
    </>
  )
}
'use client'

import Script from 'next/script'

export default function Page() {
  return (
    <>
      <Script
        src="https://cdnjs.cloudflare.com/ajax/libs/lodash.js/4.17.20/lodash.min.js"
        onLoad={() => {
          console.log(_.sample([1, 2, 3, 4]))
        }}
      />
    </>
  )
}

onReady

Warning

onReady는 아직 Server Component에서 동작하지 않으며 Client Component에서만 사용할 수 있습니다.

onReady does not yet work with Server Components and can only be used in Client Components.

일부 third-party script는 script load가 끝난 뒤, 그리고 component가 mount될 때마다(예: route navigation 이후) 사용자가 JavaScript 코드를 실행해야 합니다. onReady property를 사용하면 처음 load될 때 script의 load event 이후에, 그리고 이후 component가 re-mount될 때마다 코드를 실행할 수 있습니다.

Some third-party scripts require users to run JavaScript code after the script has finished loading and every time the component is mounted (after a route navigation for example). You can execute code after the script's load event when it first loads and then after every subsequent component re-mount using the onReady property.

다음은 component가 mount될 때마다 Google Maps JS embed를 다시 instantiate하는 예시입니다:

Here's an example of how to re-instantiate a Google Maps JS embed every time the component is mounted:

import { useRef } from 'react'
import Script from 'next/script'

export default function Page() {
  const mapRef = useRef()

  return (
    <>
      <div ref={mapRef}></div>
      <Script
        id="google-maps"
        src="https://maps.googleapis.com/maps/api/js"
        onReady={() => {
          new google.maps.Map(mapRef.current, {
            center: { lat: -34.397, lng: 150.644 },
            zoom: 8,
          })
        }}
      />
    </>
  )
}

onError

Warning

onError는 아직 Server Component에서 동작하지 않으며 Client Component에서만 사용할 수 있습니다. onError는 beforeInteractive loading strategy와 함께 사용할 수 없습니다.

onError does not yet work with Server Components and can only be used in Client Components. onError cannot be used with the beforeInteractive loading strategy.

script load가 실패했을 때 이를 잡아내는 것이 도움이 될 때가 있습니다. 이런 error는 onError property로 처리할 수 있습니다:

Sometimes it is helpful to catch when a script fails to load. These errors can be handled with the onError property:

import Script from 'next/script'

export default function Page() {
  return (
    <>
      <Script
        src="https://example.com/script.js"
        onError={(e: Error) => {
          console.error('Script failed to load', e)
        }}
      />
    </>
  )
}
