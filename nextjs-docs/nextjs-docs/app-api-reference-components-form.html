Form ComponentForm Component

<Form> component는 HTML <form> element를 확장해 loading UI의 prefetching, 제출 시 client-side navigation, 그리고 progressive enhancement를 제공합니다.

The <Form> component extends the HTML <form> element to provide prefetching of loading UI, client-side navigation on submission, and progressive enhancement.

위 기능을 구현하는 데 필요한 boilerplate 코드를 줄여 주므로, URL search params를 업데이트하는 form에 유용합니다.

It's useful for forms that update URL search params as it reduces the boilerplate code needed to achieve the above.

기본 사용법:

Basic usage:

TSJS/app/ui/search.tsx
import Form from 'next/form'

export default function Page() {
  return (
    <Form action="/search">
      {/* On submission, the input value will be appended to
          the URL, e.g. /search?query=abc */}
      <input name="query" />
      <button type="submit">Submit</button>
    </Form>
  )
}
import Form from 'next/form'

export default function Search() {

    </Form>

Reference참고

<Form> component의 동작은 action prop에 string을 전달하는지 function을 전달하는지에 따라 달라집니다.

The behavior of the <Form> component depends on whether the action prop is passed a string or function.

  • action이 string이면 <Form>은 GET method를 사용하는 native HTML form처럼 동작합니다. form data는 search params로 URL에 encode되고, form을 제출하면 지정한 URL로 navigate합니다. 또한 Next.js는 다음을 수행합니다:
    • form이 화면에 보이게 되면 해당 경로를 prefetch합니다. 이때 공유 UI(예: layout.js, loading.js)를 미리 load하므로 navigation이 더 빨라집니다.
    • form을 제출하면 전체 page reload 대신 client-side navigation을 수행합니다. 이렇게 하면 공유 UI와 client-side state가 유지됩니다.
  • action이 function(Server Action)이면 <Form>은 React form처럼 동작하며, form을 제출할 때 action을 실행합니다.
  • When action is a string, the <Form> behaves like a native HTML form that uses a GET method. The form data is encoded into the URL as search params, and when the form is submitted, it navigates to the specified URL. In addition, Next.js:
    • Prefetches the path when the form becomes visible, this preloads shared UI (e.g. layout.js and loading.js), resulting in faster navigation.
    • Performs a client-side navigation instead of a full page reload when the form is submitted. This retains shared UI and client-side state.
  • When action is a function (Server Action), <Form> behaves like a React form, executing the action when the form is submitted.

action이 string이면 <Form> component는 다음 props를 지원합니다:

  • action: form을 제출할 때 navigate할 URL 또는 경로입니다.
    • 빈 문자열 ""이면 업데이트된 search params와 함께 같은 route로 navigate합니다.
  • replace: browser history stack에 새 history state를 push하는 대신 현재 history state를 대체합니다. 기본값은 false입니다.
  • scroll: navigation 중 scroll 동작을 제어합니다. 기본값은 true이며, 이는 새 route의 맨 위로 scroll하고 뒤로/앞으로 navigation할 때는 scroll 위치를 유지한다는 뜻입니다.
  • prefetch: form이 사용자의 viewport에 보이게 될 때 경로를 prefetch할지 제어합니다. 기본값은 true입니다.
  • action: The URL or path to navigate to when the form is submitted.
    • An empty string "" will navigate to the same route with updated search params.
  • replace: Replaces the current history state instead of pushing a new one to the browser's history stack. Default is false.
  • scroll: Controls the scroll behavior during navigation. Defaults to true, this means it will scroll to the top of the new route, and maintain the scroll position for backwards and forwards navigation.
  • prefetch: Controls whether the path should be prefetched when the form becomes visible in the user's viewport. Defaults to true.

When action is a function, the <Form> component supports the following prop:

  • action: form을 제출할 때 호출할 Server Action입니다. 자세한 내용은 React 문서를 참고하세요.
  • action: The Server Action to be called when the form is submitted. See the React docs for more.
Good to know

action이 function이면 replace와 scroll props는 무시됩니다.

When action is a function, the replace and scroll props are ignored.

Caveats주의 사항

  • formAction: <button> 또는 <input type="submit"> field에서 action prop을 override하는 데 사용할 수 있습니다. Next.js는 client-side navigation을 수행하지만, 이 방식은 prefetching을 지원하지 않습니다.
    • basePath를 사용할 때는 formAction 경로에도 포함해야 합니다. 예: formAction="/base-path/search".
  • key: string action에 key prop을 전달하는 것은 지원되지 않습니다. re-render를 trigger하거나 mutation을 수행하려면 function action을 사용하는 것을 고려하세요.
  • onSubmit: form 제출 로직을 처리하는 데 사용할 수 있습니다. 하지만 event.preventDefault()를 호출하면 지정한 URL로 navigate하는 것 같은 <Form> 동작이 override됩니다.
  • method, encType, target: <Form> 동작을 override하므로 지원되지 않습니다.
    • 마찬가지로 formMethod, formEncType, formTarget을 사용해 각각 method, encType, target props를 override할 수 있으며, 이를 사용하면 native 브라우저 동작으로 fallback됩니다.
    • 이 props를 사용해야 한다면 HTML <form> element를 대신 사용하세요.
  • <input type="file">: action이 string일 때 이 input type을 사용하면, 브라우저 동작과 동일하게 file object 대신 파일 이름이 제출됩니다.
  • formAction: Can be used in a <button> or <input type="submit"> fields to override the action prop. Next.js will perform a client-side navigation, however, this approach doesn't support prefetching.
    • When using basePath, you must also include it in the formAction path. e.g. formAction="/base-path/search".
  • key: Passing a key prop to a string action is not supported. If you'd like to trigger a re-render or perform a mutation, consider using a function action instead.
  • onSubmit: Can be used to handle form submission logic. However, calling event.preventDefault() will override <Form> behavior such as navigating to the specified URL.
  • method, encType, target: Are not supported as they override <Form> behavior.
    • Similarly, formMethod, formEncType, and formTarget can be used to override the method, encType, and target props respectively, and using them will fallback to native browser behavior.
    • If you need to use these props, use the HTML <form> element instead.
  • <input type="file">: Using this input type when the action is a string will match browser behavior by submitting the filename instead of the file object.

Examples예시

Search form that leads to a search result page검색 결과 page로 이동하는 검색 form

경로를 action으로 전달해 검색 결과 page로 navigate하는 검색 form을 만들 수 있습니다:

You can create a search form that navigates to a search results page by passing the path as an action:

TSJS/app/page.tsx
import Form from 'next/form'

export default function Page() {
  return (
    <Form action="/search">
      <input name="query" />
      <button type="submit">Submit</button>
    </Form>
  )
}
import Form from 'next/form'

export default function Page() {
  return (
    <Form action="/search">
      <input name="query" />
      <button type="submit">Submit</button>
    </Form>
  )
}

사용자가 query input field를 수정하고 form을 제출하면, form data가 search params로 URL에 encode됩니다. 예: /search?query=abc.

When the user updates the query input field and submits the form, the form data will be encoded into the URL as search params, e.g. /search?query=abc.

Good to know

action에 빈 문자열 ""을 전달하면 form은 업데이트된 search params와 함께 같은 route로 navigate합니다.

If you pass an empty string "" to action, the form will navigate to the same route with updated search params.

결과 page에서는 searchParams page.js prop으로 query에 접근하고, 이를 사용해 외부 source에서 데이터를 fetch할 수 있습니다.

On the results page, you can access the query using the searchParams page.js prop and use it to fetch data from an external source.

TSJS/app/search/page.tsx
import { getSearchResults } from '@/lib/search'

export default async function SearchPage({
  searchParams,
}: {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const results = await getSearchResults((await searchParams).query)

  return <div>...</div>
}
import { getSearchResults } from '@/lib/search'

export default async function SearchPage({ searchParams }) {
  const results = await getSearchResults((await searchParams).query)

  return <div>...</div>
}

<Form>이 사용자의 viewport에 보이게 되면 /search page의 공유 UI(layout.js, loading.js 등)가 prefetch됩니다. 제출하면 form은 즉시 새 route로 navigate하고, 결과를 fetch하는 동안 loading UI를 보여 줍니다. loading.js를 사용해 fallback UI를 디자인할 수 있습니다:

When the <Form> becomes visible in the user's viewport, shared UI (such as layout.js and loading.js) on the /search page will be prefetched. On submission, the form will immediately navigate to the new route and show loading UI while the results are being fetched. You can design the fallback UI using loading.js:

TSJS/app/search/loading.tsx
export default function Loading() {
  return <div>Loading...</div>
}
export default function Loading() {
  return <div>Loading...</div>
}

공유 UI가 아직 load되지 않은 경우에 대비해, useFormStatus를 사용해 사용자에게 즉각적인 feedback을 보여 줄 수 있습니다.

To cover cases when shared UI hasn't yet loaded, you can show instant feedback to the user using useFormStatus.

먼저 form이 pending 상태일 때 loading state를 표시하는 component를 만드세요:

First, create a component that displays a loading state when the form is pending:

TSJS/app/ui/search-button.tsx
'use client'
import { useFormStatus } from 'react-dom'

export default function SearchButton() {
  const status = useFormStatus()
  return (
    <button type="submit">{status.pending ? 'Searching...' : 'Search'}</button>
  )
}
'use client'
import { useFormStatus } from 'react-dom'

export default function SearchButton() {
  const status = useFormStatus()
  return (
    <button type="submit">{status.pending ? 'Searching...' : 'Search'}</button>
  )
}

그다음 검색 form page가 SearchButton component를 사용하도록 업데이트하세요:

Then, update the search form page to use the SearchButton component:

TSJS/app/page.tsx
import Form from 'next/form'
import { SearchButton } from '@/ui/search-button'

export default function Page() {
  return (
    <Form action="/search">
      <input name="query" />
      <SearchButton />
    </Form>
  )
}
import Form from 'next/form'
import { SearchButton } from '@/ui/search-button'

export default function Page() {
  return (
    <Form action="/search">
      <input name="query" />
      <SearchButton />
    </Form>
  )
}

Mutations with Server ActionsServer Action으로 mutation 수행하기

action prop에 function을 전달해 mutation을 수행할 수 있습니다.

You can perform mutations by passing a function to the action prop.

TSJS/app/posts/create/page.tsx
import Form from 'next/form'
import { createPost } from '@/posts/actions'

export default function Page() {
  return (
    <Form action={createPost}>
      <input name="title" />
      {/* ... */}
      <button type="submit">Create Post</button>
    </Form>
  )
}
import Form from 'next/form'
import { createPost } from '@/posts/actions'

export default function Page() {
  return (
    <Form action={createPost}>
      <input name="title" />
      {/* ... */}
      <button type="submit">Create Post</button>
    </Form>
  )
}

mutation 후에는 새 resource로 redirect하는 것이 일반적입니다. next/navigation의 redirect function을 사용해 새 post page로 navigate할 수 있습니다.

After a mutation, it's common to redirect to the new resource. You can use the redirect function from next/navigation to navigate to the new post page.

Good to know

form 제출의 "목적지"는 action이 실행되기 전까지 알 수 없으므로, <Form>은 공유 UI를 자동으로 prefetch할 수 없습니다.

Since the "destination" of the form submission is not known until the action is executed, <Form> cannot automatically prefetch shared UI.

TSJS/app/posts/actions.ts
'use server'
import { redirect } from 'next/navigation'

export async function createPost(formData: FormData) {
  // Create a new post
  // ...

  // Redirect to the new post
  redirect(`/posts/${data.id}`)
}
'use server'
import { redirect } from 'next/navigation'

export async function createPost(formData) {
  // Create a new post
  // ...

  // Redirect to the new post
  redirect(`/posts/${data.id}`)
}

그다음 새 page에서 params prop을 사용해 데이터를 fetch할 수 있습니다:

Then, in the new page, you can fetch data using the params prop:

TSJS/app/posts/[id]/page.tsx
import { getPost } from '@/posts/data'

export default async function PostPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const data = await getPost(id)

  return (
    <div>
      <h1>{data.title}</h1>
      {/* ... */}
    </div>
  )
}
import { getPost } from '@/posts/data'

export default async function PostPage({ params }) {
  const { id } = await params
  const data = await getPost(id)

  return (
    <div>
      <h1>{data.title}</h1>
      {/* ... */}
    </div>
  )
}
