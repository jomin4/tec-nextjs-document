How to migrate from Create React App to Next.jsCreate React App에서 Next.js로 migrate하기

이 가이드는 기존 Create React App(CRA) 사이트를 Next.js로 migrate하는 과정을 안내합니다.

This guide will help you migrate an existing Create React App (CRA) site to Next.js.

Why Switch?왜 전환해야 할까?

Create React App에서 Next.js로 전환하고 싶은 이유는 여러 가지가 있습니다:

There are several reasons why you might want to switch from Create React App to Next.js:

Slow initial page loading time느린 초기 page loading 시간

Create React App은 순수하게 client-side rendering만 사용합니다. single-page application(SPA)이라고도 불리는 client-side 전용 애플리케이션은 초기 page loading 시간이 느린 경우가 많습니다. 그 이유는 다음과 같습니다:

Create React App uses purely client-side rendering. Client-side only applications, also known as single-page applications (SPAs), often experience slow initial page loading time. This happens due to a couple of reasons:

  1. 코드가 data를 불러오는 request를 보내기 전에, 브라우저는 React 코드와 애플리케이션 bundle 전체가 다운로드되고 실행될 때까지 기다려야 합니다.
  2. 새 기능과 dependency를 추가할 때마다 애플리케이션 코드가 커집니다.
  1. The browser needs to wait for the React code and your entire application bundle to download and run before your code is able to send requests to load data.
  2. Your application code grows with every new feature and dependency you add.

No automatic code splitting자동 code splitting 없음

앞에서 말한 느린 loading 시간 문제는 code splitting으로 어느 정도 완화할 수 있습니다. 하지만 code splitting을 직접 하려고 하면 의도치 않게 network waterfall이 생길 수 있습니다. Next.js는 router와 build pipeline에 자동 code splitting과 tree-shaking이 내장되어 있습니다.

The previous issue of slow loading times can be somewhat mitigated with code splitting. However, if you try to do code splitting manually, you can inadvertently introduce network waterfalls. Next.js provides automatic code splitting and tree-shaking built into its router and build pipeline.

Network waterfallsNetwork waterfall

performance가 나빠지는 흔한 원인은 애플리케이션이 data를 fetch하기 위해 client-server request를 순차적으로 보내는 경우입니다. SPA에서 data를 fetch하는 한 가지 pattern은 placeholder를 render한 뒤 component가 mount된 다음에 data를 fetch하는 것입니다. 안타깝게도 child component는 parent가 자신의 data를 다 불러온 뒤에야 data fetching을 시작할 수 있어서, request의 "waterfall"이 생깁니다.

A common cause of poor performance occurs when applications make sequential client-server requests to fetch data. One pattern for data fetching in a SPA is to render a placeholder, and then fetch data after the component has mounted. Unfortunately, a child component can only begin fetching data after its parent has finished loading its own data, resulting in a “waterfall” of requests.

Next.js에서도 client-side data fetching을 지원하지만, Next.js에서는 data fetching을 server로 옮길 수도 있습니다. 이렇게 하면 client-server waterfall이 아예 사라지는 경우가 많습니다.

While client-side data fetching is supported in Next.js, Next.js also lets you move data fetching to the server. This often eliminates client-server waterfalls altogether.

Fast and intentional loading states빠르고 의도된 loading state

React Suspense를 통한 streaming이 기본 지원되므로, network waterfall을 만들지 않고도 UI의 어떤 부분을 먼저, 어떤 순서로 load할지 정의할 수 있습니다.

With built-in support for streaming through React Suspense, you can define which parts of your UI load first and in what order, without creating network waterfalls.

이를 통해 더 빠르게 load되는 page를 만들고 layout shift를 없앨 수 있습니다.

This enables you to build pages that are faster to load and eliminate layout shifts.

Choose the data fetching strategydata fetching strategy 선택

Next.js에서는 필요에 따라 page나 component 단위로 data fetching strategy를 선택할 수 있습니다. 예를 들어 빠른 load 속도를 위해 build 시점에 CMS에서 data를 fetch해 블로그 글을 render(SSG)하거나, 필요할 때는 request 시점에 data를 fetch(SSR)할 수 있습니다.

Depending on your needs, Next.js allows you to choose your data fetching strategy on a page or component-level basis. For example, you could fetch data from your CMS and render blog posts at build time (SSG) for quick load speeds, or fetch data at request time (SSR) when necessary.

Proxy

Next.js Proxy를 사용하면 request가 완료되기 전에 server에서 코드를 실행할 수 있습니다. 예를 들어 인증된 사용자 전용 page에서는 proxy에서 사용자를 login page로 redirect해, 인증되지 않은 콘텐츠가 잠깐 보이는 현상을 막을 수 있습니다. A/B testing, 실험(experimentation), internationalization 같은 기능에도 사용할 수 있습니다.

Next.js Proxy allows you to run code on the server before a request is completed. For instance, you can avoid a flash of unauthenticated content by redirecting a user to a login page in the proxy for authenticated-only pages. You can also use it for features like A/B testing, experimentation, and internationalization.

Built-in Optimizations내장 최적화

Image, font, third-party script는 애플리케이션 performance에 큰 영향을 주는 경우가 많습니다. Next.js에는 이를 자동으로 최적화해 주는 전용 component와 API가 포함되어 있습니다.

Images, fonts, and third-party scripts often have a large impact on an application’s performance. Next.js includes specialized components and APIs that automatically optimize them for you.

Migration StepsMigration 단계

목표는 동작하는 Next.js 애플리케이션을 최대한 빨리 만들어서, 그다음 Next.js 기능을 점진적으로 도입할 수 있게 하는 것입니다. 우선은 기존 router를 바로 교체하지 않고 애플리케이션을 순수한 client-side 애플리케이션(SPA)으로 취급합니다. 이렇게 하면 복잡도와 merge conflict가 줄어듭니다.

Our goal is to get a working Next.js application as quickly as possible so that you can then adopt Next.js features incrementally. To begin with, we’ll treat your application as a purely client-side application (SPA) without immediately replacing your existing router. This reduces complexity and merge conflicts.

Note

package.json의 custom homepage field, custom service worker, 특정 Babel/webpack 조정 같은 고급 CRA configuration을 사용하고 있다면, 이 가이드 끝의 Additional Considerations 섹션에서 이런 기능을 Next.js에서 재현하거나 조정하는 팁을 참고하세요.

If you are using advanced CRA configurations such as a custom homepage field in your package.json, a custom service worker, or specific Babel/webpack tweaks, please see the Additional Considerations section at the end of this guide for tips on replicating or adapting these features in Next.js.

Step 1: Install the Next.js Dependency1단계: Next.js dependency 설치하기

기존 프로젝트에 Next.js를 설치하세요:

Install Next.js in your existing project:

pnpm add next@latest
npm install next@latest
yarn add next@latest
bun add next@latest

Step 2: Create the Next.js Configuration File2단계: Next.js configuration 파일 만들기

프로젝트 root(package.json과 같은 위치)에 next.config.ts를 만드세요. 이 파일에는 Next.js configuration option이 들어갑니다.

Create a next.config.ts at the root of your project (same level as your package.json). This file holds your Next.js configuration options.

JSnext.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  output: 'export', // Outputs a Single-Page Application (SPA)
  distDir: 'build', // Changes the build output directory to `build`
}

export default nextConfig
Note

output: 'export'를 사용하면 static export를 하게 됩니다. SSR이나 API 같은 server-side 기능은 사용할 수 없습니다. Next.js server 기능을 활용하려면 이 줄을 제거하면 됩니다.

Using output: 'export' means you’re doing a static export. You will not have access to server-side features like SSR or APIs. You can remove this line to leverage Next.js server features.

Step 3: Create the Root Layout3단계: Root Layout 만들기

Next.js App Router 애플리케이션에는 root layout 파일이 반드시 있어야 합니다. 이 파일은 모든 page를 감싸는 React Server Component입니다.

A Next.js App Router application must include a root layout file, which is a React Server Component that will wrap all your pages.

CRA 애플리케이션에서 root layout 파일에 가장 가까운 것은 <html>, <head>, <body> tag가 들어 있는 public/index.html입니다.

The closest equivalent of the root layout file in a CRA application is public/index.html, which includes your <html>, <head>, and <body> tags.

  1. src 폴더 안에(또는 app을 root에 두고 싶다면 프로젝트 root에) 새 app directory를 만드세요.
  2. app directory 안에 layout.tsx(또는 layout.js) 파일을 만드세요:
  1. Create a new app directory inside your src folder (or at your project root if you prefer app at the root).
  2. Inside the app directory, create a layout.tsx (or layout.js) file:
TSJSapp/layout.tsx
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return '...'
}
export default function RootLayout({ children }) {
  return '...'
}

이제 기존 index.html의 내용을 이 <RootLayout> component에 복사하세요. body div#root(와 body noscript)를 <div id="root">{children}</div>로 바꾸세요.

Now copy the content of your old index.html into this <RootLayout> component. Replace body div#root (and body noscript) with <div id="root">{children}</div>.

Good to know

Next.js는 기본적으로 CRA의 public/manifest.json, 추가 icon 이미지, testing configuration을 무시합니다. 이것들이 필요하다면 Next.js의 Metadata API와 Testing setup으로 지원받을 수 있습니다.

Next.js ignores CRA’s public/manifest.json, additional iconography, and testing configuration by default. If you need these, Next.js has support with its Metadata API and Testing setup.

위와 같이 변경하면 index.html에 모든 것을 선언하던 방식에서 framework에 내장된 Next.js의 convention 기반 접근 방식(Metadata API)으로 바뀝니다. 이 접근 방식을 사용하면 page의 SEO와 웹 공유성(shareability)을 더 쉽게 개선할 수 있습니다.

With the above changes, you shifted from declaring everything in your index.html to using Next.js' convention-based approach built into the framework (Metadata API). This approach enables you to more easily improve your SEO and web shareability of your pages.

Step 6: Create the Entrypoint Page6단계: Entrypoint Page 만들기

Create React App은 src/index.tsx(또는 index.js)를 entry point로 사용합니다. Next.js(App Router)에서는 app directory 안의 각 폴더가 하나의 route에 대응하며, 각 폴더에는 page.tsx가 있어야 합니다.

Create React App uses src/index.tsx (or index.js) as the entry point. In Next.js (App Router), each folder inside the app directory corresponds to a route, and each folder should have a page.tsx.

지금은 앱을 SPA로 유지하면서 모든 route를 가로채고 싶으므로 optional catch-all route를 사용합니다.

Since we want to keep the app as an SPA for now and intercept all routes, we’ll use an optional catch-all route.

  1. app 안에 [[...slug]] directory를 만드세요.
  1. Create a [[...slug]] directory inside app.
app
 ┣ [[...slug]]
 ┃ ┗ page.tsx
 ┣ layout.tsx
  1. page.tsx에 다음 내용을 추가하세요:
  1. Add the following to page.tsx:
TSJSapp/[[...slug]]/page.tsx
export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return '...' // We'll update this
}
export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return '...' // We'll update this
}

이렇게 하면 Next.js가 빈 slug(/)에 대해 하나의 route만 생성하므로, 사실상 모든 route가 같은 page로 mapping됩니다. 이 page는 static HTML로 prerender되는 Server Component입니다.

This tells Next.js to generate a single route for the empty slug (/), effectively mapping all routes to the same page. This page is a Server Component, prerendered into static HTML.

Step 7: Add a Client-Only Entrypoint7단계: Client 전용 Entrypoint 추가하기

다음으로 CRA의 root App component를 Client Component 안에 넣어 모든 로직이 client-side에 남도록 합니다. Next.js를 처음 사용한다면, Client Component도 (기본적으로) server에서 prerender된다는 점을 알아 두면 좋습니다. Client Component는 client-side JavaScript를 실행하는 능력이 추가된 component라고 생각하면 됩니다.

Next, we’ll embed your CRA’s root App component inside a Client Component so that all logic remains client-side. If this is your first time using Next.js, it's worth knowing that Client Components (by default) are still prerendered on the server. You can think about them as having the additional capability of running client-side JavaScript.

app/[[...slug]]/에 client.tsx(또는 client.js)를 만드세요:

Create a client.tsx (or client.js) in app/[[...slug]]/:

TSJSapp/[[...slug]]/client.tsx
'use client'

import dynamic from 'next/dynamic'

const App = dynamic(() => import('../../App'), { ssr: false })

export function ClientOnly() {
  return <App />
}
'use client'

import dynamic from 'next/dynamic'

const App = dynamic(() => import('../../App'), { ssr: false })

export function ClientOnly() {
  return <App />
}
  • 'use client' directive가 있으면 이 파일은 Client Component 파일이 됩니다.
  • ssr: false를 지정한 dynamic import는 <App /> component의 server-side rendering을 비활성화해, 완전한 client 전용(SPA)으로 만듭니다.
  • The 'use client' directive makes this file a Client Component.
  • The dynamic import with ssr: false disables server-side rendering for the <App /> component, making it truly client-only (SPA).

이제 새 component를 사용하도록 page.tsx(또는 page.js)를 업데이트하세요:

Now update your page.tsx (or page.js) to use your new component:

TSJSapp/[[...slug]]/page.tsx
import { ClientOnly } from './client'

export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return <ClientOnly />
}
import { ClientOnly } from './client'

export function generateStaticParams() {
  return [{ slug: [''] }]
}

export default function Page() {
  return <ClientOnly />
}

Step 8: Update Static Image Imports8단계: Static Image Import 업데이트하기

CRA에서는 image 파일을 import하면 그 public URL이 string으로 반환됩니다:

In CRA, importing an image file returns its public URL as a string:

import image from './img.png'

export default function App() {
  return <img src={image} />
}

Next.js에서는 static image import가 object를 반환합니다. 이 object는 Next.js <Image> component에 바로 사용할 수도 있고, object의 src property를 기존 <img> tag에 사용할 수도 있습니다.

With Next.js, static image imports return an object. The object can then be used directly with the Next.js <Image> component, or you can use the object's src property with your existing <img> tag.

<Image> component에는 자동 image 최적화라는 추가 장점이 있습니다. <Image> component는 image의 크기를 바탕으로 결과 <img>의 width와 height attribute를 자동으로 설정합니다. 이렇게 하면 image가 load될 때 layout shift가 생기지 않습니다. 하지만 앱에 가로·세로 중 한쪽 크기에만 style이 지정되고 다른 쪽은 auto로 지정되지 않은 image가 있다면 문제가 생길 수 있습니다. auto로 지정되지 않은 쪽 크기는 <img>의 크기 attribute 값을 기본값으로 쓰기 때문에 image가 찌그러져 보일 수 있습니다.

The <Image> component has the added benefits of automatic image optimization. The <Image> component automatically sets the width and height attributes of the resulting <img> based on the image's dimensions. This prevents layout shifts when the image loads. However, this can cause issues if your app contains images with only one of their dimensions being styled without the other styled to auto. When not styled to auto, the dimension will default to the <img> dimension attribute's value, which can cause the image to appear distorted.

<img> tag를 그대로 유지하면 애플리케이션의 변경량을 줄이고 위 문제를 막을 수 있습니다. 그런 다음 원한다면 나중에 <Image> component로 migrate해서 loader를 설정하거나 자동 image 최적화가 있는 기본 Next.js server로 옮겨 image 최적화의 이점을 누릴 수 있습니다.

Keeping the <img> tag will reduce the amount of changes in your application and prevent the above issues. You can then optionally later migrate to the <Image> component to take advantage of optimizing images by configuring a loader, or moving to the default Next.js server which has automatic image optimization.

/public에서 import한 image의 absolute import path를 relative import로 바꾸세요:

Convert absolute import paths for images imported from /public into relative imports:

// Before
import logo from '/logo.png'

// After
import logo from '../public/logo.png'

image object 전체 대신 image의 src property를 <img> tag에 전달하세요:

Pass the image src property instead of the whole image object to your <img> tag:

// Before
<img src={logo} />

// After
<img src={logo.src} />

또는 파일 이름을 바탕으로 image asset의 public URL을 참조할 수도 있습니다. 예를 들어 public/logo.png는 애플리케이션에서 /logo.png로 제공되며, 이것이 src 값이 됩니다.

Alternatively, you can reference the public URL for the image asset based on the filename. For example, public/logo.png will serve the image at /logo.png for your application, which would be the src value.

Warning

TypeScript를 사용한다면 src property에 접근할 때 type error가 발생할 수 있습니다. 이를 해결하려면 tsconfig.json 파일의 include array에 next-env.d.ts를 추가해야 합니다. 9단계에서 애플리케이션을 실행하면 Next.js가 이 파일을 자동으로 생성합니다.

If you're using TypeScript, you might encounter type errors when accessing the src property. To fix them, you need to add next-env.d.ts to the include array of your tsconfig.json file. Next.js will automatically generate this file when you run your application on step 9.

Step 9: Migrate Environment Variables9단계: Environment Variable migrate하기

Next.js는 CRA와 비슷하게 environment variable을 지원하지만, 브라우저에 노출하려는 variable에는 반드시 NEXT_PUBLIC_ 접두사가 필요합니다.

Next.js supports environment variables similarly to CRA but requires a NEXT_PUBLIC_ prefix for any variable you want to expose in the browser.

가장 큰 차이는 client-side에 environment variable을 노출할 때 쓰는 접두사입니다. REACT_APP_ 접두사가 붙은 모든 environment variable을 NEXT_PUBLIC_으로 바꾸세요.

The main difference is the prefix used to expose environment variables on the client-side. Change all environment variables with the REACT_APP_ prefix to NEXT_PUBLIC_.

Step 10: Update Scripts in package.json10단계: package.json의 script 업데이트하기

Next.js command를 사용하도록 package.json script를 업데이트하세요. 또한 .gitignore에 .next와 next-env.d.ts를 추가하세요:

Update your package.json scripts to use Next.js commands. Also, add .next and next-env.d.ts to your .gitignore:

package.json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "npx serve@latest ./build"
  }
}
>_.gitignore
# ...
.next
next-env.d.ts

이제 다음을 실행할 수 있습니다:

Now you can run:

pnpm dev
npm run dev
yarn dev
bun dev

http://localhost:3000을 여세요. 이제 애플리케이션이 Next.js 위에서 (SPA 모드로) 실행되는 것을 확인할 수 있습니다.

Open http://localhost:3000. You should see your application now running on Next.js (in SPA mode).

Additional Considerations추가 고려 사항

Using a Custom homepage in CRACRA에서 custom homepage 사용하기

CRA package.json의 homepage field를 사용해 특정 subpath 아래에서 앱을 제공했다면, next.config.ts의 basePath configuration으로 Next.js에서 같은 동작을 재현할 수 있습니다:

If you used the homepage field in your CRA package.json to serve the app under a specific subpath, you can replicate that in Next.js using the basePath configuration in next.config.ts:

TSnext.config.ts
import { NextConfig } from 'next'

const nextConfig: NextConfig = {
  basePath: '/my-subpath',
  // ...
}

export default nextConfig

Handling a Custom Service Workercustom Service Worker 처리하기

CRA의 service worker(예: create-react-app의 serviceWorker.js)를 사용했다면, 다음 문법으로 이 service worker를 등록할 수 있습니다:

If you used CRA’s service worker (e.g., serviceWorker.js from create-react-app), you can register this service worker using the following syntax:

await navigator.serviceWorker.register(new URL('../serviceWorker.js', import.meta.url), ...)

Next.js로 Progressive Web Application(PWA)을 만드는 방법에 대해 더 알아보세요.

Learn more about how to create Progressive Web Applications (PWAs) with Next.js.

Proxying API RequestsAPI Request proxy하기

CRA 앱에서 package.json의 proxy field를 사용해 request를 backend server로 전달했다면, next.config.ts의 Next.js rewrites로 같은 동작을 재현할 수 있습니다:

If your CRA app used the proxy field in package.json to forward requests to a backend server, you can replicate this with Next.js rewrites in next.config.ts:

TSnext.config.ts
import { NextConfig } from 'next'

const nextConfig: NextConfig = {
  async rewrites() {
    return [
      {
        source: '/api/:path*',
        destination: 'https://your-backend.com/:path*',
      },
    ]
  },
}

Custom Webpack

CRA에서 custom webpack이나 Babel configuration을 사용했다면 next.config.ts에서 Next.js의 config를 확장할 수 있습니다:

If you had a custom webpack or Babel configuration in CRA, you can extend Next.js’s config in next.config.ts:

TSnext.config.ts
import { NextConfig } from 'next'

const nextConfig: NextConfig = {
  webpack: (config, { isServer }) => {
    // Modify the webpack config here
    return config
  },
}

export default nextConfig
Note

이렇게 하려면 dev script에 --webpack을 추가해 Webpack을 사용해야 합니다.

This will require using Webpack by adding --webpack to your dev script.

TypeScript SetupTypeScript 설정

tsconfig.json이 있으면 Next.js가 TypeScript를 자동으로 설정합니다. tsconfig.json의 include array에 next-env.d.ts가 들어 있는지 확인하세요:

Next.js automatically sets up TypeScript if you have a tsconfig.json. Make sure next-env.d.ts is listed in your tsconfig.json include array:

{
  "include": ["next-env.d.ts", "app/**/*", "src/**/*"]
}

Bundler CompatibilityBundler 호환성

Create React App은 bundling에 webpack을 사용합니다. Next.js는 이제 더 빠른 로컬 개발을 위해 기본적으로 Turbopack을 사용합니다:

Create React App uses webpack for bundling. Next.js now defaults to Turbopack for faster local development:

next dev  # Uses Turbopack by default

대신 (CRA와 비슷하게) Webpack을 사용하려면:

To use Webpack instead (similar to CRA):

next dev --webpack

CRA의 고급 webpack 설정을 migrate해야 한다면 여전히 custom webpack configuration을 제공할 수 있습니다.

You can still provide a custom webpack configuration if you need to migrate advanced webpack settings from CRA.

  • Migrate from React Router to the Next.js App Router for:

static export(output: 'export')를 사용하면 현재 useParams hook이나 다른 server 기능을 지원하지 않습니다. Next.js의 모든 기능을 사용하려면 next.config.ts에서 output: 'export'를 제거하세요.

Using a static export (output: 'export') does not currently support the useParams hook or other server features. To use all Next.js features, remove output: 'export' from your next.config.ts.
