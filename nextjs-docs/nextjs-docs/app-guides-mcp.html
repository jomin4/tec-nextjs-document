Connecting coding agents to the Next.js MCP servercoding agent를 Next.js MCP server에 연결하기

Model Context Protocol (MCP)은 AI agent와 coding assistant가 하나의 공유 interface를 통해 애플리케이션과 상호작용할 수 있게 해 주는 open standard입니다.

The Model Context Protocol (MCP) is an open standard that lets AI agents and coding assistants interact with your applications through one shared interface.

Next.js 16 이상에서는 development server가 /_next/mcp에 MCP endpoint를 노출합니다. 이 endpoint는 coding agent에게 실행 중인 앱 관점의 error, route, log, compilation issue 정보를 제공합니다. agent client를 여기에 연결하려면 next-devtools-mcp package를 설치하세요.

In Next.js 16 and later, the development server exposes an MCP endpoint at /_next/mcp. It gives coding agents the running app's view of errors, routes, logs, and compilation issues. To connect your agent client to it, install the next-devtools-mcp package.

next-dev-loop 같은 skill은 /_next/mcp를 직접 호출하므로 이 setup 없이도 동작합니다.

Skills such as next-dev-loop call /_next/mcp directly, so they work without this setup.

Getting started시작하기

add-mcp로 내 컴퓨터의 coding agent에 next-devtools-mcp를 설치하세요:

Install next-devtools-mcp for the coding agents on your machine with add-mcp:

>_Terminal
npx add-mcp next-devtools-mcp@latest

또는 프로젝트 root의 .mcp.json 파일에 추가하세요:

Or add it to the .mcp.json file at the root of your project:

.mcp.json
{
  "mcpServers": {
    "next-devtools": {
      "command": "npx",
      "args": ["-y", "next-devtools-mcp@latest"]
    }
  }
}

development server를 시작하면 next-devtools-mcp가 실행 중인 Next.js instance를 찾아 연결합니다. client별 setup은 next-devtools-mcp repository를 참고하세요.

When you start your development server, next-devtools-mcp discovers and connects to the running Next.js instance. For client-specific setup, see the next-devtools-mcp repository.

Capabilities기능

next-devtools-mcp는 agent client를 Next.js development server에 연결합니다. agent에게 다음 tool을 제공합니다:

next-devtools-mcp connects your agent client to the Next.js development server. It gives agents these tools:

  • nextjs_index: 실행 중인 Next.js dev server를 찾고, 각 server가 노출하는 runtime tool 목록을 보여 줍니다.
  • nextjs_call: 찾아낸 dev server의 runtime tool을 호출합니다.
  • nextjs_docs: agent가 node_modules/next/dist/docs/에 있는, 설치된 Next.js와 버전이 일치하는 번들 문서를 참고하도록 안내합니다.
  • browser_eval: 실제 브라우저에서 페이지를 검증할 수 있도록 agent에게 agent-browser CLI를 안내합니다.
  • nextjs_index: Discovers running Next.js dev servers and lists the runtime tools each one exposes.
  • nextjs_call: Calls a runtime tool on a discovered dev server.
  • nextjs_docs: Points the agent at the version-matched docs bundled with your installed Next.js in node_modules/next/dist/docs/.
  • browser_eval: Points the agent at the agent-browser CLI for verifying pages in a real browser.

nextjs_docs와 browser_eval은 직접 작업을 수행하지 않습니다. 문서가 어디에 있는지, 또는 CLI를 어떻게 실행하는지 agent에게 알려 주고, agent가 그것을 직접 사용합니다.

nextjs_docs and browser_eval don't do the work themselves. They tell the agent where the docs are or how to run the CLI, and the agent uses them directly.

Runtime toolsRuntime tool

nextjs_call을 통해 agent는 Next.js development server가 /_next/mcp에 노출하는 tool을 사용할 수 있습니다:

Through nextjs_call, agents can use the tools the Next.js development server exposes at /_next/mcp:

  • get_errors: next.config 검증 같은 Next.js global error, browser runtime error, source-mapped stack trace가 포함된 build error 등 현재 error 상태를 가져옵니다.
  • get_logs: 브라우저 console log와 server 출력이 담긴 development log 파일의 경로를 가져옵니다.
  • get_page_metadata: 현재 page render에 무엇이 기여하는지에 대한 runtime metadata를 가져옵니다. 페이지가 브라우저에 열려 있어야 합니다.
  • get_project_metadata: 프로젝트 경로와 dev server URL을 가져옵니다.
  • get_routes: filesystem을 scan해서 entry point가 될 모든 route를 가져옵니다. route는 router 종류(appRouter, pagesRouter)별로 묶여 반환됩니다. dynamic segment는 [param] 또는 [...slug] 패턴으로 표시됩니다.
  • get_server_action_by_id: ID로 Server Action을 조회해 source 파일과 export 이름을 찾습니다.
  • get_compilation_issues: 모든 route에 대한 module graph를 build하고, resolve error, 누락된 module, transform error 같은 compilation issue를 반환합니다. browser session이 필요 없습니다. Turbopack 전용입니다.
  • compile_route: HTTP request를 보내지 않고 특정 route를 compile합니다. routeSpecifier(예: get_routes가 반환하는 /blog/[slug]) 또는 path(예: /blog/hello-world)를 받으며, path는 일치하는 route로 resolve됩니다. 해당 route의 compilation issue를 반환합니다. Turbopack 전용입니다.
  • get_request_insights: local span recorder가 기록한 최근 App Router request timeline, server fetch, cache 동작을 가져옵니다. experimental.requestInsights가 필요합니다.
  • get_errors: Get the current error state, including Next.js global errors such as next.config validation, browser runtime errors, and build errors with source-mapped stack traces.
  • get_logs: Get the path to the development log file, which contains browser console logs and server output.
  • get_page_metadata: Get runtime metadata about what contributes to the current page render. Requires the page to be open in a browser.
  • get_project_metadata: Get the project path and dev server URL.
  • get_routes: Get all routes that will become entry points by scanning the filesystem. Returns routes grouped by router type (appRouter, pagesRouter). Dynamic segments appear as [param] or [...slug] patterns.
  • get_server_action_by_id: Look up a Server Action by its ID to find its source file and export name.
  • get_compilation_issues: Build the module graph for all routes and return compilation issues such as resolve errors, missing modules, and transform errors. Doesn't require a browser session. Turbopack only.
  • compile_route: Compile a specific route without making an HTTP request to it. Accepts either a routeSpecifier (for example, /blog/[slug], as returned by get_routes) or a path (for example, /blog/hello-world), which is resolved to the matching route. Returns any compilation issues for the route. Turbopack only.
  • get_request_insights: Get recent App Router request timelines, server fetches, and cache behavior captured by the local span recorder. Requires experimental.requestInsights.

compilation tool을 사용하면 agent는 아직 코드를 편집하는 중에 next build를 실행하는 대신, 실행 중인 dev server에서 코드가 compile되는지 확인할 수 있습니다.

With the compilation tools, agents can check whether code compiles from the running dev server instead of running next build while they are still editing.

Development workflow개발 workflow

  1. Next.js development server를 시작합니다:
  1. Start your Next.js development server:
pnpm dev
npm run dev
yarn dev
bun dev
  1. coding agent가 next-devtools-mcp를 통해 실행 중인 Next.js instance에 연결합니다.
  2. 작업 중인 페이지를 브라우저에서 엽니다. get_errors, get_page_metadata 같은 tool은 활성 browser session에서 정보를 읽습니다.
  3. 아래 예시처럼 agent에게 실행 중인 앱에 대해 물어봅니다.
  1. Your coding agent connects to the running Next.js instance through next-devtools-mcp.
  2. Open the pages you're working on in the browser. Tools such as get_errors and get_page_metadata read from active browser sessions.
  3. Ask your agent about the running app, as in the examples below.

How it works동작 방식

Next.js 16+ development server는 /_next/mcp에서 built-in MCP endpoint를 실행합니다. next-devtools-mcp package는 이 endpoint를 찾아 통신하므로 다음을 할 수 있습니다:

The Next.js 16+ development server runs a built-in MCP endpoint at /_next/mcp. The next-devtools-mcp package discovers these endpoints and communicates with them, so it can:

  • 서로 다른 port에서 실행 중인 여러 Next.js instance에 연결
  • tool 호출을 올바른 Next.js dev server로 전달
  • 모든 instance에 대해 agent에게 하나의 tool set 제공
  • Connect to multiple Next.js instances running on different ports
  • Forward tool calls to the right Next.js dev server
  • Give agents one set of tools for every instance

next-devtools-mcp를 통해 연결하는 agent는 Next.js 프로젝트와 버전에 상관없이 같은 setup을 사용합니다.

Agents that connect through next-devtools-mcp use the same setup across Next.js projects and versions.

endpoint는 기본적으로 활성화되어 있습니다. 비활성화하려면 next.config에서 experimental.mcpServer를 false로 설정하세요.

The endpoint is enabled by default. To disable it, set experimental.mcpServer to false in next.config.

Troubleshooting문제 해결

MCP server not connectingMCP server가 연결되지 않을 때

  • Next.js 16 이상을 사용하세요
  • agent client에 next-devtools-mcp가 설정되어 있는지 확인하세요(예: .mcp.json)
  • next.config에서 experimental.mcpServer가 false로 설정되어 있지 않은지 확인하세요
  • npm run dev로 development server를 시작하거나, 이미 실행 중이었다면 다시 시작하세요
  • coding agent가 MCP server configuration을 load했는지 확인하세요
  • Use Next.js 16 or later
  • Verify next-devtools-mcp is configured in your agent client, for example in .mcp.json
  • Check that experimental.mcpServer is not set to false in next.config
  • Start your development server with npm run dev, or restart it if it was already running
  • Check that your coding agent has loaded the MCP server configuration
