useRouteruseRouter

앱의 어떤 function component 안에서든 router object에 접근하고 싶다면 useRouter hook을 사용할 수 있습니다. 다음 예제를 살펴보세요:

If you want to access the router object inside any function component in your app, you can use the useRouter hook, take a look at the following example:

import { useRouter } from 'next/router'

function ActiveLink({ children, href }) {
  const router = useRouter()
  const style = {
    marginRight: 10,
    color: router.asPath === href ? 'red' : 'black',
  }

  const handleClick = (e) => {
    e.preventDefault()
    router.push(href)
  }

  return (
    <a href={href} onClick={handleClick} style={style}>
      {children}
    </a>
  )
}

export default ActiveLink

useRouter는 React Hook이므로 class와 함께 사용할 수 없습니다. withRouter를 사용하거나 class를 function component로 감싸세요.

useRouter is a React Hook, meaning it cannot be used with classes. You can either use withRouter or wrap your class in a function component.

router object

다음은 useRouter와 withRouter가 모두 반환하는 router object의 정의입니다:

The following is the definition of the router object returned by both useRouter and withRouter:

  • pathname: String - /pages 뒤에 오는 현재 route 파일의 경로입니다. 따라서 basePath, locale, trailing slash(trailingSlash: true)는 포함되지 않습니다.
  • query: Object - dynamic route parameter를 포함해 object로 parse된 query string입니다. page가 Server-side Rendering을 사용하지 않으면 prerendering 중에는 빈 object가 됩니다. 기본값은 {}입니다
  • asPath: String - search params를 포함하고 trailingSlash 설정을 반영한, 브라우저에 표시되는 경로입니다. basePath와 locale은 포함되지 않습니다.
  • isFallback: boolean - 현재 page가 fallback mode인지 여부입니다.
  • basePath: String - 활성화된 basePath입니다(활성화된 경우).
  • locale: String - 활성화된 locale입니다(활성화된 경우).
  • locales: String[] - 지원하는 모든 locale입니다(활성화된 경우).
  • defaultLocale: String - 현재 기본 locale입니다(활성화된 경우).
  • domainLocales: Array<{domain, defaultLocale, locales}> - 설정된 모든 domain locale입니다.
  • isReady: boolean - router field가 client-side에서 업데이트되어 사용할 준비가 되었는지 여부입니다. useEffect method 안에서만 사용해야 하며, server에서 조건부 rendering을 하는 용도로 사용하면 안 됩니다. automatically statically optimized page에서의 use case는 관련 문서를 참고하세요
  • isPreview: boolean - 애플리케이션이 현재 preview mode인지 여부입니다.
  • pathname: String - The path for current route file that comes after /pages. Therefore, basePath, locale and trailing slash (trailingSlash: true) are not included.
  • query: Object - The query string parsed to an object, including dynamic route parameters. It will be an empty object during prerendering if the page doesn't use Server-side Rendering. Defaults to {}
  • asPath: String - The path as shown in the browser including the search params and respecting the trailingSlash configuration. basePath and locale are not included.
  • isFallback: boolean - Whether the current page is in fallback mode.
  • basePath: String - The active basePath (if enabled).
  • locale: String - The active locale (if enabled).
  • locales: String[] - All supported locales (if enabled).
  • defaultLocale: String - The current default locale (if enabled).
  • domainLocales: Array<{domain, defaultLocale, locales}> - Any configured domain locales.
  • isReady: boolean - Whether the router fields are updated client-side and ready for use. Should only be used inside of useEffect methods and not for conditionally rendering on the server. See related docs for use case with automatically statically optimized pages
  • isPreview: boolean - Whether the application is currently in preview mode.

page가 server-side rendering이나 automatic static optimization으로 render되는 경우 asPath field를 사용하면 client와 server 사이에 mismatch가 생길 수 있습니다. isReady field가 true가 될 때까지는 asPath 사용을 피하세요.

Using the asPath field may lead to a mismatch between client and server if the page is rendered using server-side rendering or automatic static optimization. Avoid using asPath until the isReady field is true.

router 안에는 다음 method가 포함되어 있습니다:

The following methods are included inside router:

router.push

client-side transition을 처리합니다. 이 method는 next/link만으로는 충분하지 않은 경우에 유용합니다.

Handles client-side transitions, this method is useful for cases where next/link is not enough.

router.push(url, as, options)
  • url: UrlObject | String - 이동할 URL입니다(UrlObject property는 Node.js URL module 문서를 참고하세요).
  • as: UrlObject | String - 브라우저 URL bar에 표시될 경로를 위한 선택적 decorator입니다. Next.js 9.5.3 이전에는 dynamic route에 사용되었습니다.
  • options - 다음 configuration option을 가진 선택적 object입니다:
    • scroll - 선택적 boolean으로, navigation 후 page 맨 위로 scroll할지 제어합니다. 기본값은 true입니다
    • shallow: getStaticProps, getServerSideProps, getInitialProps를 다시 실행하지 않고 현재 page의 경로를 업데이트합니다. 기본값은 false입니다
    • locale - 선택적 string으로, 새 page의 locale을 나타냅니다
  • url: UrlObject | String - The URL to navigate to (see Node.js URL module documentation for UrlObject properties).
  • as: UrlObject | String - Optional decorator for the path that will be shown in the browser URL bar. Before Next.js 9.5.3 this was used for dynamic routes.
  • options - Optional object with the following configuration options:
    • scroll - Optional boolean, controls scrolling to the top of the page after navigation. Defaults to true
    • shallow: Update the path of the current page without rerunning getStaticProps, getServerSideProps or getInitialProps. Defaults to false
    • locale - Optional string, indicates locale of the new page

외부 URL에는 router.push를 사용할 필요가 없습니다. 그런 경우에는 window.location이 더 적합합니다.

You don't need to use router.push for external URLs. window.location is better suited for those cases.

미리 정의된 route인 pages/about.js로 이동하기:

Navigating to pages/about.js, which is a predefined route:

import { useRouter } from 'next/router'

export default function Page() {
  const router = useRouter()

  return (
    <button type="button" onClick={() => router.push('/about')}>
      Click me
    </button>
  )
}

Navigating pages/post/[pid].js, which is a dynamic route:

import { useRouter } from 'next/router'

export default function Page() {
  const router = useRouter()

  return (

사용자를 pages/login.js로 redirect하기. authentication 뒤에 있는 page에 유용합니다:

Redirecting the user to pages/login.js, useful for pages behind authentication:

import { useEffect } from 'react'
import { useRouter } from 'next/router'

// Here you would fetch and return the user
const useUser = () => ({ user: null, loading: false })

export default function Page() {
  const { user, loading } = useUser()
  const router = useRouter()

  useEffect(() => {
    if (!(user || loading)) {
      router.push('/login')
    }
  }, [user, loading])

  return <p>Redirecting...</p>
}

Resetting state after navigationnavigation 후 state 초기화하기

Next.js에서 같은 page로 이동할 때, React는 parent component가 바뀌지 않는 한 unmount하지 않으므로 기본적으로 page의 state는 초기화되지 않습니다.

When navigating to the same page in Next.js, the page's state will not be reset by default as React does not unmount unless the parent component has changed.

JSpages/[slug].js
import Link from 'next/link'
import { useState } from 'react'
import { useRouter } from 'next/router'

export default function Page(props) {
  const router = useRouter()
  const [count, setCount] = useState(0)
  return (
    <div>
      <h1>Page: {router.query.slug}</h1>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increase count</button>
      <Link href="/one">one</Link> <Link href="/two">two</Link>
    </div>
  )
}

위 예제에서 /one과 /two 사이를 이동해도 count는 초기화되지 않습니다. top-level React component인 Page가 동일하기 때문에 useState가 render 사이에 유지됩니다.

In the above example, navigating between /one and /two will not reset the count . The useState is maintained between renders because the top-level React component, Page, is the same.

이 동작을 원하지 않는다면 몇 가지 방법이 있습니다:

If you do not want this behavior, you have a couple of options:

  • useEffect를 사용해 각 state가 업데이트되도록 직접 보장합니다. 위 예제에서는 다음과 같이 할 수 있습니다:

    useEffect(() => {
  setCount(0)
}, [router.query.slug])

  • React key를 사용해 React가 component를 remount하도록 알립니다. 모든 page에 이렇게 하려면 custom app을 사용할 수 있습니다:

    JSpages/_app.js
    import { useRouter } from 'next/router'

export default function MyApp({ Component, pageProps }) {
  const router = useRouter()
  return <Component key={router.asPath} {...pageProps} />
}

  • Manually ensure each state is updated using useEffect. In the above example, that could look like:

    useEffect(() => {
  setCount(0)
}, [router.query.slug])

  • Use a React key to tell React to remount the component. To do this for all pages, you can use a custom app:

    JSpages/_app.js
    import { useRouter } from 'next/router'

export default function MyApp({ Component, pageProps }) {
  const router = useRouter()
  return <Component key={router.asPath} {...pageProps} />
}

With URL objectURL object와 함께 사용하기

next/link에서 사용하는 것과 같은 방식으로 URL object를 사용할 수 있습니다. url과 as parameter 모두에서 동작합니다:

You can use a URL object in the same way you can use it for next/link. Works for both the url and as parameters:

import { useRouter } from 'next/router'

export default function ReadMore({ post }) {
  const router = useRouter()

  return (
    <button
      type="button"
      onClick={() => {
        router.push({
          pathname: '/post/[pid]',
          query: { pid: post.id },
        })
      }}
    >
      Click here to read more
    </button>
  )
}

pathname을 생략하면 query는 현재 page의 route(pathname)가 아니라 브라우저에 표시되는 URL(asPath)에 적용됩니다. 이렇게 하면 rewrites가 그대로 유지됩니다. rewrite로 제공되는 page에서 query만 바꾸는 navigation은 rewrite destination을 드러내는 대신 방문자가 요청한 URL을 유지합니다.

If you omit pathname, the query is applied to the URL shown in the browser (asPath) rather than to the current page's route (pathname). This keeps rewrites intact: on a page served by a rewrite, a query-only navigation preserves the URL the visitor requested instead of revealing the rewrite destination.

as parameter로 URL을 직접 mask하는 경우에도 두 값이 달라집니다. 이 경우에는 pathname을 명시적으로 전달하세요. 그렇지 않으면 query가 mask된 URL에 적용되어 다른 page로 resolve될 수 있습니다:

The two values also differ when you mask the URL yourself with the as parameter. Pass pathname explicitly in that case, otherwise the query is applied to the masked URL and can resolve to a different page:

// On the `/` page, with the URL masked as `/p/1`
router.push({ pathname: '/', query: { photoId: 2 } }, '/p/2', { shallow: true })

router.replace

next/link의 replace prop과 비슷하게, router.replace는 history stack에 새 URL 항목이 추가되는 것을 막습니다.

Similar to the replace prop in next/link, router.replace will prevent adding a new URL entry into the history stack.

router.replace(url, as, options)
  • router.replace의 API는 router.push의 API와 완전히 동일합니다.
  • The API for router.replace is exactly the same as the API for router.push.

다음 예제를 살펴보세요:

Take a look at the following example:

import { useRouter } from 'next/router'

export default function Page() {
  const router = useRouter()

  return (
    <button type="button" onClick={() => router.replace('/home')}>
      Click me
    </button>
  )
}

router.prefetch

더 빠른 client-side transition을 위해 page를 prefetch합니다. next/link가 page prefetch를 자동으로 처리하므로, 이 method는 next/link를 사용하지 않는 navigation에서만 유용합니다.

Prefetch pages for faster client-side transitions. This method is only useful for navigations without next/link, as next/link takes care of prefetching pages automatically.

이 기능은 production 전용입니다. Next.js는 development에서 page를 prefetch하지 않습니다.

This is a production only feature. Next.js doesn't prefetch pages in development.

router.prefetch(url, as, options)
  • url - prefetch할 URL로, 명시적인 route(예: /dashboard)와 dynamic route(예: /product/[id])를 포함합니다
  • as - url을 위한 선택적 decorator입니다. Next.js 9.5.3 이전에는 dynamic route를 prefetch하는 데 사용되었습니다.
  • options - 다음 field를 허용하는 선택적 object입니다:
    • locale - 활성화된 locale과 다른 locale을 지정할 수 있습니다. false이면 활성화된 locale이 사용되지 않으므로 url에 locale이 포함되어야 합니다.
  • url - The URL to prefetch, including explicit routes (e.g. /dashboard) and dynamic routes (e.g. /product/[id])
  • as - Optional decorator for url. Before Next.js 9.5.3 this was used to prefetch dynamic routes.
  • options - Optional object with the following allowed fields:
    • locale - allows providing a different locale from the active one. If false, url has to include the locale as the active locale won't be used.

login page가 있고, login 후 사용자를 dashboard로 redirect한다고 가정해 봅시다. 이 경우 다음 예제처럼 dashboard를 prefetch해서 더 빠르게 transition할 수 있습니다:

Let's say you have a login page, and after a login, you redirect the user to the dashboard. For that case, we can prefetch the dashboard to make a faster transition, like in the following example:

import { useCallback, useEffect } from 'react'
import { useRouter } from 'next/router'

export default function Login() {
  const router = useRouter()
  const handleSubmit = useCallback((e) => {
    e.preventDefault()

    fetch('/api/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        /* Form data */
      }),
    }).then((res) => {
      // Do a fast client-side transition to the already prefetched dashboard page
      if (res.ok) router.push('/dashboard')
    })
  }, [])

  useEffect(() => {
    // Prefetch the dashboard page
    router.prefetch('/dashboard')
  }, [router])

  return (
    <form onSubmit={handleSubmit}>
      {/* Form fields */}
      <button type="submit">Login</button>
    </form>
  )
}

router.beforePopState

어떤 경우에는(예: Custom Server를 사용하는 경우) popstate를 listen해서 router가 이를 처리하기 전에 무언가를 하고 싶을 수 있습니다.

In some cases (for example, if using a Custom Server), you may wish to listen to popstate and do something before the router acts on it.

router.beforePopState(cb)
  • cb - 들어오는 popstate event에서 실행할 함수입니다. 이 함수는 event의 state를 다음 props를 가진 object로 전달받습니다:
    • url: String - 새 state의 route입니다. 보통 page의 이름입니다
    • as: String - 브라우저에 표시될 url입니다
    • options: Object - router.push가 보낸 추가 option입니다
  • cb - The function to run on incoming popstate events. The function receives the state of the event as an object with the following props:
    • url: String - the route for the new state. This is usually the name of a page
    • as: String - the url that will be shown in the browser
    • options: Object - Additional options sent by router.push

cb가 false를 반환하면 Next.js router는 popstate를 처리하지 않으며, 이 경우 직접 처리해야 합니다. Disabling file-system routing을 참고하세요.

If cb returns false, the Next.js router will not handle popstate, and you'll be responsible for handling it in that case. See Disabling file-system routing.

다음 예제처럼 beforePopState를 사용해 request를 조작하거나 SSR refresh를 강제할 수 있습니다:

You could use beforePopState to manipulate the request, or force an SSR refresh, as in the following example:

import { useEffect } from 'react'
import { useRouter } from 'next/router'

export default function Page() {
  const router = useRouter()

  useEffect(() => {
    router.beforePopState(({ url, as, options }) => {
      // I only want to allow these two routes!
      if (as !== '/' && as !== '/other') {
        // Have SSR render bad routes as a 404.
        window.location.href = as
        return false
      }

      return true
    })
  }, [router])

  return <p>Welcome to the page</p>
}

router.events

Next.js Router 안에서 일어나는 여러 event를 listen할 수 있습니다. 지원되는 event 목록은 다음과 같습니다:

You can listen to different events happening inside the Next.js Router. Here's a list of supported events:

  • routeChangeStart(url, { shallow }) - route가 바뀌기 시작할 때 발생합니다
  • routeChangeComplete(url, { shallow }) - route가 완전히 바뀌었을 때 발생합니다
  • routeChangeError(err, url, { shallow }) - route를 바꾸는 중 error가 발생하거나 route load가 취소되었을 때 발생합니다
    • err.cancelled - navigation이 취소되었는지 나타냅니다
  • beforeHistoryChange(url, { shallow }) - 브라우저의 history를 바꾸기 전에 발생합니다
  • hashChangeStart(url, { shallow }) - page는 바뀌지 않고 hash가 바뀔 때 발생합니다
  • hashChangeComplete(url, { shallow }) - page는 바뀌지 않고 hash가 바뀌었을 때 발생합니다
  • routeChangeStart(url, { shallow }) - Fires when a route starts to change
  • routeChangeComplete(url, { shallow }) - Fires when a route changed completely
  • routeChangeError(err, url, { shallow }) - Fires when there's an error when changing routes, or a route load is cancelled
    • err.cancelled - Indicates if the navigation was cancelled
  • beforeHistoryChange(url, { shallow }) - Fires before changing the browser's history
  • hashChangeStart(url, { shallow }) - Fires when the hash will change but not the page
  • hashChangeComplete(url, { shallow }) - Fires when the hash has changed but not the page
Good to know

여기서 url은 basePath를 포함해 브라우저에 표시되는 URL입니다.

Here url is the URL shown in the browser, including the basePath.

예를 들어 router event routeChangeStart를 listen하려면 pages/_app.js를 열거나 만든 다음, 다음과 같이 event를 subscribe하세요:

For example, to listen to the router event routeChangeStart, open or create pages/_app.js and subscribe to the event, like so:

import { useEffect } from 'react'
import { useRouter } from 'next/router'

export default function MyApp({ Component, pageProps }) {
  const router = useRouter()

  useEffect(() => {
    const handleRouteChange = (url, { shallow }) => {
      console.log(
        `App is changing to ${url} ${
          shallow ? 'with' : 'without'
        } shallow routing`
      )
    }

    router.events.on('routeChangeStart', handleRouteChange)

    // If the component is unmounted, unsubscribe
    // from the event with the `off` method:
    return () => {
      router.events.off('routeChangeStart', handleRouteChange)
    }
  }, [router])

  return <Component {...pageProps} />
}

이 예제에서는 page navigation 시 unmount되지 않는 Custom App(pages/_app.js)을 사용해 event를 subscribe하지만, 애플리케이션의 어떤 component에서든 router event를 subscribe할 수 있습니다.

We use a Custom App (pages/_app.js) for this example to subscribe to the event because it's not unmounted on page navigations, but you can subscribe to router events on any component in your application.

Router event는 component가 mount될 때(useEffect 또는 componentDidMount / componentWillUnmount) 등록하거나, event가 발생할 때 명령형(imperatively)으로 등록해야 합니다.

Router events should be registered when a component mounts (useEffect or componentDidMount / componentWillUnmount) or imperatively when an event happens.

route load가 취소되면(예: 두 link를 빠르게 연달아 클릭한 경우) routeChangeError가 발생합니다. 그리고 전달되는 err에는 다음 예제처럼 true로 설정된 cancelled property가 들어 있습니다:

If a route load is cancelled (for example, by clicking two links rapidly in succession), routeChangeError will fire. And the passed err will contain a cancelled property set to true, as in the following example:

import { useEffect } from 'react'
import { useRouter } from 'next/router'

export default function MyApp({ Component, pageProps }) {
  const router = useRouter()

  useEffect(() => {
    const handleRouteChangeError = (err, url) => {
      if (err.cancelled) {
        console.log(`Route to ${url} was cancelled!`)
      }
    }

    router.events.on('routeChangeError', handleRouteChangeError)

    // If the component is unmounted, unsubscribe
    // from the event with the `off` method:
    return () => {
      router.events.off('routeChangeError', handleRouteChangeError)
    }
  }, [router])

  return <Component {...pageProps} />
}

The next/compat/router exportnext/compat/router export

같은 useRouter hook이지만 app과 pages directory 모두에서 사용할 수 있습니다.

This is the same useRouter hook, but can be used in both app and pages directories.

next/router와 다른 점은 pages router가 mount되지 않았을 때 error를 throw하지 않고, 대신 return type이 NextRouter | null이라는 것입니다. 이를 통해 개발자는 app router로 전환하는 동안 component가 app과 pages 모두에서 실행될 수 있도록 바꿀 수 있습니다.

It differs from next/router in that it does not throw an error when the pages router is not mounted, and instead has a return type of NextRouter | null. This allows developers to convert components to support running in both app and pages as they transition to the app router.

이전에 다음과 같았던 component는:

A component that previously looked like this:

import { useRouter } from 'next/router'
const MyComponent = () => {
  const { isReady, query } = useRouter()
  // ...
}

null은 destructure할 수 없으므로 next/compat/router로 바꾸면 error가 발생합니다. 대신 개발자는 새로운 hook을 활용할 수 있습니다:

Will error when converted over to next/compat/router, as null cannot be destructured. Instead, developers will be able to take advantage of new hooks:

import { useEffect } from 'react'
import { useRouter } from 'next/compat/router'
import { useSearchParams } from 'next/navigation'
const MyComponent = () => {
  const router = useRouter() // may be null or a NextRouter instance
  const searchParams = useSearchParams()
  useEffect(() => {
    if (router && !router.isReady) {
      return
    }
    // In `app/`, searchParams will be ready immediately with the values, in
    // `pages/` it will be available after the router is ready.
    const search = searchParams.get('search')
    // ...
  }, [router, searchParams])
  // ...
}

이제 이 component는 pages와 app directory 모두에서 동작합니다. component가 더 이상 pages에서 사용되지 않으면 compat router에 대한 참조를 제거할 수 있습니다:

This component will now work in both pages and app directories. When the component is no longer used in pages, you can remove the references to the compat router:

import { useSearchParams } from 'next/navigation'
const MyComponent = () => {
  const searchParams = useSearchParams()
  // As this component is only used in `app/`, the compat router can be removed.
  const search = searchParams.get('search')
  // ...
}

Using useRouter outside of Next.js context in pagespages에서 Next.js context 밖에서 useRouter 사용하기

또 다른 특정 use case는 pages directory의 getServerSideProps 안처럼 Next.js 애플리케이션 context 밖에서 component를 render하는 경우입니다. 이 경우 compat router를 사용하면 error를 피할 수 있습니다:

Another specific use case is when rendering components outside of a Next.js application context, such as inside getServerSideProps on the pages directory. In this case, the compat router can be used to avoid errors:

import { renderToString } from 'react-dom/server'
import { useRouter } from 'next/compat/router'
const MyComponent = () => {
  const router = useRouter() // may be null or a NextRouter instance
  // ...
}
export async function getServerSideProps() {
  const renderedComponent = renderToString(<MyComponent />)
  return {
    props: {
      renderedComponent,
    },
  }
}

Potential ESLint errors발생할 수 있는 ESLint error

router object에서 접근할 수 있는 일부 method는 Promise를 반환합니다. ESLint rule no-floating-promises가 활성화되어 있다면, 전역으로 또는 해당 줄에 대해 비활성화하는 것을 고려하세요.

Certain methods accessible on the router object return a Promise. If you have the ESLint rule, no-floating-promises enabled, consider disabling it either globally, or for the affected line.

애플리케이션에 이 rule이 필요하다면 promise를 void 처리하거나, async 함수를 사용해 Promise를 await한 다음 그 함수 호출을 void 처리해야 합니다. method가 onClick handler 안에서 호출되는 경우에는 해당되지 않습니다.

If your application needs this rule, you should either void the promise – or use an async function, await the Promise, then void the function call. This is not applicable when the method is called from inside an onClick handler.

영향을 받는 method는 다음과 같습니다:

The affected methods are:

  • router.push
  • router.replace
  • router.prefetch
  • router.push
  • router.replace
  • router.prefetch

Potential solutions가능한 해결 방법

import { useEffect } from 'react'
import { useRouter } from 'next/router'

// Here you would fetch and return the user
const useUser = () => ({ user: null, loading: false })

export default function Page() {
  const { user, loading } = useUser()
  const router = useRouter()

  useEffect(() => {
    // disable the linting on the next line - This is the cleanest solution
    // eslint-disable-next-line no-floating-promises
    router.push('/login')

    // void the Promise returned by router.push
    if (!(user || loading)) {
      void router.push('/login')
    }
    // or use an async function, await the Promise, then void the function call
    async function handleRouteChange() {
      if (!(user || loading)) {
        await router.push('/login')
      }
    }
    void handleRouteChange()
  }, [user, loading])

  return <p>Redirecting...</p>
}

withRouter

useRouter가 가장 적합하지 않다면, withRouter로도 어떤 component에든 같은 router object를 추가할 수 있습니다.

If useRouter is not the best fit for you, withRouter can also add the same router object to any component.

Usage사용법

import { withRouter } from 'next/router'

function Page({ router }) {
  return <p>{router.pathname}</p>
}

export default withRouter(Page)

TypeScript

withRouter와 함께 class component를 사용하려면 component가 router prop을 받아야 합니다:

To use class components with withRouter, the component needs to accept a router prop:

import React from 'react'
import { withRouter, NextRouter } from 'next/router'

interface WithRouterProps {
  router: NextRouter
}

interface MyComponentProps extends WithRouterProps {}

class MyComponent extends React.Component<MyComponentProps> {
  render() {
    return <p>{this.props.router.pathname}</p>
  }
}

export default withRouter(MyComponent)
