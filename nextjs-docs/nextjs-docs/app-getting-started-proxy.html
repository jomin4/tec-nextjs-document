ProxyProxy

Proxy

Good to know

Next.js 16부터 Middleware는 그 목적을 더 잘 반영하도록 Proxy라는 이름으로 바뀌었습니다. 기능은 그대로입니다.

Starting with Next.js 16, Middleware is now called Proxy to better reflect its purpose. The functionality remains the same.

Proxy를 사용하면 request가 완료되기 전에 코드를 실행할 수 있습니다. 그런 다음 들어오는 request를 바탕으로 rewrite, redirect, request 또는 response header 수정, 직접 응답 등의 방식으로 response를 바꿀 수 있습니다.

Proxy allows you to run code before a request is completed. Then, based on the incoming request, you can modify the response by rewriting, redirecting, modifying the request or response headers, or responding directly.

Use cases사용 사례

Proxy가 효과적인 일반적인 시나리오는 다음과 같습니다:

Some common scenarios where Proxy is effective include:

  • 모든 페이지 또는 일부 페이지의 header 수정
  • A/B test나 실험에 따라 다른 페이지로 rewrite
  • 들어오는 request의 property에 따른 프로그래밍 방식의 redirect
  • Modifying headers for all pages or a subset of pages
  • Rewriting to different pages based on A/B tests or experiments
  • Programmatic redirects based on incoming request properties

단순한 redirect라면 먼저 next.config.ts의 redirects configuration 사용을 고려하세요. Proxy는 request data에 접근해야 하거나 더 복잡한 로직이 필요할 때 사용해야 합니다.

For simple redirects, consider using the redirects configuration in next.config.ts first. Proxy should be used when you need access to request data or more complex logic.

Proxy는 느린 data fetching을 위한 것이 아닙니다. Proxy는 권한 기반 redirect 같은 optimistic check에는 도움이 될 수 있지만, 완전한 session 관리나 authorization 솔루션으로 사용해서는 안 됩니다.

Proxy is not intended for slow data fetching. While Proxy can be helpful for optimistic checks such as permission-based redirects, it should not be used as a full session management or authorization solution.

Proxy 안에서 options.cache, options.next.revalidate, options.next.tags와 함께 fetch를 사용해도 아무 효과가 없습니다.

Using fetch with options.cache, options.next.revalidate, or options.next.tags, has no effect in Proxy.

Convention관례

프로젝트 root(해당되는 경우 src 안)에 proxy.ts(또는 .js) 파일을 만들어 pages나 app과 같은 수준에 위치하도록 하세요.

Create a proxy.ts (or .js) file in the project root, or inside src if applicable, so that it is located at the same level as pages or app.

Note

프로젝트당 proxy.ts 파일은 하나만 지원되지만, proxy 로직을 module로 나누어 구성할 수는 있습니다. proxy 기능을 별도의 .ts 또는 .js 파일로 분리한 뒤 main proxy.ts 파일에서 import하세요. 이렇게 하면 route별 proxy를 더 깔끔하게 관리하면서 proxy.ts에 모아 중앙에서 제어할 수 있습니다. proxy 파일을 하나로 강제하면 configuration이 단순해지고, 잠재적인 충돌을 막으며, 여러 proxy layer를 피해 성능을 최적화할 수 있습니다.

While only one proxy.ts file is supported per project, you can still organize your proxy logic into modules. Break out proxy functionalities into separate .ts or .js files and import them into your main proxy.ts file. This allows for cleaner management of route-specific proxy, aggregated in the proxy.ts for centralized control. By enforcing a single proxy file, it simplifies configuration, prevents potential conflicts, and optimizes performance by avoiding multiple proxy layers.

Example예시

proxy 함수는 default export 또는 named proxy export로 내보낼 수 있습니다:

You can export your proxy function as either a default export or a named proxy export:

TSJSproxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

// This function can be marked `async` if using `await` inside
export function proxy(request: NextRequest) {
  return NextResponse.redirect(new URL('/home', request.url))
}

// Alternatively, you can use a default export:
// export default function proxy(request: NextRequest) { ... }

export const config = {
  matcher: '/about/:path*',
}
import { NextResponse } from 'next/server'

// This function can be marked `async` if using `await` inside
export function proxy(request) {
  return NextResponse.redirect(new URL('/home', request.url))
}

// Alternatively, you can use a default export:
// export default function proxy(request) { ... }

export const config = {
  matcher: '/about/:path*',
}

matcher config를 사용하면 Proxy가 특정 path에서만 실행되도록 filter할 수 있습니다. path matching에 대한 자세한 내용은 Matcher 문서를 참고하세요.

The matcher config allows you to filter Proxy to run on specific paths. See the Matcher documentation for more details on path matching.

proxy 사용하기에 대해 더 읽어 보거나 proxy API reference를 참고하세요.

Read more about using proxy, or refer to the proxy API reference.
