Server and Client ComponentsServer Component와 Client Component

기본적으로 layout과 page는 Server Component입니다. 덕분에 server에서 데이터를 fetch하고 UI의 일부를 render한 뒤, 필요하면 결과를 cache하고 client로 stream할 수 있습니다. interactivity나 browser API가 필요할 때는 Client Component를 사용해 기능을 덧붙일 수 있습니다.

By default, layouts and pages are Server Components, which lets you fetch data and render parts of your UI on the server, optionally cache the result, and stream it to the client. When you need interactivity or browser APIs, you can use Client Components to layer in functionality.

이 페이지에서는 Next.js에서 Server Component와 Client Component가 어떻게 동작하는지, 언제 사용해야 하는지 설명하고, 애플리케이션에서 둘을 함께 조합하는 예시를 소개합니다.

This page explains how Server and Client Components work in Next.js and when to use them, with examples of how to compose them together in your application.

Good to know

각 component 유형이 어디에서 실행되는지, boundary가 어떻게 동작하는지에 대한 설명은 The Server and Client Boundary를 참고하세요.

For an explanation of where each component type runs and how the boundary works, see The Server and Client Boundary.

When to use Server and Client Components?Server Component와 Client Component는 언제 사용할까?

client와 server 환경은 할 수 있는 일이 서로 다릅니다. Server Component와 Client Component를 사용하면 use case에 따라 각 환경에서 logic을 실행할 수 있습니다.

The client and server environments have different capabilities. Server and Client Components allow you to run logic in each environment depending on your use case.

다음이 필요할 때는 Client Component를 사용하세요:

Use Client Components when you need:

  • State와 event handler. 예: onClick, onChange.
  • Lifecycle logic. 예: useEffect.
  • 브라우저 전용 API. 예: localStorage, window, navigator.geolocation 등.
  • Custom hook.
  • State and event handlers. E.g. onClick, onChange.
  • Lifecycle logic. E.g. useEffect.
  • Browser-only APIs. E.g. localStorage, window, navigator.geolocation, etc.
  • Custom hooks.

다음이 필요할 때는 Server Component를 사용하세요:

Use Server Components when you need:

  • 데이터 source 가까이에서 database나 API로부터 데이터를 fetch할 때.
  • API key, token 등 secret을 client에 노출하지 않고 사용할 때.
  • 브라우저로 전송되는 JavaScript 양을 줄일 때.
  • First Contentful Paint (FCP)를 개선하고, 콘텐츠를 client로 점진적으로 stream할 때.
  • Fetch data from databases or APIs close to the source.
  • Use API keys, tokens, and other secrets without exposing them to the client.
  • Reduce the amount of JavaScript sent to the browser.
  • Improve the First Contentful Paint (FCP), and stream content progressively to the client.

예를 들어 <Page> component는 post 데이터를 fetch하는 Server Component이며, 그 데이터를 client-side interactivity를 처리하는 <LikeButton>에 props로 전달합니다.

For example, the <Page> component is a Server Component that fetches data about a post, and passes it as props to the <LikeButton> which handles client-side interactivity.

How do Server and Client Components work in Next.js?Next.js에서 Server Component와 Client Component는 어떻게 동작할까?

On the serverServer에서

server에서 Next.js는 React의 API를 사용해 rendering을 조율합니다. rendering 작업은 개별 route segment(layout과 page) 단위의 chunk로 나뉘며, 여기에는 화면에 표시되는지와 관계없이 parallel route slot도 포함됩니다:

On the server, Next.js uses React's APIs to orchestrate rendering. The rendering work is split into chunks, by individual route segments (layouts and pages), including parallel route slots whether or not they are displayed:

  • Server Component는 React Server Component Payload(RSC Payload)라는 특별한 데이터 형식으로 render됩니다.
  • Client Component와 RSC Payload는 HTML을 prerender하는 데 사용됩니다.
  • Server Components are rendered into a special data format called the React Server Component Payload (RSC Payload).
  • Client Components and the RSC Payload are used to prerender HTML.

What is the React Server Component Payload (RSC)?

RSC Payload는 render된 React Server Component tree를 간결하게 serialize한 표현입니다. client의 React가 브라우저 DOM을 업데이트하는 데 사용합니다. RSC Payload에는 다음이 들어 있습니다:

  • Server Component의 render 결과
  • Client Component가 render되어야 할 위치를 나타내는 placeholder와 해당 JavaScript 파일에 대한 reference
  • Server Component에서 Client Component로 전달된 모든 props

What is the React Server Component Payload (RSC)?

The RSC Payload is a compact, serialized representation of the rendered React Server Components tree. It's used by React on the client to update the browser's DOM. The RSC Payload contains:

  • The rendered result of Server Components
  • Placeholders for where Client Components should be rendered and references to their JavaScript files
  • Any props passed from a Server Component to a Client Component

On the client (first load)Client에서 (최초 load)

그다음 client에서는:

Then, on the client:

  1. HTML을 사용해 route의 빠른 non-interactive preview를 사용자에게 즉시 보여 줍니다.
  2. RSC Payload를 사용해 Client Component tree와 Server Component tree를 reconcile합니다.
  3. JavaScript를 사용해 Client Component를 hydrate하고 애플리케이션을 interactive하게 만듭니다.
  1. HTML is used to immediately show a fast non-interactive preview of the route to the user.
  2. RSC Payload is used to reconcile the Client and Server Component trees.
  3. JavaScript is used to hydrate Client Components and make the application interactive.

What is hydration?

Hydration은 static HTML을 interactive하게 만들기 위해 React가 DOM에 event handler를 붙이는 과정입니다.

What is hydration?

Hydration is React's process for attaching event handlers to the DOM, to make the static HTML interactive.

Subsequent Navigations이후 navigation

이후 navigation에서는:

On subsequent navigations:

  • RSC Payload가 즉각적인 navigation을 위해 prefetch되고 cache됩니다.
  • Client Component는 server에서 render된 HTML 없이 전적으로 client에서 render됩니다.
  • The RSC Payload is prefetched and cached for instant navigation.
  • Client Components are rendered entirely on the client, without the server-rendered HTML.

Using Client ComponentsClient Component 사용하기

파일 맨 위, import 문보다 위에 "use client" directive를 추가하면 Client Component를 만들 수 있습니다.

You can create a Client Component by adding the "use client" directive at the top of the file, above your imports.

TSJSapp/ui/counter.tsx
'use client'

import { useState } from 'react'

export default function Counter() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>{count} likes</p>
      <button onClick={() => setCount(count + 1)}>Click me</button>
    </div>
  )
}
'use client'

import { useState } from 'react'

export default function Counter() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>{count} likes</p>
      <button onClick={() => setCount(count + 1)}>Click me</button>
    </div>
  )
}

"use client"는 Server module graph(tree)와 Client module graph 사이의 boundary를 선언하는 데 사용합니다.

"use client" is used to declare a boundary between the Server and Client module graphs (trees).

파일에 "use client"가 표시되면, 그 파일이 import하는 모든 것과 그 파일이 직접 render하는 component가 client bundle에 포함됩니다. 즉, client용으로 의도한 모든 component에 directive를 일일이 추가할 필요가 없습니다.

Once a file is marked with "use client", all of its imports and the components it directly renders are included in the client bundle. This means you don’t need to add the directive to every component that is intended for the client.

이 동작은 Client Component의 module graph에 속한 component, 즉 그 component가 import하는 module과 직접 render하는 component에 적용됩니다. children이나 다른 props로 전달된 Server Component에는 적용되지 않습니다. 그런 component는 Client Component의 module graph로 import되지 않습니다. server에서 render된 뒤, render된 결과물 형태로 Client Component에 전달됩니다.

This behavior applies to components that are part of the Client Component’s module graph, which includes the modules it imports and the components it renders directly. It does not apply to Server Components passed as children or other props. Those components are not imported into the Client Component’s module graph. They are rendered on the server and passed to the Client Component as rendered output.

Server Component와 Client Component를 어떻게 조합할 수 있는지는 Interleaving Server and Client Components를 참고하세요.

See Interleaving Server and Client Components for how Server and Client Components can be combined.

Reducing JS bundle sizeJS bundle 크기 줄이기

client JavaScript bundle 크기를 줄이려면 UI의 큰 부분을 Client Component로 표시하는 대신, interactive component를 정의하는 파일 맨 위에만 'use client'를 추가하세요.

To reduce the size of your client JavaScript bundles, add 'use client' at the top of the files that define your interactive components instead of marking large parts of your UI as Client Components.

예를 들어 <Layout> component는 logo나 navigation link 같은 대부분 static한 요소로 구성되어 있지만, interactive한 search bar를 포함합니다. <Search />는 Client Component여야 하지만, layout의 나머지 부분은 Server Component로 남겨 둘 수 있습니다.

For example, the <Layout> component contains mostly static elements like a logo and navigation links, but includes an interactive search bar. <Search /> needs to be a Client Component, while the rest of the layout can stay a Server Component.

TSJSapp/layout.tsx
// Client Component
import Search from './search'
// Server Component
import Logo from './logo'

// Layout is a Server Component by default
export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <nav>
        <Logo />
        <Search />
      </nav>
      <main>{children}</main>
    </>
  )
}
// Client Component
import Search from './search'
// Server Component
import Logo from './logo'

// Layout is a Server Component by default
export default function Layout({ children }) {
  return (
    <>
      <nav>
        <Logo />
        <Search />
      </nav>
      <main>{children}</main>
    </>
  )
}

Interleaving Server and Client ComponentsServer Component와 Client Component 섞어 쓰기

Server Component를 Client Component에 prop으로 전달할 수 있습니다. 이렇게 하면 server에서 render된 UI를 Client Component 안에 시각적으로 중첩할 수 있습니다.

You can pass Server Components as a prop to a Client Component. This allows you to visually nest server-rendered UI within Client components.

흔히 쓰는 패턴은 children을 사용해 <ClientComponent> 안에 *slot*을 만드는 것입니다. 예를 들어 server에서 데이터를 fetch하는 <Cart> component를, client state로 표시 여부를 전환하는 <Modal> component 안에 넣는 경우입니다.

A common pattern is to use children to create a slot in a <ClientComponent>. For example, a <Cart> component that fetches data on the server, inside a <Modal> component that uses client state to toggle visibility.

TSJSapp/ui/modal.tsx
'use client'

export default function Modal({ children }: { children: React.ReactNode }) {
  return <div>{children}</div>
}
'use client'

export default function Modal({ children }) {
  return <div>{children}</div>
}

그런 다음 parent Server Component(예: <Page>)에서 <Cart>를 <Modal>의 child로 전달할 수 있습니다:

Then, in a parent Server Component (e.g.<Page>), you can pass a <Cart> as the child of the <Modal>:

TSJSapp/page.tsx
import Modal from './ui/modal'
import Cart from './ui/cart'

export default function Page() {
  return (
    <Modal>
      <Cart />
    </Modal>
  )
}
import Modal from './ui/modal'
import Cart from './ui/cart'

export default function Page() {
  return (
    <Modal>
      <Cart />
    </Modal>
  )
}

이 패턴에서 Server Component는 Client Component에 props로 전달되더라도 server에서 미리 render됩니다. React Server Component Payload에는 그 Server Component들의 render 결과와 함께, Client Component가 render되어야 할 위치를 나타내는 placeholder 및 해당 JavaScript 파일에 대한 reference가 들어 있습니다.

In this pattern, Server Components are rendered on the server ahead of time, even when passed as props to Client Components. The React Server Component Payload contains the rendered result of those Server Components, plus placeholders for where Client Components should be rendered and references to their JavaScript files.

Context providersContext provider

React context는 현재 theme 같은 global state를 공유하는 데 흔히 사용됩니다. 하지만 Server Component에서는 React context가 지원되지 않습니다.

React context is commonly used to share global state like the current theme. However, React context is not supported in Server Components.

context를 사용하려면 children을 받는 Client Component를 만드세요:

To use context, create a Client Component that accepts children:

TSJSapp/theme-provider.tsx
'use client'

import { createContext } from 'react'

export const ThemeContext = createContext({})

export default function ThemeProvider({
  children,
}: {
  children: React.ReactNode
}) {
  return <ThemeContext.Provider value="dark">{children}</ThemeContext.Provider>
}
'use client'

import { createContext } from 'react'

export default function ThemeProvider({ children }) {
  return <ThemeContext.Provider value="dark">{children}</ThemeContext.Provider>
}

그런 다음 그것을 Server Component(예: layout)에서 import하세요:

Then, import it into a Server Component (e.g. layout):

  children,

이제 Server Component가 provider를 직접 render할 수 있고, 앱 전체의 다른 모든 Client Component가 이 context를 사용할 수 있습니다.

Your Server Component will now be able to directly render your provider, and all other Client Components throughout your app will be able to consume this context.

Good to know

provider는 tree에서 가능한 한 깊은 곳에 render해야 합니다. ThemeProvider가 <html> document 전체가 아니라 {children}만 감싸고 있다는 점에 주목하세요. 이렇게 하면 Next.js가 Server Component의 static한 부분을 더 쉽게 최적화할 수 있습니다.

You should render providers as deep as possible in the tree – notice how ThemeProvider only wraps {children} instead of the entire <html> document. This makes it easier for Next.js to optimize the static parts of your Server Components.

Third-party componentsThird-party component

client 전용 기능에 의존하는 third-party component를 사용할 때는 Client Component로 감싸서 예상대로 동작하게 할 수 있습니다.

When using a third-party component that relies on client-only features, you can wrap it in a Client Component to ensure it works as expected.

예를 들어 <Carousel />을 acme-carousel package에서 import할 수 있다고 해 봅시다. 이 component는 useState를 사용하지만, 이를 정의한 module에는 아직 "use client" directive가 없습니다.

For example, the <Carousel /> can be imported from the acme-carousel package. This component uses useState, but the module that defines it doesn't yet have the "use client" directive.

<Carousel />을 Client Component 안에서 사용하면 예상대로 동작합니다:

If you use <Carousel /> within a Client Component, it will work as expected:

TSJSapp/gallery.tsx
'use client'

import { useState } from 'react'
import { Carousel } from 'acme-carousel'

export default function Gallery() {
  const [isOpen, setIsOpen] = useState(false)

  return (
    <div>
      <button onClick={() => setIsOpen(true)}>View pictures</button>
      {/* Works, since Carousel is used within a Client Component */}
      {isOpen && <Carousel />}
    </div>
  )
}

하지만 Server Component 안에서 직접 사용하려고 하면 error가 발생합니다. Next.js는 <Carousel />이 client 전용 기능을 사용한다는 사실을 모르기 때문입니다.

Advice for Library Authors

component library를 만들고 있다면, client 전용 기능에 의존하는 entry point에 "use client" directive를 추가하세요. 그러면 사용자가 wrapper를 만들지 않고도 Server Component에서 component를 import할 수 있습니다.

일부 bundler는 "use client" directive를 제거할 수 있다는 점에 유의하세요. "use client" directive를 포함하도록 esbuild를 설정하는 예시는 React Wrap Balancer와 Vercel Analytics repository에서 찾을 수 있습니다.

Advice for Library Authors

If you’re building a component library, add the "use client" directive to entry points that rely on client-only features. This lets your users import components into Server Components without needing to create wrappers.

It's worth noting some bundlers might strip out "use client" directives. You can find an example of how to configure esbuild to include the "use client" directive in the React Wrap Balancer and Vercel Analytics repositories.

Preventing environment poisoningEnvironment poisoning 방지하기

JavaScript module은 Server Component module과 Client Component module 양쪽에서 공유될 수 있습니다. 따라서 실수로 server 전용 코드를 client에 import하는 일이 생길 수 있습니다. 예를 들어 다음 함수를 생각해 봅시다:

JavaScript modules can be shared between both Server and Client Components modules. This means it's possible to accidentally import server-only code into the client. For example, consider the following function:

TSJSlib/data.ts
export async function getData() {
  const res = await fetch('https://external-service.com/data', {
    headers: {
      authorization: process.env.API_KEY,
    },
  })

  return res.json()
}
export async function getData() {
  const res = await fetch('https://external-service.com/data', {
    headers: {
      authorization: process.env.API_KEY,
    },
  })

  return res.json()
}

이 함수에는 client에 절대 노출되어서는 안 되는 API_KEY가 들어 있습니다.

This function contains an API_KEY that should never be exposed to the client.

Next.js에서는 NEXT_PUBLIC_ prefix가 붙은 environment variable만 client bundle에 포함됩니다. prefix가 없는 variable은 Next.js가 빈 문자열로 바꿉니다.

In Next.js, only environment variables prefixed with NEXT_PUBLIC_ are included in the client bundle. If variables are not prefixed, Next.js replaces them with an empty string.

그 결과 getData()를 client에서 import하고 실행할 수는 있지만, 예상대로 동작하지 않습니다.

As a result, even though getData() can be imported and executed on the client, it won't work as expected.

Client Component에서 실수로 사용하는 것을 막으려면 server-only package를 사용할 수 있습니다.

To prevent accidental usage in Client Components, you can use the server-only package.

그런 다음 server 전용 코드가 들어 있는 파일에서 이 package를 import하세요:

Then, import the package into a file that contains server-only code:

JSlib/data.js
import 'server-only'

export async function getData() {
  const res = await fetch('https://external-service.com/data', {
    headers: {
      authorization: process.env.API_KEY,
    },
  })

  return res.json()
}

이제 이 module을 Client Component에 import하려고 하면 build 시점에 error가 발생합니다.

Now, if you try to import the module into a Client Component, there will be a build-time error.

이에 대응하는 client-only package는 window object에 접근하는 코드처럼 client 전용 logic을 담은 module을 표시하는 데 사용할 수 있습니다.

The corresponding client-only package can be used to mark modules that contain client-only logic like code that accesses the window object.

Next.js에서 server-only나 client-only 설치는 선택 사항입니다. 하지만 linting rule이 불필요한(extraneous) dependency를 지적한다면, 문제를 피하기 위해 설치해도 됩니다.

In Next.js, installing server-only or client-only is optional. However, if your linting rules flag extraneous dependencies, you may install them to avoid issues.

npm install server-only
yarn add server-only
pnpm add server-only
bun add server-only

Next.js는 module이 잘못된 환경에서 사용될 때 더 명확한 error message를 제공하기 위해 server-only와 client-only import를 내부적으로 처리합니다. NPM에 있는 이 package들의 실제 내용은 Next.js가 사용하지 않습니다.

Next.js handles server-only and client-only imports internally to provide clearer error messages when a module is used in the wrong environment. The contents of these packages from NPM are not used by Next.js.

Next.js는 noUncheckedSideEffectImports가 활성화된 TypeScript 설정을 위해 server-only와 client-only에 대한 자체 type 선언도 제공합니다.

Next.js also provides its own type declarations for server-only and client-only, for TypeScript configurations where noUncheckedSideEffectImports is active.
