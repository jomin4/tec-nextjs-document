getStaticPathsgetStaticPaths

Dynamic Routes를 사용하는 page에서 getStaticPaths라는 함수를 export하면, Next.js는 getStaticPaths에 지정된 모든 path를 static하게 prerender합니다.

When exporting a function called getStaticPaths from a page that uses Dynamic Routes, Next.js will statically prerender all the paths specified by getStaticPaths.

TSJSpages/repo/[name].tsx
import type {
  InferGetStaticPropsType,
  GetStaticProps,
  GetStaticPaths,
} from 'next'

type Repo = {
  name: string
  stargazers_count: number
}

export const getStaticPaths = (async () => {
  return {
    paths: [
      {
        params: {
          name: 'next.js',
        },
      }, // See the "paths" section below
    ],
    fallback: true, // false or "blocking"
  }
}) satisfies GetStaticPaths

export const getStaticProps = (async (context) => {
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo = await res.json()
  return { props: { repo } }
}) satisfies GetStaticProps<{
  repo: Repo
}>

export default function Page({
  repo,
}: InferGetStaticPropsType<typeof getStaticProps>) {
  return repo.stargazers_count
}
export async function getStaticPaths() {
  return {
    paths: [
      {
        params: {
          name: 'next.js',
        },
      }, // See the "paths" section below
    ],
    fallback: true, // false or "blocking"
  }
}

export async function getStaticProps() {
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo = await res.json()
  return { props: { repo } }
}

export default function Page({ repo }) {
  return repo.stargazers_count
}

getStaticPaths return valuesgetStaticPaths 반환 값

getStaticPaths 함수는 다음 필수 property를 가진 object를 반환해야 합니다:

The getStaticPaths function should return an object with the following required properties:

paths

paths key는 어떤 path를 prerender할지 결정합니다. 예를 들어 pages/posts/[id].js라는 Dynamic Routes를 사용하는 page가 있다고 가정해 봅시다. 이 page에서 getStaticPaths를 export하고 paths로 다음을 반환하면:

The paths key determines which paths will be prerendered. For example, suppose that you have a page that uses Dynamic Routes named pages/posts/[id].js. If you export getStaticPaths from this page and return the following for paths:

return {
  paths: [
    { params: { id: '1' }},
    {
      params: { id: '2' },
      // with i18n configured the locale for the path can be returned as well
      locale: "en",
    },
  ],
  fallback: ...
}

Next.js는 pages/posts/[id].js의 page component를 사용해 next build 중에 /posts/1과 /posts/2를 static하게 생성합니다.

Then, Next.js will statically generate /posts/1 and /posts/2 during next build using the page component in pages/posts/[id].js.

각 params object의 값은 page 이름에 사용된 parameter와 일치해야 합니다:

The value for each params object must match the parameters used in the page name:

  • page 이름이 pages/posts/[postId]/[commentId]라면 params에는 postId와 commentId가 있어야 합니다.
  • page 이름이 pages/[...slug]처럼 catch-all route를 사용한다면 params에는 (배열인) slug가 있어야 합니다. 이 배열이 ['hello', 'world']라면 Next.js는 /hello/world에 page를 static하게 생성합니다.
  • page가 optional catch-all route를 사용한다면 null, [], undefined, false를 사용해 가장 root의 route를 render합니다. 예를 들어 pages/[[...slug]]에 slug: false를 지정하면 Next.js는 / page를 static하게 생성합니다.
  • If the page name is pages/posts/[postId]/[commentId], then params should contain postId and commentId.
  • If the page name uses catch-all routes like pages/[...slug], then params should contain slug (which is an array). If this array is ['hello', 'world'], then Next.js will statically generate the page at /hello/world.
  • If the page uses an optional catch-all route, use null, [], undefined or false to render the root-most route. For example, if you supply slug: false for pages/[[...slug]], Next.js will statically generate the page /.

params 문자열은 대소문자를 구분하는 case-sensitive 값이므로, path가 올바르게 생성되도록 정규화하는 것이 좋습니다. 예를 들어 param으로 WoRLD가 반환되면, 실제로 방문한 path가 WoRLD일 때만 일치하고 world나 World와는 일치하지 않습니다.

The params strings are case-sensitive and ideally should be normalized to ensure the paths are generated correctly. For example, if WoRLD is returned for a param it will only match if WoRLD is the actual path visited, not world or World.

params object와 별도로, i18n이 설정된 경우 locale field를 반환할 수 있으며, 이 field는 생성되는 path의 locale을 설정합니다.

Separate of the params object a locale field can be returned when i18n is configured, which configures the locale for the path being generated.

fallback: false

fallback이 false이면, getStaticPaths가 반환하지 않은 모든 path는 404 page가 됩니다.

If fallback is false, then any paths not returned by getStaticPaths will result in a 404 page.

next build가 실행되면 Next.js는 getStaticPaths가 fallback: false를 반환했는지 확인하고, getStaticPaths가 반환한 path만 build합니다. 이 option은 생성할 path 수가 적거나 새 page data가 자주 추가되지 않을 때 유용합니다. path를 더 추가해야 하는데 fallback: false를 사용하고 있다면, 새 path가 생성되도록 next build를 다시 실행해야 합니다.

When next build is run, Next.js will check if getStaticPaths returned fallback: false, it will then build only the paths returned by getStaticPaths. This option is useful if you have a small number of paths to create, or new page data is not added often. If you find that you need to add more paths, and you have fallback: false, you will need to run next build again so that the new paths can be generated.

다음 예제는 pages/posts/[id].js라는 page에서 page당 하나의 blog post를 prerender합니다. blog post 목록은 CMS에서 fetch되어 getStaticPaths가 반환합니다. 그다음 각 page에서 getStaticProps를 사용해 CMS에서 post data를 fetch합니다.

The following example prerenders one blog post per page called pages/posts/[id].js. The list of blog posts will be fetched from a CMS and returned by getStaticPaths. Then, for each page, it fetches the post data from a CMS using getStaticProps.

JSpages/posts/[id].js
function Post({ post }) {
  // Render post...
}

// This function gets called at build time
export async function getStaticPaths() {
  // Call an external API endpoint to get posts
  const res = await fetch('https://.../posts')
  const posts = await res.json()

  // Get the paths we want to prerender based on posts
  const paths = posts.map((post) => ({
    params: { id: post.id },
  }))

  // We'll prerender only these paths at build time.
  // { fallback: false } means other routes should 404.
  return { paths, fallback: false }
}

// This also gets called at build time
export async function getStaticProps({ params }) {
  // params contains the post `id`.
  // If the route is like /posts/1, then params.id is 1
  const res = await fetch(`https://.../posts/${params.id}`)
  const post = await res.json()

  // Pass post data to the page via props
  return { props: { post } }
}

export default Post

fallback: true

예제
  • 많은 수의 page를 static하게 생성하기

fallback이 true이면 getStaticProps의 동작이 다음과 같이 바뀝니다:

If fallback is true, then the behavior of getStaticProps changes in the following ways:

  • getStaticPaths가 반환한 path는 build time에 getStaticProps에 의해 HTML로 render됩니다.
  • build time에 생성되지 않은 path는 404 page가 되지 않습니다. 대신 Next.js는 그런 path에 대한 첫 request에 page의 "fallback" 버전을 제공합니다. Google 같은 web crawler에는 fallback이 제공되지 않고, 대신 해당 path가 fallback: 'blocking'처럼 동작합니다.
  • fallback: true인 page로 next/link나 next/router를 통해 (client-side에서) 이동하면 Next.js는 fallback을 제공하지 않고, 대신 page가 fallback: 'blocking'처럼 동작합니다.
  • background에서 Next.js는 요청된 path의 HTML과 JSON을 static하게 생성합니다. 여기에는 getStaticProps 실행이 포함됩니다.
  • 완료되면 브라우저는 생성된 path의 JSON을 받습니다. 이 JSON은 필요한 props로 page를 자동으로 render하는 데 사용됩니다. 사용자 입장에서는 page가 fallback page에서 전체 page로 바뀌게 됩니다.
  • 동시에 Next.js는 이 path를 prerender된 page 목록에 추가합니다. 같은 path에 대한 이후 request에는 build time에 prerender된 다른 page처럼 생성된 page가 제공됩니다.
  • The paths returned from getStaticPaths will be rendered to HTML at build time by getStaticProps.
  • The paths that have not been generated at build time will not result in a 404 page. Instead, Next.js will serve a “fallback” version of the page on the first request to such a path. Web crawlers, such as Google, won't be served a fallback and instead the path will behave as in fallback: 'blocking'.
  • When a page with fallback: true is navigated to through next/link or next/router (client-side) Next.js will not serve a fallback and instead the page will behave as fallback: 'blocking'.
  • In the background, Next.js will statically generate the requested path HTML and JSON. This includes running getStaticProps.
  • When complete, the browser receives the JSON for the generated path. This will be used to automatically render the page with the required props. From the user’s perspective, the page will be swapped from the fallback page to the full page.
  • At the same time, Next.js adds this path to the list of prerendered pages. Subsequent requests to the same path will serve the generated page, like other pages prerendered at build time.
Good to know

fallback: true는 output: 'export'를 사용할 때는 지원되지 않습니다.

fallback: true is not supported when using output: 'export'.

When is fallback: true useful?fallback: true는 언제 유용한가요?

fallback: true는 앱에 data에 의존하는 static page가 매우 많을 때(예: 아주 큰 e-commerce 사이트) 유용합니다. 모든 상품 page를 prerender하려고 하면 build에 매우 오랜 시간이 걸립니다.

fallback: true is useful if your app has a very large number of static pages that depend on data (such as a very large e-commerce site). If you want to prerender all product pages, the builds would take a very long time.

대신 일부 page만 static하게 생성하고 나머지에는 fallback: true를 사용할 수 있습니다. 누군가 아직 생성되지 않은 page를 요청하면, 사용자는 loading indicator나 skeleton component가 있는 page를 보게 됩니다.

Instead, you may statically generate a small subset of pages and use fallback: true for the rest. When someone requests a page that is not generated yet, the user will see the page with a loading indicator or skeleton component.

잠시 후 getStaticProps가 끝나면 page가 요청된 data로 render됩니다. 이제부터 같은 page를 요청하는 모든 사람은 static하게 prerender된 page를 받게 됩니다.

Shortly after, getStaticProps finishes and the page will be rendered with the requested data. From now on, everyone who requests the same page will get the statically prerendered page.

이렇게 하면 빠른 build와 Static Generation의 이점을 유지하면서도 사용자가 항상 빠른 경험을 할 수 있습니다.

This ensures that users always have a fast experience while preserving fast builds and the benefits of Static Generation.

fallback: true는 생성된 page를 _업데이트_하지 않습니다. 업데이트가 필요하다면 Incremental Static Regeneration을 살펴보세요.

fallback: true will not update generated pages, for that take a look at Incremental Static Regeneration.

fallback: 'blocking'

fallback이 'blocking'이면, getStaticPaths가 반환하지 않은 새 path는 SSR과 동일하게 HTML이 생성될 때까지 기다리고(그래서 _blocking_입니다), 이후 request를 위해 cache되어 path당 한 번만 생성됩니다.

If fallback is 'blocking', new paths not returned by getStaticPaths will wait for the HTML to be generated, identical to SSR (hence why blocking), and then be cached for future requests so it only happens once per path.

getStaticProps는 다음과 같이 동작합니다:

getStaticProps will behave as follows:

  • getStaticPaths가 반환한 path는 build time에 getStaticProps에 의해 HTML로 render됩니다.
  • build time에 생성되지 않은 path는 404 page가 되지 않습니다. 대신 Next.js는 첫 request에서 SSR을 수행하고 생성된 HTML을 반환합니다.
  • 완료되면 브라우저는 생성된 path의 HTML을 받습니다. 사용자 입장에서는 "브라우저가 page를 요청하는 중" 상태에서 "전체 page가 로드됨" 상태로 넘어갑니다. loading/fallback state가 깜빡이는 일은 없습니다.
  • 동시에 Next.js는 이 path를 prerender된 page 목록에 추가합니다. 같은 path에 대한 이후 request에는 build time에 prerender된 다른 page처럼 생성된 page가 제공됩니다.
  • The paths returned from getStaticPaths will be rendered to HTML at build time by getStaticProps.
  • The paths that have not been generated at build time will not result in a 404 page. Instead, Next.js will SSR on the first request and return the generated HTML.
  • When complete, the browser receives the HTML for the generated path. From the user’s perspective, it will transition from "the browser is requesting the page" to "the full page is loaded". There is no flash of loading/fallback state.
  • At the same time, Next.js adds this path to the list of prerendered pages. Subsequent requests to the same path will serve the generated page, like other pages prerendered at build time.

fallback: 'blocking'은 기본적으로 생성된 page를 _업데이트_하지 않습니다. 생성된 page를 업데이트하려면 fallback: 'blocking'과 함께 Incremental Static Regeneration을 사용하세요.

fallback: 'blocking' will not update generated pages by default. To update generated pages, use Incremental Static Regeneration in conjunction with fallback: 'blocking'.

Good to know

fallback: 'blocking'은 output: 'export'를 사용할 때는 지원되지 않습니다.

fallback: 'blocking' is not supported when using output: 'export'.

Fallback pagesFallback page

page의 "fallback" 버전에서는:

In the “fallback” version of a page:

  • page의 props가 비어 있습니다.
  • router를 사용해 fallback이 render되고 있는지 감지할 수 있으며, 이때 router.isFallback은 true가 됩니다.
  • The page’s props will be empty.
  • Using the router, you can detect if the fallback is being rendered, router.isFallback will be true.

다음 예제는 isFallback 사용법을 보여 줍니다:

The following example showcases using isFallback:

JSpages/posts/[id].js
import { useRouter } from 'next/router'

function Post({ post }) {
  const router = useRouter()

  // If the page is not yet generated, this will be displayed
  // initially until getStaticProps() finishes running
  if (router.isFallback) {
    return <div>Loading...</div>
  }

  // Render post...
}

// This function gets called at build time
export async function getStaticPaths() {
  return {
    // Only `/posts/1` and `/posts/2` are generated at build time
    paths: [{ params: { id: '1' } }, { params: { id: '2' } }],
    // Enable statically generating additional pages
    // For example: `/posts/3`
    fallback: true,
  }
}

// This also gets called at build time
export async function getStaticProps({ params }) {
  // params contains the post `id`.
  // If the route is like /posts/1, then params.id is 1
  const res = await fetch(`https://.../posts/${params.id}`)
  const post = await res.json()

  // Pass post data to the page via props
  return {
    props: { post },
    // Re-generate the post at most once per second
    // if a request comes in
    revalidate: 1,
  }
}

export default Post
