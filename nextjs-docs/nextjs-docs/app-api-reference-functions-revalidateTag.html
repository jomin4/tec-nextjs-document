revalidateTagrevalidateTag

revalidateTag를 사용하면 특정 cache tag에 해당하는 cached data를 on-demand로 무효화할 수 있습니다.

revalidateTag allows you to invalidate cached data on-demand for a specific cache tag.

이 함수는 블로그 글, 상품 카탈로그, 문서처럼 업데이트가 약간 늦게 반영되어도 괜찮은 콘텐츠에 적합합니다. 권장되는 max profile을 사용하면, 사용자는 새 data가 background에서 로드되는 동안 stale content를 받습니다.

This function is ideal for content where a slight delay in updates is acceptable, such as blog posts, product catalogs, or documentation. With the recommended max profile, users receive stale content while fresh data loads in the background.

Usage사용법

revalidateTag는 Server Function과 Route Handler에서 호출할 수 있습니다.

revalidateTag can be called in Server Functions and Route Handlers.

revalidateTag는 server 환경에서만 동작하므로 Client Component나 Proxy에서는 호출할 수 없습니다.

revalidateTag cannot be called in Client Components or Proxy, as it only works in server environments.

Revalidation BehaviorRevalidation 동작

revalidateTag를 호출하면 해당 tag가 붙은 data가 stale로 표시됩니다. 그 data에 대한 다음 request가 revalidation을 시작하며, revalidation이 진행되는 동안에는 stale-while-revalidate semantics에 따라 stale content가 제공됩니다. 두 번째 argument는 stale content를 얼마나 오래 제공할 수 있는지를 설정합니다. 그 시간이 지나면 request는 revalidation이 끝날 때까지 block됩니다.

Calling revalidateTag marks the tagged data as stale. The next request for that data kicks off a revalidation and is served stale content while it runs, using stale-while-revalidate semantics. The second argument sets how long stale content may be served. Past that, a request blocks until the revalidation completes.

  • profile="max" (권장): 1년의 기간으로, revalidation이 진행되는 동안 request가 항상 stale content를 제공받을 만큼 충분히 깁니다.
  • 다른 profile 또는 object: 다른 기간을 원할 때는 cacheLife에 정의된 다른 기본 또는 custom profile, 혹은 expire property를 가진 object를 사용합니다.
  • { expire: 0 }: stale content가 절대 제공되지 않으므로, 다음 request는 blocking revalidate/cache miss가 됩니다. 호출하는 쪽에서 data를 즉시 없애야 하는데 updateTag를 사용할 수 없을 때 사용하세요.
  • 두 번째 argument 없음 (deprecated): { expire: 0 }처럼 동작합니다. Server Action에서는 updateTag로, 그 외에는 profile="max"로 migrate하세요.
  • profile="max" (recommended): A one year window, long enough that requests are always served stale content while the revalidation runs.
  • Another profile, or an object: Any other default or custom profile defined in cacheLife, or an object with an expire property, when you want a different window.
  • { expire: 0 }: Stale content is never served, so the next request is a blocking revalidate/cache miss. Use it when the caller needs the data gone immediately and you cannot use updateTag.
  • No second argument (deprecated): Behaves like { expire: 0 }. Migrate to updateTag in Server Actions, or profile="max".

profile은 빠른 응답보다 data의 정확성이 더 중요해지는 시점을 설정합니다.

The profile sets the point past which data correctness is more important than being fast.

Good to know

revalidation은 revalidateTag 호출이 아니라 request에 의해 trigger되므로, 해당 tag를 사용하는 page들은 한꺼번에 revalidate되는 것이 아니라 방문될 때마다 revalidate됩니다.

A revalidation is triggered by a request, not by the revalidateTag call, so pages using the tag revalidate as they are visited rather than all at once.

Parameters

revalidateTag(tag: string, profile: string | { expire?: number }): void;
  • tag: revalidate하려는 data에 연결된 cache tag를 나타내는 string입니다. tag는 대소문자를 구분하며 256자를 넘으면 안 됩니다. 제한을 넘는 tag는 cached data에 절대 할당되지 않으므로, 그런 tag를 revalidate해도 아무 일도 일어나지 않습니다.
  • profile: stale content를 얼마나 오래 제공할 수 있는지를 나타냅니다. Revalidation Behavior를 참고하세요. 권장 값은 "max"입니다. cacheLife에 정의된 다른 기본 또는 custom profile도 받을 수 있으며, 이 경우 해당 profile의 expire만 읽습니다. 초 단위의 expire property를 가진 object를 전달할 수도 있습니다.
  • tag: A string representing the cache tag associated with the data you want to revalidate. Tags are case-sensitive and must not exceed 256 characters. A tag that exceeds the limit is never assigned to cached data, so revalidating it does nothing.
  • profile: How long stale content may be served, see Revalidation Behavior. The recommended value is "max". Any other default or custom profile defined in cacheLife is also accepted, and only its expire is read. You can also pass an object with an expire property, in seconds.

tag는 먼저 cached data에 할당되어 있어야 합니다. 두 가지 방법이 있습니다:

Tags must first be assigned to cached data. You can do this in two ways:

  • 외부 API request를 caching할 때 fetch의 next.tags option 사용:
  • Using the next.tags option with fetch for caching external API requests:
fetch(url, { next: { tags: ['posts'] } })
  • 'use cache' directive가 있는 cached function이나 component 안에서 cacheTag 사용:
  • Using cacheTag inside cached functions or components with the 'use cache' directive:
import { cacheTag } from 'next/cache'

async function getData() {
  'use cache'
  cacheTag('posts')
  // ...
}
Good to know

argument가 하나인 revalidateTag(tag) 형태는 deprecated되었습니다. 현재는 TypeScript error를 무시하면 동작하지만, 이 동작은 향후 버전에서 제거될 수 있습니다. argument 두 개를 받는 signature로 업데이트하세요.

The single-argument form revalidateTag(tag) is deprecated. It currently works if TypeScript errors are suppressed, but this behavior may be removed in a future version. Update to the two-argument signature.

Returns

revalidateTag는 값을 반환하지 않습니다.

revalidateTag does not return a value.

Relationship with revalidatePathrevalidatePath와의 관계

revalidateTag는 특정 tag가 붙은 data를 그 tag를 사용하는 모든 page에 걸쳐 무효화하고, revalidatePath는 특정 page 또는 layout 경로를 무효화합니다.

revalidateTag invalidates data with specific tags across all pages that use those tags, while revalidatePath invalidates specific page or layout paths.

Good to know

이 함수들은 서로 다른 목적을 가지며, 포괄적인 data 일관성을 위해 함께 사용해야 할 수도 있습니다. 자세한 예시와 고려 사항은 relationship with revalidateTag and updateTag를 참고하세요.

These functions serve different purposes and may need to be used together for comprehensive data consistency. For detailed examples and considerations, see relationship with revalidateTag and updateTag for more information.

Examples예시

다음 예시들은 다양한 context에서 revalidateTag를 사용하는 방법을 보여 줍니다. 두 경우 모두 profile="max"를 사용해 data를 stale로 표시하고 stale-while-revalidate semantics를 사용하며, 이는 대부분의 use case에 권장되는 방식입니다.

The following examples demonstrate how to use revalidateTag in different contexts. In both cases, we're using profile="max" to mark data as stale and use stale-while-revalidate semantics, which is the recommended approach for most use cases.

Server Action

TSJSapp/actions.ts
'use server'

import { revalidateTag } from 'next/cache'

export default async function submit() {
  await addPost()
  revalidateTag('posts', 'max')
}

import { revalidateTag } from 'next/cache'

export default async function submit() {
  await addPost()

Route Handler

TSJSapp/api/revalidate/route.ts
import type { NextRequest } from 'next/server'
import { revalidateTag } from 'next/cache'

export async function GET(request: NextRequest) {
  const tag = request.nextUrl.searchParams.get('tag')

  if (tag) {
    revalidateTag(tag, 'max')
    return Response.json({ revalidated: true, now: Date.now() })
  }

  return Response.json({
    revalidated: false,
    now: Date.now(),
    message: 'Missing tag to revalidate',
  })
}

invalidation이 Server Action 밖에서 발생하는 경우, 예를 들어 webhook이나 다른 service가 Route Handler를 호출하는 경우에는 updateTag를 사용할 수 없습니다. data를 즉시 만료시키려면 { expire: 0 }을 전달하세요:

When the invalidation comes from outside a Server Action, for example a webhook or another service calling a Route Handler, updateTag is not available. Pass { expire: 0 } to expire the data immediately:

revalidateTag(tag, { expire: 0 })
