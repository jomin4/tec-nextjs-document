Next.js GlossaryNext.js 용어 사전

이 용어 사전은 routing, rendering, caching 관련 용어를 포함해 Next.js 문서 전반에서 쓰이는 일반적인 용어를 정의합니다.

This glossary defines common terms used throughout the Next.js documentation, including terms related to routing, rendering, and caching.

A

App Router

version 13에서 도입된 Next.js router로, React Server Components 위에 만들어졌습니다. file-system 기반 routing을 사용하며 layout, nested routing, loading state, error handling 등을 지원합니다. 자세한 내용은 App Router 문서를 참고하세요.

The Next.js router introduced in version 13, built on top of React Server Components. It uses file-system based routing and supports layouts, nested routing, loading states, error handling, and more. Learn more in the App Router documentation.

App Shell

page에서 URL data에 의존하지 않는 부분을 담은 route별 prerender입니다. cache된 콘텐츠는 stale 시간이 5분 이상일 때 포함됩니다. shell은 수명이 짧은 콘텐츠가 fresh 상태로 유지되는 시간보다 더 오래 재사용되기 때문입니다. cookies()나 headers()를 읽는 route는 session data까지 포함한 shell을 만들며, 이는 client에서 session별로 cache됩니다. client navigation 중 기본 prefetch payload로, per-link prefetch가 준비되지 않았을 때의 loading state로, 그리고 ISR with Cache Components의 fallback으로 사용됩니다.

A per-route prerender containing the parts of a page that don't depend on URL data. Cached content is included when its stale time is at least 5 minutes, since the shell is reused for longer than shorter-lived content stays fresh. Routes that read cookies() or headers() produce one that also includes session data, cached per session on the client. Used as the default prefetch payload during client navigations, the loading state when a per-link prefetch is not ready, and the fallback for ISR with Cache Components.

B

Build time빌드 타임

애플리케이션이 compile되는 단계입니다. build time 동안 Next.js는 코드를 production용 최적화 파일로 변환하고, static page를 생성하며, deploy를 위한 asset을 준비합니다. next build CLI reference를 참고하세요.

The stage when your application is being compiled. During build time, Next.js transforms your code into optimized files for production, generates static pages, and prepares assets for deployment. See the next build CLI reference.

C

Cache Components

"use cache" directive를 사용해 component 단위와 function 단위의 caching을 가능하게 하는 기능입니다. Cache Components를 사용하면 즉시 제공되는 static HTML shell을 prerender하고, dynamic 콘텐츠는 준비되는 대로 stream되게 하여 하나의 route 안에서 static, cached, dynamic 콘텐츠를 섞어 쓸 수 있습니다. cacheLife()로 cache 기간을 설정하고, cacheTag()로 cache된 data에 tag를 붙이며, updateTag()로 on-demand invalidate를 할 수 있습니다. 자세한 내용은 Cache Components 가이드를 참고하세요.

A feature that enables component and function-level caching using the "use cache" directive. Cache Components allows you to mix static, cached, and dynamic content within a single route by prerendering a static HTML shell that's served immediately, while dynamic content streams in when ready. Configure cache duration with cacheLife(), tag cached data with cacheTag(), and invalidate on-demand with updateTag(). Learn more in the Cache Components guide.

Catch-all Segments

[...folder]/page.js 문법을 사용해 여러 URL 부분과 match될 수 있는 dynamic route segment입니다. 이 segment는 남은 모든 URL segment를 capture하며, 문서 사이트나 file browser 같은 기능을 구현할 때 유용합니다. 자세한 내용은 Dynamic Route Segments를 참고하세요.

Dynamic route segments that can match multiple URL parts using the [...folder]/page.js syntax. These segments capture all remaining URL segments and are useful for implementing features like documentation sites or file browsers. Learn more in Dynamic Route Segments.

Client Bundles

브라우저로 전송되는 JavaScript bundle입니다. Next.js는 초기 payload 크기를 줄이고 각 page에 필요한 코드만 load하기 위해 module graph를 기반으로 bundle을 자동으로 분할합니다.

JavaScript bundles sent to the browser. Next.js splits these automatically based on the module graph to reduce initial payload size and load only the necessary code for each page.

Client Component

브라우저에서 실행되는 React component입니다. Next.js에서 Client Component는 초기 page 생성 중에 server에서도 render될 수 있습니다. state, effect, event handler, browser API를 사용할 수 있으며, 파일 맨 위의 "use client" directive로 표시합니다. 자세한 내용은 Server and Client Components를 참고하세요.

A React component that runs in the browser. In Next.js, Client Components can also be rendered on the server during initial page generation. They can use state, effects, event handlers, and browser APIs, and are marked with the "use client" directive at the top of a file. Learn more in Server and Client Components.

Client-side navigation

전체 page를 다시 load하지 않고 page 콘텐츠를 동적으로 업데이트하는 navigation 기법입니다. Next.js는 <Link> component로 client-side navigation을 수행하며, 공유 layout을 interactive 상태로 유지하고 browser state를 보존합니다. 자세한 내용은 Linking and Navigating을 참고하세요.

A navigation technique where the page content updates dynamically without a full page reload. Next.js uses client-side navigation with the <Link> component, keeping shared layouts interactive and preserving browser state. Learn more in Linking and Navigating.

Client Cache

방문했거나 prefetch된 route의 RSC Payload를 저장하는 브라우저의 in-memory cache입니다. client-side navigation 중에 Next.js는 cache된 layout과 loading state를 server request 없이 즉시 제공합니다. page는 기본적으로 cache되지 않지만, 브라우저의 뒤로/앞으로 가기 navigation 중에는 재사용됩니다.

An in-memory cache in the browser that stores RSC Payload for visited and prefetched routes. During client-side navigation, Next.js serves cached layouts and loading states instantly without a server request. Pages are not cached by default but are reused during browser back/forward navigation.

client cache는 page를 새로고침하면 지워집니다. revalidateTag, revalidatePath, updateTag, router.refresh, cookies.set, cookies.delete로 프로그래밍 방식으로 invalidate할 수도 있습니다.

The client cache is cleared on page refresh. It can be invalidated programmatically with revalidateTag, revalidatePath, updateTag, router.refresh, cookies.set, or cookies.delete.

client cache 기간은 staleTimes로 전역 설정하거나, cacheLife의 stale property로 route별로 설정할 수 있습니다(권장).

You can configure the client cache duration with staleTimes globally, or per-route via the stale property in cacheLife (recommended).

Code Splitting

애플리케이션을 route 기준으로 더 작은 JavaScript chunk로 나누는 과정입니다. 모든 코드를 미리 load하는 대신 현재 route에 필요한 코드만 load하므로 초기 load 시간이 줄어듭니다. Next.js는 route를 기준으로 code splitting을 자동으로 수행합니다. 자세한 내용은 Package Bundling 가이드를 참고하세요.

The process of dividing your application into smaller JavaScript chunks based on routes. Instead of loading all code upfront, only the code needed for the current route is loaded, reducing initial load time. Next.js automatically performs code splitting based on routes. Learn more in the Package Bundling guide.

D

Dynamic rendering

component가 build time이 아니라 request time에 render되는 것을 말합니다. component는 Request-time APIs를 사용하면 dynamic이 됩니다.

When a component is rendered at request time rather than build time. A component becomes dynamic when it uses Request-time APIs.

Dynamic route segments

request time에 data로부터 생성되는 route segment입니다. 폴더 이름을 대괄호로 감싸서(예: [slug]) 만들며, blog post나 product page 같은 dynamic data로 route를 만들 수 있게 해 줍니다. 자세한 내용은 Dynamic Route Segments를 참고하세요.

Route segments that are generated from data at request time. Created by wrapping a folder name in square brackets (e.g., [slug]), they allow you to create routes from dynamic data like blog posts or product pages. Learn more in Dynamic Route Segments.

E

Environment Variables

build time 또는 request time에 접근할 수 있는 configuration 값입니다. Next.js에서 NEXT_PUBLIC_ prefix가 붙은 변수는 브라우저에 노출되고, 나머지는 server-side에서만 사용할 수 있습니다. 자세한 내용은 Environment Variables를 참고하세요.

Configuration values accessible at build time or request time. In Next.js, variables prefixed with NEXT_PUBLIC_ are exposed to the browser, while others are only available server-side. Learn more in Environment Variables.

Error Boundary

자식 component tree에서 발생한 JavaScript error를 잡아 fallback UI를 보여 주는 React component입니다. Next.js에서는 error.js 파일을 만들면 route segment를 error boundary로 자동으로 감쌉니다. 자세한 내용은 Error Handling을 참고하세요.

A React component that catches JavaScript errors in its child component tree and displays a fallback UI. In Next.js, create an error.js file to automatically wrap a route segment in an error boundary. Learn more in Error Handling.

F

Font Optimization

next/font를 사용한 자동 font 최적화입니다. Next.js는 font를 self-host하고, layout shift를 없애며, performance를 위한 best practice를 적용합니다. Google Fonts와 local font 파일 모두에서 동작합니다. 자세한 내용은 Fonts를 참고하세요.

Automatic font optimization using next/font. Next.js self-hosts fonts, eliminates layout shift, and applies best practices for performance. Works with Google Fonts and local font files. Learn more in Fonts.

File-system caching

실행 사이에 compiler artifact를 disk에 저장하는 Turbopack 기능으로, next dev나 next build command 간의 작업을 줄여 compile 시간을 크게 단축합니다. 자세한 내용은 Turbopack FileSystem Caching을 참고하세요.

A Turbopack feature that stores compiler artifacts on disk between runs, reducing work across next dev or next build commands for significantly faster compile times. Learn more in Turbopack FileSystem Caching.

H

Hydration

server에서 render된 static HTML을 interactive하게 만들기 위해 React가 DOM에 event handler를 연결하는 과정입니다. hydration 중에 React는 server에서 render된 markup과 client-side JavaScript를 reconcile합니다. 자세한 내용은 Server and Client Components를 참고하세요.

React's process of attaching event handlers to the DOM to make server-rendered static HTML interactive. During hydration, React reconciles the server-rendered markup with the client-side JavaScript. Learn more in Server and Client Components.

I

Import Aliases

자주 쓰는 directory를 짧게 참조할 수 있게 해 주는 custom path mapping입니다. import alias는 relative import의 복잡함을 줄이고 코드를 더 읽기 쉽고 유지보수하기 좋게 만듭니다. 자세한 내용은 Absolute Imports and Module Path Aliases를 참고하세요.

Custom path mappings that provide shorthand references for frequently used directories. Import aliases reduce the complexity of relative imports and make code more readable and maintainable. Learn more in Absolute Imports and Module Path Aliases.

Incremental Static Regeneration (ISR)

전체 사이트를 다시 build하지 않고 static 콘텐츠를 업데이트할 수 있게 해 주는 기법입니다. ISR을 사용하면 page 단위로 static generation을 사용하면서, traffic이 들어올 때 background에서 page를 revalidate할 수 있습니다. 자세한 내용은 ISR 가이드를, Cache Components를 사용한다면 ISR with Cache Components를 참고하세요.

A technique that allows you to update static content without rebuilding the entire site. ISR enables you to use static generation on a per-page basis while revalidating pages in the background as traffic comes in. Learn more in the ISR guide or, when using Cache Components, ISR with Cache Components.

Good to know

Next.js에서 ISR은 Revalidation이라고도 불립니다.

In Next.js, ISR is also known as Revalidation.

Intercepting Routes

애플리케이션의 다른 부분에 있는 route를 현재 layout 안에서 load할 수 있게 해 주는 routing pattern입니다. URL을 공유 가능한 상태로 유지하면서, 사용자가 context를 전환하지 않고도 콘텐츠(예: modal)를 보여 줄 때 유용합니다. 자세한 내용은 Intercepting Routes를 참고하세요.

A routing pattern that allows loading a route from another part of your application within the current layout. Useful for displaying content (like modals) without the user switching context, while keeping the URL shareable. Learn more in Intercepting Routes.

Image Optimization

<Image> component를 사용한 자동 이미지 최적화입니다. Next.js는 이미지를 on-demand로 최적화하고, WebP 같은 최신 형식으로 제공하며, lazy loading과 responsive sizing을 자동으로 처리합니다. 자세한 내용은 Images를 참고하세요.

Automatic image optimization using the <Image> component. Next.js optimizes images on-demand, serves them in modern formats like WebP, and automatically handles lazy loading and responsive sizing. Learn more in Images.

L

Layout

여러 page가 공유하는 UI입니다. layout은 state를 보존하고, interactive 상태를 유지하며, navigation 시 다시 render되지 않습니다. layout.js 파일에서 React component를 export해서 정의합니다. 자세한 내용은 Layouts and Pages를 참고하세요.

UI that is shared between multiple pages. Layouts preserve state, remain interactive, and do not re-render on navigation. Defined by exporting a React component from a layout.js file. Learn more in Layouts and Pages.

Loading UI

route segment가 load되는 동안 보여 주는 fallback UI입니다. 폴더에 loading.js 파일을 추가해서 만들며, 이 파일은 page를 Suspense boundary로 자동으로 감쌉니다. 자세한 내용은 Loading UI를 참고하세요.

Fallback UI shown while a route segment is loading. Created by adding a loading.js file to a folder, which automatically wraps the page in a Suspense boundary. Learn more in Loading UI.

M

Module Graph

앱의 파일 dependency를 나타내는 graph입니다. 각 파일(module)이 node이고, import/export 관계가 edge를 이룹니다. Next.js는 이 graph를 분석해 최적의 bundling과 code-splitting 전략을 결정합니다. 자세한 내용은 Server and Client Components를 참고하세요.

A graph of file dependencies in your app. Each file (module) is a node, and import/export relationships form the edges. Next.js analyzes this graph to determine optimal bundling and code-splitting strategies. Learn more in Server and Client Components.

Metadata

title, description, Open Graph 이미지처럼 브라우저와 검색 엔진이 사용하는 page 정보입니다. Next.js에서는 layout 또는 page 파일에서 metadata export나 generateMetadata function을 사용해 metadata를 정의합니다. 자세한 내용은 Metadata and OG Images를 참고하세요.

Information about a page used by browsers and search engines, such as title, description, and Open Graph images. In Next.js, define metadata using the metadata export or generateMetadata function in layout or page files. Learn more in Metadata and OG Images.

Memoization

function의 반환값을 cache해서, 하나의 render pass(request) 동안 같은 function을 여러 번 호출해도 한 번만 실행되게 하는 것입니다. Next.js에서는 URL과 option이 같은 fetch GET request가 Server Component, layout, page, generateMetadata/generateStaticParams 전반에서 자동으로 memoize됩니다(단, Route Handlers는 React component tree의 일부가 아니므로 제외됩니다).

Caching the return value of a function so that calling the same function multiple times during a render pass (request) only executes it once. In Next.js, fetch GET requests with the same URL and options are automatically memoized across Server Components, layouts, pages, and generateMetadata/generateStaticParams (but not Route Handlers since they are not part of the React component tree).

fetch가 아닌 작업에는 React의 cache function을 사용하세요. 자세한 내용은 fetch API reference를 참고하세요.

For non-fetch operations, use the React cache function. Learn more in the fetch API reference.

Middleware

Proxy를 참고하세요.

See Proxy.

N

Navigation stages

client navigation 중에 server에서 render된 작업이 사용 가능해지는 시점들입니다. Partial Prefetching에서는 이 stage가 App Shell, per-link prefetch, navigation입니다. 자세한 내용은 ensureStatic, prefetch(), navigation() API reference를 참고하세요.

The points at which server-rendered work becomes available during a client navigation. With Partial Prefetching, the stages are the App Shell, a per-link prefetch, and the navigation. Learn more in the ensureStatic, prefetch(), and navigation() API references.

Not Found

route가 존재하지 않거나 notFound() function이 호출되었을 때 보여 주는 특별한 component입니다. app directory에 not-found.js 파일을 추가해서 만듭니다. 자세한 내용은 Error Handling을 참고하세요.

A special component shown when a route doesn't exist or when the notFound() function is called. Created by adding a not-found.js file to your app directory. Learn more in Error Handling.

P

Private Folders

underscore prefix가 붙은 폴더(예: _components)로, routing 시스템에서 제외됩니다. 접근 가능한 route를 만들지 않고 코드 정리와 공유 utility를 위해 사용됩니다. 자세한 내용은 Private Folders를 참고하세요.

Folders prefixed with an underscore (e.g., _components) that are excluded from the routing system. These folders are used for code organization and shared utilities without creating accessible routes. Learn more in Private Folders.

Page

하나의 route에만 고유한 UI입니다. app directory 안의 page.js 파일에서 React component를 export해서 정의합니다. 자세한 내용은 Layouts and Pages를 참고하세요.

UI that is unique to a route. Defined by exporting a React component from a page.js file within the app directory. Learn more in Layouts and Pages.

Parallel Routes

같은 layout 안에서 여러 page를 동시에 또는 조건에 따라 render할 수 있게 해 주는 pattern입니다. @folder convention으로 named slot을 만들어 사용하며, dashboard, modal, 복잡한 layout에 유용합니다. 자세한 내용은 Parallel Routes를 참고하세요.

A pattern that allows simultaneously or conditionally rendering multiple pages within the same layout. Created using named slots with the @folder convention, useful for dashboards, modals, and complex layouts. Learn more in Parallel Routes.

Partial Prefetching

Cache Components route를 위한 prefetching 전략으로, <Link>가 기본적으로 전체 page 대신 route별 App Shell을 prefetch합니다. next.config.ts에서 partialPrefetching: true로 활성화합니다. 자세한 내용은 Adopting Partial Prefetching 가이드를 참고하세요.

A prefetching strategy for Cache Components routes where a <Link> prefetches a per-route App Shell by default instead of the full page. Enable it with partialPrefetching: true in next.config.ts. Learn more in the Adopting Partial Prefetching guide.

Partial Prerendering (PPR)

하나의 route 안에서 prerendering과 dynamic rendering을 결합하는 rendering 최적화입니다. static shell은 즉시 제공되고 dynamic 콘텐츠는 준비되는 대로 stream되어, 두 rendering 전략의 장점을 모두 얻을 수 있습니다. 자세한 내용은 Cache Components를 참고하세요.

A rendering optimization that combines prerendering and dynamic rendering in a single route. The static shell is served immediately while dynamic content streams in when ready, providing the best of both rendering strategies. Learn more in Cache Components.

Prefetching

사용자가 route로 이동하기 전에 background에서 그 route를 load하는 것입니다. Next.js는 <Link> component로 연결된 route가 viewport에 들어오면 자동으로 prefetch하여, navigation이 즉각적으로 느껴지게 합니다. 자세한 내용은 Prefetching 가이드를 참고하세요.

Loading a route in the background before the user navigates to it. Next.js automatically prefetches routes linked with the <Link> component when they enter the viewport, making navigation feel instant. Learn more in the Prefetching guide.

Prerendering

component가 build time에, 또는 revalidation 중 background에서 render되는 것을 말합니다. 그 결과는 HTML과 RSC Payload이며, cache되어 CDN에서 제공될 수 있습니다. Request-time APIs를 사용하지 않는 component는 기본적으로 prerender됩니다.

When a component is rendered at build time or in the background during revalidation. The result is HTML and RSC Payload, which can be cached and served from a CDN. Prerendering is the default for components that don't use Request-time APIs.

Proxy

request가 완료되기 전에 server에서 코드를 실행하는 파일(proxy.js)입니다. logging, redirect, rewrite 같은 server-side logic을 구현하는 데 사용됩니다. 이전에는 Middleware라고 불렸습니다. 자세한 내용은 Proxy 가이드를 참고하세요.

A file (proxy.js) that runs code on the server before request is completed. Used to implement server-side logic like logging, redirects, and rewrites. Formerly known as Middleware. Learn more in the Proxy guide.

R

Redirect

사용자를 한 URL에서 다른 URL로 보내는 것입니다. Next.js에서 redirect는 next.config.js에서 설정하거나, Proxy에서 반환하거나, redirect() function으로 프로그래밍 방식으로 실행할 수 있습니다. 자세한 내용은 Redirecting을 참고하세요.

Sending users from one URL to another. In Next.js, redirects can be configured in next.config.js, returned from Proxy, or triggered programmatically with the redirect() function. Learn more in Redirecting.

Request-time APIs

request별 data에 접근하는 function으로, component가 dynamic rendering을 사용하게 만듭니다. 다음이 포함됩니다:

Functions that access request-specific data, causing a component to opt into dynamic rendering. These include:

  • cookies() - request cookie에 접근
  • headers() - request header에 접근
  • searchParams - URL query parameter에 접근
  • draftMode() - draft mode 활성화 또는 확인
  • cookies() - Access request cookies
  • headers() - Access request headers
  • searchParams - Access URL query parameters
  • draftMode() - Enable or check draft mode

Runtime rendering

Dynamic rendering을 참고하세요.

See Dynamic rendering.

Revalidation

cache된 data를 업데이트하는 과정입니다. time-based(cacheLife()로 cache 기간 설정) 또는 on-demand(cacheTag()로 data에 tag를 붙인 뒤 updateTag()로 invalidate) 방식으로 할 수 있습니다. 자세한 내용은 Caching and Revalidating을 참고하세요.

The process of updating cached data. Can be time-based (using cacheLife() to set cache duration) or on-demand (using cacheTag() to tag data, then updateTag() to invalidate). Learn more in Caching and Revalidating.

Rewrite

브라우저의 URL은 바꾸지 않고, 들어오는 request path를 다른 destination path로 mapping하는 것입니다. next.config.js에서 설정하거나 Proxy에서 반환합니다. 외부 서비스나 legacy URL로 proxy할 때 유용합니다.

Mapping an incoming request path to a different destination path without changing the URL in the browser. Configured in next.config.js or returned from Proxy. Useful for proxying to external services or legacy URLs.

Route Groups

URL 구조에 영향을 주지 않고 route를 정리하는 방법입니다. 폴더 이름을 괄호로 감싸서(예: (marketing)) 만들며, route group은 관련된 route를 정리하고 group별 layout을 사용할 수 있게 해 줍니다. 자세한 내용은 Route Groups를 참고하세요.

A way to organize routes without affecting the URL structure. Created by wrapping a folder name in parentheses (e.g., (marketing)), route groups help organize related routes and enable per-group layouts. Learn more in Route Groups.

Route Handler

특정 route의 HTTP request를 처리하는 function으로, route.js 파일에 정의합니다. Route Handler는 Web Request와 Response API를 사용하며 GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS method를 처리할 수 있습니다. 자세한 내용은 Route Handlers를 참고하세요.

A function that handles HTTP requests for a specific route, defined in a route.js file. Route Handlers use the Web Request and Response APIs and can handle GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS methods. Learn more in Route Handlers.

Route Segment

app directory의 폴더로 정의되는 URL path의 한 부분(두 slash 사이)입니다. 각 폴더는 URL 구조에서 하나의 segment를 나타냅니다. 자세한 내용은 Project Structure를 참고하세요.

A part of the URL path (between two slashes) defined by a folder in the app directory. Each folder represents a segment in the URL structure. Learn more in Project Structure.

RSC Payload

React Server Component Payload는 render된 React Server Components tree를 압축된 binary로 표현한 것입니다. Server Component의 render 결과, Client Component를 위한 placeholder, 그리고 그 사이에 전달되는 props가 들어 있습니다. 자세한 내용은 Server and Client Components를 참고하세요.

The React Server Component Payload is a compact binary representation of the rendered React Server Components tree. It contains the rendered result of Server Components, placeholders for Client Components, and props passed between them. Learn more in Server and Client Components.

S

Server Component

App Router의 기본 component type입니다. Server Component는 server에서 render되고, data를 직접 fetch할 수 있으며, client JavaScript bundle에 추가되지 않습니다. state나 browser API는 사용할 수 없습니다. 자세한 내용은 Server and Client Components를 참고하세요.

The default component type in the App Router. Server Components render on the server, can fetch data directly, and don't add to the client JavaScript bundle. They cannot use state or browser APIs. Learn more in Server and Client Components.

Server Action

Client Component에 prop으로 전달되거나 form action에 bind된 Server Function입니다. Server Action은 주로 form 제출과 data mutation에 사용됩니다. 자세한 내용은 Server Actions and Mutations를 참고하세요.

A Server Function that is passed to a Client Component as a prop or bound to a form action. Server Actions are commonly used for form submissions and data mutations. Learn more in Server Actions and Mutations.

Server Function

"use server" directive로 표시되어 server에서 실행되는 asynchronous function입니다. Server Function은 Client Component에서 호출할 수 있습니다. Client Component에 prop으로 전달되거나 form action에 bind되면 Server Action이라고 부릅니다. 자세한 내용은 React Server Functions를 참고하세요.

An asynchronous function that runs on the server, marked with the "use server" directive. Server Functions can be invoked from Client Components. When passed as a prop to a Client Component or bound to a form action, they are called Server Actions. Learn more in React Server Functions.

Static Export

HTML, CSS, JavaScript 파일로 이루어진 완전한 static 사이트를 생성하는 deployment mode입니다. next.config.js에서 output: 'export'를 설정해 활성화합니다. static export는 Node.js server 없이 어떤 static file server에서도 hosting할 수 있습니다. 자세한 내용은 Static Exports를 참고하세요.

A deployment mode that generates a fully static site with HTML, CSS, and JavaScript files. Enabled by setting output: 'export' in next.config.js. Static exports can be hosted on any static file server without a Node.js server. Learn more in Static Exports.

Static rendering

Prerendering을 참고하세요.

See Prerendering.

Static Assets

이미지, font, 동영상 및 기타 media처럼 별도 처리 없이 그대로 제공되는 파일입니다. static asset은 보통 public directory에 저장하고 상대 경로로 참조합니다. 자세한 내용은 Static Assets를 참고하세요.

Files such as images, fonts, videos, and other media that are served directly without processing. Static assets are typically stored in the public directory and referenced by their relative paths. Learn more in Static Assets.

Static Shell

브라우저에 즉시 제공되는, prerender된 page의 HTML 구조입니다. Partial Prerendering에서 static shell은 static하게 render 가능한 모든 콘텐츠와, 나중에 stream되는 dynamic 콘텐츠를 위한 Suspense boundary fallback을 포함합니다.

The prerendered HTML structure of a page that's served immediately to the browser. With Partial Prerendering, the static shell includes all statically renderable content plus Suspense boundary fallbacks for dynamic content that streams in later.

Streaming

전체 page가 render될 때까지 기다리지 않고, page의 각 부분이 준비되는 대로 server가 client에 보낼 수 있게 해 주는 기법입니다. loading.js나 직접 작성한 <Suspense> boundary로 자동 활성화됩니다. 자세한 내용은 Streaming 가이드를 참고하세요.

A technique that allows the server to send parts of a page to the client as they become ready, rather than waiting for the entire page to render. Enabled automatically with loading.js or manual <Suspense> boundaries. Learn more in the Streaming guide.

Suspense boundary

async 콘텐츠를 감싸고, load되는 동안 fallback UI를 보여 주는 React <Suspense> component입니다. Next.js에서 Suspense boundary는 static shell이 끝나고 streaming이 시작되는 지점을 정의하여 Partial Prerendering을 가능하게 합니다.

A React <Suspense> component that wraps async content and displays fallback UI while it loads. In Next.js, Suspense boundaries define where the static shell ends and streaming begins, enabling Partial Prerendering.

T

Turbopack

Next.js를 위해 만들어진 빠른 Rust 기반 bundler입니다. Turbopack은 next dev의 기본 bundler이며 next build에서도 사용할 수 있습니다. Webpack보다 compile 시간이 훨씬 빠릅니다. 자세한 내용은 Turbopack을 참고하세요.

A fast, Rust-based bundler built for Next.js. Turbopack is the default bundler for next dev and available for next build. It provides significantly faster compilation times compared to Webpack. Learn more in Turbopack.

Tree Shaking

build 과정에서 JavaScript bundle의 사용되지 않는 코드를 제거하는 과정입니다. Next.js는 bundle 크기를 줄이기 위해 코드를 자동으로 tree-shake합니다. 자세한 내용은 Package Bundling 가이드를 참고하세요.

The process of removing unused code from your JavaScript bundles during the build process. Next.js automatically tree-shakes your code to reduce bundle sizes. Learn more in the Package Bundling guide.

U

URL data

pathname이나 query parameter처럼 특정 URL을 식별하는 data입니다. App Router에서는 params와 searchParams, 그리고 이를 읽는 usePathname, useSearchParams 같은 client hook을 의미합니다. URL data는 session이 아니라 link마다 달라지므로, 공유되는 App Shell의 일부가 될 수 없습니다.

Data that identifies a specific URL, such as the pathname and query parameters. In the App Router this means params and searchParams, and the client hooks that read them like usePathname and useSearchParams. URL data varies per link, not per session, so it can't be part of a shared App Shell.

"use cache" Directive

component나 function을 cache 가능한 것으로 표시하는 directive입니다. 파일 맨 위에 두면 그 파일의 모든 export가 cache 가능함을 나타내고, function이나 component 맨 위에 inline으로 두면 해당 scope만 cache 가능하도록 표시합니다. 자세한 내용은 "use cache" reference를 참고하세요.

A directive that marks a component or function as cacheable. It can be placed at the top of a file to indicate that all exports in the file are cacheable, or inline at the top of a function or component to mark that specific scope as cacheable. Learn more in the "use cache" reference.

"use client" Directive

server 코드와 client 코드의 경계를 표시하는 특별한 React directive입니다. 반드시 파일 맨 위, 모든 import나 다른 코드보다 앞에 두어야 합니다. React Component, helper function, 변수 선언, 그리고 import된 모든 dependency가 client bundle에 포함되어야 함을 나타냅니다. 자세한 내용은 "use client" reference를 참고하세요.

A special React directive that marks the boundary between server and client code. It must be placed at the top of a file, before any imports or other code. It indicates that React Components, helper functions, variable declarations, and all imported dependencies should be included in the client bundle. Learn more in the "use client" reference.

"use server" Directive

function을 client-side 코드에서 호출할 수 있는 Server Function으로 표시하는 directive입니다. 파일 맨 위에 두면 그 파일의 모든 export가 Server Function임을 나타내고, function 맨 위에 inline으로 두면 해당 function만 표시합니다. 자세한 내용은 "use server" reference를 참고하세요.

A directive that marks a function as a Server Function that can be called from client-side code. It can be placed at the top of a file to indicate that all exports in the file are Server Functions, or inline at the top of a function to mark that specific function. Learn more in the "use server" reference.

V

Version skew

애플리케이션의 새 버전이 deploy된 후에도, 여전히 활성 상태인 client는 이전 build의 JavaScript, CSS, data를 참조할 수 있습니다. 이렇게 client와 server 버전이 어긋나는 것을 version skew라고 하며, asset 누락, Server Action error, navigation 실패를 일으킬 수 있습니다. Next.js는 deploymentId를 사용해 version skew를 감지하고 처리합니다. 자세한 내용은 Self-Hosting - Version Skew를 참고하세요.

After a new version of your application is deployed, clients that are still active may reference JavaScript, CSS, or data from an older build. This mismatch between client and server versions is called version skew, and it can cause missing assets, Server Action errors, and navigation failures. Next.js uses deploymentId to detect and handle version skew. Learn more in Self-Hosting - Version Skew.
