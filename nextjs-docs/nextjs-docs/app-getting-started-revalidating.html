RevalidatingRevalidation

이 페이지는 next.config.ts 파일에서 cacheComponents: true를 설정해 활성화하는 Cache Components 기반의 revalidation을 다룹니다. Cache Components를 사용하지 않는다면 Caching and Revalidating (Previous Model) 가이드를 참고하세요.

This page covers revalidation with Cache Components, enabled by setting cacheComponents: true in your next.config.ts file. If you're not using Cache Components, see the Caching and Revalidating (Previous Model) guide.

revalidation은 cache된 데이터를 업데이트하는 과정입니다. 콘텐츠를 최신 상태로 유지하면서도 빠른 cache response를 계속 제공할 수 있게 해 줍니다. 전략은 두 가지입니다:

Revalidation is the process of updating cached data. It lets you keep serving fast, cached responses while ensuring content stays fresh. There are two strategies:

  • Time-based revalidation: cacheLife를 사용해 정해진 시간이 지나면 cache된 데이터를 자동으로 새로 고칩니다.
  • On-demand revalidation: mutation 후 revalidateTag, updateTag, revalidatePath를 사용해 cache된 데이터를 수동으로 invalidate합니다.
  • Time-based revalidation: Automatically refresh cached data after a set duration using cacheLife.
  • On-demand revalidation: Manually invalidate cached data after a mutation using revalidateTag, updateTag, or revalidatePath.

cacheLife

cacheLife는 cache된 데이터가 얼마나 오래 유효한지 제어합니다. use cache scope 안에서 사용해 cache lifetime을 설정하세요.

cacheLife controls how long cached data remains valid. Use it inside a use cache scope to set the cache lifetime.

TSapp/lib/data.ts
import { cacheLife } from 'next/cache'

export async function getProducts() {
  'use cache'
  cacheLife('hours')
  return db.query('SELECT * FROM products')
}

cacheLife는 profile 이름 또는 custom configuration object를 받습니다:

cacheLife accepts a profile name or a custom configuration object:

더 세밀하게 제어하려면 object를 전달하세요:

For fine-grained control, pass an object:

'use cache'
cacheLife({
  stale: 3600, // 1 hour until considered stale
  revalidate: 7200, // 2 hours until revalidated
  expire: 86400, // 1 day until expired
})
Good to know

seconds profile, revalidate: 0, 또는 5분 미만의 expire를 사용하는 cache는 "short-lived"로 간주됩니다. short-lived cache는 자동으로 prerender에서 제외되고 대신 dynamic hole이 됩니다. 자세한 내용은 Prerendering behavior를 참고하세요.

A cache is considered "short-lived" when it uses the seconds profile, revalidate: 0, or expire under 5 minutes. Short-lived caches are automatically excluded from prerenders and become dynamic holes instead. See Prerendering behavior for details.

모든 profile과 custom configuration option은 cacheLife API reference를 참고하세요.

See the cacheLife API reference for all profiles and custom configuration options.

cacheTag

cacheTag를 사용하면 cache된 데이터에 tag를 붙여 on-demand로 invalidate할 수 있습니다. use cache scope 안에서 사용하세요:

cacheTag lets you tag cached data so it can be invalidated on-demand. Use it inside a use cache scope:

TSJSapp/lib/data.ts
import { cacheTag } from 'next/cache'

export async function getProducts() {
  'use cache'
  cacheTag('products')
  return db.query('SELECT * FROM products')
}
import { cacheTag } from 'next/cache'

export async function getProducts() {
  'use cache'
  cacheTag('products')
  return db.query('SELECT * FROM products')
}

tag를 붙인 후에는 revalidateTag나 updateTag로 cache를 invalidate하세요.

Once tagged, invalidate the cache using revalidateTag or updateTag.

자세한 내용은 cacheTag API reference를 참고하세요.

See the cacheTag API reference to learn more.

revalidateTag

revalidateTag는 stale-while-revalidate semantics로 tag에 해당하는 cache entry를 invalidate합니다. 즉, stale 콘텐츠를 즉시 제공하면서 background에서 새 콘텐츠를 로드합니다. blog post나 상품 카탈로그처럼 업데이트가 약간 늦어도 괜찮은 콘텐츠에 이상적입니다.

revalidateTag invalidates cache entries by tag using stale-while-revalidate semantics — stale content is served immediately while fresh content loads in the background. This is ideal for content where a slight delay in updates is acceptable, like blog posts or product catalogs.

TSJSapp/lib/actions.ts
import { revalidateTag } from 'next/cache'

export async function updateUser(id: string) {
  // Mutate data
  revalidateTag('user', 'max') // Recommended: stale-while-revalidate
}
import { revalidateTag } from 'next/cache'

export async function updateUser(id) {
  // Mutate data
  revalidateTag('user', 'max') // Recommended: stale-while-revalidate
}

같은 tag를 여러 함수에서 재사용하면 한 번에 모두 revalidate할 수 있습니다. revalidateTag는 Server Action이나 Route Handler에서 호출하세요.

You can reuse the same tag in multiple functions to revalidate them all at once. Call revalidateTag in a Server Action or Route Handler.

Good to know

두 번째 인자는 background에서 새 콘텐츠가 생성되는 동안 stale 콘텐츠를 얼마나 오래 제공할 수 있는지 설정합니다. 이 기간이 만료되면 이후 request는 새 콘텐츠가 준비될 때까지 block됩니다. 'max'를 사용하면 stale 기간이 가장 길어집니다.

The second argument sets how long stale content can be served while fresh content generates in the background. Once it expires, subsequent requests block until fresh content is ready. Using 'max' gives the longest stale window.

자세한 내용은 revalidateTag API reference를 참고하세요.

See the revalidateTag API reference to learn more.

updateTag

updateTag는 read-your-own-writes 시나리오를 위해 cache된 데이터를 즉시 만료시킵니다. 즉, 사용자는 stale 콘텐츠 대신 자신이 변경한 내용을 바로 보게 됩니다. revalidateTag와 달리 Server Actions에서만 사용할 수 있습니다.

updateTag immediately expires cached data for read-your-own-writes scenarios — the user sees their change right away instead of stale content. Unlike revalidateTag, it can only be used in Server Actions.

TSJSapp/lib/actions.ts
import { updateTag } from 'next/cache'
import { redirect } from 'next/navigation'

export async function createPost(formData: FormData) {
  const post = await db.post.create({
    data: {
      title: formData.get('title'),
      content: formData.get('content'),
    },
  })

  updateTag('posts')
  redirect(`/posts/${post.id}`)
}
import { updateTag } from 'next/cache'
import { redirect } from 'next/navigation'

export async function createPost(formData) {
  const post = await db.post.create({
    data: {
      title: formData.get('title'),
      content: formData.get('content'),
    },
  })

  updateTag('posts')
  redirect(`/posts/${post.id}`)
}

revalidatePath

revalidatePath는 특정 route path에 대한 모든 cache된 데이터를 invalidate합니다. route에 어떤 tag가 연결되어 있는지 모르는 상태에서 route를 revalidate하고 싶을 때 사용하세요.

revalidatePath invalidates all cached data for a specific route path. Use it when you want to revalidate a route without knowing which tags are associated with it.

TSJSapp/lib/actions.ts
import { revalidatePath } from 'next/cache'

export async function updateUser(id: string) {
  // Mutate data
  revalidatePath('/profile')
}
import { revalidatePath } from 'next/cache'

export async function updateUser(id) {
  // Mutate data
  revalidatePath('/profile')
}
Good to know

가능하면 path 기반보다 tag 기반 revalidation(revalidateTag/updateTag)을 우선 사용하세요. 더 정확하고 과도한 invalidation을 피할 수 있습니다.

Prefer tag-based revalidation (revalidateTag/updateTag) over path-based when possible — it's more precise and avoids over-invalidating.

자세한 내용은 revalidatePath API reference를 참고하세요.

See the revalidatePath API reference to learn more.

What should I cache?무엇을 cache해야 할까?

runtime 데이터에 의존하지 않고, 일정 기간 cache에서 제공해도 괜찮은 데이터를 cache하세요. 이런 동작은 use cache와 cacheLife로 표현합니다.

Cache data that doesn't depend on runtime data and that you're OK serving from cache for a period of time. Use use cache with cacheLife to describe that behavior.

CMS의 데이터처럼 콘텐츠에 시간 기반 revalidation이 필요 없다면, cacheTag와 max 같은 긴 cacheLife를 사용해 static shell에 유지하세요. 콘텐츠가 바뀔 때 revalidateTag를 호출하는 webhook이나 기타 알림을 trigger하도록 content source를 설정하세요. 이렇게 하면 바뀌지 않은 콘텐츠에 대한 불필요한 시간 기반 revalidation이 줄어듭니다.

When content doesn't need time-based revalidation, for example data from a CMS, use cacheTag and a long cacheLife like max to keep it in the static shell. Configure the content source to trigger a webhook, or other notification, that calls revalidateTag when the content changes. This reduces unnecessary time-based revalidation for content that hasn't changed.

Good to know

serverless 환경에서는 in-memory cache entry가 revalidation 사이에 유지되지 않을 수 있습니다. 자세한 내용은 runtime caching considerations를 참고하세요.

In serverless environments, in-memory cache entries may not persist across revalidations. See runtime caching considerations for details.
