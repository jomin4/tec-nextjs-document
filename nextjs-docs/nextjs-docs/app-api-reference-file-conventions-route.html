route.jsroute.js

Route Handler를 사용하면 Web Request 및 Response API로 특정 route에 대한 custom request handler를 만들 수 있습니다.

Route Handlers allow you to create custom request handlers for a given route using the Web Request and Response APIs.

TSJSroute.ts
export async function GET() {
  return Response.json({ message: 'Hello World' })
}
export async function GET() {
  return Response.json({ message: 'Hello World' })
}

Reference

HTTP MethodsHTTP Method

route 파일을 사용하면 특정 route에 대한 custom request handler를 만들 수 있습니다. 지원되는 HTTP methods는 GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS입니다.

A route file allows you to create custom request handlers for a given route. The following HTTP methods are supported: GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS.

TSJSroute.ts
export async function GET(request: Request) {}

export async function HEAD(request: Request) {}

export async function POST(request: Request) {}

export async function PUT(request: Request) {}

export async function DELETE(request: Request) {}

export async function PATCH(request: Request) {}

// If `OPTIONS` is not defined, Next.js will automatically implement `OPTIONS` and set the appropriate Response `Allow` header depending on the other methods defined in the Route Handler.
export async function OPTIONS(request: Request) {}
export async function GET(request) {}

export async function HEAD(request) {}

export async function POST(request) {}

export async function PUT(request) {}

export async function DELETE(request) {}

export async function PATCH(request) {}

// If `OPTIONS` is not defined, Next.js will automatically implement `OPTIONS` and set the appropriate Response `Allow` header depending on the other methods defined in the Route Handler.
export async function OPTIONS(request) {}

Parameters

request (optional)

request 객체는 Web Request API를 확장한 NextRequest 객체입니다. NextRequest를 사용하면 cookies에 쉽게 접근하거나 확장·파싱된 URL 객체 nextUrl을 사용하는 등 들어오는 request를 더 세밀하게 제어할 수 있습니다.

The request object is a NextRequest object, which is an extension of the Web Request API. NextRequest gives you further control over the incoming request, including easily accessing cookies and an extended, parsed, URL object nextUrl.

TSJSroute.ts
import type { NextRequest } from 'next/server'

export async function GET(request: NextRequest) {
  const url = request.nextUrl
}
export async function GET(request) {
  const url = request.nextUrl
}

context (optional)

  • params: 현재 route의 dynamic route parameters를 담은 객체로 resolve되는 promise입니다.
  • params: a promise that resolves to an object containing the dynamic route parameters for the current route.
TSJSapp/dashboard/[team]/route.ts
export async function GET(
  request: Request,
  { params }: { params: Promise<{ team: string }> }
) {
  const { team } = await params
}
export async function GET(request, { params }) {
  const { team } = await params
}

app/blog/[...slug]/route.js/blog/1/2Promise<{ slug: ['1', '2'] }>

Route Context Helper

RouteContext를 사용해 Route Handler context에 type을 지정하면 route literal로부터 강타입(strongly typed) params를 얻을 수 있습니다. RouteContext는 전역에서 사용할 수 있는 helper입니다.

You can type the Route Handler context using RouteContext to get strongly typed params from a route literal. RouteContext is a globally available helper.

TSapp/users/[id]/route.ts
import type { NextRequest } from 'next/server'

export async function GET(_req: NextRequest, ctx: RouteContext<'/users/[id]'>) {
  const { id } = await ctx.params
  return Response.json({ id })
}
Good to know
  • Type은 next dev, next build 또는 next typegen 실행 중에 생성됩니다.
  • type 생성 후에는 RouteContext helper를 전역에서 사용할 수 있습니다. import할 필요가 없습니다.
  • Types are generated during next dev, next build or next typegen.
  • After type generation, the RouteContext helper is globally available. It doesn't need to be imported.

Cookies

next/headers의 cookies로 cookie를 읽거나 설정할 수 있습니다.

You can read or set cookies with cookies from next/headers.

TSJSroute.ts
import { cookies } from 'next/headers'

export async function GET(request: NextRequest) {
  const cookieStore = await cookies()

  const a = cookieStore.get('a')
  const b = cookieStore.set('b', '1')
  const c = cookieStore.delete('c')
}
import { cookies } from 'next/headers'

export async function GET(request) {
  const cookieStore = await cookies()

  const a = cookieStore.get('a')
  const b = cookieStore.set('b', '1')
  const c = cookieStore.delete('c')
}

또는 Set-Cookie header를 사용해 새 Response를 return할 수도 있습니다.

Alternatively, you can return a new Response using the Set-Cookie header.

TSJSapp/api/route.ts
import { cookies } from 'next/headers'

export async function GET(request: Request) {
  const cookieStore = await cookies()
  const token = cookieStore.get('token')

  return new Response('Hello, Next.js!', {
    status: 200,
    headers: { 'Set-Cookie': `token=${token.value}` },
  })
}
import { cookies } from 'next/headers'

export async function GET(request) {
  const cookieStore = await cookies()
  const token = cookieStore.get('token')

  return new Response('Hello, Next.js!', {
    status: 200,
    headers: { 'Set-Cookie': `token=${token.value}` },
  })
}

기반이 되는 Web API를 사용해 request(NextRequest)에서 cookie를 읽을 수도 있습니다:

You can also use the underlying Web APIs to read cookies from the request (NextRequest):

TSJSapp/api/route.ts
import { type NextRequest } from 'next/server'

export async function GET(request: NextRequest) {
  const token = request.cookies.get('token')
}
export async function GET(request) {
  const token = request.cookies.get('token')
}

Headers

next/headers의 headers로 header를 읽을 수 있습니다.

You can read headers with headers from next/headers.

TSJSroute.ts
import { headers } from 'next/headers'
import type { NextRequest } from 'next/server'

export async function GET(request: NextRequest) {
  const headersList = await headers()
  const referer = headersList.get('referer')
}
import { headers } from 'next/headers'

export async function GET(request) {
  const headersList = await headers()
  const referer = headersList.get('referer')
}

이 headers instance는 read-only입니다. header를 설정하려면 새 headers를 가진 새 Response를 return해야 합니다.

This headers instance is read-only. To set headers, you need to return a new Response with new headers.

TSJSapp/api/route.ts
import { headers } from 'next/headers'

export async function GET(request: Request) {
  const headersList = await headers()
  const referer = headersList.get('referer')

  return new Response('Hello, Next.js!', {
    status: 200,
    headers: { referer: referer },
  })
}
import { headers } from 'next/headers'

export async function GET(request) {
  const headersList = await headers()
  const referer = headersList.get('referer')

  return new Response('Hello, Next.js!', {
    status: 200,
    headers: { referer: referer },
  })
}

기반이 되는 Web API를 사용해 request(NextRequest)에서 header를 읽을 수도 있습니다:

You can also use the underlying Web APIs to read headers from the request (NextRequest):

TSJSapp/api/route.ts
import { type NextRequest } from 'next/server'

export async function GET(request: NextRequest) {
  const requestHeaders = new Headers(request.headers)
}
export async function GET(request) {
  const requestHeaders = new Headers(request.headers)
}

Route Handler는 Dynamic Segments를 사용해 동적 데이터로부터 request handler를 만들 수 있습니다.

Route Handlers can use Dynamic Segments to create request handlers from dynamic data.

Static Generation with generateStaticParamsgenerateStaticParams로 Static Generation

dynamic Route Handler와 함께 generateStaticParams를 사용하면 지정된 params에 대해서는 build 시점에 response를 정적으로 생성하고, 나머지 params는 request 시점에 동적으로 처리할 수 있습니다.

You can use generateStaticParams with dynamic Route Handlers to statically generate responses at build time for specified params, while handling other params dynamically at request time.

Cache Components를 사용할 때는 generateStaticParams와 use cache를 결합해 prerender된 params와 runtime params 모두에 대해 data caching을 활성화할 수 있습니다.

When using Cache Components, you can combine generateStaticParams with use cache to enable data caching for both prerendered and runtime params.

예시와 자세한 내용은 generateStaticParams with Route Handlers 문서를 참고하세요.

See the generateStaticParams with Route Handlers documentation for examples and details.

URL Query Parameters

Route Handler에 전달되는 request 객체는 NextRequest instance이며, query parameter를 더 쉽게 다루기 위한 method 같은 몇 가지 추가 편의 method를 포함합니다.

The request object passed to the Route Handler is a NextRequest instance, which includes some additional convenience methods, such as those for more easily handling query parameters.

TSJSapp/api/search/route.ts
import { type NextRequest } from 'next/server'

export function GET(request: NextRequest) {
  const searchParams = request.nextUrl.searchParams
  const query = searchParams.get('query')
  // query is "hello" for /api/search?query=hello
}
export function GET(request) {
  const searchParams = request.nextUrl.searchParams
  const query = searchParams.get('query')
  // query is "hello" for /api/search?query=hello
}

Streaming

Streaming은 AI 생성 콘텐츠를 위해 OpenAI 같은 Large Language Model(LLM)과 함께 흔히 사용됩니다. AI SDK에 대해 더 알아보세요.

Streaming is commonly used in combination with Large Language Models (LLMs), such as OpenAI, for AI-generated content. Learn more about the AI SDK.

TSJSapp/api/chat/route.ts
import { openai } from '@ai-sdk/openai'
import { StreamingTextResponse, streamText } from 'ai'

export async function POST(req: Request) {
  const { messages } = await req.json()
  const result = await streamText({
    model: openai('gpt-4-turbo'),
    messages,
  })

  return new StreamingTextResponse(result.toAIStream())
}
import { openai } from '@ai-sdk/openai'
import { StreamingTextResponse, streamText } from 'ai'

export async function POST(req) {
  const { messages } = await req.json()
  const result = await streamText({
    model: openai('gpt-4-turbo'),
    messages,
  })

  return new StreamingTextResponse(result.toAIStream())
}

이러한 추상화는 Web API를 사용해 stream을 만듭니다. 기반이 되는 Web API를 직접 사용할 수도 있습니다.

These abstractions use the Web APIs to create a stream. You can also use the underlying Web APIs directly.

TSJSapp/api/route.ts
// https://developer.mozilla.org/docs/Web/API/ReadableStream#convert_async_iterator_to_stream
function iteratorToStream(iterator: any) {
  return new ReadableStream({
    async pull(controller) {
      const { value, done } = await iterator.next()

      if (done) {
        controller.close()
      } else {
        controller.enqueue(value)
      }
    },
  })
}

function sleep(time: number) {
  return new Promise((resolve) => {
    setTimeout(resolve, time)
  })
}

const encoder = new TextEncoder()

async function* makeIterator() {
  yield encoder.encode('<p>One</p>')
  await sleep(200)
  yield encoder.encode('<p>Two</p>')
  await sleep(200)
  yield encoder.encode('<p>Three</p>')
}

export async function GET() {
  const iterator = makeIterator()
  const stream = iteratorToStream(iterator)

  return new Response(stream)
}

Request Body FormData

request.formData() 함수를 사용해 FormData를 읽을 수 있습니다:

You can read the FormData using the request.formData() function:

TSJSapp/items/route.ts
export async function POST(request: Request) {
  const formData = await request.formData()
  const name = formData.get('name')
  const email = formData.get('email')
  return Response.json({ name, email })
}
export async function POST(request) {
  const formData = await request.formData()
  const name = formData.get('name')
  const email = formData.get('email')
  return Response.json({ name, email })
}

formData 데이터는 모두 문자열이므로, zod-form-data를 사용해 request를 검증하고 원하는 형식(예: number)으로 데이터를 가져오는 것이 좋을 수 있습니다.

Since formData data are all strings, you may want to use zod-form-data to validate the request and retrieve data in the format you prefer (e.g. number).

CORS

표준 Web API method를 사용해 특정 Route Handler에 CORS header를 설정할 수 있습니다:

You can set CORS headers for a specific Route Handler using the standard Web API methods:

TSJSapp/api/route.ts
export async function GET(request: Request) {
  return new Response('Hello, Next.js!', {
    status: 200,
    headers: {
      'Access-Control-Allow-Origin': '*',
      'Access-Control-Allow-Methods': 'GET, POST, PUT, DELETE, OPTIONS',
      'Access-Control-Allow-Headers': 'Content-Type, Authorization',
    },
  })
}
export async function GET(request) {
  return new Response('Hello, Next.js!', {
    status: 200,
    headers: {
      'Access-Control-Allow-Origin': '*',
      'Access-Control-Allow-Methods': 'GET, POST, PUT, DELETE, OPTIONS',
      'Access-Control-Allow-Headers': 'Content-Type, Authorization',
    },
  })
}
Good to know
  • 여러 Route Handler에 CORS header를 추가하려면 Proxy 또는 next.config.js file을 사용할 수 있습니다.
  • To add CORS headers to multiple Route Handlers, you can use Proxy or the next.config.js file.

Webhooks

Route Handler를 사용해 third-party 서비스의 webhook을 받을 수 있습니다:

You can use a Route Handler to receive webhooks from third-party services:

TSJSapp/api/route.ts
export async function POST(request: Request) {
  try {
    const text = await request.text()
    // Process the webhook payload
  } catch (error) {
    return new Response(`Webhook error: ${error.message}`, {
      status: 400,
    })
  }

  return new Response('Success!', {
    status: 200,
  })
}
export async function POST(request) {
  try {
    const text = await request.text()
    // Process the webhook payload
  } catch (error) {
    return new Response(`Webhook error: ${error.message}`, {
      status: 400,
    })
  }

  return new Response('Success!', {
    status: 200,
  })
}

특히 Pages Router의 API Routes와 달리, 추가 설정을 위해 bodyParser를 사용할 필요가 없습니다.

Notably, unlike API Routes with the Pages Router, you do not need to use bodyParser to use any additional configuration.
