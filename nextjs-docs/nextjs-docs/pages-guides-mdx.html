How to use markdown and MDX in Next.jsNext.js에서 markdown과 MDX 사용하기

Markdown은 텍스트 서식을 지정하는 데 쓰이는 가벼운 markup language입니다. 일반 텍스트 문법으로 작성한 내용을 구조적으로 올바른 HTML로 변환할 수 있습니다. 웹사이트와 블로그의 콘텐츠를 작성할 때 흔히 사용됩니다.

Markdown is a lightweight markup language used to format text. It allows you to write using plain text syntax and convert it to structurally valid HTML. It's commonly used for writing content on websites and blogs.

이렇게 작성하면...

You write...

I **love** using [Next.js](https://nextjs.org/)

출력:

Output:

<p>I <strong>love</strong> using <a href="https://nextjs.org/">Next.js</a></p>

MDX는 markdown의 superset으로, markdown 파일 안에 JSX를 직접 작성할 수 있게 해 줍니다. 콘텐츠 안에 dynamic한 상호작용을 더하고 React component를 넣을 수 있는 강력한 방법입니다.

MDX is a superset of markdown that lets you write JSX directly in your markdown files. It is a powerful way to add dynamic interactivity and embed React components within your content.

Next.js는 애플리케이션 안의 로컬 MDX 콘텐츠와, server에서 dynamic하게 fetch하는 원격 MDX 파일을 모두 지원합니다. Next.js plugin이 markdown과 React component를 HTML로 변환하는 작업을 처리하며, Server Component(App Router의 기본값)에서의 사용도 지원합니다.

Next.js can support both local MDX content inside your application, as well as remote MDX files fetched dynamically on the server. The Next.js plugin handles transforming markdown and React components into HTML, including support for usage in Server Components (the default in App Router).

Install dependenciesdependency 설치

@next/mdx package와 관련 package들은 Next.js가 markdown과 MDX를 처리할 수 있도록 설정하는 데 사용됩니다. 이 package는 로컬 파일에서 데이터를 가져오므로, /pages 또는 /app directory 안에 .md나 .mdx 확장자로 바로 page를 만들 수 있습니다.

The @next/mdx package, and related packages, are used to configure Next.js so it can process markdown and MDX. It sources data from local files, allowing you to create pages with a .md or .mdx extension, directly in your /pages or /app directory.

Next.js에서 MDX를 render하려면 다음 package들을 설치하세요:

Install these packages to render MDX with Next.js:

pnpm add @next/mdx @mdx-js/loader @mdx-js/react @types/mdx
npm install @next/mdx @mdx-js/loader @mdx-js/react @types/mdx
yarn add @next/mdx @mdx-js/loader @mdx-js/react @types/mdx
bun add @next/mdx @mdx-js/loader @mdx-js/react @types/mdx

Configure next.config.mjsnext.config.mjs 설정하기

프로젝트 root에 있는 next.config.mjs 파일을 수정해 MDX를 사용하도록 설정하세요:

Update the next.config.mjs file at your project's root to configure it to use MDX:

JSnext.config.mjs
import createMDX from '@next/mdx'

/** @type {import('next').NextConfig} */
const nextConfig = {
  // Configure `pageExtensions` to include markdown and MDX files
  pageExtensions: ['js', 'jsx', 'md', 'mdx', 'ts', 'tsx'],
  // Optionally, add any other Next.js config below
}

const withMDX = createMDX({
  // Add markdown plugins here, as desired
})

// Merge MDX config with Next.js config
export default withMDX(nextConfig)

이렇게 하면 .mdx 파일을 애플리케이션에서 page, route, 또는 import 대상으로 사용할 수 있습니다.

This allows .mdx files to act as pages, routes, or imports in your application.

Handling .md files.md 파일 처리하기

기본적으로 @next/mdx는 .mdx 확장자 파일만 compile합니다. webpack으로 .md 파일도 처리하려면 extension option을 수정하세요:

By default, @next/mdx only compiles files with the .mdx extension. To handle .md files with webpack, update the extension option:

JSnext.config.mjs
const withMDX = createMDX({
  extension: /\.(md|mdx)$/,
})

Add an mdx-components.tsx filemdx-components.tsx 파일 추가하기

프로젝트 root에 mdx-components.tsx(또는 .js) 파일을 만들어 global MDX Component를 정의하세요. 예를 들어 pages나 app과 같은 위치, 또는 해당되는 경우 src 안에 둡니다.

Create an mdx-components.tsx (or .js) file in the root of your project to define global MDX Components. For example, at the same level as pages or app, or inside src if applicable.

TSJSmdx-components.tsx
import type { MDXComponents } from 'mdx/types'

const components: MDXComponents = {}

export function useMDXComponents(): MDXComponents {
  return components
}
const components = {}

export function useMDXComponents() {
  return components
}

Using custom styles and componentscustom style과 component 사용하기

Markdown은 render될 때 native HTML element로 mapping됩니다. 예를 들어 다음 markdown을 작성하면:

Markdown, when rendered, maps to native HTML elements. For example, writing the following markdown:

## This is a heading

This is a list in markdown:

- One
- Two
- Three

다음 HTML이 생성됩니다:

Generates the following HTML:

<h2>This is a heading</h2>

<p>This is a list in markdown:</p>

<ul>
  <li>One</li>
  <li>Two</li>
  <li>Three</li>
</ul>

markdown에 style을 입히려면 생성된 HTML element에 mapping되는 custom component를 제공하면 됩니다. style과 component는 global, local, 그리고 shared layout으로 적용할 수 있습니다.

To style your markdown, you can provide custom components that map to the generated HTML elements. Styles and components can be implemented globally, locally, and with shared layouts.

Global styles and componentsglobal style과 component

mdx-components.tsx에 style과 component를 추가하면 애플리케이션의 모든 MDX 파일에 적용됩니다.

Adding styles and components in mdx-components.tsx will affect all MDX files in your application.

  ),

      sizes="100vw"

  ),
} satisfies MDXComponents

Local styles and componentslocal style과 component

import한 MDX component에 local style과 component를 전달해 특정 page에만 적용할 수 있습니다. 이 값들은 global style과 component와 merge되며 이를 override합니다.

You can apply local styles and components to specific pages by passing them into imported MDX components. These will merge with and override global styles and components.

TSJSpages/mdx-page.tsx
import Welcome from '@/markdown/welcome.mdx'

function CustomH1({ children }) {
  return <h1 style={{ color: 'blue', fontSize: '100px' }}>{children}</h1>
}

const overrideComponents = {
  h1: CustomH1,
}

export default function Page() {
  return <Welcome components={overrideComponents} />
}

remark and rehype Pluginsremark와 rehype plugin

선택적으로 remark와 rehype plugin을 제공해 MDX 콘텐츠를 변환할 수 있습니다.

You can optionally provide remark and rehype plugins to transform the MDX content.

예를 들어 remark-gfm을 사용해 GitHub Flavored Markdown을 지원할 수 있습니다.

For example, you can use remark-gfm to support GitHub Flavored Markdown.

remark와 rehype ecosystem은 ESM 전용이므로 configuration 파일로 next.config.mjs 또는 next.config.ts를 사용해야 합니다.

Since the remark and rehype ecosystem is ESM only, you'll need to use next.config.mjs or next.config.ts as the configuration file.

JSnext.config.mjs
import remarkGfm from 'remark-gfm'
import createMDX from '@next/mdx'

/** @type {import('next').NextConfig} */
const nextConfig = {
  // Allow .mdx extensions for files
  pageExtensions: ['js', 'jsx', 'md', 'mdx', 'ts', 'tsx'],
  // Optionally, add any other Next.js config below
}

const withMDX = createMDX({
  // Add markdown plugins here, as desired
  options: {
    remarkPlugins: [remarkGfm],
    rehypePlugins: [],
  },
})

// Combine MDX and Next.js config
export default withMDX(nextConfig)

serializable하지 않은 option을 가진 remark와 rehype plugin은 아직 Turbopack에서 사용할 수 없습니다. JavaScript 함수를 Rust로 전달할 수 없기 때문입니다.

remark and rehype plugins without serializable options cannot be used yet with Turbopack, because JavaScript functions can't be passed to Rust.

Deep Dive: How do you transform markdown into HTML?Deep Dive: markdown을 HTML로 어떻게 변환할까?

React는 markdown을 기본적으로 이해하지 못합니다. markdown plaintext는 먼저 HTML로 변환되어야 합니다. 이 작업은 remark와 rehype로 할 수 있습니다.

React does not natively understand markdown. The markdown plaintext needs to first be transformed into HTML. This can be accomplished with remark and rehype.

remark는 markdown을 다루는 도구들의 ecosystem입니다. rehype도 같은 역할을 하지만 HTML을 다룹니다. 예를 들어 다음 code snippet은 markdown을 HTML로 변환합니다:

remark is an ecosystem of tools around markdown. rehype is the same, but for HTML. For example, the following code snippet transforms markdown into HTML:

import { unified } from 'unified'
import remarkParse from 'remark-parse'
import remarkRehype from 'remark-rehype'
import rehypeSanitize from 'rehype-sanitize'
import rehypeStringify from 'rehype-stringify'

main()

async function main() {
  const file = await unified()
    .use(remarkParse) // Convert into markdown AST
    .use(remarkRehype) // Transform to HTML AST
    .use(rehypeSanitize) // Sanitize HTML input
    .use(rehypeStringify) // Convert AST into serialized HTML
    .process('Hello, Next.js!')

  console.log(String(file)) // <p>Hello, Next.js!</p>
}

remark와 rehype ecosystem에는 syntax highlighting, heading link 연결, 목차 생성 등을 위한 plugin이 있습니다.

The remark and rehype ecosystem contains plugins for syntax highlighting, linking headings, generating a table of contents, and more.

위에서처럼 @next/mdx를 사용할 때는 이 과정이 자동으로 처리되므로 remark나 rehype를 직접 사용할 필요가 없습니다. 여기서는 @next/mdx package가 내부적으로 무엇을 하는지 더 깊이 이해할 수 있도록 설명했습니다.

When using @next/mdx as shown above, you do not need to use remark or rehype directly, as it is handled for you. We're describing it here for a deeper understanding of what the @next/mdx package is doing underneath.

Using the Rust-based MDX compiler (experimental)Rust 기반 MDX compiler 사용하기 (experimental)

Next.js는 Rust로 작성된 새로운 MDX compiler를 지원합니다. 이 compiler는 아직 experimental 단계이며 production 사용은 권장하지 않습니다. 새 compiler를 사용하려면 withMDX에 전달할 때 next.config.js를 설정해야 합니다:

Next.js supports a new MDX compiler written in Rust. This compiler is still experimental and is not recommended for production use. To use the new compiler, you need to configure next.config.js when you pass it to withMDX:

JSnext.config.js
module.exports = withMDX({
  experimental: {
    mdxRs: true,
  },
})

mdxRs는 mdx 파일 변환 방식을 설정하는 object도 받을 수 있습니다.

mdxRs also accepts an object to configure how to transform mdx files.

JSnext.config.js
module.exports = withMDX({
  experimental: {
    mdxRs: {
      jsxRuntime?: string            // Custom jsx runtime
      jsxImportSource?: string       // Custom jsx import source,
      providerImportSource?: string  // Module providing a `useMDXComponents` context
      mdxType?: 'gfm' | 'commonmark' // Configure what kind of mdx syntax will be used to parse & transform
    },
  },
})
