Options옵션

Fetching

Next.js를 development mode로 실행할 때 logging level과 전체 URL을 console에 log할지 여부를 설정할 수 있습니다.

You can configure the logging level and whether the full URL is logged to the console when running Next.js in development mode.

JSnext.config.js
module.exports = {
  logging: {
    fetches: {
      fullUrl: true,
    },
  },
}

Server Components HMR cache에서 복원된 fetch request는 기본적으로 log되지 않습니다. 하지만 logging.fetches.hmrRefreshes를 true로 설정하면 활성화할 수 있습니다.

Any fetch requests that are restored from the Server Components HMR cache are not logged by default. However, this can be enabled by setting logging.fetches.hmrRefreshes to true.

JSnext.config.js
module.exports = {
  logging: {
    fetches: {
      hmrRefreshes: true,
    },
  },
}

Server Functions

Server Function 호출은 development 중에 기본적으로 log됩니다. logging.serverFunctions를 false로 설정하면 비활성화할 수 있습니다.

Server Function invocations are logged by default during development. You can disable this by setting logging.serverFunctions to false.

JSnext.config.js
module.exports = {
  logging: {
    serverFunctions: false,
  },
}

활성화되어 있으면 terminal에 각 Server Function 호출이 함수 이름, argument, 소요 시간과 함께 표시됩니다:

When enabled, the terminal displays each Server Function call with its function name, arguments, and duration:

>_Terminal
POST /
  └─ ƒ myAction(arg1, arg2) in 5ms app/actions.ts

Incoming Requests들어오는 request

기본적으로 development 중에는 들어오는 모든 request가 console에 log됩니다. incomingRequests option을 사용해 어떤 request를 무시할지 정할 수 있습니다. 이 log는 development에서만 남기 때문에, 이 option은 production build에 영향을 주지 않습니다.

By default all the incoming requests will be logged in the console during development. You can use the incomingRequests option to decide which requests to ignore. Since this is only logged in development, this option doesn't affect production builds.

JSnext.config.js
module.exports = {
  logging: {
    incomingRequests: {
      ignore: [/\/api\/v1\/health/],
    },
  },
}

또는 incomingRequests를 false로 설정해 들어오는 request의 logging을 비활성화할 수 있습니다.

Or you can disable incoming request logging by setting incomingRequests to false.

JSnext.config.js
module.exports = {
  logging: {
    incomingRequests: false,
  },
}

Browser Console Logs브라우저 console log

development 중에 브라우저 console log(console.log, console.warn, console.error 등)를 terminal로 전달할 수 있습니다. 이는 브라우저의 developer tools를 확인하지 않고도 client-side 코드를 debugging할 때 유용합니다.

You can forward browser console logs (such as console.log, console.warn, console.error) to the terminal during development. This is useful for debugging client-side code without needing to check the browser's developer tools.

JSnext.config.js
module.exports = {
  logging: {
    browserToTerminal: true,
  },
}

Options옵션

browserToTerminal option은 다음 값을 받습니다:

The browserToTerminal option accepts the following values:

값설명
'warn'warning과 error만 전달합니다(기본값)
'error'error만 전달합니다
true모든 console 출력(log, info, warn, error)을 전달합니다
false브라우저 log 전달을 비활성화합니다
ValueDescription
'warn'Forward only warnings and errors, by default
'error'Forward only errors
trueForward all console output (log, info, warn, error)
falseDisable browser log forwarding
JSnext.config.js
module.exports = {
  logging: {
    browserToTerminal: 'warn',
  },
}

Source Locationsource 위치

활성화되어 있으면 브라우저 log에는 기본적으로 source 위치 정보(파일 경로와 줄 번호)가 포함됩니다. 예를 들면 다음과 같습니다:

When enabled, browser logs include source location information (file path and line number) by default. For example:

TSapp/page.tsx
'use client'

export default function Home() {
  return (
    <button
      type="button"
      onClick={() => {
        console.log('Hello World')
      }}
    >
      Click me
    </button>
  )
}

버튼을 클릭하면 terminal에 다음 메시지가 출력됩니다:

Clicking the button prints this message to the terminal:

>_Terminal
[browser] Hello World (app/page.tsx:8:17)

Disabling Logginglogging 비활성화

또한 logging을 false로 설정해 development logging을 비활성화할 수 있습니다.

In addition, you can disable the development logging by setting logging to false.

JSnext.config.js
module.exports = {
  logging: false,
}
