Testing AdaptersAdapter 테스트하기

Next.js는 adapter를 검증하기 위한 test harness를 제공합니다. deployment에 대한 end-to-end test를 실행합니다.

Next.js provides a test harness for validating adapters. Running the end-to-end tests for deployment.

GitHub Actions workflow 예제:

Example GitHub Actions workflow:

.github/workflows/test-e2e-deploy.yml
name: test-e2e-deploy

on:
  workflow_dispatch:
    inputs:
      nextjsRef:
        description: 'Next.js repo ref (branch/tag/SHA)'
        default: 'canary'
        type: string
  # schedule:
  #   - cron: '0 2 * * *'

jobs:
  build:
    name: Build Next.js + adapter
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4
        with:
          path: adapter

      - uses: actions/checkout@v4
        with:
          repository: vercel/next.js
          ref: ${{ inputs.nextjsRef || 'canary' }}
          path: nextjs
          fetch-depth: 25

      - uses: actions/setup-node@v4
        with: { node-version: '20' }

      - name: Setup pnpm
        run: npm i -g corepack@0.31 && corepack enable

      - name: Install & build Next.js
        working-directory: nextjs
        run: pnpm install && pnpm build && pnpm install

      - name: Install Playwright
        working-directory: nextjs
        run: pnpm playwright install --with-deps chromium

      - name: Build adapter
        working-directory: adapter
        run: pnpm install && pnpm build

      - uses: actions/cache/save@v4
        with:
          path: |
            nextjs
            adapter
            ~/.cache/ms-playwright
          key: build-${{ github.sha }}-${{ github.run_id }}

  test:
    name: Tests (${{ matrix.group }})
    needs: build
    runs-on: ubuntu-latest
    timeout-minutes: 60
    strategy:
      fail-fast: false
      matrix:
        group:
          [
            1/16,
            2/16,
            3/16,
            4/16,
            5/16,
            6/16,
            7/16,
            8/16,
            9/16,
            10/16,
            11/16,
            12/16,
            13/16,
            14/16,
            15/16,
            16/16,
          ]
    steps:
      - uses: actions/cache/restore@v4
        with:
          path: |
            nextjs
            adapter
            ~/.cache/ms-playwright
          key: build-${{ github.sha }}-${{ github.run_id }}

      - uses: actions/setup-node@v4
        with: { node-version: '20' }

      - name: Setup pnpm
        run: npm i -g corepack@0.31 && corepack enable

      - name: Ensure Playwright browser
        working-directory: nextjs
        run: pnpm playwright install chromium

      - name: Make scripts executable
        run: chmod +x adapter/scripts/e2e-deploy.sh
          adapter/scripts/e2e-logs.sh
          adapter/scripts/e2e-cleanup.sh

      - name: Run deploy tests
        working-directory: nextjs
        env:
          NEXT_TEST_MODE: deploy
          NEXT_E2E_TEST_TIMEOUT: 240000
          NEXT_EXTERNAL_TESTS_FILTERS: test/deploy-tests-manifest.json
          ADAPTER_DIR: ${{ github.workspace }}/adapter
          IS_TURBOPACK_TEST: 1
          NEXT_TEST_JOB: 1
          NEXT_TELEMETRY_DISABLED: 1

          # Change these to your adapter's scripts
          # Keep as-is if the scripts are in the adapter repository `scripts` directory
          NEXT_TEST_DEPLOY_SCRIPT_PATH: ${{ github.workspace }}/adapter/scripts/e2e-deploy.sh
          NEXT_TEST_DEPLOY_LOGS_SCRIPT_PATH: ${{ github.workspace }}/adapter/scripts/e2e-logs.sh
          NEXT_TEST_CLEANUP_SCRIPT_PATH: ${{ github.workspace }}/adapter/scripts/e2e-cleanup.sh
        run: node run-tests.js --timings -g ${{ matrix.group }} -c 2 --type e2e

      - name: Save test results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: adapter-test-results-${{ strategy.job-index }}
          path: '**/*.results.json'
          retention-days: 1

  upload-results:
    name: Report results to nextjs.org
    needs: test
    if: always()
    runs-on: ubuntu-latest
    permissions:
      contents: read
      # Minting a GitHub OIDC token to authenticate the results upload.
      id-token: write
    steps:
      - uses: actions/checkout@v4
        with:
          repository: vercel/next.js
          ref: ${{ inputs.nextjsRef || 'canary' }}
          path: nextjs

      - uses: actions/setup-node@v4
        with: { node-version: '20' }

      - uses: actions/download-artifact@v4
        with:
          pattern: adapter-test-results-*
          path: adapter-test-results
          merge-multiple: true

      - name: Upload adapter test results
        working-directory: nextjs
        run: node scripts/upload-adapter-test-results.mjs --results-root ../adapter-test-results

Reporting results to nextjs.orgnextjs.org에 결과 보고하기

위의 upload-results job은 결과를 adapter test-results endpoint로 보내며, 이 endpoint가 Adapter Support by Provider matrix를 구동합니다.

The upload-results job above sends your results to the adapter test-results endpoint, which powers the Adapter Support by Provider matrix.

upload는 GitHub Actions OIDC token으로 인증하므로, 위에 표시된 id-token: write permission이 필요합니다. 발급되거나 저장되는 secret은 없습니다. provider 이름과 commit SHA는 token claim에서 도출되므로, 결과는 그것을 생성한 repository와 workflow에만 귀속될 수 있습니다.

The upload authenticates with a GitHub Actions OIDC token, so it needs the id-token: write permission shown above. No secret is issued or stored: the provider name and commit SHA are derived from the token claims, which means results can only be attributed to the repository and workflow that produced them.

목록에 등록되기: 이 matrix는 Ecosystem Working Group에 속한 adapter에 열려 있습니다. verified adapter와 working group이 어떻게 운영되는지는 Deploying to Platforms를 참고하세요. repository와 workflow는 그 과정의 일부로 등록됩니다. 결과는 다음 workflow 실행 후 matrix에 나타납니다. 그 전까지 upload는 403 Forbidden을 반환합니다.

Getting listed: the matrix is open to adapters in the Ecosystem Working Group. See Deploying to Platforms for how verified adapters and the working group operate. Your repository and workflow are registered as part of that process. Your results appear on the matrix after your next workflow run. Until then the upload returns 403 Forbidden.

test harness는 다음 environment variable을 찾습니다:

The test harness looks for these environment variables:

  • NEXT_TEST_DEPLOY_SCRIPT_PATH: 격리된 test 앱을 build하고 deploy하는 실행 파일의 경로
  • NEXT_TEST_DEPLOY_LOGS_SCRIPT_PATH: 해당 deployment의 build log와 runtime log를 반환하는 실행 파일의 경로
  • NEXT_TEST_CLEANUP_SCRIPT_PATH: test 실행 후 deployment를 정리(tear down)하는 선택적 실행 파일의 경로
  • NEXT_TEST_DEPLOY_SCRIPT_PATH: Path to the executable that builds and deploys the isolated test app
  • NEXT_TEST_DEPLOY_LOGS_SCRIPT_PATH: Path to the executable that returns build and runtime logs for that deployment
  • NEXT_TEST_CLEANUP_SCRIPT_PATH: Path to the optional executable that tears the deployment down after the test run

Custom deploy script contractCustom deploy script 규약

deploy script NEXT_TEST_DEPLOY_SCRIPT_PATH는 Next.js test harness가 만든 격리된 임시 앱을 cwd로 설정한 상태에서 실행됩니다.

The deploy script NEXT_TEST_DEPLOY_SCRIPT_PATH is executed with cwd set to the isolated temporary app created by the Next.js test harness.

deploy script는 다음 규약(contract)을 따라야 합니다:

The deploy script must follow this contract:

  • 실패 시 0이 아닌 code로 종료합니다.
  • deployment URL을 stdout에 출력합니다. 이 URL은 deployment를 검증하는 데 사용됩니다. stdout에는 그 외의 다른 내용을 쓰지 마세요.
  • 진단 output은 stderr나 working directory 안의 파일에 씁니다.
  • Exit with a non-zero code on failure.
  • Print the deployment URL to stdout. This will be used to verify the deployment. Avoid writing anything else to stdout.
  • Write diagnostic output to stderr or to files inside the working directory.

deploy script와 logs script는 별도의 process로 실행되므로, build ID나 server log처럼 나중에 사용할 데이터는 working directory 안의 파일에 저장해 두어야 합니다.

Because the deploy script and logs script run as separate processes, any data you want to use later, such as build IDs or server logs, should be persisted to files inside the working directory.

deploy script 예제:

Example deploy script:

>_scripts/e2e-deploy.sh
#!/usr/bin/env bash
set -euo pipefail

# Install the adapter, build the app, and deploy or start it.
node -e "
const pkg=JSON.parse(require('fs').readFileSync('package.json','utf8'));
pkg.dependencies=pkg.dependencies||{};
pkg.dependencies['adapter']='file:${ADAPTER_DIR}';
require('fs').writeFileSync('package.json',JSON.stringify(pkg,null,2));
" >&2

# Set the adapter path so that the app uses it.
export NEXT_ADAPTER_PATH="${ADAPTER_DIR}/dist/index.js"

# Build the app
pnpm build

# Write any metadata needed later to files in the working directory.
BUILD_ID="$(cat .next/BUILD_ID)"
DEPLOYMENT_ID="my-adapter-local"
# If your adapter enables immutable static assets, set this to "1".
NEXT_SUPPORTS_IMMUTABLE_ASSETS="0"

{
  echo "BUILD_ID: $BUILD_ID"
  echo "DEPLOYMENT_ID: $DEPLOYMENT_ID"
  echo "NEXT_SUPPORTS_IMMUTABLE_ASSETS: $NEXT_SUPPORTS_IMMUTABLE_ASSETS"
} >> .adapter-build.log

# Start or deploy the app. Capture the URL at this point or make the script output the URL to stdout.
provider-cli-to-deploy

# Example URL output:
# echo "http://127.0.0.1:3000"

Custom logs script contractCustom logs script 규약

logs script NEXT_TEST_DEPLOY_LOGS_SCRIPT_PATH는 Next.js test harness가 만든 격리된 임시 앱을 cwd로 설정한 상태에서 실행됩니다.

The logs script NEXT_TEST_DEPLOY_LOGS_SCRIPT_PATH is executed with cwd set to the isolated temporary app created by the Next.js test harness.

또한 NEXT_TEST_DIR과 NEXT_TEST_DEPLOY_URL을 environment variable로 전달받습니다.

Additionally it receives NEXT_TEST_DIR and NEXT_TEST_DEPLOY_URL as environment variables.

output에는 다음으로 시작하는 줄이 반드시 포함되어야 합니다:

Its output must include lines starting with:

  • BUILD_ID:
  • DEPLOYMENT_ID:
  • NEXT_SUPPORTS_IMMUTABLE_ASSETS:
  • BUILD_ID:
  • DEPLOYMENT_ID:
  • NEXT_SUPPORTS_IMMUTABLE_ASSETS:

이 marker들 다음에는 실패를 debug하는 데 도움이 되는 추가 build log나 server log를 자유롭게 출력할 수 있습니다.

After those markers, the logs script can print any additional build or server logs that would help debug failures.

>_scripts/e2e-logs.sh
#!/usr/bin/env bash
set -euo pipefail

if [ -f ".adapter-build.log" ]; then
  cat ".adapter-build.log"
fi

if [ -f ".adapter-server.log" ]; then
  echo "=== .adapter-server.log ==="
  cat ".adapter-server.log"
fi

한 가지 pattern은 deploy script가 .adapter-build.log와 .adapter-server.log를 쓰게 하고, logs script가 이 파일들을 다시 출력(replay)해 harness가 필요한 marker를 추출할 수 있게 하는 것입니다. 이는 하나의 방법일 뿐이며, platform마다 log를 가져오는 방법은 다릅니다.

One pattern is to have the deploy script write .adapter-build.log and .adapter-server.log, then have the logs script replay those files so the harness can extract the required markers. This is one option, each platform has different ways to get the logs.

Custom cleanup script contractCustom cleanup script 규약

cleanup script NEXT_TEST_CLEANUP_SCRIPT_PATH는 Next.js test harness가 만든 격리된 임시 앱을 cwd로 설정한 상태에서 실행됩니다.

The cleanup script NEXT_TEST_CLEANUP_SCRIPT_PATH is executed with cwd set to the isolated temporary app created by the Next.js test harness.

또한 NEXT_TEST_DIR과 NEXT_TEST_DEPLOY_URL을 environment variable로 전달받습니다.

Additionally it receives NEXT_TEST_DIR and NEXT_TEST_DEPLOY_URL as environment variables.

cleanup script는 deploy script가 만든 resource를 정리하는 데 사용할 수 있습니다. test가 완료된 뒤에 실행됩니다.

The cleanup script can be used to clean up any resources created by the deploy script. It runs after the tests have completed.
