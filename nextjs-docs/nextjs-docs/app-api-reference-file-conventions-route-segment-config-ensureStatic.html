ensureStaticensureStatic

ensureStatic route segment config는 선택한 route output이 request마다 rendering되지 않고 static이도록 요구합니다. page나 layout에서 export하면 App Shell, link별 prefetch, 또는 server에서 rendering되는 route 전체에 이 요구 사항을 강제할 수 있습니다.

The ensureStatic route segment config requires selected route output to be static instead of rendered per request. Export it from a page or layout to enforce this requirement for the App Shell, per-link prefetches, or the complete server-rendered route.

이 설정을 사용하면 static으로 유지되어야 하는 navigation 단계에 이후 변경으로 request-time server rendering이 추가되는 것을 막을 수 있습니다. 각 수준의 실제 예시는 Keeping pages static을 참고하세요.

Use it so later changes cannot add request-time server rendering to a navigation stage that must stay static. See Keeping pages static for a worked example of each level.

Good to know
  • ensureStatic export는 cacheComponents가 활성화되어 있을 때만 동작합니다. 그렇지 않으면 build가 실패합니다.
  • Client Component에서 ensureStatic을 export하면 error가 발생합니다.
  • The ensureStatic export only works when cacheComponents is enabled. The build fails otherwise.
  • Exporting ensureStatic from a Client Component throws an error.
TSJSapp/blog/layout.tsx
export const ensureStatic = 'navigation'

export default function Layout({ children }: { children: React.ReactNode }) {
  return <>{children}</>
}
export const ensureStatic = 'navigation'

export default function Layout({ children }) {
  return <>{children}</>
}

Reference

이 export는 'auto', 'shell', 'prefetch', 'navigation', false를 받습니다. default는 'auto'이며, export를 생략한 것과 같습니다.

The export accepts 'auto', 'shell', 'prefetch', 'navigation', or false. The default is 'auto', which is equivalent to omitting the export.

ensureStatic은 server에서 rendering되는 output 중 어떤 것이 static이어야 하는지를 제어합니다. Partial Prefetching을 사용하면 그 output은 App Shell, 선택적인 link별 prefetch, 또는 navigation 중에 rendering되는 route 전체가 될 수 있습니다. 이 output들을 navigation stage라고 부릅니다. 더 엄격한 수준은 그 앞 단계들도 함께 포함합니다.

ensureStatic controls which server-rendered output must be static. With Partial Prefetching, that output can be the App Shell, an optional per-link prefetch, or the complete route rendered during navigation. These outputs are called navigation stages. Each stricter level also includes the earlier stages.

false는 static 수준을 선택하지 않습니다. 일반적인 rendering 동작을 유지하며, 다른 segment가 route에 'shell', 'prefetch', 'navigation'을 적용하지 못하게 막습니다. false를 참고하세요.

false does not select a static level. It preserves normal rendering behavior and prevents another segment from applying 'shell', 'prefetch', or 'navigation' to the route. See false.

'shell'

default <Link>가 load하는 App Shell이 static이도록 요구합니다. Partial Prefetching이 없으면 App Shell이 없으므로 이 값은 효과가 없고 Next.js가 warning을 log에 남깁니다.

Requires the App Shell loaded by a default <Link> to be static. Without Partial Prefetching there is no App Shell, so the value has no effect and Next.js logs a warning.

shell에는 static 또는 cache된 콘텐츠와 <Suspense> fallback이 포함될 수 있습니다. <Suspense> 뒤의 request별 콘텐츠는 <Link prefetch={true}>를 사용한 이후의 link별 prefetch 중에, 또는 navigation 중에 rendering될 수 있습니다.

The shell can include static or cached content and <Suspense> fallbacks. Request-specific content behind <Suspense> can render during a later per-link prefetch with <Link prefetch={true}>, or during navigation.

개별 subtree의 경우 await prefetch()가 호출 아래의 코드를 link별 prefetch나 navigation으로 미뤄서 비슷한 동작을 제공합니다. 'shell'을 설정하면 request별 subtree마다 await prefetch()를 추가하지 않고도 route 전체에 그 stage 경계를 강제할 수 있습니다. subtree별 제어 방법은 Defer work to a later stage를 참고하세요.

For an individual subtree, await prefetch() provides similar behavior by deferring code below the call to a per-link prefetch or navigation. Setting 'shell' enforces that stage boundary across the route without adding await prefetch() to each request-specific subtree. See Defer work to a later stage for the per-subtree controls.

Good to know

'shell'은 link별 prefetch가 static이도록 요구하지 않습니다. route가 await navigation() 전에 cookies(), headers(), URL 데이터를 읽는다면, 화면에 보이는 각 <Link prefetch={true}>가 여전히 server render를 일으킬 수 있습니다. link별 prefetch도 static output에서 나와야 한다면 'prefetch'를 사용하세요.

'shell' does not require per-link prefetches to be static. If the route reads cookies(), headers(), or URL data before await navigation(), each visible <Link prefetch={true}> can still trigger a server render. Use 'prefetch' when per-link prefetches must also come from static output.

'prefetch'

App Shell과 link별 prefetch가 모두 static이도록 요구합니다. Partial Prefetching이 없으면 이 값은 아무 요구 사항도 추가하지 않으며, link는 일반적인 full-prefetch 동작을 유지합니다. full prefetch는 request별 데이터를 포함할 수 있으므로 static이라고 보장되지 않습니다.

Requires both the App Shell and per-link prefetches to be static. Without Partial Prefetching, the value adds no requirement and links keep their normal full-prefetch behavior. A full prefetch can include request-specific data and is not guaranteed to be static.

<Link prefetch={true}>의 link별 prefetch는 사용자가 link를 따라가기 전에 static 또는 cache된 URL별 콘텐츠를 load할 수 있습니다. <Suspense> 뒤의 request별 콘텐츠는 navigation이 route를 완성할 때 rendering됩니다.

A per-link prefetch from <Link prefetch={true}> can load static or cached URL-specific content before the user follows the link. Request-specific content behind <Suspense> renders when the navigation completes the route.

static HTML shell에도 이런 static 또는 cache된 link별 콘텐츠가 포함될 수 있습니다. 다만 link별 prefetch와 달리, HTML shell은 prerender되기 때문에 request별 데이터를 포함할 수 없습니다.

The static HTML shell can also include this static or cached per-link content. Unlike a per-link prefetch, it cannot include request-specific data because the HTML shell is prerendered.

개별 subtree의 경우 await navigation()이 호출 아래의 코드를 navigation까지 미뤄서 비슷한 동작을 제공합니다. 'prefetch'를 설정하면 request별 subtree마다 await navigation()을 추가하지 않고도 route 전체에 그 stage 경계를 강제할 수 있습니다. 이런 방식으로 route 하나를 구성하는 방법은 Keep the prefetch static을 참고하세요.

For an individual subtree, await navigation() provides similar behavior by deferring code below the call until navigation. Setting 'prefetch' enforces that stage boundary across the route without adding await navigation() to each request-specific subtree. See Keep the prefetch static for shaping one route this way.

'navigation'

server에서 rendering되는 route 전체가 prerendering 중에 만들어지도록 요구하므로, 초기 load와 client navigation 모두 static output을 사용합니다. 이 값은 Cache Components만으로 동작하며 Partial Prefetching이 필요하지 않습니다.

Requires the complete server-rendered route to be produced during prerendering, so initial loads and client navigations use static output. This value works with Cache Components alone and does not require Partial Prefetching.

앱 전체에 static server output을 요구하려면 root layout에 'navigation'을 설정하세요. route 전체에서 수준이 어떻게 적용되는지는 Combining levels across layouts and pages를 참고하세요.

To require static server output for the entire app, set 'navigation' on the root layout. See Combining levels across layouts and pages for how levels apply across a route.

Validation검증

'shell'과 'prefetch'에서는 <Suspense> 안의 request별 작업이 이후 navigation 단계로 이동할 수 있습니다. 이 값들은 build validation을 추가하지 않습니다. Instant Navigation validation이 활성화되어 있으면 <Suspense> 밖의 request별 작업은 navigation을 block하므로 보고될 수 있습니다.

With 'shell' and 'prefetch', request-specific work inside <Suspense> can move to a later navigation stage. These values do not add build validation. When Instant Navigation validation is enabled, it can report request-specific work outside <Suspense> because it blocks the navigation.

'navigation'은 server rendering의 마지막 단계이므로 그 뒤에 남은 단계가 없습니다. Next.js는 next dev와 next build 모두에서 완전한 static output 요구 사항을 검증합니다. development에서는 error에 source map이 적용된 stack trace가 포함되며 코드를 수정하면 업데이트됩니다. build output은 더 축약되어 있으므로, 자세한 stack trace와 code frame을 보려면 next build --debug-prerender를 실행해야 할 수 있습니다. development workflow는 Ensuring instant navigations를 참고하세요.

'navigation' is the final server-rendering stage, so no later stage remains. Next.js validates its complete static-output requirement during both next dev and next build. In development, errors include source-mapped stack traces that update as you edit. Build output is more abbreviated, so you may need to run next build --debug-prerender for detailed stack traces and code frames. See Ensuring instant navigations for the development workflow.

ensureStatic = 'navigation'에서는 다음 server 콘텐츠가 <Suspense>로 감싸져 있거나 segment가 instant = false를 설정해도 validation에 실패합니다:

With ensureStatic = 'navigation', the following server content fails validation, even when it is wrapped in <Suspense> or the segment sets instant = false:

  • use cache 없이 하는 fetch나 database 호출, 그리고 connection()을 포함한 cache되지 않은 데이터.
  • cookies(), headers(), server-side searchParams 같은 runtime 데이터.
  • expire가 5분 미만이거나, stale이 30초 미만이거나, revalidate가 0인 use cache scope. 30초에서 5분 사이의 stale 시간은 허용됩니다.
  • Client Component에 전달된 request 의존 server 데이터의 promise. component가 이를 읽는지 여부와 상관없습니다.
  • Uncached data, including a fetch or database call without use cache, and connection().
  • Runtime data, such as cookies(), headers(), and server-side searchParams.
  • A use cache scope whose expire is under five minutes, stale is under 30 seconds, or revalidate is 0. A stale time between 30 seconds and five minutes is allowed.
  • A promise for request-dependent server data passed to a Client Component, whether or not the component reads it.

이 제약은 generateMetadata와 generateViewport에도 적용됩니다.

These constraints also apply to generateMetadata and generateViewport.

use cache로 cache된 데이터는 prerender될 수 있습니다. prefetch()와 navigation()도 허용되는데, static prerender는 그 stage 경계를 지나 계속 진행되기 때문입니다.

Data cached with use cache can be prerendered. prefetch() and navigation() are also allowed because a static prerender continues through their stage boundaries.

Dynamic route parametersDynamic route parameter

'navigation'에서는 dynamic route가 generateStaticParams()를 export하고 완전한 parameter 세트를 최소 하나 반환해야 합니다. 각 결과에는 route의 모든 dynamic parameter가 포함되어야 하며, parameter를 사용하지 않거나 Client Component에서만 읽더라도 마찬가지입니다.

With 'navigation', a dynamic route must export generateStaticParams() and return at least one complete parameter set. Each result must include every dynamic parameter in the route, even if the parameter is unused or only read in a Client Component.

generateStaticParams()가 반환한 값은 prerendering 중에 사용할 수 있습니다. build 시점에 prerender되지 않은 값을 request가 사용하면, Next.js는 static 결과가 생성될 때까지 기다린 뒤 이를 serve합니다.

Values returned by generateStaticParams() are available during prerendering. When a request uses a value that was not prerendered at build time, Next.js waits for the static result to be generated before serving it.

'shell'이나 'prefetch'에서는 prerender되지 않은 값에 대해 route의 fallback shell을 대신 serve합니다. 이때 콘텐츠 자리에는 <Suspense> fallback이 들어가고, Next.js는 background에서 page를 생성합니다. ISR with Cache Components를 참고하세요.

With 'shell' or 'prefetch', a value that was not prerendered serves the route's fallback shell instead, with <Suspense> fallbacks in place of its content, while Next.js generates the page in the background. See ISR with Cache Components.

generateStaticParams()가 없거나 불완전한 parameter 세트를 반환하면 build가 실패합니다. generateStaticParams error guide를 참고하세요.

The build fails when generateStaticParams() is missing or returns an incomplete parameter set. See the generateStaticParams error guide.

Client Components

Client Component는 브라우저에서 request별 콘텐츠를 load할 수 있습니다. <Suspense> 안에서는 use(browser())와 use(io())가 허용됩니다. prerender에는 미뤄진 콘텐츠의 fallback이 포함됩니다. Rendering components only in the browser를 참고하세요.

Client Components can load request-specific content in the browser. Inside <Suspense>, use(browser()) and use(io()) are allowed. The prerender includes the fallback for the deferred content. See Rendering components only in the browser.

useParams()와 useSearchParams() 같은 client hook도 허용됩니다. dynamic route에는 여전히 generateStaticParams()가 필요합니다. Server Component에서 request 의존 promise를 전달하는 것은 여전히 server 작업이 필요하므로 error가 발생합니다.

Client hooks such as useParams() and useSearchParams() are also allowed. Dynamic routes still require generateStaticParams(). Passing a request-dependent promise from a Server Component still requires server work and produces an error.

false

Partial Prefetching에서 false는 route의 일반적인 rendering 동작을 유지하며, 다른 segment가 'shell', 'prefetch', 'navigation'을 설정하면 build를 실패시킵니다. 해당 segment가 static optimization 대상이 아니라는 것을 나타낼 때 사용하세요.

With Partial Prefetching, false keeps the route's normal rendering behavior and fails the build if another segment sets 'shell', 'prefetch', or 'navigation'. Use it to signal that a segment is not meant to be statically optimized.

How ensureStatic differs from instantensureStatic과 instant의 차이

ensureStatic은 선택한 server rendering output이 request-time 작업을 하지 않도록 요구합니다. App Shell, link별 prefetch, 또는 route 전체가 static이어야 할 때 사용하세요.

ensureStatic requires selected server-rendered output to avoid request-time work. Use it when the App Shell, a per-link prefetch, or the complete route must be static.

instant는 navigation이 UI를 즉시 업데이트할 수 있는지를 검증합니다. request별 콘텐츠가 나중에 <Suspense> 뒤에서 stream되는 동안 cache되었거나 prerender된 UI가 있으면 이 요구 사항을 충족할 수 있습니다.

instant validates whether a navigation can update the UI immediately. Cached or prerendered UI can satisfy this requirement while request-specific content streams later behind <Suspense>.

instant = false를 설정하면 route의 Instant Navigation validation이 비활성화됩니다. 'shell'과 'prefetch' 값은 여전히 client가 해당 static output을 request하게 만들지만, 둘 다 별도의 build validation을 추가하지는 않습니다. static prefetch는 사용자가 link를 따라간 뒤에야 page UI가 rendering되는 경우에도 parent layout, metadata, Client Component preload hint를 포함할 수 있습니다. 'navigation' 값은 별도의 완전한 static-output validation을 사용하며, instant = false는 이를 완화하지 않습니다.

Setting instant = false disables Instant Navigation validation for the route. The 'shell' and 'prefetch' values still make the client request the corresponding static output, but neither value adds separate build validation. A static prefetch can still include a parent layout, metadata, and Client Component preload hints even when the page UI renders only after the user follows the link. The 'navigation' value uses separate complete static-output validation, which instant = false does not relax.

Combining levels across layouts and pageslayout과 page 사이에서 수준 조합하기

root layout에 설정한 수준은 앱의 모든 route에 적용됩니다. 다른 layout에 설정한 수준은 그 layout을 rendering하는 모든 route에 적용되며, 그 안의 nested layout, page, parallel route도 포함합니다. route 안에서 수준은 그것을 설정한 layout 위의 layout들까지 포함해 모든 segment에 적용됩니다.

A level set on the root layout applies to every route in the app. A level set on another layout applies to every route that renders it, including its nested layouts, pages, and parallel routes. Within a route, the level covers every segment, including the layouts above the one that sets it.

export를 설정하지 않거나 'auto'로 설정하면 어떤 수준과도 호환되며 다른 segment의 설정을 유지합니다. 하위 segment는 더 엄격한 static 수준을 설정할 수 있지만, 더 약한 수준은 설정할 수 없습니다:

Leaving the export unset or setting it to 'auto' is compatible with any level and preserves another segment's setting. A descendant can set a stricter static level, but not a weaker one:

TSapp/blog/layout.tsx
export const ensureStatic = 'prefetch'
TSapp/blog/[slug]/page.tsx
export const ensureStatic = 'navigation' // allowed, stricter than 'prefetch'

child segment에 더 약한 수준을 설정하면 build가 실패합니다:

A weaker level on a child segment fails the build:

>_Terminal
A child segment cannot override a parent segment with a less-constrained `ensureStatic`.

parent와 child에서 false를 'shell', 'prefetch', 'navigation'과 섞어 쓰면 다음과 같이 실패합니다:

Mixing false with 'shell', 'prefetch', or 'navigation' in a parent and child fails with:

>_Terminal
A child segment cannot override a parent segment with an incompatible `ensureStatic`.

함께 rendering되는 parallel route는 같은 값을 설정하거나, export를 설정하지 않거나, 'auto'를 사용해야 합니다. 값이 충돌하면 다음과 같이 실패합니다:

Parallel routes rendered together must set the same value, leave the export unset, or use 'auto'. Conflicting values fail with:

>_Terminal
Parallel slots cannot have incompatible `ensureStatic`.
