How to implement JSON-LD in your Next.js applicationNext.js 애플리케이션에 JSON-LD 구현하기

JSON-LD는 structured data를 위한 형식으로, 검색 엔진과 AI가 순수한 콘텐츠 이상으로 페이지의 구조를 이해하도록 돕는 데 사용할 수 있습니다. 예를 들어 사람, 이벤트, 조직, 영화, 책, 레시피를 비롯한 다양한 종류의 entity를 설명하는 데 사용할 수 있습니다.

JSON-LD is a format for structured data that can be used by search engines and AI to help them understand the structure of the page beyond pure content. For example, you can use it to describe a person, an event, an organization, a movie, a book, a recipe, and many other types of entities.

현재 JSON-LD에 대한 권장 방식은 structured data를 layout.js 또는 page.js component 안에서 <script> tag로 render하는 것입니다.

Our current recommendation for JSON-LD is to render structured data as a <script> tag in your layout.js or page.js components.

다음 snippet은 JSON.stringify를 사용하는데, 이 함수는 XSS injection에 쓰이는 악의적인 문자열을 sanitize하지 않습니다. 이런 종류의 취약점을 막으려면 JSON-LD payload에서 HTML tag를 제거할 수 있습니다. 예를 들어 < 문자를 그에 해당하는 unicode인 \u003c로 바꾸는 방법이 있습니다.

The following snippet uses JSON.stringify, which does not sanitize malicious strings used in XSS injection. To prevent this type of vulnerability, you can scrub HTML tags from the JSON-LD payload, for example, by replacing the character, <, with its unicode equivalent, \u003c.

잠재적으로 위험한 문자열을 sanitize하는 방법은 조직에서 권장하는 방식을 검토하거나, serialize-javascript처럼 커뮤니티에서 관리하는 JSON.stringify 대안을 사용하세요.

Review your organization's recommended approach to sanitize potentially dangerous strings, or use community maintained alternatives for JSON.stringify such as, serialize-javascript.

TSJSapp/products/[id]/page.tsx
export default async function Page({ params }) {
  const { id } = await params
  const product = await getProduct(id)

  const jsonLd = {
    '@context': 'https://schema.org',
    '@type': 'Product',
    name: product.name,
    image: product.image,
    description: product.description,
  }

  return (
    <section>
      {/* Add JSON-LD to your page */}
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{
          __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c'),
        }}
      />
      {/* ... */}
    </section>
  )
}

structured data는 Google용 Rich Results Test나 범용 Schema Markup Validator로 검증하고 테스트할 수 있습니다.

You can validate and test your structured data with the Rich Results Test for Google or the generic Schema Markup Validator.

schema-dts 같은 커뮤니티 package를 사용하면 TypeScript로 JSON-LD에 type을 지정할 수 있습니다:

You can type your JSON-LD with TypeScript using community packages like schema-dts:

import { Product, WithContext } from 'schema-dts'

const jsonLd: WithContext<Product> = {
  '@context': 'https://schema.org',
  '@type': 'Product',
  name: 'Next.js Sticker',
  image: 'https://nextjs.org/imgs/sticker.png',
  description: 'Dynamic at the speed of static.',
}
Good to know

next/script component는 JavaScript를 load하고 실행하는 데 최적화되어 있습니다. JSON-LD는 실행 가능한 코드가 아니라 structured data이므로, 여기서는 native <script> tag를 사용하는 것이 올바른 선택입니다.

The next/script component is optimized for loading and executing JavaScript. Since JSON-LD is structured data, not executable code, a native <script> tag is the right choice here.
