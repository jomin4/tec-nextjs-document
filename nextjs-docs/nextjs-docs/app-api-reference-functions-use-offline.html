useOfflineexperimentaluseOffline

useOffline hook은 앱이 현재 offline 상태인지를 나타내는 boolean을 반환합니다. 사용자가 network 연결을 잃었을 때 표시하는 banner나 offline 상태를 고려한 Suspense fallback처럼, 연결 상태를 반영하는 UI를 render하는 데 사용하세요.

The useOffline hook returns a boolean indicating whether the app is currently offline. Use it to render connectivity-aware UI, such as a banner when the user loses their network connection, or an offline-aware Suspense fallback.

이 hook은 더 큰 기능의 일부입니다. experimental.useOffline config option을 활성화하면 offline 연결 감지와, block된 navigation, prefetch, Server Action request의 자동 retry가 켜지고, Client Component가 그 state를 읽을 수 있도록 이 hook이 노출됩니다.

The hook is one piece of a larger feature. Enabling the experimental.useOffline config option turns on offline connectivity detection and automatic retry of blocked navigation, prefetch, and Server Action requests, and exposes this hook so Client Components can read the state.

이 flag가 없으면 이 hook은 항상 false를 반환합니다.

Without the flag, this hook always returns false.

JSnext.config.js
module.exports = {
  experimental: {
    useOffline: true,
  },
}
TSJSapp/offline-status.tsx
'use client'

import { useOffline } from 'next/offline'

export function OfflineStatus() {
  const isOffline = useOffline()
  return <div>{isOffline ? 'Offline' : 'Online'}</div>
}
'use client'

import { useOffline } from 'next/offline'

export function OfflineStatus() {
  const isOffline = useOffline()
  return <div>{isOffline ? 'Offline' : 'Online'}</div>
}

연결 상태를 감지하고 request를 retry하는 방식에 대한 자세한 내용은 How retry works를 참고하세요.

For details on how connectivity is detected and requests retried, see How retry works.

Parameters

const isOffline = useOffline()

useOffline은 parameter를 받지 않습니다.

useOffline does not take any parameters.

Returns

useOffline은 boolean을 반환합니다:

useOffline returns a boolean:

ValueMeaning
true앱이 offline 상태입니다. network request가 실패했거나, 브라우저가 offline event를 발생시켰습니다.
false앱이 online 상태이거나 server에서 rendering 중입니다. hydration이 완료되기 전의 초기값이기도 합니다.
ValueMeaning
trueThe app is offline. A network request has failed, or the browser has fired an offline event.
falseThe app is online, or rendering on the server. This is also the initial value before hydration completes.

Examples예시

Show an offline banneroffline banner 표시하기

사용자가 연결을 잃을 때마다 계속 유지되는 banner를 render하세요.

Render a persistent banner whenever the user loses connectivity.

TSJSapp/components/offline-banner.tsx
'use client'

import { useOffline } from 'next/offline'

export function OfflineBanner() {
  const isOffline = useOffline()

  if (!isOffline) {
    return null
  }

  return (
    <div role="status" className="offline-banner">
      You are offline. Some content may be unavailable.
    </div>
  )
}

Offline-aware Suspense fallbackoffline 상태를 고려한 Suspense fallback

사용자가 offline 상태에서 어떤 route로 이동하면, prefetch된 static shell은 즉시 render되지만 <Suspense> boundary 뒤의 dynamic content는 network를 기다리며 block됩니다. 예를 들어 loading.tsx 파일 안에서 useOffline을 사용해 content가 예상보다 오래 걸리는 이유를 설명할 수 있습니다.

When a user navigates to a route while offline, the prefetched static shell renders immediately but the dynamic content behind a <Suspense> boundary blocks on the network. For example, use useOffline inside a loading.tsx file to explain why the content is taking longer than expected.

TSJSapp/destination/loading.tsx
'use client'

import { useOffline } from 'next/offline'

export default function Loading() {
  const isOffline = useOffline()

  return (
    <div>
      {isOffline ? 'Waiting for connection to load this page...' : 'Loading...'}
    </div>
  )
}
'use client'

import { useOffline } from 'next/offline'

export default function Loading() {
  const isOffline = useOffline()

  return (
    <div>
      {isOffline ? 'Waiting for connection to load this page...' : 'Loading...'}
    </div>
  )
}

연결이 복구되면 Next.js가 block된 request를 retry하고, dynamic content가 자동으로 stream되어 들어옵니다.

When connectivity is restored, Next.js retries the blocked request and the dynamic content streams in automatically.
