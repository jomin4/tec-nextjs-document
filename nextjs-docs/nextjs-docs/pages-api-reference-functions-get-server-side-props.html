getServerSidePropsgetServerSideProps

page에서 getServerSideProps(Server-Side Rendering)라는 함수를 export하면, Next.js는 getServerSideProps가 반환한 data를 사용해 매 request마다 이 page를 prerender합니다. 자주 바뀌는 data를 fetch하고 page가 최신 data를 보여 주도록 업데이트하고 싶을 때 유용합니다.

When exporting a function called getServerSideProps (Server-Side Rendering) from a page, Next.js will prerender this page on each request using the data returned by getServerSideProps. This is useful if you want to fetch data that changes often, and have the page update to show the most current data.

TSJSpages/index.tsx
import type { InferGetServerSidePropsType, GetServerSideProps } from 'next'

type Repo = {
  name: string
  stargazers_count: number
}

export const getServerSideProps = (async () => {
  // Fetch data from external API
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo: Repo = await res.json()
  // Pass data to the page via props
  return { props: { repo } }
}) satisfies GetServerSideProps<{ repo: Repo }>

export default function Page({
  repo,
}: InferGetServerSidePropsType<typeof getServerSideProps>) {
  return (
    <main>
      <p>{repo.stargazers_count}</p>
    </main>
  )
}
export async function getServerSideProps() {
  // Fetch data from external API
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo = await res.json()
  // Pass data to the page via props
  return { props: { repo } }
}

export default function Page({ repo }) {
  return (
    <main>
      <p>{repo.stargazers_count}</p>
    </main>
  )
}

getServerSideProps에서 사용하기 위해 top-level scope에서 module을 import할 수 있습니다. 사용된 import는 client-side용으로 bundle되지 않습니다. 즉, database에서 data를 fetch하는 것을 포함해 getServerSideProps 안에 server-side 코드를 직접 작성할 수 있습니다.

You can import modules in top-level scope for use in getServerSideProps. Imports used will not be bundled for the client-side. This means you can write server-side code directly in getServerSideProps, including fetching data from your database.

Context parameter

context parameter는 다음 key를 포함하는 object입니다:

The context parameter is an object containing the following keys:

NameDescription
params이 page가 dynamic route를 사용한다면 params에 route parameter가 들어 있습니다. page 이름이 [id].js라면 params는 { id: ... } 형태가 됩니다.
reqHTTP IncomingMessage object에 cookies prop이 추가된 것으로, cookies는 string key를 cookie의 string value에 mapping하는 object입니다.
resHTTP response object.
querydynamic route parameter를 포함해 query string을 나타내는 object.
preview(draftMode로 대체되어 Deprecated) page가 Preview Mode이면 preview는 true, 아니면 false입니다.
previewData(draftMode로 대체되어 Deprecated) setPreviewData로 설정된 preview data.
draftModepage가 Draft Mode이면 draftMode는 true, 아니면 false입니다.
resolvedUrlclient 전환 시의 _next/data prefix를 제거하고 원래의 query 값을 포함한, 정규화된 request URL.
locale활성화된 locale을 담고 있습니다(활성화된 경우).
locales지원되는 모든 locale을 담고 있습니다(활성화된 경우).
defaultLocale설정된 기본 locale을 담고 있습니다(활성화된 경우).
NameDescription
paramsIf this page uses a dynamic route, params contains the route parameters. If the page name is [id].js, then params will look like { id: ... }.

preview(Deprecated for draftMode) preview is true if the page is in the Preview Mode and false otherwise.

draftModedraftMode is true if the page is in the Draft Mode and false otherwise.

getServerSideProps return valuesgetServerSideProps 반환 값

getServerSideProps 함수는 다음 property 중 하나를 가진 object를 반환해야 합니다:

The getServerSideProps function should return an object with any one of the following properties:

props

props object는 key-value 쌍이며, 각 value는 page component가 받습니다. 전달되는 모든 props가 JSON.stringify로 serialize될 수 있도록 serializable object여야 합니다.

The props object is a key-value pair, where each value is received by the page component. It should be a serializable object so that any props passed, could be serialized with JSON.stringify.

export async function getServerSideProps(context) {
  return {
    props: { message: `Next.js is awesome` }, // will be passed to the page component as props
  }
}

notFound

notFound boolean을 사용하면 page가 404 status와 404 Page를 반환할 수 있습니다. notFound: true이면 이전에 성공적으로 생성된 page가 있었더라도 page는 404를 반환합니다. 이는 사용자가 생성한 콘텐츠가 작성자에 의해 삭제되는 경우 같은 use case를 지원하기 위한 것입니다.

The notFound boolean allows the page to return a 404 status and 404 Page. With notFound: true, the page will return a 404 even if there was a successfully generated page before. This is meant to support use cases like user-generated content getting removed by its author.

export async function getServerSideProps(context) {
  const res = await fetch(`https://.../data`)
  const data = await res.json()

  if (!data) {
    return {
      notFound: true,
    }
  }

  return {
    props: { data }, // will be passed to the page component as props
  }
}

redirect

redirect object를 사용하면 내부 및 외부 resource로 redirect할 수 있습니다. { destination: string, permanent: boolean } 형태와 일치해야 합니다. 드물게 오래된 HTTP client가 올바르게 redirect하도록 custom status code를 지정해야 할 수도 있습니다. 이런 경우 permanent property 대신 statusCode property를 사용할 수 있지만, 둘을 함께 사용할 수는 없습니다.

The redirect object allows redirecting to internal and external resources. It should match the shape of { destination: string, permanent: boolean }. In some rare cases, you might need to assign a custom status code for older HTTP clients to properly redirect. In these cases, you can use the statusCode property instead of the permanent property, but not both.

export async function getServerSideProps(context) {
  const res = await fetch(`https://.../data`)
  const data = await res.json()

  if (!data) {
    return {
      redirect: {
        destination: '/',
        permanent: false,
      },
    }
  }

  return {
    props: {}, // will be passed to the page component as props
  }
}
