outputoutput

build 중에 Next.js는 각 page와 그 dependency를 자동으로 trace해서, 애플리케이션의 production 버전을 deploy하는 데 필요한 모든 파일을 파악합니다.

During a build, Next.js will automatically trace each page and its dependencies to determine all of the files that are needed for deploying a production version of your application.

이 기능은 deployment 크기를 크게 줄여 줍니다. 이전에는 Docker로 deploy할 때 next start를 실행하려면 package의 dependencies에 있는 모든 파일을 설치해야 했습니다. Next.js 12부터는 .next/ directory의 Output File Tracing을 활용해 필요한 파일만 포함할 수 있습니다.

This feature helps reduce the size of deployments drastically. Previously, when deploying with Docker you would need to have all files from your package's dependencies installed to run next start. Starting with Next.js 12, you can leverage Output File Tracing in the .next/ directory to only include the necessary files.

또한 이 기능 덕분에, 여러 문제를 일으키고 불필요한 중복도 만드는 deprecated serverless target이 더 이상 필요 없습니다.

Furthermore, this removes the need for the deprecated serverless target which can cause various issues and also creates unnecessary duplication.

How it Works동작 방식

next build 중에 Next.js는 @vercel/nft를 사용해 import, require, fs 사용을 정적으로 분석하고, page가 load할 수 있는 모든 파일을 파악합니다.

During next build, Next.js will use @vercel/nft to statically analyze import, require, and fs usage to determine all files that a page might load.

Next.js의 production server도 필요한 파일이 trace되어 .next/next-server.js.nft.json에 출력되며, production에서 이를 활용할 수 있습니다.

Next.js' production server is also traced for its needed files and output at .next/next-server.js.nft.json which can be leveraged in production.

.next output directory에 출력된 .nft.json 파일을 활용하려면, 각 trace에서 .nft.json 파일 기준 상대 경로로 된 파일 목록을 읽은 다음 deployment 위치로 복사하면 됩니다.

To leverage the .nft.json files emitted to the .next output directory, you can read the list of files in each trace that are relative to the .nft.json file and then copy them to your deployment location.

Turbopack NFT extensionsTurbopack NFT 확장

Turbopack의 .nft.json 파일에는 fileHashes와 symlinks 확장이 포함됩니다:

Turbopack .nft.json files include fileHashes and symlinks extensions:

  • fileHashes는 files와 길이와 순서가 같은 병렬 배열입니다. 예를 들어 fileHashes[0]은 files[0]의 hash입니다. consumer는 이 hash를 trace된 asset을 caching하거나 중복 제거할 때 content identifier로 사용할 수 있습니다.
  • symlinks는 형제 files 배열의 index를 각각의 직접 target에 mapping합니다. symlinks가 있을 때, 대응하는 entry가 없는 파일은 일반 파일이나 directory로 간주할 수 있습니다.
  • fileHashes is a parallel array with the same length and ordering as files. For example, fileHashes[0] is the hash for files[0]. A consumer can use the hash as a content identifier for caching or deduplicating traced assets.
  • symlinks maps indexes in the sibling files array to their immediate targets. When symlinks is present, files without a corresponding entry can be assumed to be normal files or directories.

experimental.turbopackAdditionalRoots를 사용하는 trace에는 additionalRoots 확장도 포함됩니다:

Traces that use experimental.turbopackAdditionalRoots also include the additionalRoots extension:

  • additionalRoots는 이름이 붙은 source root의 순서 있는 목록입니다. 각 root는 자체 files, fileHashes, symlinks 목록을 가집니다. 그 path는 .nft.json 파일이 있는 directory 기준의 상대 경로이며, build machine에서의 source 위치를 나타냅니다. additionalRoots의 이름은 next.config.js에 제공한 이름과 일치하며, 대부분의 운영체제와 filesystem에서 유효한 directory 이름임이 보장됩니다.
  • additionalRoots is an ordered list of named source roots. Each root has its own files, fileHashes, and symlinks lists. Its path is relative to the directory containing the .nft.json file and identifies the source location on the build machine. additionalRoots names match those provided in next.config.js and are guaranteed to be valid directory names on most operating systems and filesystems.

Automatically Copying Traced Filestrace된 파일 자동 복사

Next.js는 node_modules의 일부 파일을 포함해 production deployment에 필요한 파일만 복사한 standalone 폴더를 자동으로 만들 수 있습니다.

Next.js can automatically create a standalone folder that copies only the necessary files for a production deployment including select files in node_modules.

이 자동 복사를 활용하려면 next.config.js에서 활성화하세요:

To leverage this automatic copying you can enable it in your next.config.js:

JSnext.config.js
module.exports = {
  output: 'standalone',
}

이렇게 하면 .next/standalone에 폴더가 생성되며, node_modules를 설치하지 않고도 이 폴더만 단독으로 deploy할 수 있습니다.

This will create a folder at .next/standalone which can then be deployed on its own without installing node_modules.

Windows에서는 directory symlink를 만들 때 관리자 권한이나 Developer Mode가 필요할 수 있습니다. standalone 생성이 junction point로 fallback해야 하는 경우, Windows는 absolute target을 저장하므로 해당 output은 다른 위치로 옮길 수 없습니다.

On Windows, creating directory symlinks can require elevated privileges or Developer Mode. If standalone generation must fall back to a junction point, Windows stores an absolute target and that particular output is not relocatable.

또한 next start 대신 사용할 수 있는 최소한의 server.js 파일도 출력됩니다. 이 최소 server는 기본적으로 public이나 .next/static 폴더를 복사하지 않습니다. 이 폴더들은 이상적으로는 CDN이 처리해야 하기 때문입니다. 다만 이 폴더들을 standalone/public과 standalone/.next/static 폴더로 직접 복사할 수 있으며, 그러면 server.js 파일이 이를 자동으로 serve합니다.

Additionally, a minimal server.js file is also output which can be used instead of next start. This minimal server does not copy the public or .next/static folders by default as these should ideally be handled by a CDN instead, although these folders can be copied to the standalone/public and standalone/.next/static folders manually, after which server.js file will serve these automatically.

직접 복사하려면 next build 후에 cp command-line 도구를 사용할 수 있습니다:

To copy these manually, you can use the cp command-line tool after you next build:

>_Terminal
cp -r public .next/standalone/ && cp -r .next/static .next/standalone/.next/

최소 server.js 파일을 local에서 시작하려면 다음 command를 실행하세요:

To start your minimal server.js file locally, run the following command:

>_Terminal
node .next/standalone/server.js
Good to know
  • next.config.js는 next build 중에 읽혀 server.js output 파일 안에 serialize됩니다.
  • 프로젝트가 특정 port나 hostname에서 listen해야 한다면, server.js를 실행하기 전에 PORT 또는 HOSTNAME environment variable을 정의할 수 있습니다. 예를 들어 PORT=8080 HOSTNAME=0.0.0.0 node server.js를 실행하면 http://0.0.0.0:8080에서 server가 시작됩니다.
  • next.config.js is read during next build and serialized into the server.js output file.
  • If your project needs to listen to a specific port or hostname, you can define PORT or HOSTNAME environment variables before running server.js. For example, run PORT=8080 HOSTNAME=0.0.0.0 node server.js to start the server on http://0.0.0.0:8080.

Caveats주의 사항

  • monorepo setup에서 trace할 때는 기본적으로 프로젝트 directory가 tracing에 사용됩니다. next build packages/web-app의 경우 packages/web-app이 tracing root가 되며, 그 폴더 밖의 파일은 포함되지 않습니다. 이 폴더 밖의 파일을 포함하려면 next.config.js에서 outputFileTracingRoot를 설정하면 됩니다.
  • While tracing in monorepo setups, the project directory is used for tracing by default. For next build packages/web-app, packages/web-app would be the tracing root and any files outside of that folder will not be included. To include files outside of this folder you can set outputFileTracingRoot in your next.config.js.
JSpackages/web-app/next.config.js
const path = require('path')

module.exports = {
  // this includes files from the monorepo base two directories up
  outputFileTracingRoot: path.join(__dirname, '../../'),
}
  • Next.js가 필요한 파일을 포함하지 못하거나, 사용하지 않는 파일을 잘못 포함하는 경우가 있습니다. 이런 경우 next.config.js에서 각각 outputFileTracingExcludes와 outputFileTracingIncludes를 활용할 수 있습니다. 각 option은 object를 받으며, key는 route glob(picomatch로 route path(예: /api/hello)와 match됨)이고, value는 trace에 포함하거나 제외할 파일을 지정하는 프로젝트 root 기준으로 resolve되는 glob pattern입니다.
  • There are some cases in which Next.js might fail to include required files, or might incorrectly include unused files. In those cases, you can leverage outputFileTracingExcludes and outputFileTracingIncludes respectively in next.config.js. Each option accepts an object whose keys are route globs (matched with picomatch against the route path, e.g. /api/hello) and whose values are glob patterns resolved from the project root that specify files to include or exclude in the trace.
Good to know

monorepo에서 project root는 monorepo root가 아니라 Next.js 프로젝트 root(next.config.js가 있는 폴더, 예: packages/web-app)를 가리킵니다.

In a monorepo, project root refers to the Next.js project root (the folder containing next.config.js, e.g., packages/web-app), not necessarily the monorepo root.

JSnext.config.js
module.exports = {
  outputFileTracingExcludes: {
    '/api/hello': ['./un-necessary-folder/**/*'],
  },
  outputFileTracingIncludes: {
    '/api/another': ['./necessary-folder/**/*'],
    '/api/login/\\[\\[\\.\\.\\.slug\\]\\]': [
      './node_modules/aws-crt/dist/bin/**/*',
    ],
  },
}

src/ directory를 사용해도 이 option을 작성하는 방법은 달라지지 않습니다:

Using a src/ directory does not change how you write these options:

  • Key는 여전히 route path('/api/hello', '/products/[id]' 등)와 match됩니다.
  • Value는 프로젝트 root 기준으로 resolve되므로 src/ 아래의 경로를 참조할 수 있습니다.
  • Keys still match the route path ('/api/hello', '/products/[id]', etc.).
  • Values can reference paths under src/ since they are resolved relative to the project root.
JSnext.config.js
module.exports = {
  outputFileTracingIncludes: {
    '/products/*': ['src/lib/payments/**/*'],
    '/*': ['src/config/runtime/**/*.json'],
  },
  outputFileTracingExcludes: {
    '/api/*': ['src/temp/**/*', 'public/large-logs/**/*'],
  },
}

'/*' 같은 global key를 사용해 모든 route를 대상으로 지정할 수도 있습니다:

You can also target all routes using a global key like '/*':

JSnext.config.js
module.exports = {
  outputFileTracingIncludes: {
    '/*': ['src/i18n/locales/**/*.json'],
  },
}

이 option들은 server trace에 적용되며, server trace 파일을 만들지 않는 route에는 영향을 주지 않습니다:

These options are applied to server traces and do not affect routes that do not produce a server trace file:

  • Edge Runtime route는 영향을 받지 않습니다.
  • 완전히 static한 page는 영향을 받지 않습니다.
  • Edge Runtime routes are not affected.
  • Fully static pages are not affected.

monorepo에서, 또는 app 폴더 밖의 파일을 포함해야 할 때는 outputFileTracingRoot와 include를 함께 사용하세요:

In monorepos or when you need to include files outside the app folder, combine outputFileTracingRoot with includes:

JSnext.config.js
const path = require('path')

module.exports = {
  // Trace from the monorepo root
  outputFileTracingRoot: path.join(__dirname, '../../'),
  outputFileTracingIncludes: {
    '/route1': ['../shared/assets/**/*'],
  },
}
Good to know
  • cross-platform 호환성을 위해 pattern에는 forward slash(/)를 사용하는 것이 좋습니다.
  • 너무 큰 trace를 피하려면 pattern을 가능한 한 좁게 유지하세요(repo root에서 **/* 사용은 피하세요).
  • Prefer forward slashes (/) in patterns for cross-platform compatibility.
  • Keep patterns as narrow as possible to avoid oversized traces (avoid **/* at the repo root).

native/runtime asset에 흔히 쓰이는 include pattern:

Common include patterns for native/runtime assets:

JSnext.config.js
module.exports = {
  outputFileTracingIncludes: {
    '/*': ['node_modules/sharp/**/*', 'node_modules/aws-crt/dist/bin/**/*'],
  },
}
